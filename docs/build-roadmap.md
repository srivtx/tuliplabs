# Build your own X: what comes next

Chapters 1–25 are live. These are the parts chosen next, in the order they'll be built. Each chapter
gets the usual shape: a live simulation with a naive-vs-real comparison and one goal, write / bug /
Parsons / predict exercises, a real-world project with graded exercises, a from-memory rebuild and a
recall question.

| Part | Chapters | What you build |
|---|---|---|
| **9 · Tools devs live in** ✅ live | 26–29 | a diff tool (longest common subsequence, how `git diff` finds changes) · a build system (like make: rebuild only what's stale) · a package manager (resolving versions and conflicts, like npm and pip) · a test framework (like pytest: discovery, assertions, fixtures) |
| **10 · Runtimes and CLIs** ✅ live | 30–33 | a command-line tool kit (flags, subcommands, help, exit codes) · a shell (parsing, pipes, redirects, jobs) · an async runtime (the event loop, timers and promises behind Node and asyncio) · a container runtime (isolated processes, layered filesystems, resource limits, like Docker) |
| **11 · Real-world systems** ✅ live | 34–37 | a ride-share matcher (drivers to riders) · a stock-exchange order book (matching buys and sells) · collaborative editing with offline sync (CRDTs) · a job scheduler (cron, queues, retries) |
| **12 · Money and markets** ✅ live | 38–41 | a bank ledger (double-entry bookkeeping) · a payments system (idempotency: never charge twice) · an auction engine · a fraud detector |
| **13 · AI and agents** | 42–45 | an AI agent that uses tools (the planning loop) · embeddings and vector search · a RAG chatbot over your own notes · a decision tree and random forest |
| **14 · Simulated worlds** | 46–49 | a falling-sand world (cellular automata) · particles and fluids · a traffic simulator (why jams appear from nowhere) · crowds and epidemics |
| **15 · Inside your phone** | 50–53 | GPS (your position from satellite timings) · a touch keyboard with autocorrect · a step counter (filtering a noisy signal) · push notifications (pub/sub) |
| **16 · Games and maps** | 54–57 | a route finder (Dijkstra and A*) · a game AI that can't lose (minimax and pruning) · a recommendation engine · a 2D game engine (loop, sprites, collisions) |
| **17 · The web, end to end** | 58–61 | a DNS resolver · an HTTP server · a browser layout engine (HTML and CSS to boxes) · a rate limiter (token bucket) |
| **18 · Security and trust** | 62–65 | encryption (from Caesar to Diffie-Hellman and RSA) · a login system (salted hashes, sessions) · a message queue (acks, retries, at-least-once) · digital signatures and certificates |
| **19 · Pictures and sound** | 66–69 | an image editor (convolution: blur, sharpen, edges) · a synthesizer (waves and envelopes) · JPEG-style compression (DCT and quantization) · a font rasterizer (curves to pixels) |
