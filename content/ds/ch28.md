## Asking the same question twice

Backtracking (chapter 27) explores every branch. Sometimes different branches lead to the **same** smaller question. How many ways are there to climb 10 stairs, 1 or 2 at a time? The last move was either 1 step (from stair 9) or 2 steps (from stair 8), so:

`ways(n) = ways(n − 1) + ways(n − 2)`, with `ways(0) = ways(1) = 1`.

Correct, but plain recursion asks for `ways(8)` from `ways(10)` and again from `ways(9)`, and the repeats multiply.

```viz
name: ds-stairs
title: Ten stairs: plain recursion against a table
goal: Run **plain recursion** to the end, then run **table, bottom up** and compare the work.
height: 440
Bar height counts how many times each ways(i) was worked out.
```

**Dynamic programming (DP)** = a recursion whose subproblems **overlap**, plus storing each answer the first time. Two ways to store:

- **Memoisation (top down)**: keep the recursion, add a dictionary (or `@lru_cache`). Return the saved answer if there is one.
- **Tabulation (bottom up)**: fill an array from the base cases upwards, so everything `dp[i]` needs is already there.

```run
title: The same recurrence, three ways
calls = 0
def plain(n):
    global calls
    calls += 1
    return 1 if n < 2 else plain(n - 1) + plain(n - 2)
print(plain(25), "plain calls:", calls)

@lru_cache(maxsize=None)
def memo(n):
    return 1 if n < 2 else memo(n - 1) + memo(n - 2)
print(memo(25), "memo: each n computed once")

def table(n):
    dp = [1, 1] + [0] * (n - 1)
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
print(table(25), "table: one loop")
```

## The ladder

Every DP answers four questions. Write them down **before** coding:

1. **State**: what does `dp[i]` mean, in words? ("the number of ways to reach stair i")
2. **Transition**: how is `dp[i]` built from smaller states?
3. **Base cases**: the smallest states, known directly.
4. **Order**: fill so every state you read is already filled.


## Designing the state

The parsons puzzle is **House Robber** (LeetCode 198): adjacent houses can't both be robbed. State: `dp[i]` = best total from the first `i` houses. Transition: either skip house `i` (`dp[i − 1]`) or rob it (`dp[i − 2] + nums[i]`). Because `dp[i]` only reads the two before it, two variables are enough.

```exercise
title: min_cost_climbing
kind: write
---prompt
*LeetCode 746, asked at Amazon.* `cost[i]` is paid when you step on stair `i`. You may start on stair 0 or 1 and climb 1 or 2 at a time; the top is just past the last stair. Return the minimum total cost to reach the top.
---starter
def min_cost(cost):
    return sum(cost[::2])
---solution
def min_cost(cost):
    a = b = 0
    for i in range(2, len(cost) + 1):
        a, b = b, min(b + cost[i - 1], a + cost[i - 2])
    return b
---tests
assert min_cost([10, 15, 20]) == 15
assert min_cost([1, 100, 1, 1, 1, 100, 1, 1, 100, 1]) == 6
assert min_cost([0, 0]) == 0
---hint
`dp[i]` = cheapest way to stand at position `i` (not yet paid for `i`). `dp[0] = dp[1] = 0`; `dp[i] = min(dp[i − 1] + cost[i − 1], dp[i − 2] + cost[i − 2])`.
```

```exercise
*LeetCode 91, asked at Meta, Amazon and Uber.* Letters are coded A = 1 … Z = 26. Return how many ways the digit string `s` can be decoded. A `"0"` can only be part of `"10"` or `"20"`.
```

```exercise
title: word_break
kind: write
---prompt
*LeetCode 139, asked at Meta, Amazon and Google.* Can `s` be split into a sequence of words from `words` (each word reusable)? `dp[i]` = "the first `i` characters can be split".
---starter
def can_break(s, words):
    return all(w in s for w in words)
---solution
def can_break(s, words):
    ws = set(words)
    dp = [True] + [False] * len(s)
    for i in range(1, len(s) + 1):
        dp[i] = any(dp[j] and s[j:i] in ws for j in range(i))
    return dp[-1]
---tests

assert can_break("applepenapple", ["apple", "pen"])
assert not can_break("catsandog", ["cats", "dog", "sand", "and", "cat"])
assert can_break("ab", ["a", "b", "c"])
assert can_break("a" * 200 + "b", ["a", "aa", "aaa"]) is False
---hint
For each end `i`, look for a split point `j` where `dp[j]` is true and `s[j:i]` is a word.
```

```exercise
title: delete_and_earn
kind: write
---prompt
*LeetCode 740, asked at Amazon.* Taking a number `x` earns `x` points but deletes every `x − 1` and `x + 1`. Return the most points you can earn. Turn it into House Robber: total up the points for each value, then you can't take two neighbouring values.
---starter
def earn(nums):
    return sum(nums)
---solution
def earn(nums):
    from collections import Counter
    count = Counter(nums)
    skip = take = 0
    prev = None
    for v in sorted(count):
        gain = v * count[v]
        if prev is not None and v == prev + 1:
            skip, take = take, max(take, skip + gain)
        else:
            skip, take = take, take + gain
        prev = v
    return take
---tests
assert earn([3, 4, 2]) == 6
assert earn([2, 2, 3, 3, 3, 4]) == 9
assert earn([1, 1, 1, 5]) == 8
---hint
Values that aren't next to each other never conflict, so when there's a gap you can add the gain freely.
```

```exercise
title: max_product_subarray
kind: write
---prompt
*LeetCode 152, asked at LinkedIn and Amazon.* Return the largest product of a contiguous non-empty subarray. A negative number turns the smallest product into the largest, so track **both** the biggest and the smallest product ending here.
---starter
def max_product(nums):
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur * x)
        best = max(best, cur)
    return best
---solution
def max_product(nums):
    hi = lo = best = nums[0]
    for x in nums[1:]:
        hi, lo = max(x, hi * x, lo * x), min(x, hi * x, lo * x)
        best = max(best, hi)
    return best
---tests
assert max_product([2, 3, -2, 4]) == 6
assert max_product([-2, 0, -1]) == 0
assert max_product([-2, 3, -4]) == 24
assert max_product([-2]) == -2
---hint
The state needs two numbers per position, not one. Update both from the old pair at once.
```

```quiz
What's the difference between memoisation and tabulation?
- Memoisation is always faster
* Memoisation keeps the recursion and caches answers (top down); tabulation fills an array from the base cases up
- Tabulation can't handle 1D problems
- They store different answers
> Same states and same transitions, different order of filling.
```

## Real-world project: a courier's shift planner

```project
title: Pick the best set of delivery jobs
client: A courier app that offers drivers overlapping paid jobs during a shift and wants to suggest the most profitable plan
skills: weighted interval scheduling, DP with binary search, rebuilding the choices
---brief
Build `planner.py`. Each job is `(start, end, pay)`; a driver can do jobs back to back (one may start when the last ends) but never two at once. Sort jobs by end time. `dp[i]` = best pay using the first `i` jobs: either skip job `i`, or take it plus the best from the jobs that end by its start (find that index with binary search). Then walk back through the table to list which jobs to take.
---why
Ad slot scheduling, room and equipment booking, CPU job selection and broadcast scheduling are all weighted interval scheduling. Greedy (best-paid first) is fast but wrong; DP is fast and right.
---milestones
- Sort jobs by end time
- Find the last compatible job with `bisect`
- Fill the DP table
- Walk back to recover the chosen jobs
---stretch
- Allow a travel gap between jobs
- Let each driver work at most k jobs
```

```exercise
title: max_pay
kind: write
---prompt
*LeetCode 1235, a hard one asked at Google, DoorDash and Amazon.* Return the most pay from non-overlapping jobs `(start, end, pay)`. A job starting at time `t` can follow one ending at `t`. Sort by end; `bisect_right(ends, start, 0, i)` counts the earlier jobs ending by `start`.
---starter
def max_pay(jobs):
    taken, total = [], 0
    for s, e, p in sorted(jobs, key=lambda j: -j[2]):
        if all(e <= s2 or s >= e2 for s2, e2 in taken):
            taken.append((s, e))
            total += p
    return total
---solution
def max_pay(jobs):
    jobs = sorted(jobs, key=lambda j: j[1])
    ends = [e for _, e, _ in jobs]
    dp = [0] * (len(jobs) + 1)
    for i, (s, e, p) in enumerate(jobs):
        k = bisect.bisect_right(ends, s, 0, i)
        dp[i + 1] = max(dp[i], dp[k] + p)
    return dp[-1]
---tests
assert max_pay([(1, 3, 50), (2, 4, 10), (3, 5, 40), (3, 6, 70)]) == 120
assert max_pay([(1, 2, 5), (2, 3, 6), (3, 4, 5), (1, 4, 10)]) == 16
assert max_pay([(1, 2, 5)]) == 5
assert max_pay([]) == 0
---hint
The starter is greedy by pay: one big job can block three smaller ones worth more.
```

```exercise
title: chosen_jobs
kind: write
---prompt
Return the jobs in a best plan, sorted by end time. Fill the same table as `max_pay`, then walk back from `i = n`: if `dp[i] == dp[i − 1]` the job wasn't needed, so skip it; otherwise take job `i − 1` and jump to its compatible index.
---starter
def chosen_jobs(jobs):
    return sorted(jobs, key=lambda j: j[1])
---solution
def chosen_jobs(jobs):
    jobs = sorted(jobs, key=lambda j: j[1])
    ends = [e for _, e, _ in jobs]
    dp, back = [0] * (len(jobs) + 1), [0] * len(jobs)
    for i, (s, e, p) in enumerate(jobs):
        back[i] = bisect.bisect_right(ends, s, 0, i)
        dp[i + 1] = max(dp[i], dp[back[i]] + p)
    out, i = [], len(jobs)
    while i > 0:
        if dp[i] == dp[i - 1]:
            i -= 1
        else:
            out.append(jobs[i - 1])
            i = back[i - 1]
    return out[::-1]
---tests
assert chosen_jobs([(1, 3, 50), (2, 4, 10), (3, 5, 40), (3, 6, 70)]) == [(1, 3, 50), (3, 6, 70)]
assert chosen_jobs([(1, 2, 5), (2, 3, 6), (3, 4, 5), (1, 4, 10)]) == [(1, 2, 5), (2, 3, 6), (3, 4, 5)]
assert chosen_jobs([]) == []
---hint
Store each job's compatible index during the fill so the walk back is a simple loop.
```

## Rebuild it and explain it

```exercise
title: dp1d_rebuild
kind: rebuild
---prompt
From memory: `ways(n, steps)`: the number of ordered ways to climb `n` stairs when each move is one of the sizes in `steps`, modulo 1,000,000,007. Bottom-up table.
---starter
def ways(n, steps):
    pass
---solution
def ways(n, steps):
    M = 10 ** 9 + 7
    dp = [1] + [0] * n
    for i in range(1, n + 1):
        dp[i] = sum(dp[i - s] for s in steps if s <= i) % M
    return dp[n]
---tests
assert ways(10, [1, 2]) == 89
assert ways(4, [1, 3]) == 3
assert ways(3, [2]) == 0
assert ways(0, [1, 2]) == 1
assert ways(1000, [1, 2, 3]) == 509672692
---hint
`dp[i]` = ways to stand on stair `i`. The last move was one of the sizes, so add up `dp[i − s]`.
```

```recall
Q: Explain dynamic programming in one dimension: when it applies, memoisation versus tabulation, the four parts of a DP, and how to save space.
A: Dynamic programming applies when a recursion asks the same smaller questions repeatedly (overlapping subproblems) and each answer can be built from smaller answers (optimal substructure), like counting stair climbs with ways(n) = ways(n − 1) + ways(n − 2), which plain recursion solves in exponential time. Storing each answer the first time makes every subproblem cost O(1) after that. Memoisation keeps the recursion and caches results top down (a dict or lru_cache); tabulation fills an array from the base cases upwards with a loop, avoiding deep recursion. Design a DP by writing the state in words (what dp[i] means), the transition (how dp[i] is built from smaller states, e.g. skip or take for House Robber), the base cases, and an order that fills everything a state reads before it. If dp[i] only reads the last few states, keep just those values for O(1) space. Some states need more than one number, like the max and min product ending at i, and the choices can be recovered by walking back through the table.
```
