```prelude
import time
from collections import Counter, defaultdict

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t
```

## A window that only moves forward

"Find the longest / shortest / best **contiguous** stretch such that…" is a sliding window question nine times out of ten. Instead of trying every start and every end (O(n²)), keep one window `[L, R]`: R moves right to take in a new item, and L moves right to drop items whenever the window breaks the rule.

```viz
name: ds-window
title: Longest stretch with no repeated letter
goal: Run **restart from every letter** to the end, then run **sliding window** and compare the steps.
height: 400
The green bar underneath marks the best window found so far.
```

The inner `while` loop looks like it makes this O(n²), but count moves instead of loops: R moves n times in total and L moves at most n times in total, because neither ever goes back. That's **amortised** O(n).

Two kinds of window:

| Kind | Size | Move | Examples |
|---|---|---|---|
| Fixed | always k | add the item entering, remove the item leaving | max sum of k in a row, anagrams in a string, moving average |
| Variable | grows and shrinks | R grows it; L shrinks it while it's broken | longest without repeats, shortest with sum ≥ t, at most k distinct |

The variable template:

```run
title: The variable-window template
s = "abcabcbb"
inside, L, best = set(), 0, 0
for R, c in enumerate(s):
    while c in inside:          # window would break: shrink from the left
        inside.remove(s[L])
        L += 1
    inside.add(c)               # take in the new item
    best = max(best, R - L + 1) # the window is valid here: record it
print(best)
```

```quiz
In the variable window, why is the total work O(n) even with a `while` inside the `for`?
- The `while` loop runs at most once per step
* L only moves forward, so across the whole run the `while` body runs at most n times in total
- Python optimises nested loops
- Because the string is short
> Count pointer moves, not loop nesting: R moves n times, L moves at most n times. 2n moves in all.
```

```exercise
title: max_sum_k
kind: write
---prompt
*The warm-up.* Return the largest sum of `k` consecutive numbers (1 ≤ k ≤ n ≤ 10⁵). Don't re-add the whole window each time: when it slides one step, add the number entering and subtract the one leaving.
---starter
def max_sum_k(a, k):
    return max(sum(a[i:i + k]) for i in range(len(a) - k + 1))
---solution
def max_sum_k(a, k):
    s = best = sum(a[:k])
    for i in range(k, len(a)):
        s += a[i] - a[i - k]
        best = max(best, s)
    return best
---tests

assert r == sum(range(10000, 20000)) and secs < 0.03, f"{secs:.2f}s: slide the total, don't recompute it"
---hint
Start with `s = sum(a[:k])`. For each new `i`, `s += a[i] - a[i - k]`.
```

```exercise
title: find_anagrams
kind: write
---prompt
*LeetCode 438.* Return every start index where an anagram of `p` appears in `s`. Slide a window of length `len(p)` and keep its letter counts up to date (one letter in, one letter out) instead of recounting or re-sorting every window.
---starter
def find_anagrams(s, p):
    k = len(p)
    return [i for i in range(len(s) - k + 1) if sorted(s[i:i + k]) == sorted(p)]
---solution
def find_anagrams(s, p):
    k, need, have, out = len(p), Counter(p), Counter(), []
    for i, c in enumerate(s):
        have[c] += 1
        if i >= k:
            old = s[i - k]
            have[old] -= 1
            if have[old] == 0:
                del have[old]
        if have == need:
            out.append(i - k + 1)
    return out
---tests
assert find_anagrams("cbaebabacd", "abc") == [0, 6]
assert find_anagrams("abab", "ab") == [0, 1, 2]
assert find_anagrams("a", "ab") == []
import random
random.seed(4)
s = "".join(random.choice("abc") for _ in range(20000))
p = "".join(random.choice("abc") for _ in range(3000))
r, secs = timed(find_anagrams, s, p)
assert secs < 0.5, f"{secs:.2f}s: update the counts as the window slides"
---hint
Keep a `Counter` of the window. Add the letter entering; once the window is longer than `k`, remove the letter leaving (delete it at zero so `==` works). Compare with `Counter(p)`.
```

## Variable windows

```exercise
title: longest_unique
kind: write
---prompt
*LeetCode 3, one of the most asked questions anywhere.* Return the length of the longest substring with no repeated character, in O(n).
---starter
def longest_unique(s):
    best = 0
    for i in range(len(s)):
        seen = set()
        for j in range(i, len(s)):
            if s[j] in seen:
                break
            seen.add(s[j])
            best = max(best, j - i + 1)
    return best
---solution
def longest_unique(s):
    inside, L, best = set(), 0, 0
    for R, c in enumerate(s):
        while c in inside:
            inside.remove(s[L])
            L += 1
        inside.add(c)
        best = max(best, R - L + 1)
    return best
---tests
assert longest_unique("abcabcbb") == 3
assert longest_unique("bbbbb") == 1
assert longest_unique("pwwkew") == 3
assert longest_unique("") == 0
_, secs = timed(longest_unique, "".join(map(chr, range(200, 1700))) * 2)
assert secs < 0.03, f"{secs:.2f}s on 3000 letters: don't restart from every position"
big = "".join(map(chr, range(200, 5200))) * 2
r, secs = timed(longest_unique, big)
assert r == 5000 and secs < 0.1, f"{secs:.2f}s: don't restart from every position"
---hint
Exactly the simulation: while the new letter is already inside, drop `s[L]` and move L. Then add the letter and record the length.
```

```exercise
title: shortest_sum_at_least
kind: write
---prompt
*LeetCode 209.* All numbers are **positive**. Return the length of the shortest contiguous stretch with sum ≥ `target`, or 0 if there's none. Grow with R; while the window already reaches the target, record it and shrink with L.
---starter
def shortest(nums, target):
    return 0
---solution
def shortest(nums, target):
    L, s, best = 0, 0, float("inf")
    for R, x in enumerate(nums):
        s += x
        while s >= target:
            best = min(best, R - L + 1)
            s -= nums[L]
            L += 1
    return 0 if best == float("inf") else best
---tests
assert shortest([2, 3, 1, 2, 4, 3], 7) == 2
assert shortest([1, 4, 4], 4) == 1
assert shortest([1, 1, 1, 1], 11) == 0
assert shortest([5], 5) == 1
---hint
Here the window is "valid" when its sum is big enough, and you want it as **short** as possible, so the recording happens inside the `while`, before each shrink.
```

```exercise
title: max_ones_flips
kind: write
---prompt
*LeetCode 1004, asked at Meta and Google.* `bits` is a list of 0s and 1s. You may flip at most `k` zeros to ones. Return the longest run of ones you can get. Rephrased as a window: the longest window containing at most `k` zeros.

def max_ones(bits, k):

            L += 1
        best = max(best, R - L + 1)
```

```exercise
title: count_product_below
kind: write
---prompt
*LeetCode 713.* Positive integers; count the contiguous subarrays whose product is strictly less than `k`. For each R, once the window `[L, R]` is valid, **every** subarray ending at R and starting inside it is valid too: that's `R - L + 1` of them.
---starter
def count_below(nums, k):
    return sum(1 for x in nums if x < k)
---solution
def count_below(nums, k):
    if k <= 1:
        return 0
    L, prod, count = 0, 1, 0
    for R, x in enumerate(nums):
        prod *= x
        while prod >= k:
            prod //= nums[L]
            L += 1
        count += R - L + 1
    return count
---tests
assert count_below([10, 5, 2, 6], 100) == 8
assert count_below([1, 2, 3], 0) == 0
assert count_below([1, 1, 1], 2) == 6
---hint
Grow with R, shrink while the product is ≥ k, then add `R - L + 1` (the subarrays ending at R). Guard `k <= 1`: nothing can be below it.
```

```exercise
title: min_window
kind: write
---prompt
*LeetCode 76, a famous hard one.* Return the shortest substring of `s` containing every character of `t` (with multiplicity), or `""`. Track how many of `t`'s required characters are still missing; when none are, shrink from the left as far as possible, recording the best.
---starter
def min_window(s, t):
    return ""
---solution
def min_window(s, t):
    need = Counter(t)
    missing = len(t)
    L, best = 0, (float("inf"), 0, 0)
    for R, c in enumerate(s):
        if need[c] > 0:
            missing -= 1
        need[c] -= 1
        while missing == 0:
            if R - L + 1 < best[0]:
                best = (R - L + 1, L, R + 1)
            need[s[L]] += 1
            if need[s[L]] > 0:
                missing += 1
            L += 1
    return "" if best[0] == float("inf") else s[best[1]:best[2]]
---tests
assert min_window("ADOBECODEBANC", "ABC") == "BANC"
assert min_window("a", "a") == "a"
assert min_window("a", "aa") == ""
assert min_window("aaflslflsldkalskaaa", "aaa") == "aaa"
---hint
`need[c]` counts how many more of `c` the window still needs (it goes negative for extras). `missing` drops only when a still-needed letter enters, and rises only when a letter you really needed leaves.
```

## Quick-fire: lock it in

```quiz
Which question is a sliding window?
- Count pairs anywhere in the list adding to k
* The longest contiguous stretch whose sum is at most t (all numbers positive)
- The k-th smallest number
- Whether the list has a duplicate
> "Contiguous" plus "longest/shortest/count such that…" is the signal. Pairs anywhere is a hash map or two pointers on a sorted list.
```

```quiz
Why does "shortest subarray with sum ≥ target" need **positive** numbers for the window to work?
* With negatives, shrinking can make the sum go up, so "shrink while valid" stops being safe
- Negative numbers can't be added
- It's slower with negatives but still correct
- Python's sum fails on negatives
> The window relies on "adding makes it bigger, removing makes it smaller". With negatives you need prefix sums plus a monotonic deque (chapter 12).
```

```quiz
In a variable window, when do you record the answer for a **longest** valid window?
- Inside the shrinking loop
* After shrinking, when the window is valid again
- Only at the very end
- Before adding the new item
> For longest, record after the window is valid. For shortest, record inside the shrinking loop, while it's still valid.
```

```quiz
A fixed window of size k slides over n numbers keeping a running sum. Cost?
- O(n·k)

- O(k)
- O(n log k)
> One add and one subtract per step.
```

```exercise
title: busiest_window
kind: write
---prompt
`times` is a **sorted** list of request times in seconds. Return the largest number of requests that fall within any `w` seconds (a window `[t, t + w)`, so two requests exactly `w` apart don't count together).
---starter
def busiest(times, w):
    return len(times)
---solution
def busiest(times, w):
    L = best = 0
    for R, t in enumerate(times):
        while t - times[L] >= w:
            L += 1
        best = max(best, R - L + 1)
    return best
---tests
assert busiest([1, 2, 3, 61, 62], 60) == 3
assert busiest([0, 60, 120], 60) == 1
assert busiest([0, 59, 60], 60) == 2
assert busiest([], 60) == 0
---hint
R walks through the times; L moves past any time that's `w` or more seconds older than `times[R]`.
```

```exercise
title: rate_limiter
kind: write
---prompt
Write `class RateLimiter` with `__init__(self, limit, seconds)` and `allow(self, user, t)`. A request is allowed if the user has fewer than `limit` **allowed** requests in `(t - seconds, t]`; rejected requests don't count. Calls arrive in time order. Keep a `deque` of allowed times per user and pop old ones from the left.
---starter
class RateLimiter:
    def __init__(self, limit, seconds):
        self.limit = limit

    def allow(self, user, t):
        return True
---solution
from collections import deque

class RateLimiter:
    def __init__(self, limit, seconds):
        self.limit, self.seconds, self.log = limit, seconds, defaultdict(deque)

    def allow(self, user, t):
        q = self.log[user]
        while q and q[0] <= t - self.seconds:
            q.popleft()
        if len(q) < self.limit:
            q.append(t)
            return True
        return False
---tests
rl = RateLimiter(2, 10)
assert [rl.allow("ana", t) for t in (0, 1, 2, 10, 11, 12)] == [True, True, False, True, True, False]
assert rl.allow("bo", 12)
rl2 = RateLimiter(1, 5)
assert [rl2.allow("x", t) for t in (0, 4, 5)] == [True, False, True]
---hint
Before deciding, pop every time `≤ t - seconds` from the front of that user's deque. Then allow (and append) only if fewer than `limit` remain.
```

```recall
Q: Explain the sliding window technique: fixed versus variable windows, the template, and why it's O(n).
A: A sliding window keeps one contiguous stretch [L, R] instead of trying every start and end. A fixed window of size k slides by adding the item entering and removing the item leaving, keeping a running total or count, so each step is O(1). A variable window grows by moving R to take in a new item and, while the window breaks the rule (a repeated letter, more than k distinct, sum too big), shrinks by moving L and undoing that item; then the window is valid and you record it (for "longest" after shrinking, for "shortest" inside the shrink loop while it's still valid). For counting subarrays you add R − L + 1 per R. Though there's a while inside a for, R and L each move at most n times and never go back, so it's amortised O(n). It needs the rule to be monotone: shrinking a broken window must eventually fix it, which is why sum-based windows need non-negative numbers.
```
