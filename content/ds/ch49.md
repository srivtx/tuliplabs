## Strings as numbers

Comparing two strings of length m takes m steps. Comparing two numbers takes one. So turn strings into numbers: read the letters as digits in base B.

`hash("abc") = (a·B² + b·B + c) mod M`

With a huge prime M, different strings almost never share a hash. Two things make this powerful:

- **Rolling.** Slide a window one letter right: subtract the leaving letter's share (`letter · Bᵐ⁻¹`), multiply by B, add the new letter. O(1), however long the window.
- **Prefix hashes.** Store `h[i]`, the hash of the first i letters, and `pw[i] = Bⁱ`. Then **any** substring's hash is `h[r] − h[l]·pw[r − l]` (mod M), in O(1). It's chapter 4's prefix sums, for strings.

**Rabin-Karp** search hashes the pattern once, then rolls a window along the text, comparing numbers. A hash match is either a real match or a **collision**. With a small M, check the letters. With M = 2⁶¹ − 1 and a fixed base, a collision is about one in 10¹⁸ per comparison, so many contest solutions skip the check. But a Codeforces "anti-hash" test can break a **known, fixed** base. Pick the base at random, or use two hashes, when someone could be attacking you.

Python's big integers make `% MOD` exact with no overflow worries. In C++ you'd use unsigned 64-bit tricks for 2⁶¹ − 1.

```run
title: Prefix hashes: any substring in O(1)
class PrefixHash:
    def __init__(self, s):
        n = len(s)
        self.h = [0] * (n + 1)
        self.pw = [1] * (n + 1)
        for i, c in enumerate(s):
            self.h[i + 1] = (self.h[i] * BASE + ord(c)) % MOD
            self.pw[i + 1] = self.pw[i] * BASE % MOD

    def get(self, l, r):                 # hash of s[l:r]
        return (self.h[r] - self.h[l] * self.pw[r - l]) % MOD

s = "abracadabra"
ph = PrefixHash(s)
print(ph.get(0, 4) == ph.get(7, 11), s[0:4], s[7:11])
print(ph.get(0, 3) == ph.get(5, 8), s[0:3], s[5:8])
print(ph.get(0, 11) % 1000)
```

```exercise
title: rabin_karp
kind: write
---prompt
Write `rabin_karp(text, pat)`: every start where `pat` occurs, by rolling a window hash along the text. Confirm each hash match with a slice, so a collision can never fool you. 300,000 letters.
---starter
def rabin_karp(text, pat):
    m = len(pat)
    hp = sum(map(ord, pat))
    return [i for i in range(len(text) - m + 1) if sum(map(ord, text[i:i + 2])) == hp]
---solution
def rabin_karp(text, pat):
    m = len(pat)
    if m > len(text):
        return []
    top = pow(BASE, m - 1, MOD)
    hp = hw = 0
    for i in range(m):
        hp = (hp * BASE + ord(pat[i])) % MOD
        hw = (hw * BASE + ord(text[i])) % MOD
    out = [0] if hw == hp and text[:m] == pat else []
    for i in range(m, len(text)):
        hw = ((hw - ord(text[i - m]) * top) * BASE + ord(text[i])) % MOD
        if hw == hp and text[i - m + 1:i + 1] == pat:
            out.append(i - m + 1)
    return out
---tests
assert rabin_karp("abracadabra", "abra") == [0, 7]
assert rabin_karp("aaaa", "aa") == [0, 1, 2]
assert rabin_karp("ab", "abc") == []
r = rabin_karp(word(300000, 5, 2), "abbaabab")
assert len(r) == 1128 and sum(r) == 168837155
---hint
The starter's "hash" is a sum of letters, which ignores order (and it only sums two). A polynomial hash keeps order: each letter sits at its own power of the base.
```

## Hashing in interviews

```exercise
title: longest_duplicate_substring
kind: write
---prompt
*LeetCode 1044, a hard one asked at Google and Amazon.* Return the longest substring that occurs at least twice (occurrences may overlap), or `""`. If a repeat of length L exists, one of length L − 1 does too, so **binary search on L** (chapter 10). For a given L, put every window's hash in a dict and look for a repeat (confirm with a slice). 30,000 letters.
---starter
def longest_dup(s):
    for i in range(len(s) - 1):
        if s[i] == s[i + 1]:
            return s[i]
    return ""
---solution
def longest_dup(s):
    n = len(s)
    h, pw = [0] * (n + 1), [1] * (n + 1)
    for i, c in enumerate(s):
        h[i + 1] = (h[i] * BASE + ord(c)) % MOD
        pw[i + 1] = pw[i] * BASE % MOD
    def find(L):
        seen = {}
        for i in range(n - L + 1):
            k = (h[i + L] - h[i] * pw[L]) % MOD
            if k in seen and s[seen[k]:seen[k] + L] == s[i:i + L]:
                return i
            seen.setdefault(k, i)
        return -1
    lo, hi, best = 1, n - 1, ""
    while lo <= hi:
        mid = (lo + hi) // 2
        i = find(mid)
        if i >= 0:
            best, lo = s[i:i + mid], mid + 1
        else:
            hi = mid - 1
    return best
---tests
assert longest_dup("banana") == "ana"
assert longest_dup("abcd") == ""
assert longest_dup("aaaaa") == "aaaa", "overlapping copies count"
w = word(30000, 6, 4)
r = longest_dup(w)
assert len(r) == 14 and w.find(r) != w.rfind(r), "any repeat of the longest length is fine"
assert len(longest_dup(word(30000, 7, 2))) == 31
---hint
Binary search the length; each check is one O(n) pass of rolling hashes into a dict.
```

```exercise
title: repeated_dna
kind: write
---prompt
*LeetCode 187, asked at LinkedIn and Amazon.* Return, sorted, every 10-letter sequence that occurs more than once in a DNA string. Roll a hash over 10-letter windows and remember which hashes you've seen. 200,000 letters.
---starter
def repeated_dna(s, k=10):
    out = set()
    for i in range(0, len(s) - k + 1, k):
        if s.count(s[i:i + k]) > 1:
            out.add(s[i:i + k])
    return sorted(out)
---solution
def repeated_dna(s, k=10):
    seen, twice, h = set(), set(), 0
    top = pow(BASE, k - 1, MOD)
    for i, c in enumerate(s):
        if i >= k:
            h = (h - ord(s[i - k]) * top) % MOD
        h = (h * BASE + ord(c)) % MOD
        if i >= k - 1:
            if h in seen:
                twice.add(s[i - k + 1:i + 1])
            seen.add(h)
    return sorted(twice)
---tests
assert repeated_dna("AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT") == ["AAAAACCCCC", "CCCCCAAAAA"]
assert repeated_dna("AAAAAAAAAAAAA") == ["AAAAAAAAAA"]
dna = "".join("ACGT"[x * 4 // 1000] for x in lcg(200000, 8, 1000))
r = repeated_dna(dna)
assert len(r) == 16778 and r[0] == "AAAAAACTGT" and r[-1] == "TTTTTTTTCA"
---hint
The starter only checks windows that start at multiples of 10. Every start counts, and `count` on each is O(n²).
```

```exercise
title: shared_shingles
kind: write
---prompt
Write `shared(a, b, k)`: how many **distinct** k-letter runs appear in both `a` and `b`. Use hashes, not the substrings themselves.
---starter
def shared(a, b, k):
    return len(set(a.split()) & set(b.split()))
---solution
def shared(a, b, k):
    def shingles(s):
        n = len(s)
        h, pw = [0] * (n + 1), [1] * (n + 1)
        for i, c in enumerate(s):
            h[i + 1] = (h[i] * BASE + ord(c)) % MOD
            pw[i + 1] = pw[i] * BASE % MOD
        return {(h[i + k] - h[i] * pw[k]) % MOD for i in range(n - k + 1)}
    return len(shingles(a) & shingles(b))
---tests
assert shared("the cat sat on the mat", "the cat sat on a mat", 4) == 13
assert shared("abc", "xyz", 2) == 0 and shared("aaaa", "aa", 2) == 1
doc = word(50000, 9, 3)
copy = doc[:20000] + word(10000, 10, 3) + doc[30000:]
assert shared(doc, copy, 12) == 38703
---hint
A set of window hashes per document; the answer is the size of their intersection.
```

```exercise
title: jaccard_similarity
kind: write
---prompt
Write `similarity(a, b, k)`: |A ∩ B| / |A ∪ B| for the sets of k-letter shingle hashes, rounded to 4 places.
---starter
def similarity(a, b, k):
    return round(sum(x == y for x, y in zip(a, b)) / max(len(a), len(b)), 4)
---solution
def similarity(a, b, k):
    def shingles(s):
        n = len(s)
        h, pw = [0] * (n + 1), [1] * (n + 1)
        for i, c in enumerate(s):
            h[i + 1] = (h[i] * BASE + ord(c)) % MOD
```

## Rebuild it and explain it

```exercise
title: hash_rebuild
kind: rebuild
---prompt
From memory: `same(s, queries)` where each query is `(a, b, L)`. Return a list of booleans: is `s[a:a+L] == s[b:b+L]`? Use prefix hashes, O(1) per query.
---starter
def same(s, queries):
    pass
---solution
def same(s, queries):
    n = len(s)
    h, pw = [0] * (n + 1), [1] * (n + 1)
    for i, c in enumerate(s):
        h[i + 1] = (h[i] * BASE + ord(c)) % MOD
        pw[i + 1] = pw[i] * BASE % MOD
    get = lambda l, r: (h[r] - h[l] * pw[r - l]) % MOD
    return [get(a, a + L) == get(b, b + L) for a, b, L in queries]
---tests
assert same("abracadabra", [(0, 7, 4), (0, 1, 3), (1, 8, 3), (2, 2, 5)]) == [True, False, True, True]
---hint
Prefix hashes and powers, then compare `h[a+L] − h[a]·pw[L]` with the same for b.
```

```recall
Q: Explain rolling hashes: how a polynomial hash is defined, how a window rolls in O(1), how prefix hashes give any substring's hash, what collisions are and how to guard against them, and two problems hashing solves.
A: A polynomial hash reads the letters as digits in base B, modulo a large prime M: hash(s) = s₀·Bᵐ⁻¹ + … + sₘ₋₁ (mod M), so order matters (a sum of letters would not). To slide a window one place, subtract the leaving letter times Bᵐ⁻¹, multiply by B, and add the new letter, which is O(1) per step. Rabin-Karp searches this way in O(n + m). Prefix hashes store h[i] for the first i letters and pw[i] = Bⁱ, and the hash of s[l:r] is h[r] − h[l]·pw[r − l] mod M, so any two substrings compare in O(1). Different strings can share a hash (a collision). With M near 2⁶¹ that's about a 1 in 10¹⁸ chance per comparison. Guard against it by confirming matches by slicing, using two hashes, or picking a random base so anti-hash tests can't be prepared. Hashing finds the longest duplicate substring (binary search on the length, with a set of window hashes), finds repeated DNA windows, and measures document similarity with shingles and Jaccard.
```
