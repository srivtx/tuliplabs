## Ranges that keep changing

Part 6 is about answering questions about **ranges**: sums, minimums and counts inside `[l, r]`, and later, patterns inside strings.

Prefix sums (chapter 4) answer "sum of `l..r`" in O(1), but only while the array **doesn't change**: one update shifts every prefix after it, O(n). With 10⁵ updates and 10⁵ queries mixed together, both the naive loop and prefix sums cost about 10¹⁰.

A **segment tree** keeps the sum of every aligned block: each pair, each four, each eight, up to the whole array.

```viz
name: ds-segtree
title: Eight range jobs on 16 numbers
goal: Run **cell by cell** to the end, then run **segment tree** and compare the work.
height: 470
Any range is a few whole blocks glued together. An update touches one block per level.
```

The **iterative** version is short and fast in Python. Put the leaves at `t[n..2n−1]`, and node `i` is the sum of nodes `2i` and `2i + 1`:

- **Build**: `for i from n − 1 down to 1: t[i] = t[2i] + t[2i + 1]`. O(n).
- **Update** position `p`: set `t[p + n]`, then walk up: `p //= 2` and recompute, until the root. O(log n).
- **Query** `[l, r)`: start `l += n, r += n`. While `l < r`: if `l` is odd, take `t[l]` and `l += 1`; if `r` is odd, `r −= 1` and take `t[r]`; then halve both. O(log n).

Any **associative** operation works: sum, min, max, gcd, product mod M, even a custom summary. Use the right "empty" value: 0 for sum, `inf` for min.

```run
title: An iterative segment tree for sums
class SegTree:
    def __init__(self, a):
        self.n = len(a)
        self.t = [0] * self.n + list(a)
        for i in range(self.n - 1, 0, -1):
            self.t[i] = self.t[2 * i] + self.t[2 * i + 1]

    def update(self, p, value):
        p += self.n
        self.t[p] = value
        while p > 1:
            p //= 2
            self.t[p] = self.t[2 * p] + self.t[2 * p + 1]

    def query(self, l, r):          # sum of a[l..r], inclusive
        res, l, r = 0, l + self.n, r + self.n + 1
        while l < r:
            if l & 1:
                res += self.t[l]
                l += 1
            if r & 1:
                r -= 1
                res += self.t[r]
            l //= 2
            r //= 2
        return res

st = SegTree([5, 3, 8, 6, 1, 4, 7, 2])
print(st.query(1, 6), st.query(0, 7))
st.update(3, 100)
print(st.query(1, 6))
```

---starter

---solution
def count_smaller(nums):
    vals = sorted(set(nums))
    rank = {v: i for i, v in enumerate(vals)}
    m = len(vals)
    t = [0] * (2 * m)
    out = []
    for x in reversed(nums):
        lo, hi, c = m, m + rank[x], 0
        while lo < hi:
            if lo & 1:
                c += t[lo]
                lo += 1
            if hi & 1:
                hi -= 1
                c += t[hi]
            lo //= 2
            hi //= 2
        out.append(c)
        i = rank[x] + m
        while i:
            t[i] += 1
            i //= 2
    return out[::-1]

---prompt

---starter
def kth_present(n, ops):
    seen, out = [], []
    for op, x in ops:
        if op == "add":
            seen.append(x)
        elif op == "kth":
            s = sorted(set(seen))
            out.append(s[x - 1] if x <= len(s) else -1)
    return out
---solution
def kth_present(n, ops):
    size = 1
    while size < n:
        size *= 2
    t = [0] * (2 * size)
    out = []
    for op, x in ops:
        if op == "add" or op == "remove":
            i = x + size
            want = 1 if op == "add" else 0
            if t[i] != want:
                d = 1 if want else -1
                while i:
                    t[i] += d
                    i //= 2
        else:
            if t[1] < x:
                out.append(-1)
                continue
            i, k = 1, x
            while i < size:
                if t[2 * i] >= k:
                    i = 2 * i
                else:
                    k -= t[2 * i]
                    i = 2 * i + 1
            out.append(i - size)
    return out
---tests

    m = k % 4
    if m < 2:
        ops.append(("add", g[k]))
    elif m == 2:
        ops.append(("remove", g[k - 1]))
    else:
        ops.append(("kth", 1 + g[k] % 500))

def best_trade(prices, ops):
    E = (float("inf"), float("-inf"), 0)
    def merge(a, b):
        return (min(a[0], b[0]), max(a[1], b[1]), max(a[2], b[2], b[1] - a[0]))
    n = len(prices)
    t = [E] * n + [(p, p, 0) for p in prices]
    for i in range(n - 1, 0, -1):
        t[i] = merge(t[2 * i], t[2 * i + 1])
    out = []
    for op in ops:
        if op[0] == "set":
            p = op[1] + n
            t[p] = (op[2], op[2], 0)
            while p > 1:
                p //= 2
                t[p] = merge(t[2 * p], t[2 * p + 1])

            l, r, L, R = op[1] + n, op[2] + n + 1, E, E

                if l & 1:
                    L = merge(L, t[l])
                    l += 1
                if r & 1:
                    r -= 1
                    R = merge(t[r], R)
                l //= 2
                r //= 2
            out.append(merge(L, R)[2])
    return out

```recall
Q: Explain why prefix sums fail with updates, how an iterative segment tree is laid out, how its update and query work and why they are O(log n), and how custom nodes extend it.
A: Prefix sums answer static range sums in O(1), but one update changes every prefix after it, O(n). A segment tree stores the combined value of every aligned block of 1, 2, 4, 8, … cells: in the iterative layout the leaves sit at t[n..2n−1] and node i is op(t[2i], t[2i + 1]), built bottom-up in O(n) with 2n memory. An update writes the leaf and walks up through the parents, one per level, recomputing each. A query on [l, r) moves l and r up level by level, taking t[l] when l is a right child and t[r − 1] when r is, so it combines at most about two blocks per level. Both are O(log n). Any associative operation works, such as sum, min, max or gcd, with a matching empty value; a custom node like (low, high, best) needs an order-preserving query with separate left and right results. A count tree can also be walked from the root to find the k-th present item.
```
