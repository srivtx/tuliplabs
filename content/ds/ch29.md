## Choosing under a budget

You have a bag that holds `W` kg and some items, each with a weight and a value. Take each item **whole or not at all** (that's the "0/1"). What's the most value that fits?

Trying every subset is 2ⁿ. Grabbing the best value per kilo first is fast, but watch what it does here:

```viz

title: A 10 kg bag: greedy against a DP table
goal: Run **greedy** to the end, then run **DP table** and compare the bags.
height: 460
Four items; each is in the bag or not.
```

The DP state is two numbers: `dp[i][c]` = the best value using only the first `i` items with capacity `c`. For item `i` (weight `w`, value `v`):

- **skip it**: `dp[i − 1][c]`
- **take it** (if `w ≤ c`): `dp[i − 1][c − w] + v`

`dp[i][c]` is the larger. The answer is `dp[n][W]`. That's `n × W` cells, so O(n·W) time: fast when `W` is small, which is why it's called **pseudo-polynomial**.

```run
title: The table, then the walk back
def knapsack(weights, values, cap):
    n = len(weights)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        w, v = weights[i - 1], values[i - 1]
        for c in range(cap + 1):
            dp[i][c] = dp[i - 1][c]
            if w <= c:
                dp[i][c] = max(dp[i][c], dp[i - 1][c - w] + v)
    taken, c = [], cap
    for i in range(n, 0, -1):
        if dp[i][c] != dp[i - 1][c]:
            taken.append(i - 1)
            c -= weights[i - 1]
    return dp[n][cap], taken[::-1]

print(knapsack([6, 5, 5, 2], [30, 20, 20, 6], 10))
```

## The ladder

Each row of the table only reads the row above it, so one row is enough, **if** you loop capacity **downwards**. Going down, `dp[c − w]` still holds the previous row's value when you read it.

```exercise
title: knapsack_01
kind: write
---prompt
Return the best total value of items fitting in `cap`, each used at most once. Use a single list `dp` of length `cap + 1` and, for each item, loop `c` from `cap` down to `w`.
---starter
def knapsack(weights, values, cap):
    total = used = 0
    for w, v in sorted(zip(weights, values), key=lambda p: -p[1] / p[0]):
        if used + w <= cap:
            used += w
            total += v
    return total
---solution
def knapsack(weights, values, cap):
    dp = [0] * (cap + 1)
    for w, v in zip(weights, values):
        for c in range(cap, w - 1, -1):
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]
---tests

assert knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7) == 9

---hint
```

## Knapsacks in disguise

Three families:

| Kind | Each item | Loop | Example |
|---|---|---|---|
| **0/1** | at most once | capacity **down** | partition, target sum |
| **Unbounded** | any number of times | capacity **up** | coin change |
| **Counting** | combine with `+` instead of `max` | coins **outside**, amounts inside, to count combinations | coin change II |

Often there's no bag in the story. "Can these numbers be split into two equal halves?" is "can some subset weigh exactly half?": a knapsack with true/false cells.

```exercise
title: partition_equal_subset
kind: write
---prompt
*LeetCode 416, asked at Meta, Amazon and Apple.* Can `nums` be split into two groups with equal sums? If the total is odd, no. Otherwise ask whether some subset sums to half: a boolean 0/1 knapsack.
---starter
def can_partition(nums):
    return sum(nums) % 2 == 0
---solution
def can_partition(nums):
    s = sum(nums)
    if s % 2:
        return False
    half = s // 2
    ok = [True] + [False] * half
    for x in nums:
        for c in range(half, x - 1, -1):
            ok[c] = ok[c] or ok[c - x]
    return ok[half]
---tests
assert can_partition([1, 5, 11, 5])
assert not can_partition([1, 2, 3, 5])
assert can_partition([2, 2, 1, 1])
assert not can_partition([1, 2, 5])
assert can_partition([3, 3, 3, 4, 5])
---hint
`ok[c]` = "some subset seen so far sums to c". Loop down so each number is used once.
```

```exercise
title: target_sum
kind: write
---prompt
*LeetCode 494, asked at Meta and Google.* Put `+` or `−` in front of every number in `nums`. Count the ways the result equals `target`. Keep a dictionary from "sum so far" to "number of ways", and update it for each number.
---starter
def find_target_ways(nums, target):
    return 1 if sum(nums) == target else 0
---solution
def find_target_ways(nums, target):
    ways = {0: 1}
    for x in nums:
        nxt = {}
        for s, k in ways.items():
            nxt[s + x] = nxt.get(s + x, 0) + k
            nxt[s - x] = nxt.get(s - x, 0) + k
        ways = nxt
    return ways.get(target, 0)
---tests

assert find_target_ways([1], 1) == 1
```

```exercise
title: ones_and_zeroes
kind: write
---prompt
*LeetCode 474, asked at Google.* Each string uses some `0`s and `1`s. Pick as many strings as possible using at most `m` zeros and `n` ones in total. A knapsack with **two** capacities: `dp[i][j]`, both loops downwards.
---starter
def max_strings(strs, m, n):
    picked = 0
    for s in sorted(strs, key=len):
        z, o = s.count("0"), s.count("1")
        if z <= m and o <= n:
            m -= z
            n -= o
            picked += 1
    return picked + 1
---solution
def max_strings(strs, m, n):
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for s in strs:
        z = s.count("0")
        o = len(s) - z
        for i in range(m, z - 1, -1):
            for j in range(n, o - 1, -1):
                dp[i][j] = max(dp[i][j], dp[i - z][j - o] + 1)
    return dp[m][n]
---tests
assert max_strings(["10", "0001", "111001", "1", "0"], 5, 3) == 4
assert max_strings(["10", "0", "1"], 1, 1) == 2
assert max_strings(["111"], 1, 1) == 0
---hint
Same as one capacity, with one more nested loop. Every string is worth 1.
```

```exercise
title: last_stone_weight
kind: write
---prompt
*LeetCode 1049, asked at Google.* Smash stones together (two stones `x ≤ y` leave `y − x`) until at most one is left. Return the smallest possible final weight. It's splitting the stones into two piles as evenly as you can: find the biggest subset sum that's at most half the total.
---starter
def last_stone(stones):
    s = sorted(stones)
    while len(s) > 1:
        y, x = s.pop(), s.pop()
        if y != x:
            s.append(y - x)
            s.sort()
    return s[0] if s else 0
---solution
def last_stone(stones):
    total = sum(stones)
    half = total // 2
    ok = [True] + [False] * half
    for x in stones:
        for c in range(half, x - 1, -1):
            ok[c] = ok[c] or ok[c - x]
    best = max(c for c in range(half + 1) if ok[c])
    return total - 2 * best
---tests
assert last_stone([2, 7, 4, 1, 8, 1]) == 1
assert last_stone([31, 26, 33, 21, 40]) == 5
assert last_stone([1]) == 1
---hint
Every smash puts one stone on the "plus" side and one on the "minus" side. The result is |pile A − pile B|.
```

## Quick-fire: lock it in

```quiz
In a one-row 0/1 knapsack, why must capacity loop downwards?
- It's faster
* So `dp[c − w]` still holds the previous item's row, and the current item isn't used twice
- To find the items afterwards
- Because weights are sorted
> Upwards makes it the unbounded knapsack.
```

```quiz
Coin change II counts combinations. Which loop goes outside?
* The coins
- The amounts
- Either, the answer is the same
- Neither; it needs recursion
> Amounts outside counts orderings (permutations) instead.
```

```quiz
Why is O(n · W) called pseudo-polynomial?
- It's only approximately correct
* It's polynomial in the value W, but W can be exponential in the number of digits used to write it
- It uses randomness
- It only works for small n
> A capacity of 10¹⁸ makes the table impossible.
```

```quiz
"Can nums be split into two equal-sum halves?" becomes which knapsack?
- Unbounded, maximise value
* 0/1 with true/false cells: can a subset reach sum / 2?
- Counting combinations
- It isn't a knapsack
> Equal halves means one half sums to exactly total / 2.
```

```quiz
How do you recover which items the 0/1 knapsack took?
- Re-run greedy
* Walk back from dp[n][W]: if dp[i][c] differs from dp[i − 1][c], item i was taken, so subtract its weight
- Store the items in each cell
- Sort the table
> The full 2D table is needed for this walk; the one-row version loses it.
```

## Real-world project: a marketing budget planner

```project
title: Spend the budget where it reaches the most people
client: A small marketing agency choosing which ad placements to buy for a client with a fixed budget
skills: 0/1 knapsack, rebuilding the choice, knapsack over the value dimension
---brief
Build `budget.py`. Each placement has a cost (in £100 units) and an estimated reach. Pick placements (each at most once) to maximise reach within budget, and report **which** ones. Then answer the reverse question the client always asks: "what's the least we can spend to reach at least N people?", which is a knapsack where the reach is the capacity.
---why
Ad buying, cloud cost planning, picking features for a release, cargo loading and portfolio-style selection under a cap are knapsacks. Planners show the chosen set, not just the number.
---milestones
- Read placements as (cost, reach)
- Fill the full table
- Walk back for the chosen placements
- Minimum cost to reach a target
---stretch
- Some placements require another one (bundles)
- Two budgets at once: money and staff hours
```

```exercise
title: plan_budget
kind: write
---prompt
Return `(best_reach, chosen)` where `chosen` is the sorted list of placement indexes. Use the full 2D table so you can walk back; when skipping gives the same reach, prefer skipping.
---starter
def plan_budget(costs, reach, budget):
    chosen, spent, total = [], 0, 0
    for i in sorted(range(len(costs)), key=lambda i: -reach[i]):
        if spent + costs[i] <= budget:
            chosen.append(i)
            spent += costs[i]
            total += reach[i]
    return total, sorted(chosen)
---solution
def plan_budget(costs, reach, budget):
    n = len(costs)
    dp = [[0] * (budget + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for c in range(budget + 1):
            dp[i][c] = dp[i - 1][c]
            if costs[i - 1] <= c:
                dp[i][c] = max(dp[i][c], dp[i - 1][c - costs[i - 1]] + reach[i - 1])
    chosen, c = [], budget
    for i in range(n, 0, -1):
        if dp[i][c] != dp[i - 1][c]:
            chosen.append(i - 1)
            c -= costs[i - 1]
    return dp[n][budget], sorted(chosen)
---tests
assert plan_budget([4, 3, 2, 5], [40, 30, 15, 45], 9) == (85, [0, 1, 2])
assert plan_budget([5, 5, 6], [20, 20, 30], 10) == (40, [0, 1])
assert plan_budget([3], [9], 2) == (0, [])
---hint
The starter buys the biggest reach first: the 45 placement eats the budget.
```

```exercise
title: min_spend_for_reach
kind: write
---prompt
Return the least total cost to reach **at least** `target` people, or -1 if even buying everything isn't enough. Let `dp[t]` = least cost to reach at least `t`; reach beyond `target` counts as `target`, so use `dp[max(0, t − r)] + cost`. Loop `t` downwards (each placement once).
---starter
def min_spend(costs, reach, target):
    return min((c for c, r in zip(costs, reach) if r >= target), default=-1)
---solution
def min_spend(costs, reach, target):
    INF = float("inf")
    dp = [0] + [INF] * target
    for c, r in zip(costs, reach):
        for t in range(target, 0, -1):
            dp[t] = min(dp[t], dp[max(0, t - r)] + c)
    return dp[target] if dp[target] < INF else -1
---tests
assert min_spend([4, 3, 2, 5], [40, 30, 15, 45], 70) == 7
assert min_spend([4, 3, 2, 5], [40, 30, 15, 45], 200) == -1
assert min_spend([5, 1], [10, 3], 3) == 1
assert min_spend([5, 1], [10, 3], 0) == 0
---hint
Swap the roles: reach is the "capacity", cost is what you minimise. Clamp at 0 so overshooting is allowed.
```

## Rebuild it and explain it

```exercise
title: knapsack_rebuild
kind: rebuild
---prompt
From memory: `unbounded(weights, values, cap)`: the best value when each item may be used **any number of times**. One row.
---starter
def unbounded(weights, values, cap):
    pass
---solution
def unbounded(weights, values, cap):
    dp = [0] * (cap + 1)
    for c in range(1, cap + 1):
        for w, v in zip(weights, values):
            if w <= c:
                dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]
---tests
assert unbounded([1, 3, 4], [15, 50, 60], 8) == 130
assert unbounded([5], [10], 4) == 0
assert unbounded([2, 3], [3, 5], 7) == 11
---hint
`dp[c]` = best value with capacity c. The last item added could be any item that fits.
```

```recall
Q: Explain the knapsack family: the 0/1 table and its transition, the one-row trick and loop direction, how to recover the items, and the unbounded and counting variants.
A: In the 0/1 knapsack each item is taken whole or not, and greedy by value per weight can fail. The state dp[i][c] is the best value using the first i items with capacity c; it is the larger of skipping the item, dp[i − 1][c], and taking it if it fits, dp[i − 1][c − w] + v. There are n × W cells, so it is O(nW), pseudo-polynomial because W can be huge. Since each row only reads the row above, one row is enough if capacity loops downwards, so dp[c − w] still holds the previous row and no item is used twice; looping upwards instead gives the unbounded knapsack, where items repeat, as in fewest coins. Walking back from dp[n][W] in the full table recovers the items: if a cell differs from the one above, that item was taken. Counting versions replace max with +; for combinations of coins the coin loop goes outside the amount loop. Many problems are knapsacks in disguise: partitioning into equal halves is a true/false subset-sum knapsack to half the total, target sum counts ways per running sum, two budgets give a 2D capacity, and minimum cost for a target value swaps which quantity is the capacity.
```
