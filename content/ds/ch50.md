## Every suffix, in order

The suffixes of `banana` are `banana`, `anana`, `nana`, `ana`, `na`, `a`. Sort them and write down where each one starts:

| rank | start | suffix |
|---|---|---|
| 0 | 5 | a |
| 1 | 3 | ana |
| 2 | 1 | anana |
| 3 | 0 | banana |
| 4 | 4 | na |
| 5 | 2 | nana |

The **suffix array** is that list of starts: `[5, 3, 1, 0, 4, 2]`. It's just n numbers, but every substring of the text is a prefix of some suffix, so in this sorted list **all copies of any substring sit next to each other**. That turns searching, counting and comparing into binary searches and scans.

Sorting the suffixes as strings is slow: a comparison can read a long way before two suffixes differ, n letters on text like `abab…`.


**Prefix doubling** sorts by the first 1 letter, then 2, then 4, then 8. The trick: once you know the rank of every suffix's first k letters, the first 2k letters of suffix i are two ranks side by side, `(rank[i], rank[i + k])`. A suffix too short for its second half uses −1, which sorts before everything. Sort by that pair, give equal pairs equal ranks, double k, and stop when all ranks differ. That's at most log n rounds, each a sort of n small tuples: O(n log² n), and fast in Python because tuples are compared in C.

Next to it sits the **LCP array**: `lcp[r]` is the length of the longest common prefix of the suffixes at ranks r − 1 and r. **Kasai's algorithm** builds it in O(n) by visiting suffixes in text order: if suffix i shares h letters with its neighbour, suffix i + 1 shares at least h − 1 with its own, so h never drops by more than 1 per step.

```run
title: Suffix array by prefix doubling, and Kasai's LCP
def suffix_array(s):
    n = len(s)
    sa, rk, k = list(range(n)), [ord(c) for c in s], 1
    if n <= 1:
        return sa
    while True:
        key = [(rk[i], rk[i + k] if i + k < n else -1) for i in range(n)]
        sa.sort(key=key.__getitem__)
        nr = [0] * n
        for t in range(1, n):
            nr[sa[t]] = nr[sa[t - 1]] + (key[sa[t]] != key[sa[t - 1]])
        rk = nr
        if rk[sa[-1]] == n - 1 or k >= n:
            return sa
        k *= 2

def lcp_array(s, sa):
    n = len(s)
    rank = [0] * n
    for r, p in enumerate(sa):
        rank[p] = r
    lcp, h = [0] * n, 0
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]:
                h += 1
            lcp[rank[i]] = h
            if h:
                h -= 1
        else:
            h = 0
    return lcp

sa = suffix_array("banana")
print(sa, [("banana")[p:] for p in sa])
print(lcp_array("banana", sa))
```

## Suffix arrays in the wild

```exercise
title: distinct_substrings
kind: write
---prompt
*A CSES and SPOJ classic.* How many **different** non-empty substrings does `s` have? There are n(n + 1)/2 substrings counted with repeats. Suffix `sa[r]` contributes its own length minus the prefix it shares with the suffix before it, so the answer is `n(n+1)/2 − sum(lcp)`.
---starter
def distinct_substrings(s):
    return len(set(s)) + len({s[i:i + 2] for i in range(len(s) - 1)})
---solution
def distinct_substrings(s):
    n = len(s)
    sa, rk, k = list(range(n)), [ord(c) for c in s], 1
    while n > 1:
        key = [(rk[i], rk[i + k] if i + k < n else -1) for i in range(n)]
        sa.sort(key=key.__getitem__)
        nr = [0] * n
        for t in range(1, n):
            nr[sa[t]] = nr[sa[t - 1]] + (key[sa[t]] != key[sa[t - 1]])
        rk = nr
        if rk[sa[-1]] == n - 1 or k >= n:
            break
        k *= 2
    rank = [0] * n
    for r, p in enumerate(sa):
        rank[p] = r
    total, h = 0, 0
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]:
                h += 1
            total += h
            if h:
                h -= 1
        else:
            h = 0
    return n * (n + 1) // 2 - total
---tests
assert distinct_substrings("abaa") == 8
assert distinct_substrings("aaaa") == 4 and distinct_substrings("banana") == 15
assert distinct_substrings("a") == 1
assert distinct_substrings(word(50000, 4, 3)) == 1249576994
assert distinct_substrings("ab" * 20000) == 79999
---hint
You need the sum of the LCP array, nothing else: build the suffix array, then run Kasai and add up h.
```

```exercise
title: longest_common_substring
kind: write
---prompt
*A SPOJ and interview classic.* The longest string that's a substring of both `a` and `b`. Glue them as `a + "\x01" + b` (a separator in neither), build the suffix array and LCP, and look at **neighbouring** suffixes that come from different sides: the biggest such LCP is the answer. Return the substring itself (`""` if none). 30,000 letters each.
---starter
def longest_common(a, b):
    best = ""
    for i in range(len(a)):
        for L in (1, 2, 3):
            if a[i:i + L] in b and L > len(best):
                best = a[i:i + L]
    return best
---solution
def longest_common(a, b):
    s = a + "\x01" + b
    n, na = len(s), len(a)
    sa, rk, k = list(range(n)), [ord(c) for c in s], 1
    while True:
        key = [(rk[i], rk[i + k] if i + k < n else -1) for i in range(n)]
        sa.sort(key=key.__getitem__)
        nr = [0] * n
        for t in range(1, n):
            nr[sa[t]] = nr[sa[t - 1]] + (key[sa[t]] != key[sa[t - 1]])
        rk = nr
        if rk[sa[-1]] == n - 1 or k >= n:
            break
        k *= 2
    rank = [0] * n
    for r, p in enumerate(sa):
        rank[p] = r
    best, at, h = 0, 0, 0
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]:
                h += 1
            if (i < na) != (j < na) and h > best:
                best, at = h, i
            if h:
                h -= 1
        else:
            h = 0
    return s[at:at + best]
---tests

assert longest_common("abc", "xyz") == ""

---hint
```

```project
- The lower edge of a query's block
- Every position of a query

- Use the LCP array to skip letters you've already matched
```

## Rebuild it and explain it

```exercise
title: suffix_rebuild
kind: rebuild
---prompt
From memory: `longest_repeat(s)`, the longest substring that occurs at least twice (copies may overlap), from the suffix array and the LCP array. Return `""` if there's none. If two repeats tie, return the one whose suffix comes first in sorted order.
---starter
def longest_repeat(s):
    pass
---solution
def longest_repeat(s):
    n = len(s)
    sa, rk, k = list(range(n)), [ord(c) for c in s], 1
    while n > 1:
        key = [(rk[i], rk[i + k] if i + k < n else -1) for i in range(n)]
        sa.sort(key=key.__getitem__)
        nr = [0] * n
        for t in range(1, n):
            nr[sa[t]] = nr[sa[t - 1]] + (key[sa[t]] != key[sa[t - 1]])
        rk = nr
        if rk[sa[-1]] == n - 1 or k >= n:
            break
        k *= 2
    rank = [0] * n
    for r, p in enumerate(sa):
        rank[p] = r
    lcp, h = [0] * n, 0
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]:
                h += 1
            lcp[rank[i]] = h
            if h:
                h -= 1
        else:
            h = 0
    if not s:
        return ""
    r = max(range(n), key=lcp.__getitem__)
    return s[sa[r]:sa[r] + lcp[r]]
```

```recall
Q: Explain suffix arrays: what the array and the LCP array hold, how prefix doubling builds the array and why a comparison is O(1), how Kasai builds LCP in O(n), and three problems they solve.
A: The suffix array lists the start positions of all suffixes in sorted order. Every substring is a prefix of some suffix, so all copies of a substring sit in one block of neighbours. Prefix doubling sorts by the first 1, 2, 4… letters. Once each suffix's rank by its first k letters is known, its first 2k letters are the pair (rank[i], rank[i + k]), with −1 for a missing half so it sorts before every real rank (ranks themselves start at 0). Sorting those pairs and re-ranking takes log n rounds, O(n log² n) in all, and each comparison is two small numbers rather than a walk along strings. The LCP array holds the common-prefix length of each pair of neighbouring suffixes. Kasai builds it in O(n) by visiting suffixes in text order and carrying h, which drops by at most 1 per step. Uses: the number of distinct substrings is n(n+1)/2 − sum(lcp); the longest repeat is the largest LCP value; the longest common substring of a and b is the largest LCP between neighbours from different sides of a + separator + b; and finding every occurrence of a pattern takes two binary searches over the suffix array, O(m log n) each.
```
