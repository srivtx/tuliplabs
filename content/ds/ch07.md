## The inward walk

Chapter 3 found a pair summing to a target with a hash set. When the list is **sorted**, there's a way with no extra memory at all: one pointer at each end.

```viz
name: ds-twoptr
title: Every pair against two pointers, on a sorted list
goal: Run **every pair** to the end, then run **two pointers** and compare the number of checks.
height: 440
Step through two pointers slowly and read each line: every check fades one number out for good.
```

Why can't it skip the answer? Say the sum is too small. R points at the biggest number still in play, so L's number plus **anything** left is too small too: L can't be part of any answer, and moving it loses nothing. The same argument works for R when the sum is too big. That "this one can never work, so drop it" reasoning is the heart of the pattern.

Three shapes of two pointers come up again and again:

| Shape | Pointers | Typical problems |
|---|---|---|
| Opposite ends | L from the left, R from the right, meet in the middle | pair sums, palindromes, container with water, 3-sum |
| Slow and fast | both go left to right; fast reads, slow writes | remove items in place, dedupe, compress |
| Two lists | one pointer in each sorted list | merge, intersect, subsequence check |

```exercise
title: pair_sum_sorted
kind: write
---prompt
*LeetCode 167.* `nums` is sorted. Return the indices `(i, j)` with `i < j` and `nums[i] + nums[j] == target`, or `None`. Use O(1) extra memory and O(n) time, n up to 10⁵.
---starter
def pair_sum(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return (i, j)
    return None
---solution
def pair_sum(nums, target):
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target:
            return (l, r)
        if s < target:
            l += 1
        else:
            r -= 1
    return None
---tests

`l, r = 0, len(nums) - 1`. Too small → `l += 1`; too big → `r -= 1`; stop when they meet.
```

```exercise
title: valid_palindrome
kind: write
---prompt
*LeetCode 125, asked everywhere.* A phrase is a palindrome if, keeping only letters and digits and ignoring case, it reads the same both ways. `"A man, a plan, a canal: Panama"` is one. Use two pointers that skip anything that isn't a letter or digit.
---starter
def is_palindrome(s):
    return s == s[::-1]
---solution
def is_palindrome(s):
    l, r = 0, len(s) - 1
    while l < r:
        if not s[l].isalnum():
            l += 1
        elif not s[r].isalnum():
            r -= 1
        elif s[l].lower() != s[r].lower():
            return False
        else:
            l += 1; r -= 1
    return True
---tests
assert is_palindrome("A man, a plan, a canal: Panama")
assert not is_palindrome("race a car")
assert is_palindrome(" ")
assert is_palindrome("")
assert is_palindrome("0P0")
assert not is_palindrome("0P")
---hint
Move L right past non-alphanumerics, R left past non-alphanumerics, then compare `.lower()` of both and step both inward.
```

```exercise
title: container_water
kind: write
---prompt
*LeetCode 11, a top interview question.* `h[i]` is the height of a wall at position i. Two walls and the ground hold water: `min(h[i], h[j]) * (j - i)`. Return the most water any two walls can hold, n up to 10⁵. Start with the widest pair and always move the **shorter** wall inward (moving the taller one can only make things worse: the width shrinks and the height is still capped by the short wall).
---starter
def most_water(h):
    best = 0
    for i in range(len(h)):
        for j in range(i + 1, len(h)):
            best = max(best, min(h[i], h[j]) * (j - i))
    return best
---solution
def most_water(h):
    l, r, best = 0, len(h) - 1, 0
    while l < r:
        best = max(best, min(h[l], h[r]) * (r - l))
        if h[l] < h[r]:
            l += 1
        else:
            r -= 1
    return best
---tests
assert most_water([1, 8, 6, 2, 5, 4, 8, 3, 7]) == 49
assert most_water([1, 1]) == 1
assert most_water([4, 3, 2, 1, 4]) == 16
import random
random.seed(7)
big = [random.randint(1, 10**4) for _ in range(4000)]
r, secs = timed(most_water, big)
assert secs < 0.05, f"{secs:.2f}s: walk inward, moving the shorter wall"
---hint
`best = max(best, min(h[l], h[r]) * (r - l))`, then move whichever of `l` and `r` has the shorter wall.
```

```exercise
title: three_sum
kind: write
---prompt
*LeetCode 15, asked at almost every big company.* Return every **distinct** triple `[a, b, c]` (each sorted, the list of triples sorted) from `nums` with `a + b + c == 0`. Sort once, then fix the first number and run the inward walk on the rest: O(n²) instead of O(n³). Skip repeated values so no triple appears twice.
---starter
def three_sum(nums):
    out = set()
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                if nums[i] + nums[j] + nums[k] == 0:
                    out.add(tuple(sorted((nums[i], nums[j], nums[k]))))
    return sorted(map(list, out))
---solution
def three_sum(nums):
    a = sorted(nums)
    out = []
    for i in range(len(a) - 2):
        if i and a[i] == a[i - 1]:
            continue
        l, r = i + 1, len(a) - 1
        while l < r:
            s = a[i] + a[l] + a[r]
            if s < 0:
                l += 1
            elif s > 0:
                r -= 1
            else:
                out.append([a[i], a[l], a[r]])
                l += 1
                while l < r and a[l] == a[l - 1]:
                    l += 1
                r -= 1
    return out
---tests
assert three_sum([-1, 0, 1, 2, -1, -4]) == [[-1, -1, 2], [-1, 0, 1]]
assert three_sum([0, 0, 0, 0]) == [[0, 0, 0]]
assert three_sum([1, 2]) == []
import random
random.seed(15)
big = [random.randint(-10**5, 10**5) for _ in range(450)]
r, secs = timed(three_sum, big)
s = set()
a = sorted(big)
for i in range(len(a)):
    seen = set()
    for j in range(i + 1, len(a)):
        if -a[i] - a[j] in seen:
            s.add(tuple(sorted((a[i], a[j], -a[i] - a[j]))))
        seen.add(a[j])
assert r == sorted(map(list, s)), "wrong triples"
assert secs < 0.25, f"{secs:.2f}s: fix one number, then walk two pointers on the rest"
---hint
Sort. For each `i` (skipping a value equal to the previous one), walk `l = i + 1`, `r = end` looking for sum `-a[i]`. After a hit, move `l` past any equal values.
```

## Slow and fast: rewriting in place

The fast pointer reads every item; the slow pointer marks where the next **kept** item goes. Everything before `slow` is the answer so far.

```exercise
title: compress
kind: write
---prompt
*LeetCode 443, run-length compression in place.* Rewrite the list of characters so each run becomes the character followed by its count's digits (a run of 1 has no count): `["a","a","b","c","c","c"]` → `["a","2","b","c","3"]`. Change the list in place (`chars[:] = …` is not allowed: write with a slow pointer) and return the new length.
---starter
def compress(chars):
    return len(chars)
---solution
def compress(chars):
    write = read = 0
    while read < len(chars):
        c, start = chars[read], read
        while read < len(chars) and chars[read] == c:
            read += 1
        chars[write] = c
        write += 1
        if read - start > 1:
            for d in str(read - start):
                chars[write] = d
                write += 1
    return write
---tests
a = list("aabccc")
k = compress(a)
assert a[:k] == ["a", "2", "b", "c", "3"] and k == 5
b = list("a")
assert compress(b) == 1 and b == ["a"]
c = list("abbbbbbbbbbbb")
k = compress(c)
assert c[:k] == ["a", "b", "1", "2"]
---hint
`read` scans to the end of each run; `write` puts the character, then the digits of the run length if it's more than 1. `write` never overtakes `read`, so nothing unread gets overwritten.
```

```exercise
title: is_subsequence
kind: write
---prompt
*LeetCode 392.* Is `s` a subsequence of `t` (all of `s`'s letters appear in `t` in the same order, not necessarily next to each other)? One pointer in each string.
---starter
def is_subsequence(s, t):

def is_subsequence(s, t):
    i = 0

        if i < len(s) and s[i] == c:
```

```exercise
title: merge_from_back
kind: write
---prompt
*LeetCode 88.* `a` has `m` real numbers followed by `n` empty slots (zeros); `b` has `n` numbers; both are sorted. Merge `b` into `a` **in place**, filling from the back so nothing gets overwritten before it's used.
---starter
def merge_into(a, m, b, n):
    a[m:] = b
---solution
def merge_into(a, m, b, n):
    i, j, k = m - 1, n - 1, m + n - 1
    while j >= 0:
        if i >= 0 and a[i] > b[j]:
            a[k] = a[i]; i -= 1
        else:
            a[k] = b[j]; j -= 1
        k -= 1
---tests
a = [1, 2, 3, 0, 0, 0]
merge_into(a, 3, [2, 5, 6], 3)
assert a == [1, 2, 2, 3, 5, 6]
a = [0]
merge_into(a, 0, [1], 1)
assert a == [1]
a = [4, 5, 0, 0]
merge_into(a, 2, [1, 2], 2)
assert a == [1, 2, 4, 5]
---hint
Three pointers: the last real item of `a`, the last of `b`, and the last slot. Put the bigger of the two in the slot and step back. Stop once `b` is used up (what's left of `a` is already in place).
```

```exercise
title: pairs_below
kind: write
---prompt
*Codeforces style.* Count pairs `i < j` with `a[i] + a[j] < k`, n up to 10⁵. Sort, then for each L, every R between L and the largest R that works is a valid pair, so count them all in one go.

def pairs_below(a, k):

    s = sorted(a)
```

```exercise
title: reconcile
kind: write
---prompt
`books` and `bank` are **sorted** lists of amounts in cents (duplicates allowed). Pair equal amounts one-to-one and return `(matched, only_books, only_bank)`, each a sorted list. One pass with two pointers.
---starter
def reconcile(books, bank):
    matched = [x for x in books if x in bank]
    return matched, [x for x in books if x not in bank], [x for x in bank if x not in books]
---solution
def reconcile(books, bank):
    i = j = 0
    matched, only_a, only_b = [], [], []
    while i < len(books) and j < len(bank):
        if books[i] == bank[j]:
            matched.append(books[i]); i += 1; j += 1
        elif books[i] < bank[j]:
            only_a.append(books[i]); i += 1
        else:
            only_b.append(bank[j]); j += 1
    return matched, only_a + books[i:], only_b + bank[j:]
---tests
assert reconcile([250, 400, 400, 1200], [250, 400, 999, 1200]) == ([250, 400, 1200], [400], [999])
assert reconcile([], [5]) == ([], [], [5])
assert reconcile([1, 1, 1], [1]) == ([1], [1, 1], [])
---hint
Equal → both match, move both. Smaller one → it has no partner on the other side, record it and move that pointer. Don't forget the tails.
```

## Rebuild it and explain it

```exercise
title: two_ptr_rebuild
kind: rebuild
---prompt
From memory: `pair_sum(nums, target)` on a sorted list, returning `(i, j)` with `i < j`, or `None`, in O(n) time and O(1) memory.
```

```recall
Q: Explain the two-pointer technique: its three shapes, and why the inward walk on a sorted list never misses the answer.
A: Two pointers replace a pair search over every (i, j) with a walk where each step discards something for good. Opposite ends: on a sorted list put L at the start and R at the end; if the sum is too small, L's value is too small even with the biggest remaining partner, so L can never be in an answer and moves right; if too big, R moves left. Each step drops one item, so it's O(n) with O(1) memory; fixing one number first gives 3-sum in O(n²), and the same "drop the side that can't help" idea solves container with most water (move the shorter wall). Slow and fast: fast reads every item, slow marks where the next kept item is written, so everything before slow is the answer so far (remove in place, dedupe, compress). Two lists: one pointer in each sorted list, advancing the smaller (merge, intersect, reconcile, subsequence check); merging into the same array goes from the back. Counting with two pointers adds r − l pairs at once.
```
