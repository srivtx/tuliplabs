```prelude
import time

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(vals, pos=-1):
    dummy = ListNode()
    tail, nodes = dummy, []
    for v in vals:
        tail.next = ListNode(v)
        tail = tail.next
        nodes.append(tail)
    if pos >= 0:
        tail.next = nodes[pos]
    return dummy.next

def to_list(head, limit=100000):
    out = []
    while head and len(out) < limit:
        out.append(head.val)
        head = head.next
    return out

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t
```

## Nodes and next pointers

A **linked list** is a chain of nodes. Each node holds a value and a `next` pointer to the node after it; the last one points to `None`. You only hold the **head**.

| | Array (Python list) | Linked list |
|---|---|---|
| Read item i | O(1) | O(i): walk from the head |
| Insert or remove at the front | O(n): everything shifts | O(1): change one pointer |
| Insert after a node you hold | O(n) | O(1) |

Interviewers love lists because every trick is about **not losing your grip** on a node before you rewire it. Every lesson here uses `build([1, 2, 3])` to make a list and `to_list(head)` to read one back.

```run
title: Walk a list
head = build([3, 1, 4, 1, 5])
node, steps = head, 0
while node:
    print(node.val, "->", node.next.val if node.next else None)
    node = node.next
    steps += 1
print("walked", steps, "nodes")
```

```predict
a = build([1, 2, 3])
b = a.next
a.next = b.next
print(to_list(a), b.val, b.next.val)
```

```quiz
You hold node `x`. Which line removes the node **after** `x` from the list?
- `x = x.next`
- `x.next.next = None`
* `x.next = x.next.next`
- `del x.next`
> Point `x` past its neighbour. Moving `x` itself changes nothing in the list.
```

## Dummy heads and reversing

A **dummy** node in front of the head means "the node before the first one" always exists, so deleting or inserting at the front needs no special case. Return `dummy.next` at the end.

```exercise
title: remove_value
kind: write
---prompt
*LeetCode 203.* Remove every node whose value equals `val` and return the new head. Use a dummy node so removing the head works like removing anything else.
---starter
def remove_value(head, val):
    node = head
    while node and node.next:
        if node.next.val == val:
            node.next = node.next.next
        else:
            node = node.next
    return head
---solution
def remove_value(head, val):
    dummy = ListNode(0, head)
    node = dummy
    while node.next:
        if node.next.val == val:
            node.next = node.next.next
        else:
            node = node.next
    return dummy.next
---tests
assert to_list(remove_value(build([1, 2, 6, 3, 4, 5, 6]), 6)) == [1, 2, 3, 4, 5]
assert to_list(remove_value(build([7, 7, 7, 7]), 7)) == []
assert to_list(remove_value(build([7, 1, 7]), 7)) == [1]
assert to_list(remove_value(None, 1)) == []
---hint
`dummy = ListNode(0, head)`, walk with `node` starting at the dummy, and look at `node.next`. Only move forward when you didn't delete.
```

Reversing is three pointers: `prev` (the reversed part so far), `cur` (the node being moved) and `nxt` (saved **before** you overwrite `cur.next`, or the rest of the list is lost).

```parsons

        nxt = cur.next
        cur.next = prev

    return prev

---tests
assert to_list(reverse(build([1, 2, 3, 4]))) == [4, 3, 2, 1]
```

```exercise
title: merge_two
kind: write
---prompt
*LeetCode 21.* Merge two sorted lists into one sorted list by splicing their nodes together (chapter 6's merge, with pointers). Use a dummy and a tail pointer.
---starter
def merge_two(a, b):
    return build(sorted(to_list(a) + to_list(b)))
---solution
def merge_two(a, b):
    dummy = tail = ListNode()
    while a and b:
        if a.val <= b.val:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a or b
    return dummy.next
---tests

assert to_list(merge_two(None, build([0]))) == [0]
assert merge_two(None, None) is None
---hint
While both have nodes, attach the smaller one to `tail` and advance it. When one runs out, attach the rest of the other in one go.
```

```exercise
title: reverse_between
kind: write
---prompt
*LeetCode 92.* Reverse only positions `left..right` (1-based) and return the head. Walk a pointer to the node **before** position `left` (a dummy helps when `left` is 1), then reverse the next `right - left + 1` nodes and stitch both ends back.
---starter
def reverse_between(head, left, right):
    return head
---solution
def reverse_between(head, left, right):
    dummy = ListNode(0, head)
    before = dummy
    for _ in range(left - 1):
        before = before.next
    prev, cur = None, before.next
    for _ in range(right - left + 1):
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    before.next.next = cur
    before.next = prev
    return dummy.next
---tests

assert to_list(reverse_between(build([1, 2, 3]), 3, 3)) == [1, 2, 3]
---hint
After reversing the slice, `before.next` is still the old first node of the slice, which is now its last: point it at `cur`. Then point `before` at `prev`, the new first.
```

## Fast and slow pointers

Two runners on the same list, one twice as fast. When fast reaches the end, slow is in the **middle**. If there's a loop, fast laps slow and they **meet**.

```exercise
title: middle_node
kind: write
---prompt
*LeetCode 876.* Return the middle node; with two middles, return the **second**. One pass: slow moves 1, fast moves 2, stop when fast can't move.
---starter
def middle(head):
    n = len(to_list(head))
    node = head
    for _ in range((n - 1) // 2):
        node = node.next
    return node
---solution
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow
---tests
assert middle(build([1, 2, 3, 4, 5])).val == 3
assert middle(build([1, 2, 3, 4, 5, 6])).val == 4
assert middle(build([9])).val == 9
---hint
`while fast and fast.next:` move slow once and fast twice. Slow is the answer.
```

```exercise
title: has_cycle
kind: write
---prompt
*LeetCode 141.* Return `True` if the list loops. With O(1) memory: no set of visited nodes. (The starter just walks, so a looping list would run forever; its test gives up after a while.)

def has_cycle(head):
```

```exercise
title: cycle_start
kind: write
---prompt
*LeetCode 142.* Return the node where the loop **starts**, or `None`. Phase 1: tortoise and hare until they meet. Phase 2: one pointer back to the head, both move 1; where they meet is the start. (Why: if the tail is `a` long and they met `b` into the loop of length `L`, then `a` steps from the meeting point also lands on the start, because `a + b` is a whole number of laps.)
---starter
def cycle_start(head):
    seen = []
    while head:
        if head in seen:
            return head
        seen.append(head)
        head = head.next
    return None
---solution
def cycle_start(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p, slow = p.next, slow.next
            return p
    return None
---tests
h = build([3, 2, 0, -4], 1)
assert cycle_start(h) is h.next
h = build([1, 2], 0)
assert cycle_start(h) is h

h = build(list(range(6000)), 300)

assert r.val == 300 and secs < 0.03, f"{secs:.2f}s: use two pointers, not a list of seen nodes"
---hint
Inside the `if slow is fast:` start `p = head`, then move `p` and `slow` one at a time until they're the same node.
```

```exercise
title: palindrome_list
kind: write
---prompt
*LeetCode 234, asked at Amazon and Meta.* Is the list a palindrome? In O(1) extra memory: find the middle, reverse the second half, compare the halves node by node.
---starter
def is_palindrome(head):
    return to_list(head)[0] == to_list(head)[-1] if head else True

def is_palindrome(head):
    slow = fast = head
    while fast and fast.next:

        slow.next = prev

        a, b = a.next, b.next
    return True
```

```exercise
title: reorder_list
kind: write
---prompt
*LeetCode 143.* Reorder `L0 → L1 → … → Ln` into `L0 → Ln → L1 → Ln-1 → …` in place and return the head. It's three tricks in a row: find the middle, reverse the second half, then weave the two halves together.
```

```exercise
title: intersection
kind: write
---prompt
*LeetCode 160.* Two lists may join and share a tail. Return the first shared **node** (or `None`), in O(1) memory. Two pointers: when one falls off its list, send it to the start of the **other** list. Both travel `a + c + b` nodes, so they arrive at the join together.
---starter
def intersection(a, b):
    while a and b:
        if a is b:
            return a
        a, b = a.next, b.next
    return None
---solution
def intersection(a, b):
    p, q = a, b
    while p is not q:
        p = p.next if p else b
        q = q.next if q else a
    return p
---tests
shared = build([8, 4, 5])
a = build([4, 1]); a.next.next = shared
b = build([5, 6, 1]); b.next.next.next = shared

assert intersection(build([1, 2]), build([3])) is None
assert intersection(shared, shared) is shared
---hint
`p = p.next if p else b` (and the same for `q` with `a`). If they never join, both reach `None` at the same moment.
```

## Real-world project: an LRU cache

```project
title: A least-recently-used cache for an image service
client: A small photo-sharing site whose thumbnail server keeps re-rendering the same popular images
skills: hash maps, doubly linked lists, O(1) updates, eviction policies
---brief
Build `lru.py`: a cache with a fixed capacity. `get(key)` returns the value (or -1) and marks it as just used; `put(key, value)` stores it, and when the cache is full it **evicts the least recently used** key. Both must be O(1). A dict finds a node by key; a doubly linked list keeps nodes in use order (most recent at the front), so moving or removing a node is O(1) pointer surgery. Measure the hit rate on a stream of requests where a few images are popular.
---why
Browsers, CDNs, databases and your CPU's cache all evict "the thing not used for longest". This is LeetCode 146, one of the most-asked interview designs at every big company.
---milestones
- A doubly linked list with dummy head and tail
- get and put in O(1)
- Eviction when full
- Hit-rate statistics on a skewed request stream
---stretch
- A time-to-live on each entry
- Compare with Python's functools.lru_cache
```

```exercise
title: lru_cache
kind: write
---prompt
Write `class LRUCache(capacity)` with `get(key)` and `put(key, value)`, both O(1). Keep a dict `key → node` and a doubly linked list with dummy `head` and `tail` nodes; the node just after `head` is the most recent. The starter keeps a list of keys and calls `remove`, which is O(n).
---starter
class LRUCache:
    def __init__(self, capacity):
        self.cap, self.data, self.order = capacity, {}, []

    def get(self, key):
        if key not in self.data:
            return -1
        self.order.remove(key)
        self.order.append(key)
        return self.data[key]

    def put(self, key, value):
        if key in self.data:
            self.order.remove(key)
        elif len(self.data) == self.cap:
            del self.data[self.order.pop(0)]
        self.data[key] = value
        self.order.append(key)
---solution
class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap, self.map = capacity, {}
        self.head, self.tail = Node(), Node()
        self.head.next, self.tail.prev = self.tail, self.head

    def _unlink(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _push_front(self, n):
        n.prev, n.next = self.head, self.head.next
        self.head.next.prev = n
        self.head.next = n

    def get(self, key):
        n = self.map.get(key)
        if not n:
            return -1
        self._unlink(n)
        self._push_front(n)
        return n.val

    def put(self, key, value):
        n = self.map.get(key)
        if n:
            n.val = value
            self._unlink(n)
        else:
            if len(self.map) == self.cap:
                old = self.tail.prev
                self._unlink(old)
                del self.map[old.key]
            n = Node(key, value)
            self.map[key] = n
        self._push_front(n)
---tests
c = LRUCache(2)
c.put(1, 1); c.put(2, 2)
assert c.get(1) == 1
c.put(3, 3)
assert c.get(2) == -1
c.put(4, 4)
assert [c.get(1), c.get(3), c.get(4)] == [-1, 3, 4]
c = LRUCache(1)
c.put(5, 5); c.put(5, 6)
assert c.get(5) == 6
def stress():
    big = LRUCache(6000)
    for i in range(6000):
        big.put(i, i)
    for i in reversed(range(6000)):
        big.get(i)
    return big.get(0)
r, secs = timed(stress)
assert r == 0 and secs < 0.06, f"{secs:.2f}s: list.remove is O(n); unlink a node instead"
---hint
Unlinking a node `n` is `n.prev.next = n.next; n.next.prev = n.prev`. The least recent node is always `tail.prev`. Store the key in the node so eviction can delete it from the dict.
```

```exercise
title: hit_rate
kind: write
---prompt
For the report: given a cache capacity and a list of requested keys, return the fraction of requests that were **hits** (already in the cache) under LRU eviction. Use an `OrderedDict`: `move_to_end(key)` marks it as recent and `popitem(last=False)` evicts the oldest, both O(1) (it's a hash map plus a doubly linked list inside).
---starter
def hit_rate(capacity, requests):
    seen, hits = set(), 0
    for k in requests:
        if k in seen:
            hits += 1
        seen.add(k)
    return hits / len(requests) if requests else 0.0
---solution
from collections import OrderedDict

def hit_rate(capacity, requests):
    cache, hits = OrderedDict(), 0
    for k in requests:
        if k in cache:
            hits += 1
            cache.move_to_end(k)
        else:
            cache[k] = True
            if len(cache) > capacity:
                cache.popitem(last=False)
    return hits / len(requests) if requests else 0.0
---tests
assert hit_rate(2, [1, 2, 1, 3, 1, 2]) == 2 / 6
assert hit_rate(1, [1, 1, 1]) == 2 / 3
assert hit_rate(3, [1, 2, 3, 4, 1]) == 0.0
assert hit_rate(2, []) == 0.0
---hint
A hit moves the key to the end; a miss adds it and, if the cache is now too big, pops the first (oldest) item.
```

```exercise
def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    return prev

def cycle_start(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p, slow = p.next, slow.next
            return p
    return None

---hint
Reverse: save next, point back, step forward. Cycle: meet, then head and meeting point walk together.
```

```recall
Q: Explain how linked-list problems are solved: reversing, dummy heads, fast and slow pointers, and the LRU cache.
A: A singly linked list is nodes with a value and a next pointer, reached from the head. Reading the i-th item is O(i), but inserting or removing next to a node you hold is O(1). The danger is losing the rest of the list when you overwrite a pointer, so save next first: reversal walks prev, cur and nxt, pointing each cur back at prev, and returns prev. A dummy node before the head removes special cases for edits at the front; return dummy.next. Fast and slow pointers solve position questions in one pass and O(1) memory: when fast (2 steps) reaches the end, slow (1 step) is at the middle; a k-node head start finds the k-th from the end; in a loop fast gains one node per step so it lands on slow, and then a pointer from the head and one from the meeting point, moving together, meet at the loop's start. Combining them handles palindromes and reordering (middle, reverse half, compare or weave), and switching lists at the end finds an intersection. An LRU cache pairs a dict from key to node with a doubly linked list in use order, so get, put and eviction of tail.prev are all O(1).
```
