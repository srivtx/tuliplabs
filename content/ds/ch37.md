## The biggest tile

Part 5 is the maths that shows up again and again in contests and in interviews at quant and search companies. It starts with the oldest algorithm still in daily use.

The **greatest common divisor** `gcd(a, b)` is the largest number dividing both. Picture it as the biggest square tile that covers an `a × b` floor exactly:

```viz
name: ds-gcd
title: Tiling a 336 × 210 floor with the biggest squares
goal: Run **try every size** to the end, then run **Euclid** and compare the steps.
height: 430
Any square that tiles both sides also tiles what's left after cutting squares off.
```

**Euclid's algorithm**: `gcd(a, b) = gcd(b, a mod b)`, and `gcd(a, 0) = a`. Every two steps the larger number at least halves, so it's O(log n): about 90 steps for 18-digit numbers. Then:

- `lcm(a, b) = a // gcd(a, b) * b` (divide first to keep numbers small in other languages)
- `gcd` of a list: fold it, `reduce(gcd, nums)`
- a fraction `p/q` in lowest terms: divide both by `gcd(p, q)`

**Extended Euclid** also finds whole numbers `x, y` with `a·x + b·y = gcd(a, b)`. So `a·x + b·y = c` has integer solutions exactly when `gcd(a, b)` divides `c` (**Bézout**). That's why a 3 L and a 5 L jug can measure 4 L, but a 2 L and a 6 L jug can't measure 5 L.

```run
title: Euclid, step by step, and extended Euclid
def gcd_steps(a, b):
    while b:
        print(f"gcd({a}, {b})")
        a, b = b, a % b
    return a

print(gcd_steps(336, 210))

def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0
    d, x, y = ext_gcd(b, a % b)
    return d, y, x - (a // b) * y

d, x, y = ext_gcd(240, 46)
print(d, x, y, "check:", 240 * x + 46 * y)
```

## Working modulo M

Answers like "how many ways" grow astronomically, so problems ask for them **modulo** a prime, usually `M = 1_000_000_007` (it's prime, and the product of two numbers below it fits in 64 bits). The rules:

- `(a + b) % M = ((a % M) + (b % M)) % M`, and the same for `−` and `×`. So reduce **as you go**.
- Subtraction can go negative: write `(a − b) % M`. In Python `%` always returns a value in `[0, M)`; in C++ and Java it doesn't, so add `M` first.
- **Division doesn't work this way.** `(a / b) % M` needs the modular inverse of `b` (chapter 39).

```exercise
title: gcd_and_lcm
kind: write
---prompt
Write `my_gcd(a, b)` with Euclid's loop (no `math.gcd`) and `lcm_all(nums)`, the lowest common multiple of a list, using your `my_gcd`.
---starter
def my_gcd(a, b):
    return min(a, b)

def lcm_all(nums):
    out = 1
    for x in nums:
        out *= x
    return out
---solution
def my_gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def lcm_all(nums):
    out = 1
    for x in nums:
        out = out // my_gcd(out, x) * x
    return out
---tests
assert my_gcd(336, 210) == 42
assert my_gcd(10 ** 18, 6 * 10 ** 17 + 12) == 4
assert my_gcd(0, 5) == 5 and my_gcd(7, 0) == 7
assert lcm_all([4, 6, 10]) == 60
assert lcm_all([7]) == 7
assert lcm_all(list(range(1, 31))) == 2329089562800
---hint
The product counts shared factors twice. `lcm(a, b) = a // gcd(a, b) * b`.
```

## gcd in disguise

```exercise
title: water_jugs
kind: write
---prompt
*LeetCode 365, asked at Microsoft.* Jugs of `x` and `y` litres, unlimited water. Can you end up with exactly `t` litres in total across both jugs? By Bézout: yes if `t` is 0, or `t ≤ x + y` and `gcd(x, y)` divides `t`.
---starter
def can_measure(x, y, t):
    return t <= x + y
---solution
def can_measure(x, y, t):
    if t == 0:
        return True
    return t <= x + y and t % gcd(x, y) == 0
---tests
assert can_measure(3, 5, 4)
assert not can_measure(2, 6, 5)
assert can_measure(1, 2, 3)
assert can_measure(4, 6, 8)
assert can_measure(0, 0, 0)
---hint
Every amount you can make is a combination `a·x + b·y`, so it's a multiple of gcd(x, y).
```

```exercise
title: x_of_a_kind
kind: write
---prompt
*LeetCode 914, asked at Google.* Can the cards be split into groups of the same size `X ≥ 2`, each group all one value? Yes exactly when the gcd of all the value counts is at least 2.
---starter
def has_groups(deck):
    from collections import Counter
    return min(Counter(deck).values()) >= 2
---solution
def has_groups(deck):
    from collections import Counter
    return reduce(gcd, Counter(deck).values()) >= 2
---tests
assert has_groups([1, 2, 3, 4, 4, 3, 2, 1])
assert not has_groups([1, 1, 1, 2, 2, 2, 3, 3])
assert not has_groups([1])
assert has_groups([1, 1, 2, 2, 2, 2])
---hint
Counts 2 and 4 work with groups of 2; counts 2 and 3 don't work with any size. The group size must divide every count.
```

```exercise
title: nth_magical_number
kind: write
---prompt
*LeetCode 878, a hard one asked at Amazon.* A number is magical if it's divisible by `a` or `b`. Return the `n`-th magical number modulo 1,000,000,007. Binary search on the answer (chapter 10): up to `m` there are `m // a + m // b − m // lcm(a, b)` magical numbers.
---starter
def nth_magical(n, a, b):
    return n * min(a, b) % (10 ** 9 + 7)
---solution
def nth_magical(n, a, b):
    M = 10 ** 9 + 7
    l = a // gcd(a, b) * b
    lo, hi = 1, n * min(a, b)
    while lo < hi:
        m = (lo + hi) // 2
        if m // a + m // b - m // l >= n:
            hi = m
        else:
            lo = m + 1
    return lo % M
---tests
assert nth_magical(1, 2, 3) == 2
assert nth_magical(4, 2, 3) == 6
assert nth_magical(5, 2, 4) == 10
assert nth_magical(3, 8, 3) == 8
assert nth_magical(10 ** 9, 40000, 40000) == 999720007
---hint
Numbers divisible by both are counted twice: subtract the multiples of the lcm (inclusion-exclusion, chapter 40).
```

```exercise
title: solve_linear
kind: write
---prompt
Return whole numbers `(x, y)` with `a·x + b·y = c` and the **smallest non-negative** `x`, or `None` if there are none (`a, b > 0`). Use extended Euclid, scale by `c // g`, then shift: all solutions have `x` changing in steps of `b // g`.
---starter
def solve_linear(a, b, c):
    for x in range(c + 1):
        if (c - a * x) % b == 0:
            return x, (c - a * x) // b
    return None
---solution
def solve_linear(a, b, c):
    def ext(a, b):
        if b == 0:
            return a, 1, 0
        d, x, y = ext(b, a % b)
        return d, y, x - (a // b) * y
    g, x, y = ext(a, b)
    if c % g:
        return None
    x *= c // g
    step = b // g
    x %= step
    return x, (c - a * x) // b
---tests
assert solve_linear(6, 10, 8) == (3, -1)
assert solve_linear(3, 5, 1) == (2, -1)
assert solve_linear(4, 6, 7) is None
assert solve_linear(7, 3, 1) == (1, -2)
assert solve_linear(123456789, 987654321, 9) == (109739361, -13717420)
---hint
The starter only tries `x` up to `c`, and the smallest `x` can be far bigger. If `(x, y)` works, so does `(x + b/g, y − a/g)`.
```

## Real-world project: a bus timetable checker

```project
title: When do the buses line up?
client: A transport planner checking whether routes with different frequencies ever depart together, for timed transfers at an interchange
skills: lcm of a list, extended Euclid, the Chinese remainder theorem
---brief
Build `timetable.py`. Buses on several routes all leave the interchange at minute 0 and then every `p` minutes: when do they **all** leave together again? That's the lcm. Then the harder version: route `i` leaves at minutes `r_i, r_i + p_i, r_i + 2p_i, …`. Find the first minute at which every route departs, or say it never happens. That's the Chinese remainder theorem: find `x` with `x ≡ r_i (mod p_i)` for all `i`, merging two conditions at a time with extended Euclid.
---why
Timetables, traffic light cycles, gear and pulley designs, calendar calculations and some cryptography (RSA speed-ups) combine periodic events this way.
---milestones
- lcm of all the periods
- Merge two congruences with extended Euclid
- Detect "never" when two conditions clash
- Merge all routes
---stretch
- Report the next three joint departures
- Allow a tolerance of ±1 minute
```

```exercise
title: all_together_again
kind: write
---prompt
Return the first minute after 0 when all routes depart together, given their periods.
---starter
def together(periods):
    return max(periods)
---solution
def together(periods):
    return reduce(lambda a, b: a // gcd(a, b) * b, periods, 1)
---tests
assert together([4, 6, 10]) == 60
assert together([7]) == 7
assert together([2, 3, 5, 7, 11, 13, 17, 19, 23]) == 223092870
---hint
lcm of a list = fold lcm over it.
```

```exercise
title: first_joint_departure
kind: write
---prompt
Return the smallest `x ≥ 0` with `x % p[i] == r[i]` for every route, or `-1` if none exists. Merge conditions one at a time: from `x ≡ X (mod m)` and `x ≡ r (mod p)`, with `g, s, t = ext(m, p)`: if `(r − X) % g`, it's impossible; otherwise `X += m · ((r − X) // g · s % (p // g))` and `m = lcm(m, p)`.
---starter
def first_joint(r, p):
    x = 0
    while x < 10 ** 5:
        if all(x % pi == ri for ri, pi in zip(r, p)):
            return x
        x += 1
    return -1
---solution
def first_joint(r, p):
    def ext(a, b):
        if b == 0:
            return a, 1, 0
        d, x, y = ext(b, a % b)
        return d, y, x - (a // b) * y
    X, m = 0, 1
    for ri, pi in zip(r, p):
        g, s, _ = ext(m, pi)
        if (ri - X) % g:
            return -1
        l = m // g * pi
        X = (X + m * ((ri - X) // g * s % (pi // g))) % l
        m = l
    return X
---tests
assert first_joint([2, 3, 2], [3, 5, 7]) == 23
assert first_joint([1, 2], [4, 6]) == -1
assert first_joint([0, 0], [4, 6]) == 0
assert first_joint([5, 11], [12, 18]) == 29
assert first_joint([123456, 654321], [1000003, 999983]) == 276539953073
---hint
The starter only searches the first 100,000 minutes. With periods near a million the answer can be near 10¹².
```

## Rebuild it and explain it

```exercise
title: gcd_rebuild
kind: rebuild
---prompt
From memory: add two fractions `a/b + c/d` and return `(numerator, denominator)` in lowest terms with a positive denominator. Zero is `(0, 1)`.
---starter
def add_fractions(a, b, c, d):
    pass
---solution
def add_fractions(a, b, c, d):
    n, den = a * d + c * b, b * d
    g = gcd(n, den)
    n, den = n // g, den // g
    if den < 0:
        n, den = -n, -den
    return n, den
---tests
assert add_fractions(1, 2, 1, 3) == (5, 6)
assert add_fractions(1, 4, 1, 4) == (1, 2)
assert add_fractions(2, 3, -2, 3) == (0, 1)
assert add_fractions(5, 6, 7, 10) == (23, 15)
assert add_fractions(1, -2, 1, 1) == (1, 2)
---hint
`gcd(0, x) = x`, which turns `0/9` into `0/1` for free.
```

```recall
Q: Explain Euclid's algorithm and why it is fast, extended Euclid and Bézout, and the rules for arithmetic modulo M.
A: The gcd of a and b is the largest number dividing both, like the biggest square tile covering an a × b floor. Euclid's algorithm uses gcd(a, b) = gcd(b, a mod b), stopping at gcd(a, 0) = a, because any common divisor also divides the remainder; the larger number at least halves every two steps, so it is O(log n). From it, lcm(a, b) = a // gcd(a, b) · b, the gcd of a list is a fold, and fractions reduce by dividing by the gcd. Extended Euclid also returns x and y with a·x + b·y = gcd(a, b), so a·x + b·y = c has integer solutions exactly when the gcd divides c (Bézout), as in the water-jug puzzle, and the solutions shift x by b/g. Merging congruences pairwise this way is the Chinese remainder theorem. Huge counts are reported modulo a prime such as 1,000,000,007, which keeps products within 64 bits; addition, subtraction and multiplication can be reduced as you go, a difference must be reduced again so it is not negative, and division needs a modular inverse instead.
```
