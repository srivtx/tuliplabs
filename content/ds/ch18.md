```prelude
import time
from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(vals):
    if not vals or vals[0] is None:
        return None
    root = TreeNode(vals[0])
    q, i = [root], 1
    for node in q:
        if i >= len(vals):
            break
        if vals[i] is not None:
            node.left = TreeNode(vals[i])
            q.append(node.left)
        i += 1
        if i < len(vals) and vals[i] is not None:
            node.right = TreeNode(vals[i])
            q.append(node.right)
        i += 1
    return root

def inorder(root):
    return inorder(root.left) + [root.val] + inorder(root.right) if root else []

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t
```

## The search-tree rule

A **binary search tree** (BST) is a binary tree where, for **every** node, everything in its left subtree is smaller and everything in its right subtree is bigger. A search is binary search on a tree: compare, go left or right, repeat.

```
        8
      /   \
     4     12
    / \   /  \
   2   6 10   14
```

Search, insert and delete each walk **one path**, so they cost O(height). Read the keys **inorder** and they come out sorted.

```exercise
title: search_bst
kind: write
---prompt
*LeetCode 700.* Return the node with value `val`, or `None`. Walk down iteratively, one comparison per level: don't search both subtrees.
---starter
def search(root, val):
    if not root:
        return None
    if root.val == val:
        return root
    return search(root.left, val) or search(root.right, val)
---solution
def search(root, val):
    while root and root.val != val:
        root = root.left if val < root.val else root.right
    return root
---tests
t = build_tree([4, 2, 7, 1, 3])
assert search(t, 2).val == 2 and inorder(search(t, 2)) == [1, 2, 3]

def balanced(lo, hi):
    if lo > hi:
        return None

def many():
    return sum(search(big, v) is None for v in range(-300, 0))
```

```exercise
title: insert_bst
kind: write
---prompt
*LeetCode 701.* Insert `val` (not already in the tree) and return the root. Recursively: insert into the correct side and reattach the result; an empty tree becomes a new node.
---starter
def insert(root, val):
    if not root:
        return TreeNode(val)

        root.left = TreeNode(val)
    else:

def insert(root, val):
    if not root:
        return TreeNode(val)
    if val < root.val:

    else:
        root.right = insert(root.right, val)
    return root
---tests

    t = insert(t, v)

`root.left = insert(root.left, val)` handles both "the left side is empty" and "keep walking".
```

```exercise
title: validate_bug
kind: bug
---prompt
*LeetCode 98, asked at Amazon, Meta and Microsoft.* This check only compares each node with its own children, so it accepts `[5, 4, 6, None, None, 3, 7]`: 3 is in 5's **right** subtree but smaller than 5. Fix it by passing down the allowed range `(lo, hi)`.
---starter
def is_bst(root):
    if not root:
        return True
    if root.left and root.left.val >= root.val:
        return False
    if root.right and root.right.val <= root.val:
        return False
    return is_bst(root.left) and is_bst(root.right)
---solution
def is_bst(root, lo=float("-inf"), hi=float("inf")):
    if not root:
        return True
    if not lo < root.val < hi:
        return False
    return is_bst(root.left, lo, root.val) and is_bst(root.right, root.val, hi)
---tests
assert not is_bst(build_tree([5, 4, 6, None, None, 3, 7]))
assert is_bst(build_tree([2, 1, 3]))
assert not is_bst(build_tree([5, 1, 4, None, None, 3, 6]))
assert not is_bst(build_tree([2, 2, 2]))
assert is_bst(None)
---hint
Going left, the node becomes the new upper bound; going right, the new lower bound. Every node must sit strictly inside its range.
```

```exercise
title: kth_smallest
kind: write
---prompt
*LeetCode 230.* Return the k-th smallest key (1-based). Inorder visits keys in sorted order, so stop after k of them. Use an explicit stack so you can stop early without building the whole list.
---starter
def kth_smallest(root, k):
    return inorder(root)[-k]
---solution
def kth_smallest(root, k):
    stack, node = [], root
    while True:
        while node:
            stack.append(node)
            node = node.left
        node = stack.pop()
        k -= 1
        if k == 0:
            return node.val
        node = node.right
---tests
t = build_tree([5, 3, 6, 2, 4, None, None, 1])
assert [kth_smallest(t, k) for k in range(1, 7)] == [1, 2, 3, 4, 5, 6]
assert kth_smallest(build_tree([1]), 1) == 1
---hint
Go as far left as you can, pushing; pop one (that's the next smallest); then do the same from its right child.
```

```exercise
title: lca_bst
kind: write
---prompt
*LeetCode 235.* In a BST, the lowest common ancestor of `p` and `q` is the first node, walking down from the root, whose value lies between them (inclusive). If both are smaller go left; if both are bigger go right. Return its value. O(height), no recursion needed.
---starter
def lca(root, p, q):
    return root.val
---solution
def lca(root, p, q):
    while True:
        if p < root.val and q < root.val:
            root = root.left
        elif p > root.val and q > root.val:
            root = root.right
        else:
            return root.val
---tests
t = build_tree([6, 2, 8, 0, 4, 7, 9, None, None, 3, 5])
assert lca(t, 2, 8) == 6
assert lca(t, 2, 4) == 2
assert lca(t, 3, 5) == 4
assert lca(t, 7, 9) == 8
---hint
Where p and q split to different sides (or one of them is the node), you've found it.
```

```exercise
title: sorted_to_bst
kind: write
---prompt
*LeetCode 108.* Build a **height-balanced** BST from a sorted list: the middle item is the root, the left half builds the left subtree, the right half the right. (This is how you'd rebuild a degenerate tree.)
---starter
def sorted_to_bst(a):
    root = None
    for x in reversed(a):
        root = TreeNode(x, None, root)
    return root
---solution
def sorted_to_bst(a):
    def build(lo, hi):
        if lo > hi:
            return None
        mid = (lo + hi) // 2
        return TreeNode(a[mid], build(lo, mid - 1), build(mid + 1, hi))
    return build(0, len(a) - 1)
---tests
def height(n):
    return 1 + max(height(n.left), height(n.right)) if n else 0
t = sorted_to_bst(list(range(1, 16)))
assert inorder(t) == list(range(1, 16)) and height(t) == 4
t = sorted_to_bst(list(range(1000)))
assert inorder(t) == list(range(1000)) and height(t) == 10
assert sorted_to_bst([]) is None
---hint
Pass index ranges `(lo, hi)` rather than slicing. `None` when the range is empty.
```

```exercise
title: delete_node
kind: write
---prompt
*LeetCode 450.* Delete `key` and return the root. Three cases: a node with no left child is replaced by its right child; no right child, by its left; two children: copy in the smallest key of its right subtree (its **successor**), then delete that key from the right subtree.
---starter
def delete(root, key):
    if not root:
        return None
    if root.val == key:
        return None
    root.left = delete(root.left, key)
    root.right = delete(root.right, key)
    return root
---solution
def delete(root, key):
    if not root:
        return None
    if key < root.val:
        root.left = delete(root.left, key)
    elif key > root.val:
        root.right = delete(root.right, key)
    else:
        if not root.left:
            return root.right
        if not root.right:
            return root.left
        s = root.right
        while s.left:
            s = s.left
        root.val = s.val
        root.right = delete(root.right, s.val)
    return root
---tests
t = build_tree([5, 3, 6, 2, 4, None, 7])
t = delete(t, 3)
assert inorder(t) == [2, 4, 5, 6, 7]
t = delete(t, 5)
assert inorder(t) == [2, 4, 6, 7]
assert inorder(delete(build_tree([5, 3, 6]), 0)) == [3, 5, 6]
assert delete(build_tree([1]), 1) is None
---hint
The starter drops the whole subtree. With two children, the successor is "go right once, then left as far as possible"; it has no left child, so deleting it is an easy case.
```

```exercise
title: range_sum
kind: write
---prompt
*LeetCode 938.* Return the sum of keys within `[lo, hi]`. Use the BST rule to **skip** whole subtrees: if a node is below `lo`, nothing on its left can count.
---starter
def range_sum(root, lo, hi):
    return sum(v for v in inorder(root) if lo <= v <= hi)
---solution
def range_sum(root, lo, hi):
    total, stack = 0, [root]
    while stack:
        n = stack.pop()
        if not n:
            continue
        if lo <= n.val <= hi:
            total += n.val
        if n.val > lo:
            stack.append(n.left)
        if n.val < hi:
            stack.append(n.right)
    return total
---tests
assert range_sum(build_tree([10, 5, 15, 3, 7, None, 18]), 7, 15) == 32
assert range_sum(build_tree([10, 5, 15, 3, 7, 13, 18, 1, None, 6]), 6, 10) == 23
def balanced(lo, hi):
    if lo > hi:
        return None
    m = (lo + hi) // 2
    return TreeNode(m, balanced(lo, m - 1), balanced(m + 1, hi))
big = balanced(0, 20000)
def many():
    return sum(range_sum(big, v, v + 2) for v in range(0, 300))
r, secs = timed(many)
assert r == sum(3 * v + 3 for v in range(300)) and secs < 0.05, f"{secs:.2f}s: skip subtrees that are out of range"
---hint
Only go left if the node is bigger than `lo`, and only go right if it's smaller than `hi`.
```

```exercise
title: floor_price
kind: write
---prompt
Return the largest key `≤ x` in the BST, or `None`. Walk down: when a node is ≤ x it's a candidate and anything bigger is to its right; otherwise go left.
---starter
def floor_key(root, x):
    best = None
    for v in inorder(root):
        if v < x:
            best = v
    return best
---solution
def floor_key(root, x):
    best = None
    while root:
        if root.val <= x:
            best = root.val
            root = root.right
        else:
            root = root.left
    return best
---tests
t = build_tree([100, 95, 104, 90, 98, 102, 110])
assert floor_key(t, 99) == 98
assert floor_key(t, 104) == 104
assert floor_key(t, 89) is None
assert floor_key(t, 500) == 110
---hint
The starter uses `<` and reads the whole tree. Use `<=` and one path down.
```

```exercise
kind: write
---prompt
Each node has `.val` (a price) and `.qty` (shares at that price). Return the total quantity at prices in `[lo, hi]`, skipping subtrees that can't contain any.

def shares_between(root, lo, hi):
```

```recall
Q: Explain binary search trees: the ordering rule, search, insert and delete, validation, and why balance matters.
A: A binary search tree keeps, for every node, all smaller keys in its left subtree and all bigger keys in its right subtree, so inorder traversal lists the keys in sorted order and a search walks one path, going left or right after each comparison. Insert walks the same path and attaches a new leaf; delete replaces a node with one child by that child, and a node with two children takes its inorder successor's key (the leftmost node of its right subtree), which is then deleted from there. Validation must pass bounds down (lo, hi), because comparing only with children misses violations against higher ancestors. An iterative inorder walk with a stack gives the k-th smallest and an iterator; the LCA is the first node whose key lies between p and q; floor, ceiling and range sums prune whole subtrees. Every operation costs O(height): about log₂ n for a balanced tree but n for a chain, which is what sorted insertions produce. Building from a sorted list by taking the middle as the root gives a balanced tree, and self-balancing trees (AVL, red-black, B-trees) keep the height O(log n) under any sequence of operations.
```
