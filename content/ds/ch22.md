## Groups that only ever merge

Lots of problems look like this: things get **joined** one at a time (friendships, cables, equal variables, accounts sharing an email), and you keep asking "are these two in the same group?" and "how many groups are there?". BFS would answer, but rerunning it after every join is far too slow. **Union-find** (also called a **disjoint set union**, DSU) answers both, as the joins arrive, in almost constant time each.

The idea:

- Every item has a **parent**. A root is its own parent, and the root **names** the group.
- `find(x)` follows parents up to the root.
- `union(a, b)` finds both roots and points one at the other.

Two tricks keep the trees flat:

- **Union by size**: hang the smaller tree under the bigger one, so depth grows only when a group at least doubles: O(log n) at worst.
- **Path compression**: after a find, point every node you passed straight at the root.

With both, each operation costs about α(n), the inverse Ackermann function, which is at most 4 for any input that fits in the universe.

```run
title: A complete union-find in 15 lines
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.groups = n

    def find(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.groups -= 1
        return True

d = DSU(6)
for a, b in [(0, 1), (2, 3), (1, 3), (4, 5)]:
    d.union(a, b)
print("groups:", d.groups)
print("0 and 2 together?", d.find(0) == d.find(2))
print("0 and 4 together?", d.find(0) == d.find(4))
print("parents:", d.parent)
```

```exercise
title: count_components
kind: write
---prompt
*LeetCode 323, asked at Google, Meta and LinkedIn.* `n` nodes `0..n-1` and an undirected `edges` list. Return the number of connected components. Use union-find: start with `n` groups and subtract one for every union that actually merges.
---starter
def count_components(n, edges):
    return n - len(edges)
---solution
def count_components(n, edges):
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    groups = n
    for a, b in edges:
        ra, rb = find(a), find(b)
        if ra != rb:
            parent[ra] = rb
            groups -= 1
    return groups
---tests
assert count_components(5, [(0, 1), (1, 2), (3, 4)]) == 2
assert count_components(5, [(0, 1), (1, 2), (2, 3), (3, 4)]) == 1
assert count_components(4, [(0, 1), (1, 2), (2, 0)]) == 2
assert count_components(3, []) == 3
n = 200000
edges = [(i, i + 1) for i in range(0, n - 1, 2)] + [(i, i + 2) for i in range(0, n - 2, 2)] + [(0, 1)] * 5
```

```exercise
def smallest(s, pairs):

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

        parent[find(i)] = find(j)

        groups.setdefault(find(i), []).append(i)

            out[i] = c
    return "".join(out)
```

```exercise
title: islands_online
kind: write
---prompt
*LeetCode 305 "Number of Islands II", asked at Google.* An `rows × cols` sea; `adds` lists cells that turn into land, one at a time. After each, report how many islands there are (4-directional). Re-running BFS each time is too slow; instead give each land cell a DSU node and union it with land neighbours. Adding the same cell twice changes nothing.
---starter
def islands(rows, cols, adds):
    land, out = set(), []
    for cell in adds:
        land.add(cell)
        out.append(len(land))
    return out
---solution
def islands(rows, cols, adds):
    parent, out, count = {}, [], 0
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    for r, c in adds:
        if (r, c) in parent:
            out.append(count)
            continue
        parent[(r, c)] = (r, c)
        count += 1
        for nb in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if nb in parent:
                a, b = find((r, c)), find(nb)
                if a != b:
                    parent[a] = b
                    count -= 1
        out.append(count)
    return out
---tests
assert islands(3, 3, [(0, 0), (0, 1), (1, 2), (2, 1)]) == [1, 1, 2, 3]
assert islands(3, 3, [(0, 0), (0, 2), (0, 1)]) == [1, 2, 1]
assert islands(2, 2, [(0, 0), (0, 0), (1, 1), (0, 1)]) == [1, 1, 2, 1]
assert islands(1, 1, []) == []
---hint
New land is a new island (+1); each union with a *different* neighbouring island merges two into one (−1).
```

```exercise
title: largest_component_by_factor
kind: write
---prompt
*LeetCode 952, a hard one asked at Google.* Numbers are connected if they share a common factor greater than 1. Return the size of the largest connected group. Comparing all pairs is O(n²); instead union each number with each of its **prime factors** (as extra nodes), so numbers sharing a prime meet at that prime.
---starter
def largest(nums):
    from math import gcd
    best = 1
    for a in nums:
        best = max(best, sum(1 for b in nums if gcd(a, b) > 1))
    return best
---solution
def largest(nums):
    parent = {}
    def find(x):
        parent.setdefault(x, x)
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    for v in nums:
        x, p = v, 2
        while p * p <= x:
            if x % p == 0:
                parent[find(("n", v))] = find(("p", p))
                while x % p == 0:
                    x //= p
            p += 1
        if x > 1:
            parent[find(("n", v))] = find(("p", x))
    count = {}
    for v in nums:
        r = find(("n", v))
        count[r] = count.get(r, 0) + 1
    return max(count.values())
---tests
assert largest([4, 6, 15, 35]) == 4
assert largest([20, 50, 9, 63]) == 2
assert largest([2, 3, 6, 7, 4, 12, 21, 39]) == 8
assert largest([1]) == 1
assert largest([7, 11, 13]) == 1
---hint
Tag nodes as `("n", value)` and `("p", prime)` so a number and a prime with the same value don't collide.
```

```exercise
title: merge_records
kind: write
---prompt
`records` is a list of `(id, details)` where `details` is a list of strings. Return the groups as a sorted list of sorted id lists: records sharing any detail, directly or through a chain, are one group.
---starter
def merge(records):
    return [[rid] for rid, _ in sorted(records)]
---solution
def merge(records):
    parent = {rid: rid for rid, _ in records}
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    owner = {}
    for rid, details in records:
        for d in details:
            if d in owner:
                parent[find(rid)] = find(owner[d])
            else:
                owner[d] = rid
    groups = {}
    for rid, _ in records:
        groups.setdefault(find(rid), []).append(rid)
    return sorted(sorted(g) for g in groups.values())
---tests
```

## Rebuild it and explain it

```exercise
title: dsu_rebuild
kind: rebuild
---prompt
From memory: a `DSU(n)` class with `find` (path compression), `union` (by size, returns True if it merged) and a `groups` counter.
---starter
class DSU:
    def __init__(self, n):
        pass
---solution
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.groups = n
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.groups -= 1
        return True
---tests
d = DSU(5)
assert d.union(0, 1) is True
assert d.union(1, 0) is False
assert d.union(2, 3) and d.union(3, 0)
assert d.groups == 2
assert d.find(2) == d.find(1)
assert d.size[d.find(0)] == 4
---hint
Parents, sizes, a counter. Find walks up (halving as it goes); union merges roots, smaller under bigger.
```

```recall
Q: Explain union-find: how it is stored, its two optimisations, its cost and the kinds of problems it solves.
A: Union-find, or disjoint set union, tracks groups that only ever merge. Each item stores a parent pointer; a group is a tree and its root, the one item that is its own parent, names the group. find follows parents to the root, and union finds both roots and points one at the other, returning false if they were already the same, which in a graph means the new edge closes a cycle. Union by size (or rank) hangs the smaller tree under the larger, so depth is at most O(log n); path compression, or path halving, re-points the nodes on a find path toward the root. Together they make each operation run in amortised inverse-Ackermann time, effectively constant. It answers connectivity and group counts as edges arrive, so it is used for counting components, finding the redundant edge, checking equality constraints, grouping swappable positions, online island counting, merging accounts by shared details, and Kruskal's minimum spanning tree. It cannot delete edges directly.
```
