## Counting without listing

"How many numbers from 1 to 10¹⁸ have digit sum 90?" "How many 1s are written in all the numbers up to N?" You can't loop to 10¹⁸. But you can build the number **digit by digit**, from the left, and count how many ways each partial choice can be finished.

```viz
name: ds-digits
title: Numbers up to 4,327 with digit sum 13
goal: Run **check every number** to the end, then run **digit DP** and compare the work.
height: 470
The DP never lists a single number.
```

While you write digits from the left, there are two situations:

- **tight**: every digit so far equals the limit's digit. The next digit can only go up to the limit's next digit.
- **free**: some earlier digit was smaller, so the number is already below the limit. Every later digit can be 0–9.

The template, memoised on `(pos, state, tight)`:

```
def go(pos, state, tight):
    if pos == len(digits): return 1 if state is good else 0
    hi = digits[pos] if tight else 9
    return sum(go(pos + 1, new_state(state, d), tight and d == hi) for d in range(hi + 1))
```

The state is whatever the property needs: a digit sum, a count of 1s, a remainder mod k, a mask of used digits. States × positions × 10 is tiny: 19 positions × 163 sums × 10 for digit sums up to 10¹⁸.

```run
title: The template on the sim's question
def count(n, target):
    digits = list(map(int, str(n)))
    @lru_cache(maxsize=None)
    def go(pos, s, tight):
        if s > target:
            return 0
        if pos == len(digits):
            return 1 if s == target else 0
        hi = digits[pos] if tight else 9
        return sum(go(pos + 1, s + d, tight and d == hi) for d in range(hi + 1))
    return go(0, 0, True)

print(count(4327, 13))
print(count(10 ** 18, 90))
print(sum(1 for x in range(4328) if sum(map(int, str(x))) == 13), "by brute force")
```

## Richer states

The `state` can be anything small:

- **a count** (how many 1s so far)
- **a remainder** (digit sum mod k, or the number itself mod k)
- **a mask** of digits used (all digits distinct): 2¹⁰ masks
- **the previous digit** (no two equal neighbours; no "11" in binary)
- **started** (have we placed a non-zero digit yet?) when leading zeros would break the property

For a range, count `f(hi) − f(lo − 1)`.

```exercise
title: count_digit_one
kind: write
---prompt
*LeetCode 233, a hard one asked at Google and Amazon.* Return the total number of digit `1`s written in all the integers from 0 to `n`. Carry the count of 1s so far as the state and return it at the end.
---starter
def count_ones(n):
    return n // 10 + (1 if n % 10 >= 1 else 0)
---solution
def count_ones(n):
    digits = list(map(int, str(n)))
    @lru_cache(maxsize=None)
    def go(pos, ones, tight):
        if pos == len(digits):
            return ones
        hi = digits[pos] if tight else 9
        return sum(go(pos + 1, ones + (d == 1), tight and d == hi) for d in range(hi + 1))
    return go(0, 0, True)
---tests

assert count_ones(0) == 0
assert count_ones(99) == 20
assert count_ones(2023) == 1613
assert count_ones(10 ** 12) == 1200000000001
---hint
The starter only counts 1s in the last position. Each finished number contributes how many 1s it used.
```

```exercise
title: digits_from_a_set
kind: write
---prompt
*LeetCode 902, a hard one asked at Amazon.* Using only the digits in `digits` (strings, sorted, no 0), how many positive integers ≤ `n` can you write? Shorter numbers are all fine: `k¹ + k² + … + k^(L−1)`. Then walk `n`'s digits: count the smaller allowed digits times `k^(remaining)`, and stop if `n`'s digit isn't allowed. Add 1 if all of `n` was allowed.
---starter
def at_most(digits, n):
    k, L = len(digits), len(str(n))
    return k ** L
---solution
def at_most(digits, n):
    s = str(n)
    L = len(s)
    ds = sorted(int(d) for d in digits)
    k = len(ds)
    total = sum(k ** i for i in range(1, L))
    for i, ch in enumerate(s):
        c = int(ch)
        total += sum(1 for d in ds if d < c) * k ** (L - i - 1)
        if c not in ds:
            return total
    return total + 1
---tests
assert at_most(["1", "3", "5", "7"], 100) == 20
assert at_most(["1", "4", "9"], 1000000000) == 29523
assert at_most(["7"], 8) == 1
assert at_most(["1", "2"], 21) == 5
assert at_most(["5"], 4) == 0
---hint
Here "free" has a closed form: k choices per remaining position. The tight walk ends early when the limit uses a digit you can't.
```

```exercise
title: distinct_digit_numbers
kind: write
---prompt
*LeetCode 2376, a hard one asked at Google.* Count the integers in `[1, n]` whose digits are all different. The state needs a **mask** of used digits and a **started** flag: leading zeros don't count as using the digit 0.
---starter
def count_special(n):
    digits = list(map(int, str(n)))
    @lru_cache(maxsize=None)
    def go(pos, mask, tight):
        if pos == len(digits):
            return 1
        hi = digits[pos] if tight else 9
        return sum(go(pos + 1, mask | 1 << d, tight and d == hi) for d in range(hi + 1) if not mask >> d & 1)
    return go(0, 0, True) - 1
---solution
def count_special(n):
    digits = list(map(int, str(n)))
    @lru_cache(maxsize=None)
    def go(pos, mask, tight, started):
        if pos == len(digits):
            return 1 if started else 0
        hi = digits[pos] if tight else 9
        total = 0
        for d in range(hi + 1):
            if not started and d == 0:
                total += go(pos + 1, mask, tight and d == hi, False)
            elif not mask >> d & 1:
                total += go(pos + 1, mask | 1 << d, tight and d == hi, True)
        return total
    return go(0, 0, True, False)
---tests
assert count_special(20) == 19
assert count_special(5) == 5
assert count_special(135) == 110
assert count_special(1000) == 738
assert count_special(10 ** 9) == 5611770
---hint
The starter treats the leading zeros of 007 as real zeros, so it throws away every short number with a 0 in it... and 7 itself. Track whether the number has started.
```

```exercise
title: no_consecutive_ones
kind: write
---prompt
*LeetCode 600, a hard one asked at Pocket Gems.* Count the integers in `[0, n]` whose **binary** form has no two adjacent 1s. Digit DP in base 2; the state is the previous bit.
---starter
def no_adjacent_ones(n):
    return n // 2 + 1
---solution
def no_adjacent_ones(n):
    bits = list(map(int, bin(n)[2:]))
    @lru_cache(maxsize=None)
    def go(pos, prev, tight):
        if pos == len(bits):
            return 1
        hi = bits[pos] if tight else 1
        total = 0
        for b in range(hi + 1):
            if b == 1 and prev == 1:
                continue
            total += go(pos + 1, b, tight and b == hi)
        return total
    return go(0, 0, True)
---tests
assert no_adjacent_ones(5) == 5
assert no_adjacent_ones(1) == 2
assert no_adjacent_ones(100) == 34
assert no_adjacent_ones(10 ** 9) == 2178309
---hint
Same template with digits 0–1. (The free counts are Fibonacci numbers, which is a nice check.)
```

## Quick-fire: lock it in

```quiz
Why is digit DP fast even for n = 10¹⁸?
- It uses binary search
* The state is (position, small state, tight): about 19 positions × a few hundred states × 10 digits
- Python handles big numbers quickly
- It skips most numbers randomly
> The free part only depends on how many digits are left and the state, not on which number it is.
```

```quiz
How do you count numbers in [lo, hi] with some property?
- Run the DP from lo to hi
* f(hi) − f(lo − 1), where f(x) counts [0, x]
- f(hi) − f(lo)
- f(hi) + f(lo)
> f(lo − 1) removes everything below lo.
```

```quiz
When do you need a "started" flag?
- Always
* When leading zeros would wrongly affect the property, such as "all digits distinct" or "no zero digits"
- Never; leading zeros don't exist
- Only in binary
> For a digit sum, 0042 and 42 agree, so no flag is needed.
```

```quiz
What's the state for "numbers ≤ n divisible by 7"?
- The digit sum
* The remainder of the prefix mod 7: new remainder = (r · 10 + d) % 7
- The last digit
- A mask of digits
> Remainders compose digit by digit.
```

```quiz
Why is the `tight` flag needed at all?
* While the prefix equals the limit's prefix, the next digit can't exceed the limit's digit; otherwise you'd count numbers bigger than n
- To speed up the DP
- To handle negative numbers
- To avoid recursion
> Forgetting it counts every number with that many digits.
```

```exercise
title: checksum_range
kind: write
---prompt
Return how many integers in `[lo, hi]` have digit sum divisible by `k`. Write `f(x)` for `[0, x]` (state: digit sum mod `k`), and return `f(hi) − f(lo − 1)` (with `f(−1) = 0`).
---starter
def valid_in_range(lo, hi, k):
    return (hi - lo + 1) // k
---solution
def valid_in_range(lo, hi, k):
    def f(x):
        if x < 0:
            return 0
        digits = list(map(int, str(x)))
        @lru_cache(maxsize=None)
        def go(pos, r, tight):
            if pos == len(digits):
                return 1 if r == 0 else 0
            top = digits[pos] if tight else 9
            return sum(go(pos + 1, (r + d) % k, tight and d == top) for d in range(top + 1))
        return go(0, 0, True)
    return f(hi) - f(lo - 1)
---tests
assert valid_in_range(1, 20, 3) == 6
assert valid_in_range(10, 99, 5) == 18
assert valid_in_range(0, 0, 7) == 1
assert valid_in_range(123, 4566, 4) == 1111
assert valid_in_range(1, 10 ** 15, 7) == 142857142890619
---hint
Keep the remainder, not the sum: (r + d) % k stays below k, so the state stays small.
```

## Rebuild it and explain it

```exercise
title: digit_dp_rebuild
kind: rebuild
---prompt
From memory: count the integers in `[1, n]` that have **exactly** `k` non-zero digits, for `n` up to 10¹⁸ and small `k`.
---starter
def exactly_k_nonzero(n, k):
    pass
---solution
def exactly_k_nonzero(n, k):
    digits = list(map(int, str(n)))
    @lru_cache(maxsize=None)
    def go(pos, c, tight):
        if c > k:
            return 0
        if pos == len(digits):
            return 1 if c == k else 0
        hi = digits[pos] if tight else 9
        return sum(go(pos + 1, c + (d > 0), tight and d == hi) for d in range(hi + 1))
    return go(0, 0, True)
---tests
assert exactly_k_nonzero(100, 1) == 19
assert exactly_k_nonzero(25, 2) == 14
assert exactly_k_nonzero(314159, 2) == 937
assert exactly_k_nonzero(10 ** 18, 3) == 594864
---hint
Zero has no non-zero digits, so with k ≥ 1 it's never counted: [0, n] and [1, n] give the same answer.
```

```recall
Q: Explain digit DP: what it counts, the (position, state, tight) template, why tight is needed, leading zeros, ranges, and its cost.
A: Digit DP counts the numbers up to a huge limit N, such as 10¹⁸, that have some digit property, without listing them. It builds numbers from the left one digit at a time with a memoised function go(pos, state, tight). While tight, every digit so far equals N's digit, so the next digit can go only up to N's digit; as soon as a smaller digit is placed the number is below N and every later digit is free, 0 to 9. Forgetting tight counts every number with that many digits. The state is whatever the property needs and must stay small: a digit sum, a count of 1s, a remainder (r + d) % k or (r · 10 + d) % k, the previous digit, or a mask of used digits; a started flag stops leading zeros counting as real zeros when that matters, as for distinct digits. At the end the function returns 1 if the state is good, or the accumulated count. Ranges use f(hi) − f(lo − 1). The cost is positions × states × 10, a few thousand to a few million steps, and the free part often has a closed form, like k choices per position for a digit set.
```
