from math import isqrt
sys.setrecursionlimit(10000)

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t

def lcg(n, seed, mx):
    out, x = [], seed
    for _ in range(n):
        x = (x * 1103515245 + 12345) % 2 ** 31
        out.append(x % mx)
    return out

def all_sums(xs):
    """Every subset sum of xs (2^len(xs) of them, with repeats)."""
    sums = [0]
    for x in xs:
        sums += [s + x for s in sums]
    return sums

ITEMS = [3, 34, 4, 12, 5, 2, 27, 9]

## Halfway between brute force and clever

Some problems have no polynomial trick (subset sum is NP-hard), but n is small, say 40. Trying all 2⁴⁰ subsets is a trillion. **Meet in the middle** splits the items into two halves of 20. Each half has only 2²⁰ ≈ a million subsets. List each half's sums, then combine: a subset of everything is a subset of the left half plus a subset of the right.

```viz

```

How you combine depends on the question:

- **Exactly the target?** Put the right sums in a set and look up `target − s` for each left sum.
- **Closest without going over?** Sort the right sums and binary-search for `cap − s`.
- **Count the pairs?** Sort both and walk two pointers, as in the simulation.

Cost: O(2^(n/2) · n). That's the square root of brute force.

**Square-root decomposition** applies the same "split into pieces" idea to arrays. Cut an array of n into blocks of about √n, and keep a total for each block. A range query covers some whole blocks (use their totals, at most √n of them) plus partial blocks at the two ends (at most 2√n cells). An update changes one cell and one block total. Everything costs O(√n): slower than a Fenwick or segment tree's O(log n), but simple, and it bends to odd operations those trees can't easily handle.

```run
title: Both halves, then a set
def has_subset(nums, target):
    h = len(nums) // 2
    right = set(all_sums(nums[h:]))
    return any(target - s in right for s in all_sums(nums[:h]))

print(has_subset(ITEMS, 86), has_subset(ITEMS, 95))
N = lcg(36, 3, 10 ** 9)
found, secs = timed(has_subset, N, sum(N[::3]))
print(f"36 numbers: {found} in {secs:.2f}s (2^36 subsets would be 69 billion)")
```

```exercise
title: max_mod
kind: write
---prompt
*Codeforces 888E, Maximum Subsequence.* Write `max_mod(nums, m)`: the largest value of (sum of a subset) mod m. Up to 26 numbers. Take each half's subset sums mod m, sorted. For a left value a, the best partner is the largest right value b ≤ m − 1 − a (no wrap-around). Pairs that wrap past m give at most a + (largest b) − m, so check that too.
---starter
def max_mod(nums, m):
    return max(x % m for x in nums)
---solution
def max_mod(nums, m):
    h = len(nums) // 2
    L = sorted({s % m for s in all_sums([x % m for x in nums[:h]])})
    R = sorted({s % m for s in all_sums([x % m for x in nums[h:]])})
    best = 0
    for a in L:
        i = bisect_right(R, m - 1 - a) - 1
        best = max(best, a + R[i], (a + R[-1]) % m)
    return best
---tests
assert max_mod([5, 2, 4, 1], 4) == 3
assert max_mod([199, 41, 299], 20) == 19
assert max_mod([3], 10) == 3
assert max_mod(lcg(26, 5, 10 ** 9), 10 ** 9 + 7) == 999999980
---hint
The starter only looks at single numbers. Combining them does better, and there are 2²⁶ subsets: too many to list directly.
---hint
`bisect_right(R, m - 1 - a) - 1` finds the largest right value that keeps a + b below m. R always holds 0 (the empty subset), so the index is never −1.
```

```exercise
title: sqrt_blocks
kind: write
---prompt
*Square-root decomposition.* Write a class `Blocks(a)` with `update(i, v)` (set `a[i] = v`) and `query(l, r)` (sum of `a[l..r]`, both ends included). Keep blocks of size about √n with a total for each. A query adds partial blocks cell by cell and whole blocks by their totals. 20,000 numbers and 20,000 operations.
---starter
class Blocks:
    def __init__(self, a):
        self.a = list(a)
        self.total = sum(a)

    def update(self, i, v):
        self.a[i] = v

    def query(self, l, r):
        return self.total
---solution
class Blocks:
    def __init__(self, a):
        self.a = list(a)
        self.b = max(1, isqrt(len(a)))
        self.sums = [0] * (len(a) // self.b + 1)
        for i, x in enumerate(a):
            self.sums[i // self.b] += x

    def update(self, i, v):
        self.sums[i // self.b] += v - self.a[i]
        self.a[i] = v

    def query(self, l, r):
        s, b = 0, self.b
        while l <= r and l % b:
            s += self.a[l]
            l += 1
        while l + b - 1 <= r:
            s += self.sums[l // b]
            l += b
        while l <= r:
            s += self.a[l]
            l += 1
        return s
---tests
t = Blocks([1, 2, 3, 4, 5, 6, 7])
assert t.query(0, 6) == 28 and t.query(2, 4) == 12 and t.query(3, 3) == 4
t.update(3, 10)
assert t.query(2, 4) == 18 and t.query(0, 6) == 34
n = 20000
a = lcg(n, 8, 1000)
t, plain = Blocks(a), list(a)
ops = lcg(3 * n, 9, 10 ** 9)
check = 0
for k in range(n):
    x, y, z = (v * n // 10 ** 9 for v in ops[3 * k: 3 * k + 3])
    if z % 3 == 0:
        t.update(x, y)
        plain[x] = y
    else:
        l, r = min(x, y), max(x, y)
        got = t.query(l, r)
        if k % 500 == 0:
            assert got == sum(plain[l:r + 1]), f"query({l}, {r})"
        check = (check * 31 + got) % (10 ** 9 + 7)
assert check == 508135784
---hint
The starter returns the whole array's total and never updates it. Keep one total per block of about √n cells.
---hint
In `query`, walk single cells until l reaches a block boundary, jump whole blocks while a full one fits before r, then walk single cells again.
```

## Quick-fire: lock it in

```quiz
Why does meet in the middle work for subset sum?
* Any subset is a left-half subset plus a right-half subset, so matching sums from two lists of 2^(n/2) covers all 2ⁿ subsets
- It skips subsets that can't work
- It uses dynamic programming over the target
- It only works when numbers are small
> Each half is brute-forced; the combining step does the rest in near-linear time.
```

```quiz
With square-root decomposition on n = 1,000,000, about how many steps does a range query take?
- 1,000,000
- 20
* About 3,000: up to 1,000 block totals plus up to 2,000 single cells
- 1
> Blocks of √n = 1,000. A Fenwick tree would take about 20, but blocks handle operations Fenwick can't.
```

```quiz
The weights are small (each at most 100) and there are 40 of them. What's better than meet in the middle?
- Nothing
* A DP over achievable sums: at most 4,000 different totals
- Sorting
- Backtracking
> Meet in the middle is for when the values are huge and n is small. Small values mean subset-sum DP (chapter 28).
```

## Real-world project: loading a lorry

```project
title: Best load under the limit
client: A small freight firm loading up to 36 heavy crates onto a lorry with a strict weight limit, who wants the load as close to the limit as possible
skills: meet in the middle, sorting, binary search for "closest without going over"
---brief
Build `load.py`. Read crate weights and the limit, split the crates into two halves, list each half's subset sums, sort one side, and for every sum on the other side binary-search the best partner. Print the best total and which crates to load.
---why
"Closest without going over" with few, large items appears in budgeting, packing, cryptography (the knapsack cryptosystems were broken partly this way), and in splitting a set into two nearly equal halves.
---milestones
- Subset sums of each half
- Best total under the limit
- Which crates make it up
- 36 crates in under two seconds
---stretch
- Split the crates between two lorries as evenly as possible
- Prune the lists: drop any sum that's not better than a smaller one
```

```exercise
title: best_load
kind: write
---prompt
Write `best_load(weights, cap)`: the largest subset total that's at most `cap`. Up to 30 weights, each up to 10⁹.
---starter
def best_load(weights, cap):
    s = 0
    for w in sorted(weights):
        if s + w <= cap:
            s += w
    return s
---solution
def best_load(weights, cap):
    h = len(weights) // 2
    R = sorted(all_sums(weights[h:]))
    best = 0
    for a in all_sums(weights[:h]):
        if a <= cap:
            best = max(best, a + R[bisect_right(R, cap - a) - 1])
    return best
---tests
assert best_load(ITEMS, 50) == 50
assert best_load([10, 20, 30], 45) == 40
assert best_load([10, 20, 30], 5) == 0
C = lcg(30, 6, 10 ** 9)
assert best_load(C, 7777777777) == 7777777765
---hint
The starter adds the lightest crates first. For a limit of 45 with crates 10, 20, 30 it stops at 30, but 10 + 30 = 40.
---hint
Sort the right half's sums. For a left sum a ≤ cap, `bisect_right(R, cap - a) - 1` is the heaviest right sum that still fits.
```

```recall
Q: Explain meet in the middle and square-root decomposition: when each applies, how to combine the two halves for "exact target" and "closest under a cap", the costs, and how a block query works.
A: Meet in the middle is for small n (around 40) where 2ⁿ is too slow and the values are too large for a DP over sums. Split the items in two halves, list every subset sum of each half (2^(n/2) each), then combine, because every subset is a left subset plus a right subset. For an exact target, put the right sums in a set and look up target minus each left sum. For the closest total under a cap, sort the right sums and binary-search cap minus each left sum. For counting, sort both and walk two pointers. Cost O(2^(n/2) · n), the square root of brute force. Square-root decomposition cuts an array into blocks of about √n and keeps a total per block. An update fixes one cell and one block total. A range query walks single cells up to a block boundary, adds whole blocks by their totals, then walks the leftover cells: O(√n) per operation. It's slower than Fenwick or segment trees (O(log n)) but simpler and adapts to unusual operations.
```
