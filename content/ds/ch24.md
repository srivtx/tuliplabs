## When an edge pays you back

Sometimes an edge has a **negative** weight: a rebate, an energy gain, a currency trade that leaves you richer. Dijkstra's "the closest unsettled node is final" argument needs weights that are never negative, so it can settle a node too early.

```viz
name: ds-bellman
title: A rebate road: Dijkstra against Bellman-Ford
goal: Run **Dijkstra** to the end, then run **Bellman-Ford** and compare the cost of reaching T.
height: 440
The red road pays you 5.
```

**Bellman-Ford** does something dumber and safer:

- Set `dist[s] = 0` and everything else to infinity.
- Repeat V − 1 times: for **every** edge `(u, v, w)`, if `dist[u] + w < dist[v]`, lower `dist[v]`.
- After round i, every shortest path that uses at most i edges is correct. A shortest path never needs more than V − 1 edges, so that's enough. O(V · E).
- **Stop early** if a whole round changes nothing.
- **Negative cycle**: if a V-th round still improves something, some loop has negative total cost, and you could go round it forever.

```run
title: Bellman-Ford on the rebate road map
edges = [("S", "A", 2), ("S", "B", 6), ("B", "A", -5), ("A", "C", 3), ("C", "T", 2), ("B", "D", 4), ("D", "T", 3), ("A", "D", 6)]
nodes = {x for e in edges for x in e[:2]}
dist = {v: float("inf") for v in nodes}
dist["S"] = 0
for rnd in range(1, len(nodes)):
    changed = False
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
            changed = True
    print("after round", rnd, dict(sorted(dist.items())))
    if not changed:
        break
```

```exercise
title: bellman_ford
kind: write
---prompt
Directed `edges` `(u, v, w)` on nodes `0..n-1`, source `s`. Return the list of shortest distances (`float("inf")` if unreachable), or `None` if a negative cycle is **reachable** from `s`.
---starter
def bellman_ford(n, edges, s):
    dist = [float("inf")] * n
    dist[s] = 0
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
    return dist
---solution
def bellman_ford(n, edges, s):
    dist = [float("inf")] * n
    dist[s] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            return dist
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            return None
    return dist
---tests
assert bellman_ford(4, [(2, 3, 1), (1, 2, 1), (0, 1, 1)], 0) == [0, 1, 2, 3]
assert bellman_ford(3, [(0, 1, 4), (0, 2, 5), (2, 1, -3)], 0) == [0, 2, 5]
assert bellman_ford(3, [(0, 1, 1), (1, 2, -1), (2, 1, -1)], 0) is None
assert bellman_ford(4, [(0, 1, 1), (2, 3, -1), (3, 2, -1)], 0) == [0, 1, float("inf"), float("inf")]
---hint
One pass over the edges is only right if they happen to be in a lucky order. Loop it n − 1 times, then one more pass to check for a negative cycle. `inf + w` stays `inf`, so unreachable nodes are safe.
```

## Every pair at once: Floyd-Warshall

To get the shortest distance between **every** pair, **Floyd-Warshall** builds an n × n table. It asks, for each node k in turn: "does going through k improve the route from i to j?"

- `d[i][j] = min(d[i][j], d[i][k] + d[k][j])`
- **k must be the outer loop.** After pass k, `d[i][j]` is the best route whose middle stops all come from nodes `0..k`.
- O(n³): great up to a few hundred nodes, and negative edges are fine. A negative `d[i][i]` at the end means a negative cycle.

```exercise
title: city_fewest_neighbours
kind: write
---prompt
*LeetCode 1334, asked at Amazon.* `n` cities, undirected roads `(a, b, w)`. For each city, count the cities reachable within `limit` distance. Return the city with the **fewest**; on ties, the **largest** number. Floyd-Warshall, then count.
---starter
def find_city(n, roads, limit):
    deg = [0] * n
    for a, b, w in roads:
        if w <= limit:
            deg[a] += 1
            deg[b] += 1
    return min(range(n), key=lambda c: (deg[c], -c))
---solution
def find_city(n, roads, limit):
    INF = float("inf")
    d = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for a, b, w in roads:
        d[a][b] = d[b][a] = min(d[a][b], w)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if d[i][k] + d[k][j] < d[i][j]:
                    d[i][j] = d[i][k] + d[k][j]
    reach = [sum(1 for j in range(n) if j != i and d[i][j] <= limit) for i in range(n)]
    return min(range(n), key=lambda c: (reach[c], -c))
---tests
assert find_city(4, [(0, 1, 3), (1, 2, 1), (1, 3, 4), (2, 3, 1)], 4) == 3
assert find_city(5, [(0, 1, 2), (0, 4, 8), (1, 2, 3), (1, 4, 2), (2, 3, 1), (3, 4, 1)], 2) == 0
assert find_city(3, [(0, 1, 1), (1, 2, 1)], 1) == 2
---hint
The starter only counts direct roads. A city two cheap roads away is also within reach.
```

```exercise
title: prerequisite_queries

---prompt
*LeetCode 1462, asked at Google.* `n` courses, `prereqs` pairs `(a, b)` meaning a must come before b. For each query `(u, v)` answer whether u is a prerequisite of v, directly or indirectly. Floyd-Warshall with booleans (**transitive closure**): `reach[i][j] |= reach[i][k] and reach[k][j]`.
---starter
def check(n, prereqs, queries):

def check(n, prereqs, queries):
    reach = [[False] * n for _ in range(n)]
```

```exercise
title: arbitrage
kind: write
---prompt
*A classic interview and Codeforces idea.* `rates[i][j]` is how many units of currency j one unit of currency i buys. Is there a loop of trades that ends with **more** than you started? Multiplying rates is awkward, so take `-log(rate)` as an edge weight: a product greater than 1 becomes a sum less than 0, a **negative cycle**. Run Floyd-Warshall and look for `d[i][i] < -1e-12`.
---starter
def arbitrage(rates):
    n = len(rates)
    return any(rates[i][j] * rates[j][i] > 1 + 1e-12 for i in range(n) for j in range(n))
---solution
def arbitrage(rates):
    n = len(rates)
    d = [[-math.log(rates[i][j]) for j in range(n)] for i in range(n)]
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if d[i][k] + d[k][j] < d[i][j]:
                    d[i][j] = d[i][k] + d[k][j]
    return any(d[i][i] < -1e-12 for i in range(n))
---tests
assert arbitrage([[1, 0.9, 0.8], [1.1, 1, 0.9], [1.2, 1.1, 1]]) is False
assert arbitrage([[1, 0.5], [2, 1]]) is False
assert arbitrage([[1, 0.9, 0.5], [1.0, 1, 1.2], [1.0, 0.7, 1]]) is True
---hint
The starter only tries loops of two trades. A profitable loop can pass through three or more currencies.
```

```exercise
def best_rates(rates):
    n = len(rates)
    b = [row[:] for row in rates]
    for k in range(n):
        for i in range(n):
```

## Rebuild it and explain it

```exercise
title: floyd_rebuild
kind: rebuild
---prompt
From memory: `all_pairs(n, edges)` for directed edges `(u, v, w)` returning the full distance table with Floyd-Warshall (`float("inf")` when unreachable, 0 on the diagonal).
---starter
def all_pairs(n, edges):
    pass
---solution
def all_pairs(n, edges):
    INF = float("inf")
    d = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for u, v, w in edges:
        d[u][v] = min(d[u][v], w)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if d[i][k] + d[k][j] < d[i][j]:
                    d[i][j] = d[i][k] + d[k][j]
    return d
---tests

---hint
Table, direct edges (keep the cheapest of duplicates), then k, i, j.
```

```recall
Q: Explain Bellman-Ford and Floyd-Warshall: when Dijkstra fails, how each works, their costs, negative cycles and the hop-limited variant.
A: Dijkstra assumes non-negative weights, so a negative edge can lower a node it already declared final. Bellman-Ford instead relaxes every edge in rounds; after round i, all shortest paths of at most i edges are correct, so V − 1 rounds suffice, giving O(V·E), and it can stop early when a round changes nothing. If a further round still improves a distance, a negative cycle is reachable and shortest paths are undefined. Running exactly k + 1 rounds while reading from a copy of the previous round gives the cheapest path with at most k + 1 edges, as in cheapest flights within k stops. Floyd-Warshall computes all pairs in O(n³) with a table: for each middle node k (the outer loop), it sets d[i][j] to the minimum of d[i][j] and d[i][k] + d[k][j]; a negative diagonal entry means a negative cycle. The same triple loop with booleans gives transitive closure, and with max and multiplication gives best exchange rates; using minus log rates turns arbitrage into negative cycle detection.
```
