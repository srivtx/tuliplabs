## The biggest stretch

An array is a row of boxes in memory, side by side. Reading `a[i]` is instant because the computer jumps straight to box i. Most array problems are about walking that row **once** while carrying a few numbers in your head.

The classic: which stretch of neighbouring numbers (a **subarray**) has the largest total? Think of a shop's profit and loss per day, and the best run of days to show investors.

```viz
name: ds-kadane
title: Every stretch, or one walk
goal: Run **try every stretch** to the end, then run **Kadane** to the end and compare how many stretches each looked at.
height: 400
Click any number to see why it helps or hurts a stretch.
```

The idea in one sentence: **if the run you're carrying has a negative total, drop it**, because adding a negative start to anything only makes it smaller.

```predict
a = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
run = 0
for x in a:
    run = max(x, run + x)
    print(run, end=" ")
```

`run = max(x, run + x)` is the same rule written another way: either extend the run with x, or start fresh at x, whichever is bigger. The answer is the largest `run` ever seen (6, for `4 -1 2 1`).

```parsons
title: Kadane's algorithm
---lines
def max_subarray(a):
    best = run = a[0]
    for x in a[1:]:
        run = max(x, run + x)
        best = max(best, run)
    return best
?? best = run = 0
?? run = max(run, run + x)
---tests
assert max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]) == 6
assert max_subarray([-3, -1, -2]) == -1
assert max_subarray([5]) == 5
```

The first decoy is the classic bug: starting `best` at 0 gives the wrong answer when every number is negative (the best stretch is then the single largest number, not an empty one).

```quiz
`a = [-3, -1, -2]`. What should `max_subarray(a)` return if a stretch must contain at least one number?
- 0
* -1
- -6
- -3
> The best you can do is the single number -1. A version that starts `best = 0` returns 0, which is only right if empty stretches are allowed. Always check the all-negative case.
```

```exercise
title: max_subarray_where
kind: write
---prompt
*An interview classic, one step harder.* Write `best_stretch(a)` returning `(total, start, end)` for the maximum-sum subarray (inclusive indices). If several stretches tie, return the one that **starts earliest**, and among those the **shortest**. `a` has at least one number and can have 10⁵ of them.
---starter
def best_stretch(a):
    return (0, 0, 0)
---solution
def best_stretch(a):
    best = (a[0], 0, 0)
    run, start = 0, 0
    for j, x in enumerate(a):
        if run < 0 or j == 0:
            run, start = 0, j
        run += x
        if run > best[0]:
            best = (run, start, j)
    return best
---tests
assert best_stretch([-2, 1, -3, 4, -1, 2, 1, -5, 4]) == (6, 3, 6)
assert best_stretch([-3, -1, -2]) == (-1, 1, 1)
assert best_stretch([2, -2, 2]) == (2, 0, 0), "ties: earliest start, then shortest"
assert best_stretch([1, 2, 3]) == (6, 0, 2)
big = [random.randint(-50, 50) for _ in range(5000)]
r, secs = timed(best_stretch, big)
assert r[0] == sum(big[r[1]:r[2] + 1])
assert secs < 0.25, f"{secs:.2f}s: too slow, use one walk"
---hint
Carry `run` and the index `start` where the current run began. When `run` is negative, reset `run = 0` and `start = j` before adding `a[j]`.
---hint
Only replace `best` when the new total is **strictly** bigger: that keeps the earliest, shortest one on ties.
```

## Filtering in place: the write pointer

Building a new list costs memory. Many interview questions say "do it **in place**". The pattern: one index reads every item, another (`w`, the write pointer) marks where the next kept item goes.

```exercise
title: move_zeroes
kind: write
---prompt
*An interview classic.* Move every `0` in the list `a` to the end, **in place**, keeping the other numbers in their original order. Return nothing; change `a` itself.
---starter
def move_zeroes(a):
    return [x for x in a if x != 0] + [0] * a.count(0)
---solution
def move_zeroes(a):
    w = 0
    for x in a:
        if x != 0:
            a[w] = x
            w += 1
    for i in range(w, len(a)):
        a[i] = 0
---tests
a = [0, 1, 0, 3, 12]; move_zeroes(a); assert a == [1, 3, 12, 0, 0]
a = [0]; move_zeroes(a); assert a == [0]
a = [4, 2]; move_zeroes(a); assert a == [4, 2]
a = [0, 5, 0]; b = a; r = move_zeroes(a); assert b == [5, 0, 0] and r is None, "change the list itself, don't return a new one"
---hint
Walk with `x`. Every non-zero goes to `a[w]`, then `w += 1`. Afterwards, fill from `w` to the end with zeros.
```

```exercise
title: dedupe_sorted
kind: write
---prompt
*An interview classic.* `a` is sorted. Remove duplicates **in place** so the first `k` slots hold each distinct value once, in order, and return `k`. (What's after slot k doesn't matter.)
---starter
def dedupe_sorted(a):
    return len(set(a))
---solution
def dedupe_sorted(a):
    if not a:
        return 0
    w = 1
    for i in range(1, len(a)):
        if a[i] != a[w - 1]:
            a[w] = a[i]
            w += 1
    return w
---tests
a = [1, 1, 2]; k = dedupe_sorted(a); assert k == 2 and a[:k] == [1, 2]
a = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]; k = dedupe_sorted(a); assert k == 5 and a[:k] == [0, 1, 2, 3, 4]
a = []; assert dedupe_sorted(a) == 0
a = [7]; assert dedupe_sorted(a) == 1 and a == [7]
---hint
Because it's sorted, a duplicate always sits right after its twin. Compare `a[i]` with the last value you kept, `a[w - 1]`.
```

## Reversing and rotating in place

```run
title: Reverse with two pointers
def reverse(a, lo, hi):
    while lo < hi:
        a[lo], a[hi] = a[hi], a[lo]
        lo += 1
        hi -= 1

a = list("ABCDEFG")
reverse(a, 0, len(a) - 1)
print("".join(a))
```

Rotating right by k (the last k items move to the front) looks like it needs a second list. It doesn't: reverse the whole thing, then reverse the first k, then reverse the rest.

```predict
a = list("ABCDEFG")
k = 3
def rev(lo, hi):
    while lo < hi:
        a[lo], a[hi] = a[hi], a[lo]
        lo, hi = lo + 1, hi - 1
rev(0, 6); print("".join(a))
rev(0, k - 1); print("".join(a))
rev(k, 6); print("".join(a))
```

```exercise
title: rotate_bug
kind: bug
---prompt
This rotation works for small k but crashes or gives the wrong answer when `k` is bigger than the list (rotating 7 items by 10 is the same as rotating by 3), and when the list is empty. Fix it.
---starter
def rotate(a, k):
    def rev(lo, hi):
        while lo < hi:
            a[lo], a[hi] = a[hi], a[lo]
            lo, hi = lo + 1, hi - 1
    n = len(a)
    rev(0, n - 1)
    rev(0, k - 1)
    rev(k, n - 1)
---solution
def rotate(a, k):
    def rev(lo, hi):
        while lo < hi:
            a[lo], a[hi] = a[hi], a[lo]
            lo, hi = lo + 1, hi - 1
    n = len(a)
    if n == 0:
        return
    k %= n
    rev(0, n - 1)
    rev(0, k - 1)
    rev(k, n - 1)
---tests
a = list("ABCDEFG"); rotate(a, 3); assert "".join(a) == "EFGABCD"
a = list("ABCDEFG"); rotate(a, 10); assert "".join(a) == "EFGABCD", "10 steps on 7 items = 3 steps"
a = list("ABC"); rotate(a, 3); assert "".join(a) == "ABC"
a = []; rotate(a, 5); assert a == []
---hint
Rotating by n changes nothing, so only `k % n` matters. Guard the empty list first (`% 0` would crash).
```

## Three kinds in one pass: the Dutch flag

Sort a list holding only 0s, 1s and 2s, in one pass, in place. Keep three regions: everything before `lo` is 0, everything after `hi` is 2, and `mid` walks the unknown part in between.

```parsons
title: Dutch national flag
---lines
def sort_colors(a):
    lo, mid, hi = 0, 0, len(a) - 1
    while mid <= hi:
        if a[mid] == 0:
            a[lo], a[mid] = a[mid], a[lo]
            lo += 1
            mid += 1
        elif a[mid] == 1:
            mid += 1
        else:
            a[mid], a[hi] = a[hi], a[mid]
            hi -= 1
?? mid += 1
---tests
a = [2, 0, 2, 1, 1, 0]; sort_colors(a); assert a == [0, 0, 1, 1, 2, 2]
a = [2, 2, 0]; sort_colors(a); assert a == [0, 2, 2]
a = []; sort_colors(a); assert a == []
a = [1]; sort_colors(a); assert a == [1]
```

```quiz
In the Dutch flag, after swapping `a[mid]` with `a[hi]`, why **don't** we move `mid` forward?
- It's a mistake; we should
* The number that came from `hi` hasn't been looked at yet, so `mid` must check it
- Because `hi` already moved
- To keep the loop running longer
> Everything after `hi` was unknown. The swap brings one of those unknowns to `mid`, and it could be a 0, 1 or 2. (After a swap with `lo` it's safe to move on: that slot was already checked.)
```

## Contest ladder

```exercise
title: make_non_decreasing
kind: write
---prompt
*Codeforces style.* In one operation you may add 1 to any element. Return the minimum number of operations to make `a` non-decreasing (each element ≥ the one before it). n up to 2·10⁵, values up to 10⁹.
---starter
def make_non_decreasing(a):
    return 0
---solution
def make_non_decreasing(a):
    ops, top = 0, float("-inf")
    for x in a:
        if x < top:
            ops += top - x
        else:
            top = x
    return ops
---tests
assert make_non_decreasing([3, 2, 5, 1, 7]) == 1 + 4
assert make_non_decreasing([1, 2, 3]) == 0
assert make_non_decreasing([5, 4, 3, 2, 1]) == 1 + 2 + 3 + 4
assert make_non_decreasing([10**9, 1]) == 10**9 - 1
assert make_non_decreasing([]) == 0
---hint
Raising an element to exactly the largest value so far is always enough and never wasteful. Carry that running maximum.
```

```exercise
title: max_product
kind: write
---prompt
*An interview favourite that breaks Kadane.* Return the largest **product** of a non-empty stretch of `a` (integers, may be negative or zero). A negative times a negative is positive, so the smallest product so far matters too.
---starter
def max_product(a):
    best = run = a[0]
    for x in a[1:]:
        run = max(x, run * x)
        best = max(best, run)
    return best
---solution
def max_product(a):
    best = hi = lo = a[0]
    for x in a[1:]:
        cands = (x, hi * x, lo * x)
        hi, lo = max(cands), min(cands)
        best = max(best, hi)
    return best
---tests
assert max_product([2, 3, -2, 4]) == 6
assert max_product([-2, 0, -1]) == 0
assert max_product([-2, 3, -4]) == 24, "two negatives make a positive"
assert max_product([-2]) == -2
assert max_product([0, 2]) == 2
---hint
Carry two runs: the biggest and the smallest product ending here. A negative `x` turns the smallest into the biggest.
```

```exercise
title: leaders
kind: write
---prompt
*A warm-up that teaches walking backwards.* An element is a **leader** if it's strictly greater than everything to its right (the last element always is). Return the leaders in their original left-to-right order, in O(n).
---starter
def leaders(a):
    return [x for i, x in enumerate(a) if all(x > y for y in a[i + 1:])]
---solution
def leaders(a):
    out, top = [], float("-inf")
    for x in reversed(a):
        if x > top:
            out.append(x)
            top = x
    return out[::-1]
---tests
assert leaders([16, 17, 4, 3, 5, 2]) == [17, 5, 2]
assert leaders([1, 2, 3]) == [3]
assert leaders([]) == []
big = list(range(6000, 0, -1))
r, secs = timed(leaders, big)
assert r == big and secs < 0.25, f"{secs:.2f}s: walk from the right, keeping the maximum seen"
---hint
From the right, "greater than everything to my right" means "greater than the maximum so far".
```

## Quick-fire: lock it in

```quiz
What does Kadane's algorithm throw away, and when?
- The smallest number, at the end
* The current run, as soon as its total is negative
- Every negative number
- The best answer, when a bigger one appears
> A run with a negative total can only lower whatever follows, so starting fresh is never worse.
```

```quiz
What's the extra memory used by the write-pointer filter?
* O(1): a couple of integers
- O(n): a second list
- O(log n)
- O(k), for the k items kept
> It overwrites the same list. That's what "in place" means.
```

```quiz
Rotating 1 000 items right by 1 000 003 steps. How many steps actually matter?
- 1 000 003
- 1 000
* 3
- 0
> Every 1 000 steps brings the list back to where it started: 1 000 003 % 1 000 = 3.
```

```quiz
Which problem is **not** a "carry one summary while walking" problem?
- Best day to buy and sell a share
- Maximum subarray sum
- Leaders in an array
* Counting how many pairs of equal numbers there are, without extra memory and in O(n), when the numbers are unsorted
> The first three each need just one or two running numbers. Counting equal pairs in unsorted data needs to remember *which* values you've seen: that's a hash map (chapter 3), or sorting first.
```

```exercise
title: best_circular
kind: write
---prompt
*An interview classic.* The list is a circle: the last element is next to the first. Return the maximum total of a non-empty stretch, where a stretch may wrap around the end (but uses each element at most once).
---starter
def best_circular(a):
    best = run = a[0]
    for x in a[1:]:
        run = max(x, run + x)
        best = max(best, run)
    return best
---solution
def best_circular(a):
    best = run = a[0]
    worst = low = a[0]
    for x in a[1:]:
        run = max(x, run + x)
        best = max(best, run)
        low = min(x, low + x)
        worst = min(worst, low)
    if best < 0:
        return best
    return max(best, sum(a) - worst)
---tests
assert best_circular([1, -2, 3, -2]) == 3
assert best_circular([5, -3, 5]) == 10, "wraps: 5 + 5"
assert best_circular([-3, -2, -3]) == -2, "all negative: don't take the empty 'everything minus everything'"
assert best_circular([3, -1, 2, -1]) == 4
---hint
A wrapping stretch is "everything except a middle stretch". The best wrap = total − the worst middle stretch.
---hint
If every number is negative, the worst stretch is the whole array and "total − worst" would be an empty stretch. In that case return the normal Kadane answer.
```

## Rebuild it and explain it

```exercise
title: kadane_rebuild
kind: rebuild
---prompt
From memory: `max_subarray(a)` returns the largest total of a non-empty stretch of `a`, in one pass.
---starter
def max_subarray(a):
    pass
---solution
def max_subarray(a):
    best = run = a[0]
    for x in a[1:]:
        run = max(x, run + x)
        best = max(best, run)
    return best
---tests

assert max_subarray([-5, -2]) == -2
assert max_subarray([1]) == 1
---hint

```

```recall
Q: Explain Kadane's algorithm and the write-pointer pattern, and why each is O(n).
A: Kadane walks the array once, carrying run = the best total of a stretch ending at the current element. For each x, run = max(x, run + x): extend the stretch, or start fresh if the old run was negative and could only drag things down. The answer is the largest run seen. Starting best at a[0], not 0, handles all-negative arrays. The write pointer filters in place: one index reads every element, w marks where the next kept element goes, so nothing is copied to a new list and extra memory is O(1). Both touch every element a constant number of times, so they're O(n), versus O(n²) for trying every start and end. Related in-place tricks: reverse with two pointers, rotate by k with three reversals (k % n), and the Dutch flag with three regions lo/mid/hi.
```
