## Who wins?

These are games with two players taking turns, no luck, nothing hidden, and the rule that **a player who can't move loses**. Every position is either **winning** (the player to move can force a win) or **losing**. The rule that decides which:

- A position is **winning** if **some** move leads to a losing position.
- A position is **losing** if **every** move leads to a winning position. (No moves at all counts: you lose.)

That's a recursion, and like every recursion with repeated sub-problems it wants a table. Here's the game "take 1, 3 or 4 stones from a pile":

```viz

height: 440

```

The table goes further than win/lose. Each position gets a **Grundy number**: the **mex** (minimum excluded value, the smallest non-negative integer not in a set) of the numbers its moves reach. A position with Grundy number 0 is losing. Any other number is winning.

Why bother with numbers when win/lose is enough? Because of **sums of games**. If you play several games side by side, and each turn you move in exactly one of them, the whole position's Grundy number is the **XOR** of the parts' numbers (the **Sprague-Grundy theorem**). Win/lose alone can't tell you that: two winning piles can make a losing pair.

**Nim** is the plain case: several piles, take any number of stones from one pile. A Nim pile of size p has Grundy number p, so the player to move wins exactly when the XOR of all the pile sizes isn't 0. The winning move turns the XOR into 0: find a pile p with `p ^ x < p` (where x is the total XOR) and shrink it to `p ^ x`.

```run
title: Grundy numbers with the mex
def grundy(n, moves):
    g = [0] * (n + 1)
    for i in range(1, n + 1):
        reach = {g[i - m] for m in moves if m <= i}
        x = 0
        while x in reach:          # mex: smallest value not reached
            x += 1
        g[i] = x
    return g

g = grundy(20, MOVES)
print(g)
print("losing sizes:", [i for i, x in enumerate(g) if x == 0])
piles = [5, 9, 12]
print("three piles at once:", [g[p] for p in piles], "XOR =", xor_all(g[p] for p in piles))
```

```exercise
def first_wins(n, moves):
```

## Combining games

```exercise
title: nim_move
kind: write
---prompt
*Nim.* Write `nim_move(piles)`: if the player to move is losing (the XOR is 0), return `None`. Otherwise return `(i, new_size)`: shrink pile i to `new_size` so the XOR becomes 0. Any winning move is accepted.
---starter
def nim_move(piles):
    i = max(range(len(piles)), key=lambda k: piles[k])
    return (i, 0)
---solution
def nim_move(piles):
    x = xor_all(piles)
    if x == 0:
        return None
    for i, p in enumerate(piles):
        if p ^ x < p:
            return (i, p ^ x)
---tests

The starter empties the biggest pile, which rarely leaves an XOR of 0.
---hint
Let x be the XOR of everything. Some pile p has the top bit of x set; for that pile `p ^ x < p`. Shrink it to `p ^ x`.
```

```exercise
def first_wins_many(piles, moves):
```

```exercise
title: split_the_pile
kind: write
---prompt
*Grundy's game.* A move splits one pile into **two unequal non-empty** piles. Whoever can't move loses (piles of 1 and 2 can't be split). Write `grundy_split(n)`: the Grundy numbers for piles 0..n. A split of i into a and i − a is itself two games side by side, so it reaches the number `g[a] ^ g[i - a]`. n up to 300.
---starter
def grundy_split(n):
    return [0 if i < 3 else 1 for i in range(n + 1)]
---solution
def grundy_split(n):
    g = [0] * (n + 1)
    for i in range(3, n + 1):
        reach = {g[a] ^ g[i - a] for a in range(1, (i + 1) // 2)}
        x = 0
        while x in reach:
            x += 1
        g[i] = x
    return g
```

```exercise

kind: write
---prompt
Write `bot_move(piles, moves)`: if the position is winning, return `(i, take)`, taking `take` stones (a value from `moves`) from pile i so the XOR of Grundy numbers becomes 0. If it's losing, return `None`.
---starter
def bot_move(piles, moves):
    for i, p in enumerate(piles):
        for m in moves:
            if m <= p:
                return (i, m)
    return None
---solution
def bot_move(piles, moves):
    n = max(piles)
    g = [0] * (n + 1)
    for i in range(1, n + 1):
        reach = {g[i - m] for m in moves if m <= i}
        x = 0
        while x in reach:
            x += 1
        g[i] = x
    total = xor_all(g[p] for p in piles)
    if total == 0:
        return None
    for i, p in enumerate(piles):
        want = total ^ g[p]
        for m in moves:
            if m <= p and g[p - m] == want:
                return (i, m)
```

```recall
Q: Explain how to solve impartial two-player games: winning and losing positions, Grundy numbers and the mex, why sums of games use XOR, how to win Nim, and why a table beats plain recursion.
A: In a game with no luck where a player who can't move loses, each position is winning or losing. It's winning if some move reaches a losing position, and losing if every move reaches a winning one; no moves at all means losing. Plain recursion re-solves the same positions exponentially often, so fill a table from the end of the game backwards, or memoise. Grundy numbers refine this: each position's number is the mex (smallest non-negative integer not present) of its moves' numbers, and 0 means losing. The Sprague-Grundy theorem says the number of several games played side by side, moving in one per turn, is the XOR of their numbers. That's why two equal winning games cancel: the opponent mirrors. A Nim pile of size p has number p, so the player to move wins exactly when the XOR of the piles isn't 0. To win, pick a pile p with p XOR x less than p (x being the total) and shrink it to p XOR x, which leaves XOR 0. In Grundy's game, a split of a pile reaches g[a] XOR g[i − a], because the two parts become separate games.
```
