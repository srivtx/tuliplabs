```prelude
        out.append(x % mx)
    return out

def is_perm(p, n):
    return sorted(p) == list(range(1, n + 1))

def check_schedule(n, rounds):
    """Every pair of teams 0..n-1 meets exactly once, and nobody plays twice in a round."""
    seen = set()
    for rnd in rounds:
        busy = [t for pair in rnd for t in pair]
        assert len(busy) == len(set(busy)), "a team plays twice in one round"
        for a, b in rnd:
            assert 0 <= a < n and 0 <= b < n and a != b, f"bad pair {a, b}"
            assert (min(a, b), max(a, b)) not in seen, f"{a} and {b} meet twice"
            seen.add((min(a, b), max(a, b)))
    assert len(seen) == n * (n - 1) // 2, "some pair never meets"
```

## Build one, don't search for one

Many contest problems end with "print **any** valid answer": an arrangement, a schedule, a string, or −1 if none exists. Trying every candidate is exponential. The usual move is a **construction**: a recipe that writes a valid answer down directly.

Finding the recipe is the skill. A routine that works:

1. **Write a checker first.** Checking an answer is almost always easy.
2. **Brute-force small n** (say up to 8) with the checker, and print what it finds.
3. **Stare at the answers.** Look for a split into evens and odds, a zigzag, a rotation, a repeated block.
4. **Find an invariant** for the cases with no answer: something every move keeps the same, often a parity or a sum.

Here's a schedule that has to be built: every pair of six teams plays once, three games a round.

```viz
name: ds-roundrobin
title: Every pair plays once
goal: Run **first team not met** to the end, then run **circle method** and compare.
height: 460
Teams sit in two rows. Each round, the teams in each column play each other.
```

Picking the first opponent you haven't met gets stuck in round 2. The **circle method** never does: team 0 stays put, everyone else rotates one seat each round, and each column is a game. Every pair meets exactly once in n − 1 rounds.

```run
title: Small cases first
def ok(p):
    return all(abs(p[i] - p[i + 1]) != 1 for i in range(len(p) - 1))

for n in range(1, 8):
    found = next((p for p in permutations(range(1, n + 1)) if ok(p)), None)
    print(n, found)
```

The task: arrange 1..n so no two neighbours differ by 1. Brute force says n = 2 and 3 are impossible, and the answers for n ≥ 4 suggest a pattern: put the evens first, then the odds. Inside each half, neighbours differ by 2. At the join, the biggest even sits next to 1, which is fine once n ≥ 4.

```exercise
title: k_differences
kind: write
---prompt
*LeetCode 667, Beautiful Arrangement II.* Write `arrange(n, k)` for 1 ≤ k < n: a permutation of 1..n whose neighbour differences `|p[i] − p[i+1]|` take **exactly** k distinct values. Try a zigzag between the smallest and the largest of 1..k+1: 1, k+1, 2, k, 3, … gives differences k, k−1, …, 1. Then append k+2..n in order, which only adds more 1s.
---starter
def arrange(n, k):
    return list(range(1, n + 1))
---solution
def arrange(n, k):
    out, lo, hi = [], 1, k + 1
    while lo <= hi:
        out.append(lo)
        lo += 1
        if lo <= hi:
            out.append(hi)
            hi -= 1
    return out + list(range(k + 2, n + 1))
---tests
def ok(p, n, k):
    return is_perm(p, n) and len({abs(p[i] - p[i + 1]) for i in range(n - 1)}) == k
for n, k in [(3, 1), (3, 2), (5, 4), (10, 4), (10, 9), (1000, 1), (1000, 999), (1000, 500)]:
    assert ok(arrange(n, k), n, k), (n, k)
---hint
The starter always has exactly one difference (1). Print the zigzag 1, 5, 2, 4, 3 and its differences.
---hint
Alternate `lo` and `hi` from 1 and k + 1 moving inwards, then add the rest in order.
```

```exercise
title: coin_flips
kind: write
---prompt
*An invariant problem.* A row of coins shows `H` or `T`. One move flips two **neighbouring** coins (positions i and i + 1). Write `flips(s)`: a list of positions i that turns every coin to `H`, or `None` if it can't be done. Each move changes the number of tails by −2, 0 or +2, so the **parity** of the tails count never changes: an odd count can never reach 0. With an even count, sweep left to right and flip at every tail.
---starter
def flips(s):
    return [i for i, c in enumerate(s) if c == "T"]
---solution
def flips(s):
    if s.count("T") % 2:
        return None
    s, ops = list(s), []
    for i in range(len(s) - 1):
        if s[i] == "T":
            ops.append(i)
            s[i] = "H"
            s[i + 1] = "H" if s[i + 1] == "T" else "T"
    return ops
---tests
def works(s, ops):
    s = list(s)
    for i in ops:
        assert 0 <= i < len(s) - 1, f"no coin pair at {i}"
        for j in (i, i + 1):
            s[j] = "H" if s[j] == "T" else "T"
    return all(c == "H" for c in s)
assert flips("TTT") is None and flips("T") is None
assert works("THHT", flips("THHT"))
assert works("HHHH", flips("HHHH"))
g = lcg(5000, 3, 1000)
s = "".join("T" if x < 500 else "H" for x in g)
s2 = s[:-1] + ("H" if s[-1] == "T" else "T")      # one coin different, so the other parity
even, odd = (s, s2) if s.count("T") % 2 == 0 else (s2, s)
assert works(even, flips(even))
assert flips(odd) is None
---hint
The starter lists the tails, but flipping position i also flips i + 1. First decide when it's impossible: what does one move do to the number of tails?
---hint
If the tails count is odd, return `None`. Otherwise sweep: whenever coin i is a tail, flip i and i + 1. The last coin ends up right because the parity was even.
```

## Quick-fire: lock it in

```quiz
What's an invariant?
- A variable that never changes in the code
* A quantity every allowed move keeps the same, so states with a different value can't be reached
- The answer to the problem
- A loop that never ends
> Parity of a count, a sum mod k, and chessboard colouring are the usual ones.
```

```quiz
Why write the checker before the construction?
* Checking is easy and trustworthy, so it tests the brute force, the pattern you guess, and the final construction
- Contest judges require it
- It makes the construction faster
- Checkers are needed to read input
> A construction that "looks right" fails on edge cases like n = 2 or 3 surprisingly often.
```

```quiz
The circle method needs an even number of teams. What do you do with 7?
- It can't be done
- Drop one team
* Add a pretend team 7: whoever "plays" it sits out that round
- Play two rounds at once
> 8 teams give 7 rounds, and each real team sits out exactly once.
```

```exercise
title: round_robin
kind: write
---prompt
Write `round_robin(n)` for even n: a list of n − 1 rounds, each a list of n / 2 pairs `(a, b)` of teams 0..n−1, so every pair meets exactly once. Use the circle method: seat the teams in a line, pair seat i with seat n − 1 − i, then keep seat 0 fixed and rotate the rest by one.
---starter
def round_robin(n):
    rounds, met = [], set()
    for r in range(n - 1):
        free, rnd = list(range(n)), []
        while free:
            a = free.pop(0)
            b = next((x for x in free if (a, x) not in met), None)
            if b is None:
                break
            free.remove(b)
            rnd.append((a, b))
            met.add((a, b))
        rounds.append(rnd)
    return rounds
---solution
def round_robin(n):
    ring, rounds = list(range(1, n)), []
    for r in range(n - 1):
        line = [0] + ring
        rounds.append([(line[i], line[n - 1 - i]) for i in range(n // 2)])
        ring = ring[-1:] + ring[:-1]
    return rounds
---tests
check_schedule(2, round_robin(2))
check_schedule(6, round_robin(6))
r = round_robin(20)
assert len(r) == 19 and all(len(x) == 10 for x in r)
check_schedule(20, r)
check_schedule(500, round_robin(500))
---hint
The starter is the greedy from the simulation, which gets stuck in round 2 for six teams.
---hint
`ring = list(range(1, n))`. Each round, `line = [0] + ring`, pair the ends inwards, then rotate `ring` by one.
```

```exercise
title: round_robin_any
kind: write
---prompt
Write `fixtures(n)` for any n ≥ 2. For even n, as before. For odd n, add a pretend team n: return n rounds, leaving out the game against the pretend team, so each real team sits out exactly once.
---starter
def fixtures(n):
    ring, rounds = list(range(1, n)), []
    for r in range(n - 1):

        rounds.append([(line[i], line[n - 1 - i]) for i in range(n // 2)])

---solution
def fixtures(n):
    m = n + n % 2
    ring, rounds = list(range(1, m)), []
    for r in range(m - 1):
        line = [0] + ring
        rounds.append([(line[i], line[m - 1 - i]) for i in range(m // 2) if max(line[i], line[m - 1 - i]) < n])
        ring = ring[-1:] + ring[:-1]
    return rounds

    assert sorted(sat_out) == list(range(n)), "each team sits out exactly once"
---hint

---hint
```

```recall
Q: Explain how to attack a constructive problem: the four-step routine, one construction from this chapter and why it works, what an invariant is with an example, and how the circle method schedules a round robin.
A: Constructive problems ask for any valid answer, where searching would be exponential. The routine: write a checker first, brute-force small n with it, look at the answers for a pattern, and find an invariant to explain the cases with no answer. Example: to arrange 1..n with no neighbours differing by 1, brute force shows n = 2 and 3 are impossible, and for the rest the evens in order followed by the odds in order works: inside each half neighbours differ by 2, and at the join the largest even (at least 4) sits next to 1. An invariant is something every move preserves, so states where it differs can't be reached. Flipping two neighbouring coins changes the tails count by −2, 0 or +2, so its parity never changes: an odd count can't become 0, and an even one can by sweeping left to right. The circle method seats n teams (n even) in a line, pairs seat i with seat n − 1 − i, then keeps team 0 fixed and rotates the others one seat. After n − 1 rounds every pair has met once. For odd n, add a pretend team and whoever plays it sits out.
```
