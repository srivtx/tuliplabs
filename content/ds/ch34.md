```prelude
import time
from collections import deque

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t

class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def build(vals):
    """Build a binary tree from LeetCode's level-order list, None for gaps."""
    if not vals or vals[0] is None:
        return None
    root = Node(vals[0])
    q, i = deque([root]), 1
    while q and i < len(vals):
        n = q.popleft()
        if i < len(vals) and vals[i] is not None:
            n.left = Node(vals[i])
            q.append(n.left)
        i += 1
        if i < len(vals) and vals[i] is not None:
            n.right = Node(vals[i])
            q.append(n.right)
        i += 1
    return root

def bfs_order(parent):
    """Children lists and a top-down order for a tree given as a parent list (-1 = root)."""
    kids = [[] for _ in parent]
    root = 0
    for v, p in enumerate(parent):
        if p < 0:
            root = v
        else:
            kids[p].append(v)
    order = [root]
    for v in order:
        order.extend(kids[v])
    return kids, order
```

## Subtrees are the subproblems

A tree has no cycles, so every node's subtree is its own little problem, and the subtrees of different children don't overlap. Solve the children first (post-order), then combine. The question is **what each node should report to its parent**: often a small tuple, one number per "situation" the parent might need.

```viz
name: ds-party
title: The company party: never invite someone with their direct boss
goal: Run **greedy** to the end, then run **tree DP** and compare the fun.
height: 480
Each box is a person; the number is how much fun they bring.
```

For the party (**maximum independent set** on a tree), each person reports two numbers:

- `inv[v]` = best for v's subtree **with v invited** = `fun[v] + Σ out[child]`
- `out[v]` = best **without v** = `Σ max(inv[child], out[child])`

The answer is `max(inv[root], out[root])`. Each node is touched once: O(n).

**Recursion depth.** A tree can be a long chain: 100,000 levels deep blows Python's stack. For big trees, get a top-down order with BFS, then process it **reversed** (children before parents). The prelude's `bfs_order` does this.

```run
title: Bottom-up without recursion
parent = [-1, 0, 0, 1, 1, 2]
fun = [3, 2, 5, 4, 1, 6]
kids, order = bfs_order(parent)
print("top-down order:", order)
inv, out = [0] * 6, [0] * 6
for v in reversed(order):
    inv[v] = fun[v] + sum(out[c] for c in kids[v])
    out[v] = sum(max(inv[c], out[c]) for c in kids[v])
    print(f"person {v}: invited {inv[v]}, not invited {out[v]}")
print("best party:", max(inv[0], out[0]))
```

## Choosing the states

The hard part is deciding what a node reports. Ask: "what does my parent need to know about me to make **its** choice?"

- **Robbing houses** on a tree: (best if I'm robbed, best if I'm not).
- **Cameras** that watch their neighbours: three states: I have a camera, I'm watched without one, I'm not watched yet (my parent must fix that).
- **Paths**: report the best path going **down** from me; combine the two best children at me to update a global answer.

```exercise
title: house_robber_iii
kind: write
---prompt
*LeetCode 337, asked at Google, Amazon and Uber.* Houses form a binary tree; robbing two houses joined by an edge sets off the alarm. Return the most money. Have `go(n)` return a pair `(rob n, skip n)`.
---starter
def rob(root):
    if not root:
        return 0
    levels, q = [], [root]
    while q:
        levels.append(sum(n.val for n in q))
        q = [c for n in q for c in (n.left, n.right) if c]
    return max(sum(levels[0::2]), sum(levels[1::2]))
---solution
def rob(root):
    def go(n):
        if not n:
            return (0, 0)
        l, r = go(n.left), go(n.right)
        return (n.val + l[1] + r[1], max(l) + max(r))
    return max(go(root))
---tests
assert rob(build([3, 2, 3, None, 3, None, 1])) == 7
assert rob(build([3, 4, 5, 1, 3, None, 1])) == 9
assert rob(None) == 0
assert rob(build([4, 1, None, 2, None, 3])) == 7
---hint
Alternating levels isn't enough: in the last test the chain 4–1–2–3 is best robbed at the 4 and the 3, three levels apart. Let each node decide.
```

```exercise
def longest_path(parent, s):
```

```exercise
title: sum_of_distances
kind: write
---prompt
*LeetCode 834, a hard one asked at Google and Amazon.* For every node, return the sum of its distances to all other nodes. Two passes: bottom-up, `size[v]` and `down[v]` (sum of distances to nodes in v's subtree); then top-down **re-rooting**: moving the root from parent `p` to child `v`, `size[v]` nodes get 1 closer and `n − size[v]` get 1 farther, so `ans[v] = ans[p] − size[v] + (n − size[v])`.
---starter
def sum_distances(n, edges):
    deg = [0] * n
    for a, b in edges:
        deg[a] += 1
        deg[b] += 1
    return [n - 1 + (n - 1 - d) for d in deg]
---solution
def sum_distances(n, edges):
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b)
        adj[b].append(a)
    par, order, seen = [-1] * n, [0], [False] * n
    seen[0] = True
    for v in order:
        for u in adj[v]:
            if not seen[u]:
                seen[u] = True
                par[u] = v
                order.append(u)
    size, down = [1] * n, [0] * n
    for v in reversed(order):
        if par[v] >= 0:
            size[par[v]] += size[v]
            down[par[v]] += down[v] + size[v]
    ans = [0] * n
    ans[0] = down[0]
    for v in order[1:]:
        ans[v] = ans[par[v]] - size[v] + (n - size[v])
    return ans
---tests
assert sum_distances(6, [[0, 1], [0, 2], [2, 3], [2, 4], [2, 5]]) == [8, 12, 6, 10, 10, 10]
assert sum_distances(1, []) == [0]
assert sum_distances(2, [[1, 0]]) == [1, 1]
N = 20000
out, t = timed(sum_distances, N, [[i, i + 1] for i in range(N - 1)])
assert out[0] == 199990000 and out[N // 2] == 100000000
assert t < 1.0, f"too slow: {t:.2f}s"
---hint
Running BFS from every node is O(n²). Every child's subtree hangs one edge below its parent, which adds `size[child]` to the parent's `down`.
```

```exercise

---prompt
Return the fewest people to brief so everyone is briefed or adjacent (manager or direct report) to a briefed person. For `b`, every child takes `min(a, b)`, and if none chose `a`, force the cheapest one to `a`. A leaf can't have `b` (use infinity). Answer: `min(a[root], b[root])`.
---starter
def min_briefings(parent):
    kids, order = bfs_order(parent)
    return sum(1 for v in range(len(parent)) if kids[v])
---solution
def min_briefings(parent):
    kids, order = bfs_order(parent)
    n = len(parent)
    INF = float("inf")
    a, b, c = [0] * n, [0] * n, [0] * n
    for v in reversed(order):
        ks = kids[v]
        a[v] = 1 + sum(min(a[k], b[k], c[k]) for k in ks)
        c[v] = sum(b[k] for k in ks)
        if ks:
            base = sum(min(a[k], b[k]) for k in ks)
            extra = min(a[k] - min(a[k], b[k]) for k in ks)
            b[v] = base + extra
        else:
            b[v] = INF
    r = order[0]
    return min(a[r], b[r])
```

## Rebuild it and explain it

```exercise

kind: rebuild
---prompt
From memory: the diameter (most edges on a path) of a general tree with `n` nodes given as an edge list. No recursion: BFS order from node 0, then process it reversed, keeping the two longest downward paths at each node.
---starter
def tree_diameter(n, edges):
    pass
---solution
def tree_diameter(n, edges):
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b)
        adj[b].append(a)
    par, order, seen = [-1] * n, [0], [False] * n
    seen[0] = True
    for v in order:
        for u in adj[v]:
            if not seen[u]:
                seen[u] = True
                par[u] = v
                order.append(u)
    down, best = [0] * n, 0
    for v in reversed(order):
        top1 = top2 = 0
        for u in adj[v]:
            if u != par[v]:
                d = down[u] + 1
                if d > top1:
                    top1, top2 = d, top1
                elif d > top2:
                    top2 = d
        down[v] = top1
        best = max(best, top1 + top2)
    return best
---tests

assert tree_diameter(6, [[0, 1], [1, 2], [2, 3], [1, 4], [4, 5]]) == 4
assert tree_diameter(1, []) == 0
---hint
Same idea as the binary-tree diameter, but a node can have many children: keep only the two biggest.
```

```recall
Q: Explain DP on trees: why subtrees are good subproblems, how to choose what each node reports, the global-best pattern for paths, re-rooting, and how to avoid deep recursion.
A: A tree has no cycles, so each node's subtree is an independent subproblem; solve the children first (post-order) and combine their answers at the node. The key decision is what a node reports to its parent, usually a small tuple covering each situation the parent might need: for the maximum independent set or house robber on a tree, the best with the node taken (its value plus children not taken) and without it (each child's better option), giving O(n) overall where greedy fails. Covering problems like cameras or briefing need three states: has a camera, covered without one, or not covered yet so the parent must act. For paths and diameters, a node returns the longest downward path but updates a global best by joining its two longest child paths, since the answer may bend deep inside the tree. Re-rooting computes an answer for every node as the root in O(n): a bottom-up pass gets subtree sizes and sums, then a top-down pass adjusts across each edge, such as ans[child] = ans[parent] − size[child] + (n − size[child]). In Python, long chains overflow recursion, so process a BFS order in reverse instead.
```
