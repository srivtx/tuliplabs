## Last in, first out

A **stack** is a pile: you add to the top and take from the top. In Python it's just a list: `s.append(x)` pushes, `s.pop()` pops, `s[-1]` peeks. Both are O(1).

Stacks show up whenever the most recent unfinished thing must be finished first: brackets (the latest `(` must close first), undo (the latest change is undone first), function calls (chapter 5's call stack), and expression evaluation.

```run
title: A stack in three lines
s = []
for x in "abc":
    s.append(x)
    print("push", x, s)
while s:
    print("pop ", s.pop(), s)
```

```exercise
title: valid_brackets
kind: write
---prompt
*LeetCode 20, the most common stack question.* A string of `()[]{}` is valid if every opener is closed by the same kind, in the right order. Counting isn't enough: `"([)]"` has the right counts but is invalid.
---starter
def valid(s):
    return s.count("(") == s.count(")") and s.count("[") == s.count("]") and s.count("{") == s.count("}")
---solution
def valid(s):
    pair = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in pair:
            if not stack or stack.pop() != pair[c]:
                return False
        else:
            stack.append(c)
    return not stack
---tests
assert valid("()[]{}")
assert valid("{[()]}")
assert not valid("([)]")
assert not valid("((")
assert not valid("))")
assert valid("")
---hint
Push openers. On a closer, the top of the stack must be its partner: pop and compare. At the end the stack must be empty.
```

```exercise
title: min_stack

---prompt
*LeetCode 155.* Write `class MinStack` with `push(x)`, `pop()`, `top()` and `get_min()`, **all** O(1). The starter remembers the smallest value ever pushed, which goes wrong after that value is popped. Keep, next to each item, the minimum of the stack up to and including it.

---solution
class MinStack:
    def __init__(self):
        self.s = []

    def push(self, x):
        self.s.append((x, min(x, self.s[-1][1]) if self.s else x))

    def pop(self):
        self.s.pop()

    def top(self):
        return self.s[-1][0]

    def get_min(self):
        return self.s[-1][1]
---tests
```

```exercise
title: eval_rpn
kind: write
---prompt
*LeetCode 150.* Evaluate an expression in Reverse Polish Notation: `["2", "1", "+", "3", "*"]` means `(2 + 1) * 3 = 9`. Numbers are pushed; an operator pops two, applies itself, and pushes the result. Division truncates toward zero (`int(a / b)`).
---starter
def eval_rpn(tokens):
    return 0
---solution
def eval_rpn(tokens):
    s = []
    for t in tokens:
        if t in "+-*/":
            b, a = s.pop(), s.pop()
            s.append(a + b if t == "+" else a - b if t == "-" else a * b if t == "*" else int(a / b))
        else:
            s.append(int(t))
    return s[0]
---tests
assert eval_rpn(["2", "1", "+", "3", "*"]) == 9
assert eval_rpn(["4", "13", "5", "/", "+"]) == 6
assert eval_rpn(["10", "6", "9", "3", "+", "-11", "*", "/", "*", "17", "+", "5", "+"]) == 22
assert eval_rpn(["7", "-2", "/"]) == -3
---hint
Pop `b` first, then `a`: the order matters for `-` and `/`. Careful, `"-11"` is a number, not an operator: test with `t in "+-*/"` only works because operators are single characters.
```

```exercise
title: decode_string
kind: write
---prompt
*LeetCode 394, asked at Google.* Decode `"3[a2[c]]"` → `"accaccacc"`: `k[...]` repeats its inside k times, and brackets nest. When you meet `[`, push the text so far and the number; at `]`, pop them and glue.
---starter
def decode(s):
    return s
---solution
def decode(s):
    stack, cur, num = [], "", 0
    for c in s:
        if c.isdigit():
            num = num * 10 + int(c)
        elif c == "[":
            stack.append((cur, num))
            cur, num = "", 0
        elif c == "]":
            prev, k = stack.pop()
            cur = prev + cur * k
        else:
            cur += c
    return cur
---tests
assert decode("3[a]2[bc]") == "aaabcbc"
assert decode("3[a2[c]]") == "accaccacc"
assert decode("2[abc]3[cd]ef") == "abcabccdcdcdef"
assert decode("10[x]") == "x" * 10
assert decode("ab") == "ab"
---hint
Numbers can have several digits (`num = num * 10 + digit`). On `]`, the popped text goes **before** the repeated part.
```

## The monotonic stack

"For each item, find the next item to its right that's bigger" looks like O(n²). The simulation shows the O(n) way: keep a stack of items **still waiting** for their answer.

```viz
name: ds-stack
title: Daily temperatures: scanning right against a monotonic stack
goal: Run **scan right** to the end, then run **monotonic stack** and compare the steps.
height: 460
Watch the stack on the right: from bottom to top its temperatures only ever go down.
```

When a new item arrives, it pops every waiting item smaller than it (it *is* their next greater element), then waits itself. So the waiting items are always in decreasing order: a **monotonic** stack. Each item is pushed once and popped at most once, so the total is O(n).

```exercise
title: daily_temperatures
kind: write
---prompt
*LeetCode 739.* For each day return how many days until a warmer one, or 0 if none, in O(n).
---starter
def daily(t):
    out = []
    for i in range(len(t)):
        wait = 0
        for j in range(i + 1, len(t)):
            if t[j] > t[i]:
                wait = j - i
                break
        out.append(wait)
    return out
---solution
def daily(t):
    out, stack = [0] * len(t), []
    for i, x in enumerate(t):
        while stack and t[stack[-1]] < x:
            j = stack.pop()
            out[j] = i - j
        stack.append(i)
    return out
---tests
assert daily([73, 74, 75, 71, 69, 72, 76, 73]) == [1, 1, 4, 2, 1, 1, 0, 0]
assert daily([30, 40, 50, 60]) == [1, 1, 1, 0]
assert daily([30, 60, 90]) == [1, 1, 0]
assert daily([]) == []
cold = list(range(3000, 0, -1)) + [5000]
r, secs = timed(daily, cold)
assert r[0] == 3000 and secs < 0.03, f"{secs:.2f}s: keep a stack of waiting days instead of scanning"
---hint
Store **indices** on the stack (you need them for the distance). While today is warmer than the day on top, pop it and record `i - j`.
```

```exercise
title: next_greater_circular
kind: write
---prompt
*LeetCode 503.* Same as next greater element, but the list is **circular**: after the last item, search continues from the start. Walk the list twice (indices `0 .. 2n - 1`, using `i % n`), only pushing during the first pass.
---starter
def next_greater_circular(a):
    out = [-1] * len(a)
    stack = []
    for i, x in enumerate(a):
        while stack and a[stack[-1]] < x:
            out[stack.pop()] = x
        stack.append(i)
    return out
---solution
def next_greater_circular(a):
    n = len(a)
    out, stack = [-1] * n, []
    for i in range(2 * n):
        x = a[i % n]
        while stack and a[stack[-1]] < x:
            out[stack.pop()] = x
        if i < n:
            stack.append(i)
    return out
---tests
assert next_greater_circular([1, 2, 1]) == [2, -1, 2]
assert next_greater_circular([1, 2, 3, 4, 3]) == [2, 3, 4, -1, 4]
assert next_greater_circular([5, 5]) == [-1, -1]
---hint
The second pass only resolves items still waiting from the first; it never adds new ones.
```

```exercise
title: remove_k_digits
kind: write
---prompt
*LeetCode 402.* Remove `k` digits from the number string to make it as small as possible. Return it without leading zeros (`"0"` if empty). Greedy with an increasing stack: while the last kept digit is bigger than the new one and you still may remove, pop it.
---starter
def remove_k(num, k):
    return num[k:] or "0"
---solution
def remove_k(num, k):
    stack = []
    for d in num:
        while k and stack and stack[-1] > d:
            stack.pop()
            k -= 1
        stack.append(d)
    if k:
        stack = stack[:-k]
    return "".join(stack).lstrip("0") or "0"
---tests
assert remove_k("1432219", 3) == "1219"
assert remove_k("10200", 1) == "200"
assert remove_k("10", 2) == "0"
assert remove_k("12345", 2) == "123"
assert remove_k("9", 1) == "0"
---hint
A bigger digit before a smaller one is always worth removing (it's in a more important place). If removals are left at the end, the digits are increasing: drop from the right.
```

```exercise
title: largest_rectangle
kind: write
---prompt
*LeetCode 84, a famous hard one.* Bars of width 1 have the given heights. Return the area of the largest rectangle inside the histogram. With an increasing stack: when a bar shorter than the top arrives, the top's rectangle can't extend further right, and its left edge is the bar below it on the stack.
---starter
def largest_rectangle(h):
    best = 0
    for i in range(len(h)):
        low = h[i]
        for j in range(i, len(h)):
            low = min(low, h[j])
            best = max(best, low * (j - i + 1))
    return best
---solution
def largest_rectangle(h):
    stack, best = [], 0
    for i, x in enumerate(h + [0]):
        while stack and h[stack[-1]] >= x:
            height = h[stack.pop()]
            left = stack[-1] + 1 if stack else 0
            best = max(best, height * (i - left))
        stack.append(i)
    return best
---tests
assert largest_rectangle([2, 1, 5, 6, 2, 3]) == 10
assert largest_rectangle([2, 4]) == 4
assert largest_rectangle([1, 1, 1, 1]) == 4
assert largest_rectangle([]) == 0
r, secs = timed(largest_rectangle, list(range(1, 2500)))
assert r == 1250 * 1250 and secs < 0.03, f"{secs:.2f}s: one pass with an increasing stack"
---hint
Append a 0 at the end so everything gets popped. For a popped bar, the rectangle spans from just after the new stack top to just before `i`.
```

```exercise
title: longest_valid_parens
kind: write
---prompt
*Codeforces 5C / LeetCode 32.* Return the length of the longest substring of `(` and `)` that is a valid bracket sequence. Push indices of `(`; keep the index of the last unmatched `)` at the bottom of the stack as a "wall".
---starter
def longest_valid(s):
    return 2 * min(s.count("("), s.count(")"))
---solution
def longest_valid(s):
    stack, best = [-1], 0
    for i, c in enumerate(s):
        if c == "(":
            stack.append(i)
        else:
            stack.pop()
            if not stack:
                stack.append(i)
            else:
                best = max(best, i - stack[-1])
    return best
---tests
assert longest_valid("(()") == 2
assert longest_valid(")()())") == 4
assert longest_valid("") == 0
assert longest_valid("()(())") == 6
assert longest_valid("())(())") == 4
---hint
Start the stack with `-1`. On `)`, pop; if the stack is now empty, this `)` is unmatched, so push its index as the new wall; otherwise the valid stretch ends at `i` and starts after `stack[-1]`.
```

```exercise
title: editor
kind: write
---prompt
Write `class Editor` with `text` (a string, initially `""`), `type(s)`, `delete(n)` (remove up to n characters from the end), `undo()` and `redo()` (each does nothing if there's nothing to undo/redo). A new `type` or `delete` clears the redo stack.
---starter
class Editor:
    def __init__(self):
        self.text = ""

    def type(self, s):
        self.text += s

    def delete(self, n):
        self.text = self.text[:len(self.text) - n]

    def undo(self):
        pass

    def redo(self):
        pass
---solution
class Editor:
    def __init__(self):
        self.text, self.undos, self.redos = "", [], []

    def _apply(self, action):
        kind, s = action
        if kind == "type":
            self.text += s
        else:
            self.text = self.text[:len(self.text) - len(s)]

    def _reverse(self, action):
        kind, s = action
        return ("delete" if kind == "type" else "type", s)

    def type(self, s):
        self._apply(("type", s))
        self.undos.append(("type", s))
        self.redos.clear()

    def delete(self, n):
        gone = self.text[len(self.text) - n:] if n else ""
        self._apply(("delete", gone))
        self.undos.append(("delete", gone))
        self.redos.clear()

    def undo(self):
        if self.undos:
            a = self.undos.pop()
            self._apply(self._reverse(a))
            self.redos.append(a)

    def redo(self):
        if self.redos:
            a = self.redos.pop()
            self._apply(a)
            self.undos.append(a)
---tests
e = Editor()
e.type("hello"); e.type(" world"); e.delete(3)
assert e.text == "hello wo"
e.undo()
assert e.text == "hello world"
e.undo()
assert e.text == "hello"
e.redo()
assert e.text == "hello world"
e.type("!")
e.redo()
assert e.text == "hello world!", "a new edit clears redo"
e.undo(); e.undo(); e.undo(); e.undo()
assert e.text == ""
---hint
Store each action with enough information to reverse it: for a delete, remember the characters that were removed. Undo applies the reverse; redo applies the action again.
```

```exercise
title: browser_history
kind: write
---prompt
Write `class History` starting at a `home` page with `visit(url)`, `back(steps)` and `forward(steps)`; back and forward move as far as possible and return the current page. Visiting clears the forward history. Use two stacks.
---starter
class History:
    def __init__(self, home):
        self.cur = home

    def visit(self, url):
        self.cur = url

    def back(self, steps):
        return self.cur

    def forward(self, steps):
        return self.cur
---solution
class History:
    def __init__(self, home):
        self.cur, self.past, self.future = home, [], []

    def visit(self, url):
        self.past.append(self.cur)
        self.cur = url
        self.future.clear()

    def back(self, steps):
        while steps and self.past:
            self.future.append(self.cur)
            self.cur = self.past.pop()
            steps -= 1
        return self.cur

    def forward(self, steps):
        while steps and self.future:
            self.past.append(self.cur)
            self.cur = self.future.pop()
            steps -= 1
        return self.cur
---tests
h = History("home")
h.visit("a"); h.visit("b"); h.visit("c")
assert h.back(1) == "b"
assert h.back(1) == "a"
assert h.forward(1) == "b"
h.visit("x")
assert h.forward(2) == "x"
assert h.back(2) == "a"
assert h.back(9) == "home"
---hint
`past` holds pages behind you, `future` pages ahead. Moving back pushes the current page onto `future` and pops from `past`.
```

```recall
Q: Explain stacks and the monotonic stack: what problems they solve and why the monotonic stack is O(n).
A: A stack is last-in-first-out: in Python a list with append to push, pop to pop and [-1] to peek, all O(1). Use one whenever the most recent unfinished thing must be finished first: matching brackets (push openers, a closer must match the top, the stack must end empty), undo/redo (two stacks of reversible actions), evaluating postfix expressions, decoding nested strings, and simulating recursion. A monotonic stack keeps indices of items still waiting for an answer, such as their next greater element: each new item pops every waiting item smaller than it (recording itself as their answer) and then waits too, so the stack's values stay decreasing from bottom to top. Each item is pushed once and popped at most once, so despite the while inside the for it's O(n) in total. Variants: increasing stacks for next smaller element and the largest rectangle in a histogram, circular arrays by walking twice, and greedy digit removal.
```
