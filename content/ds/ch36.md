## The table is right, the cells are slow

Sometimes the DP is correct but too slow, because each cell **looks back over a whole range**:

- `ways[i] = ways[i − 1] + … + ways[i − k]` costs k per cell: O(n·k)
- `best[i] = nums[i] + max(best[i − k .. i − 1])` costs k per cell
- `best[j] = max over i < j of (value[i] + i) + value[j] − j` costs j per cell: O(n²)

Neighbouring cells look at **almost the same range**, and data structures from earlier chapters can answer "sum / max / min of this sliding range" in O(1) amortised.

```run
title: Window sums for the frog, both ways
n, k, broken = 20, 5, {4, 9, 10, 15}
slow, fast = [0] * n, [0] * n
slow[0] = fast[0] = 1
window = 0
for i in range(1, n):
    slow[i] = 0 if i in broken else sum(slow[max(0, i - k):i])
    window += fast[i - 1]
    if i - k - 1 >= 0:
        window -= fast[i - k - 1]
    fast[i] = 0 if i in broken else window
print(slow == fast, fast[-1])
```

## Max, min and "best so far"

When the transition needs the **max** of a sliding range, a running total won't do (you can't "subtract" a max). Keep a monotonic deque of indexes whose dp values decrease from front to back: the front is the max, anything smaller than a newcomer at the back can never win again, and indexes that fall out of range leave from the front.

When the range is "everything before me", it never shrinks, so a single variable holding the best so far is enough.

```exercise
title: constrained_subsequence_sum
kind: write
---prompt
*LeetCode 1425, a hard one asked at Amazon.* Choose a non-empty subsequence where neighbouring chosen indexes are at most `k` apart. Return the largest sum. `dp[i] = nums[i] + max(0, max(dp[i − k .. i − 1]))`, with the max from a monotonic deque.
---starter
def constrained_sum(nums, k):
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best
---solution
def constrained_sum(nums, k):
    dp = [0] * len(nums)
    dq = deque()
    best = float("-inf")
    for i, x in enumerate(nums):
        if dq and dq[0] < i - k:
            dq.popleft()
        dp[i] = x + max(0, dp[dq[0]] if dq else 0)
        best = max(best, dp[i])
        while dq and dp[dq[-1]] <= dp[i]:
            dq.pop()
        dq.append(i)
    return best
---tests
assert constrained_sum([10, 2, -10, 5, 20], 2) == 37
assert constrained_sum([-1, -2, -3], 1) == -1
assert constrained_sum([10, -2, -10, -5, 20], 2) == 23
assert constrained_sum([1, -1, 1], 1) == 1
---hint
The starter is Kadane (k = 1: neighbours must touch). With k > 1 you may skip up to k − 1 numbers, such as the −10 in the first test.
```

```exercise
title: dice_rolls
kind: write
---prompt
*LeetCode 1155, asked at Google and Amazon.* Count the ways `n` dice with faces `1..k` can total `target`, modulo 1,000,000,007. After each die, `new[t] = old[t − 1] + … + old[t − k]`: a range sum, so build prefix sums of `old` once per die.
---starter
def dice_ways(n, k, target):
    M = 10 ** 9 + 7
    dp = [1] + [0] * target
    for _ in range(n):
        dp = [sum(dp[:t]) % M for t in range(target + 1)]
    return dp[target]
---solution
def dice_ways(n, k, target):
    M = 10 ** 9 + 7
    dp = [1] + [0] * target
    for _ in range(n):
        pre = [0]
        for v in dp:
            pre.append((pre[-1] + v) % M)
        dp = [(pre[t] - pre[max(0, t - k)]) % M for t in range(target + 1)]
    return dp[target]
---tests
assert dice_ways(1, 6, 3) == 1
assert dice_ways(2, 6, 7) == 6
assert dice_ways(1, 2, 3) == 0
assert dice_ways(30, 30, 500) == 222616187
---hint
The starter forgot the faces stop at `k`: it sums every earlier total. `pre[t] − pre[t − k]` is `old[t − k] + … + old[t − 1]`.
```

```exercise
title: new_21_game
kind: write
---prompt
*LeetCode 837, asked at Google.* Start at 0 points; while below `k`, draw a uniformly random number from `1..max_pts` and add it. Return the probability you finish with **at most** `n` points. `p[i] = (sum of p[j] for j in [i − max_pts, i − 1] with j < k) / max_pts`: keep that sum in a running window.
---starter
def new21(n, k, max_pts):
    return min(1.0, n / (k + max_pts))
---solution
def new21(n, k, max_pts):
    if k == 0 or n >= k - 1 + max_pts:
        return 1.0
    p = [0.0] * (n + 1)
    p[0] = 1.0
    window, result = 1.0, 0.0
    for i in range(1, n + 1):
        p[i] = window / max_pts
        if i < k:
            window += p[i]
        else:
            result += p[i]
        if i - max_pts >= 0 and i - max_pts < k:
            window -= p[i - max_pts]
    return result
---tests
assert abs(new21(10, 1, 10) - 1.0) < 1e-9
assert abs(new21(6, 1, 10) - 0.6) < 1e-9
assert abs(new21(21, 17, 10) - 0.73278) < 1e-5
assert abs(new21(100, 90, 20) - 0.78569) < 1e-5
assert abs(new21(5710, 5000, 1000) - 0.91627) < 1e-5
---hint
Only totals below `k` keep drawing, so only they feed the window. Totals from `k` to `n` are where you stop and win.
```

```exercise
title: best_sightseeing_pair
kind: write
---prompt
*LeetCode 1014, asked at Wayfair and Amazon.* A pair `i < j` scores `values[i] + values[j] + i − j`. Return the best score. Split it: `(values[i] + i) + (values[j] − j)`. For each `j`, you only need the best `values[i] + i` seen so far.
---starter
def best_pair(values):
    a = sorted(range(len(values)), key=lambda i: -values[i])[:2]
    i, j = min(a), max(a)
    return values[i] + values[j] + i - j
---solution
def best_pair(values):
    best_left = values[0]
    ans = float("-inf")
    for j in range(1, len(values)):
        ans = max(ans, best_left + values[j] - j)
        best_left = max(best_left, values[j] + j)
    return ans
---tests

assert best_pair([1, 2]) == 2
```

## Real-world project: a drone's charging hops

```project
title: Cheapest hops for a delivery drone
client: A drone delivery startup whose drones fly a corridor of charging pads; a drone can fly past at most a few pads between charges, and each pad charges a different landing fee

---why
Routing with range limits (drones, EV charging, frog-jump planning in games), streaming video bitrate choices and some scheduling problems become sliding-window DPs that must run in O(n) on long inputs.
---milestones

- Replace the inner loop with a monotonic deque (min version)
```

```exercise
title: min_hop_cost
kind: write
---prompt
Return the cheapest total of `fees` paid on pads landed on, from pad 0 to pad `n − 1`, jumping 1 to `k` pads at a time. `dp[i] = fees[i] + min(dp[i − k .. i − 1])` with a deque of increasing `dp` values.
---starter
def min_hop_cost(fees, k):
    n, i, total = len(fees), 0, fees[0]
    while i < n - 1:
        j = min(range(i + 1, min(n, i + k + 1)), key=lambda j: fees[j])
        total += fees[j]
        i = j
    return total
---solution
def min_hop_cost(fees, k):
    n = len(fees)
    dp = [0] * n
    dp[0] = fees[0]
    dq = deque([0])
    for i in range(1, n):
        while dq[0] < i - k:
            dq.popleft()
        dp[i] = fees[i] + dp[dq[0]]
        while dq and dp[dq[-1]] >= dp[i]:
            dq.pop()
        dq.append(i)
    return dp[-1]
---tests
assert min_hop_cost([0, 5, 2, 8, 1, 9, 3, 0], 3) == 3
assert min_hop_cost([4, 1, 1, 1, 4], 1) == 11
assert min_hop_cost([0, 0], 1) == 0
assert min_hop_cost([3, 1, 50, 1, 50, 50, 1, 4], 2) == 59
assert min_hop_cost([5, 1, 8, 9, 2, 7, 3, 5], 3) == 13
---hint
The starter greedily hops to the cheapest next pad, which can strand it in front of expensive ones. Flip the deque's comparison for a min.
```

```exercise
title: min_hop_route
kind: write
---prompt
Return `(cost, pads)` where `pads` lists the pads landed on, from 0 to `n − 1`. When you set `dp[i]`, remember `par[i] = dq[0]`, then walk back from `n − 1`.
---starter
def min_hop_route(fees, k):
    return sum(fees), list(range(len(fees)))
---solution
def min_hop_route(fees, k):
    n = len(fees)
    dp, par = [0] * n, [-1] * n
    dp[0] = fees[0]
    dq = deque([0])
    for i in range(1, n):
        while dq[0] < i - k:
            dq.popleft()
        dp[i] = fees[i] + dp[dq[0]]
        par[i] = dq[0]
        while dq and dp[dq[-1]] >= dp[i]:
            dq.pop()
        dq.append(i)
    pads, i = [], n - 1
    while i >= 0:
        pads.append(i)
        i = par[i]
    return dp[-1], pads[::-1]
---tests

assert min_hop_route([4, 1, 1, 1, 4], 2) == (9, [0, 2, 4])
assert min_hop_route([3, 7], 1) == (10, [0, 1])
---hint
Pad 0 has no parent (-1), which ends the walk back.
```

## Rebuild it and explain it

```exercise
title: speedup_rebuild
kind: rebuild
---prompt
From memory: *LeetCode 1871*. `s` is a string of `0`s and `1`s; you start at index 0 and may jump from `i` to any `j` with `i + lo ≤ j ≤ i + hi` and `s[j] == "0"`. Can you reach the last index? Keep prefix counts of reachable indexes so each check is O(1).
---starter
def can_reach(s, lo, hi):
    pass
---solution
def can_reach(s, lo, hi):
    n = len(s)
    ok = [False] * n
    ok[0] = True
    pre = [0] * (n + 1)
    pre[1] = 1
    for i in range(1, n):
        if s[i] == "0":
            left, right = i - hi, i - lo
            if right >= 0 and pre[right + 1] - pre[max(0, left)] > 0:
                ok[i] = True
        pre[i + 1] = pre[i] + ok[i]
    return ok[-1]
---tests
assert can_reach("011010", 2, 3)
assert not can_reach("01101110", 2, 3)
assert can_reach("00", 1, 1)
assert can_reach("0" + "1" * 5 + "0", 6, 6)
assert not can_reach("0000000000", 8, 8)
---hint
Index `i` is reachable if any reachable index lies in `[i − hi, i − lo]`. A prefix count answers "how many in this range?" by subtraction.
```

```recall
Q: Explain how to speed up a DP whose transition looks back over a range: which structure fits which transition, why the answer doesn't change, and how to recover the choices.
A: Some DPs are correct but slow because each cell scans a range of earlier cells, costing O(n·k) or O(n²). Neighbouring cells look at almost the same range, so a data structure can answer each range query in O(1) amortised while the states and recurrence stay exactly the same, giving the same table. A sum over a sliding range uses a running total (add the cell that enters, subtract the one that leaves, i − k − 1 for a window of k ending at i − 1) or prefix sums, as in counting frog jumps, dice totals or the New 21 Game probabilities, and prefix counts answer "is any index in this range reachable?". A max or min over a sliding range uses a monotonic deque of indexes, dropping indexes that leave from the front and dominated ones from the back, as in Jump Game VI and constrained subsequence sum. When the range is everything before, one best-so-far variable is enough, often after separating the terms that depend on i from those that depend on j. Recording which index produced each cell lets you walk back and recover the chosen hops. Harder versions use the convex hull trick, divide and conquer or Knuth optimisation.
```
