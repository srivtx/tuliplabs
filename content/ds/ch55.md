import time

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t

def lcg(n, seed, mx):
    out, x = [], seed
    for _ in range(n):
        x = (x * 1103515245 + 12345) % 2 ** 31
        out.append(x % mx)
    return out

def planted(n, m, seed):
    """m random clauses on variables 1..n, all satisfied by a hidden assignment."""
    g = [x / 10 ** 9 for x in lcg(4 * m + n, seed, 10 ** 9)]
    hidden = [g[i] < 0.5 for i in range(n)]
    clauses = []
    for i in range(m):
        a, b = int(g[n + 4 * i] * n) + 1, int(g[n + 4 * i + 1] * n) + 1
        la = a if g[n + 4 * i + 2] < 0.5 else -a
        lb = b if g[n + 4 * i + 3] < 0.5 else -b
        if not (hidden[abs(la) - 1] == (la > 0) or hidden[abs(lb) - 1] == (lb > 0)):
            la = -la
        clauses.append((la, lb))
    return clauses

def satisfies(clauses, a):
    return all(a[abs(x) - 1] == (x > 0) or a[abs(y) - 1] == (y > 0) for x, y in clauses)

## Choices with rules about pairs

You have n yes/no choices and a list of rules, each about **two** of them: "at least one of p and q". Write a choice as a number 1..n and its opposite as a negative number, so `(3, -1)` means "c is true, or a is false". Can every rule hold at once?

With rules about **three** at a time this is 3-SAT, one of the hardest problems known (no one has a fast method). With two at a time it's easy, because every rule is really two **implications**:

`p or q` means `if not p then q`, and `if not q then p`.

```viz

height: 440
Top row: a, b, c, d. Bottom row: their opposites. Arrows read "if this, then that".
```

Build a graph with a node for every literal (x₁, ¬x₁, x₂, ¬x₂…) and those two arrows per rule. Then:

1. **Impossible** exactly when some x and ¬x are in the **same strongly connected component**: x forces ¬x and ¬x forces x, so neither value works.
2. **Otherwise**, run Kosaraju (chapter 51), which numbers the components in **topological order**, and set x true when `comp[x] > comp[¬x]`. Picking the side that comes **later** means you never pick a literal that forces its own opposite downstream.

It's O(n + m): two passes over a graph with 2n nodes and 2m arrows. Python's recursion won't survive 10⁵ nodes, so the passes are iterative.

Many conditions turn into clauses:

| condition | clauses |
|---|---|
| p must be true | (p, p) |
| not both p and q | (¬p, ¬q) |
| exactly one of p, q | (p, q) and (¬p, ¬q) |
| p and q equal | (p, ¬q) and (¬p, q) |

```run
title: 2-SAT with an implication graph
def two_sat(n, clauses):
    N = 2 * n
    node = lambda l: 2 * (abs(l) - 1) + (0 if l > 0 else 1)   # x -> 2(x-1), not x -> 2(x-1)+1
    out = [[] for _ in range(N)]
    inn = [[] for _ in range(N)]
    for a, b in clauses:
        for x, y in ((node(-a), node(b)), (node(-b), node(a))):
            out[x].append(y)
            inn[y].append(x)
    seen, order = [False] * N, []
    for s in range(N):
        if seen[s]:
            continue
        seen[s] = True
        st = [(s, 0)]
        while st:
            x, i = st[-1]
            if i < len(out[x]):
                st[-1] = (x, i + 1)
                y = out[x][i]
                if not seen[y]:
                    seen[y] = True
                    st.append((y, 0))
            else:
                st.pop()
                order.append(x)
    comp, c = [-1] * N, 0
    for s in reversed(order):
        if comp[s] != -1:
            continue
        comp[s] = c
        st = [s]
        while st:
            x = st.pop()
            for y in inn[x]:
                if comp[y] == -1:
                    comp[y] = c
                    st.append(y)
        c += 1
    res = []
    for v in range(n):
        if comp[2 * v] == comp[2 * v + 1]:
            return None
        res.append(comp[2 * v] > comp[2 * v + 1])
    return res

R = [(3, 2), (3, -1), (2, -3), (1, -2), (-2, 4), (-3, 1)]
print(two_sat(4, R))
print(two_sat(1, [(1, 1), (-1, -1)]))
```

## Quick-fire: lock it in

```quiz
Why is 2-SAT fast when 3-SAT is believed to be hard?
- 2 is smaller than 3
* A two-literal clause becomes implications (one false forces the other true), so the whole problem is reachability in a graph; three-literal clauses don't turn into single implications
- 3-SAT needs more memory
- They're both fast
> "if not p then q" only works when there's exactly one other literal to force.
```

```quiz
x and ¬x are in the same SCC. What does that mean?
- x must be true
* There's no valid assignment: x forces ¬x and ¬x forces x
- x can be either
- Nothing
> Same component means each reaches the other through implications.
```

```quiz
How do you force p to be true with 2-SAT clauses?
* Add the clause (p, p): its arrow ¬p → p makes ¬p contradict itself
- Add (p, ¬p)
- Delete ¬p
- You can't
> (p, ¬p) is always true and forces nothing.
```

```quiz
Kosaraju numbers components in topological order. Which literal do you set true?
- The one in the lower-numbered component
* The one in the higher-numbered (later) component
- Always the positive one
- A random one
> The later side can't reach the earlier one, so making it true never forces its own opposite.
```

    for s in range(N):
        if seen[s]:
            continue
        seen[s] = True
        st = [(s, 0)]
        while st:
            x, i = st[-1]
            if i < len(out[x]):
                st[-1] = (x, i + 1)
                y = out[x][i]
                if not seen[y]:
                    seen[y] = True
                    st.append((y, 0))
            else:
                st.pop()
                order.append(x)
    comp, c = [-1] * N, 0
    for s in reversed(order):
        if comp[s] != -1:
            continue
        comp[s] = c
        st = [s]
        while st:
            x = st.pop()
            for y in inn[x]:
                if comp[y] == -1:
                    comp[y] = c
                    st.append(y)
        c += 1
    res = []
    for v in range(n):
        if comp[2 * v] == comp[2 * v + 1]:
            return None
        res.append(comp[2 * v] > comp[2 * v + 1])
    return res
---tests

---hint

```recall
Q: Explain 2-SAT: how a clause becomes implications, how the implication graph decides satisfiability, how to read off an assignment and why, the running time, and how to encode "must be true", "not both" and "exactly one".
A: Each clause (p or q) is equivalent to two implications, ¬p → q and ¬q → p. Build a graph with a node for every literal (2n nodes) and these two arrows per clause. If x and ¬x are in the same strongly connected component, x forces ¬x and ¬x forces x, so no assignment exists. Otherwise one does. Kosaraju numbers components in topological order (arrows go from lower to higher numbers), and setting x true when comp[x] > comp[¬x] picks the later side for every variable. That literal can't reach its own negation, so no chosen literal forces a contradiction. It's O(n + m) with two iterative DFS passes. Encodings: "p must be true" is (p, p); "not both" is (¬p, ¬q); "exactly one" is (p, q) plus (¬p, ¬q); "equal" is (p, ¬q) plus (¬p, q). Clauses of three literals (3-SAT) don't reduce to single implications, and no fast algorithm is known for them.
```
