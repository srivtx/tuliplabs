## Searching without going back

`text.find(pattern)` looks easy: try every start, compare letter by letter, stop at the first mismatch. Usually that's fast. But on a text like `aaaa…ab` and a pattern `aaa…ab`, every start matches almost the whole pattern before failing. That's n × m comparisons, 10¹⁰ for a megabyte text and a 10,000-letter pattern.

The waste is this: after matching `ABABA` and failing on the next letter, the obvious search slides one place and **re-reads** letters it has already seen. But you already know what those letters are. They're the start of the pattern.

A **border** of a string is a proper prefix that's also a suffix: `aba` is a border of `abacaba`. The **prefix function** `pi[i]` is the length of the longest border of `s[0..i]`. For `ABABAC` it's `[0, 0, 1, 2, 3, 0]`: `ABABA` ends with `ABA`, which is also how it starts.

**KMP** (Knuth, Morris and Pratt) keeps `j`, how many pattern letters currently match. For each text letter:

1. While `j > 0` and the letter doesn't match `pattern[j]`, fall back: `j = pi[j − 1]`. The `pi[j − 1]` letters still line up, so you keep them.
2. If it matches, `j += 1`. If `j == m`, record a match and fall back once more to look for overlapping ones.

The text pointer only moves forward. Each fall-back undoes at least one earlier step forward, so the total work is at most 2n. Building `pi` is the same loop run on the pattern against itself: O(m).

The **Z-function** is a cousin. `z[i]` is the length of the longest stretch starting at i that matches the **start** of the string. Search by building z of `pattern + "\0" + text`: wherever `z[i] ≥ m`, the pattern starts there. It's built in O(n) by remembering the rightmost match window `[l, r)` and reusing it, the same "don't re-read what you've seen" idea.

```run
title: The prefix function and KMP search
def prefix_function(s):
    pi = [0] * len(s)
    k = 0
    for i in range(1, len(s)):
        while k and s[i] != s[k]:
            k = pi[k - 1]
        if s[i] == s[k]:
            k += 1
        pi[i] = k
    return pi

def kmp_search(text, pat):
    pi, out, j = prefix_function(pat), [], 0
    for i, ch in enumerate(text):
        while j and ch != pat[j]:
            j = pi[j - 1]
        if ch == pat[j]:
            j += 1
        if j == len(pat):
            out.append(i - len(pat) + 1)
            j = pi[j - 1]
    return out

print(prefix_function("ABABAC"), prefix_function("abacaba"))
print(kmp_search("ABABABACABABABABACAB", "ABABAC"))
print(kmp_search("aaaaa", "aa"))
text = "a" * 200000
print(timed(lambda: len(kmp_search(text, "a" * 5000)))[0])
```

```exercise
title: z_function
kind: write
---prompt
Write `z_function(s)`: `z[i]` is the length of the longest common prefix of `s` and `s[i:]`, with `z[0] = len(s)`. Keep the window `[l, r)` of the rightmost match: inside it, start from `min(r − i, z[i − l])` instead of 0. 200,000 letters.
---starter
def z_function(s):
    n = len(s)
    z = [0] * n
    if n:
        z[0] = n
    for i in range(1, n):
        if s[i] == s[0]:
            z[i] = 1
    return z
---solution
def z_function(s):
    n = len(s)
    z = [0] * n
    if n:
        z[0] = n
    l = r = 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    return z
---tests
assert z_function("aabxaab") == [7, 1, 0, 0, 3, 1, 0]
assert z_function("aaaaa") == [5, 4, 3, 2, 1]
z = z_function(word(200000, 5, 2))
assert sum(z) == 399898 and max(z[1:]) == 19
big = z_function("a" * 100000)
assert big[50000] == 50000
---hint
Without the window, "aaaa…" costs n² comparisons. `s[l..r)` equals `s[0..r−l)`, so position i inside it mirrors position `i − l`.
```

```exercise
title: shortest_palindrome
kind: write
---prompt
*LeetCode 214, a hard one asked at Google.* Add letters to the **front** of `s` to make the shortest palindrome. The trick: the longest palindrome that starts at position 0 is the longest border of `s + "#" + reversed(s)`. Keep it, and put the rest, reversed, in front. 200,000 letters.
---starter

---solution
def shortest_palindrome(s):
    if not s:
        return s
    t = s + "#" + s[::-1]
    pi = [0] * len(t)
    k = 0
    for i in range(1, len(t)):
        while k and t[i] != t[k]:
            k = pi[k - 1]
        if t[i] == t[k]:
            k += 1
        pi[i] = k
    return s[pi[-1]:][::-1] + s
---tests
```

```exercise
title: repeated_substring
kind: write
---prompt
*LeetCode 459, asked at Amazon and Google.* Is `s` some shorter string repeated two or more times? The **shortest period** of s is `n − pi[n − 1]`; s is a repeat exactly when that period is shorter than n and divides n.
---starter
def repeated(s):
    return len(s) % 2 == 0 and s[:len(s) // 2] == s[len(s) // 2:]
---solution
def repeated(s):
    pi = [0] * len(s)
    k = 0
    for i in range(1, len(s)):
        while k and s[i] != s[k]:
            k = pi[k - 1]
        if s[i] == s[k]:
            k += 1
        pi[i] = k
    n = len(s)
    per = n - pi[-1]
    return per < n and n % per == 0
---tests
assert repeated("abab") and repeated("abcabcabcabc") and repeated("aaa")
assert not repeated("aba") and not repeated("a") and not repeated("abac")
assert repeated("xyz" * 33333) and not repeated("xyz" * 33333 + "x")
---hint
The starter only tries halves, so it misses "abc" × 3. A border of length b means s repeats with period n − b.
```

```quiz
Why is KMP's search O(n) even though it has a while loop inside a for loop?
- The while loop runs at most once
* j goes up by at most 1 per text letter, and each fall-back lowers it, so all the fall-backs together are at most n
- Strings are short
- The table is sorted
> Amortised counting: you can't go down more than you went up.
```


```exercise

def count_occurrences(text, pat):
    pi = [0] * len(pat)
    k = 0
    for i in range(1, len(pat)):
        while k and pat[i] != pat[k]:
            k = pi[k - 1]
        if pat[i] == pat[k]:
```

```recall
Q: Explain KMP: what a border and the prefix function are, how the search uses the table after a mismatch and after a match, why it's O(n + m), how the Z-function differs and searches, and one more problem borders solve.
A: A border of a string is a proper prefix that is also a suffix. The prefix function pi[i] is the length of the longest border of s[0..i], and it's built by carrying k, the current border length: extend it when s[i] == s[k], otherwise fall back to pi[k − 1] and try again. KMP walks the text once, keeping j, the number of pattern letters matched so far. On a mismatch with j > 0 it sets j = pi[j − 1], because those letters still line up with the start of the pattern, and retries the same text letter. On a full match it records the position and sets j = pi[m − 1], so overlapping matches are found. The text pointer never moves back, and j rises by at most 1 per letter and only falls after rising, so the search is O(n) and the table O(m). The Z-function instead stores z[i], the longest common prefix of s and s[i:], built in O(n) by reusing the rightmost match window [l, r). To search, compute z of pattern + separator + text; the pattern starts wherever z ≥ m. Borders also give the shortest period, n − pi[n − 1] (s is a repeated block when that divides n), and the shortest palindrome: the longest border of s + "#" + reversed(s).
```
