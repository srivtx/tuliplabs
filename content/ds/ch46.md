```prelude
import time
from math import gcd

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t

def lcg(n, seed, mx):
    out, x = [], seed
    for _ in range(n):
        x = (x * 1103515245 + 12345) % 2 ** 31
        out.append(x % mx)
    return out

def walk(n, seed, step, start):
    """A random walk: each value is the last one plus something in -step..step."""
    out, v = [], start
    for d in lcg(n, seed, 2 * step + 1):
        v += d - step
        out.append(v)
    return out
```

## When the numbers never change

Segment trees and Fenwick trees pay O(log n) per question so that the numbers can **change**. Very often they don't: a day of stock prices, a fixed array in a contest, the depths of an Euler tour (next chapter). Then you can do better.

A **sparse table** stores, for every start `i` and every power of two `2ᵏ`, the minimum of the block `a[i .. i + 2ᵏ − 1]`. Row 0 is the array. Each row comes from the one below: a block of 2ᵏ is two blocks of 2ᵏ⁻¹ side by side.

```viz

```

To answer `min(a[l..r])`, let `k` be the biggest power with `2ᵏ ≤ length`. Two blocks of that size, one starting at `l` and one **ending** at `r`, cover the whole range. They usually overlap in the middle, and that's fine: `min(x, x) = x`, so a number counted twice changes nothing.

That gives you a rule for when a sparse table works. The operation must be **idempotent** (doing it twice is the same as once): min, max, gcd, bitwise AND and OR. Sum is not: an overlapping cell would be added twice. For sums of a fixed array you already have prefix sums.

| | build | question | updates |
|---|---|---|---|
| scan | none | O(n) | O(1) |
| sparse table | O(n log n) | **O(1)** | rebuild everything |
| segment tree | O(n) | O(log n) | O(log n) |

`k` comes from `(r − l + 1).bit_length() − 1`, which is ⌊log₂ length⌋ without any floating point.

```run
title: A sparse table for range minimums
class SparseMin:
    def __init__(self, a):
        self.sp = [list(a)]
        k = 1
        while (1 << k) <= len(a):
            prev, h = self.sp[-1], 1 << (k - 1)
            self.sp.append([min(prev[i], prev[i + h]) for i in range(len(a) - (1 << k) + 1)])
            k += 1

    def query(self, l, r):
        k = (r - l + 1).bit_length() - 1
        return min(self.sp[k][l], self.sp[k][r - (1 << k) + 1])

t = SparseMin([7, 2, 9, 4, 8, 6, 1, 5, 9, 3])
for row in t.sp:
    print(row)
print(t.query(0, 9), t.query(2, 5), t.query(7, 9), t.query(4, 4))
```

## Sparse tables in the wild

```exercise
title: longest_calm_stretch
kind: write
---prompt
*LeetCode 1438, asked at Google and Uber.* Return the length of the longest contiguous subarray whose **max − min ≤ limit**. Build a min table and a max table, then slide two pointers: grow `r`, and while the window's spread (two O(1) questions) is too big, move `l` right. 100,000 numbers.
---starter
def longest_within(nums, limit):
    best = 1
    for i in range(len(nums) - 1):
        if abs(nums[i + 1] - nums[i]) <= limit:
            best = 2
    return best
---solution
def longest_within(nums, limit):
    n = len(nums)
    lo, hi = [list(nums)], [list(nums)]
    k = 1
    while (1 << k) <= n:
        h, a, b = 1 << (k - 1), lo[-1], hi[-1]
        lo.append([min(a[i], a[i + h]) for i in range(n - (1 << k) + 1)])
        hi.append([max(b[i], b[i + h]) for i in range(n - (1 << k) + 1)])
        k += 1
    def spread(l, r):
        k = (r - l + 1).bit_length() - 1
        j = r - (1 << k) + 1
        return max(hi[k][l], hi[k][j]) - min(lo[k][l], lo[k][j])
    best = l = 0
    for r in range(n):
        while spread(l, r) > limit:
            l += 1
        best = max(best, r - l + 1)
    return best
---tests
assert longest_within([8, 2, 4, 7], 4) == 2
assert longest_within([10, 1, 2, 4, 7, 2], 5) == 4
assert longest_within([4, 2, 2, 2, 4, 4, 2, 2], 0) == 3
assert longest_within(walk(100000, 5, 3, 1000), 40) == 742
assert longest_within(walk(100000, 6, 50, 10 ** 6), 900) == 1747
---hint
Chapter 12 solved this with two monotonic deques. A sparse table is the other way: since the array never changes, any window's max and min are two O(1) questions.
---hint
`l` only moves right, so the whole sweep is O(n) questions.
```

```exercise
title: range_gcd
kind: write
---prompt
*A Codeforces classic.* Answer many questions "what's the gcd of `a[l..r]`?". gcd is idempotent (`gcd(x, x) = x`), so overlapping blocks are fine. 100,000 numbers and 100,000 questions.
---starter
def range_gcds(a, qs):
    return [gcd(a[l], a[r]) for l, r in qs]
---solution
def range_gcds(a, qs):
    sp = [list(a)]
    k = 1
    while (1 << k) <= len(a):
        p, h = sp[-1], 1 << (k - 1)
        sp.append([gcd(p[i], p[i + h]) for i in range(len(a) - (1 << k) + 1)])
        k += 1
    out = []
    for l, r in qs:
        k = (r - l + 1).bit_length() - 1
        out.append(gcd(sp[k][l], sp[k][r - (1 << k) + 1]))
    return out

assert range_gcds([6, 4, 9], [(0, 2)]) == [1], "the middle number matters"

q = lcg(200000, 8, 100000)
```

## Quick-fire: lock it in

```quiz
Why can't a sparse table answer range **sums** in O(1)?
- Sums are too big to store
* The two blocks overlap, and the overlapping cells would be added twice
- Sums need a Fenwick tree by law
- It can, with a bigger table
> min, max and gcd don't care about counting a cell twice. Sum does. (For a fixed array, prefix sums answer sums in O(1) anyway.)
```

```quiz
How many numbers does a sparse table on n = 1,000,000 store, roughly?
- 1,000,000
- 4,000,000
* 20,000,000 (about n log₂ n)
- 10¹²
> 20 rows, each nearly n long. That's the price of O(1) questions: memory, and no updates.
```

```quiz
One value in the array changes. What does a sparse table need?
- One O(1) fix
- O(log n) fixes, like a segment tree
* Every block containing it changes, so in practice you rebuild
- Nothing
> A position sits in up to 2ᵏ blocks of row k. Sparse tables are for arrays that don't change.
```

```quiz
For which operation is a sparse table **not** suitable?
- Range maximum
- Range bitwise OR
- Range gcd
* Range product
> Product isn't idempotent: a cell in the overlap would be multiplied in twice.
```

```recall
Q: Explain a sparse table: what it stores, how it's built, how a question is answered in O(1), which operations it works for and why, and when you'd pick it over a segment tree.
A: A sparse table stores, for every start i and every power of two 2ᵏ, the answer for the block a[i..i + 2ᵏ − 1]. Row 0 is the array, and row k comes from row k − 1, because a block of 2ᵏ is two blocks of 2ᵏ⁻¹ side by side, so building costs O(n log n) time and memory. For a question on l..r, take k = ⌊log₂(r − l + 1)⌋ (bit_length − 1) and combine the block starting at l with the block ending at r. Together they cover the range, possibly overlapping. Overlap is only harmless for idempotent operations, where applying a value twice changes nothing: min, max, gcd, AND and OR. Sum and product would count the overlap twice. Pick a sparse table when the array never changes and there are many questions, because it gives O(1) per question. If values change, use a segment tree (O(log n) updates and questions), because one change would force a rebuild.
```
