## A tree hiding in a list

A **min-heap** is a binary tree where every parent is ≤ its children, so the smallest item is at the top. It's stored in a plain list with no pointers: the children of index `i` are at `2i + 1` and `2i + 2`, and its parent is at `(i - 1) // 2`.

- **push**: add at the end, then swap it **up** while it's smaller than its parent.
- **pop**: take the root, move the last item to the root, then swap it **down** with its smaller child.

Both walk one root-to-leaf path: O(log n). Turning a whole list into a heap (`heapify`) is O(n).

Python only has a **min**-heap. For a max-heap, push `-x` and negate what comes out. For records, push tuples: `(priority, tie_breaker, item)` sorts by priority first.

## Top-k: a small heap is enough

To keep the **k largest** of a stream, keep a **min**-heap of size k. Its root is the smallest of your top k, the one to beat. A new item bigger than the root replaces it. Cost O(n log k), memory O(k), and it works on a stream you can't store.

```exercise
title: kth_largest
kind: write
---prompt
*LeetCode 215, one of the most-asked questions at Meta and Amazon.* Return the k-th largest number. Keep a min-heap of the k biggest so far: push each number, and pop whenever the heap grows past k. The answer is the root.
---starter
def kth_largest(a, k):
    best = []
    for x in a:
        best.append(x)
        best.sort(reverse=True)
        best = best[:k]
    return best[-1]
---solution
def kth_largest(a, k):
    h = []
    for x in a:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)
    return h[0]
---tests
assert kth_largest([3, 2, 1, 5, 6, 4], 2) == 5
assert kth_largest([3, 2, 3, 1, 2, 4, 5, 5, 6], 4) == 4
assert kth_largest([7], 1) == 7
random.seed(1)
big = [random.randint(0, 10**9) for _ in range(10000)]
r, secs = timed(kth_largest, big, 5000)
assert r == sorted(big)[-5000] and secs < 0.05, f"{secs:.2f}s: re-sorting the top k for every number is too slow"
---hint
`heappush`, then `if len(h) > k: heappop(h)`. The smallest of the k biggest is the k-th biggest.
```

```exercise
        self.k, self.h = k, []
        for x in nums:

        if len(self.h) < self.k:
```

## Merging k sorted streams

Put the **front** of each sorted list in a heap. Pop the smallest, then push the next item from the same list. With k lists and n items in total that's O(n log k).

```exercise
title: smallest_range
kind: write
---prompt
*LeetCode 632, a hard one asked at Google.* Each of k sorted lists must have at least one number inside the range `[lo, hi]`. Return the smallest such range (smallest `hi - lo`, then smallest `lo`). Keep one pointer per list in a heap, plus the current maximum; the range is `[heap min, current max]`. Pop the min, advance that list, and stop when any list runs out.
---starter
def smallest_range(lists):
    lo = min(l[0] for l in lists)
    hi = max(l[-1] for l in lists)
    return [lo, hi]
---solution
def smallest_range(lists):
    h = [(l[0], i, 0) for i, l in enumerate(lists)]
    heapq.heapify(h)
    hi = max(l[0] for l in lists)
    best = [h[0][0], hi]
    while True:
        lo, i, j = heapq.heappop(h)
        if hi - lo < best[1] - best[0]:
            best = [lo, hi]
        if j + 1 == len(lists[i]):
            return best
        nxt = lists[i][j + 1]
        hi = max(hi, nxt)
        heapq.heappush(h, (nxt, i, j + 1))
---tests
assert smallest_range([[4, 10, 15, 24, 26], [0, 9, 12, 20], [5, 18, 22, 30]]) == [20, 24]
assert smallest_range([[1, 2, 3], [1, 2, 3], [1, 2, 3]]) == [1, 1]
assert smallest_range([[1], [5], [9]]) == [1, 9]
---hint
It's merge-k with one extra variable: the biggest value currently in the heap. Check the range every time before you pop-and-advance.
```

## Two heaps for the median

Keep the **smaller half** in a max-heap and the **larger half** in a min-heap, balanced so their sizes differ by at most one. The median is at the top of one or both. Each insert is O(log n).

```exercise
title: median_stream
kind: write
---prompt
*LeetCode 295, a hard one asked at Amazon, Google and Microsoft.* `MedianFinder` with `add(x)` and `median()` (the average of the two middle values when the count is even). `lo` is a max-heap (stored negated) of the smaller half, `hi` a min-heap of the larger half; keep `len(lo)` equal to `len(hi)` or one more.
---starter
class MedianFinder:
    def __init__(self):
        self.a = []

    def add(self, x):
        self.a.append(x)
        self.a.sort()

    def median(self):
        return self.a[len(self.a) // 2]
---solution
class MedianFinder:
    def __init__(self):
        self.lo, self.hi = [], []

    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def median(self):
        if len(self.lo) > len(self.hi):
            return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2
---tests
m = MedianFinder()
m.add(1); m.add(2)
assert m.median() == 1.5
m.add(3)
assert m.median() == 2
m = MedianFinder()
for x in [5, 15, 1, 3]:
    m.add(x)
assert m.median() == 4
def many():
    f = MedianFinder()
    random.seed(4)
    for _ in range(8000):
        f.add(random.randint(0, 10**6))
    return f.median()
_, secs = timed(many)
assert secs < 0.08, f"{secs:.2f}s: re-sorting on every add is O(n² log n) in total"

Push into `lo`, move `lo`'s biggest over to `hi`, and if `hi` got bigger than `lo`, move `hi`'s smallest back. That keeps every item in `lo` ≤ every item in `hi`.
```

## Heaps for scheduling and greedy choices

```exercise
title: connect_ropes
kind: write
---prompt
*Amazon's classic.* Joining two ropes of lengths a and b costs `a + b`. Return the least total cost to join all ropes into one. Greedy with a heap: always join the two **shortest** (the same idea as Huffman coding).
---starter
def connect_ropes(r):
    total, cur = 0, 0
    for x in r:
        if cur:
            total += cur + x
        cur += x
    return total
---solution
def connect_ropes(r):
    h = list(r)
    heapq.heapify(h)
    total = 0
    while len(h) > 1:
        s = heapq.heappop(h) + heapq.heappop(h)
        total += s
        heapq.heappush(h, s)
    return total
---tests
assert connect_ropes([4, 3, 2, 6]) == 29
assert connect_ropes([1, 2, 3, 4, 5]) == 33
assert connect_ropes([7]) == 0
assert connect_ropes([]) == 0
---hint
Pop two, add their sum to the total, push the sum back. Repeat until one rope is left.
```

```exercise
title: reorganize_string
kind: write
---prompt
*LeetCode 767, asked at Amazon and Google.* Rearrange the letters so no two neighbours are equal; return any valid arrangement or `""` if impossible. Greedy: always place the most common letter that isn't the one you just placed. Use a max-heap of `(-count, letter)` and hold the previous letter back for one turn.
---starter
def reorganize(s):
    return "".join(sorted(s))
---solution
from collections import Counter

def reorganize(s):
    h = [(-c, ch) for ch, c in Counter(s).items()]
    heapq.heapify(h)
    out, prev = [], None
    while h:
        c, ch = heapq.heappop(h)
        out.append(ch)
        if prev:
            heapq.heappush(h, prev)
        prev = (c + 1, ch) if c + 1 < 0 else None
    return "".join(out) if len(out) == len(s) else ""
---tests
def ok(s, r):
    return sorted(s) == sorted(r) and all(a != b for a, b in zip(r, r[1:]))
assert ok("aab", reorganize("aab"))
assert reorganize("aaab") == ""
assert ok("vvvlo", reorganize("vvvlo"))
assert ok("aaabbbcc", reorganize("aaabbbcc"))
---hint
After placing a letter, push the **previous** one back (it's allowed again) and keep the current one aside. If the heap empties while a letter is still held back, it's impossible.
```

```exercise
title: buy_low_sell_high
kind: write
---prompt
*Codeforces 865D "Buy Low Sell High", rated about 2400.* You know a stock's price for each of n days. Each day you may buy one share, sell one share, or do nothing; you start with none and must end with none. Return the maximum profit. The heap trick: push each price; if the cheapest price seen is below today's, take `today - cheapest` and push today **twice** (once as a real buy option, once so a later, higher price can "undo" today's sale and sell later instead).
---starter
def max_profit(p):
    return sum(max(0, b - a) for a, b in zip(p, p[1:]))
---solution
def max_profit(p):
    h, profit = [], 0
    for x in p:
        if h and h[0] < x:
            profit += x - heapq.heappop(h)
            heapq.heappush(h, x)
        heapq.heappush(h, x)
    return profit
---tests
assert max_profit([10, 5, 4, 7, 9, 12, 6, 2, 10]) == 20
assert max_profit([3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5, 8, 9, 7, 9, 3, 2, 3, 8, 4, 6, 2, 6, 4, 3, 3, 8, 3, 2, 7]) == 58
assert max_profit([5, 4, 3]) == 0
---hint
The starter sells every rise, but you can only hold the trade one share at a time per day. Each day: if `h[0] < x`, pop it, add the difference and push `x`; then push `x` again.
```

```recall
Q: Explain how a binary heap works and the main heap patterns: top-k, merging k sorted lists, two heaps for a median, and greedy choices.
A: A binary min-heap is a tree where each parent is ≤ its children, stored in a list with the children of i at 2i+1 and 2i+2, so the minimum is at index 0. Push appends and sifts up; pop moves the last item to the root and sifts down with the smaller child; both follow one path, O(log n), and heapify builds a heap in O(n). Python's heapq is a min-heap, so push negated values for a max-heap and use tuples like (priority, counter, item) for records and fair ties. For the k largest of a stream keep a min-heap of size k and pop when it grows past k: O(n log k) time, O(k) memory, and the root is the k-th largest. To merge k sorted lists, heap the fronts, pop the smallest and push its successor: O(n log k). A running median keeps the lower half in a max-heap and the upper half in a min-heap, balanced, with the median on top. Greedy algorithms that repeatedly need the cheapest or most common item, like joining the two shortest ropes, rearranging letters, scheduling by priority or Dijkstra, use a heap for that choice.
```
