## When the answer depends on a stretch

Some problems keep **combining neighbours**: merging files, multiplying a chain of matrices, bursting balloons, cutting a stick. Whatever you do, the final step joins a left part and a right part. So the state is a **stretch** `i..j`:

`dp[i][j] = best over k of ( dp[i][k] + dp[k + 1][j] + cost of joining them )`

```viz

title: Merging six files: greedy against interval DP
goal: Run **greedy** to the end, then run **interval DP** and compare the total cost.
height: 460
Merging two neighbouring files costs their combined size.
```

**Order matters.** `dp[i][j]` reads shorter stretches inside it, so fill by **length**: all stretches of length 2, then 3, and so on. (Going `i` from high to low and `j` from low to high also works.) There are O(n²) stretches and O(n) splits each: **O(n³)**, fine for n up to a few hundred.

```run
title: Merge cost, filled by length
def merge_cost(piles):
    n = len(piles)
    pre = [0]
    for x in piles:
        pre.append(pre[-1] + x)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(dp[i][k] + dp[k + 1][j] for k in range(i, j)) + pre[j + 1] - pre[i]
        print("length", length, [dp[i][i + length - 1] for i in range(n - length + 1)])
    return dp[0][n - 1]

print(merge_cost([7, 3, 7, 2, 9, 9]))
```

## Split points and "last action"

Two ways to think about `k`:

- **First split**: the stretch is cut into `i..k` and `k + 1..j` (merging files, matrix chains).
- **Last action**: `k` is the **last** thing done inside `i..j`. For balloons, if `k` bursts last, its neighbours at that moment are the **edges** `i` and `j`, and the two sides never interact. Thinking "first" here fails because bursting changes who is next to whom.

```exercise
title: matrix_chain
kind: write
---prompt
*The classic interview DP.* Matrix `t` has shape `dims[t] × dims[t + 1]`. Multiplying a `p × q` by a `q × r` matrix costs `p·q·r`. Return the fewest scalar multiplications to multiply the whole chain.
---starter
def matrix_chain(dims):
    cost = 0
    for i in range(1, len(dims) - 1):
        cost += dims[0] * dims[i] * dims[i + 1]
    return cost
---solution
def matrix_chain(dims):
    n = len(dims) - 1
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(dp[i][k] + dp[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1] for k in range(i, j))
    return dp[0][n - 1]
---tests
assert matrix_chain([10, 30, 5, 60]) == 4500
assert matrix_chain([40, 20, 30, 10, 30]) == 26000
assert matrix_chain([10, 20]) == 0
assert matrix_chain([1, 2, 3, 4, 3]) == 30
---hint
The product of matrices `i..k` has shape `dims[i] × dims[k + 1]`, and `k + 1..j` has shape `dims[k + 1] × dims[j + 1]`.
```

```exercise
title: burst_balloons
kind: write
---prompt
*LeetCode 312, a hard one asked at Google and Amazon.* Bursting balloon `k` earns `left × nums[k] × right`, using its current neighbours (1 past either end). Return the most coins. Pad with 1s; `dp[i][j]` = best for the balloons strictly between `i` and `j`, choosing which one `k` bursts **last**.
---starter
def max_coins(nums):
    a, total = [1] + nums + [1], 0
    while len(a) > 2:
        k = min(range(1, len(a) - 1), key=lambda k: a[k])
        total += a[k - 1] * a[k] * a[k + 1]
        a.pop(k)
    return total
---solution
def max_coins(nums):
    a = [1] + nums + [1]
    n = len(a)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n):
        for i in range(n - length):
            j = i + length
            dp[i][j] = max(dp[i][k] + dp[k][j] + a[i] * a[k] * a[j] for k in range(i + 1, j))
    return dp[0][n - 1]
---tests
assert max_coins([3, 1, 5, 8]) == 167
assert max_coins([1, 5]) == 10
assert max_coins([7]) == 7
assert max_coins([9, 76, 64, 21, 97, 60]) == 1086136
---hint
If `k` is the last balloon between `i` and `j`, everything between `i` and `k` is already gone, so its neighbours are exactly `a[i]` and `a[j]`.
```

```exercise
title: predict_the_winner
kind: write
---prompt
*LeetCode 486, asked at Google and Amazon.* Two players take turns taking a number from **either end** of `nums`; both play perfectly. Return how many points the first player wins by (first minus second; may be negative). `dp[i][j]` = best margin for whoever moves on `nums[i..j]`.
---starter
def margin(nums):
    a, me, you, turn = nums[:], 0, 0, 0
    while a:
        x = a.pop(0) if a[0] >= a[-1] else a.pop()
        if turn == 0:
            me += x
        else:
            you += x
        turn ^= 1
    return me - you
---solution
def margin(nums):
    n = len(nums)
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        dp[i][i] = nums[i]
        for j in range(i + 1, n):
            dp[i][j] = max(nums[i] - dp[i + 1][j], nums[j] - dp[i][j - 1])
    return dp[0][n - 1]
---tests
assert margin([1, 5, 2]) == -2
assert margin([1, 5, 233, 7]) == 222
assert margin([4]) == 4
assert margin([2, 4, 55, 6, 8]) == -39
---hint
After you take an end, the opponent faces the rest and gets **their** best margin, which counts against you: `take − dp[rest]`.
```

## Real-world project: a keyword lookup tree

```project
title: The fastest lookup tree for a compiler's keywords
client: A language tool team whose tokenizer checks every word against a fixed list of keywords, millions of times a day, with very uneven frequencies
skills: optimal binary search trees, interval DP, rebuilding the tree from root choices
---brief
Build `obst.py`. Given sorted keywords and how often each is looked up, build the binary search tree with the smallest expected cost, where a lookup costs the depth of its key (root = 1). For each stretch of keys `i..j − 1`, try every key `r` as the root: the cost is the two subtrees plus the total frequency of the stretch (everything gets one level deeper). Store the best root so you can rebuild the tree.
---why
Compilers, static dictionaries and database indexes built once and read constantly benefit from this. It's also the classic interval DP that Knuth sped up to O(n²).
---milestones
- Prefix sums of frequencies
- Fill cost by stretch length
- Record the best root per stretch
- Output the tree in preorder
---stretch
- Knuth's speed-up: the best root lies between the roots of the two neighbouring stretches
- Include the cost of unsuccessful searches
```

```exercise
title: obst_cost
kind: write
---prompt
Return the smallest total `Σ freq × depth` for a BST over the keys (in the given order) with frequencies `freq`. Use half-open stretches: `dp[i][j]` for keys `i..j − 1`, with `dp[i][i] = 0`.
---starter
def obst_cost(freq):
    order = sorted(range(len(freq)), key=lambda i: -freq[i])
    depth, total = {}, 0
    for d, i in enumerate(order):
        total += freq[i] * (d + 1)
    return total
---solution
def obst_cost(freq):
    n = len(freq)
    pre = [0]
    for x in freq:
        pre.append(pre[-1] + x)
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    for length in range(1, n + 1):
        for i in range(n - length + 1):
            j = i + length
            dp[i][j] = min(dp[i][r] + dp[r + 1][j] for r in range(i, j)) + pre[j] - pre[i]
    return dp[0][n]
---tests
assert obst_cost([34, 8, 50]) == 142
assert obst_cost([10, 12]) == 32
assert obst_cost([5]) == 5
assert obst_cost([4, 2, 6, 3]) == 26
---hint
Making `r` the root pushes every other key in the stretch one level down, which adds the stretch's total frequency once.
```

```exercise
title: obst_preorder
kind: write
---prompt
Return the keys of an optimal tree in **preorder** (root, left subtree, right subtree). On ties, pick the smallest root index. Record `root[i][j]` while filling, then rebuild recursively.
---starter
def obst_preorder(keys, freq):
    return [k for _, k in sorted(zip(freq, keys), reverse=True)]
---solution
def obst_preorder(keys, freq):
    n = len(freq)
    pre = [0]
    for x in freq:
        pre.append(pre[-1] + x)
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    root = [[0] * (n + 1) for _ in range(n + 1)]
    for length in range(1, n + 1):
        for i in range(n - length + 1):
            j = i + length
            best = None
            for r in range(i, j):
                c = dp[i][r] + dp[r + 1][j]
                if best is None or c < best:
                    best, root[i][j] = c, r
            dp[i][j] = best + pre[j] - pre[i]
    out = []
    def build(i, j):
        if i >= j:
            return
        r = root[i][j]
        out.append(keys[r])
        build(i, r)
        build(r + 1, j)
    build(0, n)
    return out
---tests
assert obst_preorder(["do", "if", "int"], [34, 8, 50]) == ["int", "do", "if"]
assert obst_preorder(["a", "b", "c", "d"], [4, 2, 6, 3]) == ["c", "a", "b", "d"]
assert obst_preorder(["a", "b", "c", "d", "e"], [1, 1, 1, 1, 1]) == ["b", "a", "d", "c", "e"]
---hint
The starter puts the most frequent key first but ignores the BST order. Strict `<` keeps the smallest root index on ties.
```

## Rebuild it and explain it

```exercise
title: interval_rebuild
kind: rebuild
---prompt
From memory: *LeetCode 1312*. Return the fewest characters to insert anywhere in `s` to make it a palindrome. `dp[i][j]` for the stretch `s[i..j]`: if the ends match, look inside; otherwise fix one end.
---starter
def min_insertions(s):
    pass
---solution
def min_insertions(s):
    n = len(s)
    if n == 0:
        return 0
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1]
---tests
assert min_insertions("zzazz") == 0
assert min_insertions("mbadm") == 2
assert min_insertions("leetcode") == 5
assert min_insertions("a") == 0
---hint
Loop `i` downwards so `dp[i + 1][…]` is ready. A mismatch costs one insertion to copy one end onto the other side.
```

```recall
Q: Explain interval DP: what the state is, the split-point transition, the fill order, its running time, and the "last action" idea.
A: Interval DP solves problems where neighbours keep being combined, so the final step always joins a left part and a right part; the state dp[i][j] is the best answer for the stretch i..j. The transition tries every split point k and combines dp[i][k] and dp[k + 1][j] with the cost of joining them, such as the size of the stretch when merging files or dims[i]·dims[k + 1]·dims[j + 1] for a matrix chain. Each stretch reads strictly shorter stretches, so it is filled by length (or i decreasing with j increasing); filling rows with i increasing reads cells that are not yet computed. There are O(n²) stretches with O(n) splits each, so O(n³). When an action changes the neighbours, as in burst balloons, choose k as the last action in the stretch so its neighbours are the fixed edges and the two sides stay independent; cutting a stick chooses the first cut instead. Two-player games taking from the ends store the margin for whoever moves, nums[i] − dp[i + 1][j]. Recording the best split per stretch rebuilds the structure, such as an optimal binary search tree.
```
