## Pay once, answer fast

A shop has ten years of daily sales, and the manager keeps asking: "what did we sell between day 1 200 and day 1 450?" Adding up the range each time is slow when there are many questions. Instead, build the **running total** once: `P[k]` = the sum of the first k days. Then

**sum of days l..r = P[r+1] − P[l]**

because everything up to day r, minus everything before day l, leaves exactly the days in between.

```run
title: Building prefix sums
a = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3]
P = [0]
for x in a:
    P.append(P[-1] + x)
print(P)
print(list(accumulate(a, initial=0)))
l, r = 2, 7
print(sum(a[l:r + 1]), P[r + 1] - P[l])
```

```predict
a = [5, -2, 7, 1]
P = [0]
for x in a:
    P.append(P[-1] + x)
print(P[4] - P[1], P[2] - P[0], P[3] - P[3])
```

`P[3] − P[3]` is the empty range: 0. The leading zero makes every formula work at the edges with no special cases. That's the main reason prefix arrays have length n + 1.

```exercise
title: RangeSum
kind: write
---prompt
*An interview classic.* Write a class `RangeSum` built from a list `a`, with a method `query(l, r)` returning `a[l] + … + a[r]` (inclusive) in O(1). There will be 10⁵ queries.
---starter
class RangeSum:
    def __init__(self, a):
        self.a = a
    def query(self, l, r):
        return sum(self.a[l:r + 1])
---solution
class RangeSum:
    def __init__(self, a):
        self.P = [0]
        for x in a:
            self.P.append(self.P[-1] + x)
    def query(self, l, r):
        return self.P[r + 1] - self.P[l]
---tests
rs = RangeSum([-2, 0, 3, -5, 2, -1])
assert rs.query(0, 2) == 1
assert rs.query(2, 5) == -1
assert rs.query(0, 5) == -3
assert rs.query(3, 3) == -5
big = RangeSum(list(range(20000)))
t = time.perf_counter()
for i in range(20000):
    big.query(0, 19999)
secs = time.perf_counter() - t
assert secs < 0.25, f"{secs:.2f}s for 20 000 queries: each one is re-adding the range"
---hint
Build P in `__init__`. `query` is one subtraction.
```

```exercise
title: pivot_index
kind: write
---prompt
*An interview warm-up.* Return the first index i where the sum of everything left of i equals the sum of everything right of i (the element itself counts on neither side), or -1.
---starter
def pivot_index(a):
    for i in range(len(a)):
        if sum(a[:i]) == sum(a[i + 1:]):
            return i
    return -1
---solution
def pivot_index(a):
    total, left = sum(a), 0
    for i, x in enumerate(a):
        if left == total - left - x:
            return i
        left += x
    return -1
---tests
assert pivot_index([1, 7, 3, 6, 5, 6]) == 3
assert pivot_index([1, 2, 3]) == -1
assert pivot_index([2, 1, -1]) == 0, "nothing on the left sums to 0"
big = [1] * 20000
r, secs = timed(pivot_index, big)
assert r == -1 and secs < 0.25, f"{secs:.2f}s: slicing and summing for each i is O(n²)"
---hint
Right side = total − left − x. Keep `left` as a running sum.
```

## Prefix sums + a hash map

The most important combination in this chapter. "How many subarrays sum to k?" A subarray l..r sums to k exactly when `P[r+1] − P[l] = k`, that is `P[l] = P[r+1] − k`. So as you walk, count how many earlier prefix sums equal `current − k`. It's two-sum (chapter 3) on prefix sums.

```exercise
title: subarray_sum_k
kind: write
---prompt
*One of the most asked interview questions.* Count the subarrays of `a` (integers, may be negative) whose sum is exactly `k`. n up to 2·10⁴, so O(n²) is too slow in Python.
---starter
def subarray_sum_k(a, k):
    count = 0
    for l in range(len(a)):
        s = 0
        for r in range(l, len(a)):
            s += a[r]
            if s == k:
                count += 1
    return count
---solution
def subarray_sum_k(a, k):
    seen = Counter({0: 1})
    run = count = 0
    for x in a:
        run += x
        count += seen[run - k]
        seen[run] += 1
    return count
---tests
assert subarray_sum_k([1, 1, 1], 2) == 2
assert subarray_sum_k([1, 2, 3], 3) == 2
assert subarray_sum_k([1, -1, 0], 0) == 3
assert subarray_sum_k([3, 4, 7, 2, -3, 1, 4, 2], 7) == 4
big = [0] * 5000
r, secs = timed(subarray_sum_k, big, 0)
assert r == 5000 * 5001 // 2 and secs < 0.25, f"{secs:.2f}s: too slow"
---hint
`seen` counts prefix sums so far, starting with `{0: 1}` (the empty prefix). For each new running sum `run`, add `seen[run - k]`, then record `run`.
---hint
Sliding windows (chapter 8) don't work here because of negative numbers. Prefix sums + a hash map do.
```

```exercise
title: divisible_subarrays
kind: write
---prompt
*Interview and contest favourite.* Count subarrays whose sum is divisible by `k` (k ≥ 1; numbers may be negative).
---starter
def divisible_subarrays(a, k):
    return 0
---solution
def divisible_subarrays(a, k):
    seen = Counter({0: 1})
    run = count = 0
    for x in a:
        run = (run + x) % k
        count += seen[run]
        seen[run] += 1
    return count
---tests
assert divisible_subarrays([4, 5, 0, -2, -3, 1], 5) == 7
assert divisible_subarrays([5], 9) == 0
assert divisible_subarrays([-1, 2, 9], 2) == 2
---hint
`P[r+1] − P[l]` is divisible by k exactly when the two prefix sums have the **same remainder** mod k. Count equal remainders. (Python's `%` already gives a non-negative remainder for negative numbers.)
```

```exercise
title: product_except_self
kind: write
---prompt
*A top interview question.* Return a list where position i holds the product of every element **except** `a[i]`, without using division, in O(n).
---starter
def product_except_self(a):
    out = []
    for i in range(len(a)):
        p = 1
        for j in range(len(a)):
            if j != i:
                p *= a[j]
        out.append(p)
    return out
---solution
def product_except_self(a):
    n = len(a)
    out = [1] * n
    left = 1
    for i in range(n):
        out[i] = left
        left *= a[i]
    right = 1
    for i in range(n - 1, -1, -1):
        out[i] *= right
        right *= a[i]
    return out
---tests
assert product_except_self([1, 2, 3, 4]) == [24, 12, 8, 6]
assert product_except_self([-1, 1, 0, -3, 3]) == [0, 0, 9, 0, 0]
assert product_except_self([2, 3]) == [3, 2]
big = [1] * 5000
r, secs = timed(product_except_self, big)
assert r == big and secs < 0.25, f"{secs:.2f}s: too slow"
---hint
The answer at i is (product of everything left of i) × (product of everything right of i): a prefix product and a suffix product.
```

## Difference arrays: many range updates at once

The reverse problem: lots of updates "add v to every element from l to r", then read the final array. Doing each update element by element is O(n) per update. Instead, mark only the edges: `D[l] += v` and `D[r+1] -= v`. A prefix sum of D at the end spreads each mark across its range.

```parsons
title: Apply range additions with a difference array
---lines
def apply_updates(n, updates):
    D = [0] * (n + 1)
    for l, r, v in updates:
        D[l] += v
        D[r + 1] -= v
    out, run = [], 0
    for i in range(n):
        run += D[i]
        out.append(run)
    return out
?? D[r] -= v
?? for i in range(l, r + 1):
---tests
assert apply_updates(5, [(1, 3, 2), (2, 4, 3), (0, 2, -2)]) == [-2, 0, 3, 5, 3]
assert apply_updates(3, []) == [0, 0, 0]
assert apply_updates(1, [(0, 0, 7)]) == [7]
```

```exercise
title: car_pooling
kind: write
---prompt
*An interview classic.* A car with `capacity` seats drives east. Each trip is `(passengers, start, end)`: they get in at kilometre `start` and out at `end` (so they're **not** in the car at `end`). Return whether the car is never over capacity. Kilometres are 0..1000.
---starter
def car_pooling(trips, capacity):
    return sum(p for p, s, e in trips) <= capacity
---solution
def car_pooling(trips, capacity):
    D = [0] * 1002
    for p, s, e in trips:
        D[s] += p
        D[e] -= p
    run = 0
    for change in D:
        run += change
        if run > capacity:
            return False
    return True
---tests
assert car_pooling([(2, 1, 5), (3, 3, 7)], 4) is False
assert car_pooling([(2, 1, 5), (3, 3, 7)], 5) is True
assert car_pooling([(2, 1, 5), (3, 5, 7)], 3) is True, "the first group gets out at 5 as the second gets in"
assert car_pooling([(3, 2, 7), (3, 7, 9), (8, 3, 9)], 11) is True
---hint
+passengers at `start`, −passengers at `end` (not `end + 1`, because they've left by then). Walk the running total.
```

## Prefix sums in 2D

For a grid, `S[i][j]` = the sum of the rectangle from the top-left corner to (i−1, j−1). A rectangle's sum is then four lookups: the big corner rectangle, minus the strip above, minus the strip to the left, plus the corner you subtracted twice.

```exercise
title: grid_sums
kind: write
---prompt
*An interview classic.* Write `build(grid)` returning the 2D prefix table S of size (rows+1) × (cols+1), and `rect(S, r1, c1, r2, c2)` returning the sum of the rectangle with those inclusive corners, in O(1).
---starter
def build(grid):
    return grid

def rect(S, r1, c1, r2, c2):
    return sum(S[r][c] for r in range(r1, r2 + 1) for c in range(c1, c2 + 1))
---solution
def build(grid):
    R, C = len(grid), len(grid[0])
    S = [[0] * (C + 1) for _ in range(R + 1)]
    for i in range(R):
        for j in range(C):
            S[i + 1][j + 1] = grid[i][j] + S[i][j + 1] + S[i + 1][j] - S[i][j]
    return S

def rect(S, r1, c1, r2, c2):
    return S[r2 + 1][c2 + 1] - S[r1][c2 + 1] - S[r2 + 1][c1] + S[r1][c1]
---tests
g = [[3, 0, 1, 4, 2], [5, 6, 3, 2, 1], [1, 2, 0, 1, 5], [4, 1, 0, 1, 7], [1, 0, 3, 0, 5]]
S = build(g)
assert len(S) == 6 and len(S[0]) == 6, "S has an extra row and column of zeros"
assert rect(S, 2, 1, 4, 3) == 8
assert rect(S, 1, 1, 2, 2) == 11
assert rect(S, 1, 2, 2, 4) == 12
assert rect(S, 0, 0, 4, 4) == sum(map(sum, g))
---hint
Inclusion-exclusion: `S[i+1][j+1] = grid[i][j] + above + left − above-left`. The query uses the same idea backwards.
```

## Quick-fire: lock it in

```quiz
Why does the prefix array start with `P[0] = 0`?
- To make it the same length as the input
* So a range starting at index 0 is `P[r+1] − P[0]` with no special case
- Python lists must start with 0
- To handle negative numbers
> Without it, ranges that start at the beginning need an `if`. The extra zero is the "sum of nothing".
```

```quiz
n = 10⁵ numbers, q = 10⁵ "sum of l..r" queries. Total work with prefix sums?
- O(n · q)
* O(n + q)
- O(q log n)
- O(n log n)
> n to build, then O(1) per query.
```

```quiz
"Count subarrays with sum exactly k" when numbers can be negative. Which tool?
- Sliding window
- Sorting
* Prefix sums plus a hash map of how many times each prefix sum has appeared
- Binary search
> With negatives, growing a window can make the sum smaller, so windows don't work. Prefix sums turn it into two-sum.
```

```quiz
A difference array update "add 5 to positions 3..8" changes how many entries of D?
- 6
* 2
- 1
- n
> `D[3] += 5` and `D[9] -= 5`. That's why a million updates are cheap: the prefix sum at the end does the spreading.
```

```quiz
Prefix sums need the array to stay fixed. What if values change between queries?
- Rebuild P after every change, it's fine
* You need a structure that supports both updates and range sums in O(log n): a Fenwick tree or segment tree (Part 6)
- Use a difference array
- Use a hash map
> Rebuilding is O(n) per change. Fenwick and segment trees handle mixed updates and queries.
```

```exercise
title: occupancy
kind: write
---prompt
Write `occupancy(bookings, nights)`: each booking is `(check_in, check_out)` with nights numbered from 0; the guest occupies nights `check_in` up to `check_out - 1`. Return a list of how many rooms are occupied on each night `0..nights-1`.
---starter
def occupancy(bookings, nights):
    return [0] * nights
---solution
def occupancy(bookings, nights):
    D = [0] * (nights + 1)
    for a, b in bookings:
        D[a] += 1
        D[b] -= 1
    return list(accumulate(D[:nights]))
---tests
assert occupancy([(0, 2), (1, 4), (3, 5)], 6) == [1, 2, 1, 2, 1, 0]
assert occupancy([], 3) == [0, 0, 0]
assert occupancy([(2, 3), (2, 3)], 4) == [0, 0, 2, 0]
---hint
+1 on the check-in night, −1 on the check-out night, then a running total.
```

## Rebuild it and explain it

```exercise
title: subarray_rebuild
kind: rebuild
---prompt
From memory: `subarray_sum_k(a, k)` counts subarrays summing to exactly `k`, in O(n), with negatives allowed.
---starter
def subarray_sum_k(a, k):
    pass
---solution
def subarray_sum_k(a, k):
    seen = {0: 1}
    run = count = 0
    for x in a:
        run += x
        count += seen.get(run - k, 0)
        seen[run] = seen.get(run, 0) + 1
    return count
---tests
assert subarray_sum_k([1, 1, 1], 2) == 2
assert subarray_sum_k([1, -1, 1, -1], 0) == 4
assert subarray_sum_k([5], 5) == 1
---hint
Running sum, a dict of prefix-sum counts starting `{0: 1}`, look up `run - k` before recording `run`.
```

```recall
Q: Explain prefix sums, the prefix-sum + hash-map trick, and difference arrays.
A: A prefix array P has P[0] = 0 and P[k] = a[0] + … + a[k-1]. Building it is O(n); then any range sum a[l..r] = P[r+1] − P[l] in O(1), because the total up to r minus the total before l leaves just the range. The leading zero removes edge cases. To count subarrays summing to k, note that l..r works exactly when P[l] = P[r+1] − k, so walk once keeping a dict of how many times each prefix sum has appeared (starting {0: 1}) and add the count of run − k at each step: two-sum on prefix sums, which works with negative numbers. Equal remainders mod k give subarrays divisible by k. A difference array does the opposite: to add v to a[l..r], do D[l] += v and D[r+1] −= v; one prefix sum at the end applies every update, so u updates cost O(u + n). In 2D, S[i+1][j+1] = grid[i][j] + above + left − above-left, and a rectangle is four lookups by inclusion-exclusion.
```
