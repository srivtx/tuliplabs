## Choose now, never look back

A **greedy** algorithm builds an answer one choice at a time, always taking what looks best right now, and never undoes a choice. When it works it's usually the simplest and fastest solution there is: often just a sort and one pass.

The catch: "looks best right now" has to be the **right** rule, and plausible rules are often wrong.

## Proving it: the exchange argument

To prove a greedy rule, show that any optimal answer can be changed, one **swap** at a time, into the greedy answer without getting worse.

For the talks: let `g` be the talk that ends first, and take any best schedule. Its first talk ends no earlier than `g`, so swap it for `g`. Nothing after it clashes (g ends even sooner), and the count is the same. Repeat on the rest of the day.

To **disprove** a rule, one counterexample is enough. Always try to break your greedy idea with a small case before you code it.

```run
title: Greedy coins: right for real currencies, wrong in general
def greedy_coins(coins, amount):
    used = []
    for c in sorted(coins, reverse=True):
        while amount >= c:
            amount -= c
            used.append(c)
    return used if amount == 0 else None

print("euro coins, 289:", greedy_coins([1, 2, 5, 10, 20, 50, 100, 200], 289))
print("coins 1, 3, 4, amount 6:", greedy_coins([1, 3, 4], 6), " but 3 + 3 uses only 2 coins")
```

## Reach and jumps

```exercise
title: jump_game
kind: write
---prompt
*LeetCode 55.* `a[i]` is the most you can jump forward from index i. Can you reach the last index from index 0? Greedy: track the **farthest** index reachable so far; if you ever stand past it, you're stuck.
---starter
def can_jump(a):
    i = 0
    while i < len(a) - 1:
        if a[i] == 0:
            return False
        i += a[i]
    return True
---solution
def can_jump(a):
    far = 0
    for i, x in enumerate(a):
        if i > far:
            return False
        far = max(far, i + x)
    return True
---tests
assert can_jump([2, 3, 1, 1, 4])
assert not can_jump([3, 2, 1, 0, 4])
assert can_jump([0])
assert can_jump([2, 0, 0])
assert can_jump([1, 2, 0, 1])
assert can_jump([2, 5, 0, 0, 0, 0, 1])
---hint
The starter always takes the full jump, which can land on a 0 you could have jumped over. Keep `far = max(far, i + a[i])` instead.
```

```exercise
title: gas_station
kind: write
---prompt
*LeetCode 134.* Stations on a circular road: `gas[i]` fuel at station i, `cost[i]` fuel to drive to the next one. Return the start index that lets you go all the way round (it's unique if it exists), or -1. In one pass: if the total gas < total cost, it's -1. Otherwise, whenever your tank goes negative, no station from the current start up to here can work, so start again from the next station.
---starter
def start_station(gas, cost):
    n = len(gas)
    for s in range(n):
        tank, ok = 0, True
        for k in range(n):
            i = (s + k) % n
            tank += gas[i] - cost[i]
            if tank < 0:
                ok = False
                break
        if ok:
            return s
    return -1
---solution
def start_station(gas, cost):
    if sum(gas) < sum(cost):
        return -1
    start, tank = 0, 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0:
            start, tank = i + 1, 0
    return start
---tests
assert start_station([1, 2, 3, 4, 5], [3, 4, 5, 1, 2]) == 3
assert start_station([2, 3, 4], [3, 4, 3]) == -1
assert start_station([5], [4]) == 0
n = 3000
gas, cost = [1] * n, [1] * n
gas[-2], gas[-1] = 0, 2
r, secs = timed(start_station, gas, cost)
assert r == n - 1 and secs < 0.05, f"{secs:.2f}s: one pass is enough"
---hint
If you start at `s` and first run dry at `i`, every start between `s` and `i` also runs dry by `i` (they arrive with less fuel). Jump straight to `i + 1`.
```

## Sort, then be greedy

```exercise
title: assign_cookies
kind: write
---prompt
*LeetCode 455.* Child i is happy with a cookie of size at least `greed[i]`; each child gets at most one cookie. Return the most happy children. Sort both; give each cookie, smallest first, to the least greedy child it can satisfy (two pointers).
---starter
def content_children(greed, cookies):
    return min(len(greed), len(cookies))
---solution
def content_children(greed, cookies):
    greed, cookies = sorted(greed), sorted(cookies)
    i = 0
    for c in cookies:
        if i < len(greed) and c >= greed[i]:
            i += 1
    return i
---tests
assert content_children([1, 2, 3], [1, 1]) == 1
assert content_children([1, 2], [1, 2, 3]) == 2
assert content_children([10, 9], [5, 6]) == 0
assert content_children([], [1]) == 0
---hint
A cookie too small for the least greedy remaining child is too small for everyone: skip it.
```

```exercise
title: queue_disappointment
kind: write
---prompt
*Codeforces 545D "Queue".* Person i needs `t[i]` minutes to be served and is disappointed if they wait (sum of service times before them) **more** than `t[i]`. You may reorder the queue. Return the most people who are **not** disappointed. Greedy: sort by `t`; serve anyone who won't be disappointed and send everyone else to the very back (their waiting doesn't matter any more).

        if wait <= x:

        wait += x
    return happy
---solution

    wait, happy = 0, 0
    for x in sorted(t):
        if wait <= x:
            happy += 1
            wait += x
    return happy

assert not_disappointed([1, 1, 1, 1]) == 2

Two changes from the starter: sort first, and only add `x` to the waiting time if that person is actually served in their place.
```

```exercise
title: boxers
kind: write
---prompt
*Codeforces 1203E "Boxers".* Each boxer's weight can change by at most 1 (staying ≥ 1). Return the largest team in which all weights are **different**. Greedy: sort, and give each boxer the smallest unused weight among `w - 1`, `w`, `w + 1`.
---starter
def team(w):
    return len(set(w))
---solution
def team(w):
    used, last = 0, 0
    for x in sorted(w):
        for y in (x - 1, x, x + 1):
            if y > last and y >= 1:
                used += 1
                last = y
                break
    return used
---tests
assert team([3, 2, 4, 1]) == 4
assert team([1, 1, 1, 4, 4, 4]) == 5
assert team([1, 1, 1]) == 2
assert team([2, 2, 2]) == 3
---hint
Sorted order means each weight you choose must be bigger than the last one chosen. Try the smallest option first, to leave room for the rest.
```

```exercise
title: candy_bug
kind: bug
---prompt
*LeetCode 135, a hard one.* Children stand in a row with ratings; each gets at least 1 candy, and anyone rated higher than a **neighbour** gets more than that neighbour. Return the fewest candies. This version only looks left, so for ratings `[1, 3, 2, 1]` it gives `[1, 2, 1, 1]`, but the 2 must beat the 1 on its right. Fix it with a second pass from the right.
---starter
def candy(r):
    c = [1] * len(r)
    for i in range(1, len(r)):
        if r[i] > r[i - 1]:
            c[i] = c[i - 1] + 1
    return sum(c)
---solution
def candy(r):
    c = [1] * len(r)
    for i in range(1, len(r)):
        if r[i] > r[i - 1]:
            c[i] = c[i - 1] + 1
    for i in range(len(r) - 2, -1, -1):
        if r[i] > r[i + 1]:
            c[i] = max(c[i], c[i + 1] + 1)
    return sum(c)
---tests
assert candy([1, 3, 2, 1]) == 7
assert candy([1, 0, 2]) == 5
assert candy([1, 2, 2]) == 4
assert candy([5]) == 1
---hint
Going right to left, if `r[i] > r[i + 1]`, child i needs at least `c[i + 1] + 1`, but don't lose what the first pass gave it: take the max.
```

```exercise
title: partition_labels
kind: write
---prompt
*LeetCode 763, asked at Amazon.* Split a string into as many parts as possible so each letter appears in only one part; return the part sizes. Record each letter's **last** position; extend the current part's end to the furthest last-position seen, and cut when you reach it.
---starter
def partition_labels(s):
    return [len(s)]
---solution
def partition_labels(s):
    last = {ch: i for i, ch in enumerate(s)}
    out, start, end = [], 0, 0
    for i, ch in enumerate(s):
        end = max(end, last[ch])
        if i == end:
            out.append(end - start + 1)
            start = i + 1
    return out
---tests
assert partition_labels("ababcbacadefegdehijhklij") == [9, 7, 8]
assert partition_labels("eccbbbbdec") == [10]
assert partition_labels("abc") == [1, 1, 1]
---hint
It's the merge-intervals idea in disguise: each letter is an interval from its first to its last position.
```

## Greedy plus a heap: regret later

Some greedy algorithms take a choice now and **swap it out** later if something better turns up. A heap remembers the worst choice made so far.

```exercise
title: course_schedule_iii
kind: write
---prompt
*LeetCode 630, a hard one.* Each course is `(duration, deadline)`; courses run back to back from day 0 and must finish by their deadline. Return the most courses you can take. Sort by deadline. Take each course; if the total time now passes its deadline, drop the **longest** course taken so far (a max-heap of durations). Swapping a long course for a shorter one never hurts later ones: an exchange argument.
---starter
def schedule_courses(courses):
    t, n = 0, 0
    for d, end in sorted(courses, key=lambda c: c[1]):
        if t + d <= end:
            t += d
            n += 1
    return n
---solution
def schedule_courses(courses):
    h, t = [], 0
    for d, end in sorted(courses, key=lambda c: c[1]):
        heapq.heappush(h, -d)
        t += d
        if t > end:
            t += heapq.heappop(h)
    return len(h)
---tests
assert schedule_courses([(100, 200), (200, 1300), (1000, 1250), (2000, 3200)]) == 3
assert schedule_courses([(1, 2)]) == 1
assert schedule_courses([(3, 2), (4, 3)]) == 0
assert schedule_courses([(5, 5), (4, 6), (2, 6)]) == 2
---hint
Push `-d` so the heap's top is the longest course. `t += heappop(h)` subtracts that duration (it's negative).
```

```exercise
title: reachable
kind: write
---prompt
Start with `fuel` litres (1 litre = 1 km). `stations` is a list of `(position, litres)` sorted by position; at each you may take all its fuel (the tank has no limit). Can you reach `target`? Greedy: take every station's fuel as you pass it.
---starter
def reachable(target, fuel, stations):
    return fuel + sum(l for _, l in stations) >= target
---solution
def reachable(target, fuel, stations):
    for pos, litres in stations:
        if pos > fuel:
            return False
        fuel += litres
    return fuel >= target
---tests
assert reachable(100, 10, [(10, 60), (20, 30), (30, 30), (60, 40)])
assert not reachable(100, 1, [(10, 100)])
assert reachable(1, 1, [])
assert not reachable(100, 50, [(60, 100)])
---hint
`fuel` is also how far you can get. If the next station is beyond that, you're stuck, however much fuel it has.
```

```exercise
title: min_refuel_stops
kind: write
---prompt
Same setup: return the **fewest** stops to reach `target`, or -1. Drive forward; push every station you can reach onto a max-heap of litres. Whenever the next station (or the target) is out of reach, refuel from the biggest station passed so far and count a stop.
---starter
def min_stops(target, fuel, stations):
    stops = 0
    for pos, litres in stations:
        if fuel >= target:
            break
        if pos <= fuel:
            fuel += litres
            stops += 1
    return stops if fuel >= target else -1
---solution
def min_stops(target, fuel, stations):
    h, stops, i = [], 0, 0
    while fuel < target:
        while i < len(stations) and stations[i][0] <= fuel:
            heapq.heappush(h, -stations[i][1])
            i += 1
        if not h:
            return -1
        fuel += -heapq.heappop(h)
        stops += 1
    return stops
---tests
assert min_stops(1, 1, []) == 0
assert min_stops(100, 1, [(10, 100)]) == -1
assert min_stops(100, 10, [(10, 60), (20, 30), (30, 30), (60, 40)]) == 2
assert min_stops(100, 25, [(25, 25), (50, 25), (75, 25)]) == 3
assert min_stops(100, 50, [(25, 5), (50, 50)]) == 1
---hint
The starter stops at every station it passes. Instead, keep the passed stations in a heap and only "stop" (pop the biggest) when you must.
```

## Rebuild it and explain it

```exercise
title: greedy_rebuild
kind: rebuild
---prompt
From memory: `max_talks(talks)` (the most non-overlapping half-open intervals, greedy by end) and `can_jump(a)`.
---starter
def max_talks(talks):
    pass

    pass
---solution
def max_talks(talks):
    n, end = 0, float("-inf")
    for s, e in sorted(talks, key=lambda t: t[1]):
        if s >= end:
            n += 1
            end = e

def can_jump(a):
    far = 0
    for i, x in enumerate(a):
        if i > far:
            return False
        far = max(far, i + x)
    return True
```

```recall
Q: Explain what a greedy algorithm is, how you prove one with an exchange argument, and give examples where greedy works and where it fails.
A: A greedy algorithm builds the answer by repeatedly making the choice that looks best now and never undoing it, usually after sorting, so it is often O(n log n) and very short. It is only correct with the right rule. To prove a rule, use an exchange argument: take any optimal solution and show you can swap its choices one at a time for the greedy ones without making it worse, so the greedy answer is optimal too. For the most non-overlapping intervals, ending earliest is provably right while earliest start and shortest first have counterexamples. Greedy also works for reachability (track the farthest index in jump game), the gas station (restart after the tank goes negative), matching sorted items (cookies, boxers, queue order), partition labels, and with a heap of past choices for regret (drop the longest course, refuel from the biggest station passed). It fails for minimum coins with arbitrary values (1, 3, 4 for 6) and other problems that need dynamic programming, so always try small counterexamples or a brute-force check before trusting a greedy idea.
```
