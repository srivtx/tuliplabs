## Two bad choices and a good one

You have numbers that change, and you keep asking "what's the sum of the first i?". The two obvious stores each lose at one job:

- A **plain array** updates in one step, but a prefix sum reads up to n cells.
- A **prefix-sum array** (chapter 4) answers in one step, but one update rewrites up to n totals.

A **Fenwick tree** (also called a binary indexed tree, or BIT) sits in between. It's one array `t[1..n]` where **box i holds the sum of the last `i & -i` cells ending at i**. `i & -i` is the lowest set bit of i: box 12 (`1100`) covers 4 cells, 9..12; box 8 (`1000`) covers 8 cells, 1..8; box 7 (`0111`) covers just cell 7.

Two loops do everything, and they mirror each other:

- **prefix(i)**: add `t[i]`, then drop the lowest bit (`i -= i & -i`) and repeat until i is 0. 13 = `1101` visits boxes 13, 12, 8: cells 13, 9..12 and 1..8. One box per set bit, so at most log₂ n + 1.
- **add(i, v)**: add v to `t[i]`, then **add** the lowest bit (`i += i & -i`) and repeat while `i ≤ n`. That climbs through exactly the boxes whose range covers i.

A range sum is `prefix(r) − prefix(l − 1)`. The tree is 1-indexed because box 0 would have lowbit 0 and the loops would never move, so a 0-indexed API just adds 1 on the way in.

Compared with chapter 43's segment tree, a Fenwick tree is shorter, faster and uses n + 1 numbers instead of 4n. It can't do everything a segment tree does (minimum over an arbitrary range is awkward), but any job that's "**sums of something, with updates**" fits.

```run
title: A Fenwick tree in eleven lines
class Fenwick:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (n + 1)

    def add(self, i, v):          # position i is 0-indexed
        i += 1
        while i <= self.n:
            self.t[i] += v
            i += i & -i

    def prefix(self, i):          # sum of the first i numbers
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i
        return s

f = Fenwick(8)
for i, v in enumerate([5, 3, 8, 6, 1, 4, 7, 2]):
    f.add(i, v)
print(f.t)
print(f.prefix(4), f.prefix(8), f.prefix(6) - f.prefix(2))
f.add(2, 10)
print(f.prefix(4), f.prefix(8))
```

## Fenwick trees in interviews

```exercise
title: range_sum_mutable
kind: write
---prompt
*LeetCode 307, asked at Google and Meta.* `NumArray(nums)` with `update(i, val)` (position i **becomes** val) and `sumRange(l, r)`. A Fenwick tree adds, so an update adds the **difference** `val − nums[i]`, and you must remember the current values. Build it in O(n): put each value in its box, then pass the box's total to its parent `j + (j & -j)`.
---starter
class NumArray:
    def __init__(self, nums):
        self.a = list(nums)

    def update(self, i, val):
        self.a[i] += val

    def sumRange(self, l, r):
        return sum(self.a[l:r + 1])
---solution
class NumArray:
    def __init__(self, nums):
        self.a = list(nums)
        self.n = len(nums)
        self.t = [0] * (self.n + 1)
        for i, v in enumerate(nums):
            j = i + 1
            self.t[j] += v
            p = j + (j & -j)
            if p <= self.n:
                self.t[p] += self.t[j]

    def _add(self, i, v):
        i += 1
        while i <= self.n:
            self.t[i] += v
            i += i & -i

    def _pre(self, i):
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i
        return s

    def update(self, i, val):
        self._add(i, val - self.a[i])
        self.a[i] = val

    def sumRange(self, l, r):
        return self._pre(r + 1) - self._pre(l)
---tests
na = NumArray([1, 3, 5])
assert na.sumRange(0, 2) == 9
na.update(1, 2)
assert na.sumRange(0, 2) == 8 and na.sumRange(1, 1) == 2, "update sets the value, it doesn't add"
na = NumArray(lcg(100000, 9, 1000))
g, s = lcg(300000, 10, 100000), 0

    else:
        l, r = sorted((g[3 * k], g[3 * k + 1]))
        s += na.sumRange(l, r)

---hint
Keep `self.a` as the current values. `update` adds `val − self.a[i]` into the tree, then stores `val`.
```

```exercise
title: count_smaller_after_self
kind: write
---prompt
*LeetCode 315, a hard one asked at Google and Amazon.* For each `nums[i]`, count how many numbers **to its right** are strictly smaller. Sweep from the right, keeping a Fenwick tree over the **values** you've seen (compress them to ranks 1..m first). ---starter
def count_smaller(nums):
    out = []
    for i, x in enumerate(nums):
        out.append(sum(1 for y in nums[i + 1:i + 50] if y < x))
    return out
---solution
def count_smaller(nums):
    vals = sorted(set(nums))
    rank = {v: i + 1 for i, v in enumerate(vals)}
    m = len(vals)
    t = [0] * (m + 1)
    out = [0] * len(nums)
    for i in range(len(nums) - 1, -1, -1):
        r = rank[nums[i]] - 1
        s = 0
        while r > 0:
            s += t[r]
            r -= r & -r
        out[i] = s
        r = rank[nums[i]]
        while r <= m:
            t[r] += 1
            r += r & -r
    return out

---hint
```

```exercise
title: count_inversions
kind: write
---prompt
*A Codeforces staple.* An inversion is a pair `i < j` with `a[i] > a[j]`. Count them for 100,000 numbers up to 10⁹. Sweep left to right: before adding `a[j]`, the number of earlier values **greater** than it is `j − (how many earlier values are ≤ a[j])`.
---starter
def inversions(a):
    return sum(1 for i in range(len(a) - 1) if a[i] > a[i + 1])
---solution
def inversions(a):
    vals = sorted(set(a))
    rank = {v: i + 1 for i, v in enumerate(vals)}
    m = len(vals)
    t = [0] * (m + 1)
    inv = 0
    for seen, x in enumerate(a):
        r = rank[x]
        s = 0
        while r > 0:
            s += t[r]
            r -= r & -r
        inv += seen - s
        r = rank[x]
        while r <= m:
            t[r] += 1
            r += r & -r
    return inv
---tests
assert inversions([3, 1, 2]) == 2
assert inversions([2, 4, 1, 3, 5]) == 3
assert inversions(list(range(10, 0, -1))) == 45
assert inversions([7, 7, 7]) == 0, "equal values are not inversions"
assert inversions(lcg(100000, 17, 10 ** 9)) == 2495500853
---hint
The starter only counts neighbours. Every earlier value bigger than `x` makes one pair with it.
```

```exercise
    for op in ops:
        if op[0] == "add":
            a[op[1]] += op[3]

---solution
def range_add_point(n, ops):
    t = [0] * (n + 2)
    out = []
    def add(i, v):
        i += 1
        while i <= n + 1:
            t[i] += v
            i += i & -i
    for op in ops:
        if op[0] == "add":
            _, l, r, v = op
            add(l, v)
            add(r + 1, -v)
        else:
            i, s = op[1] + 1, 0
            while i > 0:
                s += t[i]
                i -= i & -i
            out.append(s)
    return out

        ops.append(("get", g[3 * k]))
```

## Real-world project: a game leaderboard

```project
title: Live ranks for a million players
client: A mobile game whose players want to see "you're rank 18,204 of 100,000" the moment a match ends, and whose weekly prize goes to whoever sits at rank 1,000

- The k-th lowest score by descending the tree
```

```exercise
---solution
class Board:
    def __init__(self, top):
        self.m = top + 1
        self.t = [0] * (self.m + 1)
        self.log = 1
        while self.log * 2 <= self.m:
            self.log *= 2

    def add(self, score, c=1):
        i = score + 1
        while i <= self.m:
            self.t[i] += c
            i += i & -i

    def kth(self, k):
        pos, step = 0, self.log
        while step:
            if pos + step <= self.m and self.t[pos + step] < k:
                pos += step
                k -= self.t[pos]
            step //= 2
        return pos
```


```recall
Q: Explain a Fenwick tree: what box i holds, how prefix and add walk the tree, why both are O(log n), why it's 1-indexed, and three jobs it solves beyond plain range sums.
A: A Fenwick tree is an array t[1..n] where box i holds the sum of the last i & -i cells ending at i, and i & -i is the lowest set bit of i. prefix(i) adds t[i] and drops the lowest bit (i -= i & -i) until i is 0, visiting one box per set bit. add(i, v) adds v to t[i] and adds the lowest bit (i += i & -i) while i ≤ n, visiting every box whose range covers i. Both take at most log₂ n + 1 steps, and a range sum is prefix(r) − prefix(l − 1). It's 1-indexed because 0 has no lowest bit, so the loops would never move. It uses n + 1 numbers and can be built in O(n) by passing each box's total to j + (j & -j). Beyond range sums: counting inversions or "smaller after self" with a tree over value ranks; range add with point query by keeping a tree over the difference array; and finding the k-th item by descending with powers of two. It suits sums, counts and XOR, not minimums, because those can't be subtracted.
```
