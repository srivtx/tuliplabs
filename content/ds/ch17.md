```prelude
import time
from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(vals):
    if not vals or vals[0] is None:
        return None
    root = TreeNode(vals[0])
    q, i = [root], 1
    for node in q:
        if i >= len(vals):
            break
        if vals[i] is not None:
            node.left = TreeNode(vals[i])
            q.append(node.left)
        i += 1
        if i < len(vals) and vals[i] is not None:
            node.right = TreeNode(vals[i])
            q.append(node.right)
        i += 1
    return root

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t
```

## Trees, briefly

A **binary tree** is nodes with up to two children, `left` and `right`. The top node is the **root**; nodes with no children are **leaves**. The **depth** of a node counts the nodes from the root down to it.

In every lesson here, `build_tree([3, 9, 20, None, None, 15, 7])` builds a tree from its **level order** (row by row, left to right, `None` for a missing child):

```
    3
   / \
  9   20
     /  \
    15   7
```

## Depth first: three orders

Recursion visits a node and both its subtrees. The only question is **when** you handle the node itself:

| Order | Node handled | Typical use |
|---|---|---|
| preorder | before its children | copying a tree, writing it out |
| inorder | between left and right | a search tree in sorted order (chapter 18) |
| postorder | after its children | anything that needs the children's answers first: heights, sizes, deleting |

```run
title: The three depth-first orders
root = build_tree([1, 2, 3, 4, 5, None, 6])
def pre(n):  return [n.val] + pre(n.left) + pre(n.right) if n else []
def ino(n):  return ino(n.left) + [n.val] + ino(n.right) if n else []
def post(n): return post(n.left) + post(n.right) + [n.val] if n else []
print("preorder: ", pre(root))
print("inorder:  ", ino(root))
print("postorder:", post(root))
```

## Think in subtrees

Most tree questions have a three-line recursive answer if you ask: **if I knew the answer for my left and right subtrees, what's mine?** And what's the answer for `None`?

```exercise
title: max_depth
kind: write
---prompt
*LeetCode 104.* Return the tree's depth: the number of nodes on the longest root-to-leaf path. `None` has depth 0.
---starter
def max_depth(root):
    d = 0
    while root:
        d += 1
        root = root.left
    return d
---solution
def max_depth(root):
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
---tests
assert max_depth(build_tree([3, 9, 20, None, None, 15, 7])) == 3
assert max_depth(build_tree([1, None, 2])) == 2
assert max_depth(None) == 0
---hint
My depth is 1 plus the deeper of my two subtrees.
```

```exercise
title: path_sum
kind: write
---prompt
*LeetCode 112.* Is there a root-to-**leaf** path whose values add up to `target`? Pass the remaining amount down: at a leaf, check whether it's exactly the leaf's value.
---starter
def has_path_sum(root, target):
    def total(n):
        return n.val + total(n.left) + total(n.right) if n else 0

---solution
def has_path_sum(root, target):
    if not root:
        return False
    if not root.left and not root.right:
```

## Passing two things up: diameter

Sometimes a subtree must report one thing to its parent (its height) while you track a **different** thing globally (the best path seen anywhere).

```exercise
title: diameter
kind: write
---prompt
*LeetCode 543, asked at Meta and Google.* The diameter is the number of **edges** on the longest path between any two nodes (it needn't pass through the root). A postorder helper returns each subtree's height; at each node, the longest path bending there is `left height + right height`.
---starter
def diameter(root):
    def h(n):
        return 1 + max(h(n.left), h(n.right)) if n else 0
    return h(root.left) + h(root.right) if root else 0
---solution
def diameter(root):
    best = 0
    def h(n):
        nonlocal best
        if not n:
            return 0
        l, r = h(n.left), h(n.right)
        best = max(best, l + r)
        return 1 + max(l, r)
    h(root)
    return best
---tests
assert diameter(build_tree([1, 2, 3, 4, 5])) == 3
assert diameter(build_tree([1, 2])) == 1
assert diameter(build_tree([1, 2, None, 3, 4, 5, None, None, 6, 7, None, None, 8])) == 6
assert diameter(None) == 0
---hint
The starter only bends at the root. Track `best` with `nonlocal` and update it at **every** node, while still returning the height.
```

```exercise
title: balanced_bug
kind: bug
---prompt
*LeetCode 110.* A tree is balanced if at **every** node the subtrees' heights differ by at most 1. This check only looks at the root, so it calls `[1, 2, 2, 3, None, None, 3, 4, None, None, 4]` balanced. Fix it in one pass: return -1 from the helper as soon as any subtree is unbalanced.
---starter
def is_balanced(root):
    def h(n):
        return 1 + max(h(n.left), h(n.right)) if n else 0
    return abs(h(root.left) - h(root.right)) <= 1 if root else True
---solution
def is_balanced(root):
    def h(n):
        if not n:
            return 0
        l, r = h(n.left), h(n.right)
        if l < 0 or r < 0 or abs(l - r) > 1:
            return -1
        return 1 + max(l, r)
    return h(root) >= 0
---tests
assert not is_balanced(build_tree([1, 2, 2, 3, None, None, 3, 4, None, None, 4]))
assert is_balanced(build_tree([3, 9, 20, None, None, 15, 7]))
assert not is_balanced(build_tree([1, 2, 2, 3, 3, None, None, 4, 4]))
assert is_balanced(None)
---hint
Let the helper return the height, or -1 meaning "unbalanced somewhere below". Pass the -1 straight up.
```

```exercise
title: max_path_sum
kind: write
---prompt
*LeetCode 124, a hard one asked at Meta, Google and Amazon.* Values can be negative. A path goes between any two nodes (at least one node). Return the largest path sum. Same shape as `diameter`: the helper returns the best path going **down** from a node (dropping a negative branch, i.e. `max(0, ...)`), and at each node you check `node.val + left + right`.
---starter
def max_path_sum(root):
    def down(n):
        return n.val + max(down(n.left), down(n.right)) if n else 0
    return down(root)
---solution
def max_path_sum(root):
    best = float("-inf")
    def down(n):
        nonlocal best
        if not n:
            return 0
        l, r = max(0, down(n.left)), max(0, down(n.right))
        best = max(best, n.val + l + r)
        return n.val + max(l, r)
    down(root)
    return best
---tests
assert max_path_sum(build_tree([1, 2, 3])) == 6
assert max_path_sum(build_tree([-10, 9, 20, None, None, 15, 7])) == 42
assert max_path_sum(build_tree([-3])) == -3
assert max_path_sum(build_tree([2, -1])) == 2
---hint
A branch that adds up to less than 0 is better left out: `max(0, down(child))`. The answer can bend at any node.
```

## Breadth first: level by level

Put the root in a queue (chapter 12). Repeatedly take from the front and add its children to the back: nodes come out in order of depth. Taking `len(q)` nodes at a time gives you exactly one level per round.

```exercise
title: min_depth
kind: write
---prompt
*LeetCode 111.* Return the depth of the shallowest **leaf**. Use breadth-first search and stop at the first leaf (the simulation's lesson). Watch out: a node with only one child is not a leaf.
---starter
def min_depth(root):
    if not root:
        return 0
    return 1 + min(min_depth(root.left), min_depth(root.right))
---solution
def min_depth(root):
    if not root:
        return 0
    q = deque([(root, 1)])
    while q:
        n, d = q.popleft()
        if not n.left and not n.right:
            return d
        for c in (n.left, n.right):
            if c:
                q.append((c, d + 1))
---tests
assert min_depth(build_tree([3, 9, 20, None, None, 15, 7])) == 2
assert min_depth(build_tree([2, None, 3, None, 4, None, 5, None, 6])) == 5
assert min_depth(None) == 0
---hint
The starter takes `min` with a missing child (depth 0), which isn't a leaf. With BFS and `(node, depth)` pairs, the first leaf you pop is the answer.
```

```exercise
title: lowest_common_ancestor
kind: write
---prompt
*LeetCode 236, one of Meta's most-asked.* Given two values `p` and `q` that are both in the tree (values are distinct), return the value of their lowest common ancestor: the deepest node that has both in its subtree (a node counts as its own descendant). Recursively: if this node is p or q, return it; otherwise ask both sides. If both sides found something, this node is the answer; otherwise pass up whichever side found something.
---starter
def lca(root, p, q):
    return root.val
---solution
def lca(root, p, q):
    def go(n):
        if not n or n.val in (p, q):
            return n
        l, r = go(n.left), go(n.right)
        if l and r:
            return n
        return l or r
    return go(root).val
---tests

assert lca(t, 5, 4) == 5
assert lca(t, 7, 4) == 2
assert lca(t, 6, 4) == 5
---hint
`go(n)` returns a node that is p, q or their meeting point, or `None`. The first node where both sides return something is the answer.
```

```exercise
title: party_groups
kind: write
---prompt
*Codeforces 115A "Party".* Employee i's direct manager is `boss[i]` (or -1 for none). Split everyone into groups so that nobody is in the same group as anyone above them in the chain of command. def groups(boss):

def groups(boss):
    kids = [[] for _ in boss]
    q = deque()
    for i, b in enumerate(boss):

        else:
            kids[b].append(i)

        levels += 1
        for _ in range(len(q)):
```

```exercise
def team_sizes(pairs):
```

## Rebuild it and explain it

```exercise
title: tree_rebuild
kind: rebuild
---prompt
From memory: `level_order(root)` (a list per level) and `diameter(root)` (edges on the longest path).
---starter
def level_order(root):
    pass

    pass
---solution
def level_order(root):
    out, q = [], deque([root] if root else [])
    while q:
        row = []
        for _ in range(len(q)):
            n = q.popleft()
            row.append(n.val)
            q.extend(c for c in (n.left, n.right) if c)
        out.append(row)

    best = 0
    def h(n):
        nonlocal best
        if not n:
            return 0
        l, r = h(n.left), h(n.right)
        best = max(best, l + r)
        return 1 + max(l, r)
    h(root)
    return best

---hint
```

```recall
Q: Explain the ways to traverse a binary tree and how to design recursive tree solutions.
A: Depth-first traversal recurses into both subtrees and handles the node before them (preorder), between them (inorder, sorted order for a search tree) or after them (postorder, needed whenever a node's answer depends on its children's, like heights and sizes). Most tree problems are solved by asking what each subtree should return and what the empty tree returns: depth is 1 + max of the children, inverting swaps inverted children, symmetry compares outside with outside and inside with inside, and path sums pass the remaining target down. When the best answer can bend at a node, the helper returns one thing to its parent (a height or best downward path, dropping negative branches) while a nonlocal variable tracks the global best (diameter, maximum path sum); returning -1 can signal failure up the tree (balanced check). Breadth-first traversal uses a queue, takes len(q) nodes per round to get one level at a time, and finds the shallowest leaf or right-side view; the first match is the nearest. The lowest common ancestor is the first node where p and q come back from different sides, or with parent pointers the first shared node walking up. Deep chains can exceed Python's recursion limit.
```
