## Two ways to sort

Insertion sort is how most people sort cards in their hand: take the next card and slide it left until it fits. Merge sort is how you'd sort a huge pile with friends: split it, everyone sorts a small pile, then merge piles two at a time.

```viz
name: ds-sort
title: Insertion sort against merge sort, counting comparisons
goal: Run **insertion sort** to the end, then run **merge sort** and compare the comparison counts.
height: 440
In merge sort each colour block is one run being merged: the runs double in length every round.
```

Merging two sorted runs is the key move: look at the front of each, take the smaller, repeat. Each comparison places one item, so merging costs about the total length. Runs double each round, so there are log₂ n rounds: **O(n log n)** in all. In practice you'll call Python's `sorted()` (Timsort, a merge-sort cousin), but you need to know what it costs and what it gives you.

```run
title: Sorting by any rule with key=
people = [("ana", 31), ("bo", 25), ("cy", 31), ("di", 19)]
print(sorted(people, key=lambda p: p[1]))            # by age
print(sorted(people, key=lambda p: (-p[1], p[0])))   # oldest first, then by name
words = ["banana", "Apple", "fig", "cherry"]
print(sorted(words, key=str.lower))
print(sorted(words, key=len))
```

```predict
nums = [3, 1, 2]
a = nums.sort()
b = sorted(nums, reverse=True)
print(a, nums, b)
```

`list.sort()` sorts **in place** and returns `None`; `sorted()` returns a **new** list. Mixing them up (`x = x.sort()`) is one of the most common Python bugs.

## Write a merge yourself

```exercise
title: merge_sorted
kind: write
---prompt
Merge two already-sorted lists into one sorted list in O(len(a) + len(b)) time, the heart of merge sort. Don't call `sorted` on the result.
---starter
def merge(a, b):
    out = a + b
    for i in range(len(out)):
        for j in range(len(out) - 1):
            if out[j] > out[j + 1]:
                out[j], out[j + 1] = out[j + 1], out[j]
    return out
---solution
def merge(a, b):
    out, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            out.append(a[i]); i += 1
        else:
            out.append(b[j]); j += 1
    out.extend(a[i:])
    out.extend(b[j:])
    return out
---tests
assert merge([1, 4, 9], [2, 3, 10, 11]) == [1, 2, 3, 4, 9, 10, 11]
assert merge([], [1]) == [1]
assert merge([5], []) == [5]
big_a, big_b = list(range(0, 6000, 2)), list(range(1, 6000, 2))
r, secs = timed(merge, big_a, big_b)
assert r == list(range(6000)) and secs < 0.1, f"{secs:.2f}s: that's a bubble sort, merge from the fronts instead"
---hint
Two pointers `i` and `j`. Append the smaller of `a[i]` and `b[j]`, move that pointer. When one list runs out, append the rest of the other.
```

```exercise
title: count_inversions
kind: write
---prompt
*A Codeforces classic.* An **inversion** is a pair i < j with `a[i] > a[j]`; it measures how unsorted a list is (it's exactly the number of swaps insertion sort makes). Count them for n up to 2·10⁴. Checking every pair is O(n²): instead, count during merge sort. When an item from the right half is taken before the remaining items of the left half, it forms an inversion with each of them.
---starter
def inversions(a):
    n = len(a)
    return sum(1 for i in range(n) for j in range(i + 1, n) if a[i] > a[j])
---solution
def inversions(a):
    def go(xs):
        if len(xs) <= 1:
            return xs, 0
        mid = len(xs) // 2
        left, x = go(xs[:mid])
        right, y = go(xs[mid:])
        out, i, j, inv = [], 0, 0, x + y
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                out.append(left[i]); i += 1
            else:
                out.append(right[j]); j += 1
                inv += len(left) - i
        out += left[i:] + right[j:]
        return out, inv
    return go(list(a))[1]
---tests
assert inversions([2, 4, 1, 3, 5]) == 3
assert inversions([1, 2, 3]) == 0
assert inversions([3, 2, 1]) == 3
assert inversions([]) == 0
big = list(range(20000, 0, -1))
r, secs = timed(inversions, big)
assert r == 20000 * 19999 // 2 and secs < 1.0, f"{secs:.2f}s: count inside the merge"
---hint
When you take `right[j]` while `left[i:]` is still waiting, every one of those `len(left) - i` items is bigger and came earlier: add that many.
```

## Sort, then scan neighbours

After sorting, things that are close in value sit next to each other. Many questions that need every pair (O(n²)) become "sort, then look at neighbours" (O(n log n)).

```exercise
title: min_gap
kind: write
---prompt
*Warm-up.* Return the smallest difference between any two numbers in the list (at least 2 numbers, up to 10⁴).
---starter
def min_gap(nums):
    return min(abs(a - b) for i, a in enumerate(nums) for b in nums[i + 1:])
---solution
def min_gap(nums):
    s = sorted(nums)
    return min(b - a for a, b in zip(s, s[1:]))
---tests
assert min_gap([30, 5, 20, 9]) == 4
assert min_gap([1, 1]) == 0
assert min_gap([-3, 10]) == 13
import random
random.seed(6)
big = random.sample(range(10**9), 6000)
r, secs = timed(min_gap, big)
s = sorted(big)
assert r == min(b - a for a, b in zip(s, s[1:])) and secs < 0.2
---hint
The closest pair in value must be neighbours once sorted. Sort, then compare each item with the next.
```

```exercise
title: meeting_rooms
kind: write
---prompt
*Asked at Google and Meta.* Given meetings as `(start, end)` (end is exclusive: a meeting ending at 10 frees the room for one starting at 10), return the fewest rooms needed. Sort the start times and the end times separately and sweep: a start needs a room unless some meeting has already ended.
---starter
def rooms(meetings):
    return len(meetings)
---solution
def rooms(meetings):
    starts = sorted(s for s, _ in meetings)
    ends = sorted(e for _, e in meetings)
    used = best = j = 0
    for s in starts:
        while j < len(ends) and ends[j] <= s:
            used -= 1; j += 1
        used += 1
        best = max(best, used)
    return best
---tests
assert rooms([(0, 30), (5, 10), (15, 20)]) == 2
assert rooms([(7, 10), (2, 4)]) == 1
assert rooms([(1, 5), (5, 10)]) == 1
assert rooms([(1, 10), (2, 9), (3, 8)]) == 3
assert rooms([]) == 0
---hint
Walk the sorted starts. Before counting a start, release every meeting whose end is ≤ that start (they're sorted too, so a pointer `j` is enough).
```

## Sorting by your own rules

```exercise

kind: write
---prompt
*Codeforces style.* Each player is `(name, solved, penalty)`. Rank by most problems solved, then by **least** penalty, then by name alphabetically. Return the names in order.

def leaderboard(players):
```

```exercise
title: largest_number
kind: write
---prompt
*An interview favourite.* Arrange non-negative integers so that, written side by side, they form the largest number; return it as a string. `[3, 30, 34, 5, 9]` → `"9534330"`. Sorting by plain value or plain string fails (try `3` against `30`): compare two numbers by which order of gluing is bigger, using `functools.cmp_to_key`.
---starter
def largest_number(nums):
    return "".join(sorted(map(str, nums), reverse=True))
---solution
from functools import cmp_to_key

def largest_number(nums):
    s = [str(x) for x in nums]
    s.sort(key=cmp_to_key(lambda a, b: -1 if a + b > b + a else (1 if a + b < b + a else 0)))
    out = "".join(s)
    return "0" if out and out[0] == "0" else out
---tests
assert largest_number([10, 2]) == "210"
assert largest_number([3, 30, 34, 5, 9]) == "9534330"
assert largest_number([0, 0]) == "0"
assert largest_number([1]) == "1"
---hint
`a` should go before `b` when `a + b > b + a` as strings. Watch out for all zeros: the answer is `"0"`, not `"00"`.
```

```exercise
title: h_index
kind: write
---prompt
*An interview classic.* A researcher's h-index is the largest h such that they have at least h papers with at least h citations each. Sort, then scan.
---starter
def h_index(citations):
    return len(citations)
---solution
def h_index(citations):
    c = sorted(citations, reverse=True)
    h = 0
    while h < len(c) and c[h] >= h + 1:
        h += 1
    return h

assert h_index([3, 0, 6, 1, 5]) == 3
```

## When values are small: counting sort

Comparison sorts can't beat n log n. But if the values are small integers (ages, grades, letters), you can **count** each value and write them back out in order: O(n + k) for values in range k, with no comparisons at all.

```exercise
title: counting_sort
kind: write
---prompt
Sort a list of integers in `0..k` (k up to 100, n up to 10⁶) in O(n + k) without calling `sorted` or `.sort`.
---starter
def counting_sort(a, k):
    out = []
    for v in range(k + 1):
        for x in a:
            if x == v:
                out.append(x)
    return out
---solution
def counting_sort(a, k):
    count = [0] * (k + 1)
    for x in a:
        count[x] += 1
    out = []
    for v in range(k + 1):
        out.extend([v] * count[v])
    return out
---tests
assert counting_sort([3, 0, 2, 3, 1, 0], 3) == [0, 0, 1, 2, 3, 3]
assert counting_sort([], 5) == []
assert counting_sort([7], 9) == [7]
import random
random.seed(1)
big = [random.randint(0, 100) for _ in range(200000)]
r, secs = timed(counting_sort, big, 100)
assert r == sorted(big) and secs < 0.25, f"{secs:.2f}s: count each value in ONE pass"
---hint
One pass to fill `count[x] += 1`, then for each value in order, write it out `count[v]` times.
```

```exercise
title: sort_by_frequency
kind: write
---prompt
*An interview question.* Sort the numbers so that the most frequent come first; ties in frequency go smaller value first. Every copy stays in the output.
---starter
def by_frequency(nums):
    return sorted(nums)
---solution
def by_frequency(nums):
    c = Counter(nums)
    return sorted(nums, key=lambda x: (-c[x], x))
---tests
assert by_frequency([4, 6, 2, 6, 4, 4]) == [4, 4, 4, 6, 6, 2]
assert by_frequency([3, 1, 2]) == [1, 2, 3]
assert by_frequency([]) == []
---hint
Count first with `Counter`, then sort with the key `(-count, value)`.
```

## Quick-fire: lock it in

```quiz
Why is merge sort O(n log n)?
- It compares every pair once
* There are log n rounds of merging, and each round does about n comparisons
- It splits the list into √n parts
- It only works on numbers
> Runs double each round (1, 2, 4, …, n), so log₂ n rounds; merging a whole round touches every item once.
```

```quiz
Insertion sort on a list that is **already sorted** costs…
* O(n): each item is compared once with its neighbour and stays
- O(n²) always
- O(n log n)
- O(1)
> Insertion sort's work equals n plus the number of inversions. Nearly sorted data is its best case, which is why Timsort uses it on small runs.
```

```quiz
You need "is there a pair with difference exactly d?" for n = 10⁵. Which plan fits?
- Check every pair
* Sort, then use two pointers (or a set of values)
- Counting sort on values up to 10⁹
- Recursion with a memo
> 10¹⁰ pair checks is too slow; sorting is 1.7·10⁶ and lets you walk two pointers. (Chapter 7 is all about that walk.)
```

```quiz
`sorted(people, key=lambda p: (-p.age, p.name))` gives…
- Youngest first, then by name
* Oldest first; people of the same age in alphabetical order
- Alphabetical, then by age
- An error, because you can't negate inside a key
> Tuples compare left to right, and negating a number flips its order. (For strings, which can't be negated, sort twice using stability.)
```

```quiz
When does counting sort beat `sorted()`?
- Always
- When the list is nearly sorted
* When the values are integers in a small range, like 0..100
- When the values are strings
> O(n + k) only wins when k (the range of values) is small. Values up to 10⁹ would need a billion counters.
```

```exercise
title: penalty
kind: write
---prompt
Submissions are `(team, problem, minute, ok)`, in time order. For each team, a problem counts once it's first accepted: add its minute plus 20 per wrong attempt before that; anything after the first accept is ignored, and wrong attempts on unsolved problems cost nothing. Return `{team: (solved, penalty)}` for every team that submitted.
---starter
def penalty(subs):
    out = {}
    for team, prob, minute, ok in subs:
        s, p = out.get(team, (0, 0))
        out[team] = (s + ok, p + minute)
    return out
---solution
def penalty(subs):
    out, wrong, done = {}, Counter(), set()
    for team, prob, minute, ok in subs:
        out.setdefault(team, (0, 0))
        if (team, prob) in done:
            continue
        if ok:
            done.add((team, prob))
            s, p = out[team]
            out[team] = (s + 1, p + minute + 20 * wrong[team, prob])
        else:
            wrong[team, prob] += 1
    return out
---tests
subs = [("red", "A", 10, False), ("red", "A", 15, True), ("red", "A", 30, True),
        ("blue", "A", 12, True), ("blue", "B", 50, False), ("green", "C", 5, False)]
assert penalty(subs) == {"red": (1, 35), "blue": (1, 12), "green": (0, 0)}
---hint
Track wrong attempts per `(team, problem)` and a set of solved `(team, problem)` pairs so later submissions are skipped.
```

```exercise
title: ranks
kind: write
---prompt
Given `{team: (solved, penalty)}`, return a list of `(rank, team)` ordered most solved, then least penalty, then name. Teams with the same solved and penalty share a rank, and the next rank skips ("1, 2, 2, 4").
---starter
def ranks(table):
    order = sorted(table)
    return [(i + 1, t) for i, t in enumerate(order)]
---solution
def ranks(table):
    order = sorted(table, key=lambda t: (-table[t][0], table[t][1], t))
    out = []
    for i, t in enumerate(order):
        if i and table[t] == table[order[i - 1]]:
            out.append((out[-1][0], t))
        else:
            out.append((i + 1, t))
    return out
---tests
```

## Rebuild it and explain it

```exercise
title: merge_sort_rebuild
kind: rebuild
---prompt
From memory: `merge_sort(xs)` returning a new sorted list, including the merge, in O(n log n). No `sorted` or `.sort`.
---starter
def merge_sort(xs):
    pass
---solution
def merge_sort(xs):
    if len(xs) <= 1:
        return list(xs)
    mid = len(xs) // 2
    a, b = merge_sort(xs[:mid]), merge_sort(xs[mid:])
    out, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            out.append(a[i]); i += 1
        else:
            out.append(b[j]); j += 1
    return out + a[i:] + b[j:]
---tests
import random
random.seed(3)
for n in (0, 1, 2, 7, 100):
    xs = [random.randint(-50, 50) for _ in range(n)]
    assert merge_sort(xs) == sorted(xs)
big = list(range(30000, 0, -1))
r, secs = timed(merge_sort, big)
assert r == sorted(big) and secs < 0.5
---hint
Base case: 0 or 1 items. Split at the middle, sort both halves recursively, merge with two pointers.
```

```recall
Q: Explain how merge sort reaches O(n log n), and what sorting unlocks in problem solving.
A: Merge sort splits the list in half, sorts each half recursively, and merges the two sorted halves by repeatedly taking the smaller front item; merging costs one comparison per item placed. The halving gives log₂ n levels, each doing about n work, so O(n log n), against insertion sort's O(n²) on shuffled data (though insertion sort is O(n) on nearly sorted data). Python's sorted() is stable and accepts key=, so you can sort by any rule with a tuple key, negating numbers to reverse their order. Sorting unlocks: close values become neighbours (min gap, duplicates, merging intervals), two pointers and binary search become possible, sweeps over sorted starts and ends (meeting rooms), and counting inversions during the merge. When values are small integers, counting sort runs in O(n + k) with no comparisons.
```
