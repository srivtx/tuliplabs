## A map, a start and a goal

Many DPs live on a 2D grid. The state is a square `(r, c)`, and the transition reads neighbouring squares that were **already filled**. When moves only go right or down, a square can only be reached from above or from the left, so row-by-row order works.

```viz
name: ds-pathsum
title: A 5 × 6 map: greedy steps against grid DP
goal: Run **greedy** to the end, then run **DP** and compare the effort.
height: 460
Move only right or down; the number is the effort for each square.
```

The cheapest route (LeetCode 64, **minimum path sum**):

- **State**: `dp[r][c]` = the least effort to reach `(r, c)`.
- **Transition**: `dp[r][c] = grid[r][c] + min(dp[r − 1][c], dp[r][c − 1])`.
- **Base cases**: the start square; along the top row and left column there's only one neighbour.
- **Order**: row by row, left to right.

```run
title: Counting routes on a 3 × 4 grid, one row at a time
R, C = 3, 4
row = [1] * C
print(row)
for r in range(1, R):
    for c in range(1, C):
        row[c] += row[c - 1]     # from above (old row[c]) + from the left (new row[c-1])
    print(row)
```

## The ladder

```exercise
title: unique_paths
kind: write
---prompt
*LeetCode 62, asked at Google, Amazon and Bloomberg.* A robot on an `m × n` grid moves only right or down. How many routes go from the top-left to the bottom-right? Keep one row and update it in place.
---starter
def unique_paths(m, n):
    return m * n
---solution
def unique_paths(m, n):
    row = [1] * n
    for _ in range(1, m):
        for c in range(1, n):
            row[c] += row[c - 1]
    return row[-1]
---tests
assert unique_paths(3, 7) == 28
assert unique_paths(3, 2) == 3
assert unique_paths(1, 1) == 1
assert unique_paths(17, 17) == 601080390
---hint
Routes into a square = routes into the square above + routes into the square on the left.
```

```exercise
            if grid[r][c]:
```

## Which way do the arrows point?

The fill order follows the dependencies, and not every grid goes top-left to bottom-right:

- **Triangle** (bottom-up): each number reads the two below it, so start at the last row.
- **Dungeon**: the health you need **now** depends on what's ahead, so fill from the goal backwards.
- **Longest increasing path**: you can move in all four directions, so there's no simple order. Use memoised DFS: each square's answer is cached the first time it's asked.

```exercise
title: triangle
kind: write
---prompt
*LeetCode 120, asked at Amazon and Apple.* From the top of the triangle, move to one of the two numbers directly below each step. Return the smallest total from top to bottom. Work from the bottom row up.
---starter
def min_total(tri):
    j, s = 0, tri[0][0]
    for i in range(1, len(tri)):
        if tri[i][j + 1] < tri[i][j]:
            j += 1
        s += tri[i][j]
    return s
---solution
def min_total(tri):
    row = tri[-1][:]
    for i in range(len(tri) - 2, -1, -1):
        row = [tri[i][j] + min(row[j], row[j + 1]) for j in range(i + 1)]
    return row[0]
---tests
assert min_total([[2], [3, 4], [6, 5, 7], [4, 1, 8, 3]]) == 11
assert min_total([[-10]]) == -10
assert min_total([[1], [2, 3], [1, 9, 1], [9, 9, 9, 1]]) == 6
assert min_total([[5], [1, 2], [9, 9, 1], [9, 9, 9, 1]]) == 9
---hint
The starter is greedy and walks into the 9s. From the bottom, each number's best total is itself plus the smaller of its two children.
```

```exercise
title: maximal_square
kind: write
---prompt
*LeetCode 221, asked at Google, Amazon and Apple.* `matrix` is a list of strings of `"0"`/`"1"`. Return the **area** of the largest square of all 1s. `dp[r][c]` = side of the biggest square whose bottom-right corner is `(r, c)`.
---starter
def maximal_square(matrix):
    return max(row.count("1") for row in matrix) ** 2
---solution
def maximal_square(matrix):
    R, C = len(matrix), len(matrix[0])
    dp = [[0] * (C + 1) for _ in range(R + 1)]
    best = 0
    for r in range(R):
        for c in range(C):
            if matrix[r][c] == "1":
                dp[r + 1][c + 1] = 1 + min(dp[r][c], dp[r][c + 1], dp[r + 1][c])
                best = max(best, dp[r + 1][c + 1])
    return best * best
---tests
assert maximal_square(["10100", "10111", "11111", "10010"]) == 4
assert maximal_square(["01", "10"]) == 1
assert maximal_square(["0"]) == 0
assert maximal_square(["1111", "1111", "1110"]) == 9
---hint
A square of side k ending at a corner needs squares of side k − 1 ending above, to the left, and diagonally. Take the smallest of the three, plus 1. The padded row and column of zeros remove edge checks.
```

```exercise
title: dungeon_game
kind: write
---prompt
*LeetCode 174, a hard one asked at Microsoft and Amazon.* A knight starts top-left and must reach the princess bottom-right, moving right or down. Each square changes health by its number; health must stay at least 1 the whole way. Return the minimum starting health. Fill **backwards** from the goal: `need[r][c] = max(1, min(need below, need right) − d[r][c])`.
---starter
def min_health(d):
    R, C = len(d), len(d[0])
    dp = [[0] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            best = 0 if r == c == 0 else max(dp[r - 1][c] if r else -10 ** 9, dp[r][c - 1] if c else -10 ** 9)
            dp[r][c] = best + d[r][c]
    return max(1, 1 - dp[-1][-1])
---solution
def min_health(d):
    R, C = len(d), len(d[0])
    INF = float("inf")
    need = [[INF] * (C + 1) for _ in range(R + 1)]
    need[R][C - 1] = need[R - 1][C] = 1
    for r in range(R - 1, -1, -1):
        for c in range(C - 1, -1, -1):
            need[r][c] = max(1, min(need[r + 1][c], need[r][c + 1]) - d[r][c])
    return need[0][0]
---tests
assert min_health([[-2, -3, 3], [-5, -10, 1], [10, 30, -5]]) == 7
assert min_health([[0]]) == 1
assert min_health([[100]]) == 1
assert min_health([[-3, 5]]) == 4
assert min_health([[1, -3, 3], [0, -2, 0], [-3, -3, -3]]) == 3
---hint
Going forwards, the best route's total doesn't tell you its lowest point along the way. Going backwards, you know exactly how much the rest of the trip will cost.
```

```exercise
title: longest_increasing_path
kind: write
---prompt
*LeetCode 329, a hard one asked at Google, Meta and Amazon.* Return the length of the longest strictly increasing path, moving up, down, left or right. Memoised DFS: `go(r, c)` = longest path starting at `(r, c)`, cached with `lru_cache`.
---starter
def longest_path(m):
    R, C = len(m), len(m[0])
    best = 1
    for r in range(R):
        run = 1
        for c in range(1, C):
            run = run + 1 if m[r][c] > m[r][c - 1] else 1
            best = max(best, run)
    return best
---solution
def longest_path(m):
    R, C = len(m), len(m[0])
    @lru_cache(maxsize=None)
    def go(r, c):
        best = 1
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            a, b = r + dr, c + dc
            if 0 <= a < R and 0 <= b < C and m[a][b] > m[r][c]:
                best = max(best, 1 + go(a, b))
        return best
    return max(go(r, c) for r in range(R) for c in range(C))
---tests
assert longest_path([[9, 9, 4], [6, 6, 8], [2, 1, 1]]) == 4
assert longest_path([[3, 4, 5], [3, 2, 6], [2, 2, 1]]) == 4
assert longest_path([[1]]) == 1
big = [[r * 20 + (c if r % 2 == 0 else 19 - c) for c in range(20)] for r in range(20)]
out, t = timed(longest_path, big)
assert out == 400
assert t < 1.0, f"too slow: {t:.2f}s"
---hint
"Strictly increasing" means a path can never loop, so caching each square's answer is safe. Each square is solved once: O(R·C).
```

```exercise
title: max_pick
kind: write
---prompt
Return the most items collected on a right/down route from top-left to bottom-right, avoiding `-1` squares, or `-1` if there's no route. Use `float("-inf")` for unreachable squares.
---starter
def max_pick(grid):
    return sum(max(v, 0) for row in grid for v in row)
---solution
def max_pick(grid):
    R, C = len(grid), len(grid[0])
    NEG = float("-inf")
    dp = [[NEG] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            if grid[r][c] < 0:
                continue
            best = 0 if r == c == 0 else max(dp[r - 1][c] if r else NEG, dp[r][c - 1] if c else NEG)
            if best > NEG:
                dp[r][c] = best + grid[r][c]
    return dp[-1][-1] if dp[-1][-1] > NEG else -1
---tests
assert max_pick([[0, 3, 1, 1], [2, 0, 0, 4], [1, 5, -1, 1], [0, 1, 2, 0]]) == 11
assert max_pick([[0, -1], [-1, 0]]) == -1
assert max_pick([[5]]) == 5
assert max_pick([[1, 2], [3, 4]]) == 8
---hint
A square is only reachable if one of its two neighbours is. Unreachable stays `-inf`, so it never wins a `max`.
```

```exercise
title: count_best_routes
kind: write
---prompt
Return how many right/down routes collect the maximum number of items (0 if packing is unreachable). Keep two tables: the best total and the number of routes achieving it. A square's count adds the counts of the neighbours that tie for the best.
---starter
def count_best(grid):
    R, C = len(grid), len(grid[0])
    row = [1] * C
    for _ in range(1, R):
        for c in range(1, C):
            row[c] += row[c - 1]
    return row[-1]
---solution
def count_best(grid):
    R, C = len(grid), len(grid[0])
    NEG = float("-inf")
    best = [[NEG] * C for _ in range(R)]
    ways = [[0] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            if grid[r][c] < 0:
                continue
            if r == c == 0:
                best[0][0], ways[0][0] = grid[0][0], 1
                continue
            cands = []
            if r and best[r - 1][c] > NEG:
                cands.append((best[r - 1][c], ways[r - 1][c]))
            if c and best[r][c - 1] > NEG:
                cands.append((best[r][c - 1], ways[r][c - 1]))
            if cands:
                top = max(v for v, _ in cands)
                best[r][c] = top + grid[r][c]
                ways[r][c] = sum(k for v, k in cands if v == top)
    return ways[-1][-1]
---tests
assert count_best([[0, 3, 1, 1], [2, 0, 0, 4], [1, 5, -1, 1], [0, 1, 2, 0]]) == 2
assert count_best([[0, 0, 0], [0, 0, 0], [0, 0, 0]]) == 6
assert count_best([[0, -1], [-1, 0]]) == 0
assert count_best([[1, 1], [1, 1]]) == 2
---hint
If both neighbours give the same best, routes from both count; if one is strictly better, only its routes do.
```

## Rebuild it and explain it

```exercise
title: grid_rebuild
kind: rebuild
---prompt
From memory: `falling_path(m)`: *LeetCode 931*. Start anywhere in the top row of a square matrix; each step goes to the row below, at most one column left or right. Return the smallest total. One row of DP.
---starter
def falling_path(m):
    pass
---solution
def falling_path(m):
    n = len(m[0])
    row = m[0][:]
    for r in range(1, len(m)):
        row = [m[r][c] + min(row[max(0, c - 1):c + 2]) for c in range(n)]
    return min(row)
---tests
assert falling_path([[2, 1, 3], [6, 5, 4], [7, 8, 9]]) == 13
assert falling_path([[-19, 57], [-40, -5]]) == -59
assert falling_path([[7]]) == 7
---hint
Each square reads up to three squares in the row above. Slicing `row[c − 1 : c + 2]` handles the edges if you clamp the start at 0.
```

```recall
Q: Explain DP on grids: the state and transition for path counting and minimum path sum, how edges and walls are handled, how to choose the fill direction, and when to use memoised DFS.
A: In a grid DP the state is a square (r, c), and its value is built from neighbouring squares that are already solved. With moves only right or down, a square is reached from above or from the left, so unique paths adds the two counts and minimum path sum adds the square's cost to the smaller of the two, filling row by row; one row of memory is enough because row[c] still holds the value from above until it is overwritten. Edges and walls are handled by one uniform rule: squares outside the grid or blocked count as zero routes or minus infinity, rather than special constants that ignore an earlier wall. The fill order must follow the dependencies: triangle minimum works from the bottom row up, the dungeon fills backwards from the goal because the health needed depends on what lies ahead, and maximal square uses the three neighbours above, left and diagonal. When moves go in every direction but the dependencies cannot cycle, as in a strictly increasing path, memoised DFS caches each square's answer the first time it is asked. Pairing a count table with a best table counts the routes that tie for the best.
```
