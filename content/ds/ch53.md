## Pipes, capacities and a trap

A **flow network** is a directed graph where each edge has a **capacity**, with a **source** s and a **sink** t. A flow sends an amount along each edge, at most its capacity, and at every node except s and t what comes in equals what goes out. The question: what's the most that can get from s to t?

It looks like water in pipes, but it models much more: data through a network, trucks along roads, people assigned to jobs (next chapter), and even "which pixels are foreground?" in image editing.

The obvious method: find any path from s to t with room on every edge, push as much as the tightest edge allows, and repeat. It can get **stuck** below the best answer.

```viz

```

The fix is the **residual graph**. For every edge a → b carrying flow f, add an **undo edge** b → a with room f. A later path may push flow along it, which cancels flow that went a → b and reroutes it. With undo edges, **no path left really means maximum**. That's Ford-Fulkerson.

Two facts make it a tool you can trust:

- **Edmonds-Karp.** Pick each path by **BFS** (fewest edges), and the number of rounds is at most O(n·m), so O(n·m²) in all, however big the capacities. In practice it's much faster.
- **Max-flow min-cut.** When it stops, let S be everything still reachable from s in the residual graph. Every edge from S to the rest is full, and every edge back into S is empty. So the flow equals the total capacity of those edges, a **cut**, and no cut can be smaller. The bottleneck of a network is exactly as big as its best flow.

Store edges in pairs (edge e and its undo edge `e ^ 1`) so pushing flow is two list updates.

```run
title: Edmonds-Karp with paired edges
class Flow:
    def __init__(self, n):
        self.n, self.adj, self.to, self.cap = n, [[] for _ in range(n)], [], []

    def add(self, a, b, c):
        self.adj[a].append(len(self.to)); self.to.append(b); self.cap.append(c)
        self.adj[b].append(len(self.to)); self.to.append(a); self.cap.append(0)   # undo edge

    def max_flow(self, s, t):
        total = 0
        while True:
            prev = [-1] * self.n
            prev[s] = -2
            q = deque([s])
            while q and prev[t] == -1:                  # BFS: shortest path with room
                v = q.popleft()
                for e in self.adj[v]:
                    w = self.to[e]
                    if self.cap[e] > 0 and prev[w] == -1:
                        prev[w] = e
                        q.append(w)
            if prev[t] == -1:
                return total
            push, v = float("inf"), t
            while v != s:                               # the bottleneck
                e = prev[v]
                push = min(push, self.cap[e])
                v = self.to[e ^ 1]
            v = t
            while v != s:                               # push it, and open the undo edges
                e = prev[v]
                self.cap[e] -= push
                self.cap[e ^ 1] += push
                v = self.to[e ^ 1]
            total += push

f = Flow(5)
for a, b, c in TRAP:
    f.add(a, b, c)
print(f.max_flow(0, 4))
```

- DFS can't find paths

```recall
Q: Explain maximum flow: what a flow network and a flow are, why greedy paths get stuck and how residual edges fix it, how Edmonds-Karp works and its bound, what the max-flow min-cut theorem says and how to read the cut, and how to handle many sources and sinks.
A: A flow network is a directed graph with a capacity on each edge, a source s and a sink t. A flow puts an amount on each edge, at most its capacity, and conserves flow at every node except s and t. The goal is to maximise what leaves s. Repeatedly filling any path that has room can get stuck, because an early path may block better routes. The residual graph adds, for every edge carrying f, an undo edge in the opposite direction with room f, so a later augmenting path can cancel and reroute earlier flow. With undo edges, "no augmenting path" means the flow is maximum (Ford-Fulkerson). Edmonds-Karp chooses each path by BFS (fewest edges), which bounds the number of rounds by O(n·m) whatever the capacities, so O(n·m²) in all. Storing each edge next to its partner (e and e ^ 1) makes a push two list updates. The max-flow min-cut theorem says the maximum flow equals the smallest total capacity of edges whose removal separates s from t. Read the cut by finding everything reachable from s in the final residual graph: the edges leaving that set are full and form a minimum cut. For many sources or sinks, add a super source with huge-capacity edges to each source and a super sink from each sink. Unit capacities count link-disjoint paths.
```
