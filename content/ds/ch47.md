```prelude
import time

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t

def lcg(n, seed, mx):
    out, x = [], seed
    for _ in range(n):
        x = (x * 1103515245 + 12345) % 2 ** 31
        out.append(x % mx)
    return out

def tall_tree(n, seed):
    """A tree on 0..n-1 given as parent[v], with parent[0] = -1 and parent[v] < v. About n/2 deep."""
    g = lcg(n, seed, 3)
    return [-1] + [max(0, i - 1 - g[i]) for i in range(1, n)]
```

## Where two paths meet

Root a tree. The **lowest common ancestor** (LCA) of u and v is the deepest node that's an ancestor of both, the spot where their paths up to the root join. It answers a surprising number of questions:

- the distance between two nodes is `depth[u] + depth[v] − 2·depth[lca]`
- in git, `merge-base` is the LCA of two commits
- in an org chart, it's the lowest manager both people report to

The obvious way is to climb: step the deeper node up until both are at the same depth, then step both up together until they meet. That's O(depth) per question, and a tree can be a long path, so O(n).


**Binary lifting** stores `up[k][v]`, the ancestor 2ᵏ levels above v. Row 0 is the parent. Each row comes from the one before: going up 2ᵏ is going up 2ᵏ⁻¹ twice, so `up[k][v] = up[k−1][ up[k−1][v] ]`. Ancestors past the root stay at the root.

With the table:

1. **Level the depths.** If u is `d` levels deeper, jump u up by d, one jump per set bit (d = 13 = 8 + 4 + 1 is three jumps).
2. If they're now equal, that's the answer.
3. **Jump together, biggest power first.** For k from high to low, if `up[k][u] ≠ up[k][v]`, jump both. A jump that lands on the **same** node might overshoot the LCA, so you skip it. At the end u and v are just below the LCA, so the answer is `up[0][u]`.

Both phases take O(log n) jumps. The table costs O(n log n) time and memory.

```run
title: Binary lifting for LCA
class LCA:
    def __init__(self, parent):
        n = len(parent)
        self.LOG = max(1, n.bit_length())
        self.depth = [0] * n
        for v in range(1, n):                    # parent[v] < v, so parents come first
            self.depth[v] = self.depth[parent[v]] + 1
        self.up = [[p if p >= 0 else 0 for p in parent]]
        for k in range(1, self.LOG):
            prev = self.up[-1]
            self.up.append([prev[prev[v]] for v in range(n)])

    def lca(self, u, v):
        if self.depth[u] < self.depth[v]:
            u, v = v, u
        d, k = self.depth[u] - self.depth[v], 0
        while d:
            if d & 1:
                u = self.up[k][u]
            d >>= 1
            k += 1
        if u == v:
            return u
        for k in range(self.LOG - 1, -1, -1):
            if self.up[k][u] != self.up[k][v]:
                u, v = self.up[k][u], self.up[k][v]
        return self.up[0][u]

#        0
#      /   \
#     1     2
#    / \     \
#   3   4     5
#      / \
#     6   7
t = LCA([-1, 0, 0, 1, 1, 2, 4, 4])
print(t.up)
print(t.lca(6, 7), t.lca(3, 7), t.lca(5, 6), t.lca(6, 6))
```

```quiz
In the second phase, why skip a jump that lands both nodes on the **same** ancestor?

- It wastes memory
- It breaks the depth
```

```exercise
title: kth_ancestor
kind: write
---prompt
*LeetCode 1483, a hard one asked at Google.* `TreeAncestor(n, parent)` with `getKthAncestor(node, k)`, the k-th ancestor of `node`, or `-1` if there isn't one. Keep `-1` in the table for "past the root". 100,000 nodes and 100,000 questions.

---solution
class TreeAncestor:
    def __init__(self, n, parent):
        self.LOG = max(1, n.bit_length())
        self.up = [list(parent)]
        for k in range(1, self.LOG):
            prev = self.up[-1]
            self.up.append([prev[x] if x != -1 else -1 for x in prev])

    def getKthAncestor(self, node, k):
        j = 0
        while k and node != -1:
            if j >= self.LOG:
                return -1
            if k & 1:
                node = self.up[j][node]
            k >>= 1
            j += 1
        return node
```

```exercise
title: tree_distances
kind: write
---prompt
*An interview and contest staple.* Edge `v → parent[v]` has length `w[v]`. Answer many questions "how far apart are a and b?". Precompute each node's distance from the root, `dist[v]`, then the answer is `dist[a] + dist[b] − 2·dist[lca(a, b)]`. 100,000 nodes and 100,000 questions.
---starter
def distances(parent, w, qs):
    dist = [0] * len(parent)
    for v in range(1, len(parent)):
        dist[v] = dist[parent[v]] + w[v]
    return [abs(dist[a] - dist[b]) for a, b in qs]
---solution
def distances(parent, w, qs):
    n = len(parent)
    LOG = max(1, n.bit_length())
    depth, dist = [0] * n, [0] * n
    for v in range(1, n):
        depth[v] = depth[parent[v]] + 1
        dist[v] = dist[parent[v]] + w[v]
    up = [[p if p >= 0 else 0 for p in parent]]
    for k in range(1, LOG):
        prev = up[-1]
        up.append([prev[prev[v]] for v in range(n)])
    def lca(u, v):
        if depth[u] < depth[v]:
            u, v = v, u
        d, k = depth[u] - depth[v], 0
        while d:
            if d & 1:
                u = up[k][u]
            d >>= 1
            k += 1
        if u == v:
            return u
        for k in range(LOG - 1, -1, -1):
            if up[k][u] != up[k][v]:
                u, v = up[k][u], up[k][v]
        return up[0][u]
    return [dist[a] + dist[b] - 2 * dist[lca(a, b)] for a, b in qs]
---tests
assert distances([-1, 0, 0, 1, 1], [0, 3, 5, 2, 7], [(3, 4), (3, 2), (0, 4), (2, 2)]) == [9, 10, 10, 0]
par = tall_tree(100000, 3)
w = [0] + [x + 1 for x in lcg(99999, 6, 100)]
q = lcg(200000, 7, 100000)
assert sum(distances(par, w, [(q[2 * i], q[2 * i + 1]) for i in range(100000)])) == 84151050784
---hint
The starter's `abs(dist[a] − dist[b])` is only right when one node is above the other. The path goes up to the LCA and back down.
```

```exercise
title: path_bottleneck
kind: write
---prompt
*A Codeforces favourite.* Edge `v → parent[v]` has weight `w[v]`. For each question `(a, b)`, return the **heaviest** edge on the path between them (0 if `a == b`). Store, next to `up[k][v]`, `mx[k][v]`: the heaviest edge on those 2ᵏ steps. `mx[k][v] = max(mx[k−1][v], mx[k−1][up[k−1][v]])`. Take the max of `mx` along every jump.
---starter
def bottlenecks(parent, w, qs):
    return [max(w[a], w[b]) for a, b in qs]
---solution
def bottlenecks(parent, w, qs):
    n = len(parent)
    LOG = max(1, n.bit_length())
    depth = [0] * n
    for v in range(1, n):
        depth[v] = depth[parent[v]] + 1
    up = [[p if p >= 0 else 0 for p in parent]]
    mx = [[w[v] if v else 0 for v in range(n)]]
    for k in range(1, LOG):
        pu, pm = up[-1], mx[-1]
        up.append([pu[pu[v]] for v in range(n)])
        mx.append([max(pm[v], pm[pu[v]]) for v in range(n)])
    out = []
    for u, v in qs:
        best = 0
        if depth[u] < depth[v]:
            u, v = v, u
        d, k = depth[u] - depth[v], 0
        while d:
            if d & 1:
                best = max(best, mx[k][u])
                u = up[k][u]
            d >>= 1
            k += 1
        if u != v:
            for k in range(LOG - 1, -1, -1):
                if up[k][u] != up[k][v]:
                    best = max(best, mx[k][u], mx[k][v])
                    u, v = up[k][u], up[k][v]
            best = max(best, mx[0][u], mx[0][v])
        out.append(best)
    return out
---tests
assert bottlenecks([-1, 0, 0, 1, 1], [0, 3, 5, 2, 7], [(3, 4), (3, 2), (0, 4), (2, 2), (1, 3)]) == [7, 5, 7, 0, 2]
par = tall_tree(100000, 3)
w = [0] + lcg(99999, 8, 10 ** 6)
q = lcg(200000, 7, 100000)
qs = [(q[2 * i], max(0, q[2 * i] - q[2 * i + 1] % 40)) for i in range(100000)]
assert sum(bottlenecks(par, w, qs)) == 88412794208
---hint
The LCA code is the same; every time a node jumps, fold in the `mx` for that jump. After the last phase, the two final parent edges count too.
```

## Real-world project: an org chart

```project

client: A company of 100,000 people whose tools need, instantly, the lowest manager two people share (for approvals) and the lowest manager a whole team shares (for a meeting invite)

---why
Binary lifting answers ancestor questions in file systems (the common folder of two paths), version control (git's merge-base), phylogenetics (the most recent common ancestor of species), and network routing trees.
---milestones
- The lifting table for the org chart
- The lowest common manager of two people
- The lowest common manager of a team
- 100,000 people, 20,000 teams
---stretch
- How many levels up the shared manager is from each person
- Teams that change one person at a time
```

```exercise

---prompt

---starter

---solution
def common_manager(boss, pairs):
    n = len(boss)
    LOG = max(1, n.bit_length())
    depth = [0] * n
    for v in range(1, n):
        depth[v] = depth[boss[v]] + 1
    up = [[p if p >= 0 else 0 for p in boss]]
    for k in range(1, LOG):
        prev = up[-1]
        up.append([prev[prev[v]] for v in range(n)])
    def lca(u, v):
        if depth[u] < depth[v]:
            u, v = v, u
        d, k = depth[u] - depth[v], 0
        while d:
            if d & 1:
                u = up[k][u]
            d >>= 1
            k += 1
        if u == v:
            return u
        for k in range(LOG - 1, -1, -1):
            if up[k][u] != up[k][v]:
                u, v = up[k][u], up[k][v]
        return up[0][u]
    return [lca(a, b) for a, b in pairs]
```

```recall
Q: Explain binary lifting for the lowest common ancestor: what the table stores and how it's built, how to level two depths, why the second phase goes from the biggest jump down and skips jumps that land on the same node, the costs, and two path questions it answers.
A: Binary lifting stores up[k][v], the ancestor 2ᵏ levels above v. Row 0 is the parent (the root points to itself), and up[k][v] = up[k−1][up[k−1][v]], because going up 2ᵏ is going up 2ᵏ⁻¹ twice. That's O(n log n) time and memory. For lca(u, v), first lift the deeper node by the depth gap, one jump per set bit, and if they're now the same node that's the answer. Otherwise try k from the highest power down and jump both nodes only when up[k][u] ≠ up[k][v]. A jump to the same node is a common ancestor that might be above the lowest one, so skipping it never overshoots. Going from big to small is like reading a number's bits from the top. Afterwards both nodes sit just below the LCA, so it's their parent. Each question takes O(log n) jumps. With dist[v] from the root, the distance between a and b is dist[a] + dist[b] − 2·dist[lca]. Storing the heaviest edge alongside each jump answers "the heaviest edge on a path" the same way. The k-th ancestor also takes one jump per set bit of k.
```
