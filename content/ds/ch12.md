## First in, first out

A **queue** is a line at a shop: join at the back, leave from the front. A **deque** ("deck", double-ended queue) can add and remove at **both** ends. Python's `collections.deque` does all four in O(1).

A plain list is a bad queue: `list.pop(0)` shifts every other item one place left, so it's O(n).

```run
title: list.pop(0) against deque.popleft()
import time
from collections import deque
n = 60000
a = list(range(n))
t = time.perf_counter()
while a:
    a.pop(0)
print(f"list.pop(0):     {time.perf_counter() - t:.3f}s")
d = deque(range(n))
t = time.perf_counter()
while d:
    d.popleft()
print(f"deque.popleft(): {time.perf_counter() - t:.3f}s")
```

## Queues in action

```exercise
title: recent_counter
kind: write
---prompt
*LeetCode 933.* Write `class RecentCounter` whose `ping(t)` records a request at time `t` (times only increase) and returns how many requests happened in `[t - 3000, t]`. Keep a queue and drop old times from the front, so each ping is amortised O(1).
---starter
class RecentCounter:
    def __init__(self):
        self.times = []

    def ping(self, t):
        self.times.append(t)
        return sum(1 for x in self.times if x >= t - 3000)
---solution
class RecentCounter:
    def __init__(self):
        self.q = deque()

    def ping(self, t):
        self.q.append(t)
        while self.q[0] < t - 3000:
            self.q.popleft()
        return len(self.q)
---tests
rc = RecentCounter()
assert [rc.ping(t) for t in (1, 100, 3001, 3002)] == [1, 2, 3, 3]
def many():
    r = RecentCounter()
    return [r.ping(t) for t in range(0, 4000)]
r, secs = timed(many)
assert r[-1] == 3001 and secs < 0.02, f"{secs:.2f}s: drop old pings from the front instead of recounting"
---hint
Append the new time, then `popleft()` while the front is older than `t - 3000`. The answer is `len(q)`.
```

```exercise
title: two_stack_queue
kind: write
---prompt
*LeetCode 232.* Build a queue from two stacks (plain lists using only `append`, `pop()` and `[-1]`): `push(x)`, `pop()`, `peek()`, `empty()`. Push onto an "in" stack; when you need the front and the "out" stack is empty, pour everything from in to out (which reverses it). Each item moves at most twice: amortised O(1).
---starter
class MyQueue:
    def __init__(self):
        self.s = []

    def push(self, x):
        self.s.append(x)

    def pop(self):
        return self.s.pop()

    def peek(self):
        return self.s[-1]

    def empty(self):
        return not self.s
---solution
class MyQueue:
    def __init__(self):
        self.inn, self.out = [], []

    def push(self, x):
        self.inn.append(x)

    def _pour(self):
        if not self.out:
            while self.inn:
                self.out.append(self.inn.pop())

    def pop(self):
        self._pour()
        return self.out.pop()

    def peek(self):
        self._pour()
        return self.out[-1]

    def empty(self):
        return not self.inn and not self.out
---tests
q = MyQueue()
q.push(1); q.push(2); q.push(3)
assert q.peek() == 1 and q.pop() == 1
q.push(4)
assert [q.pop(), q.pop(), q.pop()] == [2, 3, 4]
assert q.empty()
---hint
Only pour when `out` is empty. Pouring while `out` still has items would put newer items in front of older ones.
```

```exercise
title: josephus
kind: write
---prompt
*The classic elimination game.* People `1..n` stand in a circle. Counting starts at person 1; every `k`-th person is removed, and counting continues from the next person. Return the order people are removed in. Simulate with a deque: `rotate(-(k - 1))` brings the k-th person to the front.
---starter
def josephus(n, k):
    return list(range(k, n + 1, k))
---solution
def josephus(n, k):
    d, out = deque(range(1, n + 1)), []
    while d:
        d.rotate(-(k - 1))
        out.append(d.popleft())
    return out
---tests
assert josephus(7, 3) == [3, 6, 2, 7, 5, 1, 4]
assert josephus(5, 1) == [1, 2, 3, 4, 5]
assert josephus(1, 4) == [1]
assert josephus(4, 2) == [2, 4, 3, 1]
---hint
`d.rotate(-m)` moves the first m people to the back, so the person you want ends up at the front.
```

```exercise
title: card_war
kind: write
---prompt
*Codeforces 546C "Soldier and Cards".* Two players hold decks (fronts first). Each round both play their front card; the higher card wins, and the winner puts the **opponent's** card then **their own** at the bottom of their deck. Someone with an empty deck loses. Return `(rounds, winner)` with winner 1 or 2, or `-1` if the game is still going after 1 000 rounds (it loops forever).
---starter
def card_war(a, b):
    return (0, 1 if max(a) > max(b) else 2)
---solution
def card_war(a, b):
    p, q = deque(a), deque(b)
    rounds = 0
    while p and q:
        if rounds == 1000:
            return -1
        x, y = p.popleft(), q.popleft()
        if x > y:
            p.extend([y, x])
        else:
            q.extend([x, y])
        rounds += 1
    return (rounds, 1 if p else 2)
---tests
assert card_war([1, 3], [4, 2]) == (6, 2)
assert card_war([2], [1, 3]) == -1
assert card_war([5], [1]) == (1, 1)
---hint
Two deques; `popleft()` the fronts; the winner `extend([loser_card, winner_card])`. Count rounds and give up at 1 000.
```

## The monotonic deque

Chapter 11's monotonic stack answered "next greater". When a **window** slides, old items also have to leave from the other end, so you need a deque.

```viz
name: ds-deque
title: Maximum of every window: rescanning against a monotonic deque
goal: Run **rescan every window** to the end, then run **monotonic deque** and compare.
height: 460
The deque (under the bars) holds candidates for the maximum, biggest at the front.
```

Two rules keep it right: a new item pops every **smaller-or-equal** item from the back (they're older *and* smaller, so they can never be a window's maximum again), and the front is dropped when its index slides out. The front is always the current maximum.

```exercise
title: window_max
kind: write
---prompt
*LeetCode 239, a hard one asked at Amazon and Google.* Return the maximum of every window of `k` consecutive numbers, in O(n). Store **indices** in the deque so you can tell when the front has slid out.
---starter
def window_max(a, k):
    return [max(a[i:i + k]) for i in range(len(a) - k + 1)]
---solution
def window_max(a, k):
    dq, out = deque(), []
    for i, x in enumerate(a):
        if dq and dq[0] <= i - k:
            dq.popleft()
        while dq and a[dq[-1]] <= x:
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            out.append(a[dq[0]])
    return out
---tests
assert window_max([1, 3, -1, -3, 5, 3, 6, 7], 3) == [3, 3, 5, 5, 6, 7]
assert window_max([1, 3, 2, 5, 4, 2, 1, 6, 3, 2, 2, 4, 1, 3], 4) == [5, 5, 5, 5, 6, 6, 6, 6, 4, 4, 4]
assert window_max([4], 1) == [4]
big = list(range(20000))
r, secs = timed(window_max, big, 10000)
assert r == list(range(9999, 20000)) and secs < 0.15, f"{secs:.2f}s: don't rescan each window"
---hint
For each i: drop the front if it's at `i - k` or before; pop the back while it's ≤ the new value; append i; once `i >= k - 1`, the answer is `a[dq[0]]`.
```

```exercise
title: abs_diff_limit
kind: write
---prompt
*LeetCode 1438.* Return the length of the longest contiguous stretch where `max - min <= limit`. A sliding window (chapter 8) plus **two** monotonic deques: one for the window's max, one for its min.
---starter
def longest_within(a, limit):
    best = 0
    for i in range(len(a)):
        for j in range(i, len(a)):
            if max(a[i:j + 1]) - min(a[i:j + 1]) <= limit:
                best = max(best, j - i + 1)
    return best
---solution
def longest_within(a, limit):
    mx, mn = deque(), deque()
    L = best = 0
    for R, x in enumerate(a):
        while mx and a[mx[-1]] <= x:
            mx.pop()
        mx.append(R)
        while mn and a[mn[-1]] >= x:
            mn.pop()
        mn.append(R)
        while a[mx[0]] - a[mn[0]] > limit:
            L += 1
            if mx[0] < L:
                mx.popleft()
            if mn[0] < L:
                mn.popleft()
        best = max(best, R - L + 1)
    return best
---tests
assert longest_within([8, 2, 4, 7], 4) == 2
assert longest_within([10, 1, 2, 4, 7, 2], 5) == 4
assert longest_within([4, 2, 2, 2, 4, 4, 2, 2], 0) == 3
assert longest_within([], 3) == 0
_, secs = timed(longest_within, list(range(300)), 1000)
assert secs < 0.01, f"{secs:.2f}s: keep the max and min in deques as the window slides"
---hint
`mx` keeps decreasing values (front = max), `mn` increasing values (front = min). While the window breaks the limit, move L and drop deque fronts whose index fell below L.
```

```exercise
title: shortest_sum_negatives
kind: write
---prompt
*LeetCode 862, a hard one.* Like "shortest subarray with sum ≥ k", but numbers can be **negative**, so the plain sliding window breaks. Use prefix sums `P` (chapter 4): you want the smallest `j - i` with `P[j] - P[i] >= k`. Keep a deque of indices with **increasing** P: pop from the front while it answers the current j (it can't do better later), and pop from the back while its P is ≥ the new one (the new one is smaller *and* later, so strictly better). Return -1 if there's none.
---starter
def shortest(a, k):
    L, s, best = 0, 0, float("inf")
    for R, x in enumerate(a):
        s += x
        while s >= k:
            best = min(best, R - L + 1)
            s -= a[L]
            L += 1
    return -1 if best == float("inf") else best
---solution
def shortest(a, k):
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    dq, best = deque(), float("inf")
    for j, pj in enumerate(P):
        while dq and pj - P[dq[0]] >= k:
            best = min(best, j - dq.popleft())
        while dq and P[dq[-1]] >= pj:
            dq.pop()
        dq.append(j)
    return -1 if best == float("inf") else best
---tests
assert shortest([1], 1) == 1
assert shortest([1, 2], 4) == -1
assert shortest([2, -1, 2], 3) == 3
assert shortest([84, -37, 32, 40, 95], 167) == 3
assert shortest([-28, 81, -20, 28, -29], 89) == 3
---hint
Build P with a leading 0. For each j: first answer from the front, then clean the back, then push j.
```

```exercise
title: fcfs_waits
kind: write
---prompt
Jobs are `(arrival, duration)`, sorted by arrival. One worker runs them in order, each to completion; a job can't start before it arrives. Return each job's waiting time (start − arrival).
---starter
def waits(jobs):
    return [0 for _ in jobs]
---solution
def waits(jobs):
    t, out = 0, []
    for arrive, dur in jobs:
        start = max(t, arrive)
        out.append(start - arrive)
        t = start + dur
    return out
---tests
assert waits([(0, 5), (1, 3), (2, 1)]) == [0, 4, 6]
assert waits([(0, 2), (10, 3)]) == [0, 0]
assert waits([]) == []
---hint
Track when the worker is next free. Each job starts at the later of that and its arrival.
```

```exercise
title: round_robin
kind: write
---prompt
All jobs are ready at time 0: `durations[i]` is job i's run time. Round-robin with `quantum q`: take the front job, run it for `min(q, remaining)`, and if it isn't finished put it at the back. Return each job's finish time.
---starter
def round_robin(durations, q):
    t, out = 0, []
    for d in durations:
        t += d
        out.append(t)
    return out
---solution
def round_robin(durations, q):
    left = list(durations)
    finish = [0] * len(durations)
    queue, t = deque(range(len(durations))), 0
    while queue:
        i = queue.popleft()
        run = min(q, left[i])
        t += run
        left[i] -= run
        if left[i]:
            queue.append(i)
        else:
            finish[i] = t
    return finish
---tests
assert round_robin([5, 2, 1], 2) == [8, 4, 5]
assert round_robin([3, 3], 10) == [3, 6]
assert round_robin([], 2) == []
assert round_robin([4], 1) == [4]
---hint
A deque of job indices and a list of remaining times. Advance the clock by each slice; finished jobs record the clock, unfinished ones rejoin at the back.
```

```recall
Q: Explain queues and deques, and how the monotonic deque finds every window's maximum in O(n).
A: A queue is first-in-first-out; a deque adds and removes at both ends. Python's collections.deque does append, appendleft, pop and popleft in O(1), while list.pop(0) and insert(0, x) are O(n) because every item shifts. Queues model taking turns: rate counters that drop old times from the front, round-robin scheduling, Josephus elimination with rotate, card games, and (in Part 3) breadth-first search. Two stacks also make a queue with amortised O(1) operations. For the maximum of every window of size k, keep a deque of indices whose values decrease from front to back: each new item pops all smaller-or-equal items from the back (older and smaller, they can never be a maximum again), the front is removed when its index slides out of the window, and the front is the current maximum. Each index enters and leaves once, so O(n) for any k. Two such deques track max and min together; a deque over increasing prefix sums handles shortest subarray with sum ≥ k when numbers can be negative.
```
