## Orders that respect arrows

A **directed acyclic graph** (DAG) is a directed graph with no cycles: build steps, course prerequisites, spreadsheet formulas, package dependencies. A **topological order** lists its nodes so every arrow goes from earlier to later. One exists exactly when there's no cycle, and there are often several.

**Kahn's algorithm**:

1. Count each node's incoming arrows (its **in-degree**).
2. Queue every node with in-degree 0: nothing is blocking them.
3. Pop one, append it to the order, and decrement each node it points to; any that reach 0 join the queue.
4. If the order ends up shorter than the number of nodes, the rest are stuck in a cycle.

```run
title: Kahn's algorithm on a tiny morning routine
from collections import deque
before = [("underwear", "trousers"), ("trousers", "shoes"), ("socks", "shoes"), ("shirt", "tie"), ("tie", "jacket"), ("trousers", "belt"), ("belt", "jacket")]
nodes = sorted({x for e in before for x in e})
out = {v: [] for v in nodes}
indeg = {v: 0 for v in nodes}
for a, b in before:
    out[a].append(b)
    indeg[b] += 1
q = deque(v for v in nodes if indeg[v] == 0)
order = []
while q:
    v = q.popleft()
    order.append(v)
    for w in out[v]:
        indeg[w] -= 1
        if indeg[w] == 0:
            q.append(w)
print(order)
```

## The ladder

```exercise
title: course_order
kind: write
---prompt
*LeetCode 210, asked at Amazon, Google and Meta.* `n` courses, `prereqs` pairs `(a, b)` meaning b before a. Return an order to take them all, or `[]` if impossible. When several are ready, take the **smallest number** first (use a heap instead of a queue) so the answer is unique.
---starter
def course_order(n, prereqs):
    return list(range(n))
---solution
def course_order(n, prereqs):
    out = [[] for _ in range(n)]
    indeg = [0] * n
    for a, b in prereqs:
        out[b].append(a)
        indeg[a] += 1
    h = [v for v in range(n) if indeg[v] == 0]
    heapq.heapify(h)
    order = []
    while h:
        v = heapq.heappop(h)
        order.append(v)
        for w in out[v]:
            indeg[w] -= 1
            if indeg[w] == 0:
                heapq.heappush(h, w)
    return order if len(order) == n else []

assert course_order(2, [(1, 0)]) == [0, 1]
assert course_order(4, [(1, 0), (2, 0), (3, 1), (3, 2)]) == [0, 1, 2, 3]
assert course_order(3, [(0, 2), (1, 0)]) == [2, 0, 1]
assert course_order(2, [(1, 0), (0, 1)]) == []
assert course_order(1, []) == [0]
---hint
Edge `b → a`, so `indeg[a] += 1`. Pop the smallest ready course with `heappop`.
```

## Topological order with DFS

Depth-first search finishes a node only after everything it points to is finished. So the **reverse** of the finishing order is a topological order.

```parsons
title: Topological order from DFS finishing times
---lines
def topo_dfs(g, n):
    seen, finished = [False] * n, []
    def dfs(v):
        seen[v] = True
        for w in g[v]:
            if not seen[w]:
                dfs(w)
        finished.append(v)
    for v in range(n):
        if not seen[v]:
            dfs(v)
    return finished[::-1]
```

## Dynamic programming on a DAG

Once you have a topological order, you can process nodes so that everything feeding into a node is finished first: perfect for DP (Part 4).

```exercise
title: longest_path_dag
kind: write
---prompt
*AtCoder DP contest G "Longest Path".* A DAG with nodes `1..n` and directed edges. Return the number of **edges** on its longest path. Process nodes in Kahn's order; `best[w] = max(best[w], best[v] + 1)` along every edge.
---starter
def longest_path(n, edges):
    return len(edges)
---solution
def longest_path(n, edges):
    out = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    for a, b in edges:
        out[a].append(b)
        indeg[b] += 1
    q = deque(v for v in range(1, n + 1) if indeg[v] == 0)
    best = [0] * (n + 1)
    while q:
        v = q.popleft()
        for w in out[v]:
            best[w] = max(best[w], best[v] + 1)
            indeg[w] -= 1
            if indeg[w] == 0:
                q.append(w)
    return max(best)
---tests
assert longest_path(4, [(1, 2), (1, 3), (3, 2), (2, 4), (3, 4)]) == 3
assert longest_path(6, [(2, 3), (4, 5), (5, 6)]) == 2
assert longest_path(5, [(5, 3), (2, 3), (2, 4), (5, 2), (5, 1), (1, 4), (4, 3), (1, 3)]) == 3
assert longest_path(1, []) == 0
---hint
By the time `v` leaves the queue, every path into it has been counted, so `best[v]` is final.
```

```exercise
title: fewest_semesters
kind: write
---prompt
*LeetCode 1136.* Courses `1..n`; `relations` are `(before, after)`. Each semester you can take any number of courses whose prerequisites are all done. Return the fewest semesters, or -1 if there's a cycle. Kahn's algorithm **level by level**: each round of `len(q)` pops is one semester.
---starter
def semesters(n, relations):
    return 1 + len(relations)
---solution
def semesters(n, relations):
    out = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    for a, b in relations:
        out[a].append(b)
        indeg[b] += 1
    q = deque(v for v in range(1, n + 1) if indeg[v] == 0)
    taken = terms = 0
    while q:
        terms += 1
        for _ in range(len(q)):
            v = q.popleft()
            taken += 1
            for w in out[v]:
                indeg[w] -= 1
                if indeg[w] == 0:
                    q.append(w)
    return terms if taken == n else -1
---tests
assert semesters(3, [(1, 3), (2, 3)]) == 2
assert semesters(3, [(1, 2), (2, 3), (3, 1)]) == -1
assert semesters(4, [(1, 2), (2, 3), (1, 4)]) == 3
assert semesters(2, []) == 1
---hint
It's BFS levels (chapter 17) on Kahn's queue. Count the rounds, and check every course was taken.
```

```exercise
title: all_recipes
kind: write
---prompt
*LeetCode 2115.* `recipes[i]` needs every item in `ingredients[i]`; `supplies` are unlimited. An ingredient may itself be a recipe. Return every recipe you can make, sorted. Kahn's: nodes are items; supplies start in the queue; a recipe joins when all its ingredients are available.
---starter
def makeable(recipes, ingredients, supplies):
    have = set(supplies)
    return sorted(r for r, ing in zip(recipes, ingredients) if all(x in have for x in ing))
---solution
def makeable(recipes, ingredients, supplies):
    need = {r: len(ing) for r, ing in zip(recipes, ingredients)}
    used_by = defaultdict(list)
    for r, ing in zip(recipes, ingredients):
        for x in ing:
            used_by[x].append(r)
    q = deque(supplies)
    made = []
    while q:
        x = q.popleft()
        for r in used_by[x]:
            need[r] -= 1
            if need[r] == 0:
                made.append(r)
                q.append(r)
    return sorted(made)
---tests
assert makeable(["bread"], [["yeast", "flour"]], ["yeast", "flour", "corn"]) == ["bread"]
assert makeable(["bread", "sandwich"], [["yeast", "flour"], ["bread", "meat"]], ["yeast", "flour", "meat"]) == ["bread", "sandwich"]
assert makeable(["a", "b"], [["b"], ["a"]], []) == []
assert makeable(["burger", "sandwich", "bread"], [["sandwich", "meat", "bread"], ["bread", "meat"], ["yeast", "flour"]], ["yeast", "flour", "meat"]) == ["bread", "burger", "sandwich"]
---hint
In-degree of a recipe = how many ingredients it still needs. Making a recipe makes it an ingredient for others.
```

```exercise
title: alien_dictionary
kind: write
---prompt
*LeetCode 269, a hard one asked at Airbnb, Meta and Google.* `words` are sorted in an alien alphabet. Return a string of all their letters in an order consistent with it (ties: normal alphabetical order, so the answer is unique), or `""` if the list is impossible. Compare each pair of neighbours: the first differing letter gives one arrow. Watch out: `"abc"` before `"ab"` is impossible.
---starter
def alien_order(words):
    return "".join(sorted(set("".join(words))))
---solution
def alien_order(words):
    letters = sorted(set("".join(words)))
    out = {c: set() for c in letters}
    indeg = {c: 0 for c in letters}
    for a, b in zip(words, words[1:]):
        for x, y in zip(a, b):
            if x != y:
                if y not in out[x]:
                    out[x].add(y)
                    indeg[y] += 1
                break
        else:
            if len(a) > len(b):
                return ""
    h = [c for c in letters if indeg[c] == 0]
    heapq.heapify(h)
    order = []
    while h:
        c = heapq.heappop(h)
        order.append(c)
        for d in out[c]:
            indeg[d] -= 1
            if indeg[d] == 0:
                heapq.heappush(h, d)
    return "".join(order) if len(order) == len(letters) else ""
---tests
assert alien_order(["wrt", "wrf", "er", "ett", "rftt"]) == "wertf"
assert alien_order(["z", "x"]) == "zx"
assert alien_order(["z", "x", "z"]) == ""
assert alien_order(["abc", "ab"]) == ""
assert alien_order(["ab", "adc"]) == "abcd"
---hint
Only the first differing letter of each neighbouring pair tells you anything. Python's `for ... else` runs the `else` when the loop didn't `break`: no difference found.
```

```exercise
title: stuck_targets
kind: write
---prompt
`rules` maps each target to the list of things it needs (needs must be built first; a need that isn't a target is a plain source file). Return a sorted list of the targets that can **never** be built because they're in a cycle or depend on one. Run Kahn's over the targets; whatever is left over is stuck.
---starter
def stuck(rules):
    return sorted(t for t, needs in rules.items() if t in needs)
---solution
def stuck(rules):
    indeg = {t: sum(1 for n in needs if n in rules) for t, needs in rules.items()}
    users = defaultdict(list)
    for t, needs in rules.items():
        for n in needs:
            if n in rules:
                users[n].append(t)
    q = deque(t for t in rules if indeg[t] == 0)
    built = set()
    while q:
        t = q.popleft()
        built.add(t)
        for u in users[t]:
            indeg[u] -= 1
            if indeg[u] == 0:
                q.append(u)
    return sorted(set(rules) - built)
---tests
rules = {"site": ["index", "about"], "index": ["header", "posts.json"], "about": ["header"], "header": ["logo.png"]}
assert stuck(rules) == []
rules["header"] = ["footer"]
rules["footer"] = ["header"]
assert stuck(rules) == ["about", "footer", "header", "index", "site"]
assert stuck({"a": ["a"]}) == ["a"]
---hint
Only count needs that are themselves targets: source files are always available.
```

```exercise
title: downstream
kind: write
---prompt
When the file `changed` is edited, which targets must be rebuilt? Every target that needs it, directly or through other targets. Return them in a valid build order (ties: alphabetical). Find everything reachable along "is needed by" arrows, then topologically sort just those.
---starter
def downstream(rules, changed):
    return sorted(t for t, needs in rules.items() if changed in needs)
---solution
def downstream(rules, changed):
    users = defaultdict(list)
    for t, needs in rules.items():
        for n in needs:
            users[n].append(t)
    dirty, stack = set(), [changed]
    while stack:
        for u in users[stack.pop()]:
            if u not in dirty:
                dirty.add(u)
                stack.append(u)
    indeg = {t: sum(1 for n in rules[t] if n in dirty) for t in dirty}
    h = [t for t in dirty if indeg[t] == 0]
    heapq.heapify(h)
    order = []
    while h:
        t = heapq.heappop(h)
        order.append(t)
        for u in users[t]:
            if u in dirty:
                indeg[u] -= 1
                if indeg[u] == 0:
                    heapq.heappush(h, u)
    return order
---tests
rules = {"site": ["index", "about", "blog"], "index": ["header", "posts.json"], "about": ["header"], "header": ["logo.png"], "blog": ["posts.json"]}
assert downstream(rules, "logo.png") == ["header", "about", "index", "site"]
assert downstream(rules, "posts.json") == ["blog", "index", "site"]
assert downstream(rules, "nothing.txt") == []
---hint
First a DFS from the changed file over `users` to find the dirty set; then Kahn's restricted to it, counting only dirty needs.
```

```recall
Q: Explain topological sorting: what it is, Kahn's algorithm, the DFS method, cycle detection and DP on a DAG.
A: A topological order lists the nodes of a directed graph so every edge goes from earlier to later; it exists exactly when the graph has no cycle (a DAG). Kahn's algorithm counts each node's in-degree (incoming edges), queues the nodes with in-degree zero, and repeatedly removes one, appends it to the order and decrements its successors, queueing any that reach zero; it runs in O(V + E), a heap gives the smallest order when ties must be broken, and processing the queue in rounds gives levels such as the fewest semesters. If the order ends shorter than the number of nodes, the leftovers are in or behind a cycle. Alternatively, depth-first search appends each node when it finishes, and the reverse of that finishing order is topological. Processing nodes in topological order lets you do dynamic programming on a DAG, such as the longest path, because every predecessor is final before a node is used. Real uses include build systems, course plans, recipe dependencies, alien alphabets and spreadsheet recalculation.
```
