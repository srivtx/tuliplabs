```prelude
import sys, time
from functools import lru_cache

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t
```

## Trust the smaller copy

A recursive function solves a problem by calling itself on a **smaller** version, and has a **base case** small enough to answer directly. The leap of faith: while writing `fact(n) = n * fact(n - 1)`, assume `fact(n - 1)` already works.

Underneath, each call gets a **frame** on the call stack (its own `n`, its own local variables, and where to return to). A call can't finish until the calls it made have finished, so frames pile up and then unwind.

```run
title: Watching frames open and close
def fact(n, depth=0):
    print("  " * depth + f"fact({n}) starts")
    result = 1 if n <= 1 else n * fact(n - 1, depth + 1)
    print("  " * depth + f"fact({n}) returns {result}")
    return result

fact(4)
```

```predict
def show(n):
    if n == 0:
        return
    print("before", n)
    show(n - 1)
    print("after", n)

show(3)
```

Everything before the recursive call happens on the way **down** (3, 2, 1); everything after it happens on the way **back up**, in reverse (1, 2, 3). That's how the stack lets recursion "remember" where it was.

```quiz
What happens if a recursive function has no base case?
- It returns None
- It loops forever, using no extra memory
* Each call opens a new frame until Python's limit (about 1 000) and raises `RecursionError`
- Python detects it and stops at the first call
> Frames take memory, so infinite recursion runs out of stack. Python sets a limit (`sys.getrecursionlimit()`) to fail cleanly instead of crashing.
```

## Halving makes recursion fast

```exercise
title: fast_power
kind: write
---prompt
Write `power(x, n)` computing xⁿ for an integer n ≥ 0 using only O(log n) multiplications. The idea: xⁿ = (x^(n/2))² when n is even, and x · xⁿ⁻¹ when n is odd. (This is how cryptography raises numbers to 300-digit powers.)
---starter
def power(x, n):
    result = 1
    for _ in range(n):
        result *= x
    return result
---solution
def power(x, n):
    if n == 0:
        return 1
    if n % 2 == 0:
        half = power(x, n // 2)
        return half * half
    return x * power(x, n - 1)
---tests
assert power(2, 10) == 1024
assert power(3, 0) == 1
assert power(5, 3) == 125
assert power(7, 1) == 7
assert power(3, 200) == 3**200
_, secs = timed(power, 1, 10**7)
assert secs < 0.05, f"{secs:.3f}s: that's n multiplications; halve n instead"
---hint
Compute `half = power(x, n // 2)` **once** and square it. Calling `power(x, n // 2) * power(x, n // 2)` makes two calls and loses all the speed.
```

```exercise
title: hanoi
kind: write
---prompt
*The classic.* Move `n` discs from peg `a` to peg `c` using peg `b`, never putting a bigger disc on a smaller one. Return the list of moves as `(from, to)` pairs. Trust the smaller copy: move n−1 discs out of the way, move the biggest, move the n−1 back on top.
---starter
def hanoi(n, a="A", b="B", c="C"):
    return []
---solution
def hanoi(n, a="A", b="B", c="C"):
    if n == 0:
        return []
    return hanoi(n - 1, a, c, b) + [(a, c)] + hanoi(n - 1, b, a, c)
---tests
assert hanoi(1) == [("A", "C")]
assert hanoi(2) == [("A", "B"), ("A", "C"), ("B", "C")]
assert len(hanoi(10)) == 2**10 - 1
pegs = {"A": list(range(6, 0, -1)), "B": [], "C": []}
for f, t in hanoi(6):
    d = pegs[f].pop()
    assert not pegs[t] or pegs[t][-1] > d, "a bigger disc landed on a smaller one"
    pegs[t].append(d)
assert pegs["C"] == list(range(6, 0, -1))
---hint
Three steps: `hanoi(n-1, a, c, b)` (to the spare peg), the move `(a, c)`, then `hanoi(n-1, b, a, c)`.
```

```exercise
title: flatten
kind: write
---prompt
*An interview warm-up.* Flatten a list that may contain lists, nested to any depth, into one flat list in order.
---starter
def flatten(x):
    return [y for part in x for y in part]
---solution
def flatten(x):
    out = []
    for item in x:
        if isinstance(item, list):
            out.extend(flatten(item))
        else:
            out.append(item)
    return out
---tests
assert flatten([1, [2, [3, [4]], 5], [], 6]) == [1, 2, 3, 4, 5, 6]
assert flatten([]) == []
assert flatten([[[[]]]]) == []
assert flatten(["a", ["b"]]) == ["a", "b"]
---hint
For each item: if it's a list, flatten **it** (the smaller copy) and extend; otherwise append it.
```

## Repeated work, and the memo

```exercise
title: climb_stairs
kind: write
---prompt
*An interview classic.* You climb a staircase of `n` steps, taking 1 or 2 steps at a time. Count the different ways. n up to 80. The plain recursion `ways(n-1) + ways(n-2)` is the fib tree from the simulation, so it's far too slow at 80: memoize it.
---starter
def climb(n):
    if n <= 1:
        return 1
    return climb(n - 1) + climb(n - 2)
---solution
@lru_cache(maxsize=None)
def climb(n):
    if n <= 1:
        return 1
    return climb(n - 1) + climb(n - 2)
---tests
assert climb(1) == 1
assert climb(2) == 2
assert climb(3) == 3
assert climb(5) == 8
_, secs = timed(climb, 30)
assert secs < 0.05, f"climb(30) took {secs:.2f}s: that's the exponential call tree. Add a memo."
assert climb(80) == 37889062373143906
---hint
Add `@lru_cache(maxsize=None)` above the function (or keep a dict yourself). Every `climb(k)` is then computed once.
```

```exercise
title: memo_bug
kind: bug
---prompt
This memoized function crashes with `TypeError: unhashable type: 'list'`. A memo stores answers in a dict, so arguments must be hashable. Fix it so `best_sum` still takes a list from the caller.
---starter
@lru_cache(maxsize=None)
def best_sum(nums, i=0):
    # largest sum of non-adjacent numbers from position i on
    if i >= len(nums):
        return 0
    return max(best_sum(nums, i + 1), nums[i] + best_sum(nums, i + 2))
---solution
def best_sum(nums, i=0):
    nums = tuple(nums)

    @lru_cache(maxsize=None)
    def go(i):
        if i >= len(nums):
            return 0
        return max(go(i + 1), nums[i] + go(i + 2))

    return go(i)
---tests
assert best_sum([2, 7, 9, 3, 1]) == 12
assert best_sum([1, 2, 3, 1]) == 4
assert best_sum([]) == 0
r, secs = timed(best_sum, [5] * 400)
assert r == 1000 and secs < 0.2
---hint
Memoize an inner function that takes only the index `i`, and let it read the list from the outer function. (Or convert the list to a tuple before calling the cached function.)
```

## When the stack is too deep

Python's stack holds about 1 000 frames. A recursion that goes n levels deep fails at n = 10⁵, even with a memo. Contest solutions in Python usually turn such recursions into loops: compute small answers first and build up. That's a **bottom-up** table, the other face of dynamic programming.

```exercise
title: ways_134
kind: write
---prompt
*Codeforces style.* Count the ways to write `n` as an ordered sum of 1s, 3s and 4s (so 1+3 and 3+1 are different), modulo 1 000 000 007. n up to 10⁵, so recursion would overflow the stack: build the answers from 0 upwards in a list.
---starter
def ways(n):
    if n < 0:
        return 0
    if n == 0:
        return 1
    return (ways(n - 1) + ways(n - 3) + ways(n - 4)) % 1_000_000_007
---solution
def ways(n):
    MOD = 1_000_000_007
    w = [0] * (n + 1)
    w[0] = 1
    for i in range(1, n + 1):
        w[i] = (w[i - 1] + (w[i - 3] if i >= 3 else 0) + (w[i - 4] if i >= 4 else 0)) % MOD
    return w[n]
---tests
assert ways(1) == 1
assert ways(3) == 2, "1+1+1, 3"
assert ways(4) == 4, "1+1+1+1, 1+3, 3+1, 4"
assert ways(5) == 6
r, secs = timed(ways, 100000)
assert secs < 0.5 and 0 <= r < 1_000_000_007
---hint
`w[i] = w[i-1] + w[i-3] + w[i-4]` (skipping negative indices), starting from `w[0] = 1` (one way to make 0: take nothing).
```

```quiz

> fact(5) waits for fact(4), which waits for fact(3)… down to fact(1): five frames at once. Stack depth = depth of the recursion, not the number of calls.
```

```quiz
Plain recursive fib(n) makes about how many calls?
- n
- n²
* about 1.6ⁿ (exponential)
- n log n
> Each call makes two more, and the tree only gets one level shorter on one side. With a memo it's n + 1 calls doing real work.
```

```quiz
`power(x, n // 2) * power(x, n // 2)` instead of computing `half` once. What's the cost?
- Still O(log n)
* O(n): the two calls double at every level, undoing the halving
- O(n²)
- O(1)
> log n levels, doubling each time: 2^(log n) = n calls. Store the result once.
```

```quiz

* The same arguments are passed to the function many times
- The function has two base cases
```

## Real-world project: what's eating my disk?

```project

client: A video editor whose 2 TB drive is full and who can't tell which project folders are the culprits
```

```exercise
title: folder_size
kind: write
---prompt
A folder is a dict: keys are names; a value that's an `int` is a file's size, a value that's a `dict` is a subfolder. Write `folder_size(folder)` returning the total size of everything inside.
---starter
def folder_size(folder):
    return sum(v for v in folder.values() if isinstance(v, int))
---solution
def folder_size(folder):
    total = 0
    for v in folder.values():
        total += folder_size(v) if isinstance(v, dict) else v
    return total
---tests
disk = {"a.mp4": 700, "proj": {"raw": {"c1.mov": 4000, "c2.mov": 3500}, "edit.prproj": 20}, "notes.txt": 1, "empty": {}}
assert folder_size(disk) == 700 + 4000 + 3500 + 20 + 1
assert folder_size({}) == 0
assert folder_size(disk["proj"]) == 7520
---hint
For each value: a dict means "recurse", an int means "add it".
```

```exercise
title: all_sizes
kind: write
---prompt
Write `all_sizes(folder, path="/")` returning a dict from every folder's path to its total size. Subfolder paths are the parent's path plus the name and a `/` (so `"/proj/raw/"`). Visit each file only once in total (don't call `folder_size` for every folder).
---starter
def all_sizes(folder, path="/"):
    return {path: 0}
---solution
def all_sizes(folder, path="/"):
    out = {}
    def walk(f, p):
        total = 0
        for name, v in f.items():
            total += walk(v, p + name + "/") if isinstance(v, dict) else v
        out[p] = total
        return total
    walk(folder, path)
    return out
---tests
disk = {"a.mp4": 700, "proj": {"raw": {"c1.mov": 4000, "c2.mov": 3500}, "edit.prproj": 20}, "empty": {}}
assert all_sizes(disk) == {"/proj/raw/": 7500, "/proj/": 7520, "/empty/": 0, "/": 8220}
---hint
One recursive helper that **returns** its folder's total (so the parent can add it) and **records** it in `out` on the way back up.
```

## Rebuild it and explain it

```exercise
title: memo_rebuild
kind: rebuild
---prompt
From memory: `fib(n)` with a memo (a dict you manage yourself, no `lru_cache`), so `fib(90)` is instant. `fib(0) = 0`, `fib(1) = 1`.
---starter
def fib(n, memo=None):
    pass
---solution
def fib(n, memo=None):
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
---tests
assert [fib(i) for i in range(8)] == [0, 1, 1, 2, 3, 5, 8, 13]
r, secs = timed(fib, 90)
assert r == 2880067194370816120 and secs < 0.05
---hint
Check the memo before recursing, store the answer after. (`memo=None` then `memo = {}` avoids Python's shared-default-argument trap.)
```

```recall
Q: Explain how recursion uses the call stack, and when and how to use memoization.
A: A recursive function answers a small base case directly and otherwise calls itself on a smaller input, trusting that call to be right. Each call gets a frame on the call stack holding its arguments, locals and return point; a frame can only finish after the calls it made finish, so code before the recursive call runs on the way down and code after it runs on the way back up in reverse. Stack depth equals recursion depth, and Python allows about 1 000 frames, so very deep recursion raises RecursionError; then rewrite it bottom-up as a loop or use an explicit stack. When the same arguments recur (like fib, where the call tree has about 1.6ⁿ calls), store each answer the first time in a dict (or lru_cache) and return it on repeats: only one call per distinct argument does work, so fib becomes O(n). Halving the input (fast power) gives O(log n) calls, but only if the half result is computed once.
```
