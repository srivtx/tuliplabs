```prelude
from collections import Counter, defaultdict

def timed(fn, *args):
    t = time.perf_counter()
    out = fn(*args)
    return out, time.perf_counter() - t
```

## How a hash table finds things without looking

A list answers "is 37 in here?" by checking every item. A **hash table** (Python's `dict` and `set`) computes a number from the key (its *hash*), uses it to pick a bucket, and only looks in that bucket. With a good hash function and enough buckets, each bucket holds about one item, so a lookup is O(1) on average, however big the table gets.

```predict
d = {1: "a", 1.0: "b", True: "c"}
print(d)
```

`1`, `1.0` and `True` are equal and have the same hash, so they're the **same key**: the first spelling is kept, the last value wins. Keys are matched by `hash` and then `==`.

```quiz
Why can't a Python `list` be a dict key, but a `tuple` can?
- Lists are too long
* A list can change after it's stored, which would change its hash and lose it in the wrong bucket
- Tuples are faster
- Lists don't have an `==`
> The bucket is chosen from the hash at insert time. If the key changed, a later lookup would compute a different hash and look in the wrong bucket. So only immutable things are hashable. Convert with `tuple(lst)` when you need a list as a key.
```

## The two-sum pattern

For each item, ask: **"have I already seen the thing that completes me?"** Then store the item. One pass, one lookup each.

```exercise
title: two_sum
kind: write
---prompt
*The most famous interview question.* Return the indices `[i, j]` (i < j) of the two numbers in `nums` that add up to `target`. Exactly one answer exists. n can be 10⁵.
---starter
def two_sum(nums, target):
    for j in range(len(nums)):
        for i in range(j):
            if nums[i] + nums[j] == target:
                return [i, j]
---solution
def two_sum(nums, target):
    where = {}
    for j, x in enumerate(nums):
        if target - x in where:
            return [where[target - x], j]
        where[x] = j
---tests
assert two_sum([2, 7, 11, 15], 9) == [0, 1]
assert two_sum([3, 2, 4], 6) == [1, 2]
assert two_sum([3, 3], 6) == [0, 1], "the same value twice"
assert two_sum([-1, -2, -3, -4, -5], -8) == [2, 4]
big = list(range(0, 12000, 2)) + [7]
r2, secs2 = timed(two_sum, big, 11998 + 7)
assert r2 == [5999, 6000]
assert secs2 < 0.25, f"{secs2:.2f}s: that's comparing every pair. Remember what you've seen in a dict."
---hint
Keep a dict from value to its index. For each `x`, look up `target - x` **before** storing `x` (otherwise `[3, 3]` with target 6 would match `x` with itself).
```

```exercise
title: count_pairs
kind: write
---prompt
*Codeforces style.* Count the pairs `i < j` with `a[i] + a[j] == k`. Values can repeat, and n is up to 2·10⁵.
---starter
def count_pairs(a, k):
    return sum(1 for j in range(len(a)) for i in range(j) if a[i] + a[j] == k)
---solution
def count_pairs(a, k):
    seen = Counter()
    total = 0
    for x in a:
        total += seen[k - x]
        seen[x] += 1
    return total
---tests
assert count_pairs([1, 5, 7, -1], 6) == 2
assert count_pairs([1, 1, 1, 1], 2) == 6, "4 choose 2"
assert count_pairs([3], 6) == 0
big = [1] * 4000
r, secs = timed(count_pairs, big, 2)
assert r == 4000 * 3999 // 2 and secs < 0.25, f"{secs:.2f}s: too slow"
---hint
Like two-sum, but instead of returning on the first match, add **how many** earlier partners there are: keep counts, not indices.
```

```exercise
title: group_anagrams
kind: write
---prompt
*An interview classic.* Group words that are anagrams of each other. Return a list of groups; inside each group keep the words' original order, and order the groups by where their first word appeared.
---starter
def group_anagrams(words):
    return [[w] for w in words]
---solution
def group_anagrams(words):
    groups = {}
    for w in words:
        groups.setdefault("".join(sorted(w)), []).append(w)
    return list(groups.values())
---tests
assert group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"]) == [["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]
assert group_anagrams([""]) == [[""]]
assert group_anagrams(["ab", "ba", "abc"]) == [["ab", "ba"], ["abc"]]
---hint
Anagrams have the same letters, so they have the same **sorted** letters. Use that as a dict key. Python dicts remember insertion order, which gives the group order for free.
```

```exercise
title: first_unique

---prompt
*An interview classic.* Return the index of the first character in `s` that appears exactly once, or `-1`. Two passes, O(n).
---starter
def first_unique(s):

    for i, ch in enumerate(s):

    return -1
```

## Turn a pair condition into equal keys

A powerful contest trick: if a condition about a pair `(i, j)` can be rewritten as `f(i) == f(j)`, then counting good pairs is just counting equal keys.

```exercise
title: same_differences
kind: write
---prompt
*Codeforces style.* Count the pairs `i < j` with `a[j] - a[i] == j - i`. n is up to 2·10⁵.
---starter
def same_differences(a):
    n = len(a)
    return sum(1 for j in range(n) for i in range(j) if a[j] - a[i] == j - i)
---solution
def same_differences(a):
    seen = Counter()
    total = 0
    for i, x in enumerate(a):
        total += seen[x - i]
        seen[x - i] += 1
    return total
---tests
assert same_differences([3, 5, 1, 4, 6, 6]) == 1
assert same_differences([1, 2, 3]) == 3
assert same_differences([1, 2, 1, 2]) == 2
big = list(range(5000))
r, secs = timed(same_differences, big)
assert r == 5000 * 4999 // 2 and secs < 0.25, f"{secs:.2f}s: rewrite the condition first"
---hint
Move everything about `i` to one side: `a[j] - j == a[i] - i`. Now it's "count pairs with equal keys", where the key is `a[i] - i`.
```

```exercise
title: longest_consecutive
kind: write
---prompt
*A hard-looking interview classic.* Return the length of the longest run of consecutive integers that all appear in `nums` (in any order), in O(n). For `[100, 4, 200, 1, 3, 2]` it's 4 (1, 2, 3, 4). Sorting is O(n log n), so use a set.
---starter
def longest_consecutive(nums):
    return 0
---solution
def longest_consecutive(nums):
    s = set(nums)
    best = 0
    for x in s:
        if x - 1 not in s:
            y = x
            while y + 1 in s:
                y += 1
            best = max(best, y - x + 1)
    return best
---tests
assert longest_consecutive([100, 4, 200, 1, 3, 2]) == 4
assert longest_consecutive([0, 3, 7, 2, 5, 8, 4, 6, 0, 1]) == 9
assert longest_consecutive([]) == 0
assert longest_consecutive([5, 5, 5]) == 1
big = list(range(20000, 0, -1))
r, secs = timed(longest_consecutive, big)
assert r == 20000 and secs < 0.3, f"{secs:.2f}s: only start counting at the beginning of a run"
---hint
Put everything in a set. Only start walking upwards from `x` if `x - 1` is **not** in the set: then `x` begins a run, and every number is walked over at most once.
```

## Quick-fire: lock it in

```quiz
Average cost of `x in s` when `s` is a Python `set` of n items?
* O(1)
- O(log n)
- O(n)
- O(n log n)
> One hash, one bucket, about one comparison. (Lists are O(n); sorted lists with binary search O(log n).)
```

```quiz
Why does two-sum look up `target - x` **before** adding `x`?
- It's faster
* So a number can't be paired with itself
- To keep the dict small
- Dicts can't hold duplicates
> With target 6 and x = 3, adding first would find the 3 you just stored. Looking up first means you only match earlier numbers.
```

```quiz
A hash table's lookup is O(1) **on average**. When can it be O(n)?
- When the keys are strings
* When many keys land in the same bucket (collisions), for example inputs built to attack the hash function
- When the table is empty
- Never
> If everything collides, one bucket holds all n keys and you're back to a list. Codeforces "anti-hash" tests do exactly this to unprotected hash maps; adding a random salt to keys defeats them.
```

```quiz
Which of these needs a **dict** rather than a set?
- Has this email address signed up already?
* How many times has each email address signed up?
- Are there any duplicates in this list?
- Is this word in the dictionary?
> A set remembers *whether*; a dict remembers *something about* each key (a count, an index, a list).
```

```quiz
You need "pairs with `a[i] + i == a[j] - j`". What's the key trick?
- Sort first
* It isn't an equal-keys condition, because the two sides use different formulas: count `a[i] + i` values and look up `a[j] - j` as you go
- Two pointers
- It can't be done in O(n)
> You don't need the same formula on both sides. Walk j, look up how many earlier i had `a[i] + i == a[j] - j`, then store `a[j] + j`. Any "f(i) = g(j)" condition is one lookup per element.
```

## Real-world project: a duplicate-file finder

```project
title: Free up disk space by finding duplicate photos
client: A wedding photographer with 400 GB of photos copied between laptops, drives and cloud folders for years
skills: hashing, grouping, dicts of lists, streaming large files
---brief
Build `dupes.py FOLDER` that walks every file, groups them by size first (files with a unique size can't have a duplicate), then by a SHA-256 hash of their contents, and prints each group of identical files with the space you'd save by keeping one. Hash big files in chunks so memory stays small.
---why
Dropbox, Git and backup tools all store content by its hash, so identical data is kept once (deduplication). The size-first trick is the same idea as two-sum: a cheap key that rules most things out before doing expensive work.
---milestones
- Group files by size
- Hash only files that share a size, reading in chunks
- Print groups of identical files and the space to be saved
- Never touch a file's contents twice
---stretch
- Find near-duplicate images (resize to 8×8 grey and hash that)
- Replace duplicates with hard links
```

```exercise
title: duplicate_groups
kind: write
---prompt
`files` maps a file name to its contents (bytes). Return a list of groups (each a sorted list of names) of files with identical contents, only groups of 2 or more, sorted by their first name.
---starter
def duplicate_groups(files):
    return []
---solution
import hashlib

def duplicate_groups(files):
    by_hash = defaultdict(list)
    for name, data in files.items():
        by_hash[hashlib.sha256(data).hexdigest()].append(name)
    groups = [sorted(g) for g in by_hash.values() if len(g) > 1]
    return sorted(groups)
---tests
files = {"a.jpg": b"\x01\x02", "b.jpg": b"\x01\x02", "c.jpg": b"\x03", "d/a.jpg": b"\x01\x02", "e.txt": b"hi", "f.txt": b"hi"}
assert duplicate_groups(files) == [["a.jpg", "b.jpg", "d/a.jpg"], ["e.txt", "f.txt"]]
assert duplicate_groups({"x": b"1"}) == []
---hint
A dict from content hash (or the bytes themselves) to a list of names. Keep the lists with length ≥ 2.
```

```exercise
title: space_saved
kind: write
---prompt
Given the same `files` dict, return how many bytes you'd free by keeping one copy of each set of identical files.
---starter
def space_saved(files):
    return 0
---solution
def space_saved(files):
    copies = Counter(files.values())
    return sum(len(data) * (n - 1) for data, n in copies.items())
---tests
files = {"a": b"12345", "b": b"12345", "c": b"12345", "d": b"9", "e": b"77", "f": b"77"}
assert space_saved(files) == 5 * 2 + 2 * 1
assert space_saved({}) == 0
---hint
Count how many times each content appears. Every copy beyond the first is wasted: `len(data) * (count - 1)`.
```

```recall
Q: How does a hash table give O(1) lookups, and what's the two-sum pattern?
A: A hash table computes a hash number from the key and uses it to choose a bucket, then only compares against the few keys in that bucket. With a good hash function and a table that grows as it fills, buckets stay tiny, so lookups, inserts and deletes are O(1) on average (O(n) in the worst case, if everything collides). Keys must be immutable, because the bucket is chosen from the hash when the key is stored. The two-sum pattern: walk the array once; for each x, ask whether its partner (target − x) has been seen, then store x. Storing counts instead of indices counts pairs. More generally, rewrite a pair condition so one side depends only on i and the other only on j (for example a[i] − i == a[j] − j), then count with a dict as you walk: O(n) instead of O(n²).
```
