```prelude
from modsim import *

def bike_to_wellesley(state):
    if state.olin == 0:
        state.olin_empty += 1
        return
    state.olin -= 1; state.wellesley += 1

def bike_to_olin(state):
    if state.wellesley == 0:
        state.wellesley_empty += 1
        return
    state.wellesley -= 1; state.olin += 1

def step(state, p1, p2):
    if flip(p1):
        bike_to_wellesley(state)
    if flip(p2):
        bike_to_olin(state)
```

## Return values, not prints

A function that prints its answer can't be used by other code. A function that **returns** its answer can be called in a loop, stored, plotted and tested. Every function from here on returns its results.

```predict
def add_print(a, b):
    print(a + b)

def add_return(a, b):
    return a + b

x = add_print(2, 3)
y = add_return(2, 3)
print(x, y)
```

```quiz
In the prediction above, why is `x` equal to `None`?
- Printing failed
* `add_print` has no return statement, so calling it evaluates to None (it only displays the sum)
- 2 + 3 is None in Python
- Variables can't hold numbers
> A function without `return` returns None. The 5 appeared on screen, but no value came back to store in x.
```

## run_simulation

```exercise
title: run_simulation
kind: write
---prompt
Write the book's `run_simulation(p1, p2, num_steps)`: create a fresh state (10 bikes at Olin, 2 at Wellesley, both counters 0), call `step` `num_steps` times, and **return the final state**. `step` is defined in the prelude.
---starter
def run_simulation(p1, p2, num_steps):
    pass
---solution
def run_simulation(p1, p2, num_steps):
    state = State(olin=10, wellesley=2, olin_empty=0, wellesley_empty=0)
    for i in range(num_steps):
        step(state, p1, p2)
    return state
---tests
s = run_simulation(0, 0, 60)
assert (s.olin, s.wellesley) == (10, 2), "With no customers nothing moves"
s = run_simulation(1, 0, 60)
assert (s.olin, s.wellesley, s.olin_empty) == (0, 12, 50), f"Every minute someone leaves Olin: 10 rides, then 50 unhappy customers. Got {(s.olin, s.wellesley, s.olin_empty)}"
a, b = run_simulation(0, 0, 1), run_simulation(0, 0, 1)
assert a is not b, "Each run should start from a fresh state"
---hint
Create the `State` **inside** the function, so every run starts fresh.
```

Parameters like `p1` are values you pass in; variables like `state` are created inside and vanish when the function returns (unless you return them). That's why each run starts clean.

## Sweep a parameter

How does the number of unhappy customers depend on `p1`? Run the model for many values of `p1` and record the metric. `linspace(start, stop, num)` makes evenly spaced values; a `SweepSeries` maps each parameter value to its result.

```predict
print(linspace(0, 1, 5))
print(linrange(0, 1, 0.25))
```

```run
title: Unhappy customers vs p1
def run_simulation(p1, p2, num_steps):
    state = State(olin=10, wellesley=2, olin_empty=0, wellesley_empty=0)
    for i in range(num_steps):
        step(state, p1, p2)
    return state

p1_array = linspace(0, 1, 21)
sweep = SweepSeries()
for p1 in p1_array:
    sweep[p1] = run_simulation(p1, 0.2, 60).olin_empty
plot(sweep, "o-", label="olin_empty")
decorate(title="Olin-Wellesley bikeshare", xlabel="Arrival rate at Olin (p1 in customers/min)",
         ylabel="Number of unhappy customers")
```

```quiz
The plot is noisy: run it twice and the points move. How could you get a smoother, more reliable curve?
- Use fewer values of p1
* Run several simulations for each p1 and average the metric
- Increase p2
- Plot it on a log scale
> Each run is random, so a single run per p1 is a noisy estimate. Averaging many runs per value reduces the noise, at the cost of more computation.
```

```exercise
title: Average over repeats
kind: rebuild
---prompt
From memory: `mean_unhappy(p1, p2, num_steps, iters)` runs `run_simulation` `iters` times and returns the mean of `olin_empty + wellesley_empty`.
---setup
def run_simulation(p1, p2, num_steps):
    state = State(olin=10, wellesley=2, olin_empty=0, wellesley_empty=0)
    for i in range(num_steps):
        step(state, p1, p2)
    return state
---starter
def mean_unhappy(p1, p2, num_steps, iters):
    pass
---solution
def mean_unhappy(p1, p2, num_steps, iters):
    total = 0
    for i in range(iters):
        state = run_simulation(p1, p2, num_steps)
        total += state.olin_empty + state.wellesley_empty
    return total / iters
---tests
assert mean_unhappy(1, 0, 60, 5) == 50, "Deterministic case: always 50"
assert mean_unhappy(0, 0, 60, 3) == 0, "No customers: 0"
```

```recall
Q: What does "sweeping a parameter" mean, and why is it useful?
A: - Running the same model many times while varying one parameter over a range, and recording a metric for each value.
- It shows how sensitive the results are to the parameter, finds ranges where the system works well or badly, and supports decisions (e.g. how many bikes to put at each station).
```

## Real-world project: how many meals should the food truck prep?

A sweep turns "it depends" into a chart you can decide from. Here the parameter isn't a probability but a choice the owner makes every morning: how many meals to cook. Too few and customers leave hungry; too many and food goes in the bin. Run the day once for each choice, measure the money, and the best choice is the top of the curve.

```project
title: Daily prep quantity for a food truck
client: A taco truck that cooks everything before it opens
skills: functions that return values, SweepSeries, averaging over many runs, idxmax
---brief
Each taco plate sells for $9 and costs $3 to make. Unsold plates are thrown away. The owner has written down how many people wanted a plate on 10 recent days. Write `day_profit` for one day, then sweep the number of plates prepped from 40 to 120 and find the quantity with the best **average** profit over those days.
---why
This is the classic "newsvendor" problem, and real software solves it every day: bakeries and supermarkets decide how much fresh food to order, airlines decide how many seats to overbook, cloud teams decide how many servers to keep warm. The tool is always the same: a function that scores one choice, swept over all the choices.
---milestones
- Write `day_profit(prepped, demand, price, cost)` that returns (not prints) one day's profit
- Write `sweep_prep(prep_array, demands, price, cost)` returning a SweepSeries of mean profit
- Plot the curve and find the best quantity with `idxmax`
- Change the cost to $5: does the best quantity go up or down? Explain why
- Replace the 10 recorded days with 200 simulated days using `np.random.poisson` and compare
---stretch
- Add a second dish that shares the same cooking time budget
- Let leftover plates sell the next morning at half price
- Show the owner the risk: the worst day's profit for each prep quantity
```

```exercise
title: day_profit for the food truck
kind: write
---prompt
Write `day_profit(prepped, demand, price, cost)`: the truck sells as many plates as it can (the smaller of `prepped` and `demand`), earns `price` for each one sold, and paid `cost` for **every** plate prepped. Return the profit.
---starter
def day_profit(prepped, demand, price, cost):
    print(prepped * price)
---solution
def day_profit(prepped, demand, price, cost):
    sold = min(prepped, demand)
    return sold * price - prepped * cost
---tests
assert day_profit(50, 80, 9, 3) is not None, "Return the profit; printing it doesn't let the sweep use it"

```

---solution
def sweep_prep(prep_array, demands, price, cost):
    sweep = SweepSeries()
    for prepped in prep_array:
        profits = [day_profit(prepped, d, price, cost) for d in demands]
        sweep[prepped] = sum(profits) / len(profits)
    return sweep

def best_prep(prep_array, demands, price, cost):
    sweep = sweep_prep(prep_array, demands, price, cost)
    return sweep.idxmax()
---tests
s = sweep_prep([10, 30], [20, 40], 9, 3)

assert s[10] == 60, f"Prep 10: sold out both days, $60 profit each. Got {s[10]}"
assert s[30] == 135, f"Prep 30: day one sells 20 ($90 profit), day two sells 30 ($180). Mean $135. Got {s[30]}"
demands = [62, 75, 58, 90, 81, 70, 66, 95, 73, 60]
