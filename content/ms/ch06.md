## System objects

As models grow, functions need more parameters. We collect them in a `System` object, so a function takes one argument and reads what it needs.

```run
title: A System
system = System(t_0=1950, t_end=2016, p_0=2.558, annual_growth=0.0723)
print(system)
print(system.t_end - system.t_0, "years")
```

```predict
system = System(t_0=2000, t_end=2010, p_0=6.0, alpha=0.01)
print(system.t_end - system.t_0)
print(round(system.p_0 * (1 + system.alpha), 3))
```

## Proportional growth

People have children, and more people have more children. So maybe growth is **proportional to population**: each year, population increases by `alpha × population`, where alpha is the net growth rate (births minus deaths, per person per year).

## Factor out the update function

Every model in this part has the same loop; only the rule for "next year from this year" changes. We separate the rule into an **update function** and writes one `run_simulation` that takes the rule as an argument.

```exercise
title: run_simulation with an update function
kind: write
---prompt
Write `run_simulation(system, update_func)`: start a TimeSeries at `system.t_0` with `system.p_0`, and for each year in `linrange(system.t_0, system.t_end)` set the next value to `update_func(results[t], t, system)`. Return the TimeSeries.
---starter
def run_simulation(system, update_func):
    pass
---solution
def run_simulation(system, update_func):
    results = TimeSeries()
    results[system.t_0] = system.p_0
    for t in linrange(system.t_0, system.t_end):
        results[t + 1] = update_func(results[t], t, system)
    return results
---tests
sys1 = System(t_0=0, t_end=3, p_0=1.0)
r = run_simulation(sys1, lambda pop, t, system: pop * 2)
assert r.tolist() == [1.0, 2.0, 4.0, 8.0], f"Doubling for 3 steps: [1, 2, 4, 8], got {r.tolist()}"
assert list(r.index) == [0, 1, 2, 3], "Times 0 to t_end inclusive"
```

```exercise
title: update_func for proportional growth
kind: fill
---prompt
Fill in the update function for proportional growth.
---starter
def update_func1(pop, t, system):
    net_growth = ____
    return ____
---solution
def update_func1(pop, t, system):
    net_growth = system.alpha * pop
    return pop + net_growth
---tests
s = System(alpha=0.1)
assert abs(update_func1(10.0, 0, s) - 11.0) < 1e-9, "10% of 10 is 1, so next year is 11"
assert update_func1(0.0, 0, s) == 0, "No people, no growth"
```

```run
title: Proportional growth vs data
def run_simulation(system, update_func):
    results = TimeSeries()
    results[system.t_0] = system.p_0
    for t in linrange(system.t_0, system.t_end):
        results[t + 1] = update_func(results[t], t, system)
    return results

def update_func1(pop, t, system):
    return pop + system.alpha * pop

system = System(t_0=1950, t_end=2016, p_0=census[1950], alpha=0.017)
results = run_simulation(system, update_func1)
plot(census, "o", label="US Census")
plot(results, color="gray", label="proportional growth, alpha = 0.017")
decorate(xlabel="Year", ylabel="World population (billion)")
print("model in 2016:", round(results[2016], 2), "  data:", census[2016])
```

Change `alpha`. Can you find a value that fits the whole curve? (You can't: proportional growth is exponential, and it bends the wrong way after about 1990.)

## Birth and death

Writing alpha as one number hides two processes. So we split it into a birth rate and a death rate.

```exercise
title: Births and deaths
kind: write
---prompt
Write `update_func2(pop, t, system)` using `system.birth_rate` and `system.death_rate` (both per person per year).
---starter
def update_func2(pop, t, system):
    pass
---solution
def update_func2(pop, t, system):
    births = system.birth_rate * pop
    deaths = system.death_rate * pop
    return pop + births - deaths
---tests
s = System(birth_rate=0.03, death_rate=0.01)
assert abs(update_func2(100.0, 0, s) - 102.0) < 1e-9, "3 born, 1 dies per 100: 102"
assert abs(update_func2(50.0, 0, System(birth_rate=0.01, death_rate=0.01)) - 50.0) < 1e-9, "Equal rates: no change"
```

```quiz
Proportional growth with a constant alpha > 0 produces which shape over a long time?
- A straight line
* Exponential growth that keeps accelerating
- A curve that levels off
- A cycle
> Growth proportional to size compounds: each year's increase is bigger than the last. Real population growth has slowed since the 1960s, so the model must change; chapter 7 adds crowding.
```

```recall
Q: Why do we factor out the update function from run_simulation?
A: - The loop (start at p_0, step year by year, store results) is the same for every model; only the rule for next year changes.
- Passing the rule as an argument lets one run_simulation work for constant, proportional and quadratic growth, so you can swap models without rewriting the loop and compare them fairly.
```

## Real-world project: forecast an app's active users

Proportional growth with births and deaths isn't only for people. A subscription app grows the same way: existing users invite friends (new users **proportional** to current users), and every month some fraction cancels (losses proportional too). Add a fixed number of sign-ups from advertising and you have a model that a startup really uses to plan servers and staff.

```project
title: Monthly active users for a language-learning app
client: A small startup deciding when to hire a second support person
skills: System objects, update functions, run_simulation, comparing scenarios
---brief
The app has 2,000 users. Each month, referrals bring in 6% of current users, advertising brings in a flat 300, and 8% of users cancel. Build an update function for this, run it for 24 months with one `run_simulation`, and find the **first month** the app passes 5,000 users (when support needs a second person).
---why
Growth dashboards in real companies are built on exactly this split: an inflow proportional to size (word of mouth), a constant inflow (marketing), and an outflow proportional to size (churn). Factoring out the update function means product managers can swap in "what if we cut churn to 5%?" without touching the simulation loop, the same design that lets you swap models in this chapter.
---milestones
- Put every parameter (start users, referral rate, ad sign-ups, churn) in a `System`
- Write `update_users(users, t, system)` using all three flows
- Run 24 months with the shared `run_simulation` and plot it
- Write `months_to_target(system, target)` that returns the first month over the target
- Compare scenarios: twice the ad budget vs. cutting churn to 5%. Which reaches 5,000 sooner?
---stretch
- Find the long-run user count (the equilibrium) when churn is bigger than referrals
- Make advertising stop after month 12 by checking `t` inside the update function
- Turn monthly users into monthly revenue and server costs
```

```exercise
title: update_users with referrals, ads and churn
kind: write
---prompt
Write `update_users(users, t, system)`. Next month's users = users + referrals + ad sign-ups − cancellations, where referrals are `system.referral_rate * users`, ad sign-ups are `system.ads` (a fixed number), and cancellations are `system.churn * users`.
---starter
def update_users(users, t, system):
    return users
---solution
def update_users(users, t, system):
    referrals = system.referral_rate * users
    cancels = system.churn * users
    return users + referrals + system.ads - cancels
---tests
s = System(referral_rate=0.06, ads=300, churn=0.08)
assert abs(update_users(2000.0, 0, s) - 2260.0) < 1e-9, f"2000 + 120 + 300 - 160 = 2260, got {update_users(2000.0, 0, s)}"
assert abs(update_users(0.0, 0, s) - 300.0) < 1e-9, "With no users, only advertising brings people in"
assert abs(update_users(15000.0, 0, s) - 15000.0) < 1e-9, "At 15,000 users the inflow and outflow balance: no change"
```

```exercise
title: months_to_target
kind: write
---prompt
Write `months_to_target(system, update_func, target)`: run the simulation with the provided `run_simulation(system, update_func)` and return the first time label whose value is **at least** `target`, or `None` if it never gets there before `system.t_end`.
---setup
def run_simulation(system, update_func):
    results = TimeSeries()
    results[system.t_0] = system.p_0
    for t in linrange(system.t_0, system.t_end):
        results[t + 1] = update_func(results[t], t, system)
    return results

def update_users(users, t, system):
    return users + system.referral_rate * users + system.ads - system.churn * users
---starter
def months_to_target(system, update_func, target):
    results = run_simulation(system, update_func)
    return None
---solution
def months_to_target(system, update_func, target):
    results = run_simulation(system, update_func)
    for month, users in results.items():
        if users >= target:
            return month
    return None
---tests
s = System(t_0=0, t_end=24, p_0=2000.0, referral_rate=0.06, ads=300, churn=0.08)
m = months_to_target(s, update_users, 5000)
assert m == 13, f"With these numbers the app passes 5,000 users in month 13, got {m}"
assert months_to_target(s.set(churn=0.05), update_users, 5000) < m, "Lower churn should reach the target sooner"
assert months_to_target(s, update_users, 20000) is None, "20,000 is above the equilibrium of 15,000: never reached"
assert months_to_target(s, update_users, 1000) == 0, "Already over 1,000 at the start: month 0"
```
