## The system

Olin College and Wellesley College share a small bike system. People ride bikes between the two campuses. The question that drives the next three chapters: **how many bikes should be at each station** so riders rarely find one empty?

The model's **state** is the number of bikes at each station. ModSim's `State` object holds named state variables you can read and change as attributes.

```run
title: A State object
bikeshare = State(olin=10, wellesley=2)
print(bikeshare)
print("bikes at Olin:", bikeshare.olin)
bikeshare.olin -= 1
bikeshare.wellesley += 1
print("after one ride:", bikeshare.olin, bikeshare.wellesley)
```

```predict
bikeshare = State(olin=10, wellesley=2)
bikeshare.olin -= 3
bikeshare.wellesley = bikeshare.wellesley + 3
print(bikeshare.olin, bikeshare.wellesley)
print(bikeshare.olin + bikeshare.wellesley)
```

## Functions: one ride each way

```exercise
title: bike_to_wellesley and bike_to_olin
kind: write
---prompt
Write the two functions. Each takes the state, moves one bike, and returns nothing (it changes the state in place).
---starter
def bike_to_wellesley(state):
    pass

def bike_to_olin(state):
    pass
---solution
def bike_to_wellesley(state):
    state.olin -= 1
    state.wellesley += 1

def bike_to_olin(state):
    state.wellesley -= 1
    state.olin += 1
---tests
s = State(olin=10, wellesley=2)
bike_to_wellesley(s)
assert (s.olin, s.wellesley) == (9, 3), f"After one ride to Wellesley: (9, 3), got {(s.olin, s.wellesley)}"
bike_to_olin(s); bike_to_olin(s)
assert (s.olin, s.wellesley) == (11, 1), "Two rides back to Olin: (11, 1)"
```

## Randomness: customers arrive by chance

We don't know when people will want a bike, so the model uses probabilities. Each minute, a customer arrives at Olin with probability `p1` and at Wellesley with probability `p2`. ModSim's `flip(p)` returns True with probability p.

```run
title: flip
results = [flip(0.7) for i in range(20)]
print(results)
print("fraction True:", sum(results) / len(results))
```

```exercise
title: step
kind: fill
---prompt
Fill in the `if` statements so `step` simulates one minute: with probability `p1` a bike goes to Wellesley, and with probability `p2` a bike goes to Olin. The two ride functions are defined.
---setup
def bike_to_wellesley(state):
    state.olin -= 1
    state.wellesley += 1

def bike_to_olin(state):
    state.wellesley -= 1
    state.olin += 1
---starter
def step(state, p1, p2):
    if ____:
        bike_to_wellesley(state)
    if ____:
        bike_to_olin(state)
---solution
def step(state, p1, p2):
    if flip(p1):
        bike_to_wellesley(state)
    if flip(p2):
        bike_to_olin(state)
---tests
s = State(olin=10, wellesley=2)
step(s, 1, 0)
assert (s.olin, s.wellesley) == (9, 3), "p1 = 1, p2 = 0: one bike must go to Wellesley"
step(s, 0, 1)
assert (s.olin, s.wellesley) == (10, 2), "p1 = 0, p2 = 1: one bike back to Olin"
step(s, 0, 0)
assert (s.olin, s.wellesley) == (10, 2), "p = 0: nothing happens"
---show
bikeshare = State(olin=10, wellesley=2)
olin, wellesley = TimeSeries(), TimeSeries()
for i in range(60):
    step(bikeshare, 0.4, 0.2)
    olin[i], wellesley[i] = bikeshare.olin, bikeshare.wellesley
plot(olin, label="Olin"); plot(wellesley, label="Wellesley")
decorate(title="An hour of rides, driven by your step()", xlabel="Time step (min)", ylabel="Number of bikes")
```

## Run it and record the results

A `for` loop runs `step` once per minute. To plot what happened, store the state after each minute in a `TimeSeries`, which maps a time to a value.

```parsons

---lines
bikeshare = State(olin=10, wellesley=2)
results = TimeSeries()
results[0] = bikeshare.olin
for i in range(60):
    step(bikeshare, 0.3, 0.2)
    results[i + 1] = bikeshare.olin
?? results = bikeshare.olin
---setup
def step(state, p1, p2):
    if flip(p1):
        state.olin -= 1; state.wellesley += 1
    if flip(p2):
        state.wellesley -= 1; state.olin += 1
---tests
assert len(results) == 61 and results[0] == 10
```

```run
    if flip(p1):
        state.olin -= 1; state.wellesley += 1
    if flip(p2):
        state.wellesley -= 1; state.olin += 1

```

Run it a few times: each run is different. Then set `p1 = 0.6`. What goes wrong?

```quiz
With p1 = 0.6 and p2 = 0.2, the plot can dip below zero. What does that tell you?
- More bikes appeared
* The model allows impossible states: it lets people take bikes from an empty station
- The plot is broken
- flip is not random enough
> Real stations can't have −2 bikes. The model needs a rule: if a station is empty, the customer leaves without a bike. Chapter 3 adds that check and counts the unhappy customers.
```

```recall
- Randomness: `flip(p)` decides each minute whether a customer arrives, so every run differs.
```

## Real-world project: a scooter rebalancing schedule

Bike and scooter companies really do run this model. Every morning commuters ride from the suburbs into downtown, and every evening they ride back, so scooters pile up in one place and run out in the other. A van drives around at night moving them back. The company's question is our question: **how many should be in each zone at the start of the day?**

```project
title: Overnight rebalancing plan for an e-scooter fleet
client: A scooter-sharing startup with two zones, Downtown and Riverside
skills: State objects, functions, for loops, TimeSeries
---brief
The company has hourly ride counts for a typical weekday: how many scooters leave Downtown for Riverside and how many come back, hour by hour. Use them to simulate a day, record Downtown's stock in a TimeSeries, and work out the **smallest** number of scooters the van must leave Downtown overnight so neither zone ever runs out.
---why
This is real fleet-operations software: bike share (Citi Bike, Santander Cycles), scooter companies and car-sharing all run nightly rebalancing jobs. The same pattern, "replay the demand and find the lowest starting stock that never hits zero", is how shops set reorder levels and how cloud teams size a pool of servers before a busy period.
---milestones
- Write `run_day(state, moves)` that applies each hour's rides and records Downtown's stock
- Plot one day and spot the hour Downtown is emptiest
- Write `min_start(moves, total)`: the smallest overnight stock at Downtown that keeps both zones at 0 or above
- Turn it into a plan: "move N scooters to Downtown tonight"
- Re-run with a rainy-day demand list and compare the plans
---stretch
- Add a third zone and a van that can carry only 20 scooters per trip
- Use `flip` to make the demand random and find a start that works on 95% of simulated days
- Count how many rides you'd lose if the van skipped a night
```

```exercise
title: run_day for two zones
kind: write
---prompt
Write `run_day(state, moves)`. `state` is a `State(downtown=..., riverside=...)`. `moves` is a list of `(out, back)` pairs, one per hour: `out` scooters ride Downtown → Riverside, then `back` ride Riverside → Downtown. Change the state in place, and return a `TimeSeries` of Downtown's stock: index 0 holds the starting stock and index `h + 1` holds the stock after hour `h`.
---starter
def run_day(state, moves):
    results = TimeSeries()
    return results
---solution
def run_day(state, moves):
    results = TimeSeries()
    results[0] = state.downtown
    for h, (out, back) in enumerate(moves):
        state.downtown -= out
        state.riverside += out
        state.riverside -= back
        state.downtown += back
        results[h + 1] = state.downtown
    return results
---tests
s = State(downtown=10, riverside=5)
r = run_day(s, [(3, 1), (0, 4)])
assert len(r) == 3, f"Start plus one value per hour: 3 values, got {len(r)}"
assert r.tolist() == [10, 8, 12], f"Downtown: 10, then 10-3+1 = 8, then 8+4 = 12. Got {r.tolist()}"
assert (s.downtown, s.riverside) == (12, 3), "The state itself should end at 12 and 3"
assert s.downtown + s.riverside == 15, "Scooters are moved, never created or lost"
---hint
`for h, (out, back) in enumerate(moves):` gives you the hour number and the two counts at once.
```

```exercise
title: min_start for the van
kind: write
---prompt
Write `min_start(moves, total)`: the smallest number of scooters to leave at Downtown overnight (the other `total - start` go to Riverside) so that after **every** hour both zones have 0 or more. Try `start = 0, 1, 2, …, total` in order and return the first that works, or `None` if none does. `run_day` is provided.
---setup
def run_day(state, moves):
    results = TimeSeries()
    results[0] = state.downtown
    for h, (out, back) in enumerate(moves):
        state.downtown += back - out
        state.riverside += out - back
        results[h + 1] = state.downtown
    return results
---starter
def min_start(moves, total):
    for start in range(total + 1):
        pass
    return None
---solution
def min_start(moves, total):
    for start in range(total + 1):
        r = run_day(State(downtown=start, riverside=total - start), moves)
        if r.min() >= 0 and (total - r).min() >= 0:
            return start
    return None
---tests
morning = [(6, 1), (5, 0), (2, 3)]
assert min_start(morning, 20) == 10, f"Downtown drops by 5 then 5 more, so it needs at least 10. Got {min_start(morning, 20)}"
evening = [(0, 4), (1, 6)]
assert min_start(evening, 12) == 0, "When riders come back to Downtown, it can start empty"
assert min_start(evening, 8) is None, "Riverside needs 9 for the evening rush; with only 8 scooters no start works"
---hint
Riverside's stock at every hour is `total - downtown`, so `(total - r).min()` is its lowest point.
```
