## The problem

The case study: a small store has **two checkout counters**. Should customers form **one queue** that feeds both counters, or **two queues**, one per counter? Many stores have used two queues. Which gives shorter waits?

The model, one minute at a time: a customer arrives with probability λ (lambda) per minute; each busy counter finishes with probability μ (mu) per minute.

## One queue, one server first

Build the simplest version first: one queue, one server. The state is the number of customers in the system (waiting or being served).


## Little's law

How long does a customer wait? You can measure it without tracking individuals: **Little's law** says average number in system L = arrival rate λ × average time in system W. So W = L / λ.

```predict
L = 4.0
lam = 0.2
print(L / lam)
```

```run
title: Average time in system vs arrival rate
def update_func1(x, t, system):
    if x > 0 and flip(system.mu):
        x -= 1
    if flip(system.lam):
        x += 1
    return x

def run_simulation(system, update_func):
    x, total = 0, 0
    for t in range(system.duration):
        x = update_func(x, t, system)
        total += x
    return total / system.duration          # average number in system, L

lam_array = linspace(0.1, 0.6, 6)
sweep = SweepSeries()
for lam in lam_array:
    system = System(lam=lam, mu=0.8, duration=5000)
    sweep[lam] = run_simulation(system, update_func1) / lam    # Little's law: W = L / lambda
plot(sweep, "o-", label="one server, mu = 0.8")
decorate(xlabel="Arrival rate lambda (customers/min)", ylabel="Average time in system (min)")
```

```exercise
title: Two queues
kind: write
---prompt
Write `update_two_queues(state, t, system)` where `state` has `q1` and `q2` (customers at each counter). Each non-empty queue's counter finishes with probability `mu`. An arriving customer (probability `lam`) joins the **shorter** queue (q1 on a tie). Return the updated state.
---starter
def update_two_queues(state, t, system):
    pass
---solution
def update_two_queues(state, t, system):
    q1, q2 = state.q1, state.q2
    if q1 > 0 and flip(system.mu):
        q1 -= 1
    if q2 > 0 and flip(system.mu):
        q2 -= 1
    if flip(system.lam):
        if q1 <= q2:
            q1 += 1
        else:
            q2 += 1
    return State(q1=q1, q2=q2)
---tests
s = update_two_queues(State(q1=2, q2=1), 0, System(lam=0, mu=1))
assert (s.q1, s.q2) == (1, 0), "Both counters serve one customer"
s = update_two_queues(State(q1=3, q2=1), 0, System(lam=1, mu=0))
assert (s.q1, s.q2) == (3, 2), "The new customer joins the shorter queue"
s = update_two_queues(State(q1=1, q2=1), 0, System(lam=1, mu=0))
assert (s.q1, s.q2) == (2, 1), "Ties go to q1"
```

```run
title: One queue or two?
def update_one_queue(x, t, system):
    for i in range(min(x, 2)):
        if flip(system.mu):
            x -= 1
    if flip(system.lam):
        x += 1
    return x

def update_two_queues(state, t, system):
    q1, q2 = state.q1, state.q2
    if q1 > 0 and flip(system.mu): q1 -= 1
    if q2 > 0 and flip(system.mu): q2 -= 1
    if flip(system.lam):
        if q1 <= q2: q1 += 1
        else: q2 += 1
    return State(q1=q1, q2=q2)

def avg_time_one(system):
    x, total = 0, 0
    for t in range(system.duration):
        x = update_one_queue(x, t, system); total += x
    return total / system.duration / system.lam

def avg_time_two(system):
    s, total = State(q1=0, q2=0), 0
    for t in range(system.duration):
        s = update_two_queues(s, t, system); total += s.q1 + s.q2
    return total / system.duration / system.lam

one, two = SweepSeries(), SweepSeries()
for lam in linspace(0.2, 0.7, 6):
    system = System(lam=lam, mu=0.4, duration=10000)
    one[lam], two[lam] = avg_time_one(system), avg_time_two(system)
plot(one, "o-", label="one queue"); plot(two, "s-", label="two queues")
decorate(xlabel="Arrival rate lambda", ylabel="Average time in system (min)")
```

```quiz
The two curves are surprisingly close: one queue is at best slightly better. Why can two queues do almost as well in this model?
- The simulation is broken
* Arriving customers always join the shorter queue, which keeps the two lines balanced, so a counter rarely sits idle while the other line waits
- Two queues have more counters
- One queue is actually worse
> The advantage of one shared line is that no counter ever idles while someone is waiting. Joining the shorter line gets most of that benefit. Real customers can't see who will be slow and don't always choose well; the challenge below tests that.
```

```recall
Q: Explain Little's law and how the case study uses it.
A: - L = λ·W: the average number in the system equals the arrival rate times the average time each customer spends there.
- The simulation tracks only the number in the system each minute, so averaging that gives L, and W = L/λ gives the average wait without tracking individual customers.
```

## Real-world project: how many checkout lanes?

Queues are everywhere software meets people: support chats, call centres, web servers, hospital triage. The question is always the same: how many servers do we need so the wait stays acceptable, without paying for idle staff?

```project
title: Checkout-lane planner for a supermarket
client: A supermarket manager staffing tills for the Saturday rush
skills: queue simulation, Little's law, sweeping a design parameter, seeds for fair comparisons
---brief
On Saturday mornings about 1.5 customers arrive per minute and a cashier finishes a customer with probability 0.5 each minute. The manager wants the **fewest open lanes** that keep the average time in the store's queue under 4 minutes. Simulate one shared queue with c cashiers, measure the average time with Little's law, and sweep c.
---why
This exact calculation staffs call centres, sizes server pools behind load balancers (a "server" is a worker thread), and sets the number of ambulances on shift. Engineers call it capacity planning; the maths is queueing theory, and when the formulas get hard, they simulate exactly like this. Using the same random seed for every design keeps the comparison fair.
---milestones
- Write `simulate_lanes(lam, mu, c, minutes, seed)` for one queue served by c cashiers
- Use Little's law to turn the average queue length into an average time
- Sweep c from 1 to 8 and plot time against lanes
- Write `min_lanes(lam, mu, max_time)`: the smallest c that meets the target
- Find how the answer changes if arrivals rise 20% on a holiday
---stretch
- Compare one shared queue against one queue per lane (from this chapter) at the same c
- Add a cost per cashier per hour and a cost per customer-minute waited; minimise the total
- Model an express lane for small baskets
```

```exercise
title: min_lanes
kind: write
---prompt
`simulate_lanes(lam, mu, c, minutes, seed)` is defined: it returns the average time in system (minutes) for one queue with `c` cashiers, using Little's law. Write `min_lanes(lam, mu, max_time, seed=0)`: try `c = 1, 2, …, 20` and return the first `c` whose average time is **at most** `max_time` (pass the same `seed` every time so designs are compared on the same customers). Return `None` if none of them do.
---setup
def simulate_lanes(lam, mu, c, minutes=4000, seed=0):
    rng = np.random.default_rng(seed)
    x, total = 0, 0
    for t in range(minutes):
        busy = min(x, c)
        x -= rng.binomial(busy, mu)
        x += rng.poisson(lam)
        total += x
    L = total / minutes
    return L / lam
---starter
def min_lanes(lam, mu, max_time, seed=0):
    return 1
---solution
def min_lanes(lam, mu, max_time, seed=0):
    for c in range(1, 21):
        if simulate_lanes(lam, mu, c, seed=seed) <= max_time:
            return c
    return None
---tests
c = min_lanes(1.5, 0.5, 4.0)
assert c is not None and c >= 4, f"3 cashiers can serve at most 1.5 a minute, exactly the arrival rate, so the queue explodes; you need at least 4. Got {c}"
assert simulate_lanes(1.5, 0.5, c) <= 4.0 and simulate_lanes(1.5, 0.5, c - 1) > 4.0, "c meets the target and one fewer doesn't"
assert min_lanes(0.2, 0.5, 10.0) == 1, "a quiet morning needs one cashier"
---hint
A plain `for c in range(1, 21):` loop that returns as soon as `simulate_lanes(...) <= max_time`.
---show
cs = range(3, 9)
times = [simulate_lanes(1.5, 0.5, c) for c in cs]
for c, w in zip(cs, times):
    print(f"{c} lanes: {w:6.1f} min")
plot(list(cs), times, "o-")
decorate(xlabel="open lanes", ylabel="average time in system (min)", title="Saturday rush: diminishing returns after the first few lanes")
```
