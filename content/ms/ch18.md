## Slope functions

Our update functions took an Euler step themselves, with a fixed dt. The next step hands that job to a proper **ODE solver**. You write only a **slope function**: given the state and time, return the derivatives. `run_ode_solver(system, slope_func)` chooses its own step sizes (smaller where things change fast) and returns a TimeFrame plus details.

```exercise
title: slope_func
kind: write
---prompt
Write `slope_func(state, t, system)` for the minimal model: return `dGdt, dXdt`. Don't take a step; just return the derivatives.
---starter
def slope_func(state, t, system):
    G, X = state
    pass
---solution
def slope_func(state, t, system):
    G, X = state
    k1, k2, k3 = system.k1, system.k2, system.k3
    I, Ib, Gb = system.I, system.Ib, system.Gb
    dGdt = -k1 * (G - Gb) - X * G
    dXdt = k3 * (I(t) - Ib) - k2 * X
    return dGdt, dXdt
---tests
s = System(k1=0.03, k2=0.02, k3=1e-5, Gb=92, Ib=11, I=lambda t: 111.0)
d = slope_func(State(G=292.0, X=0.001), 0, s)
assert abs(d[0] - (-6 - 0.292)) < 1e-9, f"dG/dt = -0.03*200 - 0.001*292 = -6.292, got {d[0]}"
assert abs(d[1] - (0.001 - 0.00002)) < 1e-12, "dX/dt = 1e-5*100 - 0.02*0.001"
```

```run
    G, X = state
    dGdt = -system.k1 * (G - system.Gb) - X * G
    dXdt = system.k3 * (system.I(t) - system.Ib) - system.k2 * X
    return dGdt, dXdt

system = System(init=State(G=290.0, X=0.0), k1=0.03, k2=0.02, k3=1e-5,

results, details = run_ode_solver(system, slope_func)
print(details.message, "| function evaluations:", details.nfev)
plot(results.G, label="run_ode_solver")
plot(glucose, "o", label="data (synthetic)")
```


```quiz
Why use an ODE solver instead of the Euler loop from chapter 17?
- Euler can't handle two state variables
* The solver adapts its step size and uses better methods, so it's more accurate for the same work, and you only write the derivatives
- The solver ignores the data
- Euler is always wrong
> Euler with a fixed dt has an error that shrinks only in proportion to dt. Adaptive solvers (scipy's RK45 here) take small steps where things change fast and big ones where they don't, and they control the error for you.
```

## Fitting the parameters

Where did k₁, k₂, k₃ and G₀ come from? We **fit** them: choose the values that make the model's G closest to the data. The standard measure is the sum of squared **errors** (model − data). `fit_leastsq(error_func, params, data)` searches for the parameters that minimise it.

```run
title: Fit, starting from a poor guess
def slope_func(state, t, system):
    G, X = state
    dGdt = -system.k1 * (G - system.Gb) - X * G
    dXdt = system.k3 * (system.I(t) - system.Ib) - system.k2 * X
    return dGdt, dXdt

def error_func(params, data):
    system = System(init=State(G=params.G0, X=0.0), k1=params.k1, k2=params.k2, k3=params.k3,
                    Gb=92, Ib=11, I=I, t_0=0, t_end=182)
    results, details = run_ode_solver(system, slope_func, t_eval=data.index)
    return results.G.values - data.values

data = glucose.iloc[1:]                       # skip t=0, before the injection
guess = Params(G0=250, k1=0.02, k2=0.03, k3=2e-5)
best, details = fit_leastsq(error_func, guess, data, x_scale=[100, 0.01, 0.01, 1e-5])
print(best)
print("data were generated with G0=290, k1=0.03, k2=0.02, k3=1e-5 (plus noise)")
system = System(init=State(G=best.G0, X=0.0), k1=best.k1, k2=best.k2, k3=best.k3, Gb=92, Ib=11, I=I, t_0=0, t_end=182)
results, _ = run_ode_solver(system, slope_func)
plot(results.G, label="fitted model"); plot(glucose, "o", label="data")
```

```recall
Q: What's the difference between an update function and a slope function, and how do you fit a model's parameters?
A: - An update function computes the next state itself (e.g. an Euler step with fixed dt). A slope function only returns derivatives; the ODE solver decides how to step.
- Fitting: write an error function returning model − data for given parameters; a least-squares optimiser (`fit_leastsq`) adjusts the parameters to minimise the sum of squared errors.
```

## Real-world project: an insulin what-if explorer (for learning only)

Once a model is fitted to a person's data, you can ask it **what if** questions that would be unsafe or slow to test for real: what if the body released twice as much insulin? Half as much? Medical researchers use fitted minimal models exactly this way to compare patients and treatments. You'll build a small what-if tool on top of the fitted model. It is an educational toy with synthetic data, **not** medical advice and not something to dose from.

```project
title: Insulin what-if explorer
client: A university physiology course that wants students to explore the minimal model
skills: slope functions, run_ode_solver, functions that return functions, scenario tables, safety flags
---brief
Students should move one slider, "insulin response × 0.5 … × 4", and see what happens to blood glucose after the test injection: how low does it dip, and how long until it's back near the fasting level? Any scenario that dips below 70 mg/dL gets a clear "low glucose" warning, because a what-if tool should make dangerous results impossible to miss.
---why
"Fit a model, then run scenarios" is how drug developers plan trials (in-silico patients), how diabetes researchers compare insulin sensitivity, and, outside medicine, how banks stress-test portfolios and how engineers run digital twins of machines. The scenario wrapper, flags and summary table you build here are the same shape in all of them.
---milestones
- Write `scaled_insulin(scale)`: a function of time that multiplies the insulin above basal
- Write `what_if(scale)`: run the fitted model with that insulin and summarise the result
- Report the lowest glucose and the minutes until glucose is within 20 mg/dL of basal
- Flag any scenario whose lowest glucose is below 70 mg/dL
- Print a scenario table for scales 0.5, 1, 2, 3 and plot the curves together
---stretch
- Let the student change k₃ (insulin sensitivity) instead of the insulin curve, and compare
- Use your fitted parameters from `fit_leastsq` instead of the published values
- Add the chapter 19 insulin-secretion model so insulin responds to glucose instead of being given
```

```exercise
    dGdt = -system.k1 * (G - system.Gb) - X * G
    dXdt = system.k3 * (system.I(t) - system.Ib) - system.k2 * X
```
