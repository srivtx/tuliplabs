## Two ways to write the same model

The proportional growth model as a **recurrence relation** (discrete steps):

x(n+1) = x(n) + α·x(n)

As a **differential equation** (continuous time), the change per unit time is proportional to x:

dx/dt = α·x

Its solution is **exponential growth**: x(t) = x₀·e^(αt). For the discrete version, x(n) = x₀·(1+α)ⁿ.

```predict
x0, alpha = 1.0, 0.1
x = x0
for n in range(3):
    x = x + alpha * x
print(round(x, 4))
print(round(x0 * (1 + alpha) ** 3, 4))
```

```exercise
title: Closed form vs loop
kind: write
---prompt
Write `growth_closed(x0, alpha, n)` returning x₀·(1+α)ⁿ, and `growth_loop(x0, alpha, n)` that applies `x = x + alpha * x` n times. The checks confirm they agree.
---starter
def growth_closed(x0, alpha, n):
    pass

def growth_loop(x0, alpha, n):
    pass
---solution
def growth_closed(x0, alpha, n):
    return x0 * (1 + alpha) ** n

def growth_loop(x0, alpha, n):
    x = x0
    for i in range(n):
        x = x + alpha * x
    return x
---tests
assert abs(growth_closed(2.0, 0.05, 30) - growth_loop(2.0, 0.05, 30)) < 1e-9, "Both should give the same answer"
assert abs(growth_closed(1.0, 1.0, 10) - 1024) < 1e-9, "Doubling 10 times: 1024"
```

## Analysis vs simulation

Why bother with math if a loop gives the answer? The answer: analysis gives you **insight and speed**. The closed form tells you how the answer depends on every parameter at once (doubling time = ln 2 / α, for example), and evaluating it is instant, even for t = 10⁶. Simulation handles models that have no closed form. Good modelers use both, and check one against the other.

## The logistic solution

The quadratic model as a differential equation is the **logistic equation**: dx/dt = r·x·(1 − x/K), where K is the carrying capacity. Unlike most nonlinear equations, it has a closed-form solution:

x(t) = K / (1 + A·e^(−rt)),  with A = (K − x₀)/x₀

```exercise
title: Logistic closed form
kind: write
---prompt
Write `logistic(t, x0, r, K)` using the formula above.
---starter
def logistic(t, x0, r, K):
    pass
---solution
def logistic(t, x0, r, K):
    A = (K - x0) / x0
    return K / (1 + A * exp(-r * t))
---tests
assert abs(logistic(0, 2.5, 0.025, 13.9) - 2.5) < 1e-9, "At t = 0 it must equal x0"
assert abs(logistic(2000, 2.5, 0.025, 13.9) - 13.9) < 1e-6, "Long run: approaches K"
assert abs(logistic(10, 5.0, 0.1, 10.0) - 10 / (1 + exp(-1))) < 1e-9, "Starting at K/2: x(t) = K/(1+e^(-rt))"
```

```exercise
def logistic(t, x0, r, K):

    return K / (1 + A * exp(-r * t))
---tests
assert abs(logistic(0, 2.5, 0.025, 13.9) - 2.5) < 1e-9, "At t = 0 it must equal x0"

---hint

```

```run
title: Closed form vs simulation
x0, r, K = 2.557, 0.025, 13.9
sim = TimeSeries(); sim[1950] = x0
for t in linrange(1950, 2100):
    sim[t + 1] = sim[t] + r * sim[t] * (1 - sim[t] / K)
ts = linspace(1950, 2100, 151)
A = (K - x0) / x0
plot(sim, "o", ms=2, label="simulation (yearly steps)")
plt.plot(ts, K / (1 + A * np.exp(-r * (ts - 1950))), label="logistic closed form")
decorate(xlabel="Year", ylabel="Population (billion)")
print("2100: simulation", round(sim[2100], 2), " closed form", round(K / (1 + A * np.exp(-r * 150)), 2))
```

```quiz
The simulation and the closed form are close but not identical. Why?
- The closed form is wrong
* The simulation takes one-year steps (a recurrence), while the closed form solves the continuous equation; smaller steps would bring them closer
- Random noise in the simulation
- Python rounding errors
> The yearly recurrence is an approximation to the differential equation. The difference is a discretization error, which shrinks as the time step shrinks.
```

## SymPy: let the computer do the algebra

SymPy works with **symbols** instead of numbers, so it can solve equations exactly. It's available on this page (it's included in the browser's Python); press Run to try it.

```run
title: Solve dx/dt = αx with SymPy
from sympy import symbols, Function, Eq, diff, dsolve
t, alpha = symbols("t alpha")
x = Function("x")
eq1 = Eq(diff(x(t), t), alpha * x(t))
print(eq1)
print(dsolve(eq1))
r, K = symbols("r K")
eq2 = Eq(diff(x(t), t), r * x(t) * (1 - x(t) / K))
print(dsolve(eq2))
```

`C1` is a constant you'd choose to match the initial condition. The logistic answer looks different from the formula above, but it's the same family of curves.

```recall
Q: When would you use analysis rather than simulation, and vice versa?
A: - Analysis (closed-form solutions) gives insight into how results depend on parameters, and is fast for any time or input, but only exists for some models.
- Simulation works for almost any model (nonlinear, random, complicated) but gives one numerical answer per run and less insight.
- Check one against the other when both are possible.
```

## Real-world project: when will the waiting list double?

A closed form turns "run the loop and see" into an instant answer you can put in a spreadsheet or a dashboard. That matters when someone asks the same question for a hundred products at once.

```project
title: Growth calculator for a subscription box company
client: The planning team of a meal-kit subscription company
skills: closed-form solutions, logarithms, the logistic curve, checking formulas against simulation
---brief
Subscribers grow logistically: fast at first, then slowing as the market saturates at a carrying capacity K. Planning wants one function: "starting from x0 subscribers, when do we reach the target?" Solve the logistic formula for t instead of looping, then check it against a step-by-step simulation so you trust it.
---why
Finance and operations teams constantly invert growth formulas: "when do we hit 1 million users?", "when does this loan double?", "how long until the warehouse is full?" A closed form answers instantly for any inputs, which is what makes it usable in dashboards and spreadsheets. Checking it against a simulation is how you catch algebra mistakes before the planning meeting does.
---milestones
- Write the logistic solution `x(t) = K / (1 + ((K - x0) / x0) * exp(-r t))` as a function
- Solve it for t to get `time_to_reach(x0, target, r, K)`
- Handle impossible targets (at or above K) by returning `None`
- Check the answer against a loop that steps the continuous model with tiny time steps
- Make a table: months to reach 25%, 50%, 75% and 90% of K
---stretch
- Fit r and K to a year of made-up monthly subscriber counts with `fit_leastsq`
- Compare with plain exponential growth: when do the two forecasts disagree by 10%?
- Use SymPy to solve the logistic equation for t symbolically
```

```exercise
title: time_to_reach
kind: write
---prompt
Write `time_to_reach(x0, target, r, K)`: the time at which the logistic curve starting at `x0` reaches `target`, from solving `target = K / (1 + ((K - x0) / x0) * exp(-r t))` for t. Return `None` if `target >= K` (the curve never gets there). Use `np.log`.
---starter
def time_to_reach(x0, target, r, K):
    return 0.0
---solution
def time_to_reach(x0, target, r, K):
    if target >= K:
        return None
    return np.log(target * (K - x0) / (x0 * (K - target))) / r
---tests
t = time_to_reach(100, 5000, 0.3, 10000)
assert abs(t - np.log(99) / 0.3) < 1e-9, f"halfway to K from 100 takes ln(99)/r = {np.log(99) / 0.3:.3f}; got {t}"
assert time_to_reach(100, 10000, 0.3, 10000) is None, "the curve only approaches K, it never reaches it"
x, tt, dt = 100.0, 0.0, 0.001
while x < 2000:
    x += 0.3 * x * (1 - x / 10000) * dt
    tt += dt
assert abs(time_to_reach(100, 2000, 0.3, 10000) - tt) < 0.01, "the formula agrees with a fine-step simulation"
---hint
Rearrange: `(K - x0)/x0 * exp(-r t) = K/target - 1`, take logs, and solve for t.
```
