```prelude
from modsim import *

def update_func(state, t, system):
    T = state.T
    return State(T=T - system.r * (T - system.T_env) * system.dt)

def make_system(T_init, r, volume, t_end):
    return System(init=State(T=T_init), r=r, volume=volume, T_env=22, t_0=0, t_end=t_end, dt=1)

def run_simulation(system, update_func):
    frame = TimeFrame(columns=system.init.index)
    frame.row[system.t_0] = system.init
    for t in linrange(system.t_0, system.t_end, system.dt):
        frame.row[t + system.dt] = update_func(frame.row[t], t, system)
    return frame
```

## Finding roots

A **root** of a function is an input where it returns 0. Many "find the parameter" problems become root problems: write an **error function** that returns model minus measurement, and find where it's zero. `root_bisect(func, [low, high])` searches the bracket by repeatedly halving it.

```predict
def func(x):
    return (x - 1) * (x - 2) * (x - 3)

res = root_bisect(func, [1.5, 2.5])
print(round(res.root, 6))
```

## Mixing liquids

When you pour two liquids together, heat lost by the hot one equals heat gained by the cold one. With the same specific heat, the mixture's temperature is the **volume-weighted average**:

T_mix = (V₁·T₁ + V₂·T₂) / (V₁ + V₂)

```exercise
title: mix
kind: write
---prompt
Write `mix(system1, system2)` returning a new system for the mixture: volume `V1 + V2`, temperature as above (read each system's temperature from `system.init.T`), with `r` and `t_end` taken from `system1`. Use `make_system`.
---starter
def mix(system1, system2):
    pass
---solution
def mix(system1, system2):
    V1, V2 = system1.volume, system2.volume
    T1, T2 = system1.init.T, system2.init.T
    V_mix = V1 + V2
    T_mix = (V1 * T1 + V2 * T2) / V_mix
    return make_system(T_init=T_mix, r=system1.r, volume=V_mix, t_end=system1.t_end)
---tests
c = make_system(90, 0.0115, 300, 30); m = make_system(5, 0.13, 50, 15)
mx = mix(c, m)
assert abs(mx.volume - 350) < 1e-9, "Volumes add"
assert abs(mx.init.T - (300 * 90 + 50 * 5) / 350) < 1e-9, f"Expected {(300*90+50*5)/350:.2f}, got {mx.init.T}"
```

## Milk first or last?

The book's setup: coffee 300 mL at 90 °C (r ≈ 0.0115), milk 50 mL at 5 °C from the fridge, warming toward room temperature (r ≈ 0.13). You'll drink in 30 minutes.

```run
title: Compare the two orders
def mix(s1, s2):
    V = s1.volume + s2.volume
    T = (s1.volume * s1.init.T + s2.volume * s2.init.T) / V
    return make_system(T_init=T, r=s1.r, volume=V, t_end=s1.t_end)

def final_temp(system):
    return get_last_value(run_simulation(system, update_func).T)

r_coffee, r_milk = 0.0115, 0.13
# milk first: mix now, then let the mixture cool for 30 minutes
first = mix(make_system(90, r_coffee, 300, 30), make_system(5, r_milk, 50, 30))
T_first = final_temp(first)
# milk last: cool both separately for 30 minutes, then mix
coffee = make_system(final_temp(make_system(90, r_coffee, 300, 30)), r_coffee, 300, 0)
milk = make_system(final_temp(make_system(5, r_milk, 50, 30)), r_milk, 50, 0)
T_last = mix(coffee, milk).init.T
print(f"milk first: {T_first:.2f} C    milk last: {T_last:.2f} C")
```

```quiz
Why is adding the milk at the end the better choice for drinking hot coffee?
- Milk keeps heat in
* Cooling is fastest when the coffee is hottest; mixing late keeps the coffee hot during the fast-cooling period, and the cold milk warms up meanwhile
- The milk evaporates
- It doesn't matter; both orders give the same answer
> Newton's law makes hot coffee lose heat faster. Keeping it at 90 °C longer means more loss, but the cold milk also gains heat from the room while it waits, and with these parameters that wins. The answer depends on the numbers, which is why we simulate.
```

## Optimise the timing

```exercise
title: final temperature vs when you add the milk
kind: write
---prompt
Write `run_and_mix(t_add, t_total)`: cool the coffee (90 °C, r 0.0115, 300 mL) and the milk (5 °C, r 0.13, 50 mL) separately for `t_add` minutes, mix them, then cool the mixture for the remaining `t_total - t_add` minutes (using the coffee's r). Return the final temperature. `mix` and the simulation functions are defined.
---setup
def mix(s1, s2):
    V = s1.volume + s2.volume
    T = (s1.volume * s1.init.T + s2.volume * s2.init.T) / V
    return make_system(T_init=T, r=s1.r, volume=V, t_end=s1.t_end)
---starter
def run_and_mix(t_add, t_total):
    pass
---solution
def run_and_mix(t_add, t_total):
    coffee = make_system(90, 0.0115, 300, t_add)
    milk = make_system(5, 0.13, 50, t_add)
    T_c = get_last_value(run_simulation(coffee, update_func).T)
    T_m = get_last_value(run_simulation(milk, update_func).T)
    mixture = mix(make_system(T_c, 0.0115, 300, t_total - t_add), make_system(T_m, 0.13, 50, 0))
    return get_last_value(run_simulation(mixture, update_func).T)
---tests
early, late = run_and_mix(0, 30), run_and_mix(30, 30)
assert late > early, f"Adding at the end should be warmer: {late:.2f} vs {early:.2f}"
assert abs(late - 62.2) < 1.5, f"Adding the milk at 30 min gives about 62 C, got {late:.2f}"
```

## Analysis: the exact solution

Newton's law has a closed-form solution: T(t) = T_env + (T₀ − T_env)·e^(−rt). The simulation with dt = 1 is an approximation to it.

```run
title: Simulation vs exact
system = make_system(90, 0.0115, 300, 30)
sim = run_simulation(system, update_func)
ts = linspace(0, 30, 31)
exact = 22 + (90 - 22) * np.exp(-0.0115 * ts)
plot(sim.T, "o", ms=3, label="simulation, dt = 1")
plt.plot(ts, exact, label="exact solution")
decorate(xlabel="Time (minutes)", ylabel="Temperature (C)")
print("max difference:", round(np.max(np.abs(sim.T.values - exact)), 4), "C")
```

- Find a bracket where the error changes sign.
- Use a root finder (`root_bisect`) to find the parameter where the error is zero. For the coffee: r ≈ 0.0115 per minute gives 70 °C after 30 minutes.
