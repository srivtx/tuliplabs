```prelude
from modsim import *

def update_func(state, t, system):
    T = state.T
    return State(T=T - system.r * (T - system.T_env) * system.dt)

def make_system(T_init, r, volume, t_end):
    return System(init=State(T=T_init), r=r, volume=volume, T_env=22, t_0=0, t_end=t_end, dt=1)

def run_simulation(system, update_func):
    frame = TimeFrame(columns=system.init.index)
    frame.row[system.t_0] = system.init
    for t in linrange(system.t_0, system.t_end, system.dt):
        frame.row[t + system.dt] = update_func(frame.row[t], t, system)
    return frame
```

## Finding roots

A **root** of a function is an input where it returns 0. Many "find the parameter" problems become root problems: write an **error function** that returns model minus measurement, and find where it's zero. `root_bisect(func, [low, high])` searches the bracket by repeatedly halving it.

```predict
def func(x):
    return (x - 1) * (x - 2) * (x - 3)

res = root_bisect(func, [1.5, 2.5])
print(round(res.root, 6))
```

## Mixing liquids

When you pour two liquids together, heat lost by the hot one equals heat gained by the cold one. With the same specific heat, the mixture's temperature is the **volume-weighted average**:

T_mix = (V₁·T₁ + V₂·T₂) / (V₁ + V₂)

```exercise
title: mix
kind: write
---prompt
Write `mix(system1, system2)` returning a new system for the mixture: volume `V1 + V2`, temperature as above (read each system's temperature from `system.init.T`), with `r` and `t_end` taken from `system1`. Use `make_system`.
---starter
def mix(system1, system2):
    pass
---solution
def mix(system1, system2):
    V1, V2 = system1.volume, system2.volume
    T1, T2 = system1.init.T, system2.init.T
    V_mix = V1 + V2
    T_mix = (V1 * T1 + V2 * T2) / V_mix
    return make_system(T_init=T_mix, r=system1.r, volume=V_mix, t_end=system1.t_end)
---tests
c = make_system(90, 0.0115, 300, 30); m = make_system(5, 0.13, 50, 15)
mx = mix(c, m)
assert abs(mx.volume - 350) < 1e-9, "Volumes add"
assert abs(mx.init.T - (300 * 90 + 50 * 5) / 350) < 1e-9, f"Expected {(300*90+50*5)/350:.2f}, got {mx.init.T}"
```

## Milk first or last?

The setup: coffee 300 mL at 90 °C (r ≈ 0.0115), milk 50 mL at 5 °C from the fridge, warming toward room temperature (r ≈ 0.13). You'll drink in 30 minutes.

```run
title: Compare the two orders
def mix(s1, s2):
    V = s1.volume + s2.volume
    T = (s1.volume * s1.init.T + s2.volume * s2.init.T) / V
    return make_system(T_init=T, r=s1.r, volume=V, t_end=s1.t_end)

def final_temp(system):
    return get_last_value(run_simulation(system, update_func).T)

r_coffee, r_milk = 0.0115, 0.13
# milk first: mix now, then let the mixture cool for 30 minutes
first = mix(make_system(90, r_coffee, 300, 30), make_system(5, r_milk, 50, 30))
T_first = final_temp(first)
# milk last: cool both separately for 30 minutes, then mix
coffee = make_system(final_temp(make_system(90, r_coffee, 300, 30)), r_coffee, 300, 0)
milk = make_system(final_temp(make_system(5, r_milk, 50, 30)), r_milk, 50, 0)
T_last = mix(coffee, milk).init.T
print(f"milk first: {T_first:.2f} C    milk last: {T_last:.2f} C")
```

```quiz
Why is adding the milk at the end the better choice for drinking hot coffee?
- Milk keeps heat in
* Cooling is fastest when the coffee is hottest; mixing late keeps the coffee hot during the fast-cooling period, and the cold milk warms up meanwhile
- The milk evaporates
- It doesn't matter; both orders give the same answer
> Newton's law makes hot coffee lose heat faster. Keeping it at 90 °C longer means more loss, but the cold milk also gains heat from the room while it waits, and with these parameters that wins. The answer depends on the numbers, which is why we simulate.
```

## Analysis: the exact solution

Newton's law has a closed-form solution: T(t) = T_env + (T₀ − T_env)·e^(−rt). The simulation with dt = 1 is an approximation to it.

```run
title: Simulation vs exact
system = make_system(90, 0.0115, 300, 30)
sim = run_simulation(system, update_func)
ts = linspace(0, 30, 31)
exact = 22 + (90 - 22) * np.exp(-0.0115 * ts)
plot(sim.T, "o", ms=3, label="simulation, dt = 1")
plt.plot(ts, exact, label="exact solution")
decorate(xlabel="Time (minutes)", ylabel="Temperature (C)")
print("max difference:", round(np.max(np.abs(sim.T.values - exact)), 4), "C")
```

```recall
- Find a bracket where the error changes sign.
- Use a root finder (`root_bisect`) to find the parameter where the error is zero. For the coffee: r ≈ 0.0115 per minute gives 70 °C after 30 minutes.
```

## Real-world project: "ready to drink" alerts for a smart mug

You just used a root finder to pull r out of one measurement. That's the core of any device that **learns** how fast something cools: measure twice, fit r, then predict the future. A smart mug can do it in the first few minutes and tell you when your drink hits the temperature you like.

```project
title: Smart-mug drink-ready predictor
client: A start-up making a temperature-sensing travel mug and its phone app
skills: error functions, root_bisect, simulation loops, turning a model into a product feature
---brief
The mug's sensor reads the drink when it's poured and again a few minutes later. Every cup, lid and drink is different, so r must be fitted per cup. Then the app shows "ready in 7 minutes" for the user's favourite drinking temperature, and an option to add cold milk now to drink it sooner.
---why
"Fit a rate from early readings, then predict when a threshold is crossed" runs inside smart thermostats (when will the room reach 21 °C?), oven probes (when is the roast done?), phone batteries (time to full charge) and server monitoring (when will this disk be full?). The model is tiny; the product value is in fitting it live to each user's situation.
---milestones
- Write `fit_r(T_start, T_seen, minutes)` that finds r with `root_bisect` from two readings
- Write `minutes_until(T_start, r, T_drink)` that steps the model until the drink is cool enough
- Combine them: two readings in, "ready in N minutes" out
- Use chapter 16's `mix` to answer "how much milk makes it drinkable right now?"
- Refit r when a third reading arrives and show how the estimate changes
---stretch
- Fit r with `fit_leastsq` from many noisy readings instead of two exact ones
- Warn the user when the drink will be too cold within 10 minutes
- Model the lid on vs off as two r values and suggest which to use
```

```exercise
title: fit_r from two readings
kind: write
---prompt
Write `fit_r(T_start, T_seen, minutes)`: the r for which a drink starting at `T_start` reads `T_seen` after `minutes`. Write an error function of r that builds a system with `make_system(T_start, r, 300, minutes)`, runs it with `run_simulation(system, update_func)` and returns final temperature minus `T_seen`; then return `root_bisect(error, [0.0001, 0.5]).root`. ---starter
def fit_r(T_start, T_seen, minutes):
    return 0.0115
---solution
def fit_r(T_start, T_seen, minutes):
    def error(r):
        system = make_system(T_start, r, 300, minutes)
        results = run_simulation(system, update_func)
        return get_last_value(results.T) - T_seen
    return root_bisect(error, [0.0001, 0.5]).root
---tests

assert abs(r2 - 0.01714) < 2e-4, f"A cup that drops 85 -> 75 C in 10 min cools faster: r about 0.0171, got {r2:.5f}"
---hint
This is the chapter's `error_func` with the numbers turned into parameters. The inner function can see `T_start`, `T_seen` and `minutes` because it's defined inside `fit_r`.
```

```exercise
title: minutes_until drinkable
kind: write
---prompt
Write `minutes_until(T_start, r, T_drink, T_env=22)`: step Newton's law one minute at a time from `T_start` until the temperature is at or below `T_drink`, and return the number of minutes. If it's already cool enough, return 0.
---starter
def minutes_until(T_start, r, T_drink, T_env=22):
    pass
---solution
def minutes_until(T_start, r, T_drink, T_env=22):
    T, minutes = T_start, 0
    while T > T_drink:
        T = T - r * (T - T_env)
        minutes += 1
    return minutes
---tests
assert minutes_until(90, 0.0115, 60) == 51, f"The reference coffee needs 51 minutes to reach 60 C, got {minutes_until(90, 0.0115, 60)}"
assert minutes_until(55, 0.0115, 60) == 0, "Already below 60 C: ready now"
assert minutes_until(90, 0.03, 60) < minutes_until(90, 0.0115, 60), "A faster-cooling cup is ready sooner"
---show
r = fit_r(88, 80, 5) if "fit_r" in dir() else 0.0225
print(f"Readings 88 C then 80 C five minutes later -> r = {r:.4f}")
for T_drink in [70, 65, 60]:
    print(f"  ready for {T_drink} C in {minutes_until(80, r, T_drink)} more minutes")
```
