## The coffee cooling problem

You order coffee and a little cup of cold milk. You want to drink it in a few minutes, as hot as possible. Should you add the milk **now** or **just before drinking**? This chapter builds the cooling model; chapter 16 answers the question.

## Temperature and heat

**Heat** is energy; **temperature** measures how hot something is. Adding heat Q to a mass m raises its temperature by ΔT = Q / (m·c), where c is the **specific heat capacity** (for water, about 4.2 J/g/°C). Heat moves by **conduction** (through the cup), **convection** (air carrying it away) and **radiation**.

```predict
m, c = 300, 4.2          # grams, J/g/degC
Q = -m * c * 20          # heat lost when 300 g of water cools by 20 degC
print(Q)
print(Q / (m * c))
```

## Newton's law of cooling

All three mechanisms are complicated, so we use a simple empirical law: the rate of cooling is proportional to the **difference** between the object's temperature and its environment:

dT/dt = −r·(T − T_env)

r depends on the cup, the liquid and the air; we'll estimate it from a measurement.

```exercise
---prompt
Write `update_func(state, t, system)`: read `T = state.T`, compute the change `-system.r * (T - system.T_env) * system.dt`, and return `State(T=T + change)`.
---starter

---solution
def update_func(state, t, system):
    T = state.T
    dT = -system.r * (T - system.T_env) * system.dt
    return State(T=T + dT)
---tests
```

```recall
Q: State Newton's law of cooling and explain how it becomes an update function.
A: - dT/dt = −r(T − T_env): cooling rate proportional to the temperature difference with the surroundings.
```

## Real-world project: a food-safety cooling checker for a restaurant

Newton's law isn't only for coffee. Restaurant kitchens cook big pots of soup and stock, and food-safety rules say hot food must cool **fast**, because bacteria grow quickly in the warm middle range. The rule used in many food codes: from 57 °C down to 21 °C within **2 hours**, and down to 5 °C within **6 hours** in total. Your cooling model can predict whether a pot will pass before anyone waits six hours to find out.

```project
title: Kitchen cooling-rule checker
client: A restaurant kitchen that cooks 20-litre pots of stock every night
skills: update functions, time steps, loops with a stopping condition, None for "never"
---brief
The chef puts a pot of stock at 57 °C into the walk-in fridge (2 °C). A big pot cools slowly (small r); split into shallow pans or set in an ice bath it cools faster (bigger r). Build a checker: given r and the fridge temperature, does the food pass the two-stage rule? If not, how much faster must it cool?
---why
Food-safety software for restaurant chains (digital HACCP logs) does exactly this: wireless probes record temperatures, and the app predicts whether a batch will meet the cooling deadline so staff can switch to an ice bath before it fails, not after. The pattern "simulate until a threshold, report the time, or report never" is also how battery apps estimate time to empty and how servers estimate time until a disk fills.
---milestones
- Write `time_to_cool(T_init, T_target, r, T_env)` that steps Newton's law until the food reaches the target
- Return `None` when the target can never be reached (fridge warmer than the target)
- Write `passes_cooling_rule(r, T_env)` for the two-stage rule
- Find the smallest r that passes, by trying values in a loop
- Print advice: "pass", or "use shallow pans: you need r of at least …"
---stretch
- Fit r for a real pot from two thermometer readings (chapter 16 shows how)
- Plot the cooling curve with the two deadlines drawn as boxes
- Model an ice bath as a colder T_env and compare it with a bigger r
```

```exercise
title: time_to_cool
kind: write
---prompt
Write `time_to_cool(T_init, T_target, r, T_env, dt=1, t_max=1440)`. Start at `T_init` and time 0; while the temperature is above `T_target`, take one Newton's-law step (`T - r * (T - T_env) * dt`) and add `dt` to the time. Return the time (minutes) when it first reaches the target. If the time passes `t_max` first, return `None`.
---starter
def time_to_cool(T_init, T_target, r, T_env, dt=1, t_max=1440):
    T, t = T_init, 0
    return t
---solution
def time_to_cool(T_init, T_target, r, T_env, dt=1, t_max=1440):
    T, t = T_init, 0
    while T > T_target:
        if t >= t_max:
            return None
        T = T - r * (T - T_env) * dt
        t += dt
    return t
---tests
assert time_to_cool(57, 21, 0.01, 2) == 106, f"r = 0.01 in a 2 C fridge: 57 -> 21 C takes 106 minutes, got {time_to_cool(57, 21, 0.01, 2)}"
assert time_to_cool(57, 21, 0.02, 2) == 53, "Twice the cooling rate, about half the time"
assert time_to_cool(57, 5, 0.02, 10) is None, "A 10 C fridge can never bring food down to 5 C: return None, don't loop forever"
assert time_to_cool(4, 5, 0.01, 2) == 0, "Already cold enough: zero minutes"
---hint
The `t_max` check is what stops the loop when the target is impossible: Newton's law only approaches T_env, it never passes it.
```
