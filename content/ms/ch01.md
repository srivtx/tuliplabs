## The falling penny myth

You may have heard that a penny dropped from the top of the Empire State Building would hit the sidewalk hard enough to kill someone. Is it true? The book answers in stages, and the stages *are* the lesson.

**Modeling** means choosing which details of the real world to keep and which to leave out (**abstraction**), working out what the model predicts (by **analysis** with math, or by **simulation** with a computer), and then checking the prediction against reality (**validation**). When the model fails, you go around again with a better one.

```quiz
Which step of the modeling loop checks whether a model's predictions agree with the real world?
- Abstraction
- Simulation
* Validation
- Analysis
> Validation compares results to measurements. Abstraction decides what to include; analysis and simulation produce the predictions.
```

## A first model: ignore the air

The simplest model: the penny falls with constant acceleration g = 9.8 m/s² and nothing slows it. The building is about h = 381 m tall. Kinematics gives

- time to fall: t = √(2h / g)
- speed at the bottom: v = √(2 g h)

```run
title: How fast, how long?
g = 9.8      # m/s**2
h = 381      # m
t = sqrt(2 * h / g)
v = sqrt(2 * g * h)
print(f"fall time: {t:.1f} s")
print(f"impact speed: {v:.1f} m/s  ({v * 3.6:.0f} km/h)")
```

```predict
g = 9.8
h = 0.5 * g * 2**2
print(h)
print(sqrt(2 * g * h))
```

## Validation: the answer is wrong

86 m/s is about 300 km/h, so a penny would be dangerous. But the real answer, from experiments, is that a falling penny reaches only about **18 m/s** and stings rather than kills. The model left out **air resistance**: once the penny is fast enough, drag balances gravity and it stops speeding up (its **terminal velocity**). You'll build that better model in chapter 21.

```quiz
The no-air model predicts 86 m/s; measurements say about 18 m/s. What's the right response?
- Trust the math; the experiments must be wrong
* Go back to abstraction and add the missing physics (drag), then check again
- Give up on modeling pennies
- Average the two numbers
> A failed validation tells you which simplification mattered. Here, ignoring air resistance was fine for a short drop but not for 381 m. Iterate: add drag, predict, validate again.
```

```exercise
title: Time to terminal speed
kind: fill
---prompt
A rough second model: the penny falls freely until it reaches its terminal speed of 18 m/s, then keeps that speed. Fill in the blanks to compute the total time to fall `h` metres.
---starter
def fall_with_terminal(h, v_term=18, g=9.8):
    t1 = v_term / g              # time to reach terminal speed
    h1 = ____                    # distance fallen in that time
    t2 = ____                    # time for the rest at constant speed
    return t1 + t2
---solution
def fall_with_terminal(h, v_term=18, g=9.8):
    t1 = v_term / g
    h1 = 0.5 * g * t1**2
    t2 = (h - h1) / v_term
    return t1 + t2
---tests
t = fall_with_terminal(381)
assert abs(t - 22.1) < 0.1, f"About 22 s for the Empire State Building, got {t:.2f}"
assert abs(fall_with_terminal(100, v_term=10, g=10) - 10.5) < 1e-9, "1 s to reach 10 m/s covering 5 m, then 95 m at 10 m/s"
---hint
Free fall from rest: distance = ½·g·t².
```

- Analysis/simulation: compute the prediction (86 m/s, 8.8 s).
- Validation: compare with measurements (about 18 m/s), find the model is wrong.

## Real-world project: a drop-zone safety check

The modeling loop isn't only for pennies. Building sites have to decide where people may walk below workers on scaffolding, and the question is the same one you just answered: how fast does a dropped object hit the ground? Your two models give two answers. The no-air model is the **cautious** one (it never underestimates), and the terminal-speed model is the **realistic** one, if you know the object's terminal speed.

```project
title: Drop-zone safety check for a building site
client: A construction company putting up a 12-storey block
skills: functions, tuples, min and max, choosing between two models
---brief
The site manager has a list of work platforms (heights in metres) and a list of tools that could fall, each with a measured terminal speed. Anything that hits the ground faster than **15 m/s** needs safety netting under that platform. Write the code that says, for every platform, how fast the worst tool lands and whether netting is required.
---why
Engineers do exactly this when they write safety rules: start with a simple model, check it against measurements, and choose the model that is safe enough for the decision. The same "simple bound first, better model later" habit shows up in capacity planning, timeouts in web servers ("assume the slowest case"), and any code that has to be safe before it is precise.
---milestones
- Write `impact_speed(h, v_term)`: free-fall speed, but never more than the terminal speed
- Check it: a low platform gives the free-fall answer, a high one gives the terminal speed
- Write `netting_plan(heights, terminal_speeds, limit)` that marks each platform as needing netting or not
- Print the plan as a table the site manager can read
- Compare: how many platforms would the no-air model have flagged?
---stretch
- Add the fall *time* to the table, so workers know how long a warning shout has
- Let each platform have its own list of tools instead of one shared list
- Plot impact speed against height for both models on one chart
```

```exercise
title: impact_speed with a terminal cap
kind: write
---prompt
Write `impact_speed(h, v_term, g=9.8)`: the speed at the bottom of a fall of `h` metres. Use the free-fall formula √(2·g·h), but an object can never go faster than its terminal speed `v_term`, so return whichever is **smaller**.
---starter
def impact_speed(h, v_term, g=9.8):
    pass
---solution
def impact_speed(h, v_term, g=9.8):
    v_free = sqrt(2 * g * h)
    return min(v_free, v_term)
---tests
assert impact_speed(5, 40) is not None, "Return the speed, don't print it"
assert abs(impact_speed(5, 40) - sqrt(98)) < 1e-9, f"5 m: free fall gives about 9.9 m/s, below the cap of 40. Got {impact_speed(5, 40)}"
assert impact_speed(381, 18) == 18, "The penny from the Empire State Building: capped at 18 m/s"
assert abs(impact_speed(10, 30, g=1.6) - sqrt(32)) < 1e-9, "Use the g you are given"
---hint
`min(a, b)` returns the smaller of two numbers.
```

```exercise
title: netting_plan
kind: write
---prompt
Write `netting_plan(heights, terminal_speeds, limit=15)`. For each platform height, find the **fastest** impact among all the tools (use `impact_speed`, which is provided). Return a list of `(height, speed, needs_net)` tuples, where `needs_net` is True when the speed is above `limit`.
---setup
def impact_speed(h, v_term, g=9.8):
    return min(sqrt(2 * g * h), v_term)
---starter
def netting_plan(heights, terminal_speeds, limit=15):
    plan = []
    return plan
---solution
def netting_plan(heights, terminal_speeds, limit=15):
    plan = []
    for h in heights:
        worst = max(impact_speed(h, v) for v in terminal_speeds)
        plan.append((h, worst, worst > limit))
    return plan
---tests
plan = netting_plan([2, 20], [9, 25])
assert len(plan) == 2, f"One row per platform, got {len(plan)}"
h, v, net = plan[0]
assert h == 2 and abs(v - sqrt(39.2)) < 1e-9 and not net, f"2 m: the worst tool lands at about 6.3 m/s, no net needed. Got {plan[0]}"
h, v, net = plan[1]
assert abs(v - sqrt(392)) < 1e-9 and net, f"20 m: the hammer (terminal 25) lands at about 19.8 m/s, net needed. Got {plan[1]}"
assert not netting_plan([50], [9, 12])[0][2], "Light tools capped below 15 m/s never need a net, even from high up"
---hint
For one height, `max(impact_speed(h, v) for v in terminal_speeds)` is the worst case.
```
