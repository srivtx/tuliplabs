## Vectors

In two dimensions, position, velocity and force have a **direction** as well as a size. ModSim's `Vector` holds components (`.x`, `.y`) and knows its magnitude (`.mag`), angle (`.angle`, in radians) and unit vector (`.hat()`, length 1 in the same direction).

```predict
v = Vector(3, 4)
print(v.mag)
print(v.hat())
print(v * 2 + Vector(1, 0))
```

```exercise

---starter

---solution
def launch_velocity(speed, angle_deg):
    theta = np.deg2rad(angle_deg)
    x, y = pol2cart(theta, speed)
    return Vector(x, y)
---tests
v = launch_velocity(40, 45)
assert abs(v.x - 28.284) < 1e-3 and abs(v.y - 28.284) < 1e-3, f"40 m/s at 45 degrees: about (28.28, 28.28), got {v}"
assert abs(launch_velocity(10, 90).x) < 1e-9 and abs(launch_velocity(10, 90).y - 10) < 1e-9, "Straight up"
```

## Drag in 2-D

Drag has the same size as before, ½ρv²C_dA, but now it points **opposite the velocity**: direction −V.hat(). Gravity points down: Vector(0, −g).

```exercise
title: drag_force
kind: write
---prompt
Write `drag_force(V, system)` returning a Vector: magnitude `rho * |V|**2 * C_d * area / 2`, direction opposite `V`.
---starter
def drag_force(V, system):
    pass
---solution
def drag_force(V, system):
    rho, C_d, area = system.rho, system.C_d, system.area
    mag = rho * V.mag**2 * C_d * area / 2
    direction = -V.hat()
    return direction * mag
---tests
s = System(rho=1.2, C_d=0.33, area=pi * 0.0365**2)
f = drag_force(Vector(30, 0), s)
assert f.x < 0 and abs(f.y) < 1e-12, "Moving right: drag points left"
assert abs(Vector(f).mag - 1.2 * 900 * 0.33 * pi * 0.0365**2 / 2) < 1e-9, "Magnitude is rho v^2 C_d A / 2"
```

## Fly the ball

The baseball: mass 145 g, diameter 73 mm, C_d ≈ 0.33, hit at 40 m/s and 45° from 1 m above the ground. The state is two Vectors: position R and velocity V.

```exercise
title: slope_func for the baseball
kind: write
---prompt
Write `slope_func(state, t, system)`: unpack `R, V = state`; acceleration = gravity `Vector(0, -system.g)` plus `drag_force(V, system) / system.mass`. Return `V, A`. `drag_force` is defined.
---setup
def drag_force(V, system):
    return -V.hat() * (system.rho * V.mag**2 * system.C_d * system.area / 2)
---starter
def slope_func(state, t, system):
    R, V = state
    pass
---solution
def slope_func(state, t, system):
    R, V = state
    a_drag = drag_force(V, system) / system.mass
    A = Vector(0, -system.g) + a_drag
    return V, A
---tests
s = System(rho=1.2, C_d=0.33, area=pi * 0.0365**2, mass=0.145, g=9.8)
dR, dV = slope_func(State(R=Vector(0, 1), V=Vector(0.0, 0.0)), 0, s)
assert dV.x == 0 and abs(dV.y + 9.8) < 1e-12, "At rest only gravity acts"
dR, dV = slope_func(State(R=Vector(0, 1), V=Vector(40.0, 0.0)), 0, s)
assert dV.x < 0 and dR.x == 40, "Flying right: drag slows it horizontally; dR/dt is the velocity"
---show
def event_func(state, t, system):
    R, V = state
    return R.y

for angle in [30, 45, 60]:
    system = System(init=State(R=Vector(0, 1), V=Vector(*pol2cart(np.deg2rad(angle), 40))),
                    rho=1.2, C_d=0.33, area=pi * 0.0365**2, mass=0.145, g=9.8, t_end=10)
    results, _ = run_ode_solver(system, slope_func, events=event_func)
    x, y = results.R.extract("x"), results.R.extract("y")
    plt.plot(x.values, y.values, label=f"{angle}°: range {x.iloc[-1]:.0f} m")
plt.gca().set_aspect("equal"); decorate(xlabel="x (m)", ylabel="y (m)", title="Trajectories from your slope_func")
```

```quiz
Air resistance cuts the 45° hit from about 164 m to about 100 m. Which is also true of the trajectory with drag?
- It's still a symmetric parabola
* It's lopsided: the ball comes down more steeply than it went up, because drag has slowed its horizontal motion
- It goes higher than without air
- It curves sideways
> Without air the path is a symmetric parabola. Drag keeps removing horizontal speed, so the descent is steeper and shorter than the climb.
```

```recall
Q: How do you write drag for 2-D motion with Vectors?
A: - Magnitude ½ρ|V|²C_dA, same as 1-D.
- Direction opposite to the velocity: multiply the magnitude by −V.hat().
- Acceleration = gravity Vector(0, −g) + drag/mass; the slope function returns (V, A).
```

## Real-world project: a drone package-drop calculator

A baseball hit at an angle and a parcel let go from a moving drone are the same problem: a launch velocity, gravity down, drag opposite the velocity. For the drone the launch is **horizontal** (the parcel starts with the drone's speed), and the question flips: not "how far does it go?" but "**how far before the target must I let go?**"

```project
title: Drone drop release calculator
client: A start-up delivering first-aid kits by drone to hikers and remote farms
skills: Vector state, 2-D drag, events, wrapping a simulation as a function, aiming
---brief
The drone flies level at a known speed and altitude. The kit (2 kg, about 0.04 m² of front area, drag coefficient near 1 for a box) is released and falls on its own. Build the calculator the drone's autopilot needs: given speed and altitude, how far forward does the kit travel before landing, and so at what distance before the target should it release?
---why
Air-drop planning for humanitarian aid, agricultural spraying and firefighting water bombers all solve this, and so do video games (aim assist for thrown objects) and sports trackers. The software pattern is "simulate forward, then invert": the simulation tells you where something lands, and the product needs the input that lands it on a target.
---milestones
- Write `drop_distance(speed, altitude)` that simulates the fall with drag and returns the forward distance and fall time
- Compare it with the no-drag answer speed·√(2h/g) to see how much drag matters
- Write `release_point(target_x, speed, altitude)`: where the drone should let go
- Report the landing speed too (a first-aid kit can't hit the ground too hard)
- Tabulate release distances for a few speeds and altitudes for the flight team
---stretch
- Add a steady wind as a Vector and include it in the drag (use the velocity relative to the air)
- Find the altitude that keeps the landing speed under 15 m/s
- Add a small parachute (chapter 21) that opens after 1 second
```

```exercise
title: drop_distance
kind: write
---prompt
Write `drop_distance(speed, altitude, mass=2.0, area=0.04, C_d=1.0)`: start the parcel at `Vector(0, altitude)` with velocity `Vector(speed, 0.0)` (level flight), build a System with `rho=1.2, g=9.8, t_end=60` and those values, run it with `slope_func` and `event_func` (both defined), and return `(x_land, t_land)`: the final x position and the final time.
---setup
def drag_force(V, system):
    return -V.hat() * (system.rho * V.mag**2 * system.C_d * system.area / 2)
def slope_func(state, t, system):
    R, V = state
    return V, Vector(0, -system.g) + drag_force(V, system) / system.mass
def event_func(state, t, system):
    R, V = state
    return R.y
---starter
def drop_distance(speed, altitude, mass=2.0, area=0.04, C_d=1.0):
    t = sqrt(2 * altitude / 9.8)
    return speed * t, t
---solution
def drop_distance(speed, altitude, mass=2.0, area=0.04, C_d=1.0):
    init = State(R=Vector(0, altitude), V=Vector(speed, 0.0))
    system = System(init=init, rho=1.2, C_d=C_d, area=area, mass=mass, g=9.8, t_end=60)
    results, details = run_ode_solver(system, slope_func, events=event_func)
    x_land = get_last_value(results.R).x
    return x_land, get_last_label(results)
---tests
x, t = drop_distance(15, 40)
assert abs(x - 35.6) < 0.3, f"At 15 m/s from 40 m, drag cuts the throw to about 35.6 m, got {x:.2f}"
assert abs(t - 3.18) < 0.05, f"Drag also slows the fall: about 3.18 s, got {t:.2f}"
x0, t0 = drop_distance(15, 40, C_d=0)
assert abs(x0 - 15 * sqrt(80 / 9.8)) < 0.1, "With no drag you should match the textbook answer speed * sqrt(2h/g)"
assert abs(drop_distance(0.0, 40)[0]) < 1e-9, "A hovering drone drops straight down"
---hint
The starter is the no-drag formula: right for a vacuum, about 7 m off in real air. Use the Vector state and the solver.
```
