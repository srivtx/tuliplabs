```prelude
from modsim import *

def drag_force(V, system):
    return -V.hat() * (system.rho * V.mag**2 * system.C_d * system.area / 2)

def slope_func(state, t, system):
    R, V = state
    return V, Vector(0, -system.g) + drag_force(V, system) / system.mass

def event_func(state, t, system):
    R, V = state
    return R.y

params = Params(x=0, y=1, g=9.8, mass=0.145, diameter=0.073, rho=1.2,
                C_d=0.33, angle=45, speed=40, t_end=20)

def make_system(params):
    theta = np.deg2rad(params.angle)
    V = Vector(*pol2cart(theta, params.speed))
    init = State(R=Vector(params.x, params.y), V=V)
    area = pi * (params.diameter / 2) ** 2
    return System(params, init=init, area=area)
```

## The problem

Fenway Park in Boston has a famous left-field wall, the **Green Monster**: 11.3 m high, about 94.5 m from home plate. The question: what's the **minimum speed** a ball needs to clear it, if the batter picks the best angle? Two steps: find the best angle for a given speed, then the lowest speed that clears the wall.

## Let the optimizer search

Sweeping works, but `maximize(func, [low, high], *args)` finds the best value precisely using a **golden-section search**: it keeps shrinking the bracket around the maximum.

```run
title: Best angle at 40 m/s
def range_func(angle, params):
    system = make_system(params.set(angle=angle))
    results, details = run_ode_solver(system, slope_func, events=event_func)
    return get_last_value(results.R).x

res = maximize(range_func, [0, 90], params)
print(f"best angle {res.x:.1f} degrees, range {res.fun:.1f} m")
```

```quiz
Without air the best angle is exactly 45°. With drag the optimizer finds a smaller angle. Why does drag favour a flatter launch?
- Drag pushes the ball forward
* A higher arc keeps the ball in the air longer, giving drag more time to slow it, so trading a little height for horizontal speed pays off
- Gravity is weaker at lower angles
- The optimizer has a bug
> Drag punishes time in flight. A slightly flatter trajectory spends less time losing speed, so the optimum moves below 45°.
```

```run
title: The minimum speed to clear the wall
def range_func(angle, params):
    system = make_system(params.set(angle=angle))
    results, details = run_ode_solver(system, slope_func, events=event_func)
    return get_last_value(results.R).x

def height_at_wall(speed, params, wall_x=94.5):
    p = params.set(speed=speed)
    system = make_system(p.set(angle=maximize(range_func, [0, 90], p).x))
    def wall_event(state, t, system):
        R, V = state
        return R.x - wall_x
    results, _ = run_ode_solver(system, slope_func, events=[wall_event, event_func])
    R = get_last_value(results.R)
    return R.y if R.x >= wall_x - 1e-6 else 0

def error_func(speed, params):
    return height_at_wall(speed, params) - 11.3      # the wall is 11.3 m high

res = root_bisect(error_func, [38, 45], params, xtol=0.01)
print(f"minimum speed to clear the Green Monster: about {res.root:.1f} m/s")
```

```recall
Q: Describe the two-level search the Manny Ramirez problem uses.
A: - Inner: for a given speed, `maximize` searches over launch angle (each evaluation runs a full simulation) to find the best angle.
- Outer: `root_bisect` searches over speed for the value where the ball's height at the wall, at its best angle, equals the wall's height.
- Each level wraps a simulation in a function of one parameter, so standard optimizers and root finders can drive it.
```

## Real-world project: a lawn-sprinkler nozzle designer

The Manny Ramirez problem is really a pattern: **wrap a simulation in a function, let an optimizer pick the best angle, then let a root finder pick the smallest speed that reaches a target.** A lawn sprinkler is the same pattern with tiny, drag-dominated water drops instead of a baseball, so the answers come out very differently.

```project
title: Sprinkler nozzle designer
client: A garden-irrigation company designing a new rotating sprinkler head
skills: Params.set, wrapping simulations, maximize, root_bisect, two-level search
---brief
Water leaves the nozzle 0.3 m above the lawn as drops about 2 mm across. Drag on a drop that small is huge compared with its weight, so the best angle is nowhere near 45°. The company wants two numbers for every lawn size: the nozzle angle that throws water farthest, and the slowest water speed (which sets the pump pressure) that still wets a lawn of a given radius.
---why
Irrigation, fire-hose and paint-spray designers do this; so do game designers tuning a grenade arc and engineers sizing pumps. In software, "optimize an inner choice, then root-find an outer requirement" is how pricing engines (best price per demand level, then minimum budget to hit a target) and autoscalers (best configuration, then fewest servers that meet latency) are built.
---milestones
- Set up `drop` params for a 2 mm water drop by changing the baseball's `Params` with `.set`
- Write `throw(angle, params)`: the horizontal distance a drop travels
- Use `maximize` to find the best nozzle angle at 12 m/s
- Write `speed_for_radius(radius, params)` with `root_bisect` around the best throw
- Print a table of pump speeds for lawns of radius 4, 5 and 6 m
---stretch
- Sweep the drop size: why do fine mists fall short, and big drops go farther?
- Model wind from one side and find which way the sprinkler should lean
- Estimate how much water lands per square metre at each distance
```

```exercise
title: speed_for_radius
kind: write
---prompt
Write `speed_for_radius(radius, p)`: the slowest water speed whose **best** throw (over angles 5°–60°) reaches `radius`. Define `error(speed)` that returns `maximize(throw, [5, 60], p.set(speed=speed)).fun - radius`, and return `root_bisect(error, [2, 40], xtol=0.01).root`. `throw` and `drop` are defined.
---setup
d = 0.002
drop = params.set(y=0.3, diameter=d, mass=1000 * 4 / 3 * pi * (d / 2)**3, C_d=0.47, speed=12, angle=30, t_end=10)
def throw(angle, p):
    results, details = run_ode_solver(make_system(p.set(angle=angle)), slope_func, events=event_func)
    return get_last_value(results.R).x
---starter
def speed_for_radius(radius, p):
    return sqrt(radius * p.g)
---solution
def speed_for_radius(radius, p):
    def error(speed):
        best = maximize(throw, [5, 60], p.set(speed=speed))
        return best.fun - radius
    return root_bisect(error, [2, 40], xtol=0.01).root
---tests
v6 = speed_for_radius(6, drop)
assert abs(v6 - 13.87) < 0.1, f"Wetting a 6 m lawn needs about 13.9 m/s, got {v6:.2f}"
assert speed_for_radius(4, drop) < v6, "A smaller lawn needs less pump speed"
---show
for radius in [4, 5, 6]:
    print(f"lawn radius {radius} m: water speed at least {speed_for_radius(radius, drop):.1f} m/s")
```
