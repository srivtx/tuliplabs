## Second-order systems

Part II's systems had first derivatives: temperature changes at some rate. Mechanics is different. **Newton's second law**, F = m·a, gives the **acceleration**, the second derivative of position. The trick: track **two** state variables, position y and velocity v:

- dy/dt = v
- dv/dt = a = F/m

Now it's two first-order equations, and `run_ode_solver` can handle it.

```quiz
To simulate a falling object with run_ode_solver, what goes in the state?
- Only the position
* Position and velocity
- Velocity and acceleration
- Only the acceleration
> The slope function must return the derivative of every state variable. Position's derivative is velocity (which must therefore be in the state) and velocity's derivative is acceleration (computed from forces).
```

## Dropping the penny

Back to chapter 1: a penny dropped from 381 m, no air resistance (yet).

```exercise
title: slope_func for free fall
kind: write
---prompt
Write `slope_func(state, t, system)`: unpack `y, v = state`, return `dydt, dvdt` with constant acceleration `-system.g`.
---starter
def slope_func(state, t, system):
    y, v = state
    pass
---solution
def slope_func(state, t, system):
    y, v = state
    dydt = v
    dvdt = -system.g
    return dydt, dvdt
---tests
assert slope_func(State(y=381.0, v=-10.0), 0, System(g=9.8)) == (-10.0, -9.8), "dy/dt is the velocity; dv/dt is -g"
```

```run
title: Fall for 10 seconds
def slope_func(state, t, system):
    y, v = state
    return v, -system.g

init = State(y=381.0, v=0.0)
system = System(init=init, g=9.8, t_end=10)
results, details = run_ode_solver(system, slope_func)
plot(results.y, label="y")
decorate(xlabel="Time (s)", ylabel="Position (m)")
print(results.tail(3))
```

The plot goes **below zero**: the penny falls through the sidewalk. We ran a fixed 10 seconds, but we want to stop when y reaches 0.

```predict
results = TimeFrame({"y": [5.0, 1.0, -3.0]}, index=[8.0, 8.5, 9.0])
print(crossings(results.y, 0))
```

`crossings` finds when a TimeSeries passes a value, by interpolating between points. A better tool stops the solver right there.

## Events

An **event function** returns a number that crosses zero when something happens. `run_ode_solver(..., events=event_func)` stops the simulation at that moment.

```exercise
title: event_func
kind: write
---prompt
Write `event_func(state, t, system)` that returns the penny's height (it hits zero at the sidewalk).
---starter
def event_func(state, t, system):
    pass
---solution
def event_func(state, t, system):
    y, v = state
    return y
---tests
assert event_func(State(y=12.5, v=-3.0), 0, System()) == 12.5, "Return the height"
```

```recall
Q: How do we turn Newton's second law into something run_ode_solver can solve, and how does it stop at the ground?
A: - Use position and velocity as state variables: dy/dt = v, dv/dt = F/m (here −g). Two first-order ODEs instead of one second-order one.
- An event function returns y; the solver stops when it crosses zero, so the last row of results is the moment of impact.
```

## Real-world project: a drop-tower ride designer

A penny falling from a building is a thought experiment; a **drop tower** at a theme park is the same physics on purpose. Riders fall freely, then magnetic brakes stop them. The designer's questions are the ones you can now answer with an event: at what height does the car reach its top speed, and is there enough tower left below it to brake?

```project
title: Drop-tower ride calculator
client: A theme-park engineering team sketching a new free-fall ride
skills: second-order systems, run_ode_solver, event functions on velocity, design checks
---brief
The car is released from the top and falls freely until it reaches the brake speed (say 30 m/s). Then the brakes slow it at a fixed number of g's (say 2 g, which is comfortable for riders). Build the calculator: given tower height, brake speed and braking g's, where do the brakes start, how many seconds of free fall do riders get, and how much tower is left over?
---why
Ride and elevator engineers run exactly this check, and so do car-crash and parachute designers: "free motion until a trigger, then a controlled phase". In code it's an event that stops one simulation and hands the state to the next phase, the same pattern as game engines switching a character from "falling" to "landed", or a rocket simulator switching stages.
---milestones
- Write an event function that fires when the speed reaches the brake speed
- Write `brake_point(height, v_max)` returning the time and height when the brakes start
- Compute the braking distance v²/(2·a) and the height left over (the safety margin)
- Find the shortest tower that still leaves a 5 m margin
- Plot height vs time for the free-fall phase and mark the brake point
---stretch
- Simulate the braking phase too, as a second `run_ode_solver` starting from the brake state
- Add drag from chapter 21 and see how much free-fall time riders lose
- Let the user ask for "3 seconds of free fall" and solve for the tower height with `root_bisect`
```

```exercise
---prompt
Fill the blanks. Braking at `brake_g` g's from speed `v_max` takes a distance of v²/(2·a) with a = `brake_g * g`. The margin is the brake height minus that distance (negative means the car would hit the ground). `brake_point` is defined.

---starter
def safety_margin(height, v_max, brake_g, g=9.8):
    t_brake, y_brake = brake_point(height, v_max, g)
    brake_distance = ____
    return ____
---solution
def safety_margin(height, v_max, brake_g, g=9.8):
    t_brake, y_brake = brake_point(height, v_max, g)
    brake_distance = v_max**2 / (2 * brake_g * g)
    return y_brake - brake_distance
---tests
m = safety_margin(100, 30, 2)
assert abs(m - 31.12) < 0.05, f"100 m tower, 30 m/s, 2 g brakes: brakes start at 54.1 m and need 23.0 m, leaving about 31.1 m; got {m:.2f}"
assert safety_margin(60, 30, 2) < 0, "A 60 m tower is too short for these numbers: the margin goes negative"
assert safety_margin(100, 30, 4) > m, "Harder brakes need less distance"
---show
heights = linspace(60, 120, 13)
plot(SweepSeries({h: safety_margin(h, 30, 2) for h in heights}), "o-")
plt.axhline(5, color="#e2532c", ls="--", lw=1, label="5 m required margin")
decorate(xlabel="Tower height (m)", ylabel="Margin left after braking (m)", title="Your safety_margin: how tall must the tower be?")
```
