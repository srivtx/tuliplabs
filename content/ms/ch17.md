## The glucose–insulin system

**Pharmacokinetics** studies how substances move through the body. Part II's biggest case study is the **frequently sampled intravenous glucose tolerance test** (FSIGT): a patient fasts, gets an injection of glucose, and doctors measure blood glucose and insulin every few minutes. How fast glucose returns to normal tells you how well insulin works, which matters for diagnosing diabetes.

## The minimal model

Bergman's **glucose minimal model** has two state variables: glucose concentration G and **X**, the effect of insulin in the tissues ("remote insulin"). Insulin concentration I(t) comes from the measurements.

- dG/dt = −k₁·(G − G_b) − X·G
- dX/dt = k₃·(I(t) − I_b) − k₂·X

G_b and I_b are the basal (fasting) levels. k₁ is how fast glucose falls back on its own; X·G is the extra uptake caused by insulin; k₂ and k₃ control how remote insulin rises and decays.

```quiz
If a patient's tissues respond weakly to insulin (insulin resistance), which parameter in the model would be small?
- k₁
- k₂
* k₃: insulin above basal produces only a little remote insulin X, so glucose falls slowly
- G_b
> k₃ converts excess insulin into remote insulin X, which drives extra glucose uptake. Insulin sensitivity is defined as S_I = k₃/k₂.
```

## Interpolation

The data have gaps between measurements, but the model needs I(t) at any time. `interpolate(series)` returns a **function** that draws straight lines between the data points.

```predict
f = interpolate(TimeSeries({0: 10.0, 10: 30.0}))
print(float(f(5)), float(f(2.5)))
```

```exercise
title: update_func for the minimal model
kind: write
---prompt
Write `update_func(state, t, system)`. Unpack `G, X = state`, compute the two derivatives from the equations above (use `system.I(t)`), and take one Euler step of size `system.dt`. Return `State(G=..., X=...)`.
---starter
def update_func(state, t, system):
    G, X = state
    pass
---solution
def update_func(state, t, system):
    G, X = state
    k1, k2, k3 = system.k1, system.k2, system.k3
    I, Ib, Gb = system.I, system.Ib, system.Gb
    dGdt = -k1 * (G - Gb) - X * G
    dXdt = k3 * (I(t) - Ib) - k2 * X
    G += dGdt * system.dt
    X += dXdt * system.dt
    return State(G=G, X=X)
---tests
s = System(k1=0.03, k2=0.02, k3=1e-5, Gb=92, Ib=11, I=lambda t: 111.0, dt=2)
st = update_func(State(G=292.0, X=0.0), 0, s)
assert abs(st.G - (292 - 0.03 * 200 * 2)) < 1e-9, f"dG/dt = -0.03 * 200 = -6, so G drops 12 in a 2-minute step; got {st.G}"
assert abs(st.X - 1e-5 * 100 * 2) < 1e-12, "dX/dt = 1e-5 * 100 = 0.001, times dt = 2"
```

```run
title: Model vs (synthetic) data
def update_func(state, t, system):
    G, X = state
    dGdt = -system.k1 * (G - system.Gb) - X * G
    dXdt = system.k3 * (system.I(t) - system.Ib) - system.k2 * X
    return State(G=G + dGdt * system.dt, X=X + dXdt * system.dt)

def run_simulation(system, update_func):
    frame = TimeFrame(columns=system.init.index)
    frame.row[system.t_0] = system.init
    for t in linrange(system.t_0, system.t_end, system.dt):
        frame.row[t + system.dt] = update_func(frame.row[t], t, system)
    return frame

system = System(init=State(G=290.0, X=0.0), k1=0.03, k2=0.02, k3=1e-5,
                Gb=92, Ib=11, I=interpolate(insulin), t_0=0, t_end=182, dt=2)
results = run_simulation(system, update_func)
plot(results.G, label="model")
plot(glucose, "o", label="data (synthetic)")
decorate(xlabel="Time (min)", ylabel="Concentration (mg/dL)")
```

## Real-world project: time-in-range from a glucose sensor

You just turned sparse lab samples into a smooth function with `interpolate`. Continuous glucose monitors (CGMs), the small sensors many people with diabetes wear, have the same problem in everyday life: a reading every 5 minutes, and **gaps** when the phone loses the signal. Their apps fill the gaps and report "time in range", the share of the day glucose spent between 70 and 180 mg/dL. (This is a learning project with made-up numbers, not a medical tool.)

```project
title: CGM time-in-range report
client: A diabetes-education app that turns sensor readings into a daily summary
skills: interpolate, TimeSeries, resampling, boolean masks, why uneven samples mislead
---brief
The sensor sends readings roughly every 5 minutes, but some are missing. If you simply count readings, a gap hides however long glucose spent high or low during it. Resample to one value per minute with `interpolate`, then compute the fraction of minutes in range, plus minutes below range (the number users care about most).
---why
Every health and fitness wearable resamples irregular sensor data before computing summaries: heart-rate zones, sleep stages, step cadence. Financial apps do it to price data with missing ticks; IoT dashboards do it for sensors with flaky Wi-Fi. "Average over time, not over samples" is a bug many real dashboards have shipped.
---milestones
- Write `resample(series, step)` that returns one interpolated value every `step` minutes
- Write `time_in_range(series, low, high)` as a fraction between 0 and 1
- Compare the raw-sample answer with the resampled one on data with a gap
- Add minutes below 70 and above 180 to the report
- Refuse to fill gaps longer than 30 minutes (report them as "no data" instead)
---stretch
- Plot the day with the 70–180 band shaded
- Use the minimal model from this chapter to predict the next 30 minutes from the last readings
- Export the report as a small pandas DataFrame per hour
```
