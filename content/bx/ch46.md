## One line of air

Close your eyes in a busy café. You can pick out a voice, a spoon, the coffee machine and the song on the speakers. But your eardrum isn't receiving four things. It's a single skin being pushed in and out, so all that reaches you is **one line** going up and down. Everything you've ever heard, an orchestra included, arrived that way.

So how can one line hold a whole orchestra? In 1807 Joseph Fourier, who was studying heat, made a claim that the experts reviewing his work didn't believe: **any** repeating curve, even one with sharp corners, is a sum of plain sine waves. Try to prove him wrong.

```viz
name: bx-synth
title: Twelve sine waves and a keyboard
goal: Drag the bars until your wave is **96% square**. Then press **Drop the lowest** and hold a key.
height: 410
The bars are how loud each multiple of the base frequency is. The keys play exactly what you see.
```

The recipe for the square is the odd multiples, each one quieter: 1, ⅓, ⅕, ⅐. Smooth curves really can make a corner, though it takes infinitely many of them. Stop early and the edges keep a little overshoot, about 9% of the jump. Add more sines and the overshoot gets narrower, but never lower. It's called the **Gibbs phenomenon**, and it comes back in chapter 48 as the fuzz around letters in a JPEG.

## Making a sound out of numbers

To a computer, sound is a list of numbers: how far the speaker should be pushed at each instant. CD audio uses 44,100 numbers a second.

```exercise
title: tone
kind: write
---prompt
Write `tone(freq, seconds, rate)`. Return a list of `int(seconds * rate)` samples, where sample `n` is `sin(2π × freq × n / rate)`. `rate` is how many samples there are per second.
---starter
def tone(freq, seconds, rate):
    return [0.0] * int(seconds * rate)
---solution
from math import sin, pi

def tone(freq, seconds, rate):
    return [sin(2 * pi * freq * n / rate) for n in range(int(seconds * rate))]
---tests
s = tone(1, 1, 4)
assert len(s) == 4
assert abs(s[0]) < 1e-9 and abs(s[1] - 1) < 1e-9 and abs(s[2]) < 1e-9 and abs(s[3] + 1) < 1e-9, "one full wave in four samples"
assert len(tone(440, 0.5, 8000)) == 4000
assert abs(tone(2, 1, 8)[1] - 1) < 1e-9, "twice as fast"
---hint
Time at sample `n` is `n / rate`. Put that into `sin(2 * pi * freq * t)`.
```

Adding sounds is just adding numbers. That's all a mixing desk does, and it's what the air does when two people talk at once.

```exercise
title: stack
kind: write
---prompt
Write `stack(bars, base, t)`. `bars[0]` is the loudness of the base frequency, `bars[1]` of twice the base, `bars[2]` of three times, and so on. Return the height of the summed wave at time `t`: the sum of `bars[i] × sin(2π × (i + 1) × base × t)`.
---starter
from math import sin, pi

def stack(bars, base, t):
    return bars[0] * sin(2 * pi * base * t)
---solution
from math import sin, pi

def stack(bars, base, t):
    return sum(a * sin(2 * pi * (i + 1) * base * t) for i, a in enumerate(bars))
---tests
from math import sin, pi
assert abs(stack([1], 1, 0.25) - 1) < 1e-9
assert abs(stack([0, 1], 1, 0.125) - 1) < 1e-9, "the second bar runs twice as fast"
assert abs(stack([1, 0, 1 / 3], 1, 0.25) - (1 - 1 / 3)) < 1e-9
assert stack([], 1, 0.3) == 0
assert abs(stack([2, 3], 5, 0.01) - (2 * sin(2 * pi * 0.05) + 3 * sin(2 * pi * 0.1))) < 1e-9
---hint
`enumerate(bars)` gives you `i` and the loudness. The multiple is `i + 1`.
```

## What makes a flute a flute

Press **Flute-like**, hold a key, then press **Bowed string** and hold the same key. The note is the same and the character is completely different. That character is called **timbre**, and now you know what it is: the heights of the bars. When you recognise your friend's voice on the phone, you're reading their bars.

A real note also changes over time. A piano starts loud and fades, and an organ stays level until you let go. Synthesizers shape this with an **envelope** that has four parts: attack, decay, sustain, release.

```exercise
title: adsr
kind: write
---prompt
Write `adsr(t, a, d, s, r, off)`, the loudness at time `t` of a key pressed at time 0 and let go at time `off`. It rises from 0 to 1 over `a` seconds, falls to the level `s` over the next `d` seconds, stays at `s` until `off`, then falls to 0 over `r` seconds, and stays 0 after that. You can assume `off >= a + d`, and that `a`, `d` and `r` are above 0.
---starter
def adsr(t, a, d, s, r, off):
    return s
---solution
def adsr(t, a, d, s, r, off):
    if t < a:
        return t / a
    if t < a + d:
        return 1 - (1 - s) * (t - a) / d
    if t < off:
        return s
    if t < off + r:
        return s * (1 - (t - off) / r)
    return 0
---tests
assert adsr(0, 1, 1, 0.5, 1, 5) == 0
assert adsr(0.5, 1, 1, 0.5, 1, 5) == 0.5, "halfway up the attack"
assert adsr(1, 1, 1, 0.5, 1, 5) == 1, "the peak"
assert adsr(1.5, 1, 1, 0.5, 1, 5) == 0.75, "halfway down the decay"
assert adsr(3, 1, 1, 0.5, 1, 5) == 0.5, "sustain"
assert adsr(5.5, 1, 1, 0.5, 1, 5) == 0.25, "halfway through the release"
assert adsr(9, 1, 1, 0.5, 1, 5) == 0
---hint
Check the four time ranges in order, and work out how far through each one you are.
```

## The note that isn't there

Did you do the second half of the goal? With the lowest bar gone, there's nothing left at the base frequency, yet the note doesn't move. That's the strangest thing in this chapter, so look at why.

The number on the picture stayed the same, because the **whole pattern** still repeats at the same rate. Multiples 2, 3 and 4 of 220 are 440, 660 and 880. Nothing in that list is 220, but 220 is the rate at which all three line up again. Your brain doesn't report the lowest sine. It reports that repeat rate, and the note you hear exists only in your head.

```exercise
title: pattern_rate
kind: write
---prompt
Write `pattern_rate(freqs)`, for a list of whole-number frequencies. Return how many times a second the combined pattern repeats, which is the largest number that divides all of them. Use `math.gcd`.
---starter
def pattern_rate(freqs):
    return min(freqs)
---solution
from math import gcd

def pattern_rate(freqs):
    rate = 0
    for f in freqs:
        rate = gcd(rate, f)
    return rate
---tests
assert pattern_rate([440, 660, 880]) == 220, "a pitch that isn't in the list"
assert pattern_rate([220]) == 220
assert pattern_rate([440, 660]) == 220, "a fifth"
assert pattern_rate([440, 466]) == 2, "two notes side by side barely line up at all"
assert pattern_rate([600, 800, 1000]) == 200
---hint
`gcd(0, x)` is `x`, so you can start at 0 and fold the list in.
```

Look at two of those tests: 440 and 660 line up 220 times a second, and 440 and 466 only twice. Notes with simple ratios share many harmonics and settle into a short pattern. That's a big part of why some pairs of notes feel calm and others feel tense.

It also explains the keyboard. Doubling a frequency sounds like the same note, higher. Splitting that doubling into 12 equal steps lands very close to the simple ratios.

```predict
for steps in [12, 7, 5]:
    print(steps, round(2 ** (steps / 12), 3))
```

Seven steps give 1.498, which is almost exactly 3:2, and five give 1.335, nearly 4:3. Twelve is a lucky number: it's a small count of notes that gets close to the ratios people like. Every piano is very slightly out of tune on purpose so that it can play in every key.

## How your ear unmixes a line

Fourier says that the sines are in there. How do you get them back out? Your ear does it with physics. Inside it is the **cochlea**, a fluid-filled coil about 35 mm long, lined with about 3,500 inner hair cells. It's stiff at one end and floppy at the other, so each spot along it responds to its own pitch. Where it moves tells your brain which frequencies are present.

Here's a bank of 49 tuned reeds doing the same job.

```viz
name: bx-ear
title: Reeds that unmix a sound
goal: Name all **three hidden notes** by tapping their bright lines. You'll need to change the reeds' sharpness.
height: 430
Up is pitch, and across is time. The bars on the right are the reeds right now.
```

The real cochlea isn't separate reeds: a wave travels along it and peaks at a certain place, which Georg von Békésy won a Nobel Prize for showing. The result is the same, though: **place stands for pitch.**

A computer's version is simple and very beautiful. To test whether a line contains a frequency, multiply the line by a sine of that frequency, and add up the result. If that frequency is in there, the peaks line up with the peaks, the troughs line up with the troughs, and every product is positive, so the sum grows. If it isn't, the products are positive and negative in equal measure, and the sum cancels to nothing.

A wave might be shifted relative to your test sine, so you test with a sine and a cosine, and combine them. That's the **Fourier transform**.

```exercise
title: strength
kind: write
---prompt
Write `strength(samples, rate, freq)`, which measures how much of `freq` is in `samples`. For every sample `n`, with `t = n / rate`, add `samples[n] × cos(2π × freq × t)` to `re`, and `samples[n] × sin(2π × freq × t)` to `im`. Return `2 × hypot(re, im) / len(samples)`, which is the height of that sine in the mix.
---starter
def strength(samples, rate, freq):
    return max(samples)
---solution
from math import sin, cos, pi, hypot

def strength(samples, rate, freq):
    re = im = 0
    for n, s in enumerate(samples):
        t = n / rate
        re += s * cos(2 * pi * freq * t)
        im += s * sin(2 * pi * freq * t)
    return 2 * hypot(re, im) / len(samples)
---tests
from math import sin, pi
rate = 64
one = [3 * sin(2 * pi * 5 * n / rate) for n in range(rate)]
assert abs(strength(one, rate, 5) - 3) < 1e-9, "it's there, at height 3"
assert strength(one, rate, 9) < 1e-9, "not there at all"
mix = [sin(2 * pi * 4 * n / rate) + 0.5 * sin(2 * pi * 11 * n / rate + 1) for n in range(rate)]
assert abs(strength(mix, rate, 4) - 1) < 1e-9
assert abs(strength(mix, rate, 11) - 0.5) < 1e-9, "shifted waves still count"
assert strength(mix, rate, 7) < 1e-9
---hint
Run through the samples once, keeping two running sums, and use `math.hypot` at the end.
```

Run that for every frequency and you have the whole spectrum. Doing it this way costs n² steps. In 1965 James Cooley and John Tukey published the **fast Fourier transform**, which costs about n log n, and that's one of the most important algorithms ever written. It's in your phone's radio, in Wi-Fi, in MRI scanners and in every music app.

## You can't know both

Now the deepest thing here. Go back to the reeds, choose **Clicks**, and move the slider.

A sharp reed can tell very close notes apart, but only by listening for a long time, and so it's vague about **when** a sound happened. A loose reed reacts instantly, but it's vague about **which** note. You can't have both, and better engineering won't help. A sound that lasts a very short time simply doesn't have a precise pitch. A click is every pitch at once.

Dennis Gabor showed in 1946 that this limit on signals is the same mathematics as Heisenberg's uncertainty principle. In quantum physics a particle is described by a wave. A wave packed into a tiny space has no single wavelength, and wavelength is momentum. So position and momentum can't both be sharp. The famous strangeness of quantum physics isn't about clumsy measuring. It's what you just did with a slider.

## When sampling lies

One more trap. A list of samples only records a wave at certain instants. If the wave wiggles too fast, the samples can't tell it apart from a slower one.

Films show this: at 24 frames a second, a spinning wheel can seem to crawl backward. **Above half the sampling rate, a frequency folds back and turns up pretending to be a lower one.** This is **aliasing**, and the limit, half the rate, is called the Nyquist frequency.

```exercise
title: alias
kind: write
---prompt
Write `alias(freq, rate)`, which returns the frequency you'd actually record when sampling `freq` at `rate` samples a second. Take `f = freq % rate`, and return `min(f, rate - f)`.
---starter
def alias(freq, rate):
    return freq
---solution
def alias(freq, rate):
    f = freq % rate
    return min(f, rate - f)
---tests
assert alias(30, 100) == 30, "slow enough: recorded correctly"
assert alias(50, 100) == 50, "right at the limit"
assert alias(70, 100) == 30, "folded back"
assert alias(130, 100) == 30
assert alias(100, 100) == 0, "looks perfectly still, like a wheel under a strobe"
---hint
It's two lines. The `%` removes whole trips around the sampling rate, and the `min` does the folding.
```

People hear up to about 20,000 Hz. Twice that is 40,000, and a little more leaves room for a filter that removes everything above the limit before sampling. That's why CDs use 44,100 samples a second. And if you stay under the limit, the Nyquist–Shannon sampling theorem promises something surprising: the samples aren't an approximation. The wave between them can be rebuilt **exactly**.

That filter is another thing a synthesizer needs. Most hardware synths work the opposite way round from your bars: they start with a wave full of harmonics and carve some away. The simplest filter fits in one line.

```exercise
title: low_pass
kind: write
---prompt
Write `low_pass(samples, k)`. Keep a value `y`, which starts at 0. For each sample `x`, move `y` part of the way towards it: `y += k * (x - y)`. Return the list of `y` values. Fast wiggles never get a chance to pull `y` far, so high frequencies fade and slow ones pass.
---starter
def low_pass(samples, k):
    return list(samples)
---solution
def low_pass(samples, k):
    out = []
    y = 0
    for x in samples:
        y += k * (x - y)
        out.append(y)
    return out
---tests
assert low_pass([1, 1, 1], 0.5) == [0.5, 0.75, 0.875]
assert low_pass([1, 2, 3], 1) == [1, 2, 3], "k of 1 changes nothing"
fast = [1, -1] * 50
slow = [1] * 50 + [-1] * 50
assert max(abs(v) for v in low_pass(fast, 0.1)[50:]) < 0.1, "fast wiggles nearly vanish"
assert max(abs(v) for v in low_pass(slow, 0.1)[50:]) > 0.9, "slow changes get through"
---hint
A running value, updated once per sample. Append after updating.
```

## Real-world project: listening to machines

```project
title: pumpwatch, a vibration monitor for a water utility
client: A water utility with 200 pumps. A failed bearing floods a station and costs a week of repairs, but sensors on the pump can pick up a fault weeks before it fails
skills: Fourier transforms, peak finding, harmonics, baselines, alarms
---brief
Build `pumpwatch.py`. Read a recording from a vibration sensor on a pump, and work out its spectrum. Find the strongest peaks. Peaks at whole multiples of the shaft speed are normal: that's the machine's own "timbre". A growing peak that isn't a whole multiple is the warning sign of a worn bearing. Compare each week to that pump's healthy baseline, and raise an alarm only when a suspect peak has grown for several weeks in a row.
---why
This is real. It's called vibration analysis or predictive maintenance, and it guards pumps, wind turbines, jet engines and factory lines. Bearing faults show up at frequencies set by the bearing's geometry, and these aren't whole multiples of the shaft speed. You're doing what your cochlea does, on a machine.
---milestones
- Read a recording and work out its spectrum
- Find the strongest peaks
- Separate normal harmonics from suspects
- Compare against a healthy baseline
- An alarm that needs several bad weeks in a row
---stretch
- Use a real fast Fourier transform and compare the speed
- Handle a pump whose speed drifts during a recording
```

```exercise
title: peak_freq
kind: write
---prompt
Write `peak_freq(samples, rate, lo, hi)`. Test every whole frequency from `lo` to `hi` inclusive, and return the one with the largest strength, using the same strength measure as before. If two tie, keep the lower one.
---starter
def peak_freq(samples, rate, lo, hi):
    return lo
---solution
from math import sin, cos, pi, hypot

def strength(samples, rate, freq):
    re = im = 0
    for n, s in enumerate(samples):
        t = n / rate
        re += s * cos(2 * pi * freq * t)
        im += s * sin(2 * pi * freq * t)
    return hypot(re, im)

def peak_freq(samples, rate, lo, hi):
    best, top = lo, -1
    for f in range(lo, hi + 1):
        s = strength(samples, rate, f)
        if s > top + 1e-9:
            best, top = f, s
    return best
---tests

wave = [sin(2 * pi * 9 * n / rate) + 3 * sin(2 * pi * 20 * n / rate) for n in range(rate)]

assert peak_freq(wave, rate, 1, 15) == 9, "only look inside the range"
assert peak_freq([sin(2 * pi * 33 * n / rate) for n in range(rate)], rate, 2, 60) == 33
```

```exercise
title: suspects
kind: write
---prompt
Write `suspects(peaks, shaft, tol)`. `peaks` is a list of frequencies, and `shaft` is how many times a second the shaft turns. A peak is normal if it's within `tol` of a whole multiple of `shaft` (1×, 2×, 3× and so on). Return the peaks that aren't normal, in their original order.
---starter
def suspects(peaks, shaft, tol):
    return []
---solution
def suspects(peaks, shaft, tol):
    out = []
    for p in peaks:
        nearest = max(1, round(p / shaft)) * shaft
        if abs(p - nearest) > tol:
            out.append(p)
    return out
```

## Rebuild it and explain it

```exercise
title: strength_rebuild
kind: rebuild
---prompt
From memory: `strength(samples, rate, freq)`, which returns the height of the sine at `freq` in `samples`.
---starter

```

```recall
Q: Explain how one line of air can hold many sounds, why you can hear a note whose frequency isn't present, how a Fourier transform pulls frequencies out, and why you can't know a sound's exact pitch and exact timing together.
A: Any repeating wave is a sum of sine waves at whole multiples of a base frequency, so a single line going up and down can carry many notes at once, and the heights of those harmonics are the sound's timbre. Pitch comes from how often the whole pattern repeats, so if you remove the lowest sine, the remaining multiples still line up at the same rate and the brain reports that pitch even though it isn't in the air. To find a frequency, multiply the signal by a sine and a cosine of that frequency and add up: if it's present the products all push the same way and the sum grows, and if it's absent they cancel. The cochlea does this physically, with each place along it tuned to a pitch. A filter that separates close frequencies has to listen for a long time, which blurs when things happened, while a quick one blurs which frequency. That's a mathematical limit: a short sound really is spread over many frequencies, and the same mathematics gives Heisenberg's uncertainty principle.
```
