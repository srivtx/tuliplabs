## Two problems in one tap

When you tap "request a ride", the dispatcher has two jobs:

1. **Find drivers near you.** A city has tens of thousands of drivers moving every few seconds. Checking the distance to all of them for every request is too slow, so drivers are kept in a **spatial index**: the map is cut into cells (a grid, or hexagons like Uber's H3), and a search looks at your cell, then the ring of cells around it, then the next ring, and stops once no farther cell could hold anyone closer.
2. **Decide who gets whom.** The obvious rule is: each rider, in the order they asked, gets the nearest free driver. It's fast and feels fair, but it's **greedy**: an early rider can take the only car near a later one.

Real dispatchers **batch**: they collect requests for a second or two and solve an **assignment problem** over the batch: pair riders with drivers to minimise total pickup distance (or the worst wait).

## Finding nearby drivers

```exercise

---prompt
Write a class `Grid(cell)` holding drivers at integer points. `add(id, x, y)` places (or moves) a driver; `remove(id)` takes one out; `nearest(x, y)` returns the id of the closest driver by Manhattan distance (ties: the smaller id), or `None` if there are none. Store drivers in a dict from cell `(x // cell, y // cell)` to a set of ids. Search ring by ring: ring r is the cells at Chebyshev distance r from the query's cell. Once you've found a driver at distance `best`, you can stop after a ring r with `(r - 1) * cell >= best`, since everything in ring r+1 or beyond is farther away than that.
---starter
class Grid:
    def __init__(self, cell):
        self.cell, self.cells, self.pos = cell, {}, {}

    def add(self, id, x, y):
        self.pos[id] = (x, y)
        self.cells.setdefault((x // self.cell, y // self.cell), set()).add(id)

    def remove(self, id):
        x, y = self.pos.pop(id)
        self.cells[(x // self.cell, y // self.cell)].discard(id)

    def nearest(self, x, y):
        here = self.cells.get((x // self.cell, y // self.cell), set())
        return min(here, default=None)
---solution
class Grid:
    def __init__(self, cell):
        self.cell, self.cells, self.pos = cell, {}, {}

    def add(self, id, x, y):
        if id in self.pos:
            self.remove(id)
        self.pos[id] = (x, y)
        self.cells.setdefault((x // self.cell, y // self.cell), set()).add(id)

    def remove(self, id):
        x, y = self.pos.pop(id)
        self.cells[(x // self.cell, y // self.cell)].discard(id)

    def nearest(self, x, y):
        if not self.pos:
            return None
        cx, cy = x // self.cell, y // self.cell
        best, best_id, r = None, None, 0
        while True:
            for gx in range(cx - r, cx + r + 1):
                for gy in range(cy - r, cy + r + 1):
                    if max(abs(gx - cx), abs(gy - cy)) != r:
                        continue
                    for i in self.cells.get((gx, gy), ()):
                        px, py = self.pos[i]
                        d = abs(px - x) + abs(py - y)
                        if best is None or (d, i) < (best, best_id):
                            best, best_id = d, i
            if best is not None and (r - 1) * self.cell >= best:
                return best_id
            r += 1
```

```exercise
---solution
def greedy(riders, drivers):
    free, a, total = set(range(len(drivers))), [], 0
    for rx, ry in riders:
        j = min(free, key=lambda k: (abs(rx - drivers[k][0]) + abs(ry - drivers[k][1]), k))
        free.remove(j)
        a.append(j)
        total += abs(rx - drivers[j][0]) + abs(ry - drivers[j][1])
    return a, total
```

```exercise
def best_total(riders, drivers):
    dp = {0: 0}
    for rx, ry in riders:
        nxt = {}
        for mask, cost in dp.items():
            for j, (dx, dy) in enumerate(drivers):
                if not mask >> j & 1:
                    k, c = mask | 1 << j, cost + abs(rx - dx) + abs(ry - dy)

        dp = nxt
```

```exercise
title: pickup_time
kind: write
---prompt
Cars drive on streets, not in straight lines. Write `eta(city, start, goal)`: `city` is a list of strings where `.` is road and `#` is a closed road or building; moves go up, down, left or right one cell per minute. Return the minutes from `start` to `goal` (both `(row, col)`), or `-1` if there's no route. Use BFS.
---starter
def eta(city, start, goal):
    return abs(start[0] - goal[0]) + abs(start[1] - goal[1])
---solution
from collections import deque

def eta(city, start, goal):
    R, C = len(city), len(city[0])
    dist = {start: 0}
    q = deque([start])
    while q:
        r, c = q.popleft()
        if (r, c) == goal:
            return dist[(r, c)]
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < R and 0 <= nc < C and city[nr][nc] == "." and (nr, nc) not in dist:
                dist[(nr, nc)] = dist[(r, c)] + 1
                q.append((nr, nc))
    return -1
---tests
city = ["....",
        ".##.",
        "....",
        "###."]
assert eta(city, (0, 0), (2, 0)) == 2
assert eta(city, (2, 1), (0, 1)) == 4, "the block in the middle forces a detour"
assert eta(city, (0, 0), (3, 3)) == 6
assert eta([".#."], (0, 0), (0, 2)) == -1
assert eta(["."], (0, 0), (0, 0)) == 0
---hint
The starter uses straight Manhattan distance, which drives through buildings. Search the streets with BFS.
```

```exercise
title: fair_batch
kind: write
---prompt
Write `fair_limit(riders, drivers)`: the smallest possible **longest** pickup distance when every rider gets a different driver. Binary-search over the sorted distinct distances; for a limit T, check whether every rider can be matched to a driver within T (bipartite matching with Kuhn's algorithm from DSA chapter 54).
---starter
def fair_limit(riders, drivers):
    free, worst = set(range(len(drivers))), 0
    for rx, ry in riders:
        j = min(free, key=lambda k: abs(rx - drivers[k][0]) + abs(ry - drivers[k][1]))
        free.remove(j)
        worst = max(worst, abs(rx - drivers[j][0]) + abs(ry - drivers[j][1]))
    return worst
---solution
def fair_limit(riders, drivers):
    dist = lambda r, d: abs(r[0] - d[0]) + abs(r[1] - d[1])
    options = sorted({dist(r, d) for r in riders for d in drivers})

    def can_match(T):
        owner = [-1] * len(drivers)

        def try_kuhn(v, seen):
            for j in range(len(drivers)):
                if dist(riders[v], drivers[j]) <= T and not seen[j]:
                    seen[j] = True
                    if owner[j] < 0 or try_kuhn(owner[j], seen):
                        owner[j] = v
                        return True
            return False
        return all(try_kuhn(v, [False] * len(drivers)) for v in range(len(riders)))

    lo, hi = 0, len(options) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if can_match(options[mid]):
            hi = mid
        else:
            lo = mid + 1
    return options[lo]
---tests
```

```recall
Q: Explain how a ride-share dispatcher works: finding nearby drivers with a grid index (and when the search can stop), why greedy first-come matching is unfair, what batching and the assignment problem fix, and the difference between minimising total distance and the worst wait.
A: Drivers live in a spatial index: the map is cut into cells, and each cell keeps a set of drivers, updated as they move. A nearest-driver search checks the rider's cell, then rings of cells around it; once a driver at distance d is found, it can stop after the ring past which every cell is at least d away. Greedy dispatch gives each rider, in request order, the nearest free driver. It's fast but can hand an early rider the only car near a later rider, who then waits for one from far away. Batching collects requests for a second or two and solves an assignment problem over them: pair riders with distinct drivers to minimise total pickup distance (by DP over bitmasks for small batches, or the Hungarian algorithm and min-cost flow for large ones). Minimising the total can still leave one rider with a long wait, so a bottleneck objective minimises the longest wait instead: binary-search a limit T and check with bipartite matching whether everyone can be served within T. Real pickup times come from routes on the street graph (BFS or Dijkstra), not straight lines.
```
