## Two queues facing each other

An exchange keeps an **order book** for each stock. **Bids** are offers to buy ("up to 99.95 for 300 shares"); **asks** are offers to sell ("at least 100.00 for 50 shares"). The highest bid and the lowest ask face each other across the **spread**. While they don't overlap, nothing trades; orders just wait on the book.

When a new order **crosses** the spread (a buy at or above the lowest ask, or a sell at or below the highest bid), it trades immediately against the resting orders, using **price-time priority**:

1. **Best price first**: a buyer gets the cheapest asks, a seller the highest bids.
2. **Oldest first** at the same price: each price level is a queue.
3. The trade happens at the **resting** order's price: it was there first, and the newcomer agreed to that price or better.

Whatever isn't filled **rests** on the book at its own limit price.

The structure that makes this fast is a **heap per side**: asks ordered by `(price, arrival)`, bids by `(-price, arrival)`, so the best order is always on top. Prices are kept in whole cents (integers) so they compare exactly.

import heapq

class OrderBook:
    def __init__(self):
        self.bids, self.asks, self.left, self.seq = [], [], {}, 0

    def submit(self, id, side, price, qty):
        trades = []
        book, other = (self.bids, self.asks) if side == "buy" else (self.asks, self.bids)
        while qty and other:
            key, _, oid = other[0]
            if self.left[oid] == 0:
                heapq.heappop(other)
                continue
            best = key if side == "buy" else -key
            if (side == "buy" and best > price) or (side == "sell" and best < price):
                break
            q = min(qty, self.left[oid])
            self.left[oid] -= q
            qty -= q
            trades.append((id, oid, best, q) if side == "buy" else (oid, id, best, q))
            if self.left[oid] == 0:
                heapq.heappop(other)
        if qty:
            self.left[id] = qty
            heapq.heappush(book, (-price if side == "buy" else price, self.seq, id))
            self.seq += 1
        return trades

    def _top(self, heap):
        while heap and self.left[heap[0][2]] == 0:
            heapq.heappop(heap)
        return heap[0][0] if heap else None

    def best_bid(self):
        top = self._top(self.bids)
        return None if top is None else -top

    def best_ask(self):
        return self._top(self.asks)

    def cancel(self, id):
        if self.left.get(id):
            self.left[id] = 0
            return True
        return False

def depth(orders, side, levels):
    total = {}
    for s, p, q in orders:
        if s == side and q > 0:
            total[p] = total.get(p, 0) + q
    return sorted(total.items(), reverse=side == "buy")[:levels]

```quiz
Why lazy deletion for cancels instead of removing the order from the heap?
- Heaps can't hold strings
* Removing from the middle of a heap is O(n); marking it dead and skipping it when it reaches the top is O(1) now and O(log n) later
- Cancelled orders might come back
- It's required by law
> Each dead entry is popped at most once, so the extra cost is small.
```

---solution
def candles(trades, width):
    out = []
    for t, p, q in trades:
        start = t // width * width
        if out and out[-1][0] == start:
            s, o, h, l, c, v = out[-1]
            out[-1] = (s, o, max(h, p), min(l, p), p, v + q)
        else:
            out.append((start, p, p, p, p, q))
    return out

def vwap(trades):
    vol = sum(q for _, _, q in trades)
    if vol == 0:
        return None
    return round(sum(p * q for _, p, q in trades) / vol, 2)
---tests

```recall
Q: Explain how an exchange order book matches orders: bids, asks and the spread, price-time priority, what price a trade happens at, how heaps make it fast, and how cancels work.
A: An order book holds bids (offers to buy at up to a price) and asks (offers to sell at no less than a price). The highest bid and lowest ask are separated by the spread; while they don't overlap nothing trades. A new order that crosses the spread trades immediately with resting orders by price-time priority: best price first (cheapest asks for a buyer, highest bids for a seller), and the oldest order first within a price level. Each trade happens at the resting order's price, since it was there first and the newcomer agreed to that price or better. Any unfilled remainder rests at its own limit. Each side is a heap keyed by (price, arrival) for asks and (-price, arrival) for bids, so the best order is on top in O(1) and adding or removing is O(log n). Prices are integers in cents so comparisons are exact. Cancels use lazy deletion: mark the order's remaining quantity 0 and pop it when it reaches the top. Trades feed market data: candles (open, high, low, close, volume per time bucket) and VWAP, the quantity-weighted average price.
```
