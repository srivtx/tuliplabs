## A picture is a grid of numbers

Zoom far enough into any photo and you reach squares of colour, and each square is stored as numbers. For a grey picture it's one number per pixel, from 0 for black to 255 for white. So "editing a photo" means doing arithmetic on a grid.

Nearly every classic filter is the same piece of arithmetic. Take a small grid of numbers called a **kernel**, lay it over a pixel and its neighbours, multiply each pair and add them up. That total is the new pixel. Slide along and repeat. This is **convolution**.

```viz
name: bx-kernel
title: Nine numbers, one picture
goal: Tap the numbers to build **your own edge detector**, so the sky goes black and the outlines stay. Don't use the Edges button.
height: 320
Move over the picture to see the sum for one pixel. The small numbers are the pixels under the window.
```

Here's the rule you just found. On a flat area all nine pixels hold the same value `v`, so the answer is `v × (sum of your numbers)`. If the numbers add to 0, a flat area gives 0 at any brightness. Only change survives.

If they add to 1, flat areas stay as they were and only the edges are affected, which is what sharpen does. Three kinds of filter fall out of one sum.

```predict
kernels = {
    "blur": [1, 1, 1, 1, 1, 1, 1, 1, 1],
    "sharpen": [0, -1, 0, -1, 5, -1, 0, -1, 0],
    "edges": [-1, -1, -1, -1, 8, -1, -1, -1, -1],
}
for name, k in kernels.items():
    print(name, sum(k))
```

The blur sums to 9, so we divide by 9 to keep the brightness the same.

```exercise
title: convolve
kind: write
---prompt
Write `convolve(img, k)`. `img` is a list of rows of numbers, and `k` is a 3×3 list of rows. Return a new grid of the same size, where each pixel is the sum of `k[j][i] × neighbour`, for the 3×3 neighbours around it. At the borders, use the nearest pixel that exists, by clamping the row and column into range.
---starter
def convolve(img, k):
    return [row[:] for row in img]
---solution
def convolve(img, k):
    h, w = len(img), len(img[0])
    out = []
    for y in range(h):
        row = []
        for x in range(w):
            total = 0
            for j in range(3):
                for i in range(3):
                    yy = min(h - 1, max(0, y + j - 1))
                    xx = min(w - 1, max(0, x + i - 1))
                    total += k[j][i] * img[yy][xx]
            row.append(total)
        out.append(row)
    return out
---tests
img = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
same = [[0, 0, 0], [0, 1, 0], [0, 0, 0]]
assert convolve(img, same) == img, "a single 1 in the middle changes nothing"
left = [[0, 0, 0], [1, 0, 0], [0, 0, 0]]
assert convolve(img, left) == [[1, 1, 2], [4, 4, 5], [7, 7, 8]], "copies the pixel on the left, clamped at the border"
ones = [[1, 1, 1], [1, 1, 1], [1, 1, 1]]
assert convolve([[2, 2], [2, 2]], ones) == [[18, 18], [18, 18]]
edges = [[-1, -1, -1], [-1, 8, -1], [-1, -1, -1]]
assert convolve([[7, 7], [7, 7]], edges) == [[0, 0], [0, 0]], "flat areas vanish"
assert convolve([[0, 0, 0], [0, 9, 0], [0, 0, 0]], edges)[1][1] == 72
---hint
Four nested loops: rows, columns, and the 3×3 window. `min` and `max` hold the position inside the picture.
```

One detail for later. In mathematics, true convolution flips the kernel first, and image tools usually skip the flip, which is strictly called correlation. For the symmetric kernels most filters use, the two are the same.

## Sharpen is a subtraction

Before computers, photographers sharpened pictures in the darkroom. They made a blurry copy of the negative, and printed through both at once, which subtracted the blur from the sharp image. The name stuck: the Unsharp Mask button in today's photo apps is that same trick.

Blur is what's left when detail is removed. So `original − blurred` is the detail on its own. Add some of that back and the detail grows.

```exercise
title: unsharp
kind: write
---prompt
Write `unsharp(img, blurred, amount)`. Both grids are the same size. Each new pixel is `pixel + amount × (pixel − blurred pixel)`, held between 0 and 255.
---starter
def unsharp(img, blurred, amount):
    return img
---solution
def unsharp(img, blurred, amount):
    out = []
    for row, brow in zip(img, blurred):
        out.append([min(255, max(0, p + amount * (p - b))) for p, b in zip(row, brow)])
    return out
---tests
assert unsharp([[100]], [[100]], 2) == [[100]], "no detail here, so no change"
assert unsharp([[120]], [[100]], 1) == [[140]], "detail is doubled"
assert unsharp([[80]], [[100]], 1) == [[60]], "dark details get darker"
assert unsharp([[250]], [[100]], 1) == [[255]], "held at white"
assert unsharp([[10, 20]], [[100, 20]], 1) == [[0, 20]], "held at black"
---hint
Two `zip` calls walk the rows and then the pixels side by side.
```

Notice what sharpening can't do. It adds no information. It raises contrast at edges, and your eye reads that as detail, which is why the "enhance!" moment in crime dramas is fiction.

## The fast way to blur

Press both **Wide blur** buttons, and compare. A 15 × 15 window needs 225 additions for each pixel, but the two pictures match, and the second took 30.

A box blur averages a square, and you can average a square by averaging each row and then averaging those averages down each column. Any kernel that's an outer product of a column and a row can be split like this, and the Gaussian blur in your phone is one of them.

```exercise
title: blur_two_pass
kind: write
---prompt
Write `blur_row(row, r)`: each value becomes the average of the `2r + 1` values centred on it, clamping at the ends. Then write `blur(img, r)`, which blurs every row and then every column of the result. A list of lists turns on its side with `[list(c) for c in zip(*img)]`.
---starter
def blur_row(row, r):
    return row

def blur(img, r):
    return img
---solution
def blur_row(row, r):
    n = len(row)
    out = []
    for x in range(n):
        total = 0
        for i in range(-r, r + 1):
            total += row[min(n - 1, max(0, x + i))]
        out.append(total / (2 * r + 1))
    return out

def blur(img, r):
    across = [blur_row(row, r) for row in img]
    turned = [list(c) for c in zip(*across)]
    down = [blur_row(col, r) for col in turned]
    return [list(c) for c in zip(*down)]
---tests
assert blur_row([3, 3, 3], 1) == [3, 3, 3]
assert blur_row([0, 3, 0], 1) == [1, 1, 1]
assert blur_row([0, 0, 9, 0, 0], 1) == [0, 3, 3, 3, 0]
assert blur([[5, 5], [5, 5]], 1) == [[5, 5], [5, 5]]
g = blur([[0, 0, 0], [0, 9, 0], [0, 0, 0]], 1)
assert all(abs(v - 1) < 1e-9 for row in g for v in row), "one bright pixel spreads over the 3×3 square"
assert len(blur([[1, 2, 3]], 1)) == 1 and len(blur([[1, 2, 3]], 1)[0]) == 3, "the shape stays the same"
---hint
Write `blur_row` first. Then blur the rows, turn the grid on its side, blur again, and turn it back.
```

## Finding edges, properly

A serious edge detector asks two questions at each pixel: how fast does brightness change going across, and how fast going down? Those two kernels are called **Sobel** kernels, published in 1968. Together they give the strength of the edge in any direction.

```exercise
title: sobel
kind: write
---prompt
Write `edge_at(img, x, y)` for a pixel that isn't on the border. Work out `gx` by applying the kernel `[[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]]` to the 3×3 window around it, and `gy` by applying `[[-1, -2, -1], [0, 0, 0], [1, 2, 1]]`. Return `hypot(gx, gy)`.
---starter
def edge_at(img, x, y):
    return img[y][x]
---solution
from math import hypot

def edge_at(img, x, y):
    kx = [[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]]
    ky = [[-1, -2, -1], [0, 0, 0], [1, 2, 1]]
    gx = gy = 0
    for j in range(3):
        for i in range(3):
            p = img[y + j - 1][x + i - 1]
            gx += kx[j][i] * p
            gy += ky[j][i] * p
    return hypot(gx, gy)
---tests
flat = [[9, 9, 9], [9, 9, 9], [9, 9, 9]]
assert edge_at(flat, 1, 1) == 0, "flat: no edge"
wall = [[0, 0, 10], [0, 0, 10], [0, 0, 10]]
assert edge_at(wall, 1, 1) == 40, "a vertical edge"
shelf = [[0, 0, 0], [0, 0, 0], [10, 10, 10]]
assert edge_at(shelf, 1, 1) == 40, "a horizontal edge"
corner = [[0, 0, 0], [0, 0, 10], [0, 10, 10]]
assert edge_at(corner, 1, 1) > 0
---hint
Walk the window once, keeping two running totals. The window's top-left pixel is at `(x - 1, y - 1)`.
```

## You're running this filter right now

Here's where it stops being about software. Light-sensing cells at the back of your eye feed into cells that compare a small centre with the ring around it. Light in the centre excites them, and light in the ring quiets them. Stephen Kuffler measured this in 1953, and H. Keffer Hartline shared a 1967 Nobel Prize for work on the same idea, known as lateral inhibition.

Look at that as a kernel. A positive middle with a negative ring is the sharpen filter, built from neurons.

```viz
name: bx-retina
title: The filter you can't turn off
goal: Say which square looks lighter, then press **Cover the surroundings** to test it.
height: 420
The blue line is the real brightness along the middle of the picture. The red line is a simple model of what the retina reports.
```

So you don't see brightness, you see **differences**. Why would evolution build an eye that misreports the world? Each eye has over 100 million light-sensing cells, and only about a million fibres in the optic nerve. It can't send everything. Most of any scene is smooth, and differences hold most of the information, so sending differences is a compression scheme. It also means a white page still looks white in dim light, because the ratios survive when the total doesn't.

## What the brain does next

In the late 1950s, David Hubel and Torsten Wiesel recorded single cells in a cat's visual cortex. These cells fired for an edge at one particular angle, and that work earned them a Nobel Prize in 1981. Those cells are Sobel kernels, more or less.

Now look at modern AI. A convolutional neural network is stacks of kernels, like the ones you've just tapped in, except nobody picks the numbers: training does. When AlexNet won a famous image contest in 2012, people looked inside its first layer, and found edge detectors at various angles. Nobody told it to build them. Biology and gradient descent reached the same answer, because edges are where the information in a picture is.

Convolution works on sound too. Clap in a cathedral and record the echo, and that recording is a kernel. Convolve any dry sound with it and that sound seems to be in the cathedral. This is how studios get real rooms into a recording.

```exercise
title: reverb
kind: write
---prompt
Write `echo(sound, impulse)`, one-dimensional convolution. The output has `len(sound) + len(impulse) - 1` samples, and every `sound[i]` adds `sound[i] × impulse[j]` into `out[i + j]`.
---starter
def echo(sound, impulse):
    return list(sound)
---solution
def echo(sound, impulse):
    out = [0] * (len(sound) + len(impulse) - 1)
    for i, s in enumerate(sound):
        for j, r in enumerate(impulse):
            out[i + j] += s * r
    return out
---tests
assert echo([1, 2, 3], [1]) == [1, 2, 3], "a dead room changes nothing"
assert echo([1], [1, 0, 0.5]) == [1, 0, 0.5], "a clap gives back the room itself"
assert echo([1, 1], [1, 0.5]) == [1, 1.5, 0.5], "echoes overlap and add"
assert echo([2, 0, 1], [0, 1]) == [0, 2, 0, 1], "a delay"
---hint
Make the output list first, full of zeros. Each sample stamps a scaled copy of the impulse into it.
```

Look at the second test. A clap gives back the room itself. Every sound that passes through a room is convolved with it.

## Real-world project: a document scanner

```project
title: cleanscan, a phone scanner for clinic forms
client: A rural clinic that photographs paper forms on phones, in bad light, and needs clean black-and-white pages that staff can read and file
skills: convolution, blur, background removal, adaptive thresholds, batch processing
---brief
Build `cleanscan.py`. Load a photo of a page as a grey grid. A single cut-off for black and white fails, because a shadow across the page is darker than ink in the bright corner. So compare each pixel with a wide blur of its own surroundings: the blur estimates the paper at that spot. Pixels well below it are ink. Then remove specks, and report how much of each page is ink, so that blank or failed photos can be flagged.
---why
This is how real scanning apps and copiers handle uneven light. The method is called adaptive thresholding. It's the same trick as your retina: compare with the neighbours, not with a fixed number.
---milestones
- Load a picture as a grid
- Wide blur for the paper estimate
- Adaptive threshold
- Remove specks
- Flag blank pages
---stretch
- Straighten a tilted page by finding its edges
- Use an integral image to make the blur cost the same at any width
```

## Rebuild it and explain it

```exercise

---prompt
From memory: `convolve(img, k)` with a 3×3 kernel, the same output size, and clamped borders.

---solution
def convolve(img, k):
    h, w = len(img), len(img[0])
    out = []
    for y in range(h):
        row = []

            total = 0
```

```recall
Q: Explain what convolution is, why a kernel whose numbers add to zero finds edges, why a wide blur can be split into two passes, and why you can't see true brightness.
A: Convolution slides a small grid of numbers over a picture, and each new pixel is its neighbours multiplied by those numbers and added up. Blur, sharpen and edge detection are the same loop with different numbers. On a flat area every pixel equals v, so the result is v times the sum of the kernel; if the numbers add to zero that's zero at any brightness, so only places where neighbours differ survive, and those are edges. A box blur averages a square, which is the same as averaging each row and then averaging those down the columns, so n squared sums per pixel become 2n and the picture doesn't change. The retina does something similar with cells that compare a centre with its surround, a sharpen filter made of neurons. It can't send every sensor's value down the optic nerve, so it sends differences. That's why two identical greys look different on different backgrounds and why flat bands show Mach bands at their edges. Neural networks that learn their own kernels end up with edge detectors too.
```
