## Two problems: finding and ranking

A search engine has to do two things fast:

1. **Find** every document that contains the query's words, without reading the whole collection for every query.
2. **Rank** them so the most useful ones come first, even though most matching documents share boring words like *the*.

The trick for finding is the **inverted index**: a dictionary built ahead of time, from each word to the list of documents containing it. It's the same idea as the index at the back of a book. The trick for ranking is to weigh each word by how **rare** it is.

## Words in, words out: tokenizing

Before indexing, text is split into **tokens**: lower-case it, keep runs of letters and digits, and drop punctuation. Real engines also **stem** (`running` → `run`) and sometimes drop **stop words** like *the*, but lower-casing alone fixes the most common mismatches.

```exercise

def tokenize(text):
    return re.findall(r"[a-z0-9]+", text.lower())

---hint
```

## The inverted index

```predict
docs = ["the cat sat", "the dog", "cat and dog"]
index = {}
for i, d in enumerate(docs):
    for w in set(d.split()):
        index.setdefault(w, []).append(i)
print(index["cat"], index["dog"], index["the"])
```

Each list of document ids is a **posting list**. Building the index visits every word once; after that, any query just looks up lists.

```exercise
title: build_index
kind: write
---prompt
Write `build_index(docs)` taking a list of strings and returning a dict from each token (use the provided `tokenize`) to a **sorted list of document numbers** (positions in `docs`) containing it, with no duplicates.
---setup
def tokenize(text):
    return re.findall(r"[a-z0-9]+", text.lower())
---starter
def build_index(docs):
    return {}
---solution
def build_index(docs):
    index = {}
    for i, doc in enumerate(docs):
        for w in set(tokenize(doc)):
            index.setdefault(w, []).append(i)
    return index
---tests
idx = build_index(["The cat sat on the mat.", "The dog chased the cat!", "Dogs are friends"])
assert idx["cat"] == [0, 1], "cat is in docs 0 and 1"
assert idx["the"] == [0, 1], "no duplicates even though 'the' appears twice in each"
assert idx["dogs"] == [2] and idx["dog"] == [1], "no stemming: dog and dogs are different tokens"
assert "The" not in idx, "tokens are lower-case"
---hint
Loop over documents in order, and over the **set** of tokens in each, so each document is added to a list at most once. Lists stay sorted because you visit documents in order.
```

## AND queries: merging posting lists

To find documents with *every* query word, intersect their posting lists. Because the lists are sorted, you can walk two of them side by side with two pointers, advancing whichever is behind. That takes time proportional to the lists' lengths, and never needs a set.

```parsons
            j += 1
```

```exercise
---solution
def search_and(index, query):
    words = tokenize(query)
    if not words:
        return []
    lists = sorted((index.get(w, []) for w in words), key=len)
    result = lists[0]
    for lst in lists[1:]:
        result = intersect(result, lst)
    return result
```

## Ranking: TF-IDF

Finding isn't enough: a web search for *the cat* matches billions of pages. Each document gets a score, summed over the query words:

    score(doc) = Σ  tf(word, doc) × idf(word)
    tf  = how many times the word appears in this document
    idf = log(N / df)     N = number of documents, df = how many contain the word

A word in every document has idf = log(1) = 0: it says nothing about which document you want. A rare word has a large idf: if a document contains it, that's a strong signal.

```exercise
title: idf_bug
kind: bug
---prompt
`idf(word, index, n_docs)` is supposed to be large for **rare** words and zero for words in every document. This version ranks common words above rare ones. Fix it.
---starter
def idf(word, index, n_docs):
    df = len(index.get(word, []))
    if df == 0:

    return math.log(df / n_docs) + 1
---solution
def idf(word, index, n_docs):
    df = len(index.get(word, []))
    if df == 0:
        return 0.0
    return math.log(n_docs / df)
---tests
index = {"the": [0, 1, 2, 3], "cat": [0, 2], "zebra": [3]}
assert idf("the", index, 4) == 0, "a word in every document carries no information"
assert abs(idf("cat", index, 4) - math.log(2)) < 1e-12
assert idf("zebra", index, 4) > idf("cat", index, 4) > idf("the", index, 4), "rarer means bigger"
assert idf("unicorn", index, 4) == 0, "unknown words score nothing"
---hint
The fraction is upside down, and the `+ 1` shouldn't be there. What's log(N / df) when df = N?
```

```exercise
title: tfidf_scores
kind: write
---prompt
Write `tfidf_scores(docs, query)` returning a list with one score per document: the sum over query tokens of `tf × idf`, with `idf = log(N / df)` (0 for words in no document). Use the provided `tokenize`. A word repeated in the query counts once.
---setup
def tokenize(text):
    return re.findall(r"[a-z0-9]+", text.lower())
---starter
def tfidf_scores(docs, query):
    return [0.0] * len(docs)
---solution
def tfidf_scores(docs, query):
    toks = [Counter(tokenize(d)) for d in docs]
    n = len(docs)
    scores = [0.0] * n
    for w in set(tokenize(query)):
        df = sum(1 for t in toks if w in t)
        if df == 0:
            continue
        idf = math.log(n / df)
        for i, t in enumerate(toks):
            scores[i] += t[w] * idf
    return scores
---tests
docs = ["the cat sat on the mat", "the dog chased the cat", "a cat and a dog", "the mat is red", "the end"]
s = tfidf_scores(docs, "the cat")
the, cat = math.log(5 / 4), math.log(5 / 3)
assert abs(s[0] - (2 * the + cat)) < 1e-9 and abs(s[2] - cat) < 1e-9, s
s = tfidf_scores(docs, "red mat")
assert max(range(5), key=lambda i: s[i]) == 3, "doc 3 has both rare words"
assert tfidf_scores(docs, "unicorn") == [0.0] * 5, "unknown word"
---hint
Count tokens per document with `Counter`. For each distinct query word, compute its df and idf, then add `count × idf` to every document's score.
```

## Real-world project: site search for a docs website

```project

Even the biggest engines keep the same skeleton, an inverted index plus a scoring function, and then pile on more signals (links, freshness, clicks). - Top-k search with TF-IDF (the exercise below)
- Snippets: pick the sentence with the most query tokens and bold them

- Save and load the index; time a query
---stretch
- Stemming (a simple suffix stripper for `-s`, `-ing`, `-ed`)
- Phrase queries in quotes, using word **positions** in the posting lists
```

```exercise
title: SearchEngine
kind: write
---prompt
Write a class `SearchEngine` with `add(doc_id, text)` and `search(query, k=3)`. `search` returns up to `k` doc ids with a **positive** TF-IDF score (as in this chapter: `idf = log(N / df)` over the documents added so far), best first, breaking ties by the order the documents were added. `tokenize` is provided.
---setup
def tokenize(text):
    return re.findall(r"[a-z0-9]+", text.lower())
---starter
class SearchEngine:
    def __init__(self):
        pass

    def add(self, doc_id, text):
        pass

    def search(self, query, k=3):
        return []
---solution
class SearchEngine:
    def __init__(self):
        self.ids, self.tf, self.index = [], [], {}

    def add(self, doc_id, text):
        n = len(self.ids)
        self.ids.append(doc_id)
        counts = Counter(tokenize(text))
        self.tf.append(counts)
        for w in counts:
            self.index.setdefault(w, []).append(n)

    def search(self, query, k=3):
        n = len(self.ids)
        scores = {}
        for w in set(tokenize(query)):
            postings = self.index.get(w, [])
            if not postings:
                continue
            idf = math.log(n / len(postings))
            for d in postings:
                scores[d] = scores.get(d, 0.0) + self.tf[d][w] * idf
        ranked = sorted((d for d in scores if scores[d] > 0), key=lambda d: (-scores[d], d))
        return [self.ids[d] for d in ranked[:k]]
---tests
se = SearchEngine()
se.add("install", "Installing the library: run pip install on the command line")
se.add("config", "The config file sets the log level and the cache size")
se.add("cache", "The cache keeps recent results. Clear the cache to free memory")
se.add("faq", "Questions about the library, install problems and the cache")
assert se.search("cache") == ["cache", "config", "faq"], se.search("cache")
assert se.search("install") == ["install", "faq"], "only documents that score above zero"
assert se.search("the") == [], "'the' is everywhere: idf is 0, so nothing scores"
assert se.search("cache install", k=1) == ["faq"], "faq is the only page with both words"
---hint
Keep, per document, a `Counter` of its tokens, and an inverted index from word to document positions. At query time, accumulate scores only for documents in the query words' posting lists.
---hint
Sort by `(-score, position)` so higher scores come first and ties keep insertion order.
```

```recall
Q: Explain how a search engine finds and ranks documents quickly, and why rare words count for more.
A: Ahead of time, every document is tokenized (lower-cased, split into words, often stemmed) and an inverted index is built: for each word, a sorted posting list of the documents containing it. A query is tokenized the same way, and only the posting lists for its words are read, so the cost depends on those lists, not on the size of the collection; AND queries intersect sorted lists with two pointers. To rank, each document is scored by TF-IDF: for each query word, how often it appears in the document times log(N / df), where df is how many documents contain it. A word in every document has idf 0 and can't tell documents apart, while a rare word is strong evidence of relevance, so documents win by containing the distinctive query words rather than filler. Real engines add more signals, like links (PageRank), titles and freshness, on top of the same skeleton.
```
