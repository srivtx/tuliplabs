```prelude
import bisect
import math
import re

MAX_KEYS = 3

def bt_node(keys=None, vals=None, kids=None):
    return {"keys": keys or [], "vals": vals or [], "kids": kids or []}

def _bt_split(node):
    m = len(node["keys"]) // 2
    left = bt_node(node["keys"][:m], node["vals"][:m], node["kids"][:m + 1])
    right = bt_node(node["keys"][m + 1:], node["vals"][m + 1:], node["kids"][m + 1:])
    return left, node["keys"][m], node["vals"][m], right

def _bt_ins(node, key, val):
    i = bisect.bisect_left(node["keys"], key)
    if i < len(node["keys"]) and node["keys"][i] == key:
        node["vals"][i] = val
        return None
    if not node["kids"]:
        node["keys"].insert(i, key)
        node["vals"].insert(i, val)
    else:
        r = _bt_ins(node["kids"][i], key, val)
        if r:
            left, k, v, right = r
            node["kids"][i:i + 1] = [left, right]
            node["keys"].insert(i, k)
            node["vals"].insert(i, v)
    if len(node["keys"]) > MAX_KEYS:
        return _bt_split(node)
    return None

def bt_insert(root, key, val):
    r = _bt_ins(root, key, val)
    if r:
        left, k, v, right = r
        return bt_node([k], [v], [left, right])
    return root

def bt_height(node):
    return 1 + bt_height(node["kids"][0]) if node["kids"] else 1
```

## What happens when you type SELECT

SQLite is a single C file that runs on billions of phones. Underneath the SQL, its job is simple to say and hard to do well: keep rows on disk so that finding one, or a range of them, takes as few disk reads as possible.

The trick is the **B-tree**. Disks (and SSDs) read whole **pages**, typically 4 KB at a time. A B-tree packs hundreds of sorted keys into each page-sized node, so the tree is very short and very wide. Grow one yourself.

```viz

goal: Insert rows until the tree is **3 levels** tall, then **Search** for a key that's in it.
height: 470
Each block is a key; keys side by side are one node (one disk page, here with room for only 3 keys). Insert and watch nodes split.
```

```quiz
How does a B-tree get taller?
- A new level is added under the leaves when they're full
* The root splits: its middle key becomes a new root above it, so every leaf moves down one level together
- Each insert adds one level
- It never gets taller; it only gets wider
> Growing at the top is the whole secret of B-tree balance. Every path from root to leaf always has the same length, so the worst-case lookup is always the height: a few page reads, however unlucky the insert order.
```

## Why not a list, or a hash table?

- A **sorted list** gives fast lookups (binary search) but inserting in the middle shifts everything after it, and on disk that means rewriting pages.
- A **hash table** (chapter 6) finds one key fast but can't do `WHERE id BETWEEN 100 AND 200` or `ORDER BY` without reading everything.
- A **B-tree** keeps keys sorted (ranges are easy), inserts touch only a few pages, and lookups read `height` pages.

How short is "short"? Count the levels needed for a million rows.

```predict
rows = 1_000_000
print("binary tree levels:", math.ceil(math.log2(rows)))
print("B-tree levels, 100 keys per page:", round(math.log(rows, 100)))
print("B-tree levels, 500 keys per page:", math.ceil(math.log(rows, 500)))
```

Twenty disk reads versus three. That's the difference between a slow and an instant query.

## Searching

A node is `{"keys": [...], "vals": [...], "kids": [...]}`. Keys are sorted. In an internal node, `kids[i]` holds everything smaller than `keys[i]`, and `kids[-1]` everything bigger than the last key. A leaf has no kids.

```exercise
title: bt_search
kind: write
---prompt
Write `bt_search(node, key)` returning `(value, pages)`: the value stored under `key` (or `None` if it isn't there) and the number of nodes visited. Use `bisect.bisect_left(node["keys"], key)` to find your place in each node.
---starter
def bt_search(node, key):
    return None, 0
---solution
def bt_search(node, key):
    pages = 0
    while True:
        pages += 1
        i = bisect.bisect_left(node["keys"], key)
        if i < len(node["keys"]) and node["keys"][i] == key:
            return node["vals"][i], pages
        if not node["kids"]:
            return None, pages
        node = node["kids"][i]
---tests
root = bt_node()
for k in [20, 5, 33, 12, 41, 8, 27, 1, 15, 38, 3, 30, 22]:
    root = bt_insert(root, k, f"row {k}")
assert bt_search(root, 27)[0] == "row 27", "finds a key"
assert bt_search(root, 26)[0] is None, "a missing key returns None"
v, pages = bt_search(root, 1)
assert v == "row 1" and pages <= bt_height(root), f"never reads more pages than the height ({bt_height(root)}); read {pages}"
---hint
Loop: count a page, `bisect_left` to find `i`, return if `keys[i] == key`, stop at a leaf, otherwise go down into `kids[i]`.
```

## Splitting

When a node holds one key too many, it splits: the middle key goes **up** to the parent, the keys on its left become one node, the keys on its right another. Children split the same way: a node with 4 keys has 5 children, and the left half takes the first 3.

```exercise
title: split
kind: write
---prompt
Write `split(node)` returning `(left, middle_key, middle_val, right)`. With `m = len(keys) // 2`: the left node gets keys/vals before `m` and kids up to and including `m`; the right gets keys/vals after `m` and the kids after `m`. Build nodes with `bt_node(keys, vals, kids)`.
---starter
def split(node):
    return node, None, None, bt_node()
---solution
def split(node):
    m = len(node["keys"]) // 2
    left = bt_node(node["keys"][:m], node["vals"][:m], node["kids"][:m + 1])
    right = bt_node(node["keys"][m + 1:], node["vals"][m + 1:], node["kids"][m + 1:])
    return left, node["keys"][m], node["vals"][m], right
---tests
leaf = bt_node([1, 2, 3, 4], ["a", "b", "c", "d"])
l, k, v, r = split(leaf)
assert (l["keys"], k, v, r["keys"]) == ([1, 2], 3, "c", [4]), "the middle key goes up"
kids = [bt_node([x]) for x in range(5)]
inner = bt_node([10, 20, 30, 40], list("abcd"), kids)
l, k, v, r = split(inner)
assert len(l["kids"]) == 3 and len(r["kids"]) == 2, "3 children go left, 2 go right"
assert len(l["kids"]) == len(l["keys"]) + 1 and len(r["kids"]) == len(r["keys"]) + 1, "every internal node has one more child than keys"
---hint
Slices: `keys[:m]` and `keys[m + 1:]` for the halves, `kids[:m + 1]` and `kids[m + 1:]` for the children.
```

The full insert (provided in this chapter as `bt_insert`) walks down to a leaf, inserts in order, and splits on the way back up if needed. If the root splits, a new root holds just the middle key. Watch the height grow slowly:

```run

root = bt_node()
for k in range(1, 1001):
    root = bt_insert(root, k, None)
    if k in (3, 4, 10, 30, 100, 1000):
        print(k, "rows -> height", bt_height(root))
```

## Reading SQL

SQL is a language, so a database needs a parser (chapters 2, 4, 5). We'll handle one shape: `SELECT cols FROM table` with an optional `WHERE col op value`, where op is `=`, `<` or `>`.

```exercise
title: parse_select
kind: write
---prompt
Write `parse_select(sql)` returning a dict `{"columns": [...], "table": name, "where": (col, op, value) or None}`. Columns are comma-separated (strip spaces; `*` gives `["*"]`). The value is an `int` if it's all digits, otherwise a string with any surrounding single quotes removed. Keywords may be any case.
---starter
def parse_select(sql):
    return {"columns": [], "table": "", "where": None}
---solution
def parse_select(sql):
    m = re.match(r"\s*select\s+(.+?)\s+from\s+(\w+)(?:\s+where\s+(\w+)\s*(=|<|>)\s*(\S+))?\s*;?\s*$", sql, re.I)
    if not m:
        raise SyntaxError(sql)
    cols = [c.strip() for c in m.group(1).split(",")]
    where = None
    if m.group(3):
        raw = m.group(5)
        value = int(raw) if raw.isdigit() else raw.strip("'")
        where = (m.group(3), m.group(4), value)
    return {"columns": cols, "table": m.group(2), "where": where}
---tests
q = parse_select("SELECT name, age FROM users WHERE age > 30")
assert q == {"columns": ["name", "age"], "table": "users", "where": ("age", ">", 30)}, f"got {q}"
assert parse_select("select * from books")["where"] is None and parse_select("select * from books")["columns"] == ["*"], "no WHERE"
assert parse_select("SELECT title FROM books WHERE genre = 'scifi'")["where"] == ("genre", "=", "scifi"), "strings lose their quotes"
---hint
One regular expression with groups is enough: `select (cols) from (table)` and an optional `where (col) (op) (value)` part. Use `re.I` for any case.
```

## Range queries: why sorted matters

`WHERE id BETWEEN 10 AND 20` on a B-tree: walk the tree **in order** (left child, key, next child, …) and skip subtrees that can't contain anything in range. A hash index can't do this; a B-tree does it naturally because the keys are sorted.

```parsons
title: In-order walk
---lines
def in_order(node, out):
    for i, key in enumerate(node["keys"]):
        if node["kids"]:
            in_order(node["kids"][i], out)
        out.append(key)
    if node["kids"]:
        in_order(node["kids"][-1], out)
    return out
?? in_order(node["kids"][0], out)
---tests
root = bt_node()
for k in [9, 2, 7, 4, 1, 8, 3, 6, 5]:
    root = bt_insert(root, k, None)
assert in_order(root, []) == list(range(1, 10)), "keys come out sorted"
```

```exercise
title: Catalogue
kind: write
---prompt
Write a class `Catalogue` with `add(row)` (insert into a B-tree keyed by `row["id"]`, using `bt_insert`), `get(id)` returning the row or `None`, and `between(lo, hi)` returning the rows with `lo <= id <= hi` in id order. For `between`, walk the tree in order but **skip** child subtrees that can't overlap the range.
---starter
class Catalogue:
    def __init__(self):
        self.root = bt_node()

    def add(self, row):
        pass

    def get(self, id):
        return None

    def between(self, lo, hi):
        return []
---solution
class Catalogue:
    def __init__(self):
        self.root = bt_node()

    def add(self, row):
        self.root = bt_insert(self.root, row["id"], row)

    def get(self, id):
        node = self.root
        while True:
            i = bisect.bisect_left(node["keys"], id)
            if i < len(node["keys"]) and node["keys"][i] == id:
                return node["vals"][i]
            if not node["kids"]:
                return None
            node = node["kids"][i]

    def between(self, lo, hi):
        out = []
        def walk(node):
            keys = node["keys"]
            for i, k in enumerate(keys):
                if node["kids"] and lo < k:
                    walk(node["kids"][i])
                if lo <= k <= hi:
                    out.append(node["vals"][i])
                if k > hi:
                    return
            if node["kids"] and keys[-1] < hi:
                walk(node["kids"][-1])
        walk(self.root)
        return out
---tests
cat = Catalogue()
for i in [50, 3, 77, 12, 64, 29, 91, 8, 45, 33, 70, 18, 2, 99, 56]:
    cat.add({"id": i, "title": f"Book {i}"})
assert cat.get(64)["title"] == "Book 64" and cat.get(65) is None, "get by id"
assert [r["id"] for r in cat.between(10, 50)] == [12, 18, 29, 33, 45, 50], "range in order"
assert [r["id"] for r in cat.between(100, 200)] == [], "empty range"
assert [r["id"] for r in cat.between(0, 1000)] == sorted([50, 3, 77, 12, 64, 29, 91, 8, 45, 33, 70, 18, 2, 99, 56]), "everything"
---hint
`add` is one line with `bt_insert`. `get` is your `bt_search` without the page count.
---hint
For `between`, adapt the in-order walk: only go into `kids[i]` when `lo < keys[i]` (something in there could be ≥ lo), stop once a key is past `hi`, and only visit the last child if the last key is below `hi`.
```

```recall
Q: Explain why databases index tables with B-trees, how a B-tree stays balanced, and when an index doesn't help.
A: Storage reads whole pages, so the goal is to touch as few pages as possible. A B-tree packs hundreds of sorted keys into each page-sized node, so the tree is only a few levels deep even for billions of rows; a lookup reads one node per level. Because keys are sorted, range queries and ORDER BY are an in-order walk, which a hash index can't do. It stays balanced because inserts go into leaves, and an overfull node splits and pushes its middle key up; only a root split adds a level, so every leaf is always at the same depth. An index doesn't help for conditions on columns it doesn't cover (that's a full scan), for queries that return most of the table, and it costs extra work on every insert.
```
