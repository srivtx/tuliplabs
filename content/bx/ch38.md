## Money never appears or disappears

A naive bank keeps one number per account and edits it: "take 80 from Cara, add 80 to Alice". That's two separate writes. If the server dies between them, 80 is gone, and because only the balances were kept, nobody can tell where it went.

Accountants solved this 500 years ago. **Double-entry bookkeeping** writes every movement as one **entry** made of **lines**, each line an account and an amount. Money out is negative, money in is positive, and **the lines of an entry always add up to zero**. The entry is posted as a whole or not at all.

Then a balance isn't stored at all: it's the **sum of that account's lines** in the journal. The total of every account is always zero (or, counting the money customers brought in, always the same), so a bug can't hide.


The journal is **append-only**. You never edit or delete a line; a mistake is fixed by posting a new entry that reverses it. That gives you a complete history for free: "what was Alice's balance on 1 March?" is just a sum of the lines dated up to then.

## Posting entries

```exercise
title: post_entry
kind: write
---prompt
Write `Ledger` with `post(memo, lines)`, where `lines` is a list of `(account, amount)` pairs in whole cents, and `balance(account)`. `post` raises `ValueError` if there are fewer than two lines, any amount is zero, or the amounts don't sum to zero; otherwise it appends the entry `(memo, lines)` to `self.journal`. `balance` is the sum of that account's amounts across the whole journal (0 for an account never seen).
---starter
class Ledger:
    def __init__(self):
        self.journal = []
        self.balances = {}

    def post(self, memo, lines):
        for account, amount in lines:
            self.balances[account] = self.balances.get(account, 0) + amount

    def balance(self, account):
        return self.balances.get(account, 0)
---solution
class Ledger:
    def __init__(self):
        self.journal = []

    def post(self, memo, lines):
        if len(lines) < 2:
            raise ValueError("an entry needs at least two lines")
        if any(amount == 0 for _, amount in lines):
            raise ValueError("zero line")
        if sum(amount for _, amount in lines) != 0:
            raise ValueError("entry does not balance")
        self.journal.append((memo, list(lines)))

    def balance(self, account):
        return sum(a for _, lines in self.journal for acc, a in lines if acc == account)
---tests
L = Ledger()
L.post("open", [("cash", -1000), ("alice", 1000)])
L.post("pay bob", [("alice", -250), ("bob", 250)])
assert L.balance("alice") == 750 and L.balance("bob") == 250 and L.balance("cash") == -1000
assert L.balance("nobody") == 0
for bad in ([("alice", -100), ("bob", 90)], [("alice", -5)], [("alice", 0), ("bob", 0)]):
    try:
        L.post("bad", bad)
        assert False, f"should reject {bad}"
    except ValueError:
        pass
assert L.balance("alice") == 750, "a rejected entry changes nothing"
assert len(L.journal) == 2
L.post("split", [("alice", -300), ("bob", 100), ("cara", 200)])
assert L.balance("cara") == 200 and L.balance("alice") == 450
---hint
The starter edits balances line by line and never checks anything. Check the whole entry first, then append it in one go.
---hint
`balance` doesn't need its own storage: loop over every entry, every line, and add the amounts for that account.
```

That second line is why money is stored as **whole cents** (or the smallest unit of the currency), never as floats. `0.1` has no exact binary form, so tiny errors pile up across millions of transactions.

```exercise
def split(total, n):
    q, r = divmod(total, n)
    return [q + 1] * r + [q] * (n - r)
```

## Accounts with rules

```exercise

---prompt

---solution
class Bank:
    def __init__(self):
        self.journal = []
        self.accounts = set()

    def open(self, name):
        self.accounts.add(name)

    def _post(self, lines):
        for acc, _ in lines:
            if acc != "cash" and acc not in self.accounts:
                raise KeyError(acc)
        self.journal.append(lines)

    def deposit(self, name, cents):
        self._post([("cash", -cents), (name, cents)])

    def transfer(self, src, dst, cents):
        if dst not in self.accounts:
            raise KeyError(dst)
        if self.balance(src) - cents < 0:
            raise ValueError("insufficient funds")
        self._post([(src, -cents), (dst, cents)])

    def balance(self, name):
        if name != "cash" and name not in self.accounts:
            raise KeyError(name)
        return sum(a for e in self.journal for acc, a in e if acc == name)

    def check(self):
        return all(sum(a for _, a in e) == 0 for e in self.journal)
---tests
b = Bank()
for n in ("alice", "bob"):
    b.open(n)
b.deposit("alice", 5000)
b.transfer("alice", "bob", 1200)
assert b.balance("alice") == 3800 and b.balance("bob") == 1200
assert b.balance("cash") == -5000
try:
    b.transfer("bob", "alice", 9999)
    assert False, "overdraft"
except ValueError:
    pass
assert b.balance("bob") == 1200 and len(b.journal) == 2, "a refused transfer posts nothing"
assert b.check()
try:
    b.transfer("alice", "zed", 1)
    assert False
except KeyError:
    pass
assert b.balance("alice") == 3800
b.journal.append([("alice", 100)])
assert not b.check(), "a one-sided line is caught"
---hint
The starter posts a transfer as two separate one-line entries, and `check` never looks. Make a transfer one two-line entry, and check funds and accounts before posting.
---hint
`check` is one line: every entry's amounts must sum to zero.
```

## Quick-fire: lock it in

```quiz
A transfer debits one account and then the server crashes before crediting the other. With double-entry and atomic posting, what happens?
- Half the transfer is saved, and a nightly job fixes it
* Nothing is saved: the entry is posted as a whole or not at all, so it can simply be retried
- The money goes to a suspense account
- The total goes negative
```

## Real-world project: a wallet ledger

```project
title: pocket, a ledger for a prepaid wallet app
client: A small fintech running a prepaid card for students, whose current "balance" column has drifted from what the card processor says three times this quarter
skills: an append-only journal, entries that sum to zero, integer cents, atomic posting, reversals, reconciliation
---brief
Build `pocket.py` with a SQLite journal of entries and lines. Top-ups, card payments, refunds and fees are all entries; balances are sums, cached per account but rebuilt from the journal on demand. Posting runs in one database transaction, so a crash leaves nothing half-written. A `reconcile` command compares the ledger with the processor's daily CSV and lists every mismatch.
---why
Stripe, Monzo, Wise and every core banking system work this way. "Our numbers don't match" is one of the most expensive bugs a money business can have, and the journal is how you find out why.
---milestones
- Post balanced entries; reject unbalanced ones
- Balances as sums of the journal, in integer cents
- Atomic posting in a SQLite transaction
- Reversals instead of edits
- Reconciliation against an external statement
---stretch
- Balance on any past date
- Multiple currencies, with an FX account so each currency balances on its own
```

```exercise
title: reconcile
kind: write
---prompt
Write `reconcile(ours, theirs)`. Both are lists of `(payment_id, cents)`. Return a dict with three sorted lists: `"missing"` (ids the processor has and we don't), `"extra"` (ids we have and the processor doesn't) and `"wrong"` (ids in both with different amounts). An id appears at most once in each list.
---starter
def reconcile(ours, theirs):
    a, b = dict(ours), dict(theirs)
    return {"missing": [], "extra": [], "wrong": [k for k in a if k in b and a[k] != b[k]]}
---solution
def reconcile(ours, theirs):
    a, b = dict(ours), dict(theirs)
    return {
        "missing": sorted(set(b) - set(a)),
        "extra": sorted(set(a) - set(b)),
        "wrong": sorted(k for k in a if k in b and a[k] != b[k]),
    }
---tests
ours = [("p1", 500), ("p2", 1200), ("p4", 99)]
theirs = [("p1", 500), ("p2", 1250), ("p3", 700)]

assert reconcile(ours, ours) == {"missing": [], "extra": [], "wrong": []}
assert reconcile([], [("z", 1), ("a", 2)])["missing"] == ["a", "z"]
---hint
The starter only finds wrong amounts. Set differences give the other two.
```

```recall
Q: Explain how a double-entry ledger works and why banks use it: entries and lines, the zero-sum rule, atomic posting, balances as sums, integer cents, and reversals.
A: Every movement of money is one journal entry made of two or more lines, each an account and a signed amount: money out negative, money in positive. The lines of an entry must add up to zero, so money is only ever moved, never created or lost. An entry is posted as a single write, all lines or none, so a crash can't leave one side without the other; it can just be retried. Balances aren't stored as the truth: an account's balance is the sum of its lines, so it can always be recomputed and checked, and the sum over all accounts never changes. Amounts are kept as whole cents because floats can't represent most decimal amounts exactly. The journal is append-only: a mistake is corrected with a new entry that reverses it, which keeps a full, auditable history and lets you compute any balance at any past date.
```
