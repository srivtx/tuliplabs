## What happens when you press Enter

You type `git commit -am "fix typo" --no-verify`. Two programs share the work:

1. **The shell** splits the line into **tokens** (`argv`): spaces separate, quotes group, backslashes escape. The quotes never reach git; it gets `["git", "commit", "-am", "fix typo", "--no-verify"]`.
2. **The program's parser** reads those tokens left to right, using a **spec**: which names are on/off **flags**, which **options** take a value, which **subcommands** exist.

The conventions are old and nearly universal:

- `--name=value` or `--name value` for a long option.
- `-v` for a short flag, and `-vq` for two at once.
- `--` means "options end here": everything after is plain text, even `--draft`. That's how you delete a file called `-rf`.
- `-h` / `--help` prints usage. Exit code **0** means success, **1** a runtime error, **2** a usage error (that's what argparse uses).

## Tokens first

```exercise
title: split_args
kind: write
---prompt
Write `split_args(line)`, a small version of the shell's splitting (Python's `shlex.split`). Spaces separate tokens. Text in double or single quotes is one token piece, spaces included, and the quotes are dropped. A backslash outside quotes makes the next character literal. `""` on its own is an empty token.
---starter
def split_args(line):
    return line.split()
---solution
def split_args(line):
    tokens, cur, quote, started, i = [], "", None, False, 0
    while i < len(line):
        ch = line[i]
        if quote:
            if ch == quote:
                quote = None
            else:
                cur += ch
        elif ch in "\"'":
            quote, started = ch, True
        elif ch == "\\" and i + 1 < len(line):
            i += 1
            cur += line[i]
            started = True
        elif ch == " ":
            if started:
                tokens.append(cur)
            cur, started = "", False
        else:
            cur += ch
            started = True
        i += 1
    if quote:
        raise ValueError("unclosed quote")
    if started:
        tokens.append(cur)
    return tokens
---tests
assert split_args('todo add "buy milk" --due=fri') == ["todo", "add", "buy milk", "--due=fri"]
assert split_args("echo 'it is'   fine") == ["echo", "it is", "fine"]
assert split_args(r"rm my\ file.txt") == ["rm", "my file.txt"]
assert split_args('say "" ok') == ["say", "", "ok"]
assert split_args('a"b c"d') == ["ab cd"], "quotes can sit inside a token"
try:
    split_args('echo "oops')
    assert False, "an unclosed quote should raise ValueError"
except ValueError:
    pass
---hint
`str.split` knows nothing about quotes. Walk the characters with a flag for "inside quotes".
---hint
Keep `started` separately from `cur`, so `""` still produces an empty token, and only end a token at a space outside quotes.
```

## Reading the tokens

```exercise
title: parse_args
kind: write
---prompt
Write `parse(argv, flags, options)`. `flags` is a set of names that are on/off; `options` is a set of names that take a value. Return `(positionals, opts)` where `opts` maps each name seen to `True` (flag) or its string value (option). Rules:

- `--name=value` and `--name value` set an option. `--name` alone sets a flag.
- `-abc` sets the short flags a, b and c. `-o value` sets a short option (its letter is in `options`).
- `--` ends options; everything after is positional.
- An unknown name, or an option with no value, raises `ValueError`.
---starter
def parse(argv, flags, options):
    pos, opts = [], {}
    for t in argv:
        if t.startswith("-"):
            opts[t.lstrip("-")] = True
        else:
            pos.append(t)
    return pos, opts
---solution
def parse(argv, flags, options):
    pos, opts, i = [], {}, 0
    while i < len(argv):
        t = argv[i]
        if t == "--":
            pos += argv[i + 1:]
            break
        if t.startswith("--"):
            name, eq, value = t[2:].partition("=")
            if name in options:
                if not eq:
                    if i + 1 >= len(argv):
                        raise ValueError(f"--{name} needs a value")
                    i += 1
                    value = argv[i]
                opts[name] = value
            elif name in flags and not eq:
                opts[name] = True
            else:
                raise ValueError(f"unknown option --{name}")
        elif t.startswith("-") and len(t) > 1:
            for k, ch in enumerate(t[1:]):
                if ch in flags:
                    opts[ch] = True
                elif ch in options:
                    rest = t[k + 2:]
                    if rest:
                        opts[ch] = rest
                    elif i + 1 < len(argv):
                        i += 1
                        opts[ch] = argv[i]
                    else:
                        raise ValueError(f"-{ch} needs a value")
                    break
                else:
                    raise ValueError(f"unknown flag -{ch}")
        else:
            pos.append(t)
        i += 1
    return pos, opts
---tests
F, O = {"v", "q", "all"}, {"due", "tag", "o"}
assert parse(["add", "buy milk", "--due=fri", "-vq", "--tag", "home"], F, O) == (["add", "buy milk"], {"due": "fri", "v": True, "q": True, "tag": "home"})
assert parse(["--all", "x"], F, O) == (["x"], {"all": True})
assert parse(["a", "--", "--draft", "-v"], F, O) == (["a", "--draft", "-v"], {})
assert parse(["-o", "out.txt", "-vo", "log"], F, O) == ([], {"o": "log", "v": True})
assert parse(["-"], F, O) == (["-"], {}), "a lone dash usually means standard input"
for bad in (["--nope"], ["-x"], ["--due"], ["-vo"]):
    try:
        parse(bad, F, O)
        assert False, f"{bad} should raise ValueError"
    except ValueError:
        pass
---hint
The starter treats every dash as a flag and never looks at the next token. Use an index loop, so an option can take `argv[i + 1]` and skip it.
---hint
`t[2:].partition("=")` splits `due=fri` into name, "=", value in one go, and still works when there's no "=".
```

```quiz
A script runs `mytool input.txt && echo done`. When does "done" print?
- Always
* Only if mytool exits with code 0
- Only if mytool prints nothing
- Only if mytool exits with code 1
> `&&` runs the next command only after success (exit code 0). That's why a CLI must return non-zero when it fails, not just print an error.
```

```quiz
- `rm -rf`

- You can't
```

## Help text

```exercise
title: help_text
kind: write
---prompt
Write `usage(prog, flags, options, positionals)` that returns a usage line like argparse's, for example `usage: todo [-h] [--due DUE] [--tag TAG] [-v] title`. `flags` and `options` are lists of names, in the order given; one-letter names get one dash, longer names two. Option metavars are the name in capitals. `-h` always comes first. Positionals come last.
---starter
def usage(prog, flags, options, positionals):
    return f"usage: {prog}"
---solution
def usage(prog, flags, options, positionals):
    dash = lambda n: ("-" if len(n) == 1 else "--") + n
    parts = ["[-h]"]
    parts += [f"[{dash(o)} {o.upper()}]" for o in options]
    parts += [f"[{dash(f)}]" for f in flags]
    return " ".join([f"usage: {prog}"] + parts + list(positionals))
---tests
assert usage("todo", ["v"], ["due", "tag"], ["title"]) == "usage: todo [-h] [--due DUE] [--tag TAG] [-v] title"
assert usage("cp", ["r", "force"], [], ["src", "dst"]) == "usage: cp [-h] [-r] [--force] src dst"
assert usage("x", [], ["o"], []) == "usage: x [-h] [-o O]"
---hint
Build a list of pieces: `[-h]`, then one `[--name NAME]` per option, then one `[--flag]` per flag, then the positionals, and join with spaces.
```

## Real-world project: a todo CLI

```project
title: todo, a command-line task list
client: A developer who lives in the terminal and wants tasks one keystroke away, scriptable from cron and other tools
```

```exercise
title: todo_main
kind: write
---prompt
Write `todo(argv, store)` where `store` is a list of task dicts (it's the "file"). Return `(output, code)`:

- `add TITLE [--tag TAG]`: append `{"id": n, "title": TITLE, "tag": TAG or None, "done": False}` with ids 1, 2, 3, … Output `"added 1"`, code 0.
- `list [--tag TAG]`: lines `"[ ] 1 buy milk"` or `"[x] …"` for tasks (only that tag if given), joined with `"\n"`. Code 0.
- `done ID`: mark it done, output `"done 1"`, code 0. A missing or non-numeric ID: output `"no task ID"`, code 1.
- Anything else (no subcommand, unknown one, missing title, unknown option): output starting with `"usage:"`, code 2.
---starter
def todo(argv, store):
    if argv and argv[0] == "add":
        store.append({"id": len(store) + 1, "title": argv[1], "tag": None, "done": False})
        return f"added {len(store)}", 0
    return "", 0
---solution
def todo(argv, store):
    usage = "usage: todo {add,list,done} ..."
    if not argv or argv[0] not in ("add", "list", "done"):
        return usage, 2
    cmd, rest, tag, pos, i = argv[0], argv[1:], None, [], 0
    while i < len(rest):
        t = rest[i]
        if t.startswith("--tag="):
            tag = t[6:]
        elif t == "--tag" and i + 1 < len(rest):
            i += 1
            tag = rest[i]
        elif t.startswith("-"):
            return usage, 2
        else:
            pos.append(t)
        i += 1
    if cmd == "add":
        if len(pos) != 1:
            return usage, 2
        n = len(store) + 1
        store.append({"id": n, "title": pos[0], "tag": tag, "done": False})
        return f"added {n}", 0
    if cmd == "list":
        rows = [t for t in store if tag is None or t["tag"] == tag]
        return "\n".join(f"[{'x' if t['done'] else ' '}] {t['id']} {t['title']}" for t in rows), 0
    if len(pos) != 1:
        return usage, 2
    for t in store:
        if pos[0].isdigit() and t["id"] == int(pos[0]):
            t["done"] = True
            return f"done {t['id']}", 0
    return f"no task {pos[0]}", 1
---tests
s = []
assert todo(["add", "buy milk", "--tag", "home"], s) == ("added 1", 0)
assert todo(["add", "--tag=work", "send report"], s) == ("added 2", 0)
assert todo(["done", "1"], s) == ("done 1", 0)
assert todo(["list"], s) == ("[x] 1 buy milk\n[ ] 2 send report", 0)
assert todo(["list", "--tag", "work"], s) == ("[ ] 2 send report", 0)
assert todo(["done", "9"], s) == ("no task 9", 1)
assert todo(["done", "abc"], s) == ("no task abc", 1)
for bad in ([], ["fly"], ["add"], ["add", "x", "--colour", "red"]):
    out, code = todo(bad, s)
    assert code == 2 and out.startswith("usage:"), bad
assert len(s) == 2, "failed commands must not change the store"
---hint
The starter handles only the happy path of `add`. Check the subcommand first and return code 2 early for anything unexpected.
---hint
Parse `--tag` (both `--tag X` and `--tag=X`) and collect the other tokens as positionals, then branch on the subcommand.
```

```exercise
title: parse_rebuild
kind: rebuild
---prompt
From memory: `parse(argv, flags, options)` handling `--name=value`, `--name value`, `--flag`, bundled short flags like `-vq`, and `--`. (Short options with values aren't needed here.) Unknown names raise `ValueError`.
---starter
def parse(argv, flags, options):
    pass
---solution
def parse(argv, flags, options):
    pos, opts, i = [], {}, 0
    while i < len(argv):
        t = argv[i]
        if t == "--":
            pos += argv[i + 1:]
            break
        if t.startswith("--"):
            name, eq, value = t[2:].partition("=")
            if name in options:
                if not eq:
                    if i + 1 >= len(argv):
                        raise ValueError(name)
                    i += 1
                    value = argv[i]
                opts[name] = value
            elif name in flags and not eq:
                opts[name] = True
            else:
                raise ValueError(name)
        elif t.startswith("-") and len(t) > 1:
            for ch in t[1:]:
                if ch not in flags:
                    raise ValueError(ch)
                opts[ch] = True
        else:
            pos.append(t)
        i += 1
    return pos, opts
---tests
F, O = {"v", "q"}, {"due"}
assert parse(["x", "--due", "fri", "-vq"], F, O) == (["x"], {"due": "fri", "v": True, "q": True})
assert parse(["--due=a=b", "--", "-v"], F, O) == (["-v"], {"due": "a=b"})
try:
    parse(["--what"], F, O)
    assert False
except ValueError:
    pass
---hint
Index loop; `--` stops; `partition("=")` for long options; loop over the letters for short ones.
```

```recall
Q: Explain what happens between typing a command and the program acting on it: the shell's job, the parser's job, the option conventions, and why exit codes matter.
A: The shell splits the typed line into tokens: spaces separate, quotes group words and are removed, a backslash escapes the next character. The program receives that list (argv) and doesn't see the quotes. Its parser reads the tokens left to right with a spec of which names are on/off flags and which options take a value. Conventions: --name=value or --name value for long options, -v for a short flag, -vq for several at once, -o value for a short option, and -- to end options so later tokens are plain text even if they start with a dash. Subcommands are dispatched with a table from name to function. -h prints usage built from the spec. Exit codes tell other programs what happened: 0 is success, non-zero is failure (argparse uses 2 for usage errors), and shells use them for &&, || and if, so a tool that prints an error but exits 0 breaks scripts.
```
