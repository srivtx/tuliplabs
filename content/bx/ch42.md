## Nobody wrote the rain

Below is a small planet. Each pixel looks at the cells touching it and follows a few lines of rules. Pick a material to read its whole rule, then paint with it. Look for the code that makes piles, flat seas, rain and new rock: there isn't any.

```viz
name: bx-sand
title: A planet made of neighbours
goal: Start the **water cycle**. Let water touch the lava so steam rises, drifts over the island and falls as rain on the seeds until plants grow.
height: 460
Pour water into the crater, or erase a gap in its wall. Then try **Top-down** and **Always left** and pour some sand.
```

The word for this is **emergence**: behaviour of the whole that no part contains. No grain knows what a pile is. The slope of a dune, the flat top of the sea and the path of a raindrop all come from cells that only know their neighbours.

Real physics works the same way. A water molecule doesn't know what a wave is.

## One grain at a time

The world is a grid. In our Python version `.` is empty, `#` is rock and `s` is sand, and `G` and `show` turn rows of text into a grid and back. One **step** visits every cell and applies the rule.

The obvious loop goes top to bottom. It has a nasty bug.

```exercise
title: teleporting_sand
kind: bug
---prompt
`step(g)` should move every grain down **one** cell if the cell below is empty. It changes `g` in place and returns it. But a grain that moves gets visited again on the next row, so it reaches the floor in one step. Fix it by changing the order the rows are visited.
---starter
def step(g):
    for y in range(len(g) - 1):
        for x in range(len(g[0])):
            if g[y][x] == "s" and g[y + 1][x] == ".":
                g[y][x], g[y + 1][x] = ".", "s"
    return g
---solution
def step(g):
    for y in range(len(g) - 2, -1, -1):
        for x in range(len(g[0])):
            if g[y][x] == "s" and g[y + 1][x] == ".":
                g[y][x], g[y + 1][x] = ".", "s"
    return g
---tests
assert show(step(G("s", ".", ".", "."))) == [".", "s", ".", "."], "one cell per step, not all the way down"
assert show(step(G("s", "s", ".", "."))) == [".", "s", "s", "."], "a stack falls together"
assert show(step(G("s.", "#."))) == ["s.", "#."], "rock holds it up"
assert show(step(step(step(G("s", ".", ".", "."))))) == [".", ".", ".", "s"]
---hint
Visit the bottom rows first. Then a grain that has just moved is in a row you've already finished.
```

## Why piles have a slope

Straight down only makes towers one cell wide. Sand slides: if it can't go down, it tries down-left and down-right. That one line gives you a pile with a stable slope. Real sand has one too, called the **angle of repose**, and it's why every sand dune and salt heap has about the same steepness.

The order you try the two sides matters. Always trying left first makes piles lean, as you saw in the simulation. Our Python version has to give the same answer every run, so it alternates by step number where the simulation tosses a coin.

```exercise
title: slide
kind: write
---prompt
Write `step(g, tick)`. Go bottom-up. For each grain: if the cell below is empty, fall. Otherwise try the two lower diagonals, **left first when `tick` is even, right first when it's odd**. A diagonal needs its target cell inside the grid and empty.
---starter
def step(g, tick):
    for y in range(len(g) - 2, -1, -1):
        for x in range(len(g[0])):
            if g[y][x] == "s" and g[y + 1][x] == ".":
                g[y][x], g[y + 1][x] = ".", "s"
    return g
---solution
def step(g, tick):
    w = len(g[0])
    order = (-1, 1) if tick % 2 == 0 else (1, -1)
    for y in range(len(g) - 2, -1, -1):
        for x in range(w):
            if g[y][x] != "s":
                continue
            if g[y + 1][x] == ".":
                g[y][x], g[y + 1][x] = ".", "s"
                continue
            for d in order:
                if 0 <= x + d < w and g[y + 1][x + d] == ".":
                    g[y][x], g[y + 1][x + d] = ".", "s"
                    break
    return g
---tests
assert show(step(G("...", ".s.", ".#."), 0)) == ["...", "...", "s#."], "even tick: left first"
assert show(step(G("...", ".s.", ".#."), 1)) == ["...", "...", ".#s"], "odd tick: right first"
assert show(step(G("s.", "#."), 0)) == ["..", "#s"], "left is off the grid, so use the right"
assert show(step(G("s", "#"), 0)) == ["s", "#"], "nowhere to go"
g = G(".....", ".....", "..s..", "..s..", "..s..")
for t in range(8):
    step(g, t)
assert show(g)[4] == ".sss.", "a three-grain tower slumps into a pile"
---hint
The starter only falls straight. After that check, loop over the two diagonal directions in the right order for this tick.
---hint
`(-1, 1) if tick % 2 == 0 else (1, -1)` gives the order. Stop at the first diagonal that works.
```

## Materials are just a table

You could add water with a pile of `if` statements, then lava, then oil. The better move is the one the simulation makes: every material gets a **weight**, and one rule covers all of them: *a cell may swap with the cell below if that one is lighter*.

Now sand sinks through water and oil floats on it, with no code about sinking or floating. Adding a material means adding a row to a table.

```parsons
title: One rule for every material
---setup
WEIGHT = {".": 0, "o": 1, "~": 2, "s": 3}
SOLID = "#"
---lines
def can_swap(a, b):
    if a == SOLID or b == SOLID:
        return False
    return WEIGHT[a] > WEIGHT[b]
?? return WEIGHT[a] < WEIGHT[b]
?? return a != b
---tests
assert can_swap("s", "~") and can_swap("~", "o") and can_swap("s", ".")
assert not can_swap("o", "~") and not can_swap(".", "s")
assert not can_swap("s", "#") and not can_swap("#", ".")
```

Water needs one more line: if it can't go down, it slides sideways. That's the entire difference between a liquid and a powder.

```exercise
title: liquid
kind: write
---prompt
Write `step(g, tick)` for water only (`~`), on a grid of `.`, `#` and `~`. Bottom-up, and each cell moves at most once per step. A water cell falls if below is empty. Otherwise it moves one cell sideways if it can: left first on even ticks, right first on odd ticks.

Sideways moves stay in the same row, so the scan could meet the same water twice. Keep a set of `(x, y)` cells that have already moved this step, and skip them.
---starter
def step(g, tick):
    for y in range(len(g) - 2, -1, -1):
        for x in range(len(g[0])):
            if g[y][x] == "~" and g[y + 1][x] == ".":
                g[y][x], g[y + 1][x] = ".", "~"
    return g
---solution
def step(g, tick):
    h, w = len(g), len(g[0])
    moved = set()
    order = (-1, 1) if tick % 2 == 0 else (1, -1)
    for y in range(h - 1, -1, -1):
        for x in range(w):
            if g[y][x] != "~" or (x, y) in moved:
                continue
            if y + 1 < h and g[y + 1][x] == ".":
                g[y][x], g[y + 1][x] = ".", "~"
                moved.add((x, y + 1))
                continue
            for d in order:
                if 0 <= x + d < w and g[y][x + d] == ".":
                    g[y][x], g[y][x + d] = ".", "~"
                    moved.add((x + d, y))
                    break
    return g
---tests
assert show(step(G("~", "."), 0)) == [".", "~"]
assert show(step(G("...", ".~.", "###"), 0)) == ["...", "~..", "###"], "even tick: left"
assert show(step(G("...", ".~.", "###"), 1)) == ["...", "..~", "###"], "odd tick: right"
assert show(step(G("..~.", "####"), 1)) == ["...~", "####"], "only one cell, even though the scan reaches it again"
g = G("~~~.....", "########")
for t in range(30):
    step(g, t)
assert "".join(show(g)[0]).count("~") == 3 and "~~~" not in show(g)[0], "a heap of water spreads out flat"
---hint
The bottom row can move too (sideways), so start at `h - 1` and check `y + 1 < h` before falling.
---hint
After a move, add the **new** position to `moved`.
```

## The speed limit

Here's the deepest thing in this chapter. Watch the counter on the picture in the simulation: under the real rules it never goes above 1. Then think about why.

A cell can only see its neighbours. So if you change one cell, nothing further than one cell away can know about it after one step. After 10 steps, nothing further than 10 cells away can possibly be affected, whatever the rules are. **News travels at most one cell per step.** Here it is, in a world of plain 0s and 1s: two copies of the same world, different in one cell.

```run
title: Two worlds, one cell different
def rule(left, me, right):
    return left ^ (me | right)      # any local rule works

def tick(row):
    n = len(row)
    return [rule(row[i - 1], row[i], row[(i + 1) % n]) for i in range(n)]

import random
random.seed(4)
a = [random.randint(0, 1) for _ in range(61)]
b = a[:]
b[30] ^= 1                          # flip one cell

for t in range(16):
    print("".join("#" if x != y else "." for x, y in zip(a, b)))
    a, b = tick(a), tick(b)
```

The `#` marks where the two worlds disagree. The shape it makes can't get wider than one cell per side per step, no matter what rule you put in. Physicists call this a **light cone**.

Our universe behaves the same way. As far as anyone can measure, things only affect what's right next to them, and that influence spreads through space at a fixed top speed: about 300,000 km per second, the speed of light. Nobody knows whether space is a grid (experiments have found no sign of one). But you've just seen the logic: **if the rules are local, there has to be a top speed**. Light is the fastest thing because it's as fast as news can go.

```exercise
title: react
kind: write
---prompt
Reactions are data too. `RULES` maps a pair of touching materials to what they turn into, so `("~", "L"): ("v", "#")` means water next to lava becomes steam, and that lava becomes rock.

Write `react(g, rules)`. Go through every cell in reading order (top to bottom, left to right). For each cell, look at its right neighbour and then the one below. If the pair `(cell, neighbour)` is in `rules`, replace both. If `(neighbour, cell)` is in `rules`, replace both the other way round. Once a cell has reacted, stop checking it. Return `g`.
---starter
def react(g, rules):
    return g
---solution
def react(g, rules):
    h, w = len(g), len(g[0])
    for y in range(h):
        for x in range(w):
            for dx, dy in ((1, 0), (0, 1)):
                nx, ny = x + dx, y + dy
                if nx >= w or ny >= h:
                    continue
                a, b = g[y][x], g[ny][nx]
                if (a, b) in rules:
                    g[y][x], g[ny][nx] = rules[(a, b)]
                    break
                if (b, a) in rules:
                    g[ny][nx], g[y][x] = rules[(b, a)]
                    break
    return g
---tests
R = {("~", "L"): ("v", "#")}
assert show(react(G("~L"), R)) == ["v#"]
assert show(react(G("L~"), R)) == ["#v"], "the rule works in either order"
assert show(react(G("~", "L"), R)) == ["v", "#"], "and vertically"
assert show(react(G("~.L"), R)) == ["~.L"], "not touching"
F = {("f", "p"): ("f", "f")}
assert show(react(G("fp."), F)) == ["ff."]
---hint
For each cell, try the two neighbours `(x + 1, y)` and `(x, y + 1)`, skipping any outside the grid. Check the pair both ways round.
```

Heat spreads the same way everything here does: each cell moves a little towards the average of its neighbours. This is the rule behind a cooling cup of tea and behind weather forecasts.

```exercise
title: heat
kind: write
---prompt
Write `spread(t, k)`. `t` is a list of temperatures along a rod. Return a **new** list where each cell moves towards its neighbours: `new[i] = t[i] + k * (sum of (neighbour - t[i]) for each neighbour)`. The two end cells have only one neighbour. Read only from the old list.
---starter
def spread(t, k):
    for i in range(1, len(t)):
        t[i] = t[i] + k * (t[i - 1] - t[i])
    return t
---solution
def spread(t, k):
    new = []
    for i in range(len(t)):
        change = 0
        if i > 0:
            change += t[i - 1] - t[i]
        if i + 1 < len(t):
            change += t[i + 1] - t[i]
        new.append(t[i] + k * change)
    return new
---tests
assert spread([0, 100, 0], 0.25) == [25.0, 50.0, 25.0]
assert spread([10, 10, 10], 0.25) == [10, 10, 10], "nothing to even out"
old = [0, 100]
assert spread(old, 0.1) == [10.0, 90.0] and old == [0, 100], "don't change the old list"
t = [100.0] + [0.0] * 9
for _ in range(2000):
    t = spread(t, 0.25)
assert abs(sum(t) - 100) < 1e-6, "heat is conserved"
assert max(t) - min(t) < 0.1, "and ends up even"
---hint
The starter writes into the list while reading it. That's the top-down bug again: a step must not see its own results.
```

```recall
Q: Explain how a falling-sand world works and what it teaches about reality: local rules, scan order, materials as data, emergence, and why local rules force a speed limit.
A: The world is a grid and every cell follows a rule that reads only its neighbours. Sand moves down, or down-diagonally if blocked. Water does the same and also slides sideways, and that one extra line is why seas go flat while piles keep a slope. Scan order matters: going top-down moves a grain again on each row so it teleports, so you go bottom-up and move each cell at most once per step, and choose left or right fairly so piles don't lean. Materials are data, a table of weights, so one rule ("swap with a lighter cell below") makes sand sink and oil float, and reactions are another table. Piles, seas, rain and new rock are emergent: they belong to the whole and appear in no single rule. Because a cell sees only its neighbours, a change can spread at most one cell per step, so any world with local rules has a top speed and every event has a light cone. Our universe appears local too, and the speed of light is its top speed for news.
```
