## Editing without asking permission

Your notes app works on the train. Your colleague's copy works in the basement. Both of you edit the same note, and later both phones come online. What should the note say?

Sending whole copies and keeping the newest throws away the other person's work. Locking ("only one editor at a time") doesn't work offline. A **CRDT** (conflict-free replicated data type) is a data structure designed so that any two copies can always be **merged**, and the merge has three properties:

- **commutative**: merge(a, b) = merge(b, a), so sync order doesn't matter,
- **associative**: merging three copies in any grouping gives the same result,
- **idempotent**: merge(a, a) = a, so syncing the same thing twice is harmless.

With those, any devices that have seen the same changes hold the same state. No server has to referee.

## Counters

```exercise
title: g_counter
kind: write
---prompt
A **grow-only counter** (G-Counter) keeps one count per replica: a dict from replica id to that replica's own increments. Write a class `GCounter(replica)` with `inc(n=1)` (adds to its own entry only), `value()` (the sum), and `merge(other)` (in place: for each replica id, keep the **larger** of the two counts).
---starter
class GCounter:
    def __init__(self, replica):
        self.replica, self.total = replica, 0

    def inc(self, n=1):
        self.total += n

    def value(self):
        return self.total

    def merge(self, other):
        self.total += other.total
---solution
class GCounter:
    def __init__(self, replica):
        self.replica, self.counts = replica, {}

    def inc(self, n=1):
        self.counts[self.replica] = self.counts.get(self.replica, 0) + n

    def value(self):
        return sum(self.counts.values())

    def merge(self, other):
        for r, c in other.counts.items():
            self.counts[r] = max(self.counts.get(r, 0), c)
---tests
a, b = GCounter("a"), GCounter("b")
a.inc(); a.inc(2); b.inc(5)
a.merge(b)
assert a.value() == 8
a.merge(b); a.merge(b)
assert a.value() == 8, "syncing again must not double-count"
b.merge(a)
assert b.value() == 8, "both sides agree"
c = GCounter("c"); c.inc(1)
x, y = GCounter("x"), GCounter("y")
for g in (x, y):
    g.merge(a); g.merge(c)
y.merge(c); y.merge(a)
assert x.value() == y.value() == 9 and x.counts == y.counts
---hint
The starter adds totals when merging, so syncing twice counts everything twice. Keep each replica's count separately.
---hint
Merge with `max` per replica: a replica's count only ever grows, so the bigger number is the newer one.
```

```exercise
title: pn_counter
kind: write
---prompt
A counter that can go down (likes and unlikes, items in stock) is two G-Counters: one for increments and one for decrements. Write `PNCounter(replica)` with `inc(n=1)`, `dec(n=1)`, `value()` (increments minus decrements) and `merge(other)`. Store the two dicts as `self.p` and `self.n`.
---starter
class PNCounter:
    def __init__(self, replica):
        self.replica, self.counts = replica, {}

    def inc(self, n=1):
        self.counts[self.replica] = self.counts.get(self.replica, 0) + n

    def dec(self, n=1):
        self.counts[self.replica] = self.counts.get(self.replica, 0) - n

    def value(self):
        return sum(self.counts.values())

    def merge(self, other):
        for r, c in other.counts.items():
            self.counts[r] = max(self.counts.get(r, 0), c)
---solution
class PNCounter:
    def __init__(self, replica):
        self.replica, self.p, self.n = replica, {}, {}

    def inc(self, n=1):
        self.p[self.replica] = self.p.get(self.replica, 0) + n

    def dec(self, n=1):
        self.n[self.replica] = self.n.get(self.replica, 0) + n

    def value(self):
        return sum(self.p.values()) - sum(self.n.values())

    def merge(self, other):
        for mine, theirs in ((self.p, other.p), (self.n, other.n)):
            for r, c in theirs.items():
                mine[r] = max(mine.get(r, 0), c)
---tests
a, b = PNCounter("a"), PNCounter("b")
a.inc(5)
b.merge(a)
b.dec(2)
a.dec(1)
a.merge(b); b.merge(a)
assert a.value() == b.value() == 2
b.dec(1); a.merge(b)
assert a.value() == 1
---hint
In the starter, a decrement lowers a count, and `max` then ignores the lower value. Keep decrements in their own grow-only dict.
```

## Registers and sets

```exercise
title: lww_register
kind: write
---prompt
A **last-writer-wins register** holds one value with a stamp `(time, replica)`. Write `LWW(replica)` with `set(value, time)`, `get()` (`None` if never set) and `merge(other)`: keep whichever value has the larger stamp. Comparing `(time, replica)` tuples breaks ties between equal times the same way on every device.
---starter
class LWW:
    def __init__(self, replica):
        self.replica, self.value = replica, None

    def set(self, value, time):
        self.value = value

    def get(self):
        return self.value

    def merge(self, other):
        self.value = other.value
---solution
class LWW:
    def __init__(self, replica):
        self.replica, self.value, self.stamp = replica, None, None

    def set(self, value, time):
        self.value, self.stamp = value, (time, self.replica)

    def get(self):
        return self.value

    def merge(self, other):
        if other.stamp is not None and (self.stamp is None or other.stamp > self.stamp):
            self.value, self.stamp = other.value, other.stamp
---tests
a, b = LWW("a"), LWW("b")
a.set("draft", 1); b.set("final", 5)
a.merge(b); b.merge(a)
assert a.get() == b.get() == "final"
a.set("x", 7); b.set("y", 7)
a.merge(b); b.merge(a)
assert a.get() == b.get() == "y", "equal times: the larger replica id wins, everywhere"
c = LWW("c"); c.merge(LWW("d"))
assert c.get() is None
stale = LWW("s"); stale.set("old", 1)
a.merge(stale)
assert a.get() == "y", "an older write must not overwrite a newer one"
---hint
The starter takes whatever it merges last, so two devices can end up disagreeing. Compare stamps.
```

```exercise
title: or_set
kind: write
---prompt
An **add-wins set** (OR-Set). Each `add(item)` creates a unique tag `(replica, counter)`. `remove(item)` marks only the tags of that item **it has seen** as removed (tombstones). `items()` is every item with at least one tag not removed, sorted. `merge(other)` unions both the adds and the tombstones. So a remove on one phone can't delete an add it never saw: concurrent add and remove of the same item keeps it. Store `self.adds` (item → set of tags) and `self.removed` (set of tags).
---starter
class ORSet:
    def __init__(self, replica):
        self.replica, self.s = replica, set()

    def add(self, item):
        self.s.add(item)

    def remove(self, item):
        self.s.discard(item)

    def items(self):
        return sorted(self.s)

    def merge(self, other):
        self.s |= other.s
---solution
class ORSet:
    def __init__(self, replica):
        self.replica, self.counter, self.adds, self.removed = replica, 0, {}, set()

    def add(self, item):
        self.counter += 1
        self.adds.setdefault(item, set()).add((self.replica, self.counter))

    def remove(self, item):
        self.removed |= self.adds.get(item, set())

    def items(self):
        return sorted(k for k, tags in self.adds.items() if tags - self.removed)

    def merge(self, other):
        for k, tags in other.adds.items():
            self.adds.setdefault(k, set()).update(tags)
        self.removed |= other.removed
---tests
alice, bob = ORSet("alice"), ORSet("bob")
alice.add("milk"); alice.add("apples")
bob.merge(alice)
alice.add("eggs"); alice.remove("apples")
bob.remove("milk"); bob.add("bread")
alice.merge(bob); bob.merge(alice)
assert alice.items() == bob.items() == ["bread", "eggs"], "the shopping list from the simulation"
x, y = ORSet("x"), ORSet("y")
x.add("tea"); y.merge(x)
y.remove("tea")
x.add("tea")
x.merge(y); y.merge(x)
assert x.items() == y.items() == ["tea"], "x re-added tea without seeing y's remove: add wins"
x.merge(y)
assert x.items() == ["tea"]
---hint
With a plain set, a removed item comes back as soon as you merge with a phone that still has it. Removes have to be remembered.
---hint
Remove records the tags you can see. A later add makes a new tag nobody has removed, so the item survives.
```

## Quick-fire: lock it in

```quiz
Why must a CRDT's merge be idempotent?
- To make it faster
* Networks deliver the same update more than once, and syncing again must not change anything
- So it can run on one device
- Because merges are rare
> Retries are normal. Idempotence makes them safe.
```

```quiz
Two phones are offline for an hour with clocks 3 minutes apart. Both set the note's title. What does a last-writer-wins register do?
- Keeps both titles
* Keeps the one with the larger stamp, which may just be the phone whose clock runs fast; the other edit is silently dropped
- Asks the user
- Raises an error
> LWW is fine for a single field where losing one edit is acceptable. For text, use a sequence CRDT.
```

```quiz
Why can't a set CRDT just delete removed items?
- Memory is cheap
* Merging with a copy that still has the item would bring it back; the removal has to be remembered as a tombstone
- Sets can't delete
- To keep the order
> Tombstones are the price of offline deletes. Systems clean them up once every device has seen them.
```

```exercise
title: lww_map
kind: write
---prompt
Write `LWWMap(replica)`: a dict where each key is a last-writer-wins register. `set(key, value, time)`, `delete(key, time)` (stores a tombstone value `None` with that stamp), `get(key)` (`None` if missing or deleted), `keys()` (sorted keys with a live value) and `merge(other)` (per key, keep the larger `(time, replica)` stamp). Store entries as `self.data[key] = (stamp, value)`.
---starter
class LWWMap:
    def __init__(self, replica):
        self.replica, self.data = replica, {}

    def set(self, key, value, time):
        self.data[key] = value

    def delete(self, key, time):
        self.data.pop(key, None)

    def get(self, key):
        return self.data.get(key)

    def keys(self):
        return sorted(self.data)

    def merge(self, other):
        self.data.update(other.data)
---solution
class LWWMap:
    def __init__(self, replica):
        self.replica, self.data = replica, {}

    def _put(self, key, value, time):
        stamp = (time, self.replica)
        if key not in self.data or stamp > self.data[key][0]:
            self.data[key] = (stamp, value)

    def set(self, key, value, time):
        self._put(key, value, time)

    def delete(self, key, time):
        self._put(key, None, time)

    def get(self, key):
        return self.data[key][1] if key in self.data else None

    def keys(self):
        return sorted(k for k, (_, v) in self.data.items() if v is not None)

    def merge(self, other):
        for k, (stamp, v) in other.data.items():
            if k not in self.data or stamp > self.data[k][0]:
                self.data[k] = (stamp, v)
---tests
a, b = LWWMap("a"), LWWMap("b")
a.set("title", "Plan", 1); a.set("body", "draft", 1)
b.merge(a)
b.set("title", "Plan v2", 3)
a.delete("body", 2)
a.merge(b); b.merge(a)
assert a.keys() == b.keys() == ["title"] and a.get("title") == "Plan v2" and b.get("body") is None
c = LWWMap("c"); c.set("body", "old", 1)
c.merge(a)
assert c.get("body") is None, "the delete (time 2) beats the older value (time 1)"
x, y, z = LWWMap("x"), LWWMap("y"), LWWMap("z")
x.set("k", 1, 5); y.set("k", 2, 5); z.delete("k", 4)
p, q = LWWMap("p"), LWWMap("q")
for m in (x, y, z): p.merge(m)
for m in (z, y, x): q.merge(m)
assert p.data == q.data and p.get("k") == 2
---hint
The starter forgets deletes on merge (the other side brings the key back) and lets whoever merges last win. Store a stamp with every value, including deletes.
```

```recall
Q: Explain CRDTs: why last-upload-wins loses data, the three properties a merge needs, and how a G-Counter, PN-Counter, LWW register and add-wins set each merge.
A: When devices edit offline and then sync by sending whole copies, the last upload overwrites the others and their edits are lost (and deleted items can reappear). A CRDT is a data type whose copies can always be merged, with a merge that is commutative, associative and idempotent; then any devices that have seen the same updates hold identical state, whatever order or how often they sync. A G-Counter keeps one count per replica, each replica only increments its own, value is the sum, and merge takes the max per replica (adding would double-count repeated syncs). A PN-Counter is two G-Counters, one for increments and one for decrements. An LWW register stores a value with a (time, replica) stamp and merge keeps the larger stamp, so concurrent writes resolve the same way everywhere but one is dropped. An add-wins set gives every add a unique tag; a remove tombstones only the tags it has seen; merge unions adds and tombstones; an item is present if it has a tag not tombstoned, so a concurrent add survives a remove. Text editing uses sequence CRDTs such as RGA.
```
