```prelude
import math
import random

class Value:
    """A number that remembers how it was made, so it can send gradients back."""
    def __init__(self, data, kids=(), op=""):
        self.data, self.grad = data, 0.0
        self._kids, self._op = kids, op
        self._backward = lambda: None
    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out
    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out
    def __pow__(self, n):
        out = Value(self.data ** n, (self,), f"**{n}")
        def _backward():
            self.grad += n * self.data ** (n - 1) * out.grad
        out._backward = _backward
        return out
    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,), "tanh")
        def _backward():
            self.grad += (1 - t * t) * out.grad
        out._backward = _backward
        return out
    def backward(self):
        order, seen = [], set()
        def visit(v):
            if id(v) not in seen:
                seen.add(id(v))
                for k in v._kids:
                    visit(k)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order):
            v._backward()
    __radd__ = __add__
    __rmul__ = __mul__
    def __neg__(self): return self * -1
    def __sub__(self, other): return self + (-other if isinstance(other, Value) else -other)
    def __repr__(self): return f"Value(data={self.data:.4g}, grad={self.grad:.4g})"
```

## What a framework really does

PyTorch, JAX and TensorFlow are huge, but their beating heart is small: **a number that remembers how it was made**. When you write `y = w*x + b`, the framework quietly builds a graph: `y` came from a `+`, which came from a `*` of `w` and `x`, plus `b`. Call `y.backward()` and it walks that graph *in reverse*, handing every input its **gradient**: how much `y` would change if you nudged that input.

That gradient is all training needs: nudge every weight a little bit downhill, repeat a thousand times.

```quiz
A network has one million weights. To get the gradient of the loss with respect to *all* of them, reverse-mode autodiff (backpropagation) needs…
- a million backward passes, one per weight
- a million forward passes, nudging one weight each time
* one forward pass and one backward pass
- no passes: gradients are computed when the weights are created
> That's the whole reason deep learning is possible. The backward pass visits each node once and hands every input its share of the gradient. Nudging each weight separately (finite differences) would need a million forward passes.
```

## A number that remembers

Start small. A `Value` holds `data`, a `grad` (zero until backward runs), and the `Value`s it was made from (`_kids`). Python lets a class define what `+` and `*` mean through `__add__` and `__mul__`; that's how `w*x + b` builds a graph without you writing any graph code.

```predict

print(c.data)
print(c._op, [k.data for k in c._kids])
```

## Each operation knows one tiny rule

Backpropagation is the **chain rule**, applied one node at a time. Every operation only needs its **local** derivative: how its output moves when one input moves.

| Node | Output | Local rule: give each input… |
|---|---|---|
| `out = a + b` | a + b | `out.grad` to both (a sum passes the gradient through unchanged) |
| `out = a * b` | a × b | `b.data × out.grad` to a, `a.data × out.grad` to b |
| `out = a ** n` | aⁿ | `n × aⁿ⁻¹ × out.grad` to a |
| `out = tanh(a)` | t | `(1 − t²) × out.grad` to a |

Each node stores its rule as a little function `_backward` that runs when the gradient arrives. Multiplying by `out.grad` is the chain rule: "how the final answer moves with me" times "how I move with my input".

## Backward: the reverse walk

To run the rules in a valid order, every node must have its full gradient **before** it passes it on. So: list the nodes in **topological order** (every node after its inputs), set the output's grad to 1, and call `_backward` on each node from the end of that list to the start.

## Check gradients with numbers

Never trust a gradient you haven't checked. Nudge one input by a tiny `h` up and down and see how the output moves: `(f(x+h) - f(x-h)) / 2h`. It's slow (one pair of forward passes per input) but needs no rules, so it catches bugs in them.

```predict
def f(x):
    return (x * x * 3 + x).data

x = Value(2.0)
y = x * x * 3 + x
y.backward()
h = 1e-4
numeric = (f(Value(2.0 + h)) - f(Value(2.0 - h))) / (2 * h)
print(round(x.grad, 4), round(numeric, 4))
```

## Neurons, layers and a network are just objects

Now object modeling pays off. A **neuron** owns weights and a bias and computes `tanh(w·x + b)`. A **layer** owns a list of neurons. A **network** (MLP) owns a list of layers and feeds each one's output into the next. Each class has a `parameters()` method, so training can find every weight without knowing the shape of the network.

```run
title: The whole network, in 25 lines
class Neuron:
    def __init__(self, n_in):
        self.w = [Value(random.uniform(-1, 1)) for _ in range(n_in)]
        self.b = Value(0.0)
    def __call__(self, x):
        return sum((wi * xi for wi, xi in zip(self.w, x)), self.b).tanh()
    def parameters(self):
        return self.w + [self.b]

class Layer:
    def __init__(self, n_in, n_out):
        self.neurons = [Neuron(n_in) for _ in range(n_out)]
    def __call__(self, x):
        out = [n(x) for n in self.neurons]
        return out[0] if len(out) == 1 else out
    def parameters(self):
        return [p for n in self.neurons for p in n.parameters()]

class MLP:
    def __init__(self, sizes):
        self.layers = [Layer(a, b) for a, b in zip(sizes, sizes[1:])]
    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x
    def parameters(self):
        return [p for l in self.layers for p in l.parameters()]

random.seed(1)
net = MLP([2, 4, 1])
print("parameters:", len(net.parameters()))
print("output for [1, -1]:", net([1.0, -1.0]))
```

## Rebuild it and explain it

```exercise

---prompt

---starter

---solution
class Mini:
    def __init__(self, data, kids=()):
        self.data, self.grad, self.kids = data, 0.0, kids
        self.back = lambda: None
    def __add__(self, o):
        out = Mini(self.data + o.data, (self, o))
        def back():
            self.grad += out.grad
            o.grad += out.grad
        out.back = back
        return out
    def __mul__(self, o):
        out = Mini(self.data * o.data, (self, o))
        def back():
            self.grad += o.data * out.grad
            o.grad += self.data * out.grad
        out.back = back
        return out
    def backward(self):
        order, seen = [], set()
        def visit(v):
            if id(v) not in seen:
                seen.add(id(v))
                for k in v.kids:
                    visit(k)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order):
            v.back()
```

```recall
Q: In your own words: how does `loss.backward()` find the gradient of every weight in a single pass, and why must gradients be added with `+=`?
A: Every operation recorded its inputs, so the loss knows the whole graph behind it. Backward lists the nodes so each comes after its inputs, sets the loss's gradient to 1, and walks the list in reverse; each node multiplies the gradient it received by its own local derivative (the chain rule) and passes the result to its inputs. Each node is visited once, so all gradients come out of one pass. A value used in several places receives gradient from each path, and the total effect is the sum of those, so the rules must accumulate with `+=` instead of overwriting.
```
