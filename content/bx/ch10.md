## What Flask, Express and Django actually do

When you write `@app.get("/users/<id>")` in a framework, it feels like magic. Underneath there are only three ideas:

1. **HTTP is text.** A request is a few lines: `GET /users/42 HTTP/1.1`, some `Name: value` headers, a blank line, maybe a body.
2. **A router** maps (method, path pattern) to one of your functions, pulling parameters like `42` out of the path.
3. **Middleware** wraps the whole thing in layers. Each layer can look at the request on the way in, stop it, or change the response on the way out.

Send some requests through a tiny framework and watch where each answer comes from.

## HTTP is text

A request, exactly as it arrives (lines end with `\r\n` on the wire; we'll accept plain `\n` too):

    POST /users HTTP/1.1
    Host: shop.test
    Content-Type: application/json

    {"name": "Ida"}

The first line is the **request line**. Then headers until a blank line. Everything after the blank line is the **body**.

```predict
raw = "GET /search?q=cats HTTP/1.1\nHost: pets.test\nAccept: text/html\n\n"
head, _, body = raw.partition("\n\n")
lines = head.split("\n")
print(lines[0].split(" "))
print(len(lines) - 1, "headers,", repr(body))
```

```exercise
title: parse_request
kind: write
---prompt
Write `parse_request(raw)` returning a dict with `"method"`, `"path"` (without any `?query`), `"query"` (a dict from `a=1&b=2`, empty if none), `"headers"` (a dict with **lower-case** names) and `"body"` (a string). Accept `\r\n` or `\n` line endings.
---starter
def parse_request(raw):
    return {"method": "", "path": "", "query": {}, "headers": {}, "body": ""}
---solution
def parse_request(raw):
    raw = raw.replace("\r\n", "\n")
    head, _, body = raw.partition("\n\n")
    lines = head.split("\n")
    method, target, _version = lines[0].split(" ")
    path, _, qs = target.partition("?")
    query = dict(pair.split("=", 1) for pair in qs.split("&") if pair)
    headers = {}
    for line in lines[1:]:
        name, _, value = line.partition(":")
        headers[name.strip().lower()] = value.strip()
    return {"method": method, "path": path, "query": query, "headers": headers, "body": body}
---tests
r = parse_request("POST /users?ref=home HTTP/1.1\r\nHost: shop.test\r\nContent-Type: application/json\r\n\r\n{\"name\": \"Ida\"}")
assert r["method"] == "POST" and r["path"] == "/users", "request line"
assert r["query"] == {"ref": "home"}, "query string"
assert r["headers"]["content-type"] == "application/json", "headers, lower-case names"
assert json.loads(r["body"]) == {"name": "Ida"}, "body"
r = parse_request("GET / HTTP/1.1\nHost: x\n\n")
assert r["query"] == {} and r["body"] == "", "no query, no body"
---hint
Normalise line endings, then `raw.partition("\n\n")` separates head from body. The first head line splits on spaces into three parts.
---hint
`target.partition("?")` splits the path from the query string; split the query on `&`, then each pair on the first `=`.
```

Responses are text too: a status line, headers, a blank line, the body. `Content-Length` tells the client where the body ends.

```exercise
title: make_response
kind: write
---prompt
Write `make_response(status, body, content_type="text/plain")` returning the response text with `\r\n` line endings: `HTTP/1.1 <status> <reason>`, then `Content-Type` and `Content-Length` headers, a blank line, and the body. Reasons: 200 OK, 201 Created, 401 Unauthorized, 404 Not Found, 500 Internal Server Error. `Content-Length` is the body's length in **bytes** (UTF-8).
---starter

    return ""
---solution
REASONS = {200: "OK", 201: "Created", 401: "Unauthorized", 404: "Not Found", 500: "Internal Server Error"}

def make_response(status, body, content_type="text/plain"):
    length = len(body.encode("utf-8"))
    return (f"HTTP/1.1 {status} {REASONS[status]}\r\n"
            f"Content-Type: {content_type}\r\n"
            f"Content-Length: {length}\r\n\r\n{body}")
---tests
r = make_response(404, "nope")
assert r == "HTTP/1.1 404 Not Found\r\nContent-Type: text/plain\r\nContent-Length: 4\r\n\r\nnope", repr(r)
assert "Content-Length: 6\r\n" in make_response(200, "café!"), "é is two bytes in UTF-8: count bytes, not characters"
---hint
`len(body.encode("utf-8"))` counts bytes. Build the string with f-strings and `\r\n`.
```

## The router

A route is a method plus a pattern like `/users/<id>/orders/<n>`. The router compares the path **segment by segment**: a literal segment must match exactly; a `<name>` segment matches anything and is captured as a parameter.

```exercise
title: Router
kind: write
---prompt
Write a class `Router` with `add(method, pattern, handler)` and `match(method, path)`, which returns `(handler, params)` for the first route whose method matches and whose pattern has the same number of segments with every literal equal; `params` maps each `<name>` to its segment. Return `None` if nothing matches.
---starter
class Router:
    def __init__(self):
        self.routes = []

    def add(self, method, pattern, handler):
        pass

    def match(self, method, path):
        return None
---solution
class Router:
    def __init__(self):
        self.routes = []

    def add(self, method, pattern, handler):
        self.routes.append((method, pattern.strip("/").split("/"), handler))

    def match(self, method, path):
        parts = path.strip("/").split("/")
        for m, segs, handler in self.routes:
            if m != method or len(segs) != len(parts):
                continue
            params = {}
            for seg, part in zip(segs, parts):
                if seg.startswith("<") and seg.endswith(">"):
                    params[seg[1:-1]] = part
                elif seg != part:
                    break
            else:
                return handler, params
        return None
---tests
r = Router()
home, user, order = (lambda req: "home"), (lambda req: "user"), (lambda req: "order")
r.add("GET", "/", home)
r.add("GET", "/users/<id>", user)
r.add("GET", "/users/<id>/orders/<n>", order)
assert r.match("GET", "/") == (home, {}), "the root"
assert r.match("GET", "/users/42") == (user, {"id": "42"}), "captures id"
assert r.match("GET", "/users/42/orders/7") == (order, {"id": "42", "n": "7"}), "two parameters"
assert r.match("POST", "/users/42") is None, "wrong method"
assert r.match("GET", "/users") is None and r.match("GET", "/cart") is None, "no match"
---hint
Store each pattern pre-split into segments. To match, split the path the same way, skip routes with the wrong method or segment count, then compare segment by segment.
---hint
Python's `for … else`: the `else` runs only if the loop didn't `break`, which is exactly "every segment matched".
```

## Middleware: functions that wrap functions

A handler is a function `request → response`. A middleware takes a handler and returns a **new** handler that does something before and/or after calling the original. Stack them and you get layers, like an onion:

    app = logging(auth(router_handler))

A request enters `logging` first, then `auth`, then the router. The response leaves in the reverse order. That's why a logger on the outside sees the final status of everything, including requests that `auth` turned away.

```parsons
title: Compose middleware
---lines
def compose(middlewares, handler):
    app = handler
    for mw in reversed(middlewares):
        app = mw(app)
    return app
?? for mw in middlewares:
---tests
trace = []
def tag(name):
    def mw(nxt):
        def h(req):
            trace.append("in " + name)
            res = nxt(req)
            trace.append("out " + name)
            return res
        return h
    return mw
app = compose([tag("log"), tag("auth")], lambda req: "ok")
assert app({}) == "ok" and trace == ["in log", "in auth", "out auth", "out log"], "the first middleware listed is the outermost"
```

```exercise
title: TodoApp
kind: write
---prompt
Write `TodoApp` with a method `handle(raw)` that takes raw request text and returns `(status, body_dict_or_list)`. Support `GET /todos` (the list, in creation order), `POST /todos` with a JSON body `{"title": ...}` (store `{"id": n, "title": ..., "done": False}` with ids 1, 2, 3, … and return status 201 with it), and `GET /todos/<id>` (200 with the item, or 404 with `{"error": "not found"}`). def parse_request(raw):

    lines = head.split("\n")

                elif seg != part:

---starter
class TodoApp:
    def __init__(self):
        self.todos = []

    def handle(self, raw):
        return 404, {"error": "not found"}
---solution
class TodoApp:
    def __init__(self):
        self.todos = []
        self.router = Router()
        self.router.add("GET", "/todos", self.list)
        self.router.add("POST", "/todos", self.create)
        self.router.add("GET", "/todos/<id>", self.get)

    def list(self, req):
        return 200, self.todos

    def create(self, req):
        item = {"id": len(self.todos) + 1, "title": json.loads(req["body"])["title"], "done": False}
        self.todos.append(item)
        return 201, item

    def get(self, req, id):
        for t in self.todos:
            if str(t["id"]) == id:
                return 200, t
        return 404, {"error": "not found"}

    def handle(self, raw):
        req = parse_request(raw)
        m = self.router.match(req["method"], req["path"])
        if m is None:
            return 404, {"error": "not found"}
        handler, params = m
        return handler(req, **params)
---tests

post("call mum")
status, items = app.handle("GET /todos HTTP/1.1\nHost: x\n\n")
assert status == 200 and [t["title"] for t in items] == ["buy milk", "call mum"], "list in order"
assert app.handle("GET /todos/2 HTTP/1.1\n\n") == (200, {"id": 2, "title": "call mum", "done": False}), "get one"
assert app.handle("GET /todos/9 HTTP/1.1\n\n") == (404, {"error": "not found"}), "missing id: 404"
assert app.handle("DELETE /todos/1 HTTP/1.1\n\n")[0] == 404, "unknown route: 404"
---hint
In `__init__`, register bound methods (`self.list`, …) on a `Router`. In `handle`, parse, match, and call `handler(req, **params)`.
---hint
Path parameters are strings: compare `str(t["id"]) == id`.
```

```recall
Q: Explain what happens inside a web framework between receiving a request and sending a response, and why middleware runs in the order it does.
A: The server receives text over a socket. A parser turns it into a request: method, path, query, headers and body. The request passes through a stack of middleware: each is a function wrapping the next one, so it can act before (log, check auth, parse JSON) and after (record status, add headers, catch errors). The innermost layer is the router, which matches method and path against patterns, extracts parameters like an id, and calls one handler; no match gives a 404. The handler returns a response, which travels back out through the middleware in reverse, and is turned back into text with a status line, headers and body. The first middleware listed is the outermost, so it sees requests first and responses last, which is why logging goes on the outside and auth goes before the router.
```
