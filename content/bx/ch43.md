## The film that runs both ways

Film a pool shot and play it backward, and it looks fine: every collision obeys the same laws in reverse. The laws of motion have no arrow. So why does a film of an egg breaking look wrong backward? Why does anything in the world have a direction?

This box of gas will show you. Its particles follow a rule with no direction at all, and this simulation is exact, so you can really reverse time.

```viz
name: bx-time
title: Reverse time on a box of gas
goal: Let the gas mix and **Reverse time** until it returns to the corner. Then start again, **Nudge one** particle by the smallest possible step, reverse, and see what's left of the past.
height: 430
Blue is slow, red is fast. Let it run for a few seconds before you reverse.
```

That's the answer in one picture. Nothing forbids the gas going back: you watched it happen. But it needed every particle to be perfect, and one flaw of about a 69-billionth of the box destroyed it.

The rest of this chapter builds each piece: an honest way to move a particle, a way to run it backward, why mixing always wins, and why a tiny flaw takes over.

## Moving a particle honestly

A particle has a position and a velocity. The obvious update moves the position using the velocity, and then changes the velocity. For a weight on a spring (acceleration is `-x`), that's a disaster: the weight slowly gains energy from nowhere, which real springs don't do.

```exercise
title: energy_from_nowhere
kind: bug
---prompt
`spring(x, v, dt, steps)` simulates a weight on a spring and returns `(x, v)`. Its energy `(x*x + v*v) / 2` should stay about the same, but it grows forever. Fix it with the smallest possible change: update the **velocity first**, then move using the **new** velocity. This is called semi-implicit Euler.
---starter
def spring(x, v, dt, steps):
    for _ in range(steps):
        x, v = x + v * dt, v - x * dt
    return x, v
---solution
def spring(x, v, dt, steps):
    for _ in range(steps):
        v = v - x * dt
        x = x + v * dt
    return x, v
---tests
x, v = spring(1.0, 0.0, 0.01, 10000)
e = (x * x + v * v) / 2
assert abs(e - 0.5) < 0.01, f"energy started at 0.5 and is now {e:.3f}"
x, v = spring(1.0, 0.0, 0.05, 100000)
e = (x * x + v * v) / 2
assert abs(e - 0.5) < 0.05, f"it must hold for a long run too, energy is {e:.3f}"
---hint
Two lines instead of one. The order is the whole fix.
```

Games and physics engines use this family of methods because they keep energy steady for as long as you run them. There's an even cleaner form that doesn't store a velocity at all: the next position comes from the last two.

`next = 2 * now - before + force(now)`

Read it backward and it's the same equation: `before = 2 * now - next + force(now)`. If positions are whole numbers and the force is rounded to a whole number, not a single bit is lost. That's what the box of gas runs on, and why it could go back so perfectly.

```exercise
title: reversible
kind: write
---prompt
Write `run(before, now, force, steps)`. Each step works out `next = 2 * now - before + force(now)`, then moves on: `before` becomes `now`, and `now` becomes `next`. Return `(before, now)`.

Reversing time is then just swapping the two arguments, with no extra code.
---starter
def run(before, now, force, steps):
    for _ in range(steps):
        before, now = now, 2 * now - before
    return before, now
---solution
def run(before, now, force, steps):
    for _ in range(steps):
        before, now = now, 2 * now - before + force(now)
    return before, now
---tests
f = lambda x: -x // 4
assert run(0, 10, f, 1) == (10, 17)
a, b = run(0, 10, f, 1000)
assert run(b, a, f, 1000) == (10, 0), "swap them, run again, and you're back at the start"
g = lambda x: -x // 3 + (x * x) % 7
a, b = run(5, 9, g, 500)
assert run(b, a, g, 500) == (9, 5), "any force works, as long as it depends only on the position"
---hint
The starter forgets the force. It moves in a straight line for ever.
```

## Why mixed always wins

Why does the gas spread out? There's no force pushing it. Split the box into a left half and a right half, and count the **arrangements**. With 6 particles, exactly one arrangement has all of them on the left. Three on each side can happen in many ways:

```predict
from math import comb
for left in range(4):
    print(left, "on the left:", comb(6, left), "ways")
```

The gas doesn't *want* anything. It wanders through arrangements at random, and nearly all of them look mixed. With 100 particles there are about 10²⁹ evenly-split arrangements for each single arrangement with everything on one side. With the 10²³ particles in a glass of water, the tidy states are so rare that you'd never see one in many lifetimes of the universe.

**Entropy** is just this count, on a log scale so that big numbers are easy to handle: `S = log(ways)`. The famous second law, that entropy goes up, doesn't come from a force. It's the plain fact that a random walk among arrangements ends up where the arrangements are.

```exercise
title: entropy
kind: write
---prompt
Chop a box into cells and count how many particles are in each. Write `entropy(counts)`: the natural log of the number of ways to arrange the particles, `n! / (c1! * c2! * ...)` where `n = sum(counts)`. Use `math.lgamma(k + 1)`, which is `log(k!)`, so that huge numbers don't overflow.
---starter
import math

def entropy(counts):
    return 0.0
---solution
import math

def entropy(counts):
    n = sum(counts)
    s = math.lgamma(n + 1)
    for c in counts:
        s -= math.lgamma(c + 1)
    return s
---tests
import math
assert abs(entropy([6, 0])) < 1e-9, "one way: log(1) = 0"
assert abs(entropy([3, 3]) - math.log(20)) < 1e-9
assert abs(entropy([1, 1, 1]) - math.log(6)) < 1e-9
assert entropy([50, 50]) > 66 and entropy([90, 10]) < 31, "mixed has far more ways"
assert entropy([10**6, 10**6]) > 1e6, "and huge counts don't overflow"
---hint
Start from `log(n!)` and subtract `log(c!)` for each cell, since dividing becomes subtracting in logs.
```

So if tidy states are so rare, why does anything tidy exist? Why was your egg ever an egg? Follow that question back and it ends at the start of the universe, which began in an extraordinarily low-entropy state. Every tidy thing since, including you, is the universe running downhill from there. Why it started that way is one of the biggest open questions in physics.

## Why you can't go back

If the laws run both ways, then a broken egg *could* un-break, if every atom's motion were reversed exactly. What stops it is **chaos**: in a collision, a tiny difference in where two things meet becomes a bigger difference in where they go, and that goes into the next collision. Errors don't add up, they **multiply**. Here's chaos in one line: two starting points that differ by a trillionth.

```run
title: Two almost identical worlds
a, b = 0.3, 0.3 + 1e-12
for t in range(61):
    if t % 10 == 0:
        print(f"step {t:2}   a = {a:.6f}   b = {b:.6f}   gap = {abs(a - b):.1e}")
    a, b = 4 * a * (1 - a), 4 * b * (1 - b)
```

The gap roughly doubles each step, so it takes only about 40 steps to go from a trillionth to total disagreement. This is why weather can't be forecast more than a couple of weeks ahead, however good the computers get: a flaw too small to measure takes over.

```exercise
title: forecast_horizon
kind: write
---prompt
An error of size `err` multiplies by `grow` every step. Write `horizon(err, size, grow)`: the smallest number of steps after which the error has reached at least `size`.
---starter
def horizon(err, size, grow):
    return 0
---solution
def horizon(err, size, grow):
    steps = 0
    while err < size:
        err *= grow
        steps += 1
    return steps
---tests
assert horizon(1e-6, 1, 2) == 20
assert horizon(1, 100, 10) == 2
assert horizon(5, 1, 2) == 0, "already that big"
assert horizon(1e-12, 1, 2) == 40
assert horizon(2e-12, 1, 2) == 39, "measuring twice as well buys only one more step"
---hint
Keep multiplying and count.
```

That last test matters. Because errors grow exponentially, measuring ten times better buys you only a few more steps. Knowing the past perfectly isn't merely hard: every extra step needs exponentially better knowledge.

So: the laws have no arrow, mixed states outnumber tidy ones beyond imagining, and any imperfection grows until the way back is lost. Those three facts together are time's arrow.

## What water actually is

Now that particles are working, here's a surprise. You can get water from dots with no water code at all. The idea is called **smoothed-particle hydrodynamics**: each dot measures how crowded it is, and crowded dots push apart.

```viz
name: bx-fluid
title: Water with no water in it
goal: Press **Open the dam**, then drag through the water to stir it, with pressure on and nearby cells checked.
height: 400
Try **Pressure off** to see what water is without it, and **Check every pair** to see the cost on the picture.
```

What you call **pressure** isn't a substance. It's the shoving of crowded molecules, added up. **Temperature** is the same kind of thing: how hard they're jiggling, on average. Your hand can't feel a single molecule, so it feels the average, and the average has a name.

Each dot needs its neighbours many times a frame, and comparing every dot with every other is far too slow. The fix is the grid idea you've seen before: put dots into cells the size of their reach, and each dot only looks in the 9 cells around it.

```parsons
title: Drop points into cells

        cell = (int(x // h), int(y // h))
        grid.setdefault(cell, []).append(i)
    return grid
```

```exercise
title: near
kind: write
---prompt
Using `build_grid(points, h)` (it's already written for you), write `near(grid, points, i, h)`: a sorted list of the indices of other points strictly within distance `h` of point `i`. Look only in the 3×3 block of cells around point `i`'s cell.
---setup
def build_grid(points, h):
    grid = {}
    for i, (x, y) in enumerate(points):
        grid.setdefault((int(x // h), int(y // h)), []).append(i)
    return grid
---starter
def near(grid, points, i, h):
    x, y = points[i]
    out = []
    for j, (a, b) in enumerate(points):
        if j != i and abs(a - x) < h and abs(b - y) < h:
            out.append(j)
    return out
---solution
def near(grid, points, i, h):
    x, y = points[i]
    cx, cy = int(x // h), int(y // h)
    out = []
    for dx in (-1, 0, 1):
        for dy in (-1, 0, 1):
            for j in grid.get((cx + dx, cy + dy), []):
                a, b = points[j]
                if j != i and (a - x) ** 2 + (b - y) ** 2 < h * h:
                    out.append(j)
    return sorted(out)
---tests
```

```exercise
title: crowding
kind: write
---prompt
Write `crowding(points, i, others, h)`. `others` is a list of neighbour indices. Return the sum of `(1 - d / h) ** 2` over those neighbours, where `d` is the distance from point `i`, skipping any that are `h` or further away. A neighbour right on top counts 1, and one at the edge of reach counts nothing.
---starter
def crowding(points, i, others, h):
    return len(others)
---solution
from math import dist

def crowding(points, i, others, h):
    total = 0.0
    for j in others:
        d = dist(points[i], points[j])
        if d < h:
            total += (1 - d / h) ** 2
    return total
---tests
pts = [(0, 0), (5, 0), (0, 10), (100, 0)]
assert crowding(pts, 0, [1], 10) == 0.25
assert crowding(pts, 0, [2], 10) == 0.0, "right at the edge counts nothing"
assert crowding(pts, 0, [1, 2, 3], 10) == 0.25
assert crowding(pts, 0, [], 10) == 0.0
assert crowding([(0, 0), (0, 0)], 0, [1], 10) == 1.0
---hint
`math.dist(a, b)` gives the distance. Check it against `h` before adding.
```

```exercise
title: push_apart
kind: write
---prompt
Write `push(a, b, pa, pb, h, rest, k)`, which works out how a pair of dots shoves each other. `a` and `b` are `(x, y)` points, and `pa` and `pb` are their crowding values.

Pressure on each dot is `k * (crowding - rest)`. If the two dots are `h` or more apart, or exactly on top of each other, return `((0, 0), (0, 0))`. Otherwise the shove has size `s = (pressure_a + pressure_b) * (1 - d / h) / 2` along the line between them. Return the displacement of `a` then of `b`: `a` moves `s` away from `b`, and `b` moves `s` away from `a`, so the pair's total displacement is zero.
---starter
def push(a, b, pa, pb, h, rest, k):
    return ((0, 0), (0, 0))
---solution
from math import dist

def push(a, b, pa, pb, h, rest, k):
    d = dist(a, b)
    if d >= h or d == 0:
        return ((0, 0), (0, 0))
    s = (k * (pa - rest) + k * (pb - rest)) * (1 - d / h) / 2
    ux, uy = (b[0] - a[0]) / d, (b[1] - a[1]) / d
    return ((-s * ux, -s * uy), (s * ux, s * uy))
---tests
(ax, ay), (bx, by) = push((0, 0), (5, 0), 3, 3, 10, 1, 2)
assert (ax, ay) == (-2.0, -0.0) and (bx, by) == (2.0, 0.0), "pressure 4 each, half-way out, so s is 2"
assert push((0, 0), (10, 0), 3, 3, 10, 1, 2) == ((0, 0), (0, 0)), "out of reach"
assert push((1, 1), (1, 1), 3, 3, 10, 1, 2) == ((0, 0), (0, 0)), "no direction to push"
(ax, ay), (bx, by) = push((0, 0), (0, 5), 0, 0, 10, 1, 2)
assert ay > 0 and by < 0, "under-crowded dots pull together a little"
(ax, ay), (bx, by) = push((1, 2), (4, 6), 5, 2, 9, 1, 1)
assert abs(ax + bx) < 1e-12 and abs(ay + by) < 1e-12, "every push has an equal and opposite push"
---hint
Work out the unit vector from `a` to `b`. `a` moves along minus that, and `b` along plus that.
```

```exercise
title: temperature
kind: write
---prompt
Temperature is average jiggling. Write `temperature(velocities)`: the mean of `(vx * vx + vy * vy) / 2` over a list of `(vx, vy)` pairs. Subtract the whole group's average velocity first, because a thrown ball isn't hotter than a ball at rest: only motion **relative to the group** counts. Return 0.0 for an empty list.
---starter
def temperature(velocities):
    return sum((vx * vx + vy * vy) / 2 for vx, vy in velocities) / len(velocities)
---solution
def temperature(velocities):
    if not velocities:
        return 0.0
    n = len(velocities)
    mx = sum(v[0] for v in velocities) / n
    my = sum(v[1] for v in velocities) / n
    return sum(((vx - mx) ** 2 + (vy - my) ** 2) / 2 for vx, vy in velocities) / n
---tests
assert temperature([(1, 0), (-1, 0)]) == 0.5
assert temperature([(5, 5), (5, 5)]) == 0.0, "a thrown ball isn't hot"
assert temperature([(6, 5), (4, 5)]) == 0.5, "same jiggle, thrown"
assert temperature([]) == 0.0
assert temperature([(2, 0), (-2, 0)]) == 4 * temperature([(1, 0), (-1, 0)]), "double the speed, four times the temperature"
---hint
Work out the mean velocity first, then average the squared differences.
```

## Rebuild it and explain it


```recall
Q: Explain why time seems to run in one direction when the laws of motion don't, using arrangements, entropy and chaos. Then explain how dots can behave like water.
A: The laws of motion work equally well backward: the update next = 2*now - before + force(now) reads the same in both directions, and with exact whole numbers a gas really does return to where it began. Time's direction comes from counting. A tidy state like all the gas in one corner has very few arrangements and a mixed state has unimaginably many, so a system wandering through arrangements ends up mixed. Entropy is the log of that count, and the second law says it rises because that's where nearly all the arrangements are, not because of any force. Going back would need every particle's motion to be perfect, but chaos multiplies any error at each collision, so even the smallest flaw soon changes every path. Tidy things exist at all because the universe began in a very low-entropy state, and why it did is an open question. Water can be built from dots the same way: each dot measures how crowded it is from nearby dots, crowded pairs push apart, and pressure is just that shoving added up. A grid of cells means each dot checks only the 9 cells nearby instead of every other dot, which turns n squared work into roughly n.
```
