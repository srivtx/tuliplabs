## One rule isn't enough

The simplest fraud check is a rule: "block anything over 500". It's easy to write and easy to beat. Thieves test a stolen card with small payments and stay under the limit, while the real customer pays their rent and gets blocked.

What a bank really asks is: **is this normal for this customer?** Rent to the usual landlord is normal for them even at 820. Three gift-card payments abroad in four minutes are not, even at 45 each. A detector turns each payment into **features** (new country? new shop? amount far from their usual? many payments in a few minutes?), adds them into a **risk score**, and blocks above a threshold.


Each signal is weak on its own: people travel, try new shops, buy big things. Added together they're strong. Real systems learn the weights from millions of past payments (often with a decision tree forest, chapter 45), but the shape is the same.

## Features and a score

```exercise
title: risk_score
kind: write
---prompt
Write `risk(tx, history)`. `tx` and every item of `history` are dicts with `time` (minutes), `shop`, `amount` and `country`. `history` is this customer's past **approved** payments, oldest first. Add up:
- +2 if `tx["country"]` never appears in history
- +1 if `tx["shop"]` never appears in history
- +2 if the shop is new **and** the amount is more than 5 times the median of past amounts
- +2 if at least 2 past payments happened in the last 10 minutes (`tx["time"] - p["time"] <= 10`)

With empty history, count the median as 0.
---starter
def risk(tx, history):
    return 2 if tx["amount"] > 500 else 0
---solution
from statistics import median

def risk(tx, history):
    countries = {p["country"] for p in history}
    shops = {p["shop"] for p in history}
    typical = median(p["amount"] for p in history) if history else 0
    s = 0
    if tx["country"] not in countries:
        s += 2
    new_shop = tx["shop"] not in shops
    if new_shop:
        s += 1
    if new_shop and tx["amount"] > 5 * typical:
        s += 2
    if sum(1 for p in history if tx["time"] - p["time"] <= 10) >= 2:
        s += 2
    return s
---tests

---hint
```

## Bursts and odd amounts

Card testers fire many small payments in seconds. A **sliding window** counts recent events cheaply: keep a deque of timestamps, drop the ones that have fallen out of the window, and look at its length.

```exercise
title: velocity
kind: write
---prompt
Write `bursts(times, window, limit)`. `times` is a sorted list of payment times. Return the indices of every payment that is the `(limit + 1)`-th or later within `window` minutes, meaning that counting it, more than `limit` payments have times in `(t - window, t]`. Use a deque so the whole thing is one pass.
---starter
def bursts(times, window, limit):
    out = []
    for i, t in enumerate(times):
        if i > limit:
            out.append(i)
    return out
---solution
from collections import deque

def bursts(times, window, limit):
    recent, out = deque(), []
    for i, t in enumerate(times):
        recent.append(t)
        while recent[0] <= t - window:
            recent.popleft()
        if len(recent) > limit:
            out.append(i)
    return out
---tests
assert bursts([0, 1, 2, 3], 10, 2) == [2, 3]
assert bursts([0, 20, 40, 60], 10, 1) == []
assert bursts([0, 5, 10, 11, 12], 10, 2) == [3, 4], "0 has dropped out by time 10"
assert bursts([], 10, 1) == []
assert bursts([7, 7, 7], 1, 2) == [2]
---hint
The starter just counts from the start of time. Keep only timestamps newer than `t - window`.
```

A **z-score** says how many standard deviations an amount is from this customer's mean. Above 3 is rare for normally-behaved data.

```exercise
title: zscore_zero
kind: bug
---prompt
`z(amount, past)` crashes for a customer who always spends exactly the same (the standard deviation is 0), and for one with no history. Fix it: with fewer than 2 past amounts return 0.0; if the deviation is 0, return 0.0 when the amount equals the mean and `float("inf")` otherwise.
---starter
from statistics import mean, pstdev

def z(amount, past):
    return (amount - mean(past)) / pstdev(past)
---solution
from statistics import mean, pstdev

def z(amount, past):
    if len(past) < 2:
        return 0.0
    m, s = mean(past), pstdev(past)
    if s == 0:
        return 0.0 if amount == m else float("inf")
    return (amount - m) / s
---tests
assert z(50, [40, 42, 38, 40]) == (50 - 40) / 1.4142135623730951
assert z(9.99, [9.99, 9.99, 9.99]) == 0.0, "a subscription, always the same"
assert z(500, [9.99, 9.99, 9.99]) == float("inf")
assert z(100, []) == 0.0 and z(100, [5]) == 0.0
---hint
Check the length first, then check for a zero deviation before dividing.
```

## Is it any good?

A detector makes two kinds of mistake: **missed fraud** and **false alarms** (blocking a real customer, who may then leave). Two numbers measure it:
- **precision**: of the payments you blocked, what fraction were fraud?
- **recall**: of the fraud, what fraction did you block?

A lower threshold raises recall and lowers precision. Choosing it is a business decision.


```exercise
title: pick_threshold
kind: write
---prompt
Write `pick_threshold(scores, truth, min_recall)`. Try every distinct score as a threshold (block when `score >= threshold`) and return the one with the fewest false alarms among those whose recall is at least `min_recall`; on a tie in false alarms pick the **higher** threshold. If there is no fraud at all, return `max(scores) + 1` (block nothing).
---starter
def pick_threshold(scores, truth, min_recall):
    return min(scores)
---solution
def pick_threshold(scores, truth, min_recall):
    frauds = sum(truth)
    if frauds == 0:
        return max(scores) + 1
    best = None
    for th in sorted(set(scores), reverse=True):
        tp = sum(1 for s, t in zip(scores, truth) if s >= th and t)
        fp = sum(1 for s, t in zip(scores, truth) if s >= th and not t)
        if tp / frauds >= min_recall and (best is None or fp < best[0]):
            best = (fp, th)
    return best[1]
---tests
scores = [0, 1, 3, 5, 2, 7, 3, 1]
truth  = [0, 0, 1, 1, 0, 1, 0, 0]
assert pick_threshold(scores, truth, 1.0) == 3
assert pick_threshold(scores, truth, 0.6) == 5
assert pick_threshold(scores, truth, 0.3) == 7
assert pick_threshold([4, 9], [0, 0], 0.9) == 10
---hint
The starter blocks everything. For each threshold, count true and false positives; keep the best that reaches the recall target.
---hint
Looping thresholds from high to low and only replacing on strictly fewer false alarms keeps the higher threshold on ties.
```

```recall
Q: Explain how a payment fraud detector works: why fixed rules fail, per-customer features and risk scores, sliding windows for bursts, z-scores for unusual amounts, and how precision, recall and the threshold trade off.
A: A fixed rule like "block over 500" is easy for thieves to learn and dodge with small payments, and it blocks real customers whose large payments are normal for them. Instead, each payment is compared with that customer's own history and turned into features: is the country new, is the shop new, is the amount far above their usual, have several payments happened in the last few minutes. Each feature adds weight to a risk score, and payments above a threshold are blocked (a middle band can go to manual review). Bursts are found with a sliding window: a deque of recent timestamps, dropping those older than the window and checking how many remain. Unusual amounts can be measured with a z-score, (amount minus mean) divided by the standard deviation, guarding against no history or zero spread. A detector is judged by precision (what fraction of blocked payments were fraud) and recall (what fraction of fraud was blocked); lowering the threshold raises recall but blocks more real customers, so the threshold is chosen to meet a recall target with the fewest false alarms.
```
