## A container is a process wearing blinkers

A container isn't a small virtual machine. It's an ordinary process on the same kernel, started with three kinds of fence:

- **Namespaces** change what it can **see**: its own process list (it believes it's PID 1), its own hostname, network interfaces, mount points and user IDs.
- **cgroups** limit what it can **use**: CPU share, memory (go over and it's killed), number of processes, disk bandwidth.
- **A layered filesystem** gives it its own root directory, built from an **image**.

The image part is what makes containers cheap. An image is a stack of read-only **layers**, each the changes made by one build step (`FROM python`, `COPY app/`, `RUN pip install`). A running container adds one thin **writable** layer on top. Reading a file looks down the stack from the top and takes the first match. Writing a file that lives in a lower layer first **copies it up** into the writable layer (copy-on-write). Deleting one writes a **whiteout**, a marker that hides it.

## Reading through layers

```exercise
title: overlay_read
kind: write
---prompt
Layers are dicts from path to file contents, listed **top first**. A value of `None` is a whiteout: the file was deleted at that layer. Write `read(layers, path)`: return the contents from the topmost layer that mentions the path, or raise `FileNotFoundError` if no layer has it or the topmost mention is a whiteout.
---starter
def read(layers, path):
    for layer in layers:
        if layer.get(path):
            return layer[path]
    raise FileNotFoundError(path)
---solution
def read(layers, path):
    for layer in layers:
        if path in layer:
            if layer[path] is None:
                raise FileNotFoundError(path)
            return layer[path]
    raise FileNotFoundError(path)
---tests
```

## Writing on top

```exercise
title: copy_on_write
kind: write
---prompt
Write a class `Container(image_layers)` where `image_layers` is a list of read-only dicts, top first. The container has its own empty `upper` dict on top. Methods:

- `read(path)`: as before, looking in `upper` first.
- `write(path, text)`: store in `upper` (the image layers must never change).
- `append(path, text)`: copy-on-write: read the current contents (through the layers), add `text`, and write the result to `upper`.
- `delete(path)`: raise `FileNotFoundError` if it doesn't exist; otherwise put a whiteout (`None`) in `upper`.
- `upper_size()`: total length of the strings in `upper`.
---starter
class Container:
    def __init__(self, image_layers):
        self.layers = image_layers

    def read(self, path):
        for layer in self.layers:
            if path in layer:
                return layer[path]
        raise FileNotFoundError(path)

    def write(self, path, text):
        self.layers[0][path] = text

    def append(self, path, text):
        self.layers[0][path] += text

    def delete(self, path):
        del self.layers[0][path]

    def upper_size(self):
        return 0
---solution
class Container:
    def __init__(self, image_layers):
        self.upper = {}
        self.layers = [self.upper] + list(image_layers)

    def read(self, path):
        for layer in self.layers:
            if path in layer:
                if layer[path] is None:
                    raise FileNotFoundError(path)
                return layer[path]
        raise FileNotFoundError(path)

    def write(self, path, text):
        self.upper[path] = text

    def append(self, path, text):
        self.upper[path] = self.read(path) + text

    def delete(self, path):
        self.read(path)
        self.upper[path] = None

    def upper_size(self):
        return sum(len(v) for v in self.upper.values() if v is not None)
---tests
image = [{"/app/config": "debug=0\n"}, {"/etc/os": "debian\n", "/app/config": "old\n"}]
snapshot = [dict(l) for l in image]
a, b = Container(image), Container(image)
a.append("/app/config", "port=80\n")
assert a.read("/app/config") == "debug=0\nport=80\n"
assert b.read("/app/config") == "debug=0\n", "other containers see the original"
b.delete("/etc/os")
try:
    b.read("/etc/os")
    assert False
except FileNotFoundError:
    pass
assert a.read("/etc/os") == "debian\n"
a.write("/tmp/log", "hello")
assert a.upper_size() == len("debug=0\nport=80\n") + 5 and b.upper_size() == 0
assert image == snapshot, "the image layers must not change"
try:
    a.delete("/missing")
    assert False
except FileNotFoundError:
    pass
---hint
The starter writes straight into the top image layer, so every container sharing the image sees the change. Give each container its own `upper` dict.
---hint
Make `self.layers = [self.upper] + image_layers` so `read` checks the upper layer first. `append` reads through the stack and writes the result to `upper`.
```

```exercise
title: layer_cache
kind: write
---prompt
Docker caches build steps: each layer's ID is a hash of its **parent's ID** plus the **step's text**, so a step is reused only if it and every step before it are unchanged. Write `layer_ids(steps)`: start with parent `""`, and for each step compute `sha256((parent + "\n" + step).encode()).hexdigest()[:12]`. Then write `cache_hits(old_steps, new_steps)`: how many of the new build's layer IDs already existed in the old build.
---starter
import hashlib

def layer_ids(steps):
    return [hashlib.sha256(s.encode()).hexdigest()[:12] for s in steps]

def cache_hits(old_steps, new_steps):
    return len(set(old_steps) & set(new_steps))
---solution
import hashlib

def layer_ids(steps):
    ids, parent = [], ""
    for s in steps:
        parent = hashlib.sha256((parent + "\n" + s).encode()).hexdigest()[:12]
        ids.append(parent)
    return ids

def cache_hits(old_steps, new_steps):
    old = set(layer_ids(old_steps))
    return sum(1 for i in layer_ids(new_steps) if i in old)
---tests
v1 = ["FROM python:3.12", "COPY requirements.txt .", "RUN pip install -r requirements.txt", "COPY . ."]
v2 = ["FROM python:3.12", "COPY requirements.txt .", "RUN pip install -r requirements.txt", "COPY . .", "CMD python app.py"]
v3 = ["FROM python:3.13", "COPY requirements.txt .", "RUN pip install -r requirements.txt", "COPY . ."]
assert len(layer_ids(v1)) == 4 and len(set(layer_ids(v1))) == 4
assert cache_hits(v1, v2) == 4, "adding a step at the end reuses everything before it"
assert cache_hits(v1, v3) == 0, "changing the base invalidates every layer after it"
assert cache_hits(v1, list(reversed(v1))) == 0, "same steps in another order are different layers"
assert layer_ids(["A"]) == [hashlib.sha256(b"\nA").hexdigest()[:12]]
---hint
The starter hashes each step on its own, so a step looks cached even if something before it changed. Chain the hashes: each ID depends on the previous one.
```

## Limits

```exercise
title: memory_limit
kind: write
---prompt
cgroups kill a container that goes over its memory limit (the OOM killer). Write `oom_step(events, limit)`: `events` is a list of numbers, positive for allocating that many MB and negative for freeing. Return the index of the event that pushes usage **over** `limit`, or `None` if it never does. Usage can't go below 0.
---starter
def oom_step(events, limit):
    return None if sum(events) <= limit else len(events) - 1
---solution
def oom_step(events, limit):
    used = 0
    for i, e in enumerate(events):
        used = max(0, used + e)
        if used > limit:
            return i
    return None
---tests
assert oom_step([100, 200, -150, 300], 400) == 3
assert oom_step([100, 400, -400], 400) == 1, "the peak matters, not the final total"
assert oom_step([500, -500], 600) is None
assert oom_step([-50, 100], 60) == 1, "freeing more than you have doesn't give credit"
assert oom_step([], 1) is None
---hint
The starter only checks the final total. The kernel checks at every allocation: keep a running total.
```

```quiz
- Because disks are read-only
```

```exercise
title: disk_usage
kind: write
---prompt
Write `disk_usage(images, containers, sizes)`. `images` maps an image name to its list of layer IDs; `sizes` maps each layer ID to its size in MB; `containers` is a list of `(image_name, upper_mb)`. Layers are stored **once** however many images or containers use them. Return `(shared, naive)`: `shared` is the real usage (each distinct layer once, plus every container's upper layer); `naive` is what full copies would cost (every image's layers stored per image, plus a full copy of its image per container, plus the uppers).
---starter
def disk_usage(images, containers, sizes):
    total = sum(sizes.values()) + sum(u for _, u in containers)
    return total, total
---solution
def disk_usage(images, containers, sizes):
    image_mb = {name: sum(sizes[l] for l in ls) for name, ls in images.items()}
    used_layers = {l for ls in images.values() for l in ls}
    uppers = sum(u for _, u in containers)
    shared = sum(sizes[l] for l in used_layers) + uppers
    naive = sum(image_mb.values()) + sum(image_mb[img] for img, _ in containers) + uppers
    return shared, naive
---tests
sizes = {"os": 80, "py": 50, "web": 5, "worker": 3, "unused": 999}
images = {"web": ["os", "py", "web"], "worker": ["os", "py", "worker"]}
containers = [("web", 1), ("web", 0), ("web", 2), ("worker", 0)]
assert disk_usage(images, containers, sizes) == (141, 809)
assert disk_usage({"a": ["os"]}, [], sizes) == (80, 80)
---hint
The starter counts every layer in `sizes`, even unused ones. Shared usage counts each layer that some image uses, once.
---hint
Naive: each image stores its own layers (135 + 133), and each container copies its whole image (3 × 135 + 133), plus the uppers (3).
```

```recall
Q: Explain what a container is and how its filesystem works: namespaces, cgroups, image layers, the writable layer, copy-on-write, whiteouts, and how build caching decides what to rebuild.
A: A container is an ordinary process on the host kernel with fences around it. Namespaces change what it sees: its own process IDs (it can be PID 1), hostname, network, mounts and users. cgroups limit what it uses: CPU share, memory (going over gets it killed by the OOM killer), and number of processes. Its root filesystem comes from an image, a stack of read-only layers, each holding the changes from one build step. A running container adds a thin writable layer on top. Reading a file looks down the stack and takes the topmost match. Writing a file from a lower layer first copies it up into the writable layer (copy-on-write), so the shared layers never change and every other container still sees the original. Deleting writes a whiteout that hides the file. Because layers are shared, many containers cost one image plus their small changes, and starting one copies nothing. Each layer's ID is a hash of its parent's ID and its step, so a cached layer is reused only if it and every earlier step are unchanged; that's why dependency installs should come before copying code that changes often.
```
