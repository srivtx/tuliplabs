## The loop at the heart of a shell

A shell is a loop: **read** a line, **parse** it, **run** it, **wait**, repeat. Running a program on Unix takes two system calls: `fork()` copies the shell process, and in the copy `exec()` replaces it with the program. The parent `wait()`s for the child to exit and reads its exit code.

Everything interesting happens around that:

- `cmd > out.txt` opens the file and points the child's **standard output** (file descriptor 1) at it before `exec`. `>>` appends; `<` points **standard input** (descriptor 0) at a file.
- `a | b` creates a **pipe**, a small kernel buffer with a write end and a read end, and runs both programs **at the same time**: a's output goes into the pipe and b reads it out.
- `cmd &` runs in the **background**: the shell doesn't wait.
- `cd` and `export` must be **built-ins**: a child process changing its own directory wouldn't change the shell's.

## Parsing a command line

```exercise
title: parse_line
kind: write
---prompt
Write `parse_line(line)`. Split into tokens with `shlex.split` (imported for you in the starter). Return `(commands, background)`: `commands` is a list of dicts, one per stage of the pipeline, each `{"argv": [...], "stdin": None, "stdout": None, "append": False}`. `|` starts a new stage, `< file` sets `stdin`, `> file` sets `stdout`, `>> file` sets `stdout` with `append` True, and a final `&` sets `background`. A redirect with no file name, or an empty stage, raises `ValueError`.
---starter
import shlex

def parse_line(line):
    return [{"argv": shlex.split(line), "stdin": None, "stdout": None, "append": False}], False
---solution
import shlex

def parse_line(line):
    tokens = shlex.split(line)
    background = bool(tokens) and tokens[-1] == "&"
    if background:
        tokens = tokens[:-1]
    new = lambda: {"argv": [], "stdin": None, "stdout": None, "append": False}
    cmds, cur, i = [], new(), 0
    while i < len(tokens):
        t = tokens[i]
        if t == "|":
            if not cur["argv"]:
                raise ValueError("empty command")
            cmds.append(cur)
            cur = new()
        elif t in ("<", ">", ">>"):
            if i + 1 >= len(tokens) or tokens[i + 1] in ("|", "<", ">", ">>"):
                raise ValueError(f"{t} needs a file")
            i += 1
            if t == "<":
                cur["stdin"] = tokens[i]
            else:
                cur["stdout"], cur["append"] = tokens[i], t == ">>"
        else:
            cur["argv"].append(t)
        i += 1
    if not cur["argv"]:
        raise ValueError("empty command")
    cmds.append(cur)
    return cmds, background
---tests
cmds, bg = parse_line("cat < in.txt | grep -i 'two words' | sort >> out.txt &")
assert bg is True and len(cmds) == 3
assert cmds[0] == {"argv": ["cat"], "stdin": "in.txt", "stdout": None, "append": False}
assert cmds[1]["argv"] == ["grep", "-i", "two words"]
assert cmds[2] == {"argv": ["sort"], "stdin": None, "stdout": "out.txt", "append": True}
assert parse_line("ls > a.txt") == ([{"argv": ["ls"], "stdin": None, "stdout": "a.txt", "append": False}], False)
for bad in ("ls >", "| wc", "ls | | wc", "cat <"):
    try:
        parse_line(bad)
        assert False, f"{bad!r} should raise ValueError"
    except ValueError:
        pass
---hint
The starter treats everything as one command. Walk the tokens: `|` closes the current stage, a redirect consumes the next token.
---hint
Strip a final `&` first. Keep a `cur` dict; when you see `|` or reach the end, check it has an argv and append it.
```

```exercise
title: expand_vars
kind: write
---prompt
Write `expand(line, env)`: replace `$NAME` and `${NAME}` with `env.get(NAME, "")`. A name is letters, digits and underscores. Text inside single quotes is left exactly as is (that's why `echo '$HOME'` prints `$HOME`). Double quotes don't stop expansion. Keep all quote characters in the output; tokenizing comes later. A `$` not followed by a name stays a `$`.
---starter
def expand(line, env):
    for k, v in env.items():
        line = line.replace("$" + k, v)
    return line
---solution
def expand(line, env):
    out, i, quote = [], 0, False
    while i < len(line):
        ch = line[i]
        if ch == "'":
            quote = not quote
            out.append(ch)
            i += 1
        elif ch == "$" and not quote:
            if line[i + 1:i + 2] == "{":
                end = line.index("}", i)
                out.append(env.get(line[i + 2:end], ""))
                i = end + 1
            else:
                j = i + 1
                while j < len(line) and (line[j].isalnum() or line[j] == "_"):
                    j += 1
                out.append(env.get(line[i + 1:j], "") if j > i + 1 else "$")
                i = j
        else:
            out.append(ch)
            i += 1
    return "".join(out)
---tests
env = {"HOME": "/home/sam", "USER": "sam", "USERNAME": "sammy"}
assert expand("cd $HOME/docs", env) == "cd /home/sam/docs"
assert expand("echo $USERNAME ${USER}NAME", env) == "echo sammy samNAME", "longest name wins; braces end it"
assert expand("echo '$HOME' \"$USER\"", env) == "echo '$HOME' \"sam\""
assert expand("echo $MISSING.", env) == "echo ."
assert expand("cost: 5$ or $", env) == "cost: 5$ or $"
---hint
`str.replace` gets `$USERNAME` wrong (it replaces the `$USER` part) and ignores single quotes. Scan character by character.
---hint
Track whether you're inside single quotes. At a `$`, either read up to `}` or read the longest run of letters, digits and underscores.
```

```exercise
title: redirect_bug
kind: bug
---prompt
This redirect handler forgets that the file name is a separate token: it adds `>` to the argv and the file name too, so `echo hi > out.txt` runs `echo` with three arguments. Fix it so the redirect and its file are consumed.
---starter
def split_redirect(tokens):
    argv, out = [], None
    for i, t in enumerate(tokens):
        if t == ">":
            out = tokens[i + 1]
        argv.append(t)
    return argv, out
---solution
def split_redirect(tokens):
    argv, out, i = [], None, 0
    while i < len(tokens):
        if tokens[i] == ">":
            out = tokens[i + 1]
            i += 2
            continue
        argv.append(tokens[i])
        i += 1
    return argv, out
---tests
assert split_redirect(["echo", "hi", ">", "out.txt"]) == (["echo", "hi"], "out.txt")
assert split_redirect(["ls"]) == (["ls"], None)
assert split_redirect([">", "f", "echo", "x"]) == (["echo", "x"], "f"), "a redirect can come first"
---hint
A `for` loop can't skip the next item. Use an index and step over two tokens at a redirect.
```

## Pipes are lazy streams

Python generators behave like pipes: each stage pulls one item at a time from the one before, and nothing runs ahead. `head` that stops pulling stops the whole chain, so it works even on an endless source.

```exercise
title: lazy_pipeline
kind: write
---prompt
Write the stages as generator functions that take an iterator of lines and yield lines: `grep(pattern)` keeps lines containing `pattern`, `head(n)` passes the first n and stops, `upper()` upper-cases. Each returns a **stage** (a function from iterator to iterator). Then `pipe(source, *stages)` connects them and returns the final iterator. `pipe(count(1), ...)` on an endless source must still finish when `head` is last.
---starter
def grep(pattern):
    return lambda lines: [l for l in lines if pattern in l]

def head(n):
    return lambda lines: list(lines)[:n]

def upper():
    return lambda lines: [l.upper() for l in lines]

def pipe(source, *stages):
    return iter([])
---solution
def grep(pattern):
    def stage(lines):
        for line in lines:
            if pattern in line:
                yield line
    return stage

def head(n):
    def stage(lines):
        if n <= 0:
            return
        for k, line in enumerate(lines, 1):
            yield line
            if k == n:
                return
    return stage

def upper():
    def stage(lines):
        for line in lines:
            yield line.upper()
    return stage

def pipe(source, *stages):
    it = iter(source)
    for s in stages:
        it = s(it)
    return it
---tests
from itertools import count
words = ["apple", "banana", "cherry", "grape", "pear"]
assert list(pipe(words, grep("an"), upper())) == ["BANANA"]
assert list(pipe(words, head(2))) == ["apple", "banana"]
assert list(pipe(words, head(0))) == []
nums = (str(i) for i in count(1))
assert list(pipe(nums, grep("7"), head(3))) == ["7", "17", "27"], "must stop on an endless source"
pulled = []
def spy(lines):
    for l in lines:
        pulled.append(l)
        yield l
list(pipe((str(i) for i in count(1)), spy, head(5)))
assert len(pulled) == 5, f"head(5) should pull only 5 lines, pulled {len(pulled)}"
---hint
The starter's list comprehensions read everything first. With `yield`, nothing runs until someone asks for the next item.
---hint
In `head`, return as soon as you've yielded n lines, without asking for the next. `pipe` is just `it = stage(it)` in a loop.
```

```quiz
Why must `cd` be built into the shell instead of being a program like `ls`?
- It's faster
* A program runs in a child process, and a child changing its own working directory doesn't change the shell's
- `cd` needs root
- Programs can't read directories
> Same for `export` and `exit`: they change the shell's own state.
```

```quiz
`yes` prints "y" forever. Why does `yes | head -3` finish?
- yes notices it has printed enough
* head exits after 3 lines and closes the pipe's read end; yes's next write fails with SIGPIPE, which stops it
- The shell kills yes after one second
- The pipe holds only 3 lines
> The pipe also stops yes running ahead: once its buffer is full, yes waits until head reads.
```

```exercise
title: mini_shell
kind: write
---prompt
Write `sh(line, fs)`, a shell over a pretend file system `fs` (a dict of file name → text). Commands read lines from their input and produce lines:

- `echo WORDS...`: one line, the words joined by spaces.
- `cat [FILE]`: the file's lines, or its input if no file.
- `grep WORD`: input lines containing WORD.
- `sort`: input lines sorted.
- `wc -l`: one line, the number of input lines.

Support `|` between commands, and a final `> FILE` or `>> FILE`. With a redirect, write the output (lines joined by `"\n"`, with a final `"\n"`; append adds to the end) and return `""`. Otherwise return the output lines joined by `"\n"`. Split tokens with `shlex.split`.
---starter
import shlex

def sh(line, fs):
    argv = shlex.split(line)
    if argv[0] == "echo":
        return " ".join(argv[1:])
    return ""
---solution
import shlex

def sh(line, fs):
    tokens = shlex.split(line)
    target, append = None, False
    if len(tokens) >= 2 and tokens[-2] in (">", ">>"):
        target, append = tokens[-1], tokens[-2] == ">>"
        tokens = tokens[:-2]
    stages, cur = [], []
    for t in tokens:
        if t == "|":
            stages.append(cur)
            cur = []
        else:
            cur.append(t)
    stages.append(cur)
    lines = []
    for argv in stages:
        cmd, args = argv[0], argv[1:]
        if cmd == "echo":
            lines = [" ".join(args)]
        elif cmd == "cat":
            lines = fs[args[0]].splitlines() if args else lines
        elif cmd == "grep":
            lines = [l for l in lines if args[0] in l]
        elif cmd == "sort":
            lines = sorted(lines)
        elif cmd == "wc" and args == ["-l"]:
            lines = [str(len(lines))]
        else:
            raise ValueError(f"unknown command {cmd}")
    if target:
        text = "".join(l + "\n" for l in lines)
        fs[target] = fs.get(target, "") + text if append else text
        return ""
    return "\n".join(lines)
---tests
fs = {"log.txt": "ok start\nerror disk\nok save\nerror net\n"}
assert sh("echo hello   world", fs) == "hello world"
assert sh("cat log.txt | grep error", fs) == "error disk\nerror net"
assert sh("cat log.txt | grep error | wc -l", fs) == "2"
assert sh("cat log.txt | sort | grep ok > oks.txt", fs) == "" and fs["oks.txt"] == "ok save\nok start\n"
sh("echo third >> oks.txt", fs)
assert fs["oks.txt"] == "ok save\nok start\nthird\n"
sh("echo 'a  b' > new.txt", fs)
assert sh("cat new.txt", fs) == "a  b", "quotes keep the spaces"
---hint
Peel off a trailing `> FILE` or `>> FILE` first, then split the rest on `|` into stages.
---hint
Keep one `lines` list and let each stage replace it: `grep` filters, `sort` sorts, `wc -l` turns it into a single count.
```

## Rebuild it and explain it

```exercise
title: pipe_rebuild
kind: rebuild
---prompt
From memory: `pipe(source, *stages)` that chains generator stages, plus `head(n)` that stops pulling after n items.
---starter
def head(n):
    pass

def pipe(source, *stages):
    pass
---solution
def head(n):
    def stage(lines):
        if n <= 0:
            return
        for k, line in enumerate(lines, 1):
            yield line
            if k == n:
                return
    return stage

def pipe(source, *stages):
    it = iter(source)
    for s in stages:
        it = s(it)
    return it
---tests
from itertools import count
assert list(pipe(count(5), head(3))) == [5, 6, 7]
assert list(pipe([1, 2], head(5))) == [1, 2]
---hint
A generator that returns after its nth `yield`, and a loop of `it = stage(it)`.
```

```recall
Q: Explain how a shell runs `cat in.txt | grep x > out.txt &`: parsing, the system calls involved, what a pipe is, why some commands are built-ins, and how variables are expanded.
A: The shell reads a line, expands variables ($NAME and ${NAME}, but not inside single quotes), splits it into tokens with quotes grouping words, then parses: | separates pipeline stages, < > >> attach redirects to a stage, and a final & means background. To run it, the shell creates a pipe (a small kernel buffer with a read end and a write end), then forks a child for each stage. In each child it uses dup2 to point standard output (fd 1) at the pipe's write end or the output file, and standard input (fd 0) at the pipe's read end or input file, then exec replaces the child with the program. Both programs run at once; a full pipe makes the writer wait, an empty one makes the reader wait, and when the reader exits the writer gets SIGPIPE. Without &, the shell waits for the children and keeps the last exit code in $?. cd, export and exit are built-ins because they must change the shell's own process; a child changing its directory would leave the shell where it was.
```
