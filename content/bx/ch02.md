## What a calculator really does

Type `2+3*4` into your phone and you get 14, not 20. Somewhere inside, the calculator decided the `*` goes first. How?

It doesn't read left to right. It runs three small machines, one after another:

1. **Tokenizer:** characters → words (`"12"` is one number, not two digits).
2. **Parser:** words → a **tree**. Operators that bind tightly sit *deeper*.
3. **Evaluator:** the tree → one number, starting from the leaves.

Play with all three before writing any code.

```quiz
In the tree for `2+3*4`, which operator is at the very top (the root)?
- `*`, because it runs first
* `+`, because it runs last
- Neither; the root is always a number
- It depends on the order you type it
> The root is computed **last**: it needs both children finished first. `+` binds loosely, so it ends up on top, and `*` sits underneath it.
```

## Tokens: from characters to words

A **token** is the smallest meaningful piece: a number, an operator or a bracket. The tokenizer walks the string one character at a time. When it sees a digit, it keeps going while the next character is also a digit, so `12` becomes one token.

```predict
src = "12+3"
tokens = []
i = 0
while i < len(src):
    if src[i].isdigit():
        j = i
        while j < len(src) and src[j].isdigit():
            j += 1
        tokens.append(src[i:j])
        i = j
    else:
        tokens.append(src[i])
        i += 1
print(tokens)
print(len(tokens))
```

```exercise
def tokenize(src):
    tokens = []

        c = src[i]
        if c == " ":
            i += 1
        elif c.isdigit() or c == ".":
            j = i
```

## Precedence is the shape of the tree

Here is the trick that makes `*` go first without any special case: write **one function per precedence level**, and let the loosest level call the tighter one.

- `expr()` handles `+` and `-`. To get its operands it calls…
- `term()`, which handles `*` and `/`. To get *its* operands it calls…
- `factor()`, which reads a number or a whole `( … )` group.

Because `term()` finishes building `3*4` before `expr()` ever sees the `+`, the multiplication ends up deeper in the tree. This style is called **recursive descent**, and real compilers (GCC, Clang, Go, V8) use it.

We'll store a tree as nested tuples: a number is just a `float`, and an operation is `(op, left, right)`. So `2+3*4` is `("+", 2.0, ("*", 3.0, 4.0))`.

```parsons

    def peek(self): return self.t[self.i] if self.i < len(self.t) else None
    def take(self):
        self.i += 1
        return self.t[self.i - 1]

    return p.take()
---tests
```


## Evaluate from the leaves up

Evaluation is the easy part, and it's **recursive**: a number is its own value; an operation evaluates its left child, then its right child, then combines them. The recursion naturally goes to the deepest node first, which is why the tree's shape decides the order.

```predict
def ev(t):
    if isinstance(t, float):
        return t
    op, a, b = t
    x, y = ev(a), ev(b)
    print("compute", x, op, y)
    return x + y if op == "+" else x * y

print(ev(("+", 2.0, ("*", 3.0, 4.0))))
```

```exercise
---solution
def evaluate(tree):
    if isinstance(tree, (int, float)):
        return float(tree)
    op, a, b = tree
    x, y = evaluate(a), evaluate(b)
    if op == "+": return x + y
    if op == "-": return x - y
    if op == "*": return x * y
    if op == "/": return x / y
    if op == "^": return x ** y
    raise ValueError(f"unknown operator {op}")
---tests
assert evaluate(5.0) == 5.0, "a number evaluates to itself"
assert evaluate(("+", 2.0, ("*", 3.0, 4.0))) == 14.0, "2+3*4 = 14"
assert evaluate(("-", ("-", 8.0, 3.0), 2.0)) == 3.0, "(8-3)-2 = 3"
assert evaluate(("^", 2.0, 10.0)) == 1024.0, "2^10 = 1024"
try:
    evaluate(("/", 1.0, 0.0)); assert False, "dividing by zero should raise"
except ZeroDivisionError:
    pass
---hint
Start with the base case: `if isinstance(tree, (int, float)): return float(tree)`. Otherwise unpack `op, a, b = tree` and evaluate both sides first.
```

## Errors that point at the mistake

A good calculator doesn't just say "error". It says *where*. This version runs, but its message about a missing number is wrong.

## Real-world project: a spreadsheet formula engine

Every spreadsheet (Excel, Google Sheets, Numbers) has exactly the machine you just built at its core. A cell like `=A1*2+B1` is tokenized, parsed into a tree and evaluated, except some leaves are **cell names** that you look up.

```project
title: Mini spreadsheet: formulas that reference other cells
client: A small bakery tracking costs in a sheet
skills: tokenizer, recursive descent, recursion, dictionaries
---brief
The bakery's sheet has cells like `A1 = 2.5` (flour price), `A2 = 4` (bags) and `A3 = A1*A2` (total). Change the flour price and the total must update. Your job: extend your calculator so a leaf can be a **cell name**, and evaluating it means evaluating *that* cell's formula.
---why
This is how spreadsheets, build systems (a target depends on other targets) and reactive UI frameworks (a value depends on other values) all work: a **dependency graph** evaluated on demand. Spotting a cycle (`A1 = A2`, `A2 = A1`) is the same check `make` does.
---milestones
- Teach the tokenizer a new token kind: a letter followed by digits (`A1`, `B12`)
- In `factor`, return a `("cell", name)` leaf for cell names
- Write `cell_value(sheet, name)` that parses and evaluates that cell's formula
- Detect cycles: if evaluating `A1` needs `A1` again, raise a clear error
- Stretch it: add `SUM(A1:A3)` as a function call in `factor`
---stretch
- Cache values and only recompute cells whose inputs changed (this is what makes big sheets fast)
- Draw the dependency graph of your sheet with arrows
- Add `IF(cond, a, b)` and comparison operators
```

```exercise
def cell_value(sheet, name, visiting=None):
    visiting = set() if visiting is None else visiting
    if name in visiting:
        raise ValueError(f"cycle through {name}")
    content = sheet[name]
    if isinstance(content, (int, float)):
        return float(content)
    visiting = visiting | {name}
    def ev(t):
        if isinstance(t, float):
            return t
        if isinstance(t, str):
            return cell_value(sheet, t, visiting)
```

## Rebuild it and explain it

```exercise
title: calc
kind: rebuild
---prompt
From memory: write `calc(src)` that tokenizes, parses (with `+ -` looser than `* /`, and brackets) and evaluates a string. No peeking at the steps above.
---starter
def calc(src):
    # tokenize, parse, evaluate
    pass
---solution
def calc(src):
    toks, i = [], 0
    while i < len(src):
        c = src[i]
        if c.isdigit() or c == ".":
            j = i
            while j < len(src) and (src[j].isdigit() or src[j] == "."):
                j += 1
            toks.append(float(src[i:j])); i = j
        elif c in "+-*/()":
            toks.append(c); i += 1
        else:
            i += 1
    pos = [0]
    peek = lambda: toks[pos[0]] if pos[0] < len(toks) else None
    def take():
        pos[0] += 1
        return toks[pos[0] - 1]
    def expr():
        v = term()
        while peek() in ("+", "-"):
            v = v + term() if take() == "+" else v - term()
        return v
    def term():
        v = factor()
        while peek() in ("*", "/"):
            v = v * factor() if take() == "*" else v / factor()
        return v
    def factor():
        t = take()
        if t == "(":
            v = expr(); take(); return v
        return t
    return expr()
---tests
assert calc("2+3*4") == 14, "2+3*4 = 14"
assert calc("(2+3)*4") == 20, "(2+3)*4 = 20"
assert calc("10 - 4 - 3") == 3, "10-4-3 = 3 (left to right at the same level)"
assert calc("7/2") == 3.5, "7/2 = 3.5"
---hint
You can evaluate *while* you parse: have `expr`, `term` and `factor` return numbers instead of trees.
```

```recall
Q: In your own words: why does `2+3*4` give 14 in your calculator, even though nothing in the code says "do multiplication first"?
A: Because the parser has one function per precedence level, and the `+` level gets its operands by calling the `*` level. So `3*4` is completely built (and becomes a subtree) before the `+` is combined. Evaluation is bottom-up, so deeper nodes are computed first. Precedence is the shape of the tree.
```
