## The network makes no promises

When you send data across the internet, it's chopped into **packets** of about 1500 bytes. Each one is passed from router to router, and any of them may:

- **drop** it (its queue was full),
- **corrupt** it (a flipped bit on a noisy link),
- **reorder** it (two packets took different paths),
- or **duplicate** it.

The internet's designers decided *not* to fix this inside the network: routers stay simple and fast. Instead the two **ends** fix it, in software. That software is TCP, and this chapter builds its core ideas.

## Spotting damage: checksums

Every packet carries a **checksum**: a number computed from its bytes. The receiver recomputes it; if it differs, the packet was damaged, and it's thrown away (and later resent, just like a lost one).

```exercise
title: packets
kind: write
---prompt
Write `make_packet(seq, payload)` returning `bytes`: 2 bytes of sequence number (big-endian), 2 bytes of checksum, then the payload. The checksum is the sum of all **payload** bytes plus `seq`, modulo 65536. Write `parse_packet(packet)` returning `(seq, payload)`, or `None` if the checksum doesn't match.
---starter
def make_packet(seq, payload):
    return b""

def parse_packet(packet):
    return None
---solution
def make_packet(seq, payload):
    check = (seq + sum(payload)) % 65536
    return seq.to_bytes(2, "big") + check.to_bytes(2, "big") + payload

def parse_packet(packet):
    seq = int.from_bytes(packet[0:2], "big")
    check = int.from_bytes(packet[2:4], "big")
    payload = packet[4:]
    if (seq + sum(payload)) % 65536 != check:
        return None
    return seq, payload
---tests
p = make_packet(7, b"hi")
assert p == bytes([0, 7, 0, 7 + 104 + 105]) + b"hi", p
assert parse_packet(p) == (7, b"hi"), "round trip"
damaged = p[:4] + b"ho"
assert parse_packet(damaged) is None, "a changed byte is detected"
assert parse_packet(make_packet(300, b"")) == (300, b""), "empty payload, seq above 255"
---hint
`n.to_bytes(2, "big")` and `int.from_bytes(b, "big")` convert between numbers and 2-byte fields. `sum(payload)` adds a bytes object's byte values.
```

```quiz
This checksum adds up bytes. Which damage can it **miss**?
- One byte changing value
* Two bytes swapping places
- A byte being removed
- The sequence number changing
> Addition doesn't care about order, so swapped bytes give the same sum. Real protocols use checksums that mix in position (TCP's own is weak too; Ethernet adds a much stronger CRC underneath).
```

## Putting the pieces back in order

Packets arrive in any order, maybe twice. Sequence numbers let the receiver rebuild the original stream.

```exercise
title: reassemble
kind: write
---prompt
Write `reassemble(packets, n)` where `packets` is a list of `(seq, text)` in arrival order (possibly out of order, possibly with duplicates), and `n` is how many packets the message has (numbered 0 to n−1). Return the joined text, or `None` if any packet is missing.
---starter
def reassemble(packets, n):
    return None
---solution
def reassemble(packets, n):
    got = dict(packets)
    if any(k not in got for k in range(n)):
        return None
    return "".join(got[k] for k in range(n))
---tests
assert reassemble([(2, "c"), (0, "a"), (1, "b")], 3) == "abc", "out of order"
assert reassemble([(0, "a"), (0, "a"), (1, "b")], 2) == "ab", "a duplicate is harmless"
assert reassemble([(0, "a"), (2, "c")], 3) is None, "packet 1 never arrived"
assert reassemble([], 0) == "", "an empty message"
---hint
A dict keyed by sequence number absorbs duplicates and lets you read the packets back in order.
```

## Stop-and-wait: never give up

The simplest reliable protocol: send one packet, wait for its acknowledgement, and if nothing comes back before a **timeout**, send it again. Repeat for each packet.

```exercise
title: stop_and_wait
kind: write
---prompt
Write `stop_and_wait(n, channel)` that delivers packets `0` to `n−1`. `channel(seq)` simulates one send-and-wait: it returns `True` if the packet **and** its ack got through, `False` if something was lost (a timeout). Keep resending each packet until it succeeds. Return the list of every sequence number you sent, in order.
---starter
def stop_and_wait(n, channel):
    return []
---solution
def stop_and_wait(n, channel):
    log = []
    for seq in range(n):
        while True:
            log.append(seq)
            if channel(seq):
                break
    return log
---tests
drops = {(1, 0), (1, 1), (3, 0)}
attempts = {}
def channel(seq):
    k = attempts.get(seq, 0)
    attempts[seq] = k + 1
    return (seq, k) not in drops
assert stop_and_wait(4, channel) == [0, 1, 1, 1, 2, 3, 3], "packet 1 is lost twice, packet 3 once"
assert stop_and_wait(0, lambda s: True) == [], "nothing to send"
---hint
An outer loop over the packets, and an inner `while True` that sends (records) and stops once the channel returns `True`.
```

How fast can it go? At most one packet per **round-trip time** (RTT), however fast the link is.

```predict
packet_bytes = 1500
rtt = 0.1                       # 100 ms, roughly Europe to the US and back
for window in (1, 10, 100):
    print(window, "packets in flight:", round(window * packet_bytes / rtt / 1e6, 2), "MB/s")
```

## Sliding windows and out-of-order packets

With a window, many packets are in flight, so some arrive out of order. The simulation used **go-back-N**: the receiver throws away anything out of order, and the sender resends from the gap. Real TCP is smarter: the receiver **buffers** out-of-order packets and hands the application a gap-free stream as soon as the gap fills. It always acknowledges with the **next sequence number it still needs** (a cumulative ack).

```exercise
title: receiver_bug
kind: bug
---prompt
`Receiver.receive(seq, data)` buffers packets and should deliver every packet it can, in order, returning the next sequence number it needs. When packet 0 arrives after 1 and 2, it only delivers packet 0, leaving 1 and 2 stuck in the buffer. Fix it.
---starter
class Receiver:
    def __init__(self):
        self.expected, self.buffer, self.delivered = 0, {}, []

    def receive(self, seq, data):
        if seq >= self.expected:
            self.buffer[seq] = data
        if self.expected in self.buffer:
            self.delivered.append(self.buffer.pop(self.expected))
            self.expected += 1
        return self.expected
---solution
class Receiver:
    def __init__(self):
        self.expected, self.buffer, self.delivered = 0, {}, []

    def receive(self, seq, data):
        if seq >= self.expected:
            self.buffer[seq] = data
        while self.expected in self.buffer:
            self.delivered.append(self.buffer.pop(self.expected))
            self.expected += 1
        return self.expected
---tests
r = Receiver()
assert r.receive(1, "E") == 0 and r.receive(2, "L") == 0, "still waiting for packet 0"
assert r.receive(0, "R") == 3, "0 fills the gap, so 0, 1 and 2 are all delivered"
assert r.delivered == ["R", "E", "L"], r.delivered
assert r.receive(1, "E") == 3 and r.delivered == ["R", "E", "L"], "an old duplicate changes nothing"
---hint
One arriving packet can unlock a whole run of buffered ones. `if` checks once; what checks repeatedly?
```

## How long to wait? And how fast to send?

Two more problems make TCP what it is.

**The timeout.** Too short and you resend packets that weren't lost; too long and a loss stalls everything. TCP measures the round-trip time continuously and keeps a smoothed average plus a measure of how much it varies, then waits a bit longer than "usual".

**Congestion.** If every sender blasts at full speed, router queues overflow and *everyone's* packets get dropped. TCP's congestion control uses **AIMD**: each round trip without loss, grow the window by 1 packet (additive increase); on a loss, halve it (multiplicative decrease). The result is the sawtooth that has kept the internet from collapsing since 1988.

```exercise
title: aimd
kind: write
---prompt
Write `aimd(losses, start=1)` where `losses` is a list of booleans, one per round trip (`True` = a loss happened). Starting from a window of `start`, return the list of window sizes **after** each round trip: +1 on no loss, halve (integer division, but never below 1) on a loss.
---starter
def aimd(losses, start=1):
    return []
---solution
def aimd(losses, start=1):
    w, out = start, []
    for lost in losses:
        w = max(1, w // 2) if lost else w + 1
        out.append(w)
    return out
---tests
assert aimd([False, False, False]) == [2, 3, 4], "additive increase"
assert aimd([False] * 5 + [True] + [False] * 2) == [2, 3, 4, 5, 6, 3, 4, 5], "the sawtooth"
assert aimd([True, True], start=1) == [1, 1], "never below 1"
---hint
Keep one variable for the window. Each step is either `w + 1` or `max(1, w // 2)`.
```

```exercise
title: rtt_estimator
kind: write
---prompt
Write `rto(samples, alpha=0.125, beta=0.25)` implementing TCP's timeout rule (RFC 6298) and returning the timeout after processing every round-trip sample. On the first sample `r`: `srtt = r`, `rttvar = r / 2`. On each later sample: first `rttvar = (1 − beta) × rttvar + beta × |srtt − r|`, then `srtt = (1 − alpha) × srtt + alpha × r`. The timeout is `srtt + 4 × rttvar`.
---starter
def rto(samples, alpha=0.125, beta=0.25):
    return 0.0
---solution
def rto(samples, alpha=0.125, beta=0.25):
    srtt = rttvar = None
    for r in samples:
        if srtt is None:
            srtt, rttvar = r, r / 2
        else:
            rttvar = (1 - beta) * rttvar + beta * abs(srtt - r)
            srtt = (1 - alpha) * srtt + alpha * r
    return srtt + 4 * rttvar
---tests
assert rto([100]) == 300, "one sample: 100 + 4 × 50"
assert abs(rto([100, 100, 100, 100]) - (100 + 4 * 50 * 0.75 ** 3)) < 1e-9, "steady RTTs: the timeout shrinks toward the RTT"
jumpy, steady = rto([100, 40, 160, 50, 150]), rto([100, 100, 100, 100, 100])
assert jumpy > steady, "a jumpy network gets a longer, safer timeout"
---hint
Keep two variables, set from the first sample, then updated in the order given: `rttvar` uses the **old** `srtt`.
```

## Rebuild it and explain it

```exercise
title: in_order_rebuild
kind: rebuild
---prompt
From memory: write `deliver(arrivals)` that takes a list of `(seq, data)` in arrival order and returns `(delivered, acks)`: the data handed to the application in order (buffering anything that arrives early, ignoring duplicates), and the cumulative ack sent after each arrival (the next sequence number still needed).
---starter
def deliver(arrivals):
    pass
---solution
def deliver(arrivals):
    expected, buffer, delivered, acks = 0, {}, [], []
    for seq, data in arrivals:
        if seq >= expected:
            buffer[seq] = data
        while expected in buffer:
            delivered.append(buffer.pop(expected))
            expected += 1
        acks.append(expected)
    return delivered, acks
---tests
assert deliver([(0, "a"), (2, "c"), (1, "b")]) == (["a", "b", "c"], [1, 1, 3])
assert deliver([(1, "b"), (1, "b"), (0, "a")]) == (["a", "b"], [0, 0, 2]), "duplicates and a late first packet"
assert deliver([]) == ([], [])
---hint
`expected`, a `buffer` dict, and a `while` loop that drains the buffer as long as the next needed packet is there.
```

```recall
Q: Explain how TCP delivers a reliable, in-order stream over a network that drops, corrupts and reorders packets.
A: Every packet carries a sequence number and a checksum. The receiver discards damaged packets, buffers ones that arrive early, delivers data to the application only in order with no gaps, and sends cumulative acknowledgements naming the next sequence number it needs. The sender keeps copies of unacknowledged packets and resends any whose ack doesn't arrive before a timeout; the timeout adapts to a smoothed round-trip time plus four times its variation. Stop-and-wait is reliable but sends one packet per round trip, so TCP keeps a sliding window of many packets in flight. The window's size is set by congestion control: grow by one packet per round trip without loss, halve it on a loss (AIMD), so senders share the network instead of overwhelming it. The network itself stays simple; reliability is built end to end.
```
