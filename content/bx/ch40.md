## Who wins, and what do they pay?

An auction engine answers two questions: **who wins**, and **what they pay**. The second one changes how people bid.

In a **first-price** sealed-bid auction the winner pays their own bid. Bidding your true value means winning with no gain at all, so everyone bids less and guesses how much less. In a **second-price** (Vickrey) auction the winner pays the **second-highest** bid. Your bid only decides *whether* you win, never what you pay, so the best thing to bid is exactly what it's worth to you.

```viz
name: bx-auction
title: Six sealed bids for one painting
goal: Run **first price** to the end, then run **second price** and see who wins each time.
height: 440
Each bidder knows only their own value.
```

Why is truth safe in second price? Say it's worth 90 to you. If you bid 70 and the top other bid is 80, you lose something you'd have gained 10 on. If you bid 110 and the top other bid is 100, you win and pay 100 for something worth 90. Bidding 90 never does either.

## Sealed bids

```exercise
title: sealed_auction
kind: write
---prompt
Write `sealed(bids, rule, reserve=0)`. `bids` is a list of `(name, amount)` in the order they arrived; `rule` is `"first"` or `"second"`. The highest bid wins; on a tie the earlier bid wins. Return `(winner, price)`, or `None` if there are no bids or the highest is below `reserve`. First price: the winner pays their bid. Second price: the winner pays the larger of the runner-up's bid and the reserve (just the reserve if they're the only bidder).
---starter
def sealed(bids, rule, reserve=0):
    name, amount = max(bids, key=lambda b: b[1])
    return (name, amount)
---solution
def sealed(bids, rule, reserve=0):
    if not bids:
        return None
    order = sorted(range(len(bids)), key=lambda i: (-bids[i][1], i))
    name, top = bids[order[0]]
    if top < reserve:
        return None
    if rule == "first":
        return (name, top)
    second = bids[order[1]][1] if len(bids) > 1 else 0
    return (name, max(second, reserve))
---tests
b = [("ana", 56), ("ben", 63), ("chi", 71), ("dev", 43)]
assert sealed(b, "first") == ("chi", 71)
assert sealed(b, "second") == ("chi", 63)
assert sealed([("a", 50), ("b", 50)], "second") == ("a", 50), "the earlier bid wins a tie"
assert sealed(b, "second", reserve=65) == ("chi", 65)
assert sealed(b, "first", reserve=80) is None
assert sealed([("solo", 40)], "second", reserve=25) == ("solo", 25)
assert sealed([], "first") is None
---hint
The starter ignores the rule, ties, the reserve and empty lists. Sort indices by `(-amount, index)` so ties go to the earlier bid.
```

## Proxy bidding and sniping

On eBay you don't bid 41, then 42, then 43. You enter your **maximum** and the site bids for you, one step at a time, only as high as needed. That's a second-price auction in disguise: the winner pays about the runner-up's maximum plus one step.

```exercise
title: proxy_bidding
kind: write
---prompt
Write `proxy(maxes, start, step)`. `maxes` is a list of `(name, max_bid)` in arrival order. With no bidders return `None`; with one, they win at `start`. Otherwise the highest maximum wins (the earlier one on a tie) and pays the runner-up's maximum plus `step`, but never more than their own maximum. Return `(winner, price)`.
---starter
def proxy(maxes, start, step):
    name, top = max(maxes, key=lambda m: m[1])
    return (name, top)
---solution
def proxy(maxes, start, step):
    if not maxes:
        return None
    order = sorted(range(len(maxes)), key=lambda i: (-maxes[i][1], i))
    name, top = maxes[order[0]]
    if len(maxes) == 1:
        return (name, start)
    second = maxes[order[1]][1]
    return (name, min(top, second + step))
---tests
assert proxy([("a", 120), ("b", 95), ("c", 100)], 10, 1) == ("a", 101)
assert proxy([("a", 100), ("b", 100)], 10, 5) == ("a", 100), "capped at the winner's own max"
assert proxy([("solo", 500)], 10, 1) == ("solo", 10)
assert proxy([], 10, 1) is None
assert proxy([("x", 30), ("y", 80), ("z", 79)], 5, 2) == ("y", 80)
---hint
The starter charges the winner their whole maximum. The price is the runner-up's maximum plus one step, capped.
```

**Sniping** is bidding in the final second so nobody has time to respond. Many auction sites stop it with a **soft close**: any bid in the last few minutes pushes the end back.

```exercise
title: soft_close
kind: bug
---prompt
`closing_time(bid_times, end, window, extend)` should return when the auction really ends. A bid placed at or after `end - window` (and before the current end) pushes the end to `bid_time + extend`. Bids at or after the current end are ignored. `bid_times` is sorted. This version checks every bid against the **original** end, so a chain of late bids only extends once. Fix it.
---starter
def closing_time(bid_times, end, window, extend):
    current = end
    for t in bid_times:
        if end - window <= t < end:
            current = t + extend
    return current
---solution
def closing_time(bid_times, end, window, extend):
    current = end
    for t in bid_times:
        if t >= current:
            break
        if t >= current - window:
            current = max(current, t + extend)
    return current
---tests
assert closing_time([10, 50], 100, 5, 5) == 100
assert closing_time([97], 100, 5, 5) == 102
assert closing_time([97, 101], 100, 5, 5) == 106, "the second late bid extends again"
assert closing_time([97, 101, 105, 109], 100, 5, 5) == 114
assert closing_time([97, 103], 100, 5, 5) == 102, "103 arrives after the auction already closed"
---hint
Compare each bid with the **current** end, not the original one, and stop at the first bid that comes too late.
```

```exercise
title: gsp
kind: write
---prompt
Write `gsp(bids, slots, reserve)`. `bids` is a list of `(name, per_click)` in arrival order. Drop bids below `reserve`, rank the rest highest first (earlier wins ties), and give the top `slots` of them a slot each. The ad in each slot pays the bid of the ad ranked just below it, or the `reserve` if there is none. Return a list of `(name, price)` from the top slot down.
---starter
def gsp(bids, slots, reserve):
    ranked = sorted(bids, key=lambda b: -b[1])
    return [(n, p) for n, p in ranked[:slots]]
---solution
def gsp(bids, slots, reserve):
    ok = [(i, n, p) for i, (n, p) in enumerate(bids) if p >= reserve]
    ok.sort(key=lambda t: (-t[2], t[0]))
    out = []
    for k in range(min(slots, len(ok))):
        below = ok[k + 1][2] if k + 1 < len(ok) else reserve
        out.append((ok[k][1], below))
    return out
---tests
bids = [("jobs4u", 300), ("hireme", 120), ("devboard", 250), ("cheap", 40), ("talent", 250)]
assert gsp(bids, 3, 50) == [("jobs4u", 250), ("devboard", 250), ("talent", 120)]
assert gsp(bids, 1, 50) == [("jobs4u", 250)]
assert gsp([("a", 100)], 3, 30) == [("a", 30)]
assert gsp([("a", 20)], 2, 30) == []
assert gsp(bids, 5, 50)[-1] == ("hireme", 50), "the last ad pays the reserve"
---hint
The starter charges every ad its own bid. Each slot's price is the next ad's bid down the ranking.
```

    if not bids:

```recall
Q: Explain how an auction engine picks a winner and a price: first-price versus second-price sealed bids, why second price makes truthful bidding best, reserves, proxy bidding, soft closes, and generalized second price for ad slots.
A: In a sealed-bid auction the highest bid wins, with ties going to the earliest bid. In a first-price auction the winner pays their own bid, so bidders shade below their true value by a guess, and the item can go to someone who values it less. In a second-price (Vickrey) auction the winner pays the second-highest bid, so a bid only decides whether you win, never what you pay; bidding your true value can never do worse than bidding anything else, and the item goes to whoever values it most. A reserve price is the seller's minimum: no sale below it, and in second price the winner pays at least the reserve. Proxy bidding, as on eBay, takes each bidder's maximum and charges the winner the runner-up's maximum plus one increment, which is second price in disguise. A soft close extends the auction whenever a bid lands in the last few minutes, so sniping gains nothing. For several ad slots, generalized second price ranks bids and charges each slot the bid of the ad ranked just below it, or the reserve for the last.
```
