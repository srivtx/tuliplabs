## What `pip install` actually does

You ask for two packages. Each of them needs other packages, at certain versions, and those need more. The package manager has to choose **one version of every package** so that every requirement, from you and from every package, is satisfied at once. That's called **dependency resolution**, and it's a genuinely hard search problem (in general, as hard as Sudoku).

When it fails you see errors like pip's *ResolutionImpossible* or npm's *ERESOLVE unable to resolve dependency tree*. After this chapter you'll know exactly what they mean.

## Version numbers aren't decimals

Most packages use **semantic versioning**: `MAJOR.MINOR.PATCH`. A patch fixes bugs, a minor version adds features without breaking anything, and a major version may break your code.

```predict
print("1.10.0" > "1.9.0")
print(sorted(["1.10.0", "1.9.0", "1.2.0"]))
print((1, 10, 0) > (1, 9, 0))
```

Comparing as strings goes character by character, and `"1"` < `"9"`, so 1.10 looks older than 1.9. Split on the dots and compare **tuples of numbers** instead.

```exercise
title: parse_version
kind: write
---prompt
Write `parse(v)` that turns a version string into a tuple of three ints, padding missing parts with 0 (`"2.1"` → `(2, 1, 0)`, `"3"` → `(3, 0, 0)`). Then write `newest(versions)` that returns the newest version string from a list.
---starter
def parse(v):
    return ()

def newest(versions):
    return versions[0]
---solution
def parse(v):
    parts = [int(x) for x in v.split(".")]
    return tuple((parts + [0, 0, 0])[:3])

def newest(versions):
    return max(versions, key=parse)
---tests
assert parse("1.10.2") == (1, 10, 2)
assert parse("2.1") == (2, 1, 0) and parse("3") == (3, 0, 0)
assert newest(["1.9.0", "1.10.0", "1.2.3"]) == "1.10.0"
assert parse("1.10.0") > parse("1.9.0")
---hint
`max(versions, key=parse)` compares the tuples, not the strings.
```

## Constraints

A package doesn't ask for one exact version; it asks for a **range**, so that bug fixes can flow in. The common shorthands (npm and Cargo write them like this; pip writes `>=1.4,<2`):

| constraint | means | why |
|---|---|---|
| `^1.4.0` | `>=1.4.0, <2.0.0` | any compatible version: same major |
| `^0.3.0` | `>=0.3.0, <0.4.0` | before 1.0, every minor may break things |
| `~1.4.0` | `>=1.4.0, <1.5.0` | bug fixes only |
| `>=1.2` | at least 1.2 | |
| `==1.3.0` | exactly 1.3.0 | |

```exercise
title: satisfies
kind: write
---prompt
Write `satisfies(version, constraint)` for the five kinds in the table, plus `"*"` (anything). `parse` is ready. Versions in constraints may be short (`"^1.4"` means `^1.4.0`).
---setup
def parse(v):
    parts = [int(x) for x in v.split(".")]
    return tuple((parts + [0, 0, 0])[:3])
---starter
def satisfies(version, constraint):
    return True
---solution
def satisfies(version, constraint):
    v = parse(version)
    if constraint == "*":
        return True
    if constraint.startswith("=="):
        return v == parse(constraint[2:])
    if constraint.startswith(">="):
        return v >= parse(constraint[2:])
    lo = parse(constraint[1:])
    if constraint[0] == "^":
        hi = (lo[0] + 1, 0, 0) if lo[0] > 0 else (0, lo[1] + 1, 0)
    else:
        hi = (lo[0], lo[1] + 1, 0)
    return lo <= v < hi
---tests
assert satisfies("1.9.3", "^1.4") and not satisfies("2.0.0", "^1.4") and not satisfies("1.3.9", "^1.4")
assert satisfies("0.3.7", "^0.3.0") and not satisfies("0.4.0", "^0.3.0"), "below 1.0, ^ locks the minor"
assert satisfies("1.4.9", "~1.4.0") and not satisfies("1.5.0", "~1.4.0")
assert satisfies("3.0.0", ">=1.2") and not satisfies("1.1.9", ">=1.2")
assert satisfies("1.3.0", "==1.3.0") and not satisfies("1.3.1", "==1.3")
assert satisfies("0.0.1", "*")
---hint
Work out a lower bound `lo` and an upper bound `hi` (exclusive) for `^` and `~`, then check `lo <= v < hi` with tuples.
```

## Search, and go back when stuck

The simulation showed the problem: taking the newest web forces log 2.x, and the newest db forces log 1.x. The fix is a **backtracking search**:

1. take the next package that still needs a version
2. try its versions, newest first, skipping any that break a requirement already collected
3. for a version that fits, add *its* requirements and solve the rest recursively
4. if the rest can't be solved, undo this choice and try the next older version

```parsons
title: A backtracking resolver
---setup
def parse(v):
    return tuple(int(x) for x in v.split("."))
def satisfies(v, c):
    lo = parse(c[1:]); return lo <= parse(v) < (lo[0] + 1, 0, 0)
---lines
def resolve(todo, registry, reqs, chosen):
    if not todo:
        return chosen
    pkg, rest = todo[0], todo[1:]
    for v in sorted(registry[pkg], key=parse, reverse=True):
        if not all(satisfies(v, c) for c in reqs.get(pkg, [])):
            continue
        new_reqs = {p: list(cs) for p, cs in reqs.items()}
        for dep, c in registry[pkg][v].items():
            new_reqs.setdefault(dep, []).append(c)
        result = resolve(rest, registry, new_reqs, {**chosen, pkg: v})
        if result:
            return result
    return None
?? chosen[pkg] = v
?? for v in registry[pkg]:
---tests
reg = {"web": {"2.3.0": {"log": "^2.0"}, "2.1.0": {"log": "^1.3"}}, "db": {"1.4.0": {"log": "^1.4"}}, "log": {"2.1.0": {}, "1.5.0": {}, "1.3.0": {}}}
assert resolve(["web", "db", "log"], reg, {"web": ["^2.0"], "db": ["^1.0"]}, {}) == {"web": "2.1.0", "db": "1.4.0", "log": "1.5.0"}
assert resolve(["db", "log"], {"db": {"1.4.0": {"log": "^2.0"}}, "log": {"1.5.0": {}}}, {}, {}) is None, "no solution"
```

`new_reqs` is a fresh copy, so when a choice is undone its requirements disappear with it. The order of `todo` assumes every package that needs `log` comes before `log`; real resolvers discover packages as they go.

```quiz
npm doesn't always need to backtrack. When two packages need incompatible versions of `log`, it can install both: one copy of log in web's folder and another in db's. Why can't pip do that?
- pip is older
* Python imports a module once by name, so only one `log` can exist in a program; JavaScript resolves each `require` from the requiring file's own folder
- pip doesn't support version ranges
- It would use too much disk
> Node looks for `node_modules` next to the file that calls `require`, so different files can get different copies. Python has one `sys.modules["log"]`. Cargo can also keep two *major* versions side by side, but within a major it must pick one.
```

## Lock files and install order

Resolving is slow and depends on what's been published today. So once it succeeds, the manager writes a **lock file** (`package-lock.json`, `poetry.lock`, `Cargo.lock`) with the exact versions, and everyone on the team installs exactly those.

```exercise
title: lockfile
kind: write
---prompt
Write `lockfile(chosen)` that turns a dict `{package: version}` into the text of a pip-style lock file: one `name==version` line per package, sorted by name, ending with a newline. An empty dict gives `""`.
---starter
def lockfile(chosen):
    return ""
---solution
def lockfile(chosen):
    return "".join(f"{name}=={chosen[name]}\n" for name in sorted(chosen))
---tests
assert lockfile({"web": "2.1.0", "db": "1.4.0", "log": "1.5.0"}) == "db==1.4.0\nlog==1.5.0\nweb==2.1.0\n"
assert lockfile({}) == ""
---hint
`sorted(chosen)` gives the names in order.
```

```exercise
title: install_order
kind: write
---prompt
Packages must be installed after the packages they need (their setup may import them). Write `install_order(needs)` where `needs` maps each chosen package to the list of packages it needs. Return a list where each package comes after everything it needs. When several could go next, take them in alphabetical order, so the result is predictable.
---starter
def install_order(needs):
    return []
---solution
def install_order(needs):
    done, order = set(), []
    while len(order) < len(needs):
        ready = sorted(p for p in needs if p not in done and all(d in done for d in needs[p]))
        if not ready:
            raise ValueError("circular dependency")
        order.append(ready[0])
        done.add(ready[0])
    return order
---tests
assert install_order({"web": ["log"], "db": ["log"], "log": [], "app": ["web", "db"]}) == ["log", "db", "web", "app"]
assert install_order({}) == []
try:
    install_order({"a": ["b"], "b": ["a"]})
    assert False
except ValueError:
    pass
---hint
Repeatedly pick, from the packages whose needs are all installed, the alphabetically first one. If none is ready, there's a cycle.
```

```exercise
import re

def parse_requirement(line):
    line = line.split("#")[0].replace(" ", "")
    m = re.match(r"[A-Za-z0-9_.-]+", line)
    name, rest = m.group().lower(), line[m.end():]
    specs = [re.match(r"(>=|<=|==|!=|<|>)(.+)", part).groups() for part in rest.split(",") if part]
    return name, specs
---tests

assert parse_requirement("numpy") == ("numpy", [])

Match the name with a regex first. For each comma-separated part, the two-character operators must be tried before `<` and `>`.
```

```exercise
title: outdated
kind: write
---prompt
Write `outdated(locked, available, allowed)`. `locked` maps each package to its locked version, `available` maps each package to a list of published versions, and `allowed(pkg, version)` says whether a version would still satisfy every requirement. Return a sorted list of `(pkg, locked_version, newest_allowed_version)` for packages where a newer allowed version exists. Versions are dotted numbers.
---starter
def outdated(locked, available, allowed):
    return []
---solution
def outdated(locked, available, allowed):
    key = lambda v: tuple(int(x) for x in v.split("."))
    out = []
    for pkg, cur in locked.items():
        ok = [v for v in available.get(pkg, []) if allowed(pkg, v) and key(v) > key(cur)]
        if ok:
            out.append((pkg, cur, max(ok, key=key)))
    return sorted(out)
---tests
locked = {"web": "2.1.0", "log": "1.5.0", "db": "1.4.0"}
avail = {"web": ["2.1.0", "2.1.4", "2.3.0"], "log": ["1.5.0", "2.1.0"], "db": ["1.4.0"]}
allowed = lambda p, v: not (p == "web" and v == "2.3.0") and not (p == "log" and v.startswith("2"))
assert outdated(locked, avail, allowed) == [("web", "2.1.0", "2.1.4")]
assert outdated(locked, avail, lambda p, v: True) == [("log", "1.5.0", "2.1.0"), ("web", "2.1.0", "2.3.0")]
---hint
Compare versions as tuples of ints; keep only versions that are allowed and newer than the locked one.
```

## Rebuild it and explain it

```exercise

---prompt

def caret(version, constraint):
```

```recall
Q: Explain how a package manager picks versions, and why taking the newest version of everything can fail.
A: Every package states its dependencies as version ranges, like ^1.4 (any 1.x from 1.4) or >=2.0,<3. The manager must pick exactly one version of each package so that every range from the project and from every chosen package is satisfied. Taking the newest of everything ignores the packages' own requirements: two libraries can need incompatible ranges of a shared dependency, and only one copy can be installed (in Python, imports are by name). So it searches: pick a package, try its versions newest first, skip ones that break collected requirements, add the chosen version's own requirements, and recurse; if the rest can't be satisfied, undo the choice and try an older version (backtracking). Versions must be compared as tuples of numbers, not strings, or 1.10 sorts below 1.9. The result is written to a lock file so everyone installs the same versions, and packages are installed after the packages they need.
```
