## What a regex engine really does

A **regular expression** (regex) is a tiny language for describing text. `ab*c` means "an `a`, then any number of `b`s, then a `c`". Every editor's search box, every signup form that checks an email, and every log tool like `grep` runs a regex engine.

There are two ways to build one:

1. **Backtracking:** try one choice, and if it fails later, go back and try the other. Easy to write. Python's `re`, JavaScript and Perl work this way.
2. **State machine (NFA):** turn the pattern into a little machine of states and arrows, then walk the text once while keeping track of *every* state you could be in. `grep`, RE2 and Rust's `regex` work this way.

Both give the same answers. The difference is how many **steps** they take. Play first:

```quiz
- The state has been visited before and is now forbidden
```

## Literal text and the dot

Start with the smallest possible regex: **literal text**. The pattern `cat` matches the text `cat`, and nothing else. Comparing character by character is enough.

Add one special character: `.` means "any single character". So `c.t` matches `cat`, `cot` and `c9t`. The only change is the comparison: a pattern character matches if it is equal **or** it is a dot.

In this chapter, `match` means the **whole** text must match (like `re.fullmatch`). We'll make it "find anywhere" at the end, for grep.

```predict
def match_simple(p, t):
    if len(p) != len(t):
        return False
    for pc, tc in zip(p, t):
        if pc != "." and pc != tc:
            return False
    return True

print(match_simple("c.t", "cot"))
print(match_simple("c.t", "cart"))
print(match_simple("...", "abc"))
```

That works because each pattern character eats exactly one text character. The moment we add `*` ("zero or more of the previous thing"), that's no longer true: `ab*c` can match a text of length 2 or 200. We need a different shape of code.

## Star and question mark: try, and back up

Here is the idea, written as a **recursive** function. Look at the start of the pattern:

- If it's `x*`: either use the star **zero times** (skip `x*` and keep going), or, if the first text character matches `x`, eat it and **stay** on `x*` to maybe eat more.
- If it's `x?`: either eat one `x`, or skip it.
- Otherwise: the first characters must match, then match the rest.

The `or` is the important part: if the first choice fails *later*, Python comes back and tries the second. That "coming back" is **backtracking**.

## Counting steps: when backtracking explodes

Backtracking is simple, but each `or` can make the work **double**. Most of the time the first choice succeeds and nobody notices. Now try a nasty pattern: `a?` repeated n times, then `a` repeated n times, on a text of n `a`s.

The greedy matcher eats an `a` for every `a?`, runs out of text before the required `a`s, backs up one choice, fails again, backs up two… It tries almost **every combination** of "eat / skip" for the n question marks: about 2ⁿ of them.

```run
title: Count the calls
calls = 0
def match(p, t):
    global calls
    calls += 1
    if not p:
        return not t
    first = bool(t) and p[0] in (t[0], ".")
    if len(p) >= 2 and p[1] == "*":
        return match(p[2:], t) or (first and match(p, t[1:]))
    if len(p) >= 2 and p[1] == "?":
        return (first and match(p[2:], t[1:])) or match(p[2:], t)
    return first and match(p[1:], t[1:])

for n in [2, 4, 8, 12, 16]:
    calls = 0
    start = time.perf_counter()
    ok = match("a?" * n + "a" * n, "a" * n)
    ms = (time.perf_counter() - start) * 1000
    print(f"n={n:2}  matched={ok}  calls={calls:>8}  {ms:7.1f} ms")
```

Each extra `a?` roughly **doubles** the calls. At n = 30 it would be about a billion calls; at n = 40 your laptop would still be working tomorrow. This is a real attack called **ReDoS** (regular expression denial of service): in 2019 one bad regex took down Cloudflare's whole network for 27 minutes.

```predict

calls = 0
print(m("a?a?aa", "aa"), calls)
```

The fix is not a faster computer. It is a different idea: **never choose**. Keep every possibility alive at once. To do that we first need the pattern as a proper structure.

## Groups and `|`: parse the pattern into a tree

Real patterns have `|` ("or") and brackets: `(cat|dog)s?`. That's an expression language with precedence, just like the calculator:

- `|` binds loosest (like `+`),
- putting things next to each other (concatenation) is next (like `*`),
- `*` and `?` bind tightest, to the single thing before them,
- `( … )` groups, like brackets in maths.

So we reuse **recursive descent**: one function per level. The tree uses tuples: `("char", "a")`, `("cat", A, B)`, `("alt", A, B)`, `("star", A)`, `("opt", A)`.

```run
title: A regex parser (same shape as the calculator's)
def parse_regex(src):
    pos = 0
    def peek():
        return src[pos] if pos < len(src) else None
    def alt():                       # loosest:  A | B
        nonlocal pos
        node = cat()
        while peek() == "|":
            pos += 1
            node = ("alt", node, cat())
        return node
    def cat():                       # middle:   A B C
        node = None
        while peek() not in (None, "|", ")"):
            r = rep()
            node = r if node is None else ("cat", node, r)
        return node if node is not None else ("empty",)
    def rep():                       # tightest: A*  A?
        nonlocal pos
        node = atom()
        while peek() in ("*", "?"):
            node = ("star" if peek() == "*" else "opt", node)
            pos += 1
        return node
    def atom():                      # a letter, a dot, or ( ... )
        nonlocal pos
        c = peek()
        pos += 1
        if c == "(":
            node = alt()
            if peek() != ")":
                raise ValueError("a ( is never closed")
            pos += 1
            return node
        return ("char", c)
    tree = alt()
    if pos != len(src):
        raise ValueError(f"unexpected {src[pos]!r} at {pos}")
    return tree

print(parse_regex("ab*"))
print(parse_regex("cat|dog"))
print(parse_regex("(ab)*"))
```

Notice `ab*` became `cat(a, star(b))`: the star grabbed only the `b`, because `rep()` is *deeper* than `cat()`. Precedence is the shape of the tree, exactly like `2+3*4`.

## Thompson's construction: tree → state machine

In 1968 Ken Thompson (who later co-created Unix) turned regex trees into machines. A machine is a set of numbered **states** joined by **arrows**. An arrow either reads one character, or is a **free move** (`None`: you may take it without reading anything).

Every piece of the tree becomes a small machine with **one start and one end**, and bigger pieces just wire smaller ones together:

- `char c`: start →c→ end.
- `cat A B`: A's end →free→ B's start.
- `alt A B`: a new start with free moves into A and into B; both ends free-move to a new end.
- `star A`: a new start that can free-move into A **or skip straight to the end**; A's end can free-move **back to A's start** (go round again) or to the end.
- `opt A`: like star, without the loop back.

Why one start and one end? Because then every piece plugs into every other piece the same way, like LEGO.

## Run every path at once: the state set

Now the trick that kills the explosion. Keep a **set** of the states you could be in:

1. Start with `{start}`, plus everything reachable from it by free moves. That "plus free moves" is called the **closure**.
2. For each character of the text: follow every arrow labelled with that character (or `.`) from **any** state in the set. That gives the next set. Take its closure.
3. At the end, it matched if the `end` state is in the set.

A state is in the set at most once, however many paths lead to it. So each character costs at most "number of states" work. For a pattern of m states and a text of n characters that's at most **m × n** steps: it grows **linearly**, never 2ⁿ.

```exercise
assert not run(ab, 0, 3, "aa"), "'aa' should not match"
---hint
After reading `a` you land in state 1. To read `b` you must be in state 2. What gets you from 1 to 2 without reading anything?
```

## Real-world project: a mini grep for log files

`grep` prints every line of a file that contains a match. "Contains" is the new part: the pattern may start **anywhere** in the line. With a state set that's a one-line change: at every character, also add the start state (and its closure) to the active set, as if a new attempt began there. And instead of waiting for the end, stop as soon as `end` shows up.

```project
title: loggrep: search a server log with your own regex engine
client: An on-call engineer at a small web shop whose site is slow
skills: recursive descent, Thompson NFA, sets, file processing
---brief
The web server writes lines like `2026-11-01 12:00:03 GET /cart 500 812ms`. The engineer wants to type `loggrep "GET /cart 5.." server.log` and see every failing cart request, fast, even on a 2 GB log. Build it on your parser and NFA: parse the pattern once, compile it once, then stream lines through the state-set search.
---why
This is literally what `grep`, `ripgrep`, RE2 (Google) and Rust's `regex` crate do, and why they promise linear time: they will never hang on a pathological pattern. Log search tools (Splunk, Loki, Elastic) and code search (GitHub) rely on the same guarantee, because users type arbitrary patterns.
---milestones
- Compile the pattern once with `parse_regex` + `build`
- Write `search(nfa, start, end, line)` that finds a match **anywhere** in the line
- Write `grep(pattern, lines)` returning `(line_number, line)` for every hit
- Read a real file line by line with `open(...)` and print the hits with their numbers
- Add a `-v` option that prints lines that do **not** match
---stretch
- Add character classes like `[0-9]` (an arrow whose label is a set of characters)
- Add `+` (one or more): it's `A A*`, or a star without the skip arrow
- Cache state sets you've seen before as single states: you've just invented a DFA, the fastest regex engines of all
```

```exercise

---setup
class NFA:
    def __init__(self):
        self.edges = []
    def new(self):
        self.edges.append([])
        return len(self.edges) - 1
    def add(self, a, label, b):
        self.edges[a].append((label, b))

def _parse(src):
    pos = 0
    def peek():
        return src[pos] if pos < len(src) else None
    def alt():
        nonlocal pos
        n = cat()
        while peek() == "|":
            pos += 1; n = ("alt", n, cat())
        return n
    def cat():
        n = None
        while peek() not in (None, "|", ")"):
            r = rep(); n = r if n is None else ("cat", n, r)
        return n or ("empty",)
    def rep():
        nonlocal pos
        n = atom()
        while peek() in ("*", "?"):
            n = ("star" if peek() == "*" else "opt", n); pos += 1
        return n
    def atom():
        nonlocal pos
        c = peek(); pos += 1
        if c == "(":
            n = alt(); pos += 1; return n
        return ("char", c)
    return alt()

def _build(nfa, node):
    k = node[0]
    if k in ("char", "empty"):
        s, e = nfa.new(), nfa.new(); nfa.add(s, node[1] if k == "char" else None, e); return s, e
    if k == "cat":
        s1, e1 = _build(nfa, node[1]); s2, e2 = _build(nfa, node[2]); nfa.add(e1, None, s2); return s1, e2
    s, e = nfa.new(), nfa.new()
    if k == "alt":
        for sub in node[1:]:
            a, b = _build(nfa, sub); nfa.add(s, None, a); nfa.add(b, None, e)
        return s, e
    a, b = _build(nfa, node[1]); nfa.add(s, None, a); nfa.add(s, None, e); nfa.add(b, None, e)
    if k == "star":
        nfa.add(b, None, a)
    return s, e

COMPILES = 0
def compile_pattern(pattern):
    global COMPILES
    COMPILES += 1
    nfa = NFA()
    s, e = _build(nfa, _parse(pattern))
    return nfa, s, e

def closure(nfa, states):
    stack, seen = list(states), set(states)
    while stack:
        s = stack.pop()
        for label, t in nfa.edges[s]:
            if label is None and t not in seen:
                seen.add(t); stack.append(t)
    return seen
---starter
def search(nfa, start, end, line):
    current = closure(nfa, {start})
    return end in current

def grep(pattern, lines):

---solution
def search(nfa, start, end, line):
    begin = closure(nfa, {start})
    current = set(begin)
    if end in current:
        return True
    for ch in line:
        nxt = {t for s in current for label, t in nfa.edges[s] if label is not None and label in (ch, ".")}
        current = closure(nfa, nxt) | begin
        if end in current:
            return True
    return False

def grep(pattern, lines):
    nfa, start, end = compile_pattern(pattern)
    hits = []
    for i, line in enumerate(lines, start=1):
        if search(nfa, start, end, line):
            hits.append((i, line))
    return hits
```

## Rebuild it and explain it

```exercise
title: regex_rebuild
kind: rebuild
---prompt
From memory: write `fullmatch(pattern, text)` that supports literal characters, `.`, `*` and `?` (each applying to the single character before it) and returns whether the **whole** text matches. Any approach is fine, but it must finish the evil test below quickly, so plain backtracking won't do: use a set of positions in the pattern (a state set) instead.
---starter
def fullmatch(pattern, text):
    pass
---solution
def fullmatch(pattern, text):
    # states are positions in the pattern; position len(pattern) means "matched everything"
    def closure(states):
        stack, seen = list(states), set(states)
        while stack:
            i = stack.pop()
            if i + 1 < len(pattern) and pattern[i + 1] in "*?" and i + 2 not in seen:
                seen.add(i + 2); stack.append(i + 2)   # skip x* or x?
        return seen
    cur = closure({0})
    for ch in text:
        nxt = set()
        for i in cur:
            if i < len(pattern) and pattern[i] in (ch, "."):
                if i + 1 < len(pattern) and pattern[i + 1] == "*":
                    nxt.add(i)          # stay on x* to eat more
                elif i + 1 < len(pattern) and pattern[i + 1] == "?":
                    nxt.add(i + 2)
                else:
                    nxt.add(i + 1)
        cur = closure(nxt)
    return len(pattern) in cur
---tests
assert fullmatch("abc", "abc") and not fullmatch("abc", "abd"), "literal text"
assert fullmatch("a.c", "axc"), ". matches any character"
assert fullmatch("ab*c", "ac") and fullmatch("ab*c", "abbbbc"), "b* means zero or more b"
assert fullmatch("colou?r", "color") and fullmatch("colou?r", "colour"), "u? means zero or one u"
assert not fullmatch("ab*", "abx"), "the whole text must match"
t0 = time.perf_counter()
assert fullmatch("a?" * 30 + "a" * 30, "a" * 30), "(a?)^30 a^30 matches 30 a's"
assert time.perf_counter() - t0 < 2, "the evil pattern must be fast: keep a SET of pattern positions instead of backtracking"
---hint
Let a "state" be an index into the pattern. Being at index `i` means "the next thing to match is `pattern[i]`".
---hint
Free moves: if `pattern[i+1]` is `*` or `?`, you may jump to `i + 2` without reading anything. Reading a character on `x*` keeps you at `i`.
```

```recall
Q: Why can a backtracking regex engine take 2ⁿ steps on `a?a?…a?aa…a`, while an NFA simulation with a set of states stays fast?
A: Backtracking follows one path at a time; every `?` is a choice, and when a later part fails it goes back and tries the other branch, so it can end up trying every combination of choices (2ⁿ). The NFA simulation never chooses: it keeps a set of all states the pattern could be in. A state is in the set at most once no matter how many paths reach it, so each text character costs at most (number of states) work: m × n in total.
```
