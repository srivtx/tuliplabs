## A language model predicts the next word

Strip away the hype and a GPT does one thing: given some text, it outputs a probability for every possible **next token**. To write a paragraph, it picks a token from those probabilities, appends it, and asks again. Everything it "knows" is whatever helps it make that one prediction well.

The simplest model that does this looks only at the **last word**: count, in a pile of text, which words followed which.

```exercise
title: bigrams
kind: write
---prompt
Write `train_bigrams(words)` that returns a dict mapping each word to a dict of `{next_word: count}`. Then write `most_likely(counts, word)`: the most frequent next word (ties: the alphabetically first), or `None` if the word never had a next word.
---starter
def train_bigrams(words):
    return {}

def most_likely(counts, word):
    return None
---solution
def train_bigrams(words):
    counts = {}
    for a, b in zip(words, words[1:]):
        counts.setdefault(a, {})
        counts[a][b] = counts[a].get(b, 0) + 1
    return counts

def most_likely(counts, word):
    nexts = counts.get(word)
    if not nexts:
        return None
    return max(sorted(nexts), key=nexts.get)
---tests
words = "the cat sat on the mat the cat ran".split()
c = train_bigrams(words)
assert c["the"] == {"cat": 2, "mat": 1}, c["the"]
assert most_likely(c, "the") == "cat"
assert most_likely(c, "cat") == "ran", "a tie between ran and sat: alphabetical"
assert most_likely(c, "ran") is None, "nothing ever followed ran"
---hint
`zip(words, words[1:])` gives every pair of neighbours. `max(sorted(d), key=d.get)` returns the first of the tied maximums in sorted order.
```

A bigram model writes locally plausible nonsense: every pair of words is fine, and the sentence goes nowhere. To finish *"the cat chased the mouse because it was …"* you need to know that **it** is the cat, six words back. The model needs a way to look at the whole context and pick out the parts that matter. That's **attention**.

## Softmax and temperature

A model's raw outputs are scores (**logits**) of any size and sign. **Softmax** turns them into probabilities: exponentiate each, then divide by the total. Bigger scores get exponentially bigger shares.

```exercise
title: softmax
kind: write
---prompt
Write `softmax(scores, temperature=1.0)` for a 1-D numpy array: divide the scores by the temperature, subtract their maximum (so `exp` can't overflow), exponentiate, and normalise to sum to 1.
---starter
def softmax(scores, temperature=1.0):
    return scores
---solution
def softmax(scores, temperature=1.0):
    s = np.asarray(scores, dtype=float) / temperature
    e = np.exp(s - s.max())
    return e / e.sum()
---tests
p = softmax(np.array([2.0, 1.0, 0.1]))
assert np.allclose(p, np.exp([2, 1, 0.1]) / np.exp([2, 1, 0.1]).sum()) and abs(p.sum() - 1) < 1e-12
assert np.allclose(softmax(np.array([1000.0, 1000.0])), [0.5, 0.5]), "huge scores must not overflow"
assert softmax(np.array([2.0, 1.0]), 0.1)[0] > 0.99, "low temperature: nearly certain"
assert np.allclose(softmax(np.array([5.0, 0.0, -5.0]), 1e6), [1 / 3] * 3, atol=1e-4), "high temperature: nearly uniform"
---hint
Subtracting the max doesn't change the result (it cancels when you divide) but keeps every exponent at most 0.
```

```predict
logits = [2.0, 1.0, 0.1]
for t in (0.5, 1.0, 2.0):
    e = [math.exp(x / t) for x in logits]
    print("temperature", t, [round(v / sum(e), 2) for v in e])
```

That's the "temperature" setting in every chatbot API. Low: it nearly always picks the top word (safe, repetitive). High: it takes chances (creative, sometimes wrong).

## Tokens: not letters, not words

GPTs don't see letters or words but **tokens**: common chunks like `the`, `ing` or ` hungry`. They're found by **byte-pair encoding**: start from single characters, then repeatedly find the most common adjacent pair and merge it into a new token. After a few thousand merges, frequent words are one token and rare words are a few pieces, so no word is ever "unknown".

```exercise
title: byte_pair
kind: write
---prompt
Write `most_common_pair(tokens)`: the most frequent pair of adjacent tokens (ties: the pair that appears first), or `None` if there are fewer than 2 tokens. Then write `merge(tokens, pair, new)`: scan left to right and replace each occurrence of the pair with the single token `new`.
---starter
def most_common_pair(tokens):
    return None

def merge(tokens, pair, new):
    return tokens
---solution
from collections import Counter

def most_common_pair(tokens):
    if len(tokens) < 2:
        return None
    return Counter(zip(tokens, tokens[1:])).most_common(1)[0][0]

def merge(tokens, pair, new):
    out, i = [], 0
    while i < len(tokens):
        if i + 1 < len(tokens) and (tokens[i], tokens[i + 1]) == pair:
            out.append(new)
            i += 2
        else:
            out.append(tokens[i])
            i += 1
    return out
---tests
t = list("aaabdaaabac")
assert most_common_pair(t) == ("a", "a")
t = merge(t, ("a", "a"), "Z")
assert t == list("ZabdZabac"), t
assert most_common_pair(t) == ("Z", "a"), "a tie with (a, b): (Z, a) comes first"
assert merge(list("aaaa"), ("a", "a"), "Z") == ["Z", "Z"], "no overlapping matches"
assert most_common_pair(["x"]) is None
---hint
`Counter.most_common` keeps first-seen order among ties. In `merge`, a `while` loop lets you skip two positions after a match.
```

## Attention, in numpy

Each word gets three vectors, made by multiplying its embedding by three learned matrices:

- a **query**: what am I looking for?
- a **key**: what do I contain?
- a **value**: what do I pass on if someone looks at me?

A word's score for another word is **query · key**. Softmax turns its scores into weights, and its output is the weighted sum of the **values**. With all the words stacked as rows of matrices `Q`, `K` and `V`, that's three lines:

`attention(Q, K, V) = softmax(Q Kᵀ / √d) V`

where `d` is the length of a key, and the softmax runs along each row.

```exercise
title: attention
kind: write
---prompt
Write `attention(Q, K, V)`: `Q` is `(T, d)`, `K` is `(S, d)`, `V` is `(S, dv)`. Compute the scores `Q @ K.T / sqrt(d)`, softmax each **row** (subtract each row's max first), and return the weights times `V`, shape `(T, dv)`.
---starter
def attention(Q, K, V):
    return V
---solution
def attention(Q, K, V):
    d = Q.shape[1]
    scores = Q @ K.T / np.sqrt(d)
    w = np.exp(scores - scores.max(axis=1, keepdims=True))
    w = w / w.sum(axis=1, keepdims=True)
    return w @ V
---tests
Q = np.array([[1.0, 0.0]])
K = np.array([[1.0, 0.0], [0.0, 1.0]])
V = np.array([[10.0, 0.0], [0.0, 10.0]])
e = np.exp(1 / np.sqrt(2))
assert np.allclose(attention(Q, K, V), [[10 * e / (e + 1), 10 / (e + 1)]]), attention(Q, K, V)
assert np.allclose(attention(np.ones((2, 3)), np.zeros((4, 3)), np.arange(8.0).reshape(4, 2)), [[3, 4], [3, 4]]), "equal scores: the plain average of V"
assert attention(np.ones((5, 4)), np.ones((7, 4)), np.ones((7, 3))).shape == (5, 3)
---hint
`axis=1, keepdims=True` keeps a column of row maxima (and row sums) that broadcasts back over each row.
```

```quiz
Why divide the scores by √d?
- To make the computation faster
- Because keys and queries have different lengths
* Dot products of long vectors are large, which would push the softmax to put ~100% on one word and make learning stall
- To turn the scores into probabilities
> A dot product of d random numbers grows like √d. Dividing by √d keeps scores around the same size whatever d is, so the softmax stays soft enough for gradients to flow during training.
```

## Don't look at the future

A GPT is trained to predict every next word of a text at once, in parallel. If word 3 could attend to word 4, it could just copy the answer. So each word may only attend to itself and **earlier** words: a **causal mask** sets every "future" score to −∞ before the softmax, which makes its weight exactly 0.

```exercise
title: causal_bug
kind: bug
---prompt
This masked attention multiplies the future scores by 0 instead of removing them. A score of 0 isn't "no attention": `exp(0) = 1`, so future words still get weight. Fix it so future positions get a weight of exactly 0.
---starter
def causal_attention(Q, K, V):
    T, d = Q.shape
    scores = Q @ K.T / np.sqrt(d)
    mask = np.tril(np.ones((T, T)))
    scores = scores * mask
    w = np.exp(scores - scores.max(axis=1, keepdims=True))
    w = w / w.sum(axis=1, keepdims=True)
    return w @ V
---solution
def causal_attention(Q, K, V):
    T, d = Q.shape
    scores = Q @ K.T / np.sqrt(d)
    mask = np.tril(np.ones((T, T)))
    scores = np.where(mask == 1, scores, -np.inf)
    w = np.exp(scores - scores.max(axis=1, keepdims=True))
    w = w / w.sum(axis=1, keepdims=True)
    return w @ V
---tests
Z = np.zeros((3, 2))
V = np.array([[1.0], [2.0], [3.0]])
assert np.allclose(causal_attention(Z, Z, V), [[1], [1.5], [2]]), "word 1 sees only itself; word 2 averages 1 and 2; word 3 all three"
Q = np.array([[0.0, 0.0], [0.0, 0.0], [5.0, 0.0]])
K = np.array([[0.0, 0.0], [0.0, 0.0], [5.0, 0.0]])
assert np.allclose(causal_attention(Q, K, V)[:2], [[1], [1.5]]), "the third word's big key is invisible to earlier words"
---hint
`np.where(mask == 1, scores, -np.inf)` keeps the allowed scores and puts −∞ elsewhere; `exp(-inf)` is exactly 0. The diagonal is always allowed, so no row is all −∞.
```

## One attention head

Where do `Q`, `K` and `V` come from? Each word starts as an **embedding** vector (a learned row per token), and three learned weight matrices project it: `Q = X Wq`, `K = X Wk`, `V = X Wv`. That's one **head**. A GPT runs several heads side by side (each learns to look for something different: the subject, the previous word, a matching bracket), then a small feed-forward network, and stacks that block dozens of times. Training adjusts every number by gradient descent to make the next-token predictions better.

```exercise
title: attention_head
kind: write
---prompt
Write `self_attention(X, Wq, Wk, Wv)`: `X` is `(T, d_model)`, one row per word; the weight matrices are `(d_model, d)`. Project to queries, keys and values, then return **causal** scaled dot-product attention, shape `(T, d)`.
---starter
def self_attention(X, Wq, Wk, Wv):
    return X
---solution
def self_attention(X, Wq, Wk, Wv):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    T, d = Q.shape
    scores = Q @ K.T / np.sqrt(d)
    scores = np.where(np.tril(np.ones((T, T))) == 1, scores, -np.inf)
    w = np.exp(scores - scores.max(axis=1, keepdims=True))
    w = w / w.sum(axis=1, keepdims=True)
    return w @ V
---tests
X = np.eye(3)
out = self_attention(X, np.zeros((3, 2)), np.zeros((3, 2)), np.eye(3))
assert np.allclose(out, [[1, 0, 0], [0.5, 0.5, 0], [1 / 3, 1 / 3, 1 / 3]]), "no preferences: each word averages its past"
rng = np.random.default_rng(1)
X, Wq, Wk, Wv = rng.normal(size=(5, 4)), rng.normal(size=(4, 3)), rng.normal(size=(4, 3)), rng.normal(size=(4, 3))
out = self_attention(X, Wq, Wk, Wv)
assert out.shape == (5, 3)
assert np.allclose(out[0], (X @ Wv)[0]), "the first word can only attend to itself"
---hint
Three matrix products, then exactly the causal attention from the bug exercise.
```

```recall
Q: Explain how a GPT predicts the next word, and what attention does inside it.
A: Text is split into tokens by byte-pair encoding, and each token becomes an embedding vector. The model's job is to output, for every position, a probability for every possible next token; generating text means sampling a token from those probabilities (sharpened or flattened by the temperature), appending it, and repeating. A bigram model only sees the last word; attention lets each word use the whole context. Each word is projected into a query (what it looks for), a key (what it offers) and a value (what it passes on). Its scores against every word are query · key divided by √d, a causal mask removes future words with −∞, a softmax turns the scores into weights, and the output is the weighted sum of the values. Several heads run in parallel, followed by a feed-forward layer, and these blocks are stacked; every weight is learned by gradient descent on next-token prediction.
```
