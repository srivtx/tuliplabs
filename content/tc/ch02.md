## Is everyone reachable?

A graph is **connected** if you can get from any node to any other by following edges. The book's algorithm: start somewhere, mark it seen, then keep visiting neighbours of things you've seen until there's nothing new.

```exercise
title: A faster search
kind: write
---prompt
The book points out that `reachable_nodes` pushes a node onto the stack once for every edge that leads to it. Write `reachable_nodes_precheck`, which only pushes neighbours that aren't **already seen**, and returns the same set. It also returns how many pushes it made, so we can compare.
---starter
def reachable_nodes_precheck(G, start):
    seen = set()
    stack = [start]
    pushes = 1
    # your loop here
    return seen, pushes
---solution
def reachable_nodes_precheck(G, start):
    seen = {start}
    stack = [start]
    pushes = 1
    while stack:
        node = stack.pop()
        for nb in G.neighbors(node):
            if nb not in seen:
                seen.add(nb)
                stack.append(nb)
                pushes += 1
    return seen, pushes
---tests

assert seen2 == {0, 1, 2}, f"Expected {{0, 1, 2}}, got {seen2}"
---hint
Mark a node as seen the moment you **push** it, not when you pop it. Then the check `if nb not in seen` stops duplicates.
```

## Erdős–Rényi random graphs

In the ER model G(n, p), each possible pair of nodes gets an edge with probability `p`, independently. The book flips a biased coin for each pair.

```exercise
- `make_random_graph(n, p)` returns an ER graph with nodes `0 … n-1`

---solution
def flip(p):
    return np.random.random() < p

def random_pairs(nodes, p):
    for edge in all_pairs(nodes):
        if flip(p):
            yield edge

    G = nx.Graph()
    nodes = range(n)

    G.add_edges_from(random_pairs(nodes, p))
    return G
```

## The tipping point

Erdős and Rényi found that connectivity doesn't rise smoothly with `p`. Below a critical value, ER graphs are almost never connected; just above it, they almost always are. For large `n` the critical value is about **p\* = ln(n) / n**.

```run
title: Estimate the probability of being connected
def all_pairs(nodes):
    for i, u in enumerate(nodes):
        for j, v in enumerate(nodes):
            if i > j:
                yield u, v

def flip(p):
    return np.random.random() < p

def random_pairs(nodes, p):
    for edge in all_pairs(nodes):
        if flip(p):
            yield edge

def make_random_graph(n, p):
    G = nx.Graph()
    G.add_nodes_from(range(n))
    G.add_edges_from(random_pairs(range(n), p))
    return G

def reachable_nodes(G, start):
    seen, stack = set(), [start]
    while stack:
        node = stack.pop()
        if node not in seen:
            seen.add(node)
            stack.extend(G.neighbors(node))
    return seen

def is_connected(G):
    return len(reachable_nodes(G, next(iter(G)))) == len(G)

def prob_connected(n, p, iters=100):
    tf = [is_connected(make_random_graph(n, p)) for i in range(iters)]
    return np.mean(tf)

n = 10
pstar = np.log(n) / n
ps = np.logspace(-1.3, 0, 11)
ys = [prob_connected(n, p) for p in ps]
for p, y in zip(ps, ys):
    print(f"p = {p:.3f}   P(connected) = {y:.2f}")
plt.axvline(pstar, color="gray", ls="--", label="p* = ln(n)/n")
plt.plot(ps, ys, "o-", label="simulation")
plt.xscale("log"); plt.xlabel("p (probability of an edge)"); plt.ylabel("P(connected)")
plt.legend()
```

Try `n = 30` (and fewer `iters` if it feels slow). The jump gets sharper as `n` grows, and it moves to smaller `p`.

## Real-world project: will the office network survive cable cuts?

Real networks lose links all the time: a cable gets cut by a digger, a switch port dies, a Wi-Fi bridge drops out. An engineer's question is not "is my network connected today?" but "**how likely** is it to stay connected when some links fail?" That is the same experiment you just ran on random graphs, pointed at a real design: remove each link with some probability, check `is_connected`, repeat many times.

```project

---brief
```

```recall
Q: Explain how `reachable_nodes` works, and why it can't loop forever even though the graph has cycles.
A: - It keeps a **stack** of nodes still to process and a **set** of nodes already processed.
- Each round it pops a node; if it's new it marks it seen and pushes all its neighbours.
- Cycles lead back to nodes already in `seen`, which are popped and skipped, so each node is processed at most once and the loop ends when the stack is empty.
- The graph is connected exactly when the set it returns contains every node.
```

```recall
Q: What happens to the probability that G(n, p) is connected as p increases, and what's special about ln(n)/n?
A: - It stays near 0 for small p, then jumps to near 1 over a narrow range of p: a **phase transition**.
- The jump is centred near p\* = ln(n)/n, and it gets sharper as n grows.
- Intuition: at p\*, the expected number of isolated nodes drops below about one; isolated nodes are the last thing stopping the graph from being connected.
```
