## The missing piece: hubs

The WS model gets clustering and short paths right. But test it against real data (a Facebook friendship network with about 4,000 people) and one thing is badly wrong: the **degrees**. In the WS graph almost everyone has close to `k` friends. In the real network most people have a few dozen, while a handful have **hundreds or thousands**. Those people are **hubs**.

The **degree** of a node is its number of neighbours. The **degree distribution** says how many nodes have each degree. This chapter is about distributions with a **heavy tail**: rare, huge values that matter a lot.

```bridge

```

## The PMF: fraction of nodes per degree

A **probability mass function** (PMF) maps each value to the fraction of times it appears. Libraries do this for you; you'll write your own in four lines.

```exercise

kind: write
---prompt
Write `pmf(values)` that returns a dict mapping each distinct value to the **fraction** of values equal to it. Sorted keys are a nice touch but not required.
---starter
def pmf(values):
    pass
---solution
def pmf(values):
    counts = {}
    for v in values:
        counts[v] = counts.get(v, 0) + 1
    n = len(values)
    return {v: c / n for v, c in sorted(counts.items())}
---tests

---hint
Count with a dict (`counts.get(v, 0) + 1`), then divide every count by `len(values)`.
```

## Heavy tails on a log-log plot

On ordinary axes a heavy tail is invisible: it's a long, flat line near zero. On **log-log** axes, a **power law** PMF(k) ∝ k^(−α) becomes a straight line with slope −α. Compare the WS graph with NetworkX's built-in Barabási–Albert graph (which you're about to write yourself).

```run
title: Two degree distributions, log-log
def pmf(values):
    counts = {}
    for v in values:
        counts[v] = counts.get(v, 0) + 1
    return {v: c / len(values) for v, c in sorted(counts.items())}

ws = nx.watts_strogatz_graph(2000, 10, 0.05, seed=1)
ba = nx.barabasi_albert_graph(2000, 5, seed=1)
for name, G in [("WS", ws), ("BA", ba)]:
    p = pmf([G.degree(u) for u in G])
    plt.plot(list(p), list(p.values()), "o", ms=4, label=name)
    print(name, "max degree:", max(p))
plt.xscale("log"); plt.yscale("log")
plt.xlabel("degree k"); plt.ylabel("PMF(k)"); plt.legend()
plt.title("WS: a bump around k=10.  BA: a straight line = power law")
```

```quiz
On log-log axes the BA degree PMF is roughly a straight line. What does that tell you?
- Degrees are normally distributed
* PMF(k) is roughly proportional to k raised to some negative power
- All nodes have the same degree
- The graph is a lattice
> log PMF = −α log k + c is a straight line on log-log axes, which is the same as PMF(k) ∝ k^(−α): a power law. For the BA model α is about 3.
```

## Preferential attachment

Barabási and Albert's idea, which you played as the Town's lottery:

```viz
name: tc-ba
title: Grow your own hubs
goal: Grow 300 nodes with **Pick anyone**, then with **Rich get richer**, and get a hub of **25 links or more**.
height: 440
Each newcomer makes 2 links. Only the rule for choosing whom to link to changes.
```

1. **Growth:** start with `k` nodes; add new nodes one at a time.
2. **Preferential attachment:** each new node links to `k` existing nodes, chosen with probability **proportional to their degree**.

The trick for "proportional to degree" is lovely: keep a list, `repeated_nodes`, where every node appears **once per edge it has**. Picking uniformly from that list picks nodes in proportion to degree.

```predict
repeated = [0, 0, 0, 1, 2, 2]
counts = {u: repeated.count(u) for u in set(repeated)}
print(counts)
print(round(counts[0] / len(repeated), 3))
```

---solution
def barabasi_albert_graph(n, k):
    G = nx.empty_graph(k)
    targets = list(range(k))
    repeated_nodes = []
    for source in range(k, n):
        G.add_edges_from(zip([source] * k, targets))

---hint

## The CCDF: a cleaner view of the tail

PMFs of real data are noisy in the tail (most high degrees appear once or not at all). So we prefer the **complementary CDF**: CCDF(x) = the fraction of values **greater than** x. For a power law it's also a straight line on log-log axes, and it's much smoother.

```exercise
title: ccdf
kind: write
---prompt
Write `ccdf(values, xs)` returning a numpy array with, for each x in `xs`, the fraction of `values` that are **strictly greater** than x.
---starter
def ccdf(values, xs):
    values = np.asarray(values)
    pass
---solution
def ccdf(values, xs):
    values = np.asarray(values)
    return np.array([np.mean(values > x) for x in xs])
---tests
c = ccdf([1, 2, 3, 4], [0, 1, 3, 4])
assert c.tolist() == [1.0, 0.75, 0.25, 0.0], f"Expected [1.0, 0.75, 0.25, 0.0], got {c.tolist()}"
assert len(ccdf([5, 5], range(10))) == 10, "One result per x"
---hint
"Mean of a mask" again: `np.mean(values > x)` is the fraction above x.
```

```quiz
In the CCDF plot, the WS curve plunges to zero just past x ≈ 15, while BA's declines in a straight line out to the hundreds. In plain words?
- Both graphs have hubs, BA's are just bigger
* In WS nobody has many more friends than average; in BA a few nodes have tens of times the average
- WS has more edges than BA
- The CCDF can't compare graphs with different k
> WS degrees are concentrated near the mean, so the CCDF drops off a cliff. BA's power-law tail means the chance of finding a node with degree above x falls slowly, so hubs exist.
```

## Real-world project: which hub airports matter most?

Airline routes, the internet's routers and protein networks in your cells all have hubs. Hubs are a strength (few hops from anywhere to anywhere) and a weakness: if a storm closes the two biggest hubs, far more of the network falls apart than if two random small airports close. Here you'll measure that, using the BA graphs you just built as a stand-in for a route map.

```project
title: Hub-failure stress test for an airline route map
client: An airline operations team planning for storms and strikes
skills: degree ranking, graph copies, connected components, comparing strategies
---brief
Operations wants two things: a ranked list of the **most critical airports** (the hubs), and a stress test that answers "if we lose this fraction of airports, what share of the network can still fly between each other?" Run it twice: once removing airports **at random** (bad weather anywhere) and once removing the **biggest hubs first** (a targeted failure).
---why
This is the classic robustness result for scale-free networks (Albert, Jeong and Barabási, 2000): they shrug off random failures but break under targeted attacks. Cyber-security teams use it to decide which servers to harden, epidemiologists to decide whom to vaccinate first (the "hubs" of contact), and logistics firms to decide which warehouses need backups.
---milestones
- Write `most_critical(G, k)`: the k nodes with the highest degree
- Write `robustness(G, fraction, targeted, seed)`: remove nodes and measure the largest connected part
- Compare random and targeted removal of 15% of a 1,000-node BA graph
- Plot both curves from 0% to 30% removal and find where the targeted curve collapses
- Recommend which 10 airports most need backup plans
---stretch
- Recompute degrees after **each** removal (an adaptive attack) and see if it is even worse
- Repeat on a Watts–Strogatz graph: does it have the same weakness?
- Rank by betweenness centrality (`nx.betweenness_centrality`) instead of degree and compare
```

---solution
def robustness(G, fraction, targeted, seed=0):
    n = len(G)
    m = int(fraction * n)
    H = G.copy()
    if targeted:
        gone = most_critical(G, m)
    else:
        gone = np.random.default_rng(seed).choice(list(G), m, replace=False)
    H.remove_nodes_from(gone)
    if len(H) == 0:
        return 0.0
    return max(len(c) for c in nx.connected_components(H)) / n

## Rebuild and explain

```exercise
title: Rebuild degrees and the PMF
kind: rebuild
---prompt
From memory, write `degree_pmf(G)`: the PMF (dict value → fraction) of the degrees of all nodes in `G`.
---starter
def degree_pmf(G):
    pass
---solution
def degree_pmf(G):
    degrees = [G.degree(u) for u in G]
    counts = {}
    for d in degrees:
        counts[d] = counts.get(d, 0) + 1
    return {d: c / len(degrees) for d, c in sorted(counts.items())}
---tests
p = degree_pmf(nx.star_graph(4))
assert abs(p[1] - 0.8) < 1e-9 and abs(p[4] - 0.2) < 1e-9, f"A star with 4 leaves: 80% degree 1, 20% degree 4. Got {p}"
assert degree_pmf(nx.cycle_graph(7)) == {2: 1.0}, "Every node of a cycle has degree 2"
```

```recall
Q: Why does the BA model produce hubs while the WS model doesn't? Mention both ingredients.
A: - WS starts from a lattice where every node has degree k and rewires a few edges, so degrees stay close to k.
- BA has **growth** (old nodes have had more time to collect links) and **preferential attachment** (high-degree nodes are more likely to get the next link).
- Together they create a feedback loop: being big makes you grow faster. The result is a power-law degree distribution with a few huge hubs.
- Remove preferential attachment (uniform choice) and the tail becomes exponential: no hubs.
```

```recall
Q: What does the `repeated_nodes` list contain, and why does choosing from it uniformly implement preferential attachment?
A: - Every node appears in the list once for each edge it has (both ends of every edge get added).
- So a node with degree d occupies d slots, and a uniform random pick lands on it with probability d / (total degree): proportional to degree.
- It avoids computing probabilities explicitly; updating the list is just `extend`.
```
