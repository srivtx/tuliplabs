## What evolution needs

The book takes a minimal view. Evolution happens whenever you have:

1. **Replicators:** things that make copies of themselves.
2. **Variation:** copies aren't all identical (mutation).
3. **Differential survival or reproduction:** some variants do better than others.

Nothing about DNA or living things is required. That's why we can study evolution with a simulation of bit strings, and switch each ingredient off to see what it does.

```bridge

```

```quiz
A population copies itself perfectly (no mutation) and some genotypes reproduce faster than others. What happens over a long time?
- Fitness keeps rising forever
* The best genotype already present takes over, then nothing changes
- Nothing at all changes
- Fitness falls
> Selection only chooses among existing variants. Without new variation the fittest starting genotype eventually dominates and evolution stops. You'll see this in the simulation.
```

## The fitness landscape

A genome is a string of N bits (with N = 8 there are 2⁸ = 256 possible genotypes; the simulation below uses N = 16, so 65,536). Each position contributes to fitness, and the contribution depends on whether that bit is 0 or 1. The book draws two random numbers per position, `zero_values[i]` and `one_values[i]`, and fitness is the **average** contribution:

fitness(loc) = mean over i of (one_values[i] if loc[i] == 1 else zero_values[i])

```predict
one_values  = np.array([0.9, 0.1, 0.5])
zero_values = np.array([0.2, 0.7, 0.5])
loc = np.array([1, 1, 0])
print(np.where(loc, one_values, zero_values))
print(round(np.mean(np.where(loc, one_values, zero_values)), 3))
```

## Differential reproduction

The book's `Simulation.step`: each generation, some agents die at random and are replaced by copies of survivors, chosen with probability **proportional to fitness**. Fitter agents leave more offspring.

```exercise
title: choose_replacements
kind: write
---prompt
Write `choose_replacements(n, fits, rng)`: return an array of `n` indices into `fits`, drawn **with replacement**, where index i is chosen with probability `fits[i] / sum(fits)`.
---starter
def choose_replacements(n, fits, rng):
    pass
---solution
def choose_replacements(n, fits, rng):
    p = np.asarray(fits) / np.sum(fits)
    return rng.choice(len(fits), size=n, replace=True, p=p)
---tests
rng = np.random.default_rng(0)

assert len(idx) == 10000, "Return n indices"

assert set(choose_replacements(50, np.array([0.0, 1.0]), rng)) == {1}, "Zero fitness is never chosen"
---hint
`rng.choice(len(fits), size=n, replace=True, p=...)` with `p` the fitnesses divided by their sum.
```

## Variation: mutation

When an agent is copied, with some probability one random bit flips.

```exercise

kind: bug
---prompt
After a few generations, parents mysteriously change their own genomes when their children mutate. This `mutate` is meant to return a **new** genome with one bit flipped. What's wrong?
---starter
def mutate(loc, rng):
    i = rng.integers(len(loc))
    loc[i] = 1 - loc[i]
    return loc
---solution
def mutate(loc, rng):
    child = loc.copy()
    i = rng.integers(len(child))
    child[i] = 1 - child[i]
    return child
---tests

---hint
```


## Run evolution, then switch ingredients off

```run
title: Four populations, one landscape
class FitnessLandscape:
    def __init__(self, N, rng):
        self.N = N
        self.one_values = rng.random(N)
        self.zero_values = rng.random(N)
    def fitness(self, loc):
        return np.mean(np.where(loc, self.one_values, self.zero_values))

def run(landscape, rng, n=100, gens=400, selection=True, p_mutate=0.2, start="worst", strength=8):
    N = landscape.N
    worst = (landscape.one_values < landscape.zero_values).astype(int)
    pop = [worst.copy() if start == "worst" else rng.integers(0, 2, N) for _ in range(n)]
    mean_fit = []
    for g in range(gens):
        fits = np.array([landscape.fitness(x) for x in pop])
        mean_fit.append(fits.mean())
        dead = np.flatnonzero(rng.random(n) < 0.2)
        weights = fits ** strength                  # exaggerate fitness differences
        p = weights / weights.sum() if selection else None
        parents = rng.choice(n, size=len(dead), p=p)
        for d, par in zip(dead, parents):
            child = pop[par].copy()
            if rng.random() < p_mutate:
                i = rng.integers(N); child[i] = 1 - child[i]
            pop[d] = child
    return mean_fit

landscape = FitnessLandscape(16, np.random.default_rng(5))
best = np.mean(np.maximum(landscape.one_values, landscape.zero_values))
runs = [("selection + mutation", {}),
        ("no mutation, random start", {"p_mutate": 0, "start": "random"}),
        ("no mutation, identical start", {"p_mutate": 0}),
        ("no selection", {"selection": False})]
for label, kw in runs:
    curve = run(landscape, np.random.default_rng(1), **kw)
    plt.plot(curve, label=label)
    print(f"{label:30s} start {curve[0]:.3f}  end {curve[-1]:.3f}")
plt.axhline(best, color="gray", ls="--", label=f"best possible = {best:.3f}")
plt.xlabel("generation"); plt.ylabel("mean fitness"); plt.legend(fontsize=8)
```

Two choices to know about: everyone except the "random start" population begins at the **worst** genome, so any climb is visible; and `strength = 8` makes fitness differences matter more than in the book (whose gentle selection needs thousands of generations). Set `strength = 1` to see the book's pace.

```quiz
"No mutation, random start" rises quickly and then goes flat below the best possible fitness, while "no mutation, identical start" never moves at all. Why?
- The population died out
* Selection used up the variation that was there at the start; with no new variants it can't climb higher
- Mutation is required for any change at all
- The landscape changed
> With a random start there's plenty of variation, so selection improves fitness at first. Once the population converges on the best of what existed, there's nothing new to select. With an identical start there's no variation at all, so selection has nothing to act on. Mutation supplies the novelty that keeps the climb going.
```

```quiz
"No selection" drifts up from the worst genome to about the middle (roughly 0.5) and then wanders, far below the peak. Which ingredient is missing?
- Replication; the population can't copy itself
* Differential reproduction; without it, mutation just causes random drift, not adaptation
- Variation; nothing changes
- Nothing is missing; this is normal evolution
> Copies and mutations still happen, so the population changes, but nothing favours fitter variants. It drifts toward a typical random genome (average fitness), not toward the peak. Adaptation needs selection and variation together.
```

## Real-world project: evolve a delivery route

You've seen evolution climb a fitness landscape with nothing but copying, variation and selection. Engineers borrow that recipe as a **genetic algorithm** when a problem has far too many options to try them all. A van that visits 12 shops has about 20 million possible round trips; 20 shops, over 10¹⁷. Instead of checking them all, breed good routes from good routes.

```project
title: Genetic algorithm for a delivery van's route
client: A local bakery whose van visits a dozen cafés every morning
skills: permutations, numpy distances, mutation without shared state, selection by fitness
---brief
A **genome** is now an order of stops (a permutation like `[3, 0, 7, …]`), and fitness is "shorter is better". Write `route_length` to score a round trip, then `evolve_route`: a population of random routes where, each generation, some routes die and are replaced by mutated copies of short routes. The mutation reverses a stretch of the route, which untangles crossings.
---why
Genetic algorithms and their cousins schedule exams and shifts, pack shipping containers, tune machine-learning hyperparameters and design antennas (NASA evolved one for its ST5 satellites). Real route planners (Google OR-Tools, delivery companies' dispatch systems) combine this kind of search with smarter local moves. And the shared-genome bug from earlier is a classic GA bug: forget to copy the parent and your whole population silently changes.
---milestones
- Write `route_length(order, pts)`: the length of the closed loop through the stops in that order
- Use `reverse_segment` as the mutation, and check it never changes the parent
- Write `evolve_route`: selection by fitness, mutation, and remember the best route ever seen
- Test it on stops placed round a circle, where you know the best answer
- Plot the bakery's route before and after evolution
---stretch
- Add a time window ("café 4 must be visited before 8 am") as a penalty in the fitness
- Add **crossover** (order crossover, OX) so two good routes can combine their good parts
- Compare with a simple greedy "nearest unvisited stop" route: which is shorter, and which is faster to compute?
```

```exercise
title: route_length
kind: write
---prompt
Write `route_length(order, pts)`. `pts` is an `(n, 2)` array of stop coordinates and `order` a permutation of `0 … n-1`. Return the total distance of visiting the stops in that order **and driving back to the start**. Hint: `pts[order]` puts the stops in visiting order, and `np.roll(…, -1, axis=0)` lines each stop up with the next one.
---starter
def route_length(order, pts):
    p = pts[order]
    pass
---solution
def route_length(order, pts):
    p = pts[order]
    return np.sum(np.linalg.norm(p - np.roll(p, -1, axis=0), axis=1))
---tests
square = np.array([[0, 0], [1, 0], [1, 1], [0, 1]], dtype=float)
assert abs(route_length(np.array([0, 1, 2, 3]), square) - 4.0) < 1e-9, "Round the unit square: 4 sides of length 1"

---hint
`p - np.roll(p, -1, axis=0)` is the step from each stop to the next (the last one wraps to the first). `np.linalg.norm(..., axis=1)` gives each step's length.
```

```exercise
def evolve_route(pts, gens=200, n=60, seed=0):
    rng = np.random.default_rng(seed)
    pop = [rng.permutation(len(pts)) for _ in range(n)]
    best = min(pop, key=lambda o: route_length(o, pts))
    for g in range(gens):
        lengths = np.array([route_length(o, pts) for o in pop])
        fits = (1 / lengths) ** 8
        dead = np.flatnonzero(rng.random(n) < 0.2)
        parents = rng.choice(n, size=len(dead), p=fits / fits.sum())
        for d, par in zip(dead, parents):
            pop[d] = reverse_segment(pop[par], rng)
        cand = min(pop, key=lambda o: route_length(o, pts))
        if route_length(cand, pts) < route_length(best, pts):
            best = cand.copy()
    return best
---tests
```

```recall
Q: What are the three ingredients of evolution in the book's minimal view, and what happens when you remove variation or selection?
A: - Replicators, variation, differential survival or reproduction.
- No variation (no mutation): selection quickly picks the best existing genotype, then fitness stops rising.
- No selection: mutation causes random drift; fitness wanders but doesn't climb.
- Only with all three does the population keep adapting toward a peak.
```

```recall
Q: Why choose replacements with probability proportional to fitness instead of always copying the single best agent?
A: - It models differential reproduction realistically: fitter agents tend to have more offspring, but luck still matters.
- It keeps variation in the population longer, so evolution can explore instead of collapsing onto one genotype immediately.
```
