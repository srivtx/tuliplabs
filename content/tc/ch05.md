## What a cellular automaton is

A **cellular automaton** (CA) is a world reduced to the bare minimum:

- **cells** in a row (or grid),
- each in one of a few **states** (here 0 or 1),
- a **rule** that gives a cell's next state from its own state and its neighbours',
- discrete **time**: every cell updates at once, step after step.

Wolfram's **elementary** CAs use a 1-D row and look at three cells: left, self, right. Three cells of 0/1 give 2³ = **8 possible neighbourhoods**, so a rule is just a table of 8 output bits. Read those 8 bits as a binary number and you get the rule's name: Rule 0 to Rule 255.

## From a rule number to a rule table

The book's trick: neighbourhood `(left, self, right)` is itself a 3-bit binary number, `4·left + 2·self + 1·right`, from 0 to 7. Write the rule number in binary, and **bit v** of the rule is the output for neighbourhood v.

```predict
rule = 50
bits = [(rule >> v) & 1 for v in range(8)]
print(bits)
print(format(rule, "08b"))
```

```exercise
title: make_table
kind: write
---prompt
Write `make_table(rule)` returning a numpy array `table` of length 8 where `table[v]` is the output for neighbourhood number `v`. The book uses `np.unpackbits`, which gives the **most** significant bit first, so it reverses the result. Any method is fine.
---starter
def make_table(rule):
    pass
---solution
def make_table(rule):
    rule = np.array([rule], dtype=np.uint8)
    table = np.unpackbits(rule)[::-1]
    return table
---tests
assert list(make_table(50)) == [0, 1, 0, 0, 1, 1, 0, 0], f"Rule 50 should be [0, 1, 0, 0, 1, 1, 0, 0], got {list(make_table(50))}"
assert list(make_table(0)) == [0] * 8, "Rule 0 maps everything to 0"
assert list(make_table(255)) == [1] * 8, "Rule 255 maps everything to 1"
assert make_table(30)[4] == 1 and make_table(30)[7] == 0, "Rule 30: 100 -> 1, 111 -> 0"
---hint
`np.unpackbits(np.array([rule], dtype=np.uint8))` gives 8 bits, most significant first. `[::-1]` reverses them.
```

## A whole row at once

To get the next row you need, for every cell, `4·left + 2·self + 1·right`. `np.correlate` slides a window along the row and does exactly that sum at every position (the ends are padded with 0).

```predict
row = np.array([0, 1, 1, 0, 1])
print(np.correlate(row, [4, 2, 1], mode="same"))
```

Read the output position by position. The middle cell (index 2) sees left=1, self=1, right=0, so 4 + 2 + 0 = 6. Then the next state is just `table[6]`. Indexing a table with an array looks up every cell at once.

## Run the classics

```run
title: Rules 50, 30 and 110
def make_table(rule):
    return np.unpackbits(np.array([rule], dtype=np.uint8))[::-1]

def run_ca(rule, n_rows=60, width=121, start="single", seed=0):
    table = make_table(rule)
    array = np.zeros((n_rows, width), dtype=np.uint8)
    if start == "single":
        array[0, width // 2] = 1
    else:
        array[0] = np.random.default_rng(seed).integers(0, 2, width)
    for i in range(1, n_rows):
        c = np.correlate(array[i - 1], [4, 2, 1], mode="same")
        array[i] = table[c]
    return array

fig, axes = plt.subplots(1, 3, figsize=(10, 3.4))
for ax, rule in zip(axes, [50, 30, 110]):
    ax.imshow(run_ca(rule, start="random" if rule == 110 else "single"), cmap="Blues", interpolation="none")
    ax.set_title(f"Rule {rule}"); ax.set_xticks([]); ax.set_yticks([])
```

Change the rules. Try 18, 90, 54, 73, 184.

## Wolfram's four classes

Wolfram sorted the 256 rules by what they do from a random start:

| Class | Behaviour | Example |
|---|---|---|
| 1 | Everything dies out to a uniform state | Rule 0 |
| 2 | Simple, stable or repeating structures | Rule 50 |
| 3 | Chaotic, random-looking forever | Rule 30 |
| 4 | Localised structures that move and interact: neither order nor chaos | Rule 110 |

Rule 110 is **Turing complete**: with the right starting row it can compute anything a computer can. Simple rules, universal computation.

```quiz
You run a rule from a random start and see triangles of all sizes, never settling, with no repeating pattern. Which class?
- Class 1
- Class 2
* Class 3
- Class 4
> Endless random-looking structure is Class 3, like Rule 30. Class 4 would show persistent "particles" moving through a regular background and colliding.
```

```quiz
What's surprising about Rule 30, given how it's built?
- It needs a random number generator to run
* It's completely deterministic, yet its output passes many tests of randomness
- It only works on wide rows
- It produces a different picture each time from the same start
> Rule 30 has no randomness in it at all, yet from a single cell its centre column looks like coin flips. Mathematica used it as its random-number generator for years.
```

## Rule 30 as a random-number generator

```exercise
title: Random bits from Rule 30
kind: write
---prompt
Write `rule30_bits(n)`: run Rule 30 from a single cell for `n` rows on a row wide enough that the edges never matter (`2*n + 1` cells is enough) and return the **centre column** as a numpy array of `n` bits. `make_table` is defined.
---setup
def make_table(rule):
    return np.unpackbits(np.array([rule], dtype=np.uint8))[::-1]
---starter
def rule30_bits(n):
    pass
---solution
def rule30_bits(n):
    table = make_table(30)
    width = 2 * n + 1
    row = np.zeros(width, dtype=np.uint8)
    row[n] = 1
    bits = [row[n]]
    for _ in range(n - 1):
        row = table[np.correlate(row, [4, 2, 1], mode="same")]
        bits.append(row[n])
    return np.array(bits)
---tests
b = rule30_bits(16)
assert len(b) == 16, f"Expected 16 bits, got {len(b)}"
assert b[:10].tolist() == [1, 1, 0, 1, 1, 1, 0, 0, 1, 1], f"The first ten centre bits of Rule 30 are 1101110011, got {''.join(map(str, b[:10]))}"
big = rule30_bits(800)
assert 0.45 < big.mean() < 0.55, f"Roughly half the bits should be 1, got {big.mean():.3f}"
---hint
You only need the current row, not the whole history. Keep `row`, update it with `table[np.correlate(...)]`, and record `row[n]` each time.
```

## Rebuild it

```exercise
title: Rebuild run_ca
kind: rebuild
---prompt
From memory: `run_ca(rule, n_rows, width)` returns an `(n_rows, width)` uint8 array whose first row has a single 1 in the middle (`width // 2`) and whose later rows follow the rule.
---starter
def run_ca(rule, n_rows, width):
    pass
---solution
def run_ca(rule, n_rows, width):
    table = np.unpackbits(np.array([rule], dtype=np.uint8))[::-1]
    array = np.zeros((n_rows, width), dtype=np.uint8)
    array[0, width // 2] = 1
    for i in range(1, n_rows):
        c = np.correlate(array[i - 1], [4, 2, 1], mode="same")
        array[i] = table[c]
    return array
---tests
a = run_ca(90, 4, 9)
assert a.shape == (4, 9), f"Shape should be (4, 9), got {a.shape}"
assert a[3].tolist() == [0, 1, 0, 1, 0, 1, 0, 1, 0], f"Rule 90 row 3 is a Sierpinski row [0,1,0,1,0,1,0,1,0], got {a[3].tolist()}"
assert run_ca(0, 3, 5)[1:].sum() == 0, "Rule 0 kills everything after the first row"
```

```recall
Q: Walk through how one row of an elementary CA is computed with numpy, from rule number to new row.
A: - Turn the rule number into an 8-entry table: bit v of the rule is the output for neighbourhood v.
- For every cell, encode its neighbourhood as one number: 4·left + 2·self + 1·right. `np.correlate(row, [4, 2, 1], mode="same")` does this for the whole row.
- Look up all cells at once: `new_row = table[codes]`.
```

```recall
Q: What are Wolfram's four classes, and why is Class 4 the interesting one?
A: - 1: dies to uniform; 2: simple stable/periodic patterns; 3: chaos (random-looking); 4: complex localised structures that move and interact.
- Class 4 sits between order and chaos. Structures persist long enough to carry information and interact to process it, which is why Rule 110 can perform universal computation.
```
