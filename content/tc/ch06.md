```prelude
import numpy as np
import matplotlib.pyplot as plt

def add_pattern(array, row, col, pattern):
    """Paste a pattern written with 'O' for alive and '.' for dead."""
    for i, line in enumerate(pattern.strip().split()):
        for j, ch in enumerate(line):
            array[row + i, col + j] = 1 if ch == "O" else 0
    return array
```

## Two rules

Conway's Game of Life (1970) is a 2-D cellular automaton. Every cell is alive or dead and has 8 neighbours (including diagonals). Each step, all cells update at once:

- **Birth:** a dead cell with exactly **3** live neighbours comes alive.
- **Survival:** a live cell with **2 or 3** live neighbours stays alive.
- Everyone else dies or stays dead (from loneliness or overcrowding).

That's all. From these two rules come still lifes, blinking oscillators, spaceships that glide across the grid, and machines that build other machines.

> Survival needs 2 or 3 neighbours, so 4 is too many. Birth needs exactly 3, so 2 is not enough.

## Count every cell's neighbours at once

Just like the street in chapter 1, but in two directions: shift the grid one step in each of the 8 directions with `np.roll` and add the results. The grid wraps around (a **torus**), so there are no edges to special-case.

```predict

              [1, 1, 1],
              [0, 0, 0]])
print(np.roll(a, 1, axis=0))
print(np.roll(a, 1, axis=1)[1])
```

## The trick: weight yourself by 10

We count neighbours with `scipy.signal.correlate2d` and a 3×3 **kernel** whose centre is **10** instead of 0. Then every cell gets one number: `c = 10 × (alive?) + neighbours`. A dead cell with 3 neighbours has c = 3; a live cell with 2 or 3 has c = 12 or 13. So the whole rule is: **alive next iff c is 3, 12 or 13**.

```run
title: Life the fast way (correlate2d)
from scipy.signal import correlate2d

kernel = np.array([[1, 1, 1],
                   [1, 10, 1],
                   [1, 1, 1]])

def step(a):
    c = correlate2d(a, kernel, mode="same", boundary="wrap")
    return ((c == 3) | (c == 12) | (c == 13)).astype(np.uint8)

a = np.zeros((6, 6), dtype=np.uint8)
a[2, 1:4] = 1
print(correlate2d(a, kernel, mode="same", boundary="wrap"))
print(step(a))
```

## Gliders and the gun

A **glider** is five cells that, every 4 steps, reappear one cell diagonally away. Nothing in the rules says "move"; motion **emerges**.

```run
title: Watch a glider walk
def count_neighbors(a):
    n = np.zeros_like(a, dtype=int)
    for di in (-1, 0, 1):
        for dj in (-1, 0, 1):
            if (di, dj) != (0, 0):
                n += np.roll(np.roll(a, di, axis=0), dj, axis=1)
    return n

def life_step(a):
    n = count_neighbors(a)
    return (((a == 0) & (n == 3)) | ((a == 1) & ((n == 2) | (n == 3)))).astype(int)

glider = """
.O.
..O
OOO
"""
a = add_pattern(np.zeros((8, 8), dtype=int), 0, 0, glider)
fig, axes = plt.subplots(1, 5, figsize=(10, 2.3))

    ax.imshow(a, cmap="Greens", interpolation="none")
    ax.set_title(f"step {t}"); ax.set_xticks([]); ax.set_yticks([])
    a = life_step(a)
```

## Real-world project: a pattern library that names what it sees

Life fans have catalogued hundreds of thousands of patterns, and nobody sorts them by hand: a program runs each one and **classifies** it. Is it a still life (never changes), an oscillator (comes back after k steps), a spaceship (comes back moved), or does it die? Writing that classifier is a lesson in a very common engineering problem: deciding when two states are "the same", even if one has moved.

```project
title: Pattern detector for a Game of Life library
client: An online Life pattern wiki that wants to auto-tag uploads
skills: bounding boxes, array comparison, simulation loops, state matching
---brief
When someone uploads a pattern, the wiki should tag it automatically. Run it forward step by step and compare each state with the start. To spot a spaceship you need to compare **shapes**, not positions, so first write `crop`, which cuts a board down to the smallest box holding every live cell. Then `classify` returns `("dies", t)`, `("still life", 1)`, `("oscillator", period)`, `("spaceship", period)` or `("unknown", 0)`.
---why
Comparing states "up to a shift" is how image search finds a logo anywhere in a picture, how version-control tools spot moved code, and how simulators detect that a system has entered a cycle (a key trick in debugging and in model checkers that verify software). The real Life community runs exactly this kind of tool (apgsearch) over billions of random starts.
---milestones
- Write `crop(a)`: the bounding box of the live cells
- Write `classify`: step forward and compare with the start, both in place and cropped
- Test it on a block, a blinker, a toad, a glider and a single cell
- Run 100 random 5×5 soups and count how many end up as each kind
- Show the wiki's tag next to a picture of each pattern
---stretch
- Patterns that **settle** into an oscillator after a while (like most soups) need you to compare against every earlier state, not just the start: store them in a dict keyed by `a.tobytes()`
- Report a spaceship's speed (cells moved per step), like the glider's c/4
- Detect when a pattern grows forever (like the glider gun)
```

## What Life teaches about science

Life also makes a philosophical point. Gliders "exist" at a higher level of description than cells. Are they real things, or just a convenient way to talk about cell patterns?

- **Realism:** higher-level entities like gliders (or species, or economies) are real and the theories about them are true or false.
- **Instrumentalism:** they're useful models; a theory is judged by how well it predicts, not whether it's "true".

Life also shows that **simple rules can be universal**: you can build logic gates from gliders, and Life is Turing complete.

```quiz
Someone says: "Gliders aren't real. There are only cells turning on and off." Which point answers that?
- They're right; higher-level descriptions are errors
* "Glider" is a valid, useful higher-level description, and the debate over whether it's "real" is the realism vs instrumentalism question
- Gliders are real because they're in the source code
- The rules of Life explicitly define gliders
> Nothing in the two rules mentions gliders, yet "a glider moves one cell diagonally every 4 steps" predicts the system perfectly. Whether such emergent objects are "real" is exactly what realists and instrumentalists disagree about.
```

```recall
Q: Explain the kernel-10 trick: why is "alive next step" the same as "c is 3, 12 or 13"?
A: - The kernel adds up the 8 neighbours with weight 1 and the cell itself with weight 10, so c = 10·self + neighbours.
- Dead cells have c = 0…8; live cells have c = 10…18. The two ranges can't overlap.
- Birth (dead, 3 neighbours) → 3. Survival (alive, 2 or 3) → 12 or 13. Any other value means dead next step.
```

```recall
Q: What did the glider gun prove, and why does it matter for complexity science?
A: - Conway conjectured that every finite starting pattern eventually stops growing. The gun is a finite pattern whose population grows forever (one glider every 30 steps), so the conjecture is false.
- It shows you often can't predict what simple rules will do by reasoning about them: you have to run them. And guns are a building block for computation in Life (glider streams as signals).
```

```puzzle

title: One generation of Life
---items
Count each cell's 8 neighbours
A live cell with 2 or 3 neighbours stays alive
A dead cell with exactly 3 neighbours is born
Every other cell is dead in the next generation
Apply all the changes at once
---why
Updating "at once" matters. If you change cells one at a time, later cells see a half-updated board and the patterns fall apart.
```
