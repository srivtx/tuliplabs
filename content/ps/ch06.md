## A bell from anything

Waiting times are lopsided: lots of short waits, a few very long ones. A lottery is lopsided: almost always 0, rarely a jackpot. Yet take **averages** of many draws from either one, and the averages pile into the same symmetric bell. Try to break it.

```viz

height: 430

```

```quiz

- 10, the same as the source
- 0.4

- 250
> Averages wobble less than single draws, by a factor of √n. With n = 25 that's 5 times less. (Chapter 5 found the same σ/√n from the other direction.)
```

## The normal distribution and z-scores

The normal (Gaussian) distribution is the bell, fixed by two numbers: its mean μ (where the centre is) and its standard deviation σ (how wide). Every normal curve is the same shape, just shifted and stretched. So to compare a value with its curve, measure how many σ it is from the mean: the **z-score**

    z = (x − μ) / σ

A z of 2 means "two standard deviations above average", whatever the units: cm, kg, exam points.

```predict
heights_mu, heights_sd = 170, 8
for x in [170, 186, 158]:
    print(x, (x - heights_mu) / heights_sd)
```

```exercise
title: rarer_than
kind: write
---prompt
Write `rarer_than(x, mu, sigma)`: the probability that a normal(μ, σ) value is **at least as far from the mean** as `x`, in either direction (a two-sided tail). Compute the z-score and use `stats.norm.sf` (the upper tail, 1 − CDF).
---starter
def rarer_than(x, mu, sigma):
    return 0.0
---solution
def rarer_than(x, mu, sigma):
    z = abs(x - mu) / sigma
    return 2 * stats.norm.sf(z)
---tests
assert abs(rarer_than(186, 170, 8) - 0.0455) < 1e-3, "2 sd away: about 4.6% of values are that extreme"
assert abs(rarer_than(154, 170, 8) - rarer_than(186, 170, 8)) < 1e-12, "the bell is symmetric: below works the same as above"
assert abs(rarer_than(170, 170, 8) - 1) < 1e-12, "everything is at least 0 sd from the mean"
---hint
Take the absolute z-score, then double the one-sided tail `stats.norm.sf(z)`.
```

## 68–95–99.7

For any normal curve:

- about **68%** of values are within 1σ of the mean,
- about **95%** within 2σ,
- about **99.7%** within 3σ.

Memorise these three numbers. They let you sanity-check claims instantly: if someone reports a "normal" process with a 5σ event every week, either it isn't normal or something is broken.

```exercise
title: within
kind: fill
---prompt
Fill in `within(k)`: the probability that a normal value lands within `k` standard deviations of its mean. Use the **standard** normal CDF.
---starter

    return ____
---solution
def within(k):
    return stats.norm.cdf(k) - stats.norm.cdf(-k)
---tests
assert abs(within(1) - 0.6827) < 1e-4, "within 1 sd: 68%"
assert abs(within(2) - 0.9545) < 1e-4, "within 2 sd: 95%"
assert abs(within(3) - 0.9973) < 1e-4, "within 3 sd: 99.7%"
---hint
The area between −k and k is `CDF(k) − CDF(−k)`.
```

## The central limit theorem

Here it is, the reason the bell is everywhere:

> Add up (or average) **n independent** draws from almost any distribution with a finite spread. As n grows, the sum's distribution gets closer and closer to **normal**, with mean n·μ (for the average: μ) and standard deviation σ·√n (for the average: σ/√n).

Heights are sums of many genes and nutrition effects; measurement errors are sums of many tiny disturbances; a poll's result is an average of many answers. None of the individual pieces needs to be normal.

```run
title: Sums of skewed waiting times
rng = np.random.default_rng(0)
import matplotlib.pyplot as plt
fig, axes = plt.subplots(1, 4, figsize=(12, 2.6))
for ax, n in zip(axes, [1, 2, 10, 50]):
    means = rng.exponential(1.0, size=(20000, n)).mean(axis=1)
    ax.hist(means, bins=60, density=True)
    ax.set_title(f"mean of {n} waits")
plt.tight_layout()
```

```exercise
    rng = np.random.default_rng(seed)

---tests
expo = lambda rng, size: rng.exponential(2.0, size)

---hint

```

## When the CLT is slow, or fails

"As n grows" hides a question: how big is big enough? It depends on the source.

- Nearly symmetric sources (a die): n ≈ 5–10 already looks normal.
- Lopsided sources (waiting times, incomes, jackpots): you may need n in the dozens or hundreds. The rarer and bigger the jackpot, the longer it takes.
- Sources with **infinite variance** (some "heavy-tailed" distributions, like the Cauchy): the CLT doesn't apply at all, and averaging never settles.

```quiz
A startup averages the revenue of 10 customers to estimate the typical customer. Revenue is extremely lopsided: most pay 10, a few enterprise customers pay 50,000. Is a normal-based error bar trustworthy?
- Yes, the CLT always works for n ≥ 10
* No: with such a lopsided source, 10 customers is far too few for the average to be near normal; one big customer in or out swings it wildly
- Yes, because revenue can't be negative
- No, because the CLT only applies to coins and dice
> The rule of thumb "n ≥ 30" is for mild sources. With one-in-a-hundred giants, the average of 10 is dominated by whether a giant happened to be in the sample. Use the bootstrap (chapter 8) or a median, and look at the data.
```

## Real-world project: a control chart for a factory

```project
title: Catch a drifting machine before customers do
client: A factory filling 500 g bags of coffee
skills: z-scores, the CLT, standard error, three-sigma limits, false alarms
---brief
A machine fills bags with mean 500 g and standard deviation 4 g when it's working properly. Every hour, an inspector weighs 9 bags and records their average. By the CLT, those hourly averages are about normal with spread 4/√9 ≈ 1.33 g. Draw **control limits** at μ ± 3 standard errors and flag any hour whose average falls outside: something has probably changed. Then measure how often your chart raises a false alarm, and how fast it catches a machine that drifts to 503 g.
---why
Control charts (Shewhart, 1920s) still run on every production line, in labs and in hospitals, and the same idea is behind alerting on software metrics: "page someone when latency is more than 3σ from normal". Choosing the limit is a trade-off between false alarms and missed problems.
---milestones
- Write `limits(mu, sigma, n, k=3)` returning the lower and upper control limits
- Write `out_of_control(hourly_means, ...)` returning the hours that break the limits
- Simulate a year of a healthy machine and count false alarms
- Simulate a drift to 503 g and measure how many hours until the first alarm
- Recommend k (2, 2.5 or 3) to the plant manager, with numbers
---stretch
- Add the "two of three points beyond 2σ" rule and compare detection speed
- Plot the chart with the limits as lines and the alarms in red
- Track the spread too (an R-chart): a machine can get noisier without drifting
```

```exercise
title: out_of_control
kind: write
---prompt
Write `out_of_control(hourly_means, mu, sigma, n, k=3)`: the control limits are `mu ± k * sigma / sqrt(n)`. Return the list of **indices** of hours whose mean is strictly outside them.
---starter
def out_of_control(hourly_means, mu, sigma, n, k=3):
    return []
---solution
def out_of_control(hourly_means, mu, sigma, n, k=3):
    se = sigma / np.sqrt(n)
    lo, hi = mu - k * se, mu + k * se
    return [i for i, m in enumerate(hourly_means) if m < lo or m > hi]
---tests
assert out_of_control([500.2, 499.1, 504.5, 500.0, 495.5], 500, 4, 9) == [2, 4], "limits are 500 ± 4: hours 2 and 4 are outside"
rng = np.random.default_rng(0)
healthy = rng.normal(500, 4, size=(8760, 9)).mean(axis=1)
rate = len(out_of_control(healthy, 500, 4, 9)) / 8760
assert 0.001 < rate < 0.006, f"a healthy machine trips 3σ limits about 0.27% of hours; got {rate:.4f}"
drift = rng.normal(503, 4, size=(200, 9)).mean(axis=1)
assert len(out_of_control(drift, 500, 4, 9)) > 20, "a 3 g drift gets flagged often"
---hint
Compute the standard error once, then the two limits, then keep the indices outside them.
```

## Rebuild it and explain it

```exercise
title: clt_check
kind: rebuild
---prompt
From memory: write `clt_check(n, reps=20000, seed=0)` that draws `reps` samples of `n` fair-die rolls (`rng.integers(1, 7, ...)`), averages each, and returns `(mean_of_means, sd_of_means)`.

---solution
def clt_check(n, reps=20000, seed=0):
    rng = np.random.default_rng(seed)
    means = rng.integers(1, 7, size=(reps, n)).mean(axis=1)
    return means.mean(), means.std()

---hint
One `(reps, n)` block of rolls, averaged along each row.
```

```recall
Q: Explain the central limit theorem to someone who's never heard of it, and say why it makes the bell curve so common.
A: If you add up or average many independent random pieces, the total's distribution looks like a bell, no matter what each piece looked like, as long as no single piece dominates. The bell is centred on the average of the pieces' mean, and its width shrinks like 1/√n for averages. Lots of real quantities (heights, measurement errors, poll results, total sales) are sums of many small independent effects, so they come out bell-shaped. It needs more pieces when each one is very lopsided, and it fails when single pieces can be wildly extreme.
```
