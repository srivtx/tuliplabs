## Did the new design work?

A website tried a new sign-up page for 8 days and kept the old one for 8 other days. Daily sign-ups:

- old page: 31, 28, 35, 30, 27, 33, 29, 32
- new page: 34, 30, 38, 33, 29, 36, 31, 37

The new page averages about 3 more sign-ups a day. But days vary anyway: some are just busier. So the real question is: **if the page made no difference at all, how often would luck alone produce a gap this big?**

Here's the trick that answers it with no formulas. If the page did nothing, the labels "old" and "new" are meaningless: any day could have worn either label. So **shuffle the labels**, recompute the gap, and repeat thousands of times. That pile of shuffled gaps is what luck looks like.

```viz
name: ps-permute
title: Shuffle the labels, see what luck looks like
goal: Shuffle at least **1,000** times to estimate the p-value, then try **p-hacking: 20 tests on noise** and run them.
height: 430
Each column is one day (its height is the sign-ups). **Shuffle labels** mixes which days count as old or new and drops the new gap into the histogram behind. The marker is the real gap.
```

```quiz
After 1,000 shuffles, 21 of the shuffled gaps were at least as big as the real one. What does that tell you?
- There's a 2.1% chance the new page works
- There's a 97.9% chance the new page works
* If the page made no difference, luck alone would produce a gap this big about 2.1% of the time
- The new page adds 2.1% more sign-ups
> That's the definition of a p-value: the probability of data at least this extreme **assuming the null hypothesis is true**. It isn't the probability that the null (or the alternative) is true. That needs a prior: chapter 11.
```

## The null hypothesis and the test statistic

Every test has the same skeleton:

1. **The null hypothesis (H₀):** the boring explanation. "The page makes no difference."
2. **A test statistic:** one number that measures the effect you care about. Here: mean(new) − mean(old).
3. **The null distribution:** what that number looks like when H₀ is true. Shuffling builds it for us.
4. **The p-value:** where the real number falls in that distribution.

Choosing the statistic is a modelling decision. The difference in means is natural, but you could compare medians if a few huge days worried you.

```predict
old = np.array([31, 28, 35, 30, 27, 33, 29, 32])
new = np.array([34, 30, 38, 33, 29, 36, 31, 37])
print(new.mean(), old.mean())
print(new.mean() - old.mean())
```

## The permutation test, in code

Put all 16 days in one array. A shuffle is `rng.permutation(pooled)`: the first 8 are "old", the rest "new". Count how often a shuffled gap is at least as big as the real one.

```parsons
title: One shuffle
---lines
pooled = np.concatenate([old, new])
mixed = rng.permutation(pooled)
fake_old, fake_new = mixed[:len(old)], mixed[len(old):]
gap = fake_new.mean() - fake_old.mean()
?? gap = new.mean() - old.mean()
---setup
old = np.array([31, 28, 35, 30, 27, 33, 29, 32])
new = np.array([34, 30, 38, 33, 29, 36, 31, 37])
rng = np.random.default_rng(0)
---tests
assert len(fake_old) == 8 and len(fake_new) == 8, "split back into two groups of the original sizes"

```

```exercise
title: perm_test
kind: write
---prompt
Write `perm_test(a, b, n=10000, seed=0)` for the one-sided question "is b's mean bigger than a's?". Compute the observed gap `mean(b) - mean(a)`, then shuffle the pooled data `n` times with `rng = np.random.default_rng(seed)` and count shuffled gaps **≥** the observed one. Return `(observed, p_value)` where `p_value = count / n`.
---starter
def perm_test(a, b, n=10000, seed=0):
    rng = np.random.default_rng(seed)
    observed = 0.0
    return observed, 1.0
---solution
def perm_test(a, b, n=10000, seed=0):
    rng = np.random.default_rng(seed)
    a, b = np.asarray(a, float), np.asarray(b, float)
    observed = b.mean() - a.mean()
    pooled = np.concatenate([a, b])
    count = 0
    for _ in range(n):
        m = rng.permutation(pooled)
        if m[len(a):].mean() - m[:len(a)].mean() >= observed:
            count += 1
    return observed, count / n
---tests
old = [31, 28, 35, 30, 27, 33, 29, 32]
new = [34, 30, 38, 33, 29, 36, 31, 37]
obs, p = perm_test(old, new)
assert obs == 2.875, f"the real gap is 2.875 sign-ups a day, got {obs}"
assert 0.02 < p < 0.12, f"luck makes a gap of 3 or more fairly rarely here: p should be a few percent, got {p}"
same = [10, 12, 11, 13, 9, 12]
_, p_same = perm_test(same, same)
assert p_same > 0.4, f"identical groups: a gap of 0 or more is common, p should be big, got {p_same}"
---hint
`pooled = np.concatenate([a, b])`; each loop does `m = rng.permutation(pooled)` and compares `m[len(a):].mean() - m[:len(a)].mean()` with the observed gap.
```

One choice to make up front: **one-sided** ("is new *better*?") or **two-sided** ("is new *different*, either way?"). The simulation above counts shuffled gaps of 2.875 or more in **either** direction, so its p-value comes out about twice your one-sided one. Decide which question you're asking *before* you look at the data; switching afterwards to get a smaller p is a quiet form of cheating.

## What a p-value is not

A p-value answers a narrow question. It's easy to stretch it into one it doesn't answer:

- It is **not** the chance that H₀ is true. (That needs Bayes, chapter 11.)
- It is **not** the size of the effect. A tiny, useless effect can have p = 0.0001 with enough data.
- A big p-value does **not** prove "no effect". It may just mean too little data.

The 0.05 line is a convention, not a law of nature. Report the p-value *and* the effect size (with an interval, chapter 8).

```quiz
An app tested a new button on 2 million users. Click rate went from 10.00% to 10.02%, with p = 0.003. Should they celebrate?
- Yes: p < 0.05 means the effect is large
* Not much: the effect is real but tiny; whether 0.02 points matters is a business question, not a p-value question
- No: p = 0.003 means the result is probably a fluke
- No: a p-value can't be computed with 2 million users
> With huge samples, even microscopic effects become "significant". Significance says the effect probably isn't zero; it says nothing about whether it's big enough to care about.
```

## Two ways to be wrong, and power

A test can fail in two directions:

| | Really no effect | Really an effect |
|---|---|---|
| Test says "effect!" | **False positive** (type I) | correct |
| Test says "nothing" | correct | **False negative** (type II) |

The 0.05 threshold (called **α**) caps false positives at 5% *when there's no effect*. **Power** is the chance of catching an effect that is really there. It grows with the effect size and the sample size, and it's the reason you should decide the sample size *before* running an experiment.

```predict
rng = np.random.default_rng(7)
false_pos = 0
for trial in range(2000):
    a = rng.normal(0, 1, 30)
    b = rng.normal(0, 1, 30)
    se = np.sqrt(a.var(ddof=1) / 30 + b.var(ddof=1) / 30)
    if (b.mean() - a.mean()) / se > 1.645:
        false_pos += 1
print(false_pos / 2000)
```

```exercise
title: power
kind: write
---prompt
Write `power(effect, n, trials=2000, seed=0)`: simulate `trials` experiments where group A is `rng.normal(0, 1, n)` and group B is `rng.normal(effect, 1, n)`. In each, compute `z = (mean(B) - mean(A)) / se` with `se = sqrt(var(A, ddof=1)/n + var(B, ddof=1)/n)` and count it as a detection when `z > 1.645` (one-sided α = 0.05). Return the fraction detected.
---starter
def power(effect, n, trials=2000, seed=0):
    rng = np.random.default_rng(seed)
    return 0.0
---solution
def power(effect, n, trials=2000, seed=0):
    rng = np.random.default_rng(seed)
    hits = 0
    for _ in range(trials):
        a = rng.normal(0, 1, n)
        b = rng.normal(effect, 1, n)
        se = np.sqrt(a.var(ddof=1) / n + b.var(ddof=1) / n)
        if (b.mean() - a.mean()) / se > 1.645:
            hits += 1
    return hits / trials
---tests
p0 = power(0.0, 30)
assert 0.03 < p0 < 0.08, f"with no effect, 'power' is just the false-positive rate, about 5%; got {p0}"
small, big = power(0.3, 30), power(0.3, 300)
assert big > 0.9 and small < 0.6, f"the same small effect: hard to catch with 30 per group ({small}), easy with 300 ({big})"
assert power(1.0, 30) > 0.95, "a big effect is caught almost every time"
---hint
Same loop as the false-positive simulation above, but group B's mean is `effect` instead of 0.
```

## Twenty tests on pure noise

Here's how good scientists fool themselves. Test 20 things (20 button colours, 20 subgroups, 20 outcome measures) where **nothing** is going on. Each test has a 5% false-positive rate, so the chance that **at least one** looks "significant" is 1 − 0.95²⁰ ≈ 64%. Report only that one and you've published noise. That's **p-hacking**.

The simplest fix, **Bonferroni**, uses α/20 for each of 20 tests, which keeps the chance of *any* false positive near 5%.

```exercise
title: any_false_positive
kind: bug
---prompt
`family_rate(k, alpha, trials, seed)` simulates `trials` studies that each run `k` independent tests on noise (each test's p-value is uniform on 0–1) and should return the fraction of studies with **at least one** p below `alpha`. It returns something far too small. Fix it.
---starter
def family_rate(k, alpha, trials=20000, seed=0):
    rng = np.random.default_rng(seed)
    hits = 0
    for _ in range(trials):
        ps = rng.random(k)
        if (ps < alpha).all():
            hits += 1
    return hits / trials
---solution
def family_rate(k, alpha, trials=20000, seed=0):
    rng = np.random.default_rng(seed)
    hits = 0
    for _ in range(trials):
        ps = rng.random(k)
        if (ps < alpha).any():
            hits += 1
    return hits / trials
---tests
r = family_rate(20, 0.05)
assert 0.6 < r < 0.68, f"20 tests at 0.05: about 64% of studies find something; got {r}"
rb = family_rate(20, 0.05 / 20)
assert 0.04 < rb < 0.06, f"with Bonferroni the family rate is back near 5%; got {rb}"
---hint
"At least one" test fired, not "every" test fired.
```

## Real-world project: did the new design increase sign-ups?

```project
title: A/B test report for a sign-up page redesign
client: The growth team of a small SaaS company
skills: null hypotheses, permutation tests, effect sizes, power, multiple testing
---brief
The team ran the old and new sign-up pages on random days and wants a decision they can defend. Write a report function that takes the two samples and returns the effect (difference in means), a permutation p-value, a bootstrap 95% interval for the effect (chapter 8), and a plain-English verdict. Then use your `power` function to tell them how many days they'd need next time to reliably detect a lift of 2 sign-ups a day.
---why
Every product team at Netflix, Booking.com, Amazon and thousands of start-ups makes decisions this way, and A/B-testing tools (Optimizely, Statsig, GrowthBook) are permutation and z-tests with a dashboard on top. The classic failures, deciding on p alone, stopping early when it looks good, slicing data until something is significant, cost real money.
---milestones
- Write `ab_report(control, treatment)` returning effect, p-value and verdict
- Add a bootstrap interval for the effect so the report shows a range, not just a point
- Write the verdict in plain words, including the effect size, not just "significant"
- Use simulation to find the sample size for 80% power at the lift they care about
- Check your report on fake data where you *know* there's no effect: it should say so ~95% of the time
---stretch
- Report a Bayesian "probability the new page is better" too (chapter 11)
- Simulate what happens if they peek every day and stop at the first p < 0.05 (chapter 13)
- Handle conversion *rates* (yes/no per visitor) instead of daily counts
```

```exercise
title: ab_report
kind: write
---prompt
Write `ab_report(control, treatment, n=5000, seed=0)` returning a dict with keys `"effect"` (mean(treatment) − mean(control)), `"p"` (one-sided permutation p-value with `n` shuffles and `np.random.default_rng(seed)`) and `"verdict"`: `"ship it"` if p < 0.05 **and** the effect is at least `1.0`, `"real but too small"` if p < 0.05 but the effect is under 1.0, and `"not convincing"` otherwise.
---starter
def ab_report(control, treatment, n=5000, seed=0):
    return {"effect": 0.0, "p": 1.0, "verdict": "ship it"}
---solution
def ab_report(control, treatment, n=5000, seed=0):
    rng = np.random.default_rng(seed)
    a, b = np.asarray(control, float), np.asarray(treatment, float)
    effect = b.mean() - a.mean()
    pooled = np.concatenate([a, b])
    count = 0
    for _ in range(n):
        m = rng.permutation(pooled)
        if m[len(a):].mean() - m[:len(a)].mean() >= effect:
            count += 1
    p = count / n
    if p < 0.05:
        verdict = "ship it" if effect >= 1.0 else "real but too small"
    else:
        verdict = "not convincing"
    return {"effect": effect, "p": p, "verdict": verdict}
---tests
r = ab_report([31, 28, 35, 30, 27, 33, 29, 32], [34, 30, 38, 33, 29, 36, 31, 37])
assert r["effect"] == 2.875 and r["p"] < 0.1, f"the sign-up data: effect 2.875, small p; got {r}"
rng = np.random.default_rng(1)
big_a, big_b = rng.normal(50, 5, 400), rng.normal(50.5, 5, 400)
assert ab_report(big_a, big_b)["verdict"] == "real but too small", "lots of data and a tiny lift: significant, but not worth it"
assert ab_report([5, 6, 7, 5, 6], [6, 5, 7, 6, 5])["verdict"] == "not convincing", "no real difference: not convincing"
assert ab_report(rng.normal(50, 5, 60), rng.normal(55, 5, 60))["verdict"] == "ship it", "a big, clear lift: ship it"
---hint
Reuse your permutation test for `p`, then decide with two conditions: is it significant, and is it big enough to matter?
```

```recall
Q: Explain a p-value to a friend who runs a bakery and tried a new recipe on some days, without using the words "null hypothesis".
A: Suppose the recipe made no difference at all. Then which days happened to get the new recipe is just luck of the draw. If I reshuffle which days count as "new recipe" thousands of times, I see how big a difference luck alone tends to make. The p-value is how often luck matched or beat the difference you actually saw. A small p-value means luck rarely does that, so the recipe probably did something. It doesn't say how much, or guarantee it, and if you try twenty recipes some will look good by luck.
```
