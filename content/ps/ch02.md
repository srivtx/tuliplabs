## Does knowing one thing change the odds of another?

A shop has 400 customers. Some bought bread, some bought butter. If I tell you a customer bought butter, is it now *more* likely they bought bread? And if I tell you they shopped at the weekend, does that tell you anything about the butter?

The simulation shows each customer as one block. Colour shows two yes/no facts about them: **A** and **B**. Pressing **Given B** lifts the B customers out of the crowd. Asking "what's the chance of A, given B?" just means: **among the lifted people**, what fraction are A?

## The complement and the addition rule

Two rules come straight from counting.

**Complement.** Every outcome is either in event A or not. So P(not A) = 1 − P(A). This is often the easy way in: "at least one six in four rolls" is hard to count directly, but "no sixes" is just (5/6)⁴.

**Addition rule.** P(A or B) = P(A) + P(B) − P(A and B). Why subtract? If you add the A people and the B people, everyone who is *both* got counted twice. Take them away once.

```predict
die = {1, 2, 3, 4, 5, 6}
even = {2, 4, 6}
big = {4, 5, 6}
print(len(even) + len(big))
print(len(even | big))
print(len(even & big))
print(1 - (5 / 6) ** 4)
```

The naive answer for "even or big" is 3 + 3 = 6 outcomes, which would be *certain*. But 1 and 3 are neither! The overlap {4, 6} was counted twice.

## Conditional probability: count inside the smaller world

The notation **P(A | B)** reads "probability of A given B". The recipe is what the simulation does:

1. Throw away everyone who isn't B (they fade out).
2. Among who's left, count the A's.

As a formula: P(A | B) = (number who are A and B) / (number who are B). Divide the top and bottom by the total and you get the textbook version, **P(A | B) = P(A and B) / P(B)**. It's the same thing.

Careful: P(A | B) and P(B | A) are different. The fraction of butter buyers who buy bread is 96/120 = 0.8. The fraction of bread buyers who buy butter is 96/180 = 0.53. Different bottom number, different world.

```predict
# each row: (bought bread, bought butter) for 10 customers
rows = [(1, 1), (1, 0), (0, 0), (1, 1), (0, 1),
        (1, 1), (0, 0), (1, 0), (0, 0), (1, 1)]
bread = np.array([r[0] for r in rows]) == 1
butter = np.array([r[1] for r in rows]) == 1
print(butter.sum())
print((bread & butter).sum())
print((bread & butter).sum() / butter.sum())
print((bread & butter).sum() / bread.sum())
```

```exercise
def cond_prob(a, b):
```

## Independence and the multiplication rule

Two events are **independent** when learning one doesn't change the chance of the other: P(A | B) = P(A). In the weekend scenario, the fraction of butter buyers among weekend shoppers is about the same as overall: the day tells you nothing about butter.

Rearranging the conditional formula gives the **multiplication rule**, which always works:

P(A and B) = P(B) × P(A | B)

When A and B are independent, P(A | B) is just P(A), so it shrinks to P(A and B) = P(A) × P(B). That shortcut is why we could multiply dice in chapter 1. Using it when events are *not* independent is one of the most common mistakes in real analysis: rain and umbrellas, or two components failing in the same storm.

```parsons
title: An independence test from counts
---lines
def looks_independent(a, b, tol=0.02):
    p_a = a.mean()
    p_b = b.mean()
    p_ab = (a & b).mean()
    return abs(p_ab - p_a * p_b) < tol
?? return abs(p_ab - (p_a + p_b)) < tol
?? p_ab = (a | b).mean()
---tests
rng = np.random.default_rng(3)
x = rng.random(100000) < 0.4
y = rng.random(100000) < 0.5
assert looks_independent(x, y), "Two separate random draws are independent"
assert not looks_independent(x, x), "An event is never independent of itself (unless P is 0 or 1)"
```

```quiz
P(rain) = 0.3 and P(I carry an umbrella) = 0.4. Someone computes P(rain and umbrella) = 0.3 × 0.4 = 0.12. What's wrong?
- Nothing, that's the multiplication rule
- They should have added: 0.3 + 0.4 = 0.7
* They assumed independence, but I'm much more likely to carry an umbrella when it rains, so the real answer is bigger
- Probabilities can't be multiplied
> The general rule is P(rain and umbrella) = P(rain) × P(umbrella | rain). If P(umbrella | rain) is 0.9, the answer is 0.27, more than twice 0.12. Multiplying the plain probabilities is only allowed when the events are independent.
```

## Tree diagrams: one stage at a time

A bag has 3 red and 2 blue marbles. Draw two **without putting the first back**. What's P(both red)?

Draw it as a tree. The first branch: red with 3/5. Now the bag has changed (2 red, 2 blue), so the second branch, *given* the first was red, is 2/4. Multiply along a path: 3/5 × 2/4 = 6/20 = 0.3. That's the multiplication rule with a picture.

To get P(second is red) you add up **every path** that ends in red: (red, red) + (blue, red) = 3/5 × 2/4 + 2/5 × 3/4 = 0.6. Same as the first draw, which surprises most people.

```predict
from fractions import Fraction as F
rr = F(3, 5) * F(2, 4)
br = F(2, 5) * F(3, 4)
print(rr)
print(br)
print(rr + br)
```

## Monty Hall: let the computer settle the argument

A game show has three doors: a car behind one, goats behind two. You pick a door. The host, **who knows where the car is**, opens one of the other doors to show a goat, then offers you a swap. Should you switch?

Almost everyone says "two doors left, so it's 50/50". Professional mathematicians wrote angry letters saying so in 1990. They were wrong: switching wins **2/3** of the time. Your first pick is right 1/3 of the time. The other 2/3, the car is behind one of the two doors you didn't pick, and the host is *forced* to open the other one, so switching takes you straight to the car.

When intuition fights, simulate. Play by hand first, then a few hundred games each way.

```viz

height: 400
Pick a door, then press **Stay** or **Switch**. Then use the **Play 100** buttons. Click a door to see why its chance doesn't change.
```

```exercise
---starter

---solution
def monty_hall(switch, games, seed=0):
    rng = np.random.default_rng(seed)
    wins = 0
    for _ in range(games):
        car = rng.integers(0, 3)
        pick = rng.integers(0, 3)
        opened = [d for d in range(3) if d != pick and d != car][0]
        if switch:
            pick = [d for d in range(3) if d != pick and d != opened][0]
        wins += pick == car
    return wins / games
---tests
s = monty_hall(True, 20000)
k = monty_hall(False, 20000)
assert abs(s - 2 / 3) < 0.02, f"Switching should win about 2/3, got {s:.3f}"
assert abs(k - 1 / 3) < 0.02, f"Staying should win about 1/3, got {k:.3f}"
---hint
The host's door: `[d for d in range(3) if d != pick and d != car][0]`.
---hint
After switching, your new door is the one that's neither your old pick nor the opened door.
```

## Real-world project: "customers who bought this also bought…"

Every online shop shows "people who buy X also buy Y". Under the hood that's conditional probability on shopping baskets, a technique called **association rules**.

```project
title: Basket analysis for a corner shop
client: A corner shop that wants to know what to put next to what
skills: conditional probability, independence, numpy boolean arrays, ranking
---brief
The shop gives you its till receipts: each basket is a set of items. For a rule "X → Y" compute three numbers: **support** P(X and Y) (how common the pair is), **confidence** P(Y | X) (of baskets with X, how many have Y), and **lift** P(Y | X) / P(Y). Lift is the independence test in disguise: lift ≈ 1 means X tells you nothing about Y; lift 2 means X doubles the chance of Y. Recommend the rules with the highest lift that aren't too rare.
---why
This is the classic "market basket analysis" used by supermarkets for shelf layout, by Amazon-style recommenders, by streaming apps ("viewers of this also watched"), and in fraud detection (which events happen together more than chance). Confidence alone misleads: milk is in most baskets, so "anything → milk" has high confidence but lift near 1.
---milestones
- Turn a list of baskets into one boolean array per item
- Compute support, confidence and lift for one rule
- Show that a very popular item gives high confidence but lift near 1
- Rank all item pairs by lift, keeping only those with support ≥ 5%
- Write two shelf recommendations for the shop owner in plain words
---stretch
- Three-item rules: {bread, butter} → jam
- Shuffle one item's column at random and check its lifts fall to about 1 (a built-in sanity test)
- Use pandas: `pd.DataFrame` of booleans, then `df.mean()` gives every support at once
```

```exercise
title: rule_stats
kind: write
---prompt
Write `rule_stats(baskets, x, y)` returning a tuple `(support, confidence, lift)` for the rule x → y. `baskets` is a list of sets. Support = fraction of baskets with both; confidence = P(y | x); lift = confidence / P(y).
---starter
def rule_stats(baskets, x, y):
    pass
---solution
def rule_stats(baskets, x, y):
    has_x = np.array([x in b for b in baskets])
    has_y = np.array([y in b for b in baskets])
    support = float((has_x & has_y).mean())
    confidence = float((has_x & has_y).sum() / has_x.sum())
    lift = confidence / float(has_y.mean())
    return support, confidence, lift
---tests
baskets = [{"bread", "butter", "milk"}, {"bread", "butter"}, {"milk"}, {"bread", "milk"},
           {"butter", "bread", "jam"}, {"milk", "eggs"}, {"milk"}, {"bread", "butter", "milk"}]
s, c, l = rule_stats(baskets, "butter", "bread")
assert abs(s - 0.5) < 1e-12, f"4 of 8 baskets have butter and bread: support 0.5, got {s}"
assert abs(c - 1.0) < 1e-12, "Every butter basket has bread: confidence 1.0"
assert abs(l - 1.6) < 1e-12, f"P(bread) = 5/8, so lift = 1 / 0.625 = 1.6, got {l}"
s2, c2, l2 = rule_stats(baskets, "bread", "milk")
assert abs(c2 - 0.6) < 1e-12 and l2 < 1, "Milk is everywhere: 'bread -> milk' looks confident (0.6) but its lift is below 1"
---hint
Build one boolean array per item with a list comprehension: `np.array([x in b for b in baskets])`.
```

```exercise
title: best_pairs
kind: write
---prompt
Write `best_pairs(baskets, min_support=0.05)`: look at every ordered pair of different items (x, y), keep those with support ≥ `min_support`, and return a list of `(lift, x, y)` sorted from highest lift to lowest. `rule_stats` is provided.
---setup

    has_y = np.array([y in b for b in baskets])

    confidence = float((has_x & has_y).sum() / has_x.sum())

---starter

---solution
def best_pairs(baskets, min_support=0.05):
    items = sorted(set().union(*baskets))
    out = []
    for x in items:
        for y in items:
            if x != y:
                s, c, l = rule_stats(baskets, x, y)
                if s >= min_support:
                    out.append((l, x, y))
    out.sort(reverse=True)
    return out
---tests

    b = set()
    if rng.random() < 0.7: b.add("milk")
    if rng.random() < 0.3:

        if rng.random() < 0.8: b.add("dip")
    elif rng.random() < 0.05: b.add("dip")
    if rng.random() < 0.4: b.add("bread")
    baskets.append(b or {"milk"})

assert top and {top[0][1], top[0][2]} == {"chips", "dip"}, f"chips and dip go together far more than chance; top rule was {top[:1]}"
assert top[0][0] > 2, "their lift should be well above 2"

```

## Rebuild it and explain it

```exercise
title: conditional
kind: rebuild
---prompt
From memory: write `given(a, b)` returning P(a | b) for boolean arrays, and `independent(a, b, tol=0.02)` returning whether P(a | b) is within `tol` of P(a).
---starter
def given(a, b):
    pass

def independent(a, b, tol=0.02):
    pass
---solution
def given(a, b):
    return float((a & b).sum() / b.sum())

def independent(a, b, tol=0.02):
    return abs(given(a, b) - float(a.mean())) < tol
---tests
rng = np.random.default_rng(11)
rain = rng.random(50000) < 0.3
umbrella = np.where(rain, rng.random(50000) < 0.9, rng.random(50000) < 0.15)
coin = rng.random(50000) < 0.5
assert abs(given(umbrella, rain) - 0.9) < 0.01, "P(umbrella | rain) should be about 0.9"
assert not independent(umbrella, rain), "umbrellas depend on rain"
assert independent(coin, rain), "a coin flip doesn't care about the weather"
---hint
Conditional = count of both / count of the condition. Independent = conditioning didn't move the number.
```

```recall
Q: Explain P(A | B) to a friend without a formula, and say how you'd check whether A and B are independent.
A: Throw away everyone who isn't B, then ask what fraction of the people left are A. It's counting inside a smaller world. A and B are independent if that fraction is the same as the fraction of A in the whole crowd: learning B didn't change anything. Equivalently P(A and B) = P(A) × P(B). If they're not independent you must use P(A and B) = P(B) × P(A | B).
```
