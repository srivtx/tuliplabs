## The best line through a cloud

Bigger apartments cost more rent, roughly. "Roughly" is the interesting part: the points don't sit on a line. So which line is **best**? The classic answer: the line that makes the **squared** vertical misses as small as possible in total. In the simulation those squares are real squares. Shrink them.

```quiz
Why does one far-away outlier move the least-squares line so much?
- Outliers have more weight in the formula by design
* Its miss gets squared, so a miss 5 times bigger counts 25 times as much, and the line tilts to reduce it
- The line has to pass through every point
- It doesn't; least squares ignores outliers
> Squaring is what makes the maths neat (one exact best line), and also what makes it sensitive: a single big residual can dominate the total. Always plot your data before trusting a fitted line.
```

## Covariance and correlation

Do two variables rise together? Look at each point's distance from the averages: (x − x̄) and (y − ȳ). When both are above average, or both below, their product is positive. The average of those products is the **covariance**. Its size depends on the units (cm vs m changes it), so we divide by both standard deviations to get the **correlation** r, which is always between −1 and 1:

- r = 1: a perfect rising line; r = −1: a perfect falling line;
- r = 0: no *straight-line* relationship (there could still be a curve!).

```predict
x = np.array([1, 2, 3, 4, 5], float)
print(np.corrcoef(x, 2 * x + 1)[0, 1])
print(np.corrcoef(x, -x)[0, 1])
print(round(np.corrcoef(x, (x - 3) ** 2)[0, 1], 6))
```

The last one is a perfect relationship (a parabola) with correlation 0. Correlation only sees straight lines.

```exercise

---prompt
Write `correlation(x, y)` from the definition: the sum of `(x - mean_x) * (y - mean_y)` divided by `sqrt(sum((x - mean_x)**2) * sum((y - mean_y)**2))`. Don't use `np.corrcoef` (the tests compare against it).
---starter

    return 0.0
---solution
def correlation(x, y):
    x, y = np.asarray(x, float), np.asarray(y, float)
    dx, dy = x - x.mean(), y - y.mean()
    return (dx * dy).sum() / np.sqrt((dx ** 2).sum() * (dy ** 2).sum())
---tests
rng = np.random.default_rng(0)
a, b = rng.normal(size=200), rng.normal(size=200)
c = a + 0.5 * b
assert abs(correlation(a, c) - np.corrcoef(a, c)[0, 1]) < 1e-12, "matches numpy"
assert abs(correlation([1, 2, 3], [30, 20, 10]) + 1) < 1e-12, "a perfect falling line: -1"
assert abs(correlation(a, 100 * c + 7) - correlation(a, c)) < 1e-12, "changing units doesn't change the correlation"
---hint
Centre both arrays first (`dx = x - x.mean()`), then it's one sum on top and a square root of two sums underneath.
```

## Correlation is not causation

Ice-cream sales and drownings are strongly correlated. Ice cream doesn't cause drowning: **hot weather** drives both. A hidden variable that moves both is a **confounder**. Others: children's shoe size correlates with reading skill (age), hospitals correlate with deaths (sick people go there). To show causation you need an experiment (randomise who gets the treatment, chapter 9) or very careful reasoning about every confounder.

```quiz
A study finds that people who drink more coffee live longer. What's the most careful conclusion?
- Coffee makes you live longer
- Living longer makes you drink coffee
* Coffee drinking and longevity are associated; something else (income, health, habits) could drive both, so this alone doesn't show coffee causes it
- The study must be wrong
> Observational data shows association. Healthier, wealthier people might both drink more coffee and live longer. Only a randomised experiment (or strong causal reasoning) separates cause from confounding.
```

## The least-squares line

For a line y = a + b·x, minimising the total squared residual Σ (yᵢ − a − b·xᵢ)² with calculus gives a beautiful answer:

    b = Σ (x − x̄)(y − ȳ) / Σ (x − x̄)²        a = ȳ − b·x̄

So the slope is "how x and y move together" divided by "how much x moves", and the line always passes through the point of averages (x̄, ȳ).

```parsons

---lines

    a = y.mean() - b * x.mean()
    return a, b

x = np.array([0.0, 1, 2, 3])

assert abs(a - 1) < 1e-12 and abs(b - 2) < 1e-12, "points exactly on y = 1 + 2x give back a = 1, b = 2"
```

## Residuals and R²

After fitting, look at the **residuals** (actual − predicted). They should look like shapeless noise. A curve or a funnel in the residuals means the straight-line model is missing something.

**R²** says what fraction of the variation in y the line explains:

    R² = 1 − Σ residual² / Σ (y − ȳ)²

R² = 1 is a perfect fit; R² = 0 means the line does no better than predicting ȳ for everyone. For a single straight line, R² is exactly r².

```exercise
title: r_squared_bug
kind: bug
---prompt
`r_squared(y, predicted)` gives values above 1 for decent fits. Fix the formula.
---starter
def r_squared(y, predicted):
    y, predicted = np.asarray(y, float), np.asarray(predicted, float)
    ss_res = ((y - predicted) ** 2).sum()
    ss_tot = ((y - y.mean()) ** 2).sum()
    return 1 + ss_res / ss_tot
---solution
def r_squared(y, predicted):
    y, predicted = np.asarray(y, float), np.asarray(predicted, float)
    ss_res = ((y - predicted) ** 2).sum()
    ss_tot = ((y - y.mean()) ** 2).sum()
    return 1 - ss_res / ss_tot
---tests
y = np.array([1.0, 2, 3, 4])
assert r_squared(y, y) == 1, "a perfect prediction explains everything"
assert abs(r_squared(y, np.full(4, y.mean()))) < 1e-12, "predicting the average for everyone explains nothing: R² = 0"
assert 0 < r_squared(y, np.array([1.2, 1.9, 3.1, 3.8])) < 1, "a decent fit is between 0 and 1"
---hint
R² is the fraction of variation explained: one **minus** the fraction left over.
```

## More than one input

Rent depends on size **and** distance to the centre. With several inputs, the model is y = a + b₁x₁ + b₂x₂ + …, and the same least-squares idea applies. Put the inputs as columns of a matrix (with a column of 1s for the intercept) and let `np.linalg.lstsq` find the coefficients.

```run
title: Two inputs at once
rng = np.random.default_rng(2)
size = rng.uniform(30, 120, 200)
dist = rng.uniform(1, 15, 200)
rent = 300 + 12 * size - 40 * dist + rng.normal(0, 80, 200)
X = np.column_stack([np.ones(200), size, dist])
coef, *_ = np.linalg.lstsq(X, rent, rcond=None)
print("intercept, per m², per km:", coef.round(1))
```

## Real-world project: an apartment rent estimator

```project
title: A fair-rent estimator for a tenants' association
client: A tenants' association that wants to spot overpriced listings
skills: least squares, several inputs, R², train/test split, residuals
---brief
The association has listings with size (m²), distance to the centre (km) and rent. Fit a model on 80% of them, check it on the other 20% it has never seen, and flag listings whose rent is more than two typical errors above what the model predicts. Report how much each extra m² and each extra km is worth.
---why
This is the backbone of pricing models everywhere: house-price estimates, salary benchmarks, insurance premiums and ad bidding all start as a regression. Testing on held-out data is the habit that separates a model that *describes* the past from one that *predicts*, and residuals are how you find the listings, transactions or patients that don't fit the pattern.
---milestones
- Simulate (or load) listings and plot rent against each input
- Split into training and test sets with a fixed seed
- Write `fit(X, y)` and `predict(coef, X)` with `np.linalg.lstsq`
- Report R² on the training and the test data, and the typical error (RMSE)
- Flag listings with a residual above 2 × RMSE and look at them
---stretch
- Add a "has balcony" yes/no input as a 0/1 column
- Try rent per m² as the target instead, and compare
- Plot residuals against distance: is a straight line enough, or is there a curve?
```

```exercise
title: fit_predict
kind: write
---prompt
Write `fit(X, y)` returning the least-squares coefficients for inputs `X` (an `(n, k)` array **without** an intercept column: add a column of ones yourself as the first column) and `predict(coef, X)` returning predictions for new rows (again adding the ones column).
---starter
def fit(X, y):

def predict(coef, X):
    return np.zeros(len(X))
---solution
def fit(X, y):
    A = np.column_stack([np.ones(len(X)), X])
    coef, *_ = np.linalg.lstsq(A, y, rcond=None)
    return coef

def predict(coef, X):
    return np.column_stack([np.ones(len(X)), X]) @ coef
---tests
rng = np.random.default_rng(5)
X = np.column_stack([rng.uniform(30, 120, 300), rng.uniform(1, 15, 300)])
y = 300 + 12 * X[:, 0] - 40 * X[:, 1] + rng.normal(0, 50, 300)
train, test = slice(0, 240), slice(240, 300)
coef = fit(X[train], y[train])
assert np.allclose(coef, [300, 12, -40], atol=[40, 0.5, 2]), f"recovers about 300, 12 per m², -40 per km; got {coef.round(1)}"
pred = predict(coef, X[test])
rmse = np.sqrt(((y[test] - pred) ** 2).mean())
assert rmse < 70, f"on unseen listings the typical error is close to the noise level, 50; got {rmse:.1f}"
---hint
`np.column_stack([np.ones(len(X)), X])` builds the design matrix; `np.linalg.lstsq(A, y, rcond=None)[0]` solves it.
```

## Rebuild it and explain it

```exercise
title: line_and_r2
kind: rebuild
---prompt
From memory: write `line_and_r2(x, y)` returning `(a, b, r2)` for the least-squares line and its R².
---starter
def line_and_r2(x, y):
    pass
---solution
def line_and_r2(x, y):
    x, y = np.asarray(x, float), np.asarray(y, float)
    dx, dy = x - x.mean(), y - y.mean()
    b = (dx * dy).sum() / (dx ** 2).sum()
    a = y.mean() - b * x.mean()
    res = y - (a + b * x)
    return a, b, 1 - (res ** 2).sum() / (dy ** 2).sum()
---tests
a, b, r2 = line_and_r2([1, 2, 3, 4], [3, 5, 7, 9])
assert abs(a - 1) < 1e-12 and abs(b - 2) < 1e-12 and abs(r2 - 1) < 1e-12, "y = 1 + 2x exactly: R² = 1"
x = np.arange(20.0); y = x + np.where(x % 2, 3.0, -3.0)
assert abs(line_and_r2(x, y)[2] - np.corrcoef(x, y)[0, 1] ** 2) < 1e-9, "for one input, R² equals r²"
---hint
Slope from the centred sums, intercept from the averages, then 1 minus leftover over total.
```

```recall
Q: Explain what "least squares" means and name two ways a regression line can mislead you.
A: Among all straight lines, least squares picks the one with the smallest total of squared vertical misses: each point's error is squared and the squares are added. It can mislead when (1) an outlier, because squaring makes big misses dominate and drags the line toward one strange point, and (2) when you read the slope as cause and effect: a confounder can make two things move together without one causing the other. It also only captures straight-line patterns, so always plot the data and the residuals.
```
