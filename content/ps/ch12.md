## A walk that remembers only now

A **Markov chain** is a random process where the next state depends only on the current one, not on the whole history. Tomorrow's weather given today's. A shopper's next aisle given this one. Your next word given the last.

That short memory is surprisingly powerful. Let it run long enough and it often settles into a fixed long-run pattern. And you can *design* a chain whose long-run pattern is whatever distribution you want. That's **MCMC**, Markov chain Monte Carlo, the engine behind modern Bayesian statistics.

```quiz
With step size 1 the walker stayed on the left island. Why?
- The right island has less probability
* Every small step into the valley is a big drop in height, so it's nearly always refused; small steps can't reach the other island
- The walker is programmed to stay where it started
- Step size 1 means it never moves
> The chain is still correct in theory, it would get there eventually, but "eventually" could be millions of steps. Real samplers fail like this all the time, which is why people run several chains from different starting points and check they agree.
```

## Transition matrices

Put the chances in a table: row = today, column = tomorrow. Each row adds to 1. If `d` is today's distribution (a row vector), tomorrow's is `d @ P`.

```predict
P = np.array([[0.9, 0.1],     # sunny -> sunny, rainy
              [0.5, 0.5]])    # rainy -> sunny, rainy
d = np.array([0.0, 1.0])      # it's raining today
for day in range(1, 4):
    d = d @ P
    print(day, d.round(3))
```

The chain is forgetting that it started on a rainy day. Where does it end up?

```exercise

---starter

---solution
def after_n_steps(P, d, n):
    d = np.asarray(d, float)
    for _ in range(n):
        d = d @ P
    return d
---tests
P = np.array([[0.9, 0.1], [0.5, 0.5]])
assert np.allclose(after_n_steps(P, [0, 1], 1), [0.5, 0.5]), "one rainy day later: 50/50"
assert np.allclose(after_n_steps(P, [0, 1], 0), [0, 1]), "zero steps changes nothing"
assert abs(after_n_steps(P, [1, 0], 200).sum() - 1) < 1e-12, "it stays a distribution"
---hint
`d = d @ P` inside a `for` loop that runs `n` times.
```

## Where it settles

Most chains forget their start and settle into a **stationary distribution** π with π @ P = π. For the weather chain, it's sunny 5/6 of the time in the long run, whatever today is. One way to find π: start anywhere and keep stepping until it stops changing (**power iteration**).

```exercise
title: stationary
kind: write
---prompt
Write `stationary(P, tol=1e-12)` that starts from the uniform distribution and repeats `d = d @ P` until the biggest change in one step is below `tol`. Return `d`.
---starter
def stationary(P, tol=1e-12):
    n = len(P)
    return np.ones(n) / n
---solution
def stationary(P, tol=1e-12):
    d = np.ones(len(P)) / len(P)
    while True:
        new = d @ P
        if np.abs(new - d).max() < tol:
            return new
        d = new
---tests
P = np.array([[0.9, 0.1], [0.5, 0.5]])
assert np.allclose(stationary(P), [5 / 6, 1 / 6]), "sunny 5/6 of the time"
Q = np.array([[0, 1, 0], [0, 0.5, 0.5], [0.5, 0, 0.5]])
pi = stationary(Q)
assert np.allclose(pi @ Q, pi) and abs(pi.sum() - 1) < 1e-9, "pi @ P == pi"
---hint
Keep `new = d @ P` in a loop; stop when `np.abs(new - d).max() < tol`.
```

## PageRank: a surfer's chain

Early Google ranked pages with a Markov chain. Imagine a surfer who, on each page, clicks a random link with probability 0.85, or gets bored and jumps to a random page with probability 0.15. The stationary distribution of that walk is the **PageRank**: pages that lots of important pages link to get visited a lot.

The random jump matters: without it the surfer could get trapped on a page with no links out, and the chain would never settle.

## The Metropolis rule

Now flip the problem. We have a shape p(x) we can *evaluate* (say prior × likelihood from chapter 11) and we want samples from it. Metropolis builds a chain whose stationary distribution is exactly p:

1. from the current x, propose x′ = x + a small random step;
2. if p(x′) ≥ p(x), move there;
3. otherwise move there with probability p(x′) / p(x), else stay at x (and record x again).

You only ever need the **ratio** p(x′) / p(x), so the unknown normalising total cancels out. That's why it's so useful.

```parsons
title: One Metropolis step
---lines
def metropolis_step(x, logp, scale, rng):
    proposal = x + rng.normal(0, scale)
    log_ratio = logp(proposal) - logp(x)
    if np.log(rng.random()) < log_ratio:
        return proposal
    return x
?? if log_ratio > 0:
---tests
rng = np.random.default_rng(0)
logp = lambda x: -0.5 * x * x
xs = [0.0]
for _ in range(4000):
    xs.append(metropolis_step(xs[-1], logp, 1.0, rng))
assert abs(np.mean(xs)) < 0.2 and 0.8 < np.std(xs) < 1.2, "samples a standard normal"
```

```quiz
A sampler accepts 99% of its proposals. What's the likely problem?
- Nothing, a high acceptance rate is ideal
* The steps are tiny, so it barely moves and explores very slowly
- The steps are huge
- The target distribution is wrong
> Tiny steps are almost always accepted because the height barely changes, but the walker crawls. Huge steps are mostly rejected. A common rule of thumb for one-dimensional targets is to aim for roughly 40–50% acceptance, and lower in many dimensions.
```

## Real-world project: rank a team wiki

```project
title: Which pages matter in our team wiki?
client: An engineering team whose wiki has 300 pages and no one knows where to start
skills: transition matrices, stationary distributions, damping, power iteration
---brief
Turn the wiki into a graph (page → the pages it links to), build the random-surfer transition matrix with damping 0.85, and compute PageRank by power iteration. Publish a "start here" list of the top 10 pages, and a list of orphan pages nothing links to.
---why
PageRank-style chains rank web pages, papers by citations, people in social networks and even proteins in interaction networks. Building the matrix teaches you the classic traps: pages with no outgoing links (dangling nodes), disconnected pieces, and why the random jump makes the answer exist and be unique.
---milestones

- Build the transition matrix, sending dangling pages' surfers to a random page
- Mix in the 15% random jump and check every row sums to 1
- Find the stationary distribution by power iteration
- Rank the pages and sanity-check: is the most-linked page near the top?
---stretch
- Check your answer by simulating one surfer for 100,000 clicks and counting visits
- Personalised PageRank: make the random jump land only on the onboarding pages
```

```exercise
title: pagerank
kind: write
---prompt
Write `pagerank(links, damping=0.85)` where `links[i]` is a list of the pages page `i` links to (pages are numbered `0..n-1`). Build `P`: from a page with k links, each link gets `damping / k`, and every page gets an extra `(1 - damping) / n`. A page with **no** links sends its surfer to a uniformly random page (`1 / n` each). Return the stationary distribution (power iteration until the change is below 1e-12).
---starter
def pagerank(links, damping=0.85):
    n = len(links)
    return np.ones(n) / n
---solution
def pagerank(links, damping=0.85):
    n = len(links)
    P = np.zeros((n, n))
    for i, out in enumerate(links):
        if out:
            for j in out:
                P[i, j] += damping / len(out)
            P[i] += (1 - damping) / n
        else:
            P[i] = 1 / n
    d = np.ones(n) / n
    while True:
        new = d @ P
        if np.abs(new - d).max() < 1e-12:
            return new
        d = new
---tests
pr = pagerank([[1], [2], [0]])
assert np.allclose(pr, [1 / 3] * 3), "a ring: everyone equal"
pr = pagerank([[3], [3], [3], [0]])
assert pr.argmax() == 3 and pr[0] > pr[1], "the page everyone links to wins; the page it links to comes next"
pr = pagerank([[1], []])
assert abs(pr.sum() - 1) < 1e-9 and pr[1] > pr[0], "a dangling page doesn't leak probability"
---hint
Build P row by row. A row with links gets `damping / len(out)` per link plus `(1 - damping) / n` everywhere; a row with no links is all `1 / n`. Then reuse your power iteration.
```

## Rebuild it and explain it

```exercise
title: metropolis
kind: rebuild
---prompt
From memory: write `metropolis(logp, x0, steps, scale, seed=0)` returning `(samples, acceptance_rate)` for a 1-D random-walk Metropolis sampler with normal proposals.
---starter
def metropolis(logp, x0, steps, scale, seed=0):
    pass
---solution
def metropolis(logp, x0, steps, scale, seed=0):
    rng = np.random.default_rng(seed)
    x, out, acc = x0, [], 0
    for _ in range(steps):
        prop = x + rng.normal(0, scale)
        if np.log(rng.random()) < logp(prop) - logp(x):
            x, acc = prop, acc + 1
        out.append(x)
    return np.array(out), acc / steps
---tests
s, rate = metropolis(lambda x: -abs(x), 0.0, 20000, 1.5)
assert abs(s[2000:].mean()) < 0.15, "a symmetric target centred on 0"
assert 0.2 < rate < 0.9, "a sensible acceptance rate"
_, tiny = metropolis(lambda x: -abs(x), 0.0, 5000, 0.01)
assert tiny > 0.95, "tiny steps are almost always accepted"
---hint
Propose with `rng.normal(0, scale)`, accept if `log(u) < logp(prop) - logp(x)`, always record the current x.
```

```recall
Q: Explain what a stationary distribution is and how the Metropolis rule uses it to draw samples from a shape you can't sample directly.
A: A Markov chain hops between states using only the current state. Many chains settle into a long-run pattern where the fraction of time in each state stops changing: that's the stationary distribution, π @ P = π. Metropolis designs a chain whose stationary distribution is the target: propose a nearby point, always accept if it's higher, accept with probability new/old if it's lower. Only ratios of heights are needed, so unknown normalising constants cancel. Run it long enough and the time spent in each region matches the target; but if steps are too small or too big it explores slowly, so you check acceptance rates and run several chains.
```
