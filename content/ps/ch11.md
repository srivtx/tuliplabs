## Beliefs that move

In chapter 3, Bayes' rule updated the probability of **one** yes/no hypothesis (is the patient ill?). Now the unknown is a **number**: the chance p that a coin lands heads, the click rate of an ad, the defect rate of a factory. Instead of one probability we keep a whole row of them, one for every possible value of p. That row is a **belief**.

Two people watch the same coin. Ada has no opinion. Bo is sure the coin favours tails. Flip it and watch.


```quiz
Bo started out very sure the coin favoured tails. Why did his belief still end up near Ada's?
- Bayes' rule ignores the prior
* Each flip multiplies in more evidence; after many flips the likelihood is so sharp that it outweighs any reasonable prior
- Bo changed his mind on purpose
- The coin changed its bias
> The prior counts like a fixed number of imaginary flips. Real flips keep piling up, so eventually they dominate. Only a prior that says "impossible" (a bar at exactly zero) can never be overturned, which is why careful Bayesians avoid zeros.
```

## The grid recipe

Pick a grid of possible values for p. For each one:

1. **prior**: how believable it was before the data;
2. **likelihood**: how probable the data is if p were that value. For h heads and t tails it's p^h · (1 − p)^t;
3. **posterior** = prior × likelihood, then divide by the total so it adds to 1.

That's all of Bayesian inference. Everything else is about doing step 3 faster.

```predict
grid = np.array([0.25, 0.5, 0.75])
prior = np.array([1, 1, 1]) / 3
like = grid ** 2 * (1 - grid) ** 0      # we saw 2 heads, 0 tails
post = prior * like
post = post / post.sum()
print(post.round(3))
```

After two heads, 0.75 is nine times as believable as 0.25, because 0.75² / 0.25² = 9.

```exercise
title: grid_posterior
kind: write
---prompt
Write `grid_posterior(grid, prior, heads, tails)` returning the normalised posterior over `grid`. Work in **logs** (`np.log`) and subtract the maximum before `np.exp`, so 1000 flips don't underflow to zero.
---starter
def grid_posterior(grid, prior, heads, tails):
    return prior
---solution
def grid_posterior(grid, prior, heads, tails):
    grid, prior = np.asarray(grid, float), np.asarray(prior, float)
    logp = np.log(prior) + heads * np.log(grid) + tails * np.log(1 - grid)
    w = np.exp(logp - logp.max())
    return w / w.sum()
---tests
g = np.array([0.25, 0.5, 0.75])
p = grid_posterior(g, np.ones(3) / 3, 2, 0)
assert np.allclose(p, np.array([1, 4, 9]) / 14), "2 heads on a flat prior: 1 : 4 : 9"
g = np.linspace(0.01, 0.99, 99)
p = grid_posterior(g, np.ones(99), 700, 300)
assert abs(p.sum() - 1) < 1e-12 and not np.isnan(p).any(), "1000 flips still gives a proper distribution (no underflow)"
assert abs(g[p.argmax()] - 0.7) < 1e-9, "the peak is at 700 / 1000"
---hint
`logp = np.log(prior) + heads * np.log(grid) + tails * np.log(1 - grid)`, then `w = np.exp(logp - logp.max())` and divide by its sum.
```

## The Beta shortcut

For yes/no data there's a famous shortcut. If the prior has the shape of a **Beta(a, b)** distribution, the posterior after h heads and t tails is simply **Beta(a + h, b + t)**. You can read a and b as "imaginary heads and tails I'm pretending I've already seen":

- Beta(1, 1) is flat (Ada);
- Beta(4, 12) is like having seen 4 heads and 12 tails (a Bo-ish prior, mean 0.25);
- the posterior mean is (a + h) / (a + b + h + t).

```parsons
title: Update a Beta belief
---lines
def beta_update(a, b, flips):
    for f in flips:
        if f == "H":
            a += 1
        else:
            b += 1
    return a, b, a / (a + b)
?? return a, b, a / b
---tests
assert beta_update(1, 1, "HHT") == (3, 2, 0.6), "flat prior plus 2 heads and 1 tail: Beta(3, 2), mean 0.6"
```

## Credible intervals

A **90% credible interval** is a range that holds 90% of the posterior: "given my prior and the data, I'm 90% sure p is in here". That is the sentence people *wish* a confidence interval meant. A confidence interval (chapter 8) is a statement about the method: 90% of intervals built this way catch the truth. With a flat prior and lots of data the two usually come out almost the same; with little data or a strong prior they can differ a lot.

```exercise
title: credible_interval
kind: write
---prompt
Write `credible_interval(grid, post, level=0.9)` returning `(lo, hi)`: the grid values where the running total of `post` first reaches `(1 - level) / 2` and `1 - (1 - level) / 2`. Use `np.cumsum` and `np.searchsorted`.
---starter
def credible_interval(grid, post, level=0.9):
    return grid[0], grid[-1]
---solution
def credible_interval(grid, post, level=0.9):
    c = np.cumsum(post)
    tail = (1 - level) / 2
    return grid[np.searchsorted(c, tail)], grid[np.searchsorted(c, 1 - tail)]
---tests
g = np.linspace(0.001, 0.999, 999)
w = g ** 69 * (1 - g) ** 29
post = w / w.sum()
lo, hi = credible_interval(g, post)
assert 0.61 < lo < 0.64 and 0.76 < hi < 0.78, f"70 heads, 30 tails on a flat prior: about (0.62, 0.77); got ({lo:.3f}, {hi:.3f})"
lo2, hi2 = credible_interval(g, post, 0.5)
assert lo < lo2 < hi2 < hi, "a 50% interval sits inside the 90% one"
---hint
`c = np.cumsum(post)`; `np.searchsorted(c, x)` is the first index where the running total reaches x.
```

```quiz
After 7 heads in 10 flips with a flat prior, the 90% credible interval for p is about (0.45, 0.86). Which statement is correct?
* Given the flat prior and these flips, there's a 90% probability that p is between 0.45 and 0.86
- 90% of future flips will be between 0.45 and 0.86
- p is 0.7 for sure; the interval is just rounding
- If you repeated the experiment, 90% of the time you'd get 7 heads
> A credible interval is a direct probability statement about the unknown, conditional on the prior. That's its big advantage, and its cost: someone with a different prior would report a different interval.
```

## Real-world project: ranking with few reviews

```project
title: Fair rankings for a small recipe site
client: A recipe site where some recipes have 2 reviews and others have 2,000
skills: Beta priors, posterior means, credible intervals, shrinkage
---brief
A recipe with one 5-star review shouldn't outrank one with 900 reviews averaging 4.8. Treat each recipe's "share of happy cooks" (4 or 5 stars) as an unknown p with a Beta prior built from the whole site's average, update it with that recipe's reviews, and rank by the lower end of the 90% credible interval. Compare the ranking to sorting by the raw average.
---why
This is how sensible review sites, app stores and leaderboards handle small samples: shrink every item towards the site average, by an amount that depends on how much data it has. The same idea, called partial pooling, is used in sports statistics, hospital comparisons and A/B tests across many small groups.
---milestones
- Simulate 50 recipes with true happiness rates and very different review counts
- Rank by raw share of happy reviews and notice who wins
- Pick a prior Beta(a, b) whose mean is the site average, worth about 20 reviews
- Compute each recipe's posterior mean and 90% credible interval
- Rank by the lower end of the interval and compare the top 5 with the raw ranking
---stretch
- Plot raw average against posterior mean: watch small recipes get pulled to the middle
- Choose the prior's strength from the data instead of guessing 20
- Extend from happy/unhappy to the full 1–5 stars with a Dirichlet prior
```

```exercise
title: bayes_rank
kind: write
---prompt
Write `bayes_rank(happy, total, prior_mean, strength)` for arrays of happy-review counts and review totals. Use the prior Beta(a, b) with `a = prior_mean * strength`, `b = (1 - prior_mean) * strength`, and return the item indices sorted from **best** to worst by posterior mean.
---starter
def bayes_rank(happy, total, prior_mean, strength):
    return np.arange(len(happy))
---solution
def bayes_rank(happy, total, prior_mean, strength):
    happy, total = np.asarray(happy, float), np.asarray(total, float)
    a, b = prior_mean * strength, (1 - prior_mean) * strength
    mean = (a + happy) / (a + b + total)
    return np.argsort(-mean, kind="stable")
---tests
happy = [1, 860, 45, 0]
total = [1, 900, 50, 3]
r = bayes_rank(happy, total, 0.8, 20)
assert list(r) == [1, 2, 0, 3], f"900 reviews at 96% beats one lucky 5-star review; got {list(r)}"
assert list(bayes_rank(happy, total, 0.8, 0))[0] == 0, "with no prior, the 1-for-1 recipe tops the raw ranking"
---hint
Posterior mean is `(a + happy) / (a + b + total)`; `np.argsort(-mean)` sorts from biggest to smallest.
```

## Rebuild it and explain it

```exercise
title: update_belief
kind: rebuild
---prompt
From memory: write `update_belief(grid, prior, heads, tails)` that returns `(posterior, mean)`: the normalised grid posterior (computed in logs) and its mean.
---starter
def update_belief(grid, prior, heads, tails):
    pass
---solution
def update_belief(grid, prior, heads, tails):
    grid, prior = np.asarray(grid, float), np.asarray(prior, float)
    logp = np.log(prior) + heads * np.log(grid) + tails * np.log(1 - grid)
    w = np.exp(logp - logp.max())
    post = w / w.sum()
    return post, (grid * post).sum()
---tests
g = np.linspace(0.005, 0.995, 199)
post, mean = update_belief(g, np.ones(199), 6, 2)
assert abs(post.sum() - 1) < 1e-12, "it's a distribution"
assert abs(mean - 7 / 10) < 1e-3, "flat prior, 6 heads 2 tails: Beta(7, 3), mean 0.7"
---hint
Log prior plus log likelihood, subtract the max, exponentiate, normalise; the mean is the sum of grid times posterior.
```

```recall
Q: Explain how Bayesian inference updates a belief about an unknown number, and why two people with different priors end up agreeing.
A: Write down a belief about the unknown as a distribution over its possible values (the prior). For each value, compute how likely the observed data would be (the likelihood). Multiply prior by likelihood and rescale to get the posterior: values that explain the data well gain belief. With few data points the prior matters a lot; but each new observation multiplies in more evidence, the likelihood gets sharper, and it eventually swamps any prior that doesn't rule the truth out completely, so people with different reasonable priors converge.
```
