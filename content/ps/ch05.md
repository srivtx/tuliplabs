## Where do averages settle?

Roll a die once and you get anything from 1 to 6. Roll it a thousand times and average: you'll get very close to 3.5, every time, for everyone. That number, the **expected value**, is where averages settle. But *how fast* do they settle? Watch eight people roll at once.

```viz

title: Eight people, rolling forever
goal: Keep 8 or more streams and roll each to **1,000** so you can see how much the spread shrank from n = 10 to n = 1,000.
height: 430
Each ribbon is one person's running average, on a log scale of rolls. Try the **raffle ticket** too: a rare big win makes the averages settle much more slowly.
```

```quiz
You've rolled a fair die 10 times and the average is 4.6, well above 3.5. What happens to your running average over the next 10,000 rolls?
- The next rolls will be low, to make up for the high start
* It drifts toward 3.5, because 10,000 ordinary rolls swamp the first 10
- It stays near 4.6, since you're on a hot streak
- It can't be predicted at all
> Dice have no memory, so nothing "makes up" for the early rolls (believing it does is the gambler's fallacy). The early excess just gets diluted: it's 10 rolls out of 10,010.
```

## Expected value: a weighted average

For a random variable that takes values x with probabilities P(x):

    E[X] = Σ x · P(x)

It's an ordinary average where each value counts in proportion to how often it happens. Picture the probabilities as weights hung on a ruler at their values: E[X] is where the ruler **balances** (the green pivot in the simulation).

```predict
vals = [1, 2, 3, 4, 5, 6]
probs = [1 / 6] * 6
print(sum(v * p for v, p in zip(vals, probs)))
print(sum(v * p for v, p in zip([0, 20], [0.9, 0.1])))
```

```exercise
---hint
`sum(v * p for v, p in zip(vals, probs))`, after checking `sum(probs)`.
```

## Linearity: the shortcut that always works

Expected values **add**: E[X + Y] = E[X] + E[Y], and E[aX + b] = a·E[X] + b. This holds even when X and Y are **dependent**, which makes it shockingly useful. The expected total of 10 dice is 10 × 3.5 = 35, with no need to work out the distribution of the total.

```quiz
100 people throw their hats in a pile and each takes one back at random. On average, how many get their own hat?
- About 37
- 0.01
* Exactly 1
- 50
> Let Xᵢ be 1 if person i gets their own hat. Each has a 1/100 chance, so E[Xᵢ] = 1/100. The total is the sum of 100 of them, and expectations add even though the Xᵢ depend on each other: 100 × 1/100 = 1. (It's 1 for any number of people.)
```

## Variance: how much it wobbles

Two games can have the same expected value and feel completely different: winning 1 for sure, or winning 0 or 100 at 99% / 1%. **Variance** measures the spread: the expected **squared** distance from the mean,

    Var(X) = E[(X − μ)²] = Σ (x − μ)² · P(x)

and the **standard deviation** σ = √Var is the spread in the original units. Why square? Positive and negative distances would cancel if you just averaged them, and squaring punishes big misses most, which is usually what risk is about.

```exercise
title: variance_bug
kind: bug
---prompt
`variance(vals, probs)` should return Σ (x − μ)² · P(x). It runs but gives 0 for a fair die. Fix it.
---starter
def variance(vals, probs):
    mu = sum(v * p for v, p in zip(vals, probs))
    return sum((v - mu) * p for v, p in zip(vals, probs))
---solution
def variance(vals, probs):
    mu = sum(v * p for v, p in zip(vals, probs))
    return sum((v - mu) ** 2 * p for v, p in zip(vals, probs))
---tests
v = variance([1, 2, 3, 4, 5, 6], [1 / 6] * 6)
assert abs(v - 35 / 12) < 1e-12, f"a fair die's variance is 35/12 ≈ 2.917; got {v}"
assert variance([5], [1.0]) == 0, "something certain doesn't vary"
---hint
The deviations from the mean always average to zero. What does the formula do to each deviation before weighting it?
```

```predict
vals_a, probs_a = [1], [1.0]
vals_b, probs_b = [0, 100], [0.99, 0.01]
for vals, probs in [(vals_a, probs_a), (vals_b, probs_b)]:
    mu = sum(v * p for v, p in zip(vals, probs))
    var = sum((v - mu) ** 2 * p for v, p in zip(vals, probs))
    print(mu, round(var ** 0.5, 2))
```

## The law of large numbers, and its speed limit

**Law of large numbers:** the average of n independent draws gets closer and closer to E[X] as n grows. That's why casinos, insurers and polls work.

But how close? The average of n draws has standard deviation **σ / √n**. The square root is the speed limit: 100× more data shrinks the wobble only 10×. Halving your error costs **four times** the data. You saw this in the funnel.

```run
title: Spread of the average vs n
rng = np.random.default_rng(1)
for n in [10, 100, 1000, 10000]:
    averages = rng.integers(1, 7, size=(2000, n)).mean(axis=1)
    print(f"n = {n:6d}:  spread of averages {averages.std():.4f}   sigma/sqrt(n) = {np.sqrt(35 / 12) / np.sqrt(n):.4f}")
```

```exercise
title: rolls_for_precision
kind: write
---prompt
Write `rolls_for_precision(sigma, target)`: the smallest whole number n such that σ/√n is **at most** `target`. (How many rolls until the average's typical error is that small?) Use `math.ceil` and be careful at exact boundaries.
---starter
import math
def rolls_for_precision(sigma, target):
    return 1
---solution
import math
def rolls_for_precision(sigma, target):
    n = math.ceil((sigma / target) ** 2)
    while sigma / math.sqrt(n) > target:
        n += 1
    while n > 1 and sigma / math.sqrt(n - 1) <= target:
        n -= 1
    return n
---tests
assert rolls_for_precision(2.0, 0.2) == 100, "σ = 2, error 0.2: (2/0.2)² = 100"
assert rolls_for_precision(2.0, 0.1) == 400, "halving the error takes 4× the data"
d = rolls_for_precision((35 / 12) ** 0.5, 0.05)
assert (35 / 12) ** 0.5 / d ** 0.5 <= 0.05 < (35 / 12) ** 0.5 / (d - 1) ** 0.5, f"for a die to ±0.05 you need {d} rolls, and one fewer isn't enough"
---hint
Solve σ/√n ≤ target for n: n ≥ (σ/target)². Round up.
```

## Real-world project: pricing an insurance policy

```project
title: Break-even price for phone insurance
client: A small electronics shop that wants to sell one-year phone insurance
skills: expected value, variance, the law of large numbers, simulation
---brief
Each year a customer's phone is fine (70%), gets a cracked screen costing 120 (25%), or is lost or destroyed costing 800 (5%). Find the **expected payout** per policy: that's the break-even premium. Then work out how much the shop's average payout per customer wobbles when it sells 50 policies versus 5,000, and set a premium with a safety margin of two standard errors so a bad year doesn't sink it.
---why
This is literally how insurance works: expected claims set the base price, and the law of large numbers is the business model, since an insurer with many customers can predict its average payout closely even though no single customer is predictable. Warranties, extended guarantees and even "buy now, pay later" defaults are priced the same way.
---milestones
- Write the loss distribution and compute the expected payout with `expected`
- Compute the standard deviation of one customer's payout
- Write `premium(vals, probs, customers, z)`: expected payout + z standard errors
- Simulate 1,000 years for 50 and for 5,000 customers and count the losing years
- Explain to the shop why a small customer base needs a higher price
---stretch
- Add a deductible (the customer pays the first 50) and see how the price drops
- Model customers who are riskier than average buying more insurance (adverse selection)
- Plot the distribution of yearly profit for both shop sizes
```

```exercise
title: premium
kind: write
---prompt
Write `premium(vals, probs, customers, z=2.0)`: return the expected payout per customer **plus** `z` times the standard error of the average payout across `customers` independent customers (σ/√customers, with σ the standard deviation of one customer's payout).
---starter
def premium(vals, probs, customers, z=2.0):
    return 0.0
---solution
def premium(vals, probs, customers, z=2.0):
    mu = sum(v * p for v, p in zip(vals, probs))
    sigma = sum((v - mu) ** 2 * p for v, p in zip(vals, probs)) ** 0.5
    return mu + z * sigma / customers ** 0.5
---tests
vals, probs = [0, 120, 800], [0.70, 0.25, 0.05]
assert abs(premium(vals, probs, 10**12, 2.0) - 70.0) < 0.01, "with endless customers, the price is just the expected payout, 70"
small, big = premium(vals, probs, 50), premium(vals, probs, 5000)
assert small > big > 70, f"fewer customers means more wobble, so a bigger margin: {small:.2f} vs {big:.2f}"
assert abs(premium(vals, probs, 100, 0) - 70) < 1e-9, "z = 0 means no safety margin"
---hint
Compute μ and σ from the distribution, then `mu + z * sigma / sqrt(customers)`.
---show
rng = np.random.default_rng(0)
vals, probs = np.array([0, 120, 800]), [0.70, 0.25, 0.05]
for n in [50, 5000]:
    price = premium(list(vals), probs, n)
    yearly = rng.choice(vals, size=(1000, n), p=probs).mean(axis=1)
    print(f"{n:5d} customers: price {price:6.2f}, losing years {np.mean(yearly > price):.1%}")
```

## Rebuild it and explain it

```exercise
title: mean_and_sd
kind: rebuild
---prompt
From memory: write `mean_and_sd(vals, probs)` returning `(mu, sigma)` for a discrete distribution.
---starter
def mean_and_sd(vals, probs):
    pass
---solution
def mean_and_sd(vals, probs):
    mu = sum(v * p for v, p in zip(vals, probs))
    var = sum((v - mu) ** 2 * p for v, p in zip(vals, probs))
    return mu, var ** 0.5
---tests
mu, sd = mean_and_sd([0, 1], [0.5, 0.5])
assert (mu, sd) == (0.5, 0.5), "a fair coin: mean 0.5, sd 0.5"
mu, sd = mean_and_sd([2, 4, 6], [0.25, 0.5, 0.25])
assert mu == 4 and abs(sd - 2 ** 0.5) < 1e-12, "mean 4, variance 2"
---hint
Weighted average for μ, weighted average of squared deviations for the variance, then a square root.
```

```recall
Q: A friend says "the law of large numbers means if I've lost 10 coin flips in a row, I'm due a win". Explain what the law really says, and how fast averages settle.
A: The law says the *average* of many independent flips gets close to the expected value, not that later flips compensate for earlier ones. Coins have no memory; the next flip is still 50/50. Early streaks get diluted by the many flips that follow, not corrected. And it's slow: the average's typical error is σ/√n, so 100 times more flips only makes the average 10 times more precise.
```

