Most Node backends are built on **Express**, and Express is small enough to write yourself in an afternoon. That's what this project is. You start with Node's bare `http` module, feel what's missing, and add it one piece at a time until you have the same framework: routes, helpers, params, middleware, body parsing, error handling and routers.

The terminal is a client. **client.js** starts your server, then sends each line you type as a real HTTP request: `GET /notes`, or `POST /notes {"text": "milk"}`. Add `-i` to see the response headers. Your framework goes in **express.js**, and **app.js** is a small notes API that uses it exactly the way it would use the real Express.

title: Answer a request
files: app.js
---brief
Run the project and type `GET /` in the terminal. Nothing comes back: the server got the request, but nobody answered it.

`http.createServer(handler)` calls `handler(req, res)` for every request. `req` says what was asked: **`req.method`** (`GET`) and **`req.url`** (`/health`). `res` is how you answer: set **`res.statusCode`**, set headers with **`res.setHeader(name, value)`**, then send the body and finish with **`res.end(text)`**.

Make the server answer:

| Request | Status | Body |
|---|---|---|
| `GET /` | 200 | `hello from trellis` |
| `GET /health` | 200 | `ok` |
| anything else | 404 | `Not found` |

Send `Content-Type: text/plain` with every answer, so the client knows what it got.
---why
Every web framework in every language sits on exactly this: one function that receives every request and must answer each one, exactly once. Express, Fastify, Django and Rails all start here. A request that never gets `res.end()` hangs until the client gives up, which is one of the most common bugs in real servers. You just saw it from the client's side.

  200 OK                           res.setHeader(...)

// client.js: the terminal. It starts your server, then turns each line you type into an HTTP request
// and sends it with fetch(), the way a browser, curl or another service would. You don't need to change it.
//
//   GET /notes                         a request
//   POST /notes {"text": "milk"}       with a JSON body
//   GET /notes -i                      -i shows the response's headers too
//   GET /me -H "Authorization: abc"    -H adds a request header
require("./app");

const PORT = 3000;
// headers Node adds to every response, left out so the ones your code sets stand out
const HIDDEN = new Set(["connection", "content-length", "date", "keep-alive", "transfer-encoding"]);

function parse(line) {
  const m = /^(\S+)\s+(\S+)\s*(.*)$/.exec(line.trim());
  if (!m) return null;
  let [, method, path, rest] = m;
  const headers = {};
  let verbose = false;
  rest = rest.replace(/(^|\s)-H\s+"([^"]*)"/g, (_, space, h) => {
    const i = h.indexOf(":");
    headers[h.slice(0, i).trim()] = h.slice(i + 1).trim();
    return space;
  });
  rest = rest.replace(/(^|\s)-i(?=\s|$)/g, () => { verbose = true; return ""; }).trim();
  if (rest && !Object.keys(headers).some((k) => k.toLowerCase() === "content-type")) {
    headers["Content-Type"] = /^[[{]/.test(rest) ? "application/json" : "text/plain";
  }
  return { method: method.toUpperCase(), path, headers, body: rest || undefined, verbose };
}

async function handle(line) {
  if (!line.trim()) return null;
  const r = parse(line);
  if (!r || !r.path.startsWith("/")) return 'usage: METHOD /path [body] [-i] [-H "Name: value"]';
  let res;
  try {
    res = await fetch(`http://localhost:${PORT}${r.path}`, {
      method: r.method, headers: r.headers, body: r.body, redirect: "manual", signal: AbortSignal.timeout(2000),
    });
  } catch (err) {
    if (err.name === "TimeoutError") return "(no response in 2 s: the server never finished its answer)";
    return `(no response: ${err.cause ? err.cause.message : err.message})`;
  }
  const out = [`${res.status} ${res.statusText}`];
  if (r.verbose) for (const [k, v] of res.headers) if (!HIDDEN.has(k)) out.push(`${k}: ${v}`);
  const text = await res.text();
  if (text) out.push(...(r.verbose ? ["", text] : [text]));
  return out.join("\n");
}

module.exports = { handle };

title: A table of routes
files: express.js, app.js
---brief
One `if` per route stops working at about the tenth route. Express replaces the chain with a **table**: `app.get("/health", handler)` adds a row, and one function looks each request up in it.

Write **`express()`** in express.js. It returns `app`, which is itself a request handler `(req, res)`, so `http.createServer(app)` works. The app also has:

- `app.get(path, handler)`, and the same for `post`, `put`, `patch` and `delete`. Each adds a route and returns `app`.
- `app.listen(port, callback)`, which starts an http server that calls `app`, and returns the server.

A route matches when its method and path both match exactly. The path is `req.url` without its query string, so `/a?x=1` is `/a`. With no match, answer **404** with `Content-Type: text/plain` and the body `Cannot GET /nope`, the method and then the path. Those are Express's own words.

Then rewrite app.js on top of it:

~~~js
const express = require("./express");
const app = express();
app.get("/", (req, res) => { res.setHeader("Content-Type", "text/plain"); res.end("hello from trellis"); });
// ...and /health the same way
app.listen(3000, () => console.log("listening on http://localhost:3000"));
~~~
---why
This is the **front controller** pattern: one entry point gets every request and dispatches it through a table. Routing becomes data you can add to, list and test, instead of control flow you have to read. Express, Flask, Rails and Spring all have this table at their centre. Returning `app` from every method is what makes `app.get(...).post(...)` chain.

// express.js: Trellis, a web framework in the shape of Express.
// app.js uses it exactly as it would use the real thing: const express = require("./express").
const http = require("http");

const METHODS = ["get", "post", "put", "patch", "delete"];

function express() {
  const routes = [];   // { method, path, handler }, in the order they were added

  // the app is a request handler: http.createServer(app) calls it for every request
  function app(req, res) {
    const path = req.url.split("?")[0];
    const route = routes.find((r) => r.method === req.method && r.path === path);
    if (route) return route.handler(req, res);
    res.statusCode = 404;
    res.setHeader("Content-Type", "text/plain; charset=utf-8");
    res.end(`Cannot ${req.method} ${path}`);
  }

  for (const m of METHODS) {
    app[m] = (path, handler) => {
      routes.push({ method: m.toUpperCase(), path, handler });
      return app;
    };
  }

  app.listen = (...args) => http.createServer(app).listen(...args);

  return app;
}

module.exports = express;

title: Speak JSON
files: express.js, app.js
---brief
Every handler so far is three lines of `setHeader` and `end`. An API answers in **JSON** almost every time, so Express gives `res` some helpers. Add them in express.js, on every `res` before the route runs:

| Helper | Does |
|---|---|
| `res.status(code)` | sets `res.statusCode` |
| `res.set(name, value)` | sets a header |
| `res.json(data)` | sends `JSON.stringify(data)` with `Content-Type: application/json; charset=utf-8` |
| `res.send(body)` | an object goes to `res.json`; a string is sent as `text/html; charset=utf-8` |

Each returns `res`, so `res.status(201).json(note)` chains. A Content-Type the handler set itself wins: only set one if there isn't one yet.

Then give app.js some data. Keep a list of notes in memory, `{ id: 1, text: "buy tulip bulbs" }` and `{ id: 2, text: "water the trellis" }`, and answer **`GET /notes`** with all of them. Use `res.send` for `/` and `/health`.
---why
These helpers look like sugar, but they encode rules people get wrong by hand: JSON must be stringified *and* labelled, or clients mis-read it; the status must be set before the body is sent. Returning `res` is the **fluent interface** pattern: each call hands back the object, so a whole answer reads as one sentence.

---solution express.js
// express.js: Trellis, a web framework in the shape of Express.
// app.js uses it exactly as it would use the real thing: const express = require("./express").
const http = require("http");

const METHODS = ["get", "post", "put", "patch", "delete"];

// the helpers every handler finds on res, so nobody writes setHeader, JSON.stringify and end by hand
function helpers(res) {
  res.status = (code) => {
    res.statusCode = code;
    return res;
  };
  res.set = (name, value) => {
    res.setHeader(name, value);
    return res;
  };
  res.json = (data) => {
    if (!res.getHeader("Content-Type")) res.setHeader("Content-Type", "application/json; charset=utf-8");
    res.end(JSON.stringify(data));
    return res;
  };
  res.send = (body) => {
    if (body !== null && typeof body === "object" && !Buffer.isBuffer(body)) return res.json(body);
    if (!res.getHeader("Content-Type")) res.setHeader("Content-Type", "text/html; charset=utf-8");
    res.end(body === undefined ? "" : body);
    return res;
  };
}

function express() {
  const routes = [];   // { method, path, handler }, in the order they were added

  // the app is a request handler: http.createServer(app) calls it for every request
  function app(req, res) {
    helpers(res);
    const path = req.url.split("?")[0];
    const route = routes.find((r) => r.method === req.method && r.path === path);
    if (route) return route.handler(req, res);
    res.status(404).set("Content-Type", "text/plain; charset=utf-8").send(`Cannot ${req.method} ${path}`);
  }

  for (const m of METHODS) {
    app[m] = (path, handler) => {
      routes.push({ method: m.toUpperCase(), path, handler });
      return app;
    };
  }

  app.listen = (...args) => http.createServer(app).listen(...args);

  return app;
}

module.exports = express;

title: Paths with holes
files: express.js, app.js
---brief
`GET /notes/2` should be note 2, and you can't add a route for every id. Express routes can have **holes**: `/notes/:id` matches `/notes/2`, and the handler finds `"2"` in **`req.params.id`**.

Turn each route's path into a regular expression when it's added. Each `:name` becomes `([^/]+)`, one path segment, and its name goes in a list. `/notes/:id` becomes `/^\/notes\/([^/]+)\/?$/`. The `\/?` lets a trailing slash match too, as in Express. Before a handler runs, set:

- **`req.params`**: each name with its decoded value (`a%20b` is `a b`);
- **`req.path`**: the path without the query string;
- **`req.query`**: the query string as an object of strings. `new URL(req.url, "http://localhost").searchParams` reads it for you.

Then in app.js: `GET /notes/:id` answers the note, or **404** with `{"error": "no such note"}`. `GET /notes?q=tulip` answers only the notes whose text contains `q`, ignoring case.
---why
Routes compiled to patterns are how every router works, and compiling once when the route is added keeps each request cheap. A param is exactly one segment, because `/notes/1/2` should never quietly match `/notes/:id`. Params and query values are always **strings**: `req.params.id` is `"2"`, not `2`. Forgetting that is why `notes.find((n) => n.id === req.params.id)` finds nothing.

// express.js: Trellis, a web framework in the shape of Express.
// app.js uses it exactly as it would use the real thing: const express = require("./express").
const http = require("http");

const METHODS = ["get", "post", "put", "patch", "delete"];

// "/notes/:id" -> /^\/notes\/([^/]+)\/?$/ and the names of its holes, ["id"]
function compile(path) {
  const keys = [];
  const pattern = path
    .replace(/\/$/, "")
    .replace(/[.*+?^${}()|[\]\\]/g, "\\$&")
    .replace(/:(\w+)/g, (_, name) => {
      keys.push(name);
      return "([^/]+)";
    });
  return { re: new RegExp(`^${pattern}/?$`), keys };
}

// the helpers every handler finds on res, so nobody writes setHeader, JSON.stringify and end by hand
function helpers(res) {
  res.status = (code) => {
    res.statusCode = code;
    return res;
  };
  res.set = (name, value) => {
    res.setHeader(name, value);
    return res;
  };
  res.json = (data) => {
    if (!res.getHeader("Content-Type")) res.setHeader("Content-Type", "application/json; charset=utf-8");
    res.end(JSON.stringify(data));
    return res;
  };
  res.send = (body) => {
    if (body !== null && typeof body === "object" && !Buffer.isBuffer(body)) return res.json(body);
    if (!res.getHeader("Content-Type")) res.setHeader("Content-Type", "text/html; charset=utf-8");
    res.end(body === undefined ? "" : body);
    return res;
  };
}

function express() {
  const routes = [];   // { method, re, keys, handler }, in the order they were added

  // the app is a request handler: http.createServer(app) calls it for every request
  function app(req, res) {
    helpers(res);
    const url = new URL(req.url, "http://localhost");
    req.path = url.pathname;
    req.query = Object.fromEntries(url.searchParams);
    for (const route of routes) {
      if (route.method !== req.method) continue;
      const m = route.re.exec(req.path);
      if (!m) continue;
      req.params = {};
      route.keys.forEach((k, i) => { req.params[k] = decodeURIComponent(m[i + 1]); });
      return route.handler(req, res);
    }
    res.status(404).set("Content-Type", "text/plain; charset=utf-8").send(`Cannot ${req.method} ${req.path}`);
  }

  for (const m of METHODS) {
    app[m] = (path, handler) => {
      routes.push({ method: m.toUpperCase(), ...compile(path), handler });
      return app;
    };
  }

  app.listen = (...args) => http.createServer(app).listen(...args);

  return app;
}

---brief
Some work belongs to many routes: logging every request, checking a key on everything under `/admin`, loading the note before two different routes use it. Express's answer is its central idea: **middleware**. A handler gets a third argument, **`next`**. It can answer, or call `next()` to pass the request to the next handler in line.

Rebuild `app` around one **stack of layers**, walked by `next()`:

- `app.use(fn)` adds a layer that runs for every path. `app.use("/admin", fn)` runs for `/admin` and everything under it, but not `/administrator`.
- Routes take any number of handlers: `app.get("/notes/:id", findNote, show)`. Each becomes a layer.
- `next()` runs the next layer that matches. When there's none left, answer the 404.

Set `req.originalUrl = req.url` at the start, as Express does. Then in app.js:

- add a logger, before everything: on the response's `"finish"` event, `console.log` the method, original URL and status, like `GET /notes/1 → 200`;
- move the note lookup into a middleware `findNote` that sets `req.note` or answers the 404, and use it in `GET /notes/:id`.
---why
Middleware is the **chain of responsibility** pattern, and it's why Express stayed small: logging, auth, body parsing, compression and CORS are all just layers, written by anyone, in any order. One stack for both middleware and routes keeps the rule simple: layers run in the order you added them. That's why the logger goes first, and why order bugs, like auth added after the route it guards, are real and common.

title: Read the body
files: express.js, app.js
---brief
Time to write notes. `POST /notes {"text": "prune the roses"}` sends JSON in the request **body**, and the body isn't in `req` yet: it arrives as a **stream**, in chunks, after your handler starts. You read it with `req.on("data", ...)` and `req.on("end", ...)`.

Write **`express.json()`**, a function that returns a middleware:

- If the request's `Content-Type` is `application/json` (a `; charset=...` after it is fine), read the whole body, `JSON.parse` it into **`req.body`**, then call `next()`. An empty body becomes `{}`.
- Anything else: leave `req.body` alone and call `next()` straight away.
- Broken JSON: answer **400** with `{"error": "invalid JSON"}`.

| Request | Answer |
|---|---|
| `POST /notes` with a non-empty `text` | **201**, the new note with the next id and its text trimmed, and a `Location: /notes/3` header |
| `POST /notes` without one | **400** `{"error": "text is required"}` |
| `DELETE /notes/:id` | **204** and no body, or the 404 from `findNote` |

Parsing the body in one middleware, once, means no route ever touches the stream, and every route gets the same rules. Checking `Content-Type` first stops a form post or a file upload from being fed to `JSON.parse`. The 201 with a `Location` header is how HTTP says *"made it, and here's where it lives"*. 204 says *"done, nothing to send back"*. Status codes are part of your API: clients branch on them.

    const type = (req.headers["content-type"] || "").split(";")[0].trim().toLowerCase();

    let raw = "";
    req.setEncoding("utf8");
    req.on("data", (chunk) => { raw += chunk; });
    req.on("end", () => {
      try {
        req.body = raw ? JSON.parse(raw) : {};
      } catch (e) {
        return res.status(400).json({ error: "invalid JSON" });
      }
      next();
    });
  };

title: Errors don't crash
files: express.js, app.js
---brief
First, see the problem. Add a route to app.js that throws, `app.get("/boom", () => { throw new Error("boom"); })`, press Run and type `GET /boom`. The error goes up through your framework, into Node's http server, and nobody catches it, so **the whole program dies**. Then `GET /notes` is refused: one bad request took everyone's down. Take the route out again when you've seen it.

Express catches errors and routes them, like requests. Change `next` in express.js to take an error, **`next(err)`**:

- With an error, skip ordinary layers and run only **error handlers**: functions with **four** parameters, `(err, req, res, next)`. (`handler.length` tells you how many a function declares.)
- Without one, skip the error handlers.
- Run each handler inside `try`/`catch`, and pass what's thrown to `next(e)`. If a handler returns a **promise** (an `async` function does), pass its rejection to `next` too.
- When the stack runs out with an error nobody handled, answer it: status `err.status` if it's a 4xx or 5xx, otherwise **500**. For a 4xx, send the error's message; for a 500, just `Internal Server Error`.

`express.json()` should now call `next(err)` for broken JSON, with `err.status = 400` and the message `invalid JSON`. In app.js, add an error handler last that answers every error as JSON: `{"error": message}` with its status, and `{"error": "something went wrong"}` for a 500.
---why
In Node, an exception nobody catches ends the process, and every request in flight with it. Frameworks turn errors into a second path through the same stack, so one handler at the end decides how errors look. That's also the only safe place to decide what a client may see: a 4xx message helps the client fix its request; a 500's details are your internals, so they stay in your logs. Catching rejected promises is what Express 5 added, because `async` handlers are now the normal case.

// express.js: Trellis, a web framework in the shape of Express.

const METHODS = ["get", "post", "put", "patch", "delete"];

// "/notes/:id" -> /^\/notes\/([^/]+)\/?$/ and the names of its holes, ["id"].
// A prefix pattern (for app.use) matches the path and anything under it: "/admin" matches "/admin/stats".
function compile(path, prefix = false) {
  const keys = [];
  const pattern = path
    .replace(/\/$/, "")
    .replace(/[.*+?^${}()|[\]\\]/g, "\\$&")
    .replace(/:(\w+)/g, (_, name) => {
      keys.push(name);
      return "([^/]+)";
    });
  return { re: new RegExp(`^${pattern}${prefix ? "(?=/|$)" : "/?$"}`), keys };
}

// the helpers every handler finds on res, so nobody writes setHeader, JSON.stringify and end by hand
function helpers(res) {
  res.status = (code) => {
    res.statusCode = code;
    return res;
  };
  res.set = (name, value) => {
    res.setHeader(name, value);
    return res;
  };
  res.json = (data) => {
    if (!res.getHeader("Content-Type")) res.setHeader("Content-Type", "application/json; charset=utf-8");
    res.end(JSON.stringify(data));
    return res;
  };
  res.send = (body) => {
    if (body !== null && typeof body === "object" && !Buffer.isBuffer(body)) return res.json(body);
    if (!res.getHeader("Content-Type")) res.setHeader("Content-Type", "text/html; charset=utf-8");
    res.end(body === undefined ? "" : body);
    return res;
  };
}

// what happens when the stack runs out: a 404, or an error nobody handled.
// A 4xx message is for the client; a 500's details are internals, so they stay out of the answer.
function done(err, req, res) {
  if (res.headersSent) return res.end();
  res.set("Content-Type", "text/plain; charset=utf-8");
  if (!err) return res.status(404).send(`Cannot ${req.method} ${req.path}`);
  const status = err.status >= 400 && err.status < 600 ? err.status : 500;
  res.status(status).send(status < 500 ? err.message : "Internal Server Error");
}

function express() {
  const stack = [];   // layers: { method (null for use), re, keys, handler }, in the order they were added

  // the app is a request handler: http.createServer(app) calls it for every request
  function app(req, res) {
    helpers(res);
    const url = new URL(req.url, "http://localhost");
    req.originalUrl = req.url;
    req.path = url.pathname;
    req.query = Object.fromEntries(url.searchParams);
    req.params = {};
    let i = 0;
    function next(err) {
      while (i < stack.length) {
        const layer = stack[i++];
        if (layer.method && layer.method !== req.method) continue;
        const m = layer.re.exec(req.path);
        if (!m) continue;
        // with an error, only error handlers (four arguments) run; without one, they're skipped
        if (Boolean(err) !== (layer.handler.length === 4)) continue;
        req.params = {};
        layer.keys.forEach((k, j) => { req.params[k] = decodeURIComponent(m[j + 1]); });
        try {
          const out = err ? layer.handler(err, req, res, next) : layer.handler(req, res, next);
          // an async handler returns a promise: if it rejects, that's an error too
          if (out && typeof out.then === "function") out.then(null, next);
        } catch (e) {
          next(e);
        }
        return;
      }
      done(err, req, res);
    }
    next();
  }

  app.use = (path, ...handlers) => {
    if (typeof path === "function") {
      handlers.unshift(path);
      path = "/";
    }
    for (const handler of handlers) stack.push({ method: null, ...compile(path, true), handler });
    return app;
  };

  for (const m of METHODS) {
    app[m] = (path, ...handlers) => {
      for (const handler of handlers) stack.push({ method: m.toUpperCase(), ...compile(path), handler });
      return app;
    };
  }

  app.listen = (...args) => http.createServer(app).listen(...args);

  return app;
}

// express.json(): a middleware that reads a JSON body into req.body, once, for every route after it
express.json = function json() {
  return (req, res, next) => {
    const type = (req.headers["content-type"] || "").split(";")[0].trim().toLowerCase();
    if (type !== "application/json") return next();
    let raw = "";
    req.setEncoding("utf8");
    req.on("data", (chunk) => { raw += chunk; });
    req.on("end", () => {
      try {
        req.body = raw ? JSON.parse(raw) : {};
      } catch (e) {
        const err = new Error("invalid JSON");
        err.status = 400;
        return next(err);
      }
      next();
    });
  };
};

- `req.url` loses it: under `/notes`, `/notes/7?x=1` is `/7?x=1` (and `/notes` alone is `/`);
- `req.baseUrl` gains it: `/notes`, or `/api/users` when routers are nested;

That's **composition**, the same idea as functions calling functions, and it's how big Express codebases stay navigable: one router per resource, each one testable alone. Rewriting the URL on the way in and restoring it on the way out is what lets each router believe it lives at `/`.

  req.note = all.find((n) => n.id === Number(req.params.id));
  if (!req.note) return res.status(404).json({ error: "no such note" });
  next();
}

notes.get("/", (req, res) => {
  const q = (req.query.q || "").toLowerCase();
  res.json(all.filter((n) => n.text.toLowerCase().includes(q)));
});

notes.get("/:id", findNote, (req, res) => res.json(req.note));

notes.post("/", (req, res) => {
  const text = req.body && req.body.text;
  if (typeof text !== "string" || !text.trim()) return res.status(400).json({ error: "text is required" });
  const note = { id: nextId++, text: text.trim() };
  all.push(note);
  res.status(201).set("Location", `${req.baseUrl}/${note.id}`).json(note);
});

notes.delete("/:id", findNote, (req, res) => {
  all.splice(all.indexOf(req.note), 1);
  res.status(204).end();
});

Cut `express()` in two. `Router()` keeps the stack, `use`, the route methods and the walking `next`, and returns `router(req, res, out)`, which calls `out(err)` when its stack runs out. `express()` makes one router, sets up `req`, and calls `router(req, res, (err) => done(err, req, res))`.
