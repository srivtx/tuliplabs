---

Shortlink is the third project people build when they learn Express: a **URL shortener**. You send it a long address and it gives you a short one, like `http://localhost:3000/q0U`. Anyone who visits the short one is sent on to the long one, and you count every visit.

It looks small, but it's a good tour of real backend questions: how to make short codes that never collide, why the redirect is a **302** and not a 301, how to count clicks, what to do when two people want the same name, and why a deleted link should **stay** deleted. The routes, the error handler and `httpError` are the same as in Taskflow, so the new ideas get all the room.

---brief
A short code is just a **number written in base 62**: the digits `0-9`, then `a-z`, then `A-Z`. Count up from 100000 and every code is three characters, with room for 238,328 links before a fourth character is needed.

In **codes.js**, write **`encode(n)`**: take the last digit with `n % 62`, look it up in `DIGITS`, put it in front, and divide `n` by 62 until nothing is left. `encode(61)` is `"Z"`, `encode(62)` is `"10"` and `encode(100000)` is `"q0U"`.

Then in **app.js**:

- **`checkUrl(url)`**: a 400 `"url is required"` if it's missing, and a 400 `"url must be a full http:// or https:// address"` unless `new URL(url)` parses it **and** its protocol is `http:` or `https:`. Answer `u.href`, the normalised form.
- **`view(link)`**: what clients see, `{ code, url, short, clicks }`, where `short` is `` `${BASE}/${code}` ``.
- **`POST /api/links`** `{"url": "..."}`: make `{ code: encode(counter++), url, clicks: 0 }`, keep it in `links` by its code, and answer **201** with a `Location`.
- **`GET /api/links/:code`**: through a **`findLink`** middleware, as in Taskflow, with a 404 `"Link not found"`.
---why
A counter can never repeat, so two links can never get the same code, and you never have to check. Base 62 keeps the codes short because every character carries 62 possibilities instead of 10. Random codes are the other choice. They hide how many links you have, but they can collide, so you'd have to check every time. Checking the URL is about safety, not tidiness. A shortener that accepts `javascript:alert(1)` sends that code to everyone who clicks. Only real web addresses go through.

// client.js: the terminal. It starts your server, then turns each line you type into an HTTP request
// and sends it with fetch(), the way a browser, curl or another service would. You don't need to change it.
//
//   GET /notes                         a request
//   POST /notes {"text": "milk"}       with a JSON body
//   GET /notes -i                      -i shows the response's headers too
//   GET /me -H "Authorization: abc"    -H adds a request header
require("./app");

const PORT = 3000;
// headers Node adds to every response, left out so the ones your code sets stand out
const HIDDEN = new Set(["connection", "content-length", "date", "keep-alive", "transfer-encoding"]);

function parse(line) {
  const m = /^(\S+)\s+(\S+)\s*(.*)$/.exec(line.trim());
  if (!m) return null;
  let [, method, path, rest] = m;
  const headers = {};
  let verbose = false;
  rest = rest.replace(/(^|\s)-H\s+"([^"]*)"/g, (_, space, h) => {
    const i = h.indexOf(":");
    headers[h.slice(0, i).trim()] = h.slice(i + 1).trim();
    return space;
  });
  rest = rest.replace(/(^|\s)-i(?=\s|$)/g, () => { verbose = true; return ""; }).trim();
  if (rest && !Object.keys(headers).some((k) => k.toLowerCase() === "content-type")) {
    headers["Content-Type"] = /^[[{]/.test(rest) ? "application/json" : "text/plain";
  }
  return { method: method.toUpperCase(), path, headers, body: rest || undefined, verbose };
}

async function handle(line) {
  if (!line.trim()) return null;
  const r = parse(line);
  if (!r || !r.path.startsWith("/")) return 'usage: METHOD /path [body] [-i] [-H "Name: value"]';
  let res;
  try {
    res = await fetch(`http://localhost:${PORT}${r.path}`, {
      method: r.method, headers: r.headers, body: r.body, redirect: "manual", signal: AbortSignal.timeout(2000),
    });
  } catch (err) {
    if (err.name === "TimeoutError") return "(no response in 2 s: the server never finished its answer)";
    return `(no response: ${err.cause ? err.cause.message : err.message})`;
  }
  const out = [`${res.status} ${res.statusText}`];
  if (r.verbose) for (const [k, v] of res.headers) if (!HIDDEN.has(k)) out.push(`${k}: ${v}`);
  const text = await res.text();
  if (text) out.push(...(r.verbose ? ["", text] : [text]));
  return out.join("\n");
}

module.exports = { handle };

// codes.js: a number as a short code, in base 62: the digits 0-9, then a-z, then A-Z
const DIGITS = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";

// encode(0) is "0", encode(61) is "Z", encode(62) is "10"
function encode(n) {
  let code = "";
  do {
    code = DIGITS[n % 62] + code;
    n = Math.floor(n / 62);
  } while (n > 0);
  return code;
}

// app.js: Shortlink, a URL shortener. client.js starts it with require("./app").
const express = require("express");
const { encode } = require("./codes");

const app = express();
app.use(express.json());

const BASE = "http://localhost:3000";
// every link, by its code
const links = new Map();
// the number behind the next code: 100000 is "q0U" in base 62, so codes start at three characters
let counter = 100000;

// an error that carries the status to answer with, for the error handler at the bottom
function httpError(status, message) {
  const err = new Error(message);
  err.status = status;
  return err;
}

// a URL a client sent: it has to parse, and be http or https (never javascript: or file:). Answers it normalised
function checkUrl(url) {
  if (typeof url !== "string" || !url.trim()) throw httpError(400, "url is required");
  let u;
  try {
    u = new URL(url.trim());
  } catch (err) {
    throw httpError(400, "url must be a full http:// or https:// address");
  }
  if (u.protocol !== "http:" && u.protocol !== "https:") throw httpError(400, "url must be a full http:// or https:// address");
  return u.href;
}

// a link as clients see it
function view(link) {
  return { code: link.code, url: link.url, short: `${BASE}/${link.code}`, clicks: link.clicks };
}

// middleware: loads the link named by :code into req.link
function findLink(req, res, next) {
  req.link = links.get(req.params.code);
  if (!req.link) throw httpError(404, "Link not found");
  next();
}

app.post("/api/links", (req, res) => {
  const body = req.body || {};
  const url = checkUrl(body.url);
  const link = { code: encode(counter++), url, clicks: 0 };
  links.set(link.code, link);
  res.status(201).location(`/api/links/${link.code}`).json(view(link));
});

app.get("/api/links/:code", findLink, (req, res) => {
  res.json(view(req.link));
});

// every error ends up here, as JSON
app.use((err, req, res, next) => {
  if (err.type === "entity.parse.failed") return res.status(400).json({ error: "Invalid JSON" });
  const status = err.status || 500;
  if (status >= 500) console.error(`${req.method} ${req.originalUrl} failed: ${err.message}`);
  res.status(status).json({ error: status >= 500 ? "Something went wrong" : err.message });
});

app.listen(3000, () => console.log("Shortlink on http://localhost:3000"));

---brief
Now the part people actually use. Add **`GET /:code`**: find the link with `findLink`, then **`res.redirect(302, url)`**. A browser that gets a 302 goes straight to the `Location` it names.

After it, add a catch-all, **`app.use((req, res) => { throw httpError(404, "Not found"); })`**, so any other path gets a JSON 404 like every other error here.

Try `GET /q0U -i` to see the whole answer: the status, the `Location`, and a short text body for clients that don't follow redirects.
---why
Why **302 Found** and not **301 Moved Permanently**? A browser remembers a 301 and never asks you again: the next click on the same short link goes straight to the long one without touching your server. That's great for speed and terrible for a shortener, because those clicks are invisible to you and you can't change where the link goes. A 302 means *"for now, go there"*, so every click comes back through you. The real shorteners use 301 only when they don't care about counting.

title: Count the clicks
files: app.js
---brief
A shortener is mostly a counter. Every time `GET /:code` redirects, add one to the link's **`clicks`**, and one to **`referrers`**, keyed by where the click came from.

- Browsers say where a click came from in the **`Referer`** header (spelled that way since 1996). Write **`source(req)`**: the host of `new URL(req.get("Referer"))`, or **`"direct"`** when there's no Referer or it doesn't parse.
- New links start with `referrers: {}`, and `view` shows them.

Only the redirect counts. Reading the stats with `GET /api/links/:code` isn't a click.

Try it: `GET /q0U -H "Referer: https://news.example/item?id=7"`, then `GET /api/links/q0U`.
---why
Counting by the host and not the full Referer is on purpose. Full addresses can carry private things, like a search query or an id in a page's URL, and you don't need them to know that a link spread through a news site. A header is input from outside like any other: `new URL` throws on garbage, and one odd click must never take the redirect down with it. That's why the `try` is there.

  GET /q0U   (no Referer)                              ─▶ clicks 2   referrers { "news.example": 1, "direct": 1 }
  GET /api/links/q0U                                   ─▶ just reads them

title: Top links, and tombstones
files: app.js
---brief
Two last things a real shortener needs.

**`GET /api/links`**: the live links, in the order they were made. `?sort=clicks` puts the most clicked first, and `?limit=` caps how many come back: 10 if it's missing, never more than 100, and a 400 `"limit must be a whole number from 1"` if it isn't one.

**`DELETE /api/links/:code`**: answer **204**. Don't remove the code. Replace the link with a **tombstone**, `{ code, deleted: true }`, and take its URL out of `byUrl`. A tombstone keeps the code taken forever:

- `GET /:code` on a deleted link is **410 Gone**, `"This link was deleted"`. The redirect needs its own lookup now, because `findLink` should treat a tombstone as **404** for the API.
- `freshCode()` and the alias check already skip it, because it's still in `links`.
- The list leaves tombstones out, and so does rebuilding `byUrl`.
---why
A short link outlives its database row. It's printed on posters, saved in old emails, and pasted in chat history. If a deleted code could be made again, all of those would start pointing at someone else's page. That's how people get phished through old links. Tombstones are cheap: a code and a flag. The cost is that a deleted alias can't be picked again, and real shorteners accept that. Sorting is stable, so links with the same number of clicks stay in the order they were made.

  if (byUrl.get(req.link.url) === req.link.code) byUrl.delete(req.link.url);
  links.set(req.link.code, { code: req.link.code, deleted: true });
  persist();
  res.status(204).end();
});

// the short link itself: send the browser on to the long URL
app.get("/:code", (req, res) => {
  const link = links.get(req.params.code);
  if (!link) throw httpError(404, "Link not found");
  if (link.deleted) throw httpError(410, "This link was deleted");
  if (expired(link)) throw httpError(410, "This link has expired");
  const from = source(req);
  link.clicks++;
  link.referrers[from] = (link.referrers[from] || 0) + 1;
  persist();
  res.redirect(302, link.url);
});

// any other path: a JSON 404, like every other error here
app.use((req, res) => {
  throw httpError(404, "Not found");
});

// every error ends up here, as JSON
app.use((err, req, res, next) => {
  if (err.type === "entity.parse.failed") return res.status(400).json({ error: "Invalid JSON" });
  const status = err.status || 500;
  if (status >= 500) console.error(`${req.method} ${req.originalUrl} failed: ${err.message}`);
  res.status(status).json({ error: status >= 500 ? "Something went wrong" : err.message });
});

app.listen(3000, () => console.log("Shortlink on http://localhost:3000"));
